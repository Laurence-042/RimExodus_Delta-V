
`ExpansionProbe.cs` 使用 `Fighter_0` 实际导出质量 **1448**、惯量 **77059.85**、十台推进器，以及与前述实际战机实验相同的 SHA256 输入。共 153 个条件行、18360 次独立发射相位探测：距离 100／115／140 格，弹速 30／35／45 格/秒，随机换位用种子 17／42／137。每次模拟 96 秒，40～80 秒每 1/3 秒取一次射击相位，共 120 发；无散布，每发按发射时目标位姿、刚体速度及射手速度求预瞄，再与生产 `SpaceCollision.FindBestCell` 所用占格判定检查扫掠。炮弹互不造成伤害，目标不会因中弹改变运动。

移动射手组使用另一具**相同战机动力模型**，按保持射位追随目标，并将射手速度纳入预瞄；它不是实际驱逐舰复原，也不是双方完整默认策略对战。非对称直接推力组只保留固定射手参考。

## 扩展前实际战机实验（2026-10-28）

```powershell
dotnet build Source/DeltaV.csproj -c Release --no-restore
powershell -ExecutionPolicy Bypass -File scripts/CombatManeuverSimulation/run_mpc.ps1 -GameRoot 'D:/SteamLibrary/steamapps/common/RimWorld' -Fighter
```

本轮只增加离线探针，没有修改 AI、武器 Def 或 prefab。`fighter_inputs.py` 复用本地战机设计工具的 Def 继承读取器，从已安装游戏 Data 与当前 Delta-V Def 读取质量、尺寸，再读取 `Prefabs/Fighter_0.xml`。该导出 SHA256 为 `a4f00087cb366dc3bbcbd85bcc7f952082835bd2a448eb8f78d588f00ba4c556`。不加载整套第三方 Mod 的运行时 XML/Harmony 修改，不声称恢复了某一时刻的受损存档。所有推进器假定正常供电、完整且按 prefab 保存的出力上限运行。

`FighterEvasionProbe.cs` 调用原版 `GenAdj.OccupiedRect` 取得旋转后的建筑格，按当前 `ShipPhysics.Measure` 的基架、建筑质量及矩形本征惯量口径汇总。普通松散物资和 Pawn 不进入当前游戏的质量算法；生成后消失的 Pawn 标记也排除。完整战机质量 **1448**、惯量 **77059.85**，10 台推进器合计 **20000**；主推 8000、反推 4000、左右各 4000。生产分配器给出的主推加速度约 **5.521**，其余方向约 **2.761** 格/秒²。迎弹投影：船首/船尾朝敌为 **19 格**，侧舷朝敌为 **22 格**；斜向并不必然更窄。包围圆半径约 **13.91 格**，没有当作实心圆盘判定全部命中。

运动复用生产版 `ForceToCommand → PreviewAllocation → Integrate`，60 Hz、默认线速度半衰期 8 秒与角速度半衰期 3 秒。预瞄调用 `SpaceTransform.TrySolveInterceptPlanar`，包括船体瞄准中心的刚体点速度。炮弹使用统一 `OrbitSphere`/`SpaceTransform` 轨迹转换，脚印半径为 1×1 弹体的 √2/2 格；每 tick 按生产 `SweepOne` 的 0.5 格采样步长直接调用生产私有 `FindBestCell`，检查实际占格与弹体脚印相交。占格统一作为不透明包络；不随机计算掩体放行、裸基架拦截、盾与伤害。**避开表示没有碰到占格包络；相交不等于最终伤害命中。** 射手固定，炮弹准确匀速预瞄、无散布、没有其他船或炮口偏移；不是整场战斗胜率模拟。

当前 Circle 对照取日志相对朝向 31°，固定射位距离，直接运行生产 `CombatAttackPose.Trajectory` 和 `OnlineMpcGuidance`。这隔离了绕行控制的效果，不模拟规则重选、战损和双方追逐。其他轨迹是独立时钟驱动的试验控制输入，不读取炮弹或开火事件，也不是已实现的 AI。周期实验预热 40 秒，每种完整机动周期均匀抽取 240 个开火相位，每发持续检查 15 秒；Circle 则采样 40 秒稳定轨迹。

## Cosmoteer 对照调研（2026-10-28）

本节是机制核对和设计推论，没有启动游戏或修改 Delta-V AI。证据包括官方更新公告，以及本机 `D:/SteamLibrary/steamapps/common/Cosmoteer/` 的规则文件、随包 API 文档和 `Bin/Cosmoteer.dll` IL。程序集内版本标识为 **0.30.5a_steam**。网页 Wiki 的部分武器表仍是调整前数据，以下数值以本机此版本为准。这里没有测量一艘具体 Cosmoteer 小舰的推重比，也没有得到其实际闪避率，不能声称它的小舰天然比当前战机更能闪避。

### 已确认的机制

1. **它也通过弹速平衡解决难躲问题。** [官方 0.30.3 公告](https://steamcommunity.com/games/799600/announcements/detail/565894691447375085) 将超频大炮弹速从 195 降到 170，明确解释为炮弹过于难以躲避或拦截。[官方 0.30.5 公告](https://steamcommunity.com/games/799600/announcements/detail/699905228356458048) 又将大多数弹速降低六分之一，并恢复 Meltdown 更新前的船体阻力。公告正文亦可从 SteamDB 的 [0.30.3 转录](https://steamdb.info/patchnotes/21198132/) 和 [0.30.5 转录](https://steamdb.info/patchnotes/26170927/) 复核。这是具体版本的平衡措施，不能解释成万能闪避算法。
2. **普通 AI 会间歇改变攻击方位，不是持续匀速绕圈。** `Data/ai/ai_normal.rules` 配置 `RandomAttackAngle`：每 5～10 秒选一次角度偏移，范围 ±30°，开启协同包抄。核对 `AIRandomAttackAngleModule.UpdateAttackAngle` 及其辅助方法：由游戏逻辑时间触发，设置世界方向表示的目标周围跟随方位；单舰基准是目标指向本舰的当前方位，有同阵营攻击者时则用其他攻击方位单位向量之和的反方向作为基准，再加随机偏移。该模块未读取炮弹或敌方发射事件，也没有按预计命中误差优化动作。它与船首朝向分别由不同模块控制。推论：换射位过程可能产生加速、减速和反向，但不保证持续运动或躲过重炮；不能把当前 Circle 的失败当作对这个机制的验证。
3. **默认射位和玩家保存的设置并存。** 同一规则文件将距离/船体朝向交给 `DefaultAttackRadiusAndRotation`，检查 8 个朝向，切换阈值系数 1.25。`UseSavedAboveHealth=50%` 对应实际代码读取本船 `ShipMetadata.DefaultAttackRadius/DefaultAttackRotation`，健康比高于阈值时采用已保存设置；保存距离写入的是边到边跟随距离，且仍有视野约束。默认自动求解另走 `AttackCommand.SetBestAttackRadiusAndRotation`。因此其每船设计意图并未被一个统一运动模式替代，也不能把边到边距离直接搬成 Delta-V 的中心距。
4. **炮弹按目标尺寸提供不同理想射程，但是否采用取决于调用。** 普通、重型及甲板炮弹均设 `IdealRange=[75,190]`、`IdealRadius=[5,50]`。`BulletRules.GetIdealRange` 实际将目标半径在后一范围内反插值，再在前一范围内插值。至少在半径 5～50 区间内，小目标对应较近的武器理想射程、大目标对应较远的射程；这不是最终船心间距。进一步核对调用：`AttackCommand` 初始化选射位时启用 `useIdealRange`，普通 NPC 的 `AIDefaultAttackRadiusAndRotationModule` 后续重选则关闭它，并启用资源检查、八朝向和随机距离探查。因此不能把该字段直接解释成普通 NPC 始终执行“近小远大”，也不能当作保护小舰的闪避机制。
5. **武器仍有预瞄，但散布、跟踪和拦截形成额外约束。** `BulletEmitterRules` 默认启用 `TargetLeadPrediction`，`BulletEmitter.TryGetAimLocation` 调用真实 `Algorithms.TryComputeAimLocation`，传入射手刚体状态及可选发射延迟；随包 `Bin/Cosmoteer.xml` 描述的目标预测包括平移和旋转。不能假定其炮塔因为不会预瞄而容易打空。大炮配置射界 115°、炮塔转速 30°/秒、散布 ±2.5°；甲板炮分别为 270°、20°/秒、±2.5°。两者自动瞄准目标类型是舰船部件。`point_defense.rules` 可攻击 `bullet` 类弹体，而大炮弹本身有 `Targetable`、1000 生命和 `bullet` 分类，说明实弹存在点防拦截链。

### 与当前战机实验如何对应

本机普通、重型、甲板炮的基础弹速分别为 **200 / 125 / 100**，基础射程均为 **190**。固定射手、静止目标、飞行距离取 190 时，名义飞行时间为 **0.95 / 1.52 / 1.90 秒**；当前 Delta-V 对照为 115/45≈**2.56 秒**。这不是对实际交战射距的测量，但足以说明“Cosmoteer 单靠更长飞行时间让小船躲炮”并无证据。绝对速度数值也不能脱离距离、船宽和加速度跨游戏比较。

用于筛查的无量纲量可写作 `Q = a_perp * (D/c)^2 / W`：理想恒定净横向加速度产生的名义位移 `0.5*a_perp*(D/c)^2`，除以迎弹半宽 `W/2`。Q 不是命中概率；真实迎弹几何、最近接时刻、初速、阻力、推力换向及预瞄都会改变结果。尤其不能把绕圈所需的向心加速度全部当作有效脱靶加速度。应同时检查炮塔跟踪所需角速度、射界和散布。

以散布 ±2.5° 为例，距离 190 的几何横向散布半宽约 `190*tan(2.5°)=8.30`；它能降低对某个小部件的命中集中度，却不保证整船避弹。类似地，若只是 `v=12、D=115` 的横移，视线转速约 6°/秒，单凭这种运动不足以超过 20～30°/秒炮塔的跟踪能力；还须看预瞄点变化及真实炮口几何，不能凭“有转速上限”断言能闪避。

**对设计的判断：** Cosmoteer 提供的是每船射位意图、间歇换位/包抄、武器几何与数值、点防等组合；现有证据不能支持“其普通 AI 保证小舰躲开大炮”。其随机换位值得作为独立离线对照，但不能先假定它优于已测的非对称往返。后续若做对照，应保留当前战机、生产推进和碰撞链，只替换运动输入，在多个随机种子及 30/35/45 弹速下记录避开比例、保持射程比例和本船输出窗口。玩家仍应能选择保存射位、换位幅度与节奏；不要把随机换位或某一套闪避动作强制套在所有自定义策略上。此处仅记录验证方向，未实施该对照，也未修改 AI。

## 早期校准实验（不代表实际质量）

从仓库根目录运行：

```powershell
python scripts/CombatManeuverSimulation/simulate.py
python scripts/CombatManeuverSimulation/pose_probe.py
powershell -ExecutionPolicy Bypass -File scripts/CombatManeuverSimulation/run_mpc.ps1 -GameRoot 'D:\SteamLibrary\steamapps\common\RimWorld'
```

`simulate.py` 是单发弹道的解析近似与时机敏感性检查。`CombatProbe.cs` 读取本地 `Fighter_0.xml` 的十台推进器位置与朝向，调用已编译的生产版 `ShipPhysics` 分配器、`CombatTrajectoryIntent`、`OnlineMpcGuidance`、`SpaceTransform.TrySolveInterceptPlanar`，以每 0.1 秒一个制导微步、两步计划回放、每 0.5 秒重规划和每游戏刻积分。测试只在单发炮弹的目标包围圆上判定命中；没有启动游戏。

日志校准输入：小舰十台推进器合计 20000 推力，起始和侧向朝向的横移余量约 3.55／5.11 格／秒²，正向角加速度 0.728 弧度／秒²；重炮射距取 150 格、弹速 45 格／秒，船体包围圆半径 13.9 格，目标初速取日志中的横向 −2.34 格／秒。`Fighter_0` 的占地包围为 22×19 格，加上口袋图四周各 12 格正好对应日志的 46×43 地图；`Demo_0` 的 49×54 格也对应 73×78。质量与惯量按上述能力反推，因此不是从存档恢复的精确战斗状态。单发判定忽略具体船体占格、护盾、多炮口、炮塔跟踪及第三方 Mod；所有推进器均假定正常供电。报告的是这组条件下的控制链可行性，不是游戏内命中率。

对照动作保持同一初态。`current 2.53` 使用日志中的候选横向加速度；`full 3.55` 使用现朝向的真实预览余量；`full 5.11` 同时要求转向约 35° 与更大横移；`reverse` 在 1.5 秒时要求反向推力。`circle-miss` 表示弹体没有进入保守包围圆，因此也不会命中其内的船体；`circle-hit` 只表示进入包围圆，不能替代真实占格碰撞。重规划场景每 30 tick 重新制作参考轨迹，保持生产版轨迹采样和时间轴口径。

另以 120／130／140／150／170 格射距检查弹体飞行时间敏感性，及质量上下 15% 的变化。`Fighter_0` 的两门激光炮射程 120 格、两门速射炮射程 140 格；若四门都启用且使用内置默认距离曲线，按当前伤害率权重得出的交战峰值约 102 格。单发实验没有运行策略规则选择，因此只能验证候选动作能否由控制链执行、执行后的弹道是否掠过；不能证明规划器会选择该动作，也不能推算整场战斗命中率。

`pose_probe.py` 依 [Cosmoteer 开发者对经典 AI 的说明](https://oldforum.cosmoteer.net/d/2892-can-someone-fully-explain-how-the-game-s-kiting-algorithm-works) 对本仓库 prefab 做八朝向、整数格距离的武器覆盖扫描，可指定任意 `Prefabs/` 下文件名。输入来自真实 prefab 的武器安装格、旋转和 Def 的射程、射界、冷却、伤害倍率；导弹按实际锁定弧处理。暂不模拟地图射线遮挡、实际炮塔转速、弹药、供能与提前量。Delta-V 当前射击链按炮口至目标中心检查射程，因此这里也按中心算，不能把 Cosmoteer 的目标包围圆规则直接当成现有发射门禁。扫描结果：`Fighter_0` 四门齐射武器均为 360° 炮塔，102 格四门均可用，120 格处是否四门都够射程取决于安装位置与朝向，130 格只剩两门速射；`Demo_0` 的联合射位扫描给出约 128 格的满火力距离，而把每门炮的安装偏移机械地从射程扣掉只剩约 100 格。这说明既不能只用射程中位数，也不能用逐炮保守射程代替联合位置与朝向搜索。仅最大化本船火力不会自然选出战机的侧舷规避朝向，也不会保证躲过敌方重炮；战术评分还须结合敌方武器风险与本船真实推力。

下一步接入应保持现有战略／战术边界：每船驾驶台的规则仍决定偏好；战术层按武器炮口、真实锁定弧与安全射线生成可攻击的距离／朝向候选，并按敌方武器风险及 `ShipPhysics` 可达性评价它们；真实发射仍由 `SpaceWeaponShot` 门禁决定。冷却中的武器可贡献“未来射位”但不能虚增当前预计输出。用户固定距离曲线应仍可明确要求近战或持续拉远。游戏内实际命中率与切换迟滞须后续实测。
