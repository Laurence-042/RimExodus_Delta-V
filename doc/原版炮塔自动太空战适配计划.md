# 原版炮塔自动太空战适配计划

**状态：阶段 A/B、通用自动适配设置与本地分析报告已实施；适配器不包含具体 Mod 专项逻辑。构建与专项数字以本轮交付记录为准，游戏内仍待验收。**

## 1. 目标与边界

为原版及第三方 Mod 中结构符合原版契约的 `Building_TurretGun` 自动生成 Delta-V 太空战能力。自动适配不是把武器压缩到现有四门舰炮模板，而是从原武器最终 Def 的单发、峰值和持续表现生成连续的装药、弹头、发热、热容、散热、激光能量与射击节奏。现有小／中型速射、重炮和激光只作为转换曲线的标定锚点，不作为数值上限。

必须同时满足以下约束：

- 实弹的实际速度、质量、动能、爆炸、贯穿、护盾交互和弹药消费继续只走 `SpaceKinetics`、`SpaceImpactEffects`、`SpaceWeaponBallistics` 与共同发射事务，不建立兼容武器专用弹道。
- 强力 Mod 武器的火力不做平衡削平。单发越强，反推出的每发弹头与装药越多；持续吞吐越高，反推出的散热能力越强，同时每秒弹药消耗和热流同步提高。
- 来源具有有限逐发弹容时，弹仓保留其完整射击次数并乘解析后的固定 `C/M`；来源没有可识别有限弹容时才按炮塔物理规模兜底。两者都以“至少容纳一轮解析后的完整 burst”为硬下限，不能出现满仓仍不足一发或不足一轮的兼容性事故。容量增加不赠送库存，高吞吐武器仍须实际补充并消耗全部弹药。
- 激光无热循环，实际伤害、守卫扣容和逐束电费仍线性同源；高伤害或高频激光必须支付相应脉冲能量与持续功率。
- 自动适配只影响太空模式。切回地面模式后，普通炮塔继续走自己的原版／第三方 Verb、索敌、弹药与冷却，不把 Delta-V 弹仓和热状态强塞进地面开火链。
- 不自动改造 Pawn 手持武器。只读取炮塔建筑的 `turretGunDef` 作为源武器；跨容器 Pawn 射击继续不在范围内。
- 已有 `CompSpaceWeapon` 的 Def、Delta-V 自有舰炮、导弹、轨道炮、点防和工程光束全部跳过。
- 新档为验收基线，不增加旧开发快照迁移分支，不改版本号，不提交代码。

## 2. 支持与排除判据

扫描发生在所有 XML Patch 和继承完成后的 `DefGenerator.GenerateImpliedDefs_PreResolve` 末尾，读取最终 Def 值。逐 Def 独立计算，禁止按当前加载武器集合做百分位归一化，避免增删 Mod 后同一武器改变类型或参数。

### 2.1 自动纳入

候选建筑必须同时满足：

1. `thingClass` 是 `Building_TurretGun` 或其子类；
2. `building.turretGunDef` 存在，且能唯一解析一个主射击 Verb；
3. 未声明 `CompSpaceWeapon`，未由显式扩展禁用；
4. 弹体具有 Sharp／Blunt 或 Heat／Beam 可解释伤害；
5. 没有硬性缺失字段或无效数值。

实弹按 Sharp／Blunt（包括使用 Sharp 护甲类别的爆炸伤害）读取单发伤害、AP 与速度；激光按 Heat／Beam 识别。自定义 Verb、爆炸、曲射、特殊资源事务、`fuelIsMortarBarrel`，以及第三方 Building／Verb／Comp 运行机制只产生通用软警告，不执行其地面特殊后效；爆炸范围不带入太空。第一个来源 `CompRefuelable` 不解释资源名称，统一按逐发／逐 burst 消费可支持的射击数换算仓容；异常性能请求在反解 C/M 前限制为生产毁伤上界的 95%。

### 2.2 自动排除

硬拒绝限定为：不是自动炮塔、已有太空武器、Def 明确禁用、缺少 gun、无法唯一解析主 Verb、缺少弹体、伤害类别不可解释、无正伤害或周期数值无效。硬拒绝零行为、零错误并给出稳定原因码。

### 2.3 显式覆盖

新增公开 `DefModExtension_AutoSpaceWeapon`，允许其他 Mod 或本项目 XML Patch：

- 禁用／强制启用自动适配；
- 强制 `Rapid`、`Heavy` 或 `Laser`；
- 指定源 Verb／弹体；
- 覆盖或倍率调整目标装药、弹头、峰值间隔、目标 burst、休止时间、散热、热容、激光脉冲伤害／电费、射程、散布与转速；
- 声明第三方资源事务已由外部 Comp 负责。

覆盖发生在通用推导之后、数值安全校验之前。显式值优先，但仍必须满足有限数、正值、整数弹耗和共同发射事务契约。

玩家设置另有两级策略：Mod 级为推荐／全部启用／全部禁用，武器级为继承／启用／禁用。武器级优先但不能覆盖硬拒绝；推荐模式只启用零警告候选，Def 的 `force` 只允许其通过推荐警告。键为规范化 packageId＋turret defName，修改在下次重启的 Def 生成阶段生效。全部判定只读取通用结构，不匹配具体 Mod、Def 或第三方类型名。

设置页提供主动导出分析报告。单个版本化 JSON 按加载顺序覆盖全部活动 Mod，记录绝对根路径和实际加载目录；逐武器区分当前设置计算结果、生成器在本次启动时的决定与 resolved marker 实际注入状态，并保存来源快照及同一次解析得到的完整 profile。报告另附盾容护盾 Def 的只读观察数据，供后续[护盾自动太空战适配](护盾自动太空战适配计划.md)分析；不因此声明支持。导出写入用户数据 `DeltaV/AutoAdaptationReports/`，不上传。

## 3. 源武器快照

每个候选只在 Def 解析期生成一次不可变快照，运行时不得逐 tick 反读 Verb 或弹体 Def。快照至少包含：

- 最终单发伤害、建筑伤害倍率、DamageDef、护甲类别、armor penetration；
- 原弹体速度、爆炸半径、飞越模式及实际 Beam 证据；
- `burstShotCount = N`、`ticksBetweenBurstShots = delta`；
- 炮塔 warmup、建筑 cooldown 覆盖值，以及回退后的 Verb cooldown；
- 完整周期 `T = warmup + cooldown + (N - 1) * delta / 60`；
- 峰值频率与持续频率 `N / T`；
- 炮塔脚印、建造成本、耐久、耗电、科技等级、原射程、精度和是否需要操作员。

原版调用语义以对应版本源码为准。完整周期中的 burst 间隔必须使用 `N - 1`，建筑 `turretBurstCooldownTime` 的有效覆盖优先于 Verb 默认冷却。

## 4. 连续物理参数生成

### 4.1 结果空间标定，而非直接映射伤害

原版伤害不能唯一还原弹体质量和装药，因此只允许两条显式、固定、可审计的尺度曲线：

- 源单发表现 → 目标钢弹爆心伤害；
- 源单发表现、AP、速度与 Sharp／Blunt 倾向 → 目标铀弹结构预算。

曲线在对数空间用固定锚点作单调分段插值；超出最大锚点后沿末段斜率继续外推，不使用人口百分位，也不以现有舰炮最大值封顶。数值安全上限只防止整数／浮点溢出，触发时输出明确警告，不能伪装成平衡上限。

真实炮塔标定锚点至少覆盖原版 Mini-turret、Autocannon、Uranium slug turret，以及当前 Delta-V 小／中型速射、重炮和激光的生产结果。Odyssey Beam repeater 是继承 `BaseHumanMakeableGun` 的手持武器，不是自动纳入候选；因原版没有同类激光炮塔，阶段 A 只把它包装为明确命名的合成激光公式夹具，用来验证伤害、逐束能量和功率范围，不得把它列入原版炮塔支持表。锚点表和曲线常量必须先由离线审计输出，经用户审阅后才能启用运行时注入。

### 4.2 反解弹头 M 与装药 C

不得复制生产伤害公式。适配器调用生产计算入口，以确定性二分／单调搜索反解：

- `M`：寻找达到目标钢弹爆心伤害的最小整数弹头份数；
- `C`：寻找达到目标铀弹结构预算的最小整数装药份数；
- AP、高速 Sharp 倾向提高 `C/M`，Blunt、低速高伤倾向提高 `M/C`，但最终效果仍由生产入口复核。

生成后的真实行为继续是：

```text
m = M * 弹头材料质量系数
v = 60 * sqrt(C / m)
E = 0.5 * m * v^2 = 1800C
每发弹耗 = C 份装药 + M 份弹头
```

钢弹读取实际 `M` 的高爆曲线；铀弹读取实际接触动能和共同贯穿曲线。玩家切换弹头时不重新生成另一套武器数值。

### 4.3 角色只决定机构，不决定数值档位

实弹的角色由单发规模、持续频率、峰值频率和 burst 形态共同判定：

- `Rapid`：连续机构，不逐发强制热锁；
- `Heavy`：单发机构，每发热锁到零；
- 冲突项进入审计，使用固定评分与显式覆盖，不按 Def 名称猜测。

两类都可以得到远超现有四门舰炮的 `C`、`M`、散热和热容。角色不隐含小／中型模板或硬上限。

### 4.4 时间尺度与热循环

原版秒数先通过一组全局、单调、无平衡封顶的时间尺度曲线，得到目标：

```text
N'      Delta-V 热循环内的目标发数
delta' 目标发射间隔
R'      一轮射击后的目标休止时间
B' = (N' - 1) * delta'
```

该曲线只转换战斗时间尺度；弹药和热量不在这里任意指定。源完整 burst 周期统一读取为 `(N-1) × 原连射间隔 + Verb 瞄准 + 炮塔平均瞄准 + burst 后冷却`；冷却从最后一发完成后开始，不能把内部间隔误乘 `N`，也不能漏掉继承的炮塔瞄准。原版每 15 tick 的自动索敌检查只是调度延迟，不计入武器硬件周期。Mini-turret、Autocannon、Uranium slug 的声明周期分别为 `326/274/222 tick`。`N'` 对原 burst 作次线性但不封顶的扩展，使原版少量 burst 进入太空后成为数十发弹流，同时让 20 发、100 伤害、3 秒冷却等极端武器继续得到更高的目标 burst 与吞吐。

每发热量由装药决定：

```text
Hshot = k_family * C
```

速射机构随后由能量守恒式反解散热与热容：

```text
CoolingPerSecond = N' * Hshot / (B' + R')
HeatCapacity     = N' * Hshot - CoolingPerSecond * B'
```

实现时统一秒／tick 单位并按离散开火时点复核误差。连续武器若目标平均热流不低于开火热流，应稳定射击而不伪造热锁。

重炮不把 `N' = 1` 代入速射守恒式，也不从源 cooldown 直接反解出可以任意高效的散热器。它先解析单发装药，再解析重炮散热硬件，最后由生产热锁公式导出间隔：

```text
N' = 1
Hshot = 4C
HeavyAreaCooling(A) = 8 * sqrt(A)             // 2×2 = 16，3×3 = 24
SourceChargeFlow = C * SourceSustainedRate
SlugChargeFlow = 24 / (3.2 + 0.5) = 24 / 3.7
Cooling = HeavyAreaCooling(A) * SourceChargeFlow / SlugChargeFlow
IntervalTicks = ceil(Hshot * 60 / Cooling)
HeatCapacity = Hshot
```

显式时间倍率以散热硬件的反倍率实现，显式散热倍率直接作用于 `Cooling`；最终间隔仍只能由 `Hshot / Cooling` 得出。面积曲线与源装药吞吐倍率均单调且不封顶，所以离谱单发重炮仍可得到离谱散热能力；但相同面积和归一化源强度下，重炮的 2×2／3×3 散热锚 `16/24` 必须低于速射的 `40/85`，并且每发都设置 `lockEveryShot`、冷却至零才能再射。Uranium slug 的来源吞吐使用完整 `222 tick` 声明周期归一化；生成后的完整热锚仍是 `C/M=24/24、Hshot=96、Cooling=16、Interval=360 tick`，而不是把原版 192-tick 纯 cooldown 或约 240-tick 运行调度延迟直接当成 Delta-V 热循环。

速射散热和热容不对齐现有四炮；极端高装药、高持续频率速射武器必须同时得到极高每发热量、极高散热、极大热容和极高弹药吞吐。

### 4.5 弹仓与后勤

自动实弹炮增加真实的 Delta-V 弹头、装药和 `CompSpaceWeaponMagazine`。若源炮塔由 `CompRefuelable` 逐发消费，先从最终 Def 读取 `fuelCapacity` 和 Verb 的 `consumeFuelPerShot`，得到能够完成的整发数；这保留原炮塔的射击次数，而不是保留原补给物的质量或数量：

```text
S = floor(SourceFuelCapacity / SourceConsumePerShot)
HeadCapacity       = max(S * M, N' * M)
PropellantCapacity = max(S * C, N' * C)
```

Mini-turret、Autocannon、Uranium slug 的 `S` 分别为 `60/90/30`，因此在 `C/M=1/1、4/2、24/24` 时最终来源基准分别为 `60/60、180/360、720/720`。两仓分别取整并校验至少能提供 `N'` 个完整装填；即使单发 `C/M` 极高，也不得出现满仓不足一发。来源没有可识别的有限逐发弹容时，才用原面积基准与完整目标 burst 取较大值。火力不按持续 DPS 或期望作战时长继续赠送储量。新建炮塔仍为空仓，补给目标默认仓容上限，扩容不生成任何弹药。每发成功提交后一次性扣除完整 `C/M`，失败发射零消费。

目标热循环被判定为可无限持续时，仍使用 profile 中已解析的有限 `N'` 作为最低补给批次，不以“无限 burst”生成无限仓容。显式覆盖改变 `N'`、`C` 或 `M` 时必须重算两仓容量。

审计同时输出：

```text
装药吞吐 = C * 持续射速
弹头吞吐 = M * 持续射速
平均热流 = Hshot * 持续射速
满仓理论持续时间
```

这四项以及“满仓完整 burst 数”是极端 Mod 武器是否忠实承担代价的主要验收指标；后者必须不小于 1。

### 4.6 激光

激光使用独立的结果空间曲线生成基础脉冲伤害、目标脉冲间隔、默认／最大功率与逐束能量。伤害、守卫扣容和电费继续按同一功率线性缩放，不增加热循环。源单发强度决定脉冲规模，峰值与持续频率决定脉冲节奏和平均功率需求；极端激光不封顶，但不得出现伤害增长而逐束电费或持续功率不增长。

## 5. Def 注入与运行时接线

### 5.1 Def 生成

在 `GenerateImpliedDefs_PreResolve` 的最低优先级 Postfix 中：

1. 复制可能共享的 `comps`／`modExtensions` 列表；
2. 为合格实弹炮加入 Traverse、双 `CompGunSupply`、Magazine、Tuning、SpaceWeapon 和自动炮塔顶部来源；
3. 为激光加入 Traverse、Tuning、SpaceWeapon 和顶部来源，不增加弹仓；
4. 复用现有 Delta-V 速射／重炮钢弹、铀弹和激光弹体 Def，参数通过冻结的武器实例配置进入共同发射事务；
5. 为每个适配炮塔生成稳定命名的 implied `ShellRenderRuleDef`，外壳使用其真实原版 TurretTop 材质与角度；
6. 写入只读 resolved marker，供 Harmony 桥接、审计和热重载幂等检查使用。

不得修改或克隆源 `turretGunDef`、Verb、Projectile Def；不得在运行时修改共享弹体 Def。

### 5.2 普通炮塔双模桥接

普通 `Building_TurretGun` 不是 `Building_SpaceTurretGun`，仅注入 Comp 会导致原版 Tick 与太空火控并行。桥接必须：

- 太空模式抑制原版自动索敌、强制目标与 `BeginBurst`，只接受 `SpaceWeaponService` 命令；
- 地面模式完全放行原版行为，不消费 Delta-V 弹药或热量；
- 模式切换时清除另一模式的目标／warmup，按已提交状态同步必要冷却，禁止同 tick 双发；
- 自动适配炮塔的 Traverse 只在太空模式接管 TurretTop；地面模式仍由原版更新；
- 原有 `Building_SpaceTurretGun` 行为不回归、不重复拦截。

### 5.3 操作员、射界和外观

- 有 `CompMannable` 的炮塔继续要求实际炮手；原本全自动的炮塔根据源精度生成 `intrinsicAimSkill`，不伪造 Pawn。
- 全向顶部炮塔默认 `fireArcDeg = 360`，射程、散布和转速使用固定单调曲线转换；这些曲线同样进入审计表。
- 炮口位置优先读取原版 turret top offset 和脚印几何；无法可靠得到炮管长度时从脚印边缘生成保守炮口，不从屏幕 Mesh 反推。
- 聚焦图继续画原版炮塔顶部；非聚焦外壳读取同一顶部材质、真实角度和 Delta-V 后坐偏移。

## 6. 分阶段实施与审批门

### 阶段 A：纯推导器与审计，不启用游戏行为

实现不可变源快照、分类、结果空间曲线、`C/M` 反解、时间／热循环公式和覆盖模型；离线扫描原版 Def 与合成极端样本，输出逐武器表。此阶段不向生产 ThingDef 注入任何 Comp。

阶段 A 交付表至少包含：来源、纳入／排除原因、角色、`C/M`、每发热量、目标间隔、目标发数、休止、散热、热容、弹药／热量吞吐、弹仓持续时间、激光逐束与持续能耗。用户审阅锚点和曲线常量后，才进入阶段 B；若需要改曲线或字段，按实施偏差重新提交逐文件计划。

### 阶段 B：Def 注入、炮塔桥接和外壳渲染

## 8. 离线验证与通过标准

阶段 A 必须通过：

1. 同一 Def 在相同最终字段下重复解析得到逐字段一致结果；增删无关武器不改变结果。
2. 增加源单发伤害／AP 不得降低目标 `C/M` 所代表的相应结果；增加持续频率不得降低弹药吞吐或所需平均散热。
3. 合成的“100 伤害、20 连射、3 秒冷却”武器必须比普通原版速射炮具有更高每发 `C/M`、更高每发热量、更高散热、热容和每秒弹耗；不得被钳成现有中型速射参数；两仓满载时必须至少完成其解析后的整轮 burst。
4. 原版三个来源的完整 burst 周期必须精确为 `326/274/222 tick`，并分别生成可供原炮塔完整射击 `60/90/30` 发的固定配比仓容；不得把 192-tick 纯冷却、240-tick 爆炸引信或自动索敌哈希延迟混入声明周期。
5. 由 `Cooling`、`HeatCapacity` 和离散 tick 重放得到的速射 burst／休止误差不超过 1 发和 1 tick；连续目标不得伪造热锁。重炮必须满足 `burst=1`、每发锁定、`IntervalTicks=ceil(Hshot*60/Cooling)`，Uranium slug 精确命中小型重炮 `96/16/360 tick` 热锚，同面积重炮散热锚低于速射且源吞吐提高时仍可无封顶增长。
6. 每发弹头／装药、钢弹爆炸、铀弹贯穿、守卫扣容、动能盾质量响应和激光电费均调用生产入口核对，不复制近似公式。
7. 所有排除类别只给出稳定原因码，不注入半套 Comp，不产生 ConfigErrors。

阶段 B 追加通过：

1. implied Def 热重载／重复调用不重复注入 Comp 或 ShellRenderRuleDef；已有 Delta-V 武器逐字段不变。
2. 太空模式下普通炮塔只由 `SpaceWeaponService` 发射一次；原版 Verb 不索敌、不 burst、不重复扣费。
3. 地面模式恢复原版索敌、强制目标、Verb、原弹药和 cooldown；Delta-V 弹仓与热量不被地面射击消费。
4. 缺任一完整 `C/M`、缺激光脉冲电费、未对齐、冷却或安全预检失败时零发射、零消费；成功时一次提交完整事务。
5. 聚焦与外壳炮塔顶部方向一致，重复切图不改变绝对状态；外壳不从 Mesh 反推炮口或命中。
6. `dotnet build Source/DeltaV.csproj` 对目标版本零错误；完整 `WeaponTuningRegression` 与自动适配审计通过。
