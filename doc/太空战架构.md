# 太空战架构：统一容器碰撞、联合效果与 Shuttle 化跳帮

**状态：现行架构与早期设计记录（更新于 2026-10-24；截击飞控与六推进器布局待游戏内验证）。**
本文是阶段5太空战与 shuttle 化跳帮的专题文档；涉及当前控制行为时以 §6、§9 为准。
护盾当前机制与待测项目以[护盾机制基线](护盾机制基线.md)为准；本文后段仍保留部分早期圆弧盾施工记录，不作为当前机制依据。
核心模型：**「弹体」「飞船」都是抽象概念，不是类型**——代码里只有容器
（SpaceObject）；弹体 = 注册进 `universe.objects` 的、带**弹体 tag** 与弹体 building
的容器；一切命中都走**容器 collider 碰撞 → 取出两侧 building → 双 def + 相对速度
（标量与矢量）的联合效果注册表**（命中判定二值 + 命中后效），**每个参与容器各自
解析自己的后效**。侵入式对接复用真实推进器和 MPC，碰撞与后效共用弹体链；shuttle 与飞船共用同一套
起飞/飞行/降落实现，差异只允许在降落后处理。**旧跳帮舱机制整体退役**（§8）。施工
具体待验证项记在 `doc/TODO.md`；玩家可见入口见 README，单实现位置见 [代码入口索引](代码入口索引.md)。

术语：**容器** = SpaceObject 地图容器（[解耦架构](飞船与SpaceObject解耦架构.md)）；
**船** = 驾驶台认领归属 + 控制域；**弹体（抽象角色）** = 带弹体 tag + 弹体 building
的容器；**联合效果** = 注册表里的两段式碰撞效果（§3.4）；**MiniShip** = shuttle
在飞形态。

## 1. 动机与范围

- 阶段1–4 已验证参考系、连续驾驶、POI 生命周期、对接/分离与解耦重构；阶段5 补齐
  战斗。范围（2026-09-26 定案）：
  - **发射入口 = 归属 controller**：玩家主驾驶台默认自动火控，侧边栏或可配置 B 键
    切换为手动集火；手动会话按鼠标位置瞄准，左键射击主套、右键射击副套激活组。
    自动火控与 NPC 共用选敌组件，所有齐射复用同一转向和发射链；炮手位置与点防独立。
    火控键不占用空格／暂停；弹道受武器散射与炮手技能影响，预瞄只作显示；
  - **武器 = 专用 def 体系**（§5），且**同时携带原版武器 comp**：地表图上作为原版
    防御武器工作（原版机制、不经 SpaceObject）；后续可给原版武器追加本 mod comp 使
    其太空可用（仅预留思路）；
  - **弹道三类**：直射弹、激光（即时）、导弹（制导）——弹道类型与「可否被点防御
    拦截」正交（§3.2）；
  - **统一命中机制**（核心）：容器之间 collider 碰撞 → 根据 collider 获取碰撞的
    **两个 building** → 根据**两个 building 的 def + 相对速度（标量与矢量）**经
    联合效果注册表结算——**对称结算**：每个参与容器各自解析自己的后效（例：射弹
    射入船体——飞船容器的后效是对自己内部图产生破片毁伤，弹体容器的后效是摧毁
    弹体）；
  - **弹体容器注册进 `universe.objects` 并携带自己的 tag**：剪影、星区显示等一律
    按 tag 过滤；数据一致性由同一列表保证（船/shuttle tag 有显示朝向策略、弹体
    基础类型为 Projectile 的普通弹体不被被动阻力减速；将来弹体要上星球仪只是改过滤）；
  - **侵入式对接**：弹体服务接管现有 shuttle 的碰撞任务，飞控使用真实推进器、限时主推加力与截击 MPC；命中后效破拆并调用共同 Gravship 降落链（§7.5）；
  - **碰撞核心自研**（2026-09-26 讨论定案）：宽相位包围域 + 窄相位格网步进 + 弧
    闭式求交，全部经 `SpaceTransform` 现有坐标入口；tick 锁定、零分配、不引入
    Unity 物理代理场景（分析见 §3.3）；将来做物理化碎片场时再独立评估；
  - **点防御**：不受驾驶瞄准控制、自行瞄准**可拦截容器**射击；拦截 shuttle 与
    拦截导弹完全是同一个机制。**可拦截性是结构派生**（2026-09-26 修订）：可拦截
    = 有图（依托内部建筑存在）∧ tag ∈ {projectile, shuttle}——不是 def 上的
    标记字段；
  - **护盾**：独立 `DeltaV_ShieldGenerator` 建筑使用三模式；守卫模式复用原版 `CompProjectileInterceptor` 的容量与圆盾拦截，持续耗电 10 W，断电仍可用已有盾容拦截、恢复倒计时暂停，每累计通电一小时免费充满或提前消耗白银补盾；动能与电磁模式由 `CompSpaceShield` 投射单向有限线盾。原版发生器自身不修改。结算契约见 [护盾机制基线](护盾机制基线.md)；
  - **跳弹是命中后效**：命中判定只决定要不要产生后效；跳弹 = 「产生出射角的相同
    射弹」的一种后效（当前默认实现为消灭无伤，可反弹类型留扩展位）；
  - **刚体碰撞演进路径**：碰撞参与是 tag 级属性（弹体恒为主动碰撞方、普通飞船
    暂不开放）；后续开放飞船碰撞 = 放开 ship tag 的主动参与 + 注册飞船结构件联合
    后效（本质上是舱壁×舱壁的互相毁伤）——弹丸撞船与飞船撞船是完全相同的实现；
  - **shuttle 起飞校验直接取原版 shuttle 发射校验函数的结果**（冷却、乘员等检查
    不在本 mod 二次实现）；**shuttle 与飞船不得出现两套逻辑**（起飞/飞行/降落全
    部同一实现，差异只允许在降落后处理与侵入能力，§7）；
  - **原版复用优先级纪律**：能直接调用原版函数、或经简单 Prefix/Postfix 解决的，
    禁止做镜像（§10）；
  - **跳帮舱改制为小型 shuttle**（§7）；**NPC 来源无关 + dev 验证**。

明确不在阶段5 范围：飞船×飞船碰撞的实际开放、
可反弹弹型的实际实现（留扩展位）、原版 pawn 武器的跨容器桥接、飞船/shuttle 燃料、
开火后效实现（只留接口）。

## 2. 概念与权威数据

| 概念 | 权威事实 | 不承担的职责 |
|---|---|---|
| 容器（唯一实体类型） | SpaceObject：tag、位姿/速度、（可选）图、弹体 building（弹体角色时） | 「弹体」「飞船」只是抽象角色，不是类型分叉 |
| tag | SpaceObject 上可叠加的角色 flags，以 `HasTag` 查询；剪影、星区记账、被动阻力、显示朝向、碰撞主动参与、序列化过滤由对象统一分派 | 不替代派系/归属语义 |
| 弹体（抽象角色） | 弹体 tag + 弹体 building（def/脚印/HP/贴图）+ 服务侧弹体数据（制导/超时/launcher）；注册进 objects；有图型（依托内部 building 实例计算血量并提供贴图，可拦截）/ 无图型（building def 提供贴图，不可拦截） | 不设独立类；不序列化（写档按 tag 过滤）；不被渲染层驱动 |
| 可拦截性 | 结构派生：有图（依托内部建筑存在）且具有 Projectile 或在飞 Shuttle 角色；shuttle 正常及侵入飞控均可拦截 | 不是 def 标记字段；仅 Ship 角色不构成可拦截资格 |
| 碰撞核心（SpaceCollision） | 容器级特性：碰撞面（占用格集 + 护盾弧）、扫掠求交、参与判定（tag）、命中事件（两侧 building + 相对速度） | 不结算效果（只产出事件）；不决定生命周期 |
| 联合效果注册表 | 一切命中后效的唯一来源：键 =（弹体 building def × 对面 building/基架 def），入参 = 相对速度标量 + 矢量（入射角）；每个参与容器各自取自己的后效 | 不持有运行时状态；纯函数式解析 |
| 护盾容量 | 原版 `CompProjectileInterceptor.currentHitPoints/HitPointsMax`，事实驻留护盾建筑 | 太空弧几何是派生缓存（随容器姿态旋转），不是事实源 |
| 图池 | `UniverseManager.MapPool` 通用资源池，弹体以 Projectile tag 和脚印尺寸租用 | 队列/租约不落档；用途标记用于读档重建，契约见对接设计 §13 |
| 玩家火控 | 各船身份锚通过 `ShipCombatState` 保存自动火控／手动集火，默认自动；`ShipFireControl` 供玩家与 NPC controller 共用选敌和齐射意图 | 自动候选共用 §6.1 的有效敌船资格；手动仅所选船的 `SpaceAimController` 采样鼠标；火控提供明确请求，武器层执行转向与发射事务 |
| 自动战斗机动 | `ShipAutoManeuverControl` 供玩家与 NPC controller 共用交战姿态选择和持续战法执行 | 玩家 controller 的自动任务之一；选中时替换旧任务及其同步计划，任意驾驶键可暂停，目标暂缺时显示“寻找目标” |
| 武器组 | 两套（主/副）× 每套 1–6 组；武器 comp 持久字段（套别 + 组号）+ 每船两套激活位 | 不存炮手 job 状态 |
| 点防御（PD） | 武器 comp 的瞄准模式；所在船的 `ShipFireControl` 按武器实例保存锁定、重选并请求射击 | 不受驾驶或玩家瞄准状态控制；不占玩家瞄准 |
| 武器（CompSpaceWeapon） | 持久配置：瞄准模式（齐射/PD）、组别、弹道、射界、散射、冷却、挂件/加速连接点与安全限制 | 同图/地表战斗可选走原版炮塔；共享炮手、转向和默认弹仓门禁 |
| 炮手预留 | `CompSpaceWeapon.reservedGunner` 实例持久字段（含「不指定」） | 只是分配偏好；实际操作人只读原版 `CompMannable`，操作格只读原版交互格 |
| MiniShip（shuttle 在飞） | SpaceObject 容器 + `ShipBase` 的 `ShuttleShip` 实现；角色为 Ship + Shuttle，侵入时追加 Projectile | 不使用基架归属域；停靠后仍为船成员，但不保留独立容器或驾驶宿主 |

## 3. 统一容器碰撞与联合效果（核心）

### 3.1 弹体与飞船是抽象角色，不是类型（已定）

- 宇宙碰撞消费 **SpaceObject 容器的角色**。「弹体」「飞船」「攻方/守方」由
  **tag + 注册效果 + 服务数据** 组合；共同船体接口及不同实现见
  [飞船与SpaceObject解耦架构](飞船与SpaceObject解耦架构.md) §2，碰撞不依赖具体船型。
- 弹体角色的三要素：弹体 tag（注册进 `universe.objects`，经 `AllocateOwnerId`
  正常发号——单一计数器纪律不变，弹体发号量大但 int 空间在游戏时长内无实际风险）、
  弹体 building（身份载体：def 作注册表键、脚印作 collider、HP 作受击、贴图来源）、
  服务侧弹体数据（制导律、超时、launcher/equipment 引用）。
- **tag 分派的行为**（单点分派，不散写判断）：
  - 剪影/星球仪/星区记账按 tag 过滤（弹体不进剪影与星区计数；将来弹体要显示在
    星球仪上只改过滤，机制已就绪）；
  - 显示朝向策略按 tag（船容器与 shuttle 按自身位姿角；无姿态角的点状弹体按
    速度方向）；
  - **被动阻力按 tag 豁免**（弹体不受被动阻力减速；shuttle 与船照常受阻力）；
  - **碰撞主动参与按 tag**（见下）；
  - **序列化按基础 tag 过滤**（baseTag 为 Projectile 的纯弹体是瞬态成员，写档时
    从 objects 过滤视图剔除；侵入 shuttle 只追加运行时角色，仍保存艇体与地图）。
- **碰撞参与 = 主动方角色（已定口径）**：projectile tag 容器恒为碰撞**主动方**
  （移动的攻击体）；shuttle/船 tag 不作主动方，但**任何有碰撞面的容器都是合法
  被撞目标**（飞船被弹体命中正是此路径——目标资格只看有无碰撞面）。**后续开放
  飞船碰撞 = 允许 ship tag 作主动方 + 注册飞船结构件联合后效（舱壁×舱壁互相
  毁伤），不改核心。**
- 侵入模式的 shuttle = **弹体碰撞服务接管 + 追加 Projectile 角色**，保留 Ship 与 Shuttle；
  弹体工作项负责目标解析和扫掠，MPC 负责真实推进，面板中止或目标失效时交还原艇体；命中后效解除接管并
  用共同 Gravship 链落地。baseTag 保持 Container，读档后从船体重建 Ship／Shuttle 角色并按飞船继续存在。

### 3.2 建图规则与可拦截性（已定，结构派生）

对象角色由船体 `RolesIn` 提供并缓存，点防资格只读缓存 tag；基架船不因共用 `ShipBase` 而获得 Shuttle 角色。成员发现与武器设备查询也复用缓存，结构事件立即失效；完整战术 AI 不以有无驾驶台或当前武器数量排除船型。角色失效、武器和几何的共同能力入口见 [解耦架构 §2](飞船与SpaceObject解耦架构.md#2-概念与权威数据)。

- **可拦截 ⇔ 有图，对弹体成立的原因是结构判据**（2026-09-26 修订）：可拦截 =
  有图（依托内部建筑存在的 SpaceObject）∧ tag ∈ {projectile, shuttle}。弹体 def
  只决定**有图/无图形态**（有图型 def 走图池、无图型轻量）——有图弹体（projectile
  tag + 图）可拦截，无图弹体不可拦截；**不存在「可拦截标记」字段**。
- 与弹道类型正交：低速重弹类**直射弹**可以做成有图型（可拦截）；高速轻**导弹**
  可以做成无图型（不可拦截）。
- 有图弹体的图大小 = 弹体脚印（包括实际 1×1、2×1）；按原版占位矩形反求建筑根格，保证奇偶尺寸完整落入图内。原 2×2 下限已取消，单格生成的 RNG 修正与验收边界见 [对接设计 §13](对接与舱外作业重构设计.md#13-第一阶段实现与验证记录)。有图 = 弹体 building spawn 于自己的小图，
  **受击走与飞船完全相同的图内结算链**——血量由 building 实例计算、贴图由实例
  提供；无图 = **不实例化 building**（实现口径：def 即事实源，渲染/碰撞面/
  注册表键/HP 兜底均读 def；HP 只有有图受击链需要实例），极轻量。
- **性能/GC 用对象池解决**：地图复用交给通用池，弹体服务仅持有本发租约、通过回调生成/清除自己的 Building；短命的弹道工作对象仍有上限 256 的独立池，每发 SpaceObject 身份与 ID 新建。填充成功后注册容器；帧边界注销容器后归还租约，有残留内容时保留地图并报告，不能删图兜底。通用池的身份、容量、存档与失败契约只在上述对接设计维护。**池内空闲图不作为独立 POI 纳管**；
  在飞弹体图按 tag 豁免距离休眠/归档。
- sourceMap 锚专用宿主口袋图（与船图同契约，不占 tile）。

### 3.3 碰撞面与扫掠求交（自研，已定案）

- **实现路线定案（2026-09-26 讨论）**：自研单实现——宽相位包围域 + 窄相位格网
  步进 + 弧闭式求交。依据：负载形态为「几十个移动体 × 数千格占用集」的数组下标
  查询，无凸体/关节/堆叠需求；Unity 物理需要维护平行欧氏代理场景（第二套坐标
  表示，违反坐标纪律）与结构变化时的 collider 重建 churn；RimWorld 本体视线/
  寻路同为手搓格网算法。将来做物理化碎片场再独立评估。
- **占用格集**（碰撞面）：cell →（建筑引用 | 基架 | 自然岩石）。已生成建筑
  参与碰撞候选，包括不绘入外壳的炮塔和内部设备；按原版 `building.isPowerConduit`
  排除普通／隐藏电缆，它们不是保护基架的碰撞面。隐藏电缆原版免疫攻击，
  若作为实体遮挡会使下方基架永久无法切除；同格墙体等其他建筑仍正常保护基架。
  外壳仍只绘实体结构或显式规则。
  同格建筑优先于基架，重叠建筑优先墙、再按掩体效果选取。分类收口碰撞核心内部，
  与 `ShellPicking`（选择级）不得互调。**弹体的碰撞面 = 弹体 building 脚印**
  （1×1 或 2×1 的扫掠块）。
- **护盾线段**：目标发生器的守卫半径由实例拦截器 Props 读取；动能／电磁模式线段由 `CompSpaceShield.GetSegment` 按建筑朝向、相对角、距离和长度确定。碰撞与显示消费同一几何；从正面进入背面时按模式碎裂实弹或折射激光，导弹和侵入 shuttle 穿越。其他未配置此 Comp 的拦截器仍可沿原有圆弧路径工作。
- 缓存失效：统一结构版本 + 建筑增删 + 护盾供电轮询，无时间重扫；完整重建前
  必须清空旧格数组，避免已毁结构残留。宽相位圆按占用包围盒半对角线构造，必须覆盖四角；
  休眠图冻结保留；容器注销释放（[AGENTS 缓存纪律](../AGENTS.md#架构不变量)）。
- 独立碰撞调试开关绘制全部可见对象**实际缓存**的半透明占用格与宽相位包围圆；不另建
  实时重算碰撞体，显示内容就是命中系统正在消费的事实。
- 求交（守方局部坐标，`SpaceTransform.MapPointToUniverse/UniverseToMapPoint`）：
  1. 宽相位：主动方本 tick 扫掠块 × 守方包围域（占用包围盒与弧半径取大）；
  2. **先弧后格**：扫掠块 × 弧环段求交（`GenGeo.IntersectLineCircleOutline` 同款
     语义 + 弧角限制）；命中弧 → 事件携带护盾建筑；
  3. 0.5 格步进采样占用集：建筑以原版 `fillPercent`（掩体效果）为命中概率，墙恒中；
     基架不读掩体效果，按匹配的弹体×基架效果 Def 的 `substructureHitChance` 判定。一次扫掠对同一建筑或基架格只
     掷一次；建筑放行后弹体继续穿过，不判定其脚下基架。只有没有存活建筑覆盖的基架可参与命中。
- 事件附带几何事实（一次性计算，参与方只消费不重算）：命中 universe 点、**两侧
  building 引用**（主动方弹体 building、守方被撞 building/基架/护盾）、入射方向、
  相对速度**标量与矢量**（`v_攻 − v_守`，切空间）、入射角（入射方向与被撞面法线
  夹角；基架格以竖直法线抽象）。解算唯一入口 `SpaceTransform` 扩展，调用点禁止
  自行点乘。
- **己方规则（跨墙感知）**：顶部炮塔弹排除己方容器；舰中固定武器弹包含己方容器
  （自伤是特性）。排除从炮口格自身起算。
- 驱动节奏（**tick 顺序调整，随施工更新 [代码入口索引](代码入口索引.md)**）：`Projectiles（记录扫掠起点、普通导弹制导）→ Autopilot
  → Controls / Approach → 尚未推进的容器积分 → SpaceCollision 扫掠与结算`——先动后撞，消除一拍滞后；结算中的注销/销毁/归池经 `QueueFrameAction`
  帧边界（禁止在扫掠 foreach 内执行）。弹体与一切容器共用同一条积分链（数据
  一致性）；施工时如主循环对无推进容器有额外开销，做 tag 快速路径，不改语义。

### 3.4 联合效果注册表：命中判定（二值）+ 命中后效（已定）

基架外污渍清理由 `SubstructureDamageUtility.CleanInvalidFilth` 统一执行：毁伤地形与建筑后效完成后、Gravship 剥离源格后，按最终地形的真空限制和原版 `FilthMaker.TerrainAcceptsFilth` 清除非法污渍；毁伤复用散落服务的已有帧边界事件再检查受影响格，覆盖迟到后效。当前游戏的 Space 继承 `NaturalTerrainBase` 后仍含 `Unnatural` 污渍掩码，因此原版地形变更清理会接受建筑碎石，而生成入口另有真空限制。修复限于 Delta-V 毁伤／搬运，不改全局 Def、不周期扫图；合法基架／天然地面污渍保留，人员、物品和尸体走原搬运／散落链。

- **命中概率**：建筑按目标类型和掩体效果判定，基架读取匹配的联合效果 Def；命中后的效果也来自注册表（XML Def 可扩展）。契约两段：

```text
联合效果（键 = 弹体 building def × 对面 building/基架 def；命中后效读取相对速度标量+矢量）
├─ 命中判定（HitTest，二值）
│   ├─ 产生后效 → 进入后效段
│   └─ 放行穿过 → 无后效，弹体继续飞行（建筑掩体概率或基架特殊概率）
└─ 命中后效（Apply）—— 每个参与容器各自解析自己的后效，种类包括：
    ├─ 毁伤：对自己内部图施加（原版原语 TakeDamage / GenExplosion /
    │   DamageInfo.armorPenetration 携带护甲穿透；可配置逐层结构毁伤；instigator = launcher，敌意与
    │   战斗日志走原版链路）
    ├─ 自毁：弹体容器销毁（有图则清图归池，帧边界）
    ├─ 生成弹体：跳弹 =「产生出射角的相同射弹」的一种后效（守方图结算侧生成；
    │   当前默认实现 = 消灭无伤，可反弹类型留 def 字段与生成出口，阶段5 不实现）
    ├─ 放置：侵入 shuttle 的后效 = 把 shuttle（舱体 building）放置在撞击位置
    │   **靠船体内侧一些**（沿内法线偏移）——侵入共用弹体碰撞与后效链
    ├─ 护盾容量消耗：写原版 comp 字段（currentHitPoints -= 消耗量；EMP/击破/
    │   重充语义沿用原版状态机）
    └─ （未来）飞船结构件撞击后效（本质上是舱壁×舱壁的互相毁伤）
```

- **注册的效果示例**（用户定案）：
  - 激光 + 舱壁：判定 = 产生后效；后效 = 按入射角决定伤害；
  - 射弹 + 舱壁：判定 = 产生后效；后效 = 高耐久舱壁 ∧ 入射角太歪 → 跳弹（当前
    默认消灭无伤、可反弹扩展位），否则伤害随相对速度/入射角；
  - 激光／速射弹 + 基架：大多数格子放行；少数命中时按本发实际伤害与基架损毁阈值掷一次损毁概率，弹体停止。基架不储存累积耐久；
  - 重炮弹 + 基架：按拦截概率判定，命中保留爆炸及周边剥离；完整轨道弹命中基架则按损毁阈值消耗贯穿预算并继续，不再爆炸扩孔。未命中不消耗预算；
  - 弹体 + 太空线盾：逐层计算折射或全反射，重弹超过自身碎裂角时按类型变成新的 projectile；激光在发射 tick 内继续分段扫掠。实际效果支付本层蓄电，欠额则当前弹直行、本层短暂失效。导弹和侵入 shuttle 穿越，由点防另行处理；
  - 侵入 shuttle + 船壳：判定 = 产生后效；后效（shuttle 侧）= 放置于撞击位内侧
    偏移 + 容器销毁；（船侧）= 撞击毁伤/清障（数值 §15）。
- **船体贯穿**：护甲穿透不等于贯穿深度。重炮继续使用 `ImpactOutcomePart.penetrationLayers` 的三格局部轮廓（首格宽三格，空格占轮廓距离）；速射／激光及轨道破片只打首个结构。完整轨道弹以 `penetrates` 声明预算贯穿：`SpaceImpactEffects.ApplyToDefender` 通过原版 TakeDamage 施伤，仅在建筑实际销毁后按实际扣血返回剩余比例；存活／免伤建筑截停。Bullet 建筑倍率为 1，不继承 Bomb 的不可通行建筑 ×4。当前候选仍只含建筑和基架，不新增人员直击。
  `SpaceCollision` 把比例一次性乘入本弹 `damageScale`，从原交点继续同一盾／建筑求交链，空舱不消耗预算，遇到内层盾仍照常结算。同心盾不跳过；零盾容、已毁建筑不重复吸收。`SpaceProjectileService` 将剩余比例写回同一弹体供后续 tick 使用，不额外降低速度／穿甲系数重复扣预算。单 tick 最多处理 128 次续穿／折射，超出时停在最后交点，下 tick 继续，不凭空穿过未处理结构。
  护盾表只在盾面求交时使用；发生器实体按普通建筑承伤，防止零盾容设备无限吞弹或返还全部预算。动能碎裂仍由原弹 Def 选择独立破片，破片不继承母弹倍率及贯穿能力。数值与验收口径见 [武器伤害与费效比基线](武器伤害与费效比基线.md)。
- **基架承伤顺序**：存活建筑保护其全部占用格内的基架，建筑先承伤；仅建筑损毁后，裸露基架才可被直击或周边破片摧毁。`SubstructureDamageUtility.CanDamage` 复用实时 `SpaceStructureRules.ClassifyCell`，直击、破片和纳管地图的原版地形毁伤共用此门禁。原版爆炸仍负责建筑伤害，未命中建筑的弹体不把伤害转给其脚下基架。命中、周边破片和采矿后效显式调用 `SubstructureDamageUtility.TryDestroy`：复核建筑保护，移除基架后统一清除临时层、地板、该格屋顶和残留建筑（含电缆，多格建筑整件销毁），保留真实底层太空／天然地面。建筑列表取快照，跳过已被连带销毁或移走的插件。原版 `Notify_FoundationDestroyed` 仅在纳管地图记录毁伤前状态，完成原版毁伤后调用同一 `CompleteDestruction` 清理方法，保留原版特效和自动重建。通用 `RemoveFoundation` 补丁只同步归属，不承担地板或建筑、屋顶毁伤；手动拆除、普通地形操作和起飞搬运不触发联动销毁，非纳管图保持原版行为。不新增基架耐久或持久状态。
  离线入口：`scripts/SubstructureDamageRegression/run.ps1 -GameRoot <游戏目录> -HarmonyPath <Lib.Harmony 的 net8.0/0Harmony.dll>`。验证真实补丁绑定、地形与屋顶清理、电缆／重叠建筑联动销毁、多格建筑保护、建筑放行后的碰撞候选及搬运／非纳管图边界；隔离 Unity 地图通知、建筑死亡后效、自动重建任务及 DLC 配置读取，不替代游戏内爆炸与存读档回归。
- **兜底规则（已定）**：碰撞结构任意一方未注册效果时，**按同等耐久的舱壁结算**
  ——把被撞物视作与其耐久（maxHitPoints）同等的舱壁走标准舱壁效果（伤害随相对
  速度/入射角、满足跳弹条件时跳弹）；耐久只换参数，不换规则。
- 建筑命中概率取原版 `ThingDef.fillPercent`，墙恒中，点防专用激光对有图制导导弹
  跳过掩体概率且不加散布；基架的拦截概率由弹体×基架效果 Def 指定，命中格损毁概率 = `clamp01(本发实际伤害 / substructureBreakThreshold)`。相对速度只参与命中
  后毁伤，不参与拦截概率。加速段明确声明 `fillPercent=0.6`；
  爆炸波及由 `GenExplosion` 原生处理，不 patch 原版 verb/射击/拦截代码。

### 3.5 结算：对称分发，各容器各结自己的后效（已定）

- **碰撞事件对每个参与容器对称派发**；每个容器用同一 def 对（自己的弹体/结构
  building def × 对面的 def）从注册表解析**自己的**后效并执行。「弹体被摧毁」
  「飞船受破片毁伤」不是攻守两套逻辑，是**两侧容器各自后效的输出**：
  - **射弹射入船体**：飞船容器的后效 = 对自己内部图产生破片毁伤（命中位爆炸/
    递减摧毁基架/人员杀伤，随 def 对与相对速度解析）；弹体容器的后效 = 摧毁
    弹体（销毁、有图归池）。
  - **点防激光命中导弹**：导弹容器（守方）的后效 = 对自己的图 TakeDamage 弹体
    building（HP 归零 → 帧边界销毁容器、图归池）；激光临时容器（攻方）的后效 =
    自毁。**与飞船通用的受击逻辑即此链**——导弹没有特殊受击代码。
  - **点防激光命中 shuttle（正常或侵入飞控）**：shuttle 容器的后效 = 对自己的图
    TakeDamage 舱体 building；激光临时容器自毁——与打导弹完全同链（可拦截性同判据）。
  - **侵入 shuttle 撞船壳**：艇体从弹体服务释放；船容器按联合效果承受撞击毁伤，
    再在两排三格破口中经共同 Gravship 链接收艇体（§7.5）。
  - **（未来）飞船撞飞船**：双方各自对自己内部图解析结构后效（舱壁×舱壁互相
    毁伤）——同一实现。
- 一切销毁/注销/图归池经 `UniverseManager.QueueFrameAction` 帧边界；同 tick 多
  命中按事件顺序结算，一容器销毁后跳过其后续事件。

## 4. 弹道系统

### 4.1 直射弹与导弹

- 直射弹：恒速直线（球面切空间步进，`OrbitSphere.Move` 唯一入口），无目标概念；
  有图型（可拦截）/无图型（不可拦截）由弹体 def 决定（低速重弹类可做成有图型）。
- 导弹：`SpaceProjectileService` 根据目标位姿与速度，以有限加速度修正自身速度；
  接管式跳帮艇可指定目标 Map 局部点，仍使用真实推进器与 MPC。def
  配置期望接近速度与机动；目标由火控在发射请求中指定，身份及手动射线锁定规则见 §6.2。导弹
  同样可做成有图型（可拦截，默认）或无图型（高速轻导弹，不可拦截）。
- 超时（def/全局上限）未命中 → 自毁（无后效）。
- 服务归属：`universe.Projectiles`（新实例服务，取代 `universe.BoardingPods`
  槽位）：弹体创建/注册、制导、超时、碰撞调度对接、渲染、通用图池租约、ResetFlow。
  积分与被动阻力豁免走主容器循环按 tag 分派（§3.3）。

### 4.2 点防御（PD，已定）

- PD 是**武器的瞄准模式**（comp 字段）：不受驾驶开火控制、不参与玩家瞄准与预瞄，
  自动索敌开火。
- `ShipController` 调度本船火控；逐图武器索引用于空态早退。每船 `ShipFireControl` 在本船齐射之后遍历一次对象表，以有效地图、Projectile／Shuttle tag 和相对本船的敌对关系建立本次共同候选；无敌对候选时跳过全部拦截武器（牵引器另用散落候选）。同 tick 齐射生成的弹体可立即参与筛选；候选缓冲在本次调用结束清空，不保留位置快照。
- 点防锁定和下次空锁重试 tick 只保存在 `ShipFireControl` 的逐武器状态表中。有效目标持续沿用，冷却期间仍转向；目标失效当 tick 重选，只在共同候选内检查射程和接近优先级。找不到射程内目标时等待 30 tick 再试，不逐 tick 空搜；全船无候选时清空锁表，下次出现敌对候选立即恢复搜索。武器移除、结构换属、改派系、模式切换、地图卸载和 controller 清理都释放相应状态；主台继任的绑定会剔除已不属于该船的武器锁定。牵引器保留自身 30 tick 重试节拍。
- 同船点防在本次调度内按成功发射的弹体命中伤害估值临时预留有图弹体的剩余 HP。已有锁定目标被预留火力覆盖时，后续武器转向其他射程内目标；若没有其他未覆盖目标，仍可继续集火。预留在下一次共同候选筛选时清空，不写档；冷却、失效或未能开火的武器不占火力名额。shuttle 不使用弹体 HP 的覆盖判定，仍按来袭优先级集中拦截。
- 1×1 点防御激光炮的 Def 将该模式固定为点防御：内置 16 级火控，无炮手、弹仓或插件槽；原版同图炮塔不自行索敌，武器组仍负责启停。其他武器的齐射／点防切换不变。
- 索敌（结构判据）：射程内扫描敌对的**可拦截容器** = 有图 ∧ tag ∈ {projectile,
  shuttle}——含导弹、有图直射弹、正常飞控 shuttle（shuttle tag）与侵入飞控
  shuttle（projectile tag）。**拦截 shuttle 与拦截导弹完全是同一个机制**：点防射束 ×
  目标容器 collider 碰撞 → 联合效果 → 两侧各自后效（目标图内 building 被毁、
  容器销毁；射束临时容器自毁）。
- 射击：有飞行时间的弹体解算截击提前量；普通点防目标仍走炮手/插件散布。专用
  点防激光弹体对有图制导导弹跳过散布与掩体概率，并在碰撞结算 tick 对准导弹现位；
  就绪判定（武器组/炮手或插件/供电弹药/冷却）仍同齐射武器。
- 瞬时激光瞄准目标当前位置；索敌射程从武器炮口到目标碰撞包围域计算，不随所在舰体尺寸变化。当前点防激光以 50 格射程、110 tick 冷却、每发 1 W·d 蓄电与 10 点直击伤害为初始标定；25 HP 高爆导弹需要三次命中。束宽由弹体 Def 指定并复用激光渲染。
- 优先级：来袭容器按预计接近时间排序，非来袭按距离兜底；资格独立于自动敌船的推进器门禁。
- 性能分析的 `pdCandidates` 记录共同候选筛选，`pdSearch` 记录逐武器的候选内选取；两者都包含在 `pointDefense` 中。`pdInterceptTicks` 统计至少一船发现敌对拦截候选的 tick 数。离线覆盖多武器共用一次筛选、友方对象早退、有效锁延续、同 tick 失效／新候选、空锁重试，以及 25 HP 导弹在预留 20／30 点伤害时的继续集火／分散与单目标兜底；实际拦截率与 TPS 待游戏内验收。

### 4.3 激光（即时链）

- 激光弹体同样有弹体 building（注册表键与效果载体），无图型（即时，不可拦截）；
  其「飞行」= 发射 tick 内的一次即时扫掠（炮口 → 散布方向 × 最大射程），经同一
  碰撞核心与联合效果链（先弧后格；相对速度取发射瞬间双方速度）；命中 → 后效
  结算、弹体容器随即销毁；未命中 → 射线消失。
- 视觉：炮口 → 命中点聚焦帧线段（约 15 tick 渐隐，纯表现不持容器）；音效 def
  配置。激光不可被拦截（即时）、可被护盾弧吸收。

### 4.4 渲染、音效、生命周期与存档

- 弹体渲染统一 = 弹体 building 的 def 图形经 `FocusedDrawPosition/
  FocusedMeshRotation` 投影到聚焦帧（ShellRenderer 前景层槽位、池化）——有图/无图
  弹体同一路径（图形取自 def，不读图）。激光另加光束线段（线段方向 = 两端点
  显示系差向量，换基回宇宙角后走唯一变换入口）。命中聚焦容器自身的后效在聚焦
  图内由原版产生。**弹体 mesh 自身不随速度向旋转**（2026-09-27 用户定案）：旋转

### 4.5 测试场景重建与清理顺序

`ShipTestScene.Create → UniverseManager.BeginSceneReset` 是双船场景重建入口。重建期间保持暂停，停止宇宙 tick、驾驶输入与增量生成器的自动推进；重复请求复用正在进行的重建，不再创建第二套流程。

1. 在现有 `QueueFrameAction` 消费点排空旧动作；动作中新入队者仍在下一帧执行，后续阶段必须等待队列再次为空。已开始的增量地图生成经现有同步完成入口收尾，再取消尚未开始的生成任务，避免销毁尚未完成原版初始化的地图。
2. 停止驾驶／对接／自动驾驶等流程，调用弹体 `ResetFlow`。此时旧容器仍在注册表；活动弹体和已经死亡但待回收的弹体均完成同一收尾链，侵入 shuttle 先解除接管。弹体小图和闲置图池通过 `SpaceLifecycleService.DestroyPocketMap` 销毁。
3. 弹体及其后续动作完成后，销毁其余旧地图、注销容器并清理宿主下的孤儿口袋图。实际销图复用原版 `PocketMapUtility.DestroyPocketMap → Game.DeinitAndRemoveMap → MapDeiniter.Deinit / Map.Dispose`；原版销图通知在旧身份仍可解析时通知弹体服务，并排队注销容器。再次等待销图产生的后续动作完成，才清理运行时缓存。重建路径不得用清空帧队列代替执行收尾；单个动作抛错时保留该批尚未执行的动作。
4. 最后排入生成新场景的原版长事件。生成异常在事件内部记录并排队清理，使事件正常返回，允许原版 `Map.FinalizeInit` 的结束回调执行。成功后的武器／controller 重建与聚焦交接，以及失败图的销毁，都在原版初始化回调完成后的帧边界进行。重建结束保持暂停，由玩家恢复运行。

这些流程状态不存档；读档仍丢弃旧运行时回调，不与同游戏实例的场景重建混用。离线回归入口为 `scripts/NpcRetreatRegression/run.ps1`，`SceneResetChecks` 覆盖生产 DLL 的弹体收尾和重建阶段顺序；Unity 地图生成、绘制资源析构与完整游戏交火重建仍按 `doc/TODO.md` 验收。

## 5. 武器体系（专用 def，双模）

### 5.1 def 与 comp 结构

武器归属使用 `CompSpaceWeapon.OwnerShip` 的独立运行时缓存：首次通过 `ShipRegistry.ShipOf(..., requireWholeFootprint: true)` 校验完整脚印，之后按统一结构版本、地图、位置／朝向及有效句柄复用；无归属结论同样缓存。未注册地图不缓存。出生、移除、地图释放和换档经 `ClearRuntimeModel` 清理，主台变更经既有 `ReconcileOwner` 推进结构版本。齐射／点防在每次分派前读取一次主副组掩码，逐炮直接判断当前套别和组号，不再为组别重复解析所属船。组别不按结构缓存，切换立即生效；归属缓存不依赖连接布局，纯指向不因此查询挂件或弹药。

武器 = 建筑 ThingDef + **双模 comp 组合**：

| 维度 | 载体 | 取值 |
|---|---|---|
| 原版武器能力 | 可选原版炮塔/verb comps | 地表与太空图同图战斗由原版负责；没有这些能力的 Def 不凭空获得同图战斗 |
| 瞄准模式 | CompSpaceWeapon | 齐射（随瞄准模式射击）/ 点防御（自动索敌） |
| 组别 | comp 持久字段 | 套别（主/副）+ 组号（1–6） |
| 弹道类型 | 武器 def → 弹体 building def 引用 | 直射弹 / 激光 / 导弹 |
| 建造位置 | ThingDef 与 PlaceWorker | 炮塔、导弹架与轨道炮部件按各自脚印放置 |
| 炮手 | 原版 `CompMannable + ManTurret` | 原版持有操作人和岗位；有效自瞄挂件或 Def 内置火控可替代开火需求，不伪造操作人 |
| 转向 | `CompSpaceWeaponTraverse` | 当前角、每秒转速和开火容差；仅在 controller 或原版炮塔有目标时接收逐 tick 转向命令，暂停时不转 |
| 弹仓 | `CompSpaceWeaponMagazine` + 原版 `CompRefuelable` | 默认仓优先级 0；挂件仓默认 1；发射成功后才消费 |
| 挂件 | `CompSpaceWeaponAttachment` | 以非 Edifice 覆盖在武器或加速段脚印内声明的旋转槽位；炮塔由同格 Edifice 派生宿主，加速段由同格 ThingGrid 派生；允许 Def 与挂件自身允许宿主表双向限制；可多选启停 |
| 加速件 | `CompSpaceRailgun` | 修改出膛速度、位置及本段逐发耗电，声明两侧电容槽；核心开火服务不认识具体武器家族 |
| 安装性质 | comp 字段 | 顶部炮塔排除己方容器；固定武器保留自伤并默认作己方实心结构路径预检 |
| 射界 | comp 字段 | 锁定弧与发射轴分离；实例分别设置手控与自动开火偏离角，射弹始终沿当前炮口或固定轴发射 |
| 散布 | comp 字段 + 炮手/插件 | 基础散射角 × 技能偏差系数（§5.4） |
| 功耗/弹药 | 原版电网/燃料 comp + `SpaceWeaponShot` | 所有炮塔有低持续功耗；实弹射击只耗材料，激光逐发耗电或由附加电容储能代付，轨道炮逐发同时耗材料与电 |
| 冷却 | comp 字段 | tick 数 |

- 弹体 building def（武器或弹仓引用）：脚印、HP、**有图/无图形态**（可拦截性由结构
  派生）、速度/制导/超时、冷发射时长与速度倍率、锁定弧、激光最大射程和效果挂点。
- controller 只提交 `WeaponControlCommand`：本图局部瞄点或本 tick 已解析目标、触发意图与手动／自动／点防来源。权限、输入、武器组和战术选择属于控制层；`ShipFireControl` 保留敌舰选择、点防共享候选和逐武器锁，只负责分派命令。武器经 `SpaceWeaponService.ApplyControl` 统一执行转向、就绪、射界／偏差、安全、发射和扣费；导弹手动射线锁定只在武器准备实际开火时执行，不自行补选战术目标。
- 手动无触发命令只转动 Traverse，固定武器立即结束；不读弹仓、挂件、弹速或电量，不创建 `SpaceWeaponShot`。冷却、缺弹等情况仍可转向。自动目标跟踪与手动预瞄统一使用 `SpaceWeaponBallistics.Read/TryAim`，冷却不降低弹速计算精度。手控实际指向始终是鼠标，预瞄解不替代玩家选择。
- `CompSpaceWeapon.Layout` 是武器唯一的可重建连接布局，保存挂件、弹仓候选、加速段顺序及固定炮口几何，按统一结构版本、Map、位置和朝向失效。建拆、归属改划及换图后下次消费重建；状态色绑定同一布局，保留的 appearance 引用仅用于分发颜色。未登记的生成中地图尚无宇宙结构事件，不复用连接缓存；登记后进入同一缓存规则。布局与查询工作区不序列化，移除武器、注销地图与场景重置释放，读档重建。
- 弹仓从缓存候选单次遍历，实时检查弹药与启用状态；先最高优先级，再按稳定 ID 轮换，成功后才推进轮换位置。供电、电容和电网储能不作为跨 tick 结论缓存。`SpaceWeaponEnergy` 每次查询清空工作区，每个电网只汇总一次可用储能，先预留装弹机基础脉冲，再按链路顺序检查各段；共享电网及共享电容均减去已预留余额。缺电段不加速，后段继续检查，末端出膛点保持既有物理连接语义。
- 预瞄与状态查询不创建发射事务。触发命令先过廉价就绪检查，再准备一次弹药、弹速与能量方案；瞄准与 `SpaceWeaponShot.Prepare → Launch → Commit` 使用同一份参数。转向后的真实炮管出口仅更新几何，不重复选择弹仓或查询电量。自动／点防已解析目标在本次调用复用，位置不跨 tick 保存。成功发射才扣弹、电网／电容电费、轮转弹仓和写冷却；失败不消费。查询工作区与正在执行的射击账本分离，状态刷新不能覆盖扣费方案。
- 顶部炮塔的弹体起点和炮口闪光共用 `SpaceWeaponGeometry.MuzzleMapPoint`：Def 的 `turretMuzzleDistance` 从脚印中心沿 `CompSpaceWeaponTraverse.CurrentAngle` 定位炮口；固定武器仍由 `muzzleOffset`／轨道链末端决定位置。不得为闪光再计算一套独立炮口。
- 本轮已完成 Release 构建、321 项控制／输入／驾驶离线检查、86 项轨道炮检查和严格 MPC 回归。新增检查使用生产 DLL，覆盖 120 tick 纯手动转向零资源查询、同帧多 tick 采样边界、冷却自动／预瞄解一致、满链／缺电／共享电网、每网一次储能汇总、弹仓优先级轮换、失败发射不扣电、归属断链／重连、移除重建及地图释放。原版 Building 回调与 Game.UpdatePlay／TickManager.TickManagerUpdate 顺序已静态核对；Unity 原生输入、建拆即时配色、实际存读档与五场景 TPS 仍由用户游戏内验收，离线结果不代表稳定 360 TPS 已达成。
- 第三方 Comp 可实现 `ISpaceWeaponFireGate`、`ISpaceWeaponShotModifier`、
  `ISpaceWeaponFireCommit` 或 `IFireEffect` 正交参与，不需要派生自定义 Building。
- 武器必须位于基架格上（含墙下基架）——归属随基架、随控制域捕获搬运。
- 给第三方武器追加太空能力的最小入口是 `CompSpaceWeapon`；原版 Mannable、Traverse、Magazine、
  挂件和加速件均按需添加。没有 Mannable 时按自带基础火控处理。
- 重炮、速射炮和激光炮的 2×2／3×3 炮塔可逐实例切换地面／太空模式，默认太空模式。地面模式只用原版 `Building_TurretGun` 与专属 `Verb_SpaceTurretGround` 攻击同图目标；太空模式只用 `SpaceWeaponShot` 攻击其他容器。原版炮塔的索敌、掩体、距离与燃料消耗仍由原版处理；模式门禁使切换后的未完成原版齐射停下，太空武器索引与开火均跳过地面模式。点防专用炮固定太空自动拦截，轨道炮和导弹架本轮不增加同图 Verb。
- 太空 `minRange` 和 `range` 都从实际炮口计算，`SpaceWeaponShot.Prepare` 用它们限制自动齐射与点防；手控跳过鼠标点位的距离门禁，实际射弹仍按弹体速度、寿命及碰撞规则飞行。火力估算和射界叠层读同一 Def 参数。地面最小／最大射程由原版 Verb 自身声明。小型炮塔地面 13–33 格、太空自动最小 10 格；中型地面 17–37 格、太空自动最小 15 格。固定武器自动开火的导弹架／小轨道／大轨道最小射程为 12／20／30 格；点防为 0 格。地面炮弹初速重炮 50、速射 65 格／秒，激光使用原版 Beam 弹体；以上伤害与节奏为初始标定，待游戏内验证。

### 5.2 建造规则

- 所有多格武器要求完整脚印位于同一有效基架归属。导弹架和轨道炮装弹机本身为
  不可通行、气密、承顶的结构墙体，不再要求背后另建墙；允许把加速导轨留在船外。
- 当前内置矩阵：点防御激光炮 1×1，小型炮塔 2×2、中型炮塔 3×3（各有重炮、速射炮、激光炮），
  轨道炮装弹机与加速单元 2×1/4×2，导弹发射架仅 1×3；原 1×2 Def 已退役。
- 导弹架没有炮手 Comp，以固定火控值开火，不读取 Pawn 射击技能。1×3 脚印朝向炮口：前一格与舱壁平齐，后两格在船内。自身 `CompChangeableProjectile` 保存一枚待发的导弹物品 Def，原版储存筛选控制允许装载的弹种。物品的 `DefModExtension_SpaceMissileAmmo.spaceProjectileDef` 指定宇宙弹体；原版 `projectileWhenLoaded` 仍指向有效的原版抛射物。`CompSpaceWeaponMagazine` 统一把装填状态接入 `SpaceWeaponShot` 的 Prepare→Launch→Commit，成功发射后才消耗待发弹。搬运工可经 `WorkGiver_LoadMissileLauncher` 向发射架直接装入一枚。
- 附加导弹仓是 1×2 气密 `Building`，不提供原版储物格；`CompMissileMagazineFacility` 按导弹 Def 保存数量和逐弹种上限，总容量由 Def 设置为 20，两个上限同时约束装入。`WorkGiver_LoadMissileMagazine` 派工搬运工把一枚实体导弹送到可触及的仓体，完成时直接增加抽象库存并销毁手中实体；仓内导弹因此不再成为原版搬运目标。Gizmo 可逐弹种调整上限，或将指定弹种的一组导弹退出到仓旁。仓体销毁时尝试放出库存。旧 prefab 中落在弹仓脚印内的实体导弹在导入时装入同一库存，溢出放到附近可用格。
- 弹仓根格只能放在发射架朝北局部坐标 `(-1,0,-1)` 或 `(1,0,-1)`，且朝向必须与发射架相同。插槽坐标由发射架 `CompProperties_MissileAutoloader.magazineRootOffsets` 声明，建造校验与运行时连接判定统一使用 `SpaceMissileMagazineGeometry.Fits`；后者还要求同归属、同派系。原版 `CompFacility`／`CompAffectedByFacilities` 登记链接。开火、库存、待发位筛选、供电与归属变化只登记补弹请求，下一游戏 tick 按发射架 ID 顺序从内部库存取弹；一个弹仓连接两座发射架时逐架原子消费，不重复取弹。
- 发射架沿用原版 `CompChangeableProjectile` 的一发内部待发位，Pawn 直接装入时消耗手中实体导弹，选中发射架可用退弹命令放出待发弹。同一搬运工作类型中，直接装填发射架的优先级高于弹仓；弹仓寻找物资时也排除同船可触及、未装弹且接受该弹种的发射架所需导弹，因此仓只缓冲已满足待发位需求的弹种。弹仓覆写继承自 `Wall` 的禁止多选标志，双击可选中同类仓。弹仓容量与退弹、武器模式／角度／优先级、护盾模式与参数的多选命令通过原版 gizmo 合组入口收集目标并批量应用；护盾预览取消时逐台恢复原值。
- 导弹架的固定内构由 `graphicData` 绘制；`CompLoadedProjectileGraphic` 从 `SelectMagazine()` 获取待发弹对应的宇宙弹体 Def 并绘中层；原版 `CompDrawAdditionalGraphics` 在更高位置绘制固定终端与外壳。空仓时不绘中层。中层按宿主 Def 独立缩放与定位，飞行中的弹体仍使用弹体 Def 自身的绘制尺寸；绝不在运行时改共享的 `GraphicData.texPath`。内构与外壳沿宽度铺满格边，发射架 `graphicData.linkFlags=Wall`；原版仅把连接型 Graphic 写入 `LinkGrid`，故 `Patch_MissileLauncherWallLink` 仅为带导弹装填 Comp 的整图建筑开启此登记，使相邻原版墙贴图能接入发射架，发射架自身仍保留 1×3 三层整图。
  大型炮塔 4×4 暂不实装。点防御仍是一般武器可切换的运行时瞄准模式；1×1 专用点防激光炮由 Def 固定为点防模式。重复的 2×2 速射副炮 Def 已退役。
- 内置 2×2 顶部炮塔各只有一个覆盖挂件槽；3×3 顶部炮塔各有两个槽。实体弹炮可装铀弹仓或自瞄，激光炮可装附加电容或自瞄；轨道装弹机的唯一槽位可选铀弹仓或同尺寸轨道电容，加速段左右各有一个三发电容槽。挂件槽随 Def 局部坐标旋转，
  美术上须在固定底座预留，不画进转动炮身。
- 地表图保留原版规则（RimExodus 兼容边界）；可切换炮塔须选地面模式才按原版 Verb 工作，Delta-V 太空弹道不在地表图运行。
- 非聚焦船壳按 `ShellRenderRuleDef.render` 指定贴图来源与表面层级。顶部炮塔用
  `TurretTop` 来源读取当前旋转炮身材质、角度、偏移和绘制尺寸，只把炮身放在
  `Exposed` 层；固定底座和覆盖插件不绘入船壳。轨道炮装弹机用 `exclude`
  隐藏，加速段的原版内构和外壳绘入 `Exposed` 层。`MapOverlayRenderer` 收集并按
  `Hull → Exposed → Effects` 排序，再同步交给绘制后端；当前 1.6 的命令缓冲后端逐层
  清深度（保留颜色），避免依赖透明材质与海拔推测遮挡顺序。规则只控制外观，
  建筑的碰撞占用仍由 `SpaceStructureRules` 判定，与外壳是否绘制无关。

### 5.3 射界与跨墙感知

- 所有武器在 `SpaceWeaponShot.Prepare` 先以 Def 的锁定弧约束目标，再按本次请求来源，以实例 `fireDeviationDeg`（自动齐射／点防）或 `manualFireDeviationDeg`（玩家手控）比较目标方向和实际发射方向；地面模式原版炮塔读取自动值。旋转炮塔持续转向且沿当前炮口发射；固定武器沿安装轴发射。手控均不按鼠标点位检查最小／最大射程；鼠标恰在炮口时沿当前炮口或固定轴发射。固定轴武器手控设为 180° 时，鼠标方向也不限制开火，弹体仍沿轴飞行；实际弹体碰撞不变。自动和手控各有独立 gizmo，分别使用原版 `Dialog_Slider` 在 0–180° 按整度调整，均支持多选；仅支持一种模式的武器只显示有效设置。重炮自动／手控均默认 1°；速射炮与激光炮自动分别为 2°／1°、手控均为 6°；轨道炮自动 1°、手控 180°；点防炮自动 0.25°；导弹架两种模式均为 180°。导弹的 360° 锁定弧允许锁定反向目标，但仍沿架体前向冷发射后制导转向。
- 顶部炮塔排除己方容器。固定武器默认沿实际炮口方向检查本归属有命中概率的建筑，
  预计先撞自己结构时拒绝发射；玩家可用 gizmo 临时关闭该安全限制。

### 5.4 散布模型

- 发射方向 = 当前炮口／固定轴方向 + 角偏移；偏移 = 基础散射角 × 技能偏差系数。
- 技能来源取有效自瞄插件、Def 内置火控技能与当前炮手 Shooting 的较高者；有 Mannable 而三者皆无时不能开火，
  没有 Mannable 的第三方武器使用等效技能 10。散布映射共用
  `SpaceWeaponService.SpreadFactorForSkill`。
- 不模拟原版 ShotReport 掩体/姿态判定（真空无掩体）。

### 5.5 武器组与「进入战斗位置」（已定机制）

- **武器组 = 主/副两套，每套 1–6 组**：每武器经 gizmo 指派（套别 + 组号）；左侧
  面板显示**两排** 6 个水平数字方块（主/副各一排），点击切换该组**激活**。只有
  激活组的武器会被发射（瞄准模式左键 = 主套
  激活组、右键 = 副套激活组；PD 查两套全部激活组）。套别/组号/两套激活位是存档
  事实。
- 多选武器的组别命令经原版 `GroupsWith/InheritInteractionsFrom` 汇总为一个菜单；不同现有组别也可合并。菜单捕获本次选择，选择主／副和组号后统一写入仍存在且可管理的武器，只有全部一致的项显示勾选。
- 战斗位置使用独立的「进入/重新协调」与「退出（当前人数）」按钮：
  - 作用域 = 当前聚焦图全部可用玩家派系武器；人手不足时才优先激活组；再次进入会
    结束现有舰炮岗位并按最新预留炮手完整重排；
    记账按图上全部玩家船的归属域 ownerId（每船 controller 运行时状态）：对接合图/脱离换图后
    「已进入战斗位置」状态随船保持（炮手岗位随 pawn 搬运本就存活），
    主台、归档与销图事件释放已消失的归属域；
  - 征用规则（用户定案）：gizmo 预留炮手（含「不指定」）仍可射击工作且未征召
    （drafted）→ 由其操作；未预留/不可用 → 从「胜任（Violent 未禁用）+ 可到达 +
    未征召」随机选取；drafted 殖民者不被征用；
  - 实现 = 载人武器声明原版 `CompMannable`，手动菜单和自动分配均下发原版
    `JobDefOf.ManTurret`，武器保存在原版 `targetA`。预约、移动、持续操作、失效检查、
    中断和读档恢复全部由原版 Job 负责；操作 toil 每 tick 调用原版 `ManForATick`，
    停止续报后原版状态自然过期，不另存操作人、不镜像 Mannable getter，也不自写
    `lastMannedThing`。原版操作 Job 的实际操作段支持普通 `Building + CompMannable`，
    轨道装弹机无需另建岗位。选择连线只在原版当前／排队任务的两个目标有效性判断中
    排除本类岗位，不替换后续目标读取、不改真实 `targetA`；其余排队命令仍由原版绘线；
  - 地面炮塔保留原版 `Active`、供电、眩晕和索敌规则，只在原版 Tick 的 Mannable
    开火判定中允许有效自瞄通过；`MannedNow/ManningPawn` 始终表示真实操作人。
    太空发射仍由 `SpaceWeaponShot` 读取同一原版操作人和自瞄技能；

    验证器中排除，自动派遣只走共同 controller；其他原版武器不受影响。
  - **状态变更补分配（事件驱动）**：玩家进入战斗位置或 NPC 获得作战目标后，双方
    使用同一 `DispatchGunners`。原版 `JobDriver.Cleanup` 的统一结束通知、武器供电／生成／模式

    岗位、再分配空岗。该判定同时检查武器存在、归属、炮手需求、供电和必需弹药；
    每件载人武器有随档保存且默认开启的「武器无法工作时保留炮手」开关：仅已在岗炮手
    可在断电或缺少必需弹药时继续留岗，失效武器不征用新炮手。关闭此开关后，这两种
    状态会释放岗位，炮手可转到其他可用武器；武器损毁或归属失效仍释放岗位。
    有效自瞄只排除新炮手的自动分配，已经下达的岗位仍可执行；
    复电或装填后由空闲炮手补位。双方共用同一

  - 退出按钮取消全部岗位，炮手回原工作；不进自发工作优先级。

### 5.6 自动瞄准插件（阶段5 实现）

- 独立覆盖挂件是 `BuildingOnTop` 非 Edifice，只能覆盖建造在宿主脚印内声明的旋转槽位；同一槽位已有挂件成品、蓝图或施工框架时不得再放置挂件。炮塔宿主由挂件所在格的 `GetEdifice(map)` 派生，加速段由同格 ThingGrid 中声明该槽的 `CompSpaceRailgun` 派生，不缓存、不扫描相邻格，也不使用放置 Harmony 强行允许 Edifice 重叠；
  同一基架归属且自身供电/启用时生效；选中宿主会显示兼容附件的原版建造 designator。Def
  提供等效射击技能。有效插件满足开火需求并释放交互格保护，玩家可在该格建造其他
  建筑。有效自瞄时不自动分配新炮手，仍可右键命令 Pawn 操作；炮手格被建筑阻挡或
  不可到达时无法下达操作命令。插件随后停用时不拆建筑，缺少炮手的武器停火。插件与附加弹仓均提供可多选合并的启停
  gizmo，对 PD 武器同样适用。
- 炮手格只由原版 Def 的 `hasInteractionCell + interactionCellOffset` 声明，位置、旋转、
  寻路和建造预览共用原版入口。有效自瞄只隐藏成品的交互点，并在原版
  `GenConstruct.NotBlockingAnyInteractionCells` 枚举该实例时解除保护；其他建筑、蓝图、
  框架以及新武器自身交互格的检查仍走原版。建造规则沿用原版通行性语义，
  不再以全图武器扫描拒绝任何覆盖。自瞄不删除实际操作格，堵格后原版右键可达性
  检查自然拒绝操作；插件停用不拆除已有建筑。
  太空模式的炮塔选择覆盖层直接调用原版 `ThingWithComps` 入口，保留交互点和插件
  槽位提示；地面模式继续调用原版炮塔入口，附带地面射程和强制目标提示。
  插件也不设原版墙面附件 `isAttachment`：它是同格覆盖建筑，选中框须居于自身格内，Gravship 搬运按普通建筑
  捕获。真正销毁宿主时先记下槽内插件，销毁后按相同 `DestroyMode` 一并处理；普通
  `DeSpawn` 搬运不清除插件。
- 预留人选是武器 comp 的存档引用；当前操作人只由原版 Mannable 持有。炮手格不区分舰内外。

### 5.7 轨道炮分体建造（阶段5 实现）

伤害与费效比的统一假设、当前数值和验证顺序见 [武器伤害与费效比基线](武器伤害与费效比基线.md)。

- 装弹机本身是完整固定武器，含钢铁默认弹仓、内置等效技能 10 的轴向火控、基础短导轨和炮口；保留南侧操作终端但开火不依赖炮手。没有外接件也
  能沿固定安装轴以基础性能开火。装弹机本体气密、不可通行且承顶，因此加速导轨可以布置
  在船体外。`CompSpaceWeapon` 声明可用加速件 Def 与一个或多个连接起点。
- `CompSpaceRailgun` 只表示串联加速件：装弹机是必须支付完整基础脉冲的起始加速段；外接各段只有在本发能付足该段脉冲时才增加实际出膛速度和逐发电费。没有电的段仍让弹丸穿过，后面的段继续独立尝试加速。物理链末端仍决定出膛位置，和本发有几段通电无关；没有独立炮口建筑，也不直接修改伤害倍率。联合命中链继续从实际
  相对速度得到毁伤差异。
- 装弹机和每段导轨选中时标示下一部件脚印；放置幽灵同样标示连接位置。允许各段间隔
  规划/建造，开火时只从连接点按同朝向、同归属和允许 Def 解析连续成品链；供电状态只决定各段本发是否起效。
- 小/大型链使用各自允许 Def，避免误连；整链随基架控制域搬运，断裂后自动按仍连续的
  前缀重算。
- 轨道炮为高耗能、少量决定性射击的固定轴攻坚主炮；加速段同时提高弹速、贯穿预算与盾容冲击。参数、破盾门槛、电容容量与回充时间统一维护在 [武器伤害与费效比基线](武器伤害与费效比基线.md)。装弹机基础脉冲必须付足，每段依链序独立预留电容／电网脉冲，缺电段跳过但不中断后段；同网不重复预支。装弹机的唯一槽位可选铀弹仓或同尺寸轨道电容，后者直接复用加速段电容 Def，容量及充电功率不变，可代付两次装弹机基础脉冲；加速段每侧电容容纳三次本段脉冲。各电容新建为空，只代付所属部件的脉冲，不代付其他部件或弹药；储能不足时回退该部件所在电网支付完整脉冲。
- 装弹机与加速单元的内构是 `Building` 层地图网格图；两者各用 `CompRailgunShell`
  在实时绘制中复用同一张外壳图，外壳中心位于本段朝向的北侧脚印边界。大型件占
  4×2，连接起点和逐段 root 步长均为朝前 2 格。高度次序为内构／炮塔底座、覆盖插件、
  遮缝外壳、旋转炮身；外壳高度位于插件静态网格顶部与 `TurretTop` 高度之间。

### 5.8 弹药、挂件与冷发射程序

- 实体弹药直接使用 Steel、Uranium 等 ThingDef，由原版 `CompRefuelable` 提供搬运、
  任意邻接装填与持久计数。默认仓优先级 0，附加仓默认 1；高者先用，同优先级按
  thingID 顺序轮流，只有成功发射后消费。
- 附加弹仓可以替换本发 projectileDef，并通过 gizmo 调整优先级、启停；默认仓耗尽后
  自动回退到下一可用优先级。武器可用 `allowedAttachmentDefs` 收紧允许挂件；空列表保持
  第三方开放接入。
- 铀弹仓每发耗 3 铀、优先级 1，只把本发护甲穿透倍率提高至 1.5，不提高伤害；激光炮不接受铀弹仓。激光附加电容建成时无储能，上限 80 W·d，以 240 W 回充，20000 tick 从空到满；小型激光每发取 2 W·d，中型每发取 4 W·d，不足一发时恢复从电网蓄电池取电。电容不免除持续功耗；轨道炮即便换铀弹仍支付装弹机基础电费及所有起效段的电费。逐发电费优先由所属部件的电容足额代付，否则取自该部件所在 PowerNet 的蓄电池；装弹机电容与加速段电容各付各自的脉冲。激光炮和轨道炮装弹机都必须有足额电容或电网蓄电池储能，不能靠瞬时发电白射高峰值脉冲。
- 电容建筑的武器插件 `CompSpaceWeaponCapacitor` 仅实现 `CompSpaceWeaponAttachment` 的直供接口，储能事实、限速充电、存档与电网回送均归独立的 `CompSwitchableBattery : CompPowerTrader`。开火事务只调用抽象插件基类方法，成功发射后由插件向本机电池扣费；无武器插件的建筑可单独复用该电池，武器不会扫描到它。电池默认仅充电及直供，开启回送后按可调功率持续作为发电机向同一电网输出，关闭后恢复充电；不注册为原版 `CompPowerBattery`，因此不会被原版电网或其他武器的电池扣费路径直接抽走。
- `CompSwitchableBattery` 在开发模式下提供与原版电池同名的 `DEV: Fill`／`DEV: Empty`，分别设置满电与清空，并立即刷新当前充电或电网输出功率；普通模式不显示。
- 电池检查行的当前储能与容量，以及详情页的 W·d 数值共用两位固定小数格式；仅格式化显示值，储能累计和开火扣费继续使用原始浮点值。
- 炮塔与加速段的 `attachmentSlots` 建造格、允许附件列表及附件自己的 `allowedHostDefs` 共用 `SpaceWeaponAttachmentSlots` 生成选中建造按钮和空／已占槽位提示；无两套家族专用绘制逻辑。武器、加速段和电容的 Def 参数经各自 CompProperties 的 `SpecialDisplayStats` 进入详情页“Delta-V太空战”分类，显示逐发耗电、射击间隔、射程、槽数，以及电容容量、充电功率和从空到满时间。
- `SpaceRailgunConstruction` 从装弹机 `allowedAcceleratorDefs` 建立装弹机 → 加速段按钮，并反查接受当前加速段的装弹机 Def 建立加速段 → 装弹机按钮；加速段还提供同型下一段按钮。建造关联只读 Def 配置。装弹机和加速段内构均使用原版 `Graphic_Single` + `CutoutComplex`：灰度底图的对应部位由同路径 `_m` 红色蒙版标出，状态 Comp 的 `ForceColor()` 经原版 `ThingWithComps.DrawColor` 给红色通道赋色，状态边沿调用 `Notify_ColorChanged` 刷新原版建筑 MapMesh；绿色通道才对应 `DrawColorTwo`。建筑维持原版 `Building` 类型，不切换整张贴图，也不使用 `CompGlower`。装弹机的 `CompRailgunReadinessAppearance` 绑定武器的 `SpaceWeaponLayout`，每次只执行一份 `SpaceWeaponEnergy.Evaluate` 只读规划，同时分发装弹机和线圈的三态电力颜色：断电、未连接或对应脉冲预算不足为灰色；预算足够且未冷却为蓝色；预算足够且整炮冷却中为红色。缺弹、炮手和炮口安全条件不参与电力配色；加速段的颜色 Comp 只接收结果，不反查装弹机或独立轮询。外壳贴图保持独立且不变。生成接线在原版 Building.SpawnSetup 收尾、统一结构版本更新后刷新，避免 Comp.PostSpawnSetup 读取旧布局；移除、供电和成功发射触发刷新，连续储能变化最迟每 60 tick 由装弹机复核，冷却结束当 tick 刷新颜色。装弹机复用原版迫击炮的 `ProgressBar` 效果和 `CanFireIn` 秒数文本；进度、文字与颜色读取 `CompSpaceWeapon.CooldownTicksLeft`，不维护第二个计时器。冷却截止 tick 随武器保存，读档不重置；沿用游戏 tick 推进，断电不暂停冷却。效果在冷却结束或移除时释放，非聚焦外壳不绘制 Mote。跨存档复用 prefab 时清除旧世界的截止 tick。颜色不替代弹药、炮手、安全通路、武器组、瞄准目标和锁定范围判断。
- 弹体 Def 声明冷发射时长、离架速度倍率、初次强转向最长时长／转向率、点火加速时长与锁定弧；发射架仍可覆盖冷发射时长。`SpaceProjectileService.AdvanceFlight` 是冷发射 → 初次转向 → 主机追踪的唯一阶段入口，所有计时使用游戏 tick，位移和碰撞沿用现有容器积分与扫掠。
  冷发射阶段保留发射轴推出速度与宿主速度继承，不主动转向或推进；离架后初转只旋转弹体朝向，不瞬间改写平移速度，对准、目标失效或时限到达即进入主机阶段。主机在唯一的 universe 速度状态上沿弹体朝向逐 tick 施加有限加速度，转向不直接旋转速度矢量。制导期把目标速度换算至导弹位置，取「目标速度 + 指向目标的 32 格/s」作为期望速度；弹头朝目标视线转动，并按横向相对速度偏转；微小速度残差不改变朝向，单 tick 速度增量以离架速度至巡航速度差除以点火加速 tick 数为上限。这里的 32 格/s 是相对目标的期望接近速度，不限制绝对宇宙速度；两船共同高速漂移时导弹保留发射瞬间的漂移。普通弹体不接入飞船 MPC；发射瞬间的继承速度只作为初始条件，不另存运动参考系。正式高爆导弹保留 30 tick 冷发射、初转最多 12 tick／1080°/s、点火加速标定 6 tick／最大 4 格/s 每 tick 速度增量、主机转向 540°/s。固定 `timeoutTicks` 仍控制总寿命，不根据当前速度重算。目标消失后停止制导，正在进行的点火段沿当前朝向完成，之后沿当前速度飞行。发射架能力只能进一步限制、不能扩大弹体锁定包线。
  初转的实际转向符号驱动外侧 RCS 短焰；冷发射只留少量短寿命烟气，主机实际施加速度增量时才绘长尾焰和相应烟迹。普通弹体喷口取 Def 的 `exhaustOffset`（弹头前向 +X、左侧 +Y），烟迹和尾焰共用同一喷口坐标；烟迹继续使用服务已有总量上限。表现不改变弹体位姿或碰撞几何。
- 侵入 shuttle 的真实推进器、截击飞控和加力规则见 §7.3–7.5；不进入普通导弹的冷发射／简化加速度制导状态机。普通导弹尾焰只在本 tick 实际加速时显示；侵入烟焰读取真实推进器布局与油门，只有正在加力的尾部主推使用 afterburner 表现配置。

惯性耦合器与采矿光束由自动齐射、点防和 AI 火力估计跳过；它们不执行拖曳、停靠或地图扩容。月池牵引器复用射击事务的供电、瞄准和扣费，通过 `ISpaceWeaponLaunch` 直接查找／续接散落对象，不创建弹体或执行碰撞查询。自动模式保持有效锁定，失效后复用点防 30 tick 重选节拍、只查询散落对象事件索引；手动模式使用常规武器组。牵引与回收的权威设计见 [对接与舱外作业重构设计](对接与舱外作业重构设计.md)。
设备和弹体初始参数以 `1.6/Defs/SpaceCombat/DeltaV_Engineering.xml` 为唯一数值来源。
惯性耦合器的 `continuousBeam` 每游戏 tick 通过同一发射事务支付能量并更新射线，
耦合强度及冲量上限按同一步长配置；松开开火、停用武器组、失去射击资格或欠电时停止。
详情页显示每秒蓄电消耗，不显示脉冲射击间隔。
对无驾驶台残骸及天然岩石的作用来自统一射线碰撞，不要求目标具备驾驶身份。

- **惯性耦合**：`SpaceImpactEffects` 的 `CoupleMotion` 后效从仍在图上的发射器解析当前容器，
  经 `SpaceObject.CoupleMotionWith` 调用 `ShipPhysics.CoupleMotion`。双方使用现有质量和惯量，
  在命中点共同切平面分别交换容器平移动量与自旋角动量；线速度差不转成两船中心的公转。
  两种交换均等大反向且受单 tick 冲量上限限制，小残差按相同上限完成收敛，避免无阻力模式
  下分数脉冲停在浮点精度尾差。守恒的是切平面线动量和自旋角动量，不再使用含力臂的轨道角动量模型；
  不声称球面远距全局欧氏动量精确守恒。不能凭空消除共同漂移或共同旋转，本船需主动反推。
  后效只改双方已有速度，不推进位置、不再次积分、不触发推进器分离，也不保存独立任务或耦合状态。
  连续射线从发射时冻结的船体局部炮口及方向，在本 tick 刚体积分后换回宇宙坐标，跟随本船运动。
  切向量换基只由 `SpaceTransform.TransportTangent` 计算。
- **采矿**：`Salvage` 后效只处理实际命中的可破坏建筑／矿岩或裸露基架。
  建筑切割消耗真实耐久，不另外记录进度；完成时用 `Destroy(Vanish)` 移除，
  然后由原版 `GenLeaving.DoLeavingsFor(..., Deconstruct)` 在接收船生成正常拆除材料，
  不同时生成原址击杀残料。矿岩改按 Def 的产物、掉落概率与有效基础产量乘光束回收率生成矿物。
  基架无累计耐久，达到单发切割阈值后经 `SubstructureDamageUtility.TryDestroy` 毁伤成功后结算基架拆除材料，
  附着地板、屋顶及残留建筑由同一毁伤工具清理。完整设备、库存、燃料和人员不作为额外回收收益。
  输出以设备所在格为中心：矿物与深钻井一样调用 `GenPlace.TryPlaceThing(..., Near)`；
  建筑和基架分别调用原版 `GenLeaving.DoLeavingsFor` 的 Thing／TerrainDef 入口，
  内部同走 Near 放置。合堆、单格容量、货架筛选、附近搜索和溢出拆堆均交给原版，
  不再预扫空格、按完整成本预留容量，也不附加八格／本船甲板白名单。
  空间不足不阻止扣耐久或完成拆除；完全无法放置时沿用原版失败行为，放不下的材料不保留。

  读取原版 `GenPlace.TryPlaceThing` 带 out 参数重载的最终返回值，失败（含部分放下后失败）
  才由 `SpaceWeaponService` 通过原版左上角消息提示玩家。矿物、建筑和基架每次出料失败均立即提示，
  不增加提示冷却、容量扫描、收益预估或存档状态；作用域在异常时也恢复。
  已确认放置失败的采矿作用域内，原版两类 GenLeaving 失败警告改由该玩家提示替代；
  其他调用及其他警告保留。
  不增加输出缓存、存档队列或重试收益。产物放置及电缆修复已通过用户游戏内验证；
  损失提示按用户反馈移除冷却，每次失败均调用原版消息入口。
  电缆沿 §3.2 共同碰撞规则处理，只有电缆的基架可正常切除并结算材料。
  多束按实际命中顺序处理，已销毁实体和已移除基架不能再兑现材料；最后一格消失后的销图仍由现有生命周期执行。
- **光束与护盾**：共同 `SpaceCollision` 处理遮挡、距离与盾面；工程条目明确设结构必中。

  开始照射时播放一次启用音，不逐 tick 重播；高频发射／命中／退出不刷日志。

## 6. 瞄准模式与预瞄

### 6.1 玩家火控与机动（统一 controller 下的独立输入会话）

- 基架船与 shuttle 的身份锚通过同一 `ShipCombatState` 保存火控模式与武器组，**新船默认自动火控**。侧边栏或可配置 B 键切换当前所选船的
  自动火控／手动集火。自动火控沿用有效目标；没有目标时按决策间隔评分索敌，已有目标失效时当 tick 重选。玩家与 NPC 各持有同一类
  `ShipFireControl`，经 `ShipFireControl.TickVolley` 分派统一武器命令；执行边界见 §5.1。
- `ShipFireControl.CandidateValid` 是自动索敌、逐 tick 齐射复核、预瞄和 NPC 目标数诊断的共同资格入口：已加载且在战术范围内的非纯弹体容器，必须包含敌对、有效且可在该容器驾驶的 `ShipBase`，并且该成员自己的控制域内至少有一台实际可用推进器。读取对象 `MotionInfo` 后按成员 `Contains` 筛选实体推进器；独立 shuttle 使用其虚拟推进器。无主台残骸、全部推进器失效的船，以及仅剩同图友船动力的敌船均不入选；同向主台继任后的有效成员仍可入选。船型无武器不影响资格，shuttle 不要求驾驶台。
- 自动火控只在索敌时枚举每个容器的每一艘合格船，以带种类的 `DriveSubject` 锁定。评分中的敌方火力、可用动力、船体半径及建筑耐久只读取该船；不汇总整图碎片、友方或其他成员。保留原评分权重和设置中的索敌间隔，同分按稳定船身份排序。
- 齐射、预瞄与自动机动统一解析所选船的当前 `HullCenter` 和刚体点速度。提前量查询在武器侧 `SpaceWeaponBallistics`，数学唯一调用 `SpaceTransform.TrySolveInterceptPlanar`；Boarder 可指定该船的点防或推进器设备。资格失效立即阻止新齐射，并在当前战斗 tick 重选目标；已发射弹体不再检查自动攻击资格。
- 手动集火只允许当前聚焦图中所选的那艘船读取鼠标，其他手动船停火。
  `SpaceAimController` 是该船 controller 的运行时输入会话，独立于手操和自动驾驶；
  聚焦切走时挂起，切回可恢复，同图改选另一船时释放旧会话。会话不序列化，船消失时释放。
  手动时：
  - 鼠标位置以**预瞄指示器同款绘制方式**显示**瞄准位置标记**；
  - **左键 = 射击主武器组的激活武器**（按住持续，方案默认）；**右键 = 射击副
    武器组的激活武器**（按住持续）；
  - 瞄准会话内，原版左键点选与右键命令菜单**让位**（与 Targeter 瞄准会话的让位
    契约同族——`ShellPicking` 注释中既有的「瞄准点击 vs 选择点击」分界）；
  - 开火资格只由 `MapInterface.HandleMapClicks` 前、原版窗口和控件处理后剩余的地图 `MouseDown` 授予，左右键独立；该入口早于空选中右键打开建筑栏的低优先级快捷键，每事件仅接收一次，避免后续将自身消费的事件当作 UI 阻断。tick 仅消费资格及帧快照的按住状态。`PlayerFrameInput` 缓存窗口、侧栏实际矩形、原版吸收输入矩形、底栏及殖民者栏，鼠标使用原版 UI 坐标口径。UI 按下拖回地图不取得资格；移入 UI、阻断窗口、设计器／Targeter、切图或失焦清除资格，必须松开重按；退出会话和读档不保留资格。
  - UI 命中检查在 tick 和 OnGUI 均使用 `UI.MousePositionOnUIInverted`（实时 Input 鼠标按 UI 缩放换算），不读取 `MousePosUIInvertedUseEventIfCan`：tick 中 `Event.current` 可残留，但 GUI 变换不处于有效 OnGUI 上下文，会将地图位置错误放大并判入日志窗／底栏。控件矩形仍在 OnGUI 中采集。`NpcRetreatRegression -AimInputOnly` 覆盖日志窗开启／关闭、残留坐标、1／1.5／2 倍缩放及真实 UI 阻挡；用户游戏内实测通过，专项临时诊断已清理。
  - 鼠标局部点、左右键、驾驶轴与刹车由 `UniverseManager.PlayerInput` 在该帧首次消费时统一采样，同帧多 tick 共用；暂停绘制也可消费。UI 门禁独立按帧、地图、焦点和 UI 矩形变更失效，OnGUI 刷新资格不会重采样整套原始输入。每 tick 执行前仍验证当前船、所选会话和地图；切图、选船、模式退出、失焦或 UI 阻断清除资格。各炮共用同船局部瞄点，转向不做逐炮坐标往返。
  - PD 武器不受火控模式影响（恒自动索敌）。
- 侧边栏另有**自动战斗机动**开关，运行时默认关闭且不存档。玩家和 NPC 共用
  `ShipAutoManeuverControl` 的持续战法及 `ShipAutopilot.TrackOrbit`；玩家模式不会自动撤退、
  退场或发射跳帮 shuttle。开启替换当前自动驾驶任务（含对接与航点制导），保留对接计划；
  任意驾驶键打断机动并进入手操。火控与机动互不绑定，炮手战斗位置也独立管理。
- 火控键不占用空格／暂停；驾驶期间由按键抑制桥让位其原版重叠功能。
- 炮塔转向只在火控或原版图内目标存在时接收命令；同 tick 两者都有目标时宇宙火控优先，
  无目标时 Traverse 不做逐 tick 工作。
- 有触发意图时由武器执行层独立判定就绪：所在组激活 ∧（原版当前炮手 ∨ 有效自瞄 ∨ 无 Mannable 的自带火控）∧ 供电/弹药 ∧
  冷却完毕 ∧ 瞄准方向在射界内 ∧ 非地表图。
- 手控瞄准参考点为共享地图局部鼠标点；各武器用本图炮口计算转向，真正开火时才转换发射所需的 universe 几何。实际发射角沿当前炮口／固定轴，再加既有散布。

### 6.2 目标身份与解析

- 运行时 `CombatTarget` 区分三类：飞船（带种类的 `DriveSubject` + 可选设备 ID）、容器（objectId + 可选 Map 局部点）、自由瞄点（universe 坐标，无隐式锁定）。`TryResolve` 只回答当前位置，不判断敌对、推进能力或攻击资格。
- 飞船经 `ShipRegistry.ShipByIdentity` 找当前成员，再经 `FrameOf` 找当前承载容器；不长期持有 Map／ShipBase，也不以 ownerId 反查容器。设备被毁或离开该船时回退到同一船中心。分离、换图和同向主台继任保持船身份。
- 手动导弹先按射线选最近敌对容器；该容器中射线命中敌对船成员时记录船身份，否则记录容器身份。此策略允许失能船和残骸；没有候选时无锁定直飞。直射弹／激光仍以发射方向和碰撞结算命中。
- 在飞导弹只解析发射时指定的目标，分离后跟随原船的新容器；推进器失效不解除制导。身份消失／无法解析后清除锁定并沿当前方向继续飞行，不扫描或重新捕获其他目标。
- 玩家侵入使用明确容器局部落点；NPC 跳帮使用火控已选船身份。弹体每 tick 解析一次目标，将同次解析得到的位置用于制导、容器 ID 用于限定碰撞对象；不允许追踪新容器却仍限定命中旧容器。
- 自动机动消费同一目标身份，由战术层的 `CombatTargetSampler` 提供当前位置给 `ShipAutopilot`。轨迹、视线朝向与相对速度使用目标船位姿；避碰距离仍覆盖整个承载容器及船中心偏移。自动驾驶不解释船身份和选敌规则。
- 目标和锁定均不存档；控制器、武器状态、地图卸载与换档沿既有生命周期清理。战斗调度每 tick 通过共同身份索引取得当前船，不另留船体快照。地图卸载和容器移除即时清除相关弹体目标及当 tick 解析缓存，包括先替换为无图表示、再清理旧图的归档顺序；按当前船所在图判断，清理旧图不会解除已分离到新图的船目标。侵入目标失效时停止该次限定扫掠，解除接管沿共同弹体收尾路径执行，遍历中安全移除。

### 6.3 预瞄指示器与瞄准标记（已定需求）

- 手动输入会话每帧自动显示预瞄，从 `ShipFireControl.LeadPoints` 先为各激活武器准备一次精确参数，再遍历目标求解；同帧绘制复用显示结果，结构变化立即失效：对每个通过 §6.1 共同资格入口的敌船 × 激活齐射武器的真实炮口／弹种／弹速，解算并合并重合的
  瞄准点；在炮口切基中以相对速度 `w = 目标速度 − 发射继承速度` 求 `|p + w·t| = 弹速·t` 的最小正根，瞄准偏移为 `p + w·t`，再由 `OrbitSphere.Move` 转回 universe。该点补偿弹体继承的发射方速度，不等于目标的绝对未来位置；发射继承速度与真实 `Launch` 同读 `SpaceTransform.TransportVelocity(sourcePose, muzzle)`。激光档 = 目标当前位置。聚焦帧投影绘制标记。标记纯显示派生，不参与发射判定；自动齐射、PD 和预瞄复用 `SpaceWeaponBallistics.TryAim/TrySolveIntercept`。预测仍假设目标匀速，后续机动会产生误差。
- 瞄准模式激活时，**瞄准位置标记**（鼠标处）与预瞄标记同管线绘制，视觉上区分
  （形态 §15）。
- **图标与角度语义（2026-09-27 实测定案）**：图标用原版 overlay 贴图——瞄准位置
  = `UI/Overlays/TargetHighlight_Square`（原版 targeter 同款，橙红）、预瞄 =
  `Circle75Solid`（绿）。旋转与聚焦船同宇宙角（`FocusedMeshRotation(frame,
  frame.pose.angle)`）：从聚焦船看恒水平、随聚焦船旋转——不锁宇宙 0 角。

## 7. Shuttle 体系（跳帮舱改制）

### 7.1 定位与原版复用

- 月池是特殊基架地形，自带专用 `DeltaV_MoonPoolFieldRoof`：原版屋顶格负责房间、
  温度、天气和真空气密，照明判定允许完整日照透过。已有普通屋顶保留到玩家手动拆除，
  拆除后自动露出力场顶；自动／手动盖顶不作用于月池，力场顶不能拆除或坍塌。
  地形、屋顶变更和搬运落位按事件同步，读档只重建一次，不逐 tick 扫图。
  穿梭机发射、放置和 Delta-V 普通对接的原版落点检查仅在月池格豁免屋顶；
  整艘逆重飞船不豁免，落地也不拆除宿主屋顶。
  离线回归入口：`scripts/MoonPoolRoofRegression/run.ps1 -GameRoot <游戏目录> -HarmonyPath <net8.0 Harmony DLL>`；
  校验 Harmony 绑定、屋顶替换与清除、局部透光／通行和防坍塌，不替代游戏内验收。
- shuttle = 与原版 shuttle 同类的小艇建筑：停靠时是普通建筑 + 原版
  `CompTransporter`（装货/乘员登舱）+ `CompLaunchable` 系发射语义；**完全使用
  原版装货逻辑与一键卸货**，不自研装卸。跳帮舱与普通 shuttle 无非数值差异（乘员
  更少、血量更厚、机动更强；燃料差异随燃料系统后续接入）。
- **起飞校验直接取原版 shuttle 发射校验函数的结果**（2026-09-26 定案）：冷却、
  乘员等全部门禁由原版函数判定，本 mod 不做第二份检查（具体入口施工前核对
  CompLaunchable 系；按 §10 优先级纪律，能直接调就不 patch，能 Prefix/Postfix 就
  不镜像）。
- shuttle 不是武器、不占武器组、不进战斗位置征用。
- **可拦截性（2026-09-26 修订，结构派生）**：shuttle 之所以可被点防御拦截，是
  因为它是一个**有地图的、依托于内部建筑存在的 SpaceObject**，且 **tag 为
  shuttle（正常驾驶）或附加 projectile（侵入碰撞角色）**——
  结构上即拦截合法目标，**不是因为** building def 上的可拦截标记。
- **与飞船不得有两套逻辑（已定约束）**：起飞/飞行/降落/受击全部复用飞船的同一
  实现；普通降落读取 shuttle 的单建筑船体脚印与锚，同样执行
  `CaptureDomain → StripDomain → PlaceIntoMap`。shuttle 特有的只有不搬地形/不盖
  归属、落地后触发原版冷却、起飞后立即进入驾驶（玩家方），以及侵入式对接能力
  （真实推进器截击与共同碰撞）。

### 7.2 状态机：建筑 ⇄ MiniShip

```text
建筑（停靠：装货/卸货，held 货物与乘员随建筑存档；起飞门禁 = 原版校验结果）
  ↓ 起飞（原版校验通过 ∧ 非地表图；玩家方舱体自动进入驾驶）
MiniShip（在飞：普通 SpaceObject 容器 + 口袋图里的舱体建筑；tag = Ship + Shuttle；
         可驾驶/自动驾驶/受击/可被 PD 拦截）
  ↓ 停靠（与飞船同一对接计划管线 §7.4 / 侵入式截击 §7.5；都触发原版降落冷却）
建筑（停靠，冷却中 → 期满可再起飞）
```

- 起飞 = 舱体建筑（含 held 内容）经**与船脱离同一套**统一搬运核心捕获进新口袋
  容器（`TransferDomainToNewPocket`，cells = 舱体脚印；**不搬基架、不进控制域
  语义**）；新容器位姿/速度 = 宿主刚体上舱体锚点位姿（含自旋切向继承，
  `RigidPointPose`）。
- `ShuttleShip` 与 `FoundationShip` 并列继承 `ShipBase`，进入 `ShipRegistry.AllShipsOnMap` 成员枚举，
  但没有基架归属域。容器注册／积分／休眠／归档走既有 SpaceObject 通道，受击走 §3 统一碰撞链。
- 全部船型启用共同的完整战术 AI：选敌、火控、武器组、站位、战损重评与返厂不按 shuttle 船型排除，无武器只使真实火力为零。目标威胁按单艘船成员分别评估，不混入其他成员及碎片；对象敌我关系读取成员派系，陈旧环境派系不覆盖成员事实。跳帮能力的可用艇查询与执行统一由 `SpaceShuttleService` 提供，仅使用本船及其控制域内的载员侵入艇，已在飞的艇可直接侵入，不再次起飞。NPC 决策在显式对接或弹体接管期间不覆盖其任务。
- 驾驶：`ShipController` 契约复用——`PilotService` 目标泛化为「可控体」（容器 +
  推进器控制模型），玩家/NPC 双子类与按键抑制、打断语义原样适用（不复制第二套）。
  面板、星球仪与世界标记统一枚举飞船，停靠和在飞 shuttle 都有船身份。玩家方舱体**起飞完成即自动进入驾驶**
  （共同的 `TransferShipToPocket` 完成相机与 `PilotService.Enter` 交接）：只在聚焦已随起飞
  交接进新口袋图时生效，否则下一帧聚焦自动退出驾驶，进入无意义；与飞船的差异在于
  飞船本就处于驾驶状态才能出力起飞，shuttle 靠起飞按钮进入宇宙，故需要此自动接管。
  未注视起飞（dev 敌对发射/NPC）或非玩家方舱体不自动进入，仍可经面板手动驾驶。

### 7.3 飞行动力学：矩形刚体 + 虚拟推进器（已定）

- 虚拟推进器布局是 **XML 列表**，每项显式给出 shuttle 船体帧中的作用点 `position`
  与推力矢量 `force`（方向 = 推力方向，长度 = 最大推力）；数量、位置、方向和大小均
  可自定义。原版 PassengerShuttle 的默认表为 8 台，但“8 台/四角/轴向”不是代码
  常量；跳帮档位可通过 `DefModExtension_BoardingProfile.virtualThrusters` 整表覆盖。
- 虚拟推进器由 `MapSpaceObject` 提供给共同物理核心与只读预览：质量 = def + 原版
  `CompTransporter.MassUsage` 载重，惯量 = 各建筑矩形本征惯量 + 平行轴项。3×5
  跳帮 shuttle 空载质量 140，`I=140*(3²+5²)/12≈396.7`；载重增加后加速度与转向
  响应按真实质量、惯量降低。驾驶输入、飞行辅助、被动阻力与飞船完全同构。
- 跳帮艇共六台推进器，船体帧 +X 为艇首、+Y 为左侧；以下均为推力矢量，排气方向相反。
  尾部两台位于 `(-2.2, ±0.69)`、各 `(280, 0)`；头部两台位于 `(2.02, ±0.85)`，
  分别 `(-140, ∓210)`；中部两台位于 `(-0.55, ±1.1)`，分别 `(140, ∓210)`。
  四台斜推兼顾纵向、侧向和姿控，每台推力约 252.4；转矩按位置、质心与推力叉积计算。
  常规前推总上限 840（尾部 560 + 中部纵向 280）；加力前推总上限 1400。
  空载静止、零转矩时对应理论初始加速度 6／10 格/秒²，实际还受载重、分配和阻力影响。
- 虚拟推进器表是有图对象持有的可重建缓存，不序列化；首次读取驾驶信息时按 XML 重建，
  读档后走同一入口，不另设全局虚拟布局注册表。舱体销毁及地图卸载事件在帧边界清理容器，
  无须每 tick 扫描在飞 shuttle。
- 受击：碰撞面 = 舱体脚印（建筑实体格）；被弹体命中 → §3 统一链（联合后效毁伤落
  shuttle 口袋图打舱体建筑）。舱体被毁 = shuttle 消失（乘员/货物按原版 transporter
  摧毁语义），帧边界注销容器。

### 7.4 普通停靠 = 与飞船同一对接计划管线（已定）

- **降落逻辑只有一套**（飞船的对接计划管线）：目标选择（排除自身容器、多候选
  按可见壳距离选）→ 选点（初始落点 = 悬停投影，玩家可调；合法性门禁照常）→
  幽灵提示 →（可选）随动自动驾驶接近（玩家可手操打断）→ 位姿窗口保持判据 →
  捕获-剥离-直接放置。**shuttle 复用全链**，唯一参数差异 = 计划脚印来源
  （船 = 控制域脚印；shuttle = 舱体 building def 脚印），选点预览按同一门禁的
  脚印校验。
- shuttle 的舱体脚印就是其完整控制域；完成时与飞船一样按选点注册的 Gravship root/
  Rotation 捕获、剥离、放置，禁止再用建筑 `DeSpawn + GenSpawn` 解释落点或朝向。
- **差异只允许在降落属性与后处理**：飞船 = 搬基架并保留结构身份；shuttle =
  `includeTerrain=false`、不盖归属，放置后成为普通建筑并触发原版降落冷却
  （入口施工核对，§10 优先级纪律）。除此之外不得有任何 shuttle 专属降落分支。
- 侵入计划/对接计划均为运行时数据：读档丢弃、按已存速度漂移、不自动续接。

### 7.5 侵入式对接：真实推进器截击与共同碰撞

- 能力 per-def；启用 = 左侧面板开关（针对在飞 shuttle）；指挥 = 选中在飞
  shuttle → gizmo/点击敌舰外壳指定目标容器。
- **运动 = 同一艇体、真实推进器、截击 MPC**：进入侵入时停止旧驾驶任务，弹体服务
  为原艇体登记唯一碰撞工作项，并调用 `ShipAutopilot.Intercept`。质量、惯量、推进器分配、
  被动阻力和积分均与正常驾驶共用；不直接改写速度方向、不设导弹巡航速度或转向率。
  玩家点选的容器局部点随其刚体运动，NPC 跳帮跟随已选船身份；同次目标解析供制导与碰撞使用。
  只与指定目标结算，沿途不会撞母舰。MPC 滚动搜索较短到达时域，不要求末端停稳；具体成本、
  预测与调度见[在线 MPC 自动驾驶](在线MPC自动驾驶.md#侵入截击2026-10-24)。
- **限时加力**：仅尾部两台主推翻倍，预算为 600 游戏 tick（10 秒）。真实执行推进时，
  只要任一主推有有效油门便扣一 tick，两台同时燃烧不重复扣；空转和仅斜推工作不消耗。
  耗尽后恢复常规推力继续追踪；取消、重启任务与存读档均不补充预算。累计用量随艇体保存，
  普通或侵入落地后恢复预算。加力预测包含耗尽后的常规能力，表现读取实际油门。
- 侵入超时为 7200 tick（120 秒）。`projectileRoleOverride` 只追加碰撞角色，不改变基础类型或阻力。
  面板主动中止、目标失效或超时均解除接管和对应 MPC 任务，保留艇体及线／角动量。
  读档不恢复侵入任务，艇体按保存速度正常漂移。
- 宽相位仍使用完整艇体外接圆，窄相位只以实际 3×5 脚印的艇首 3×1 一排触发破拆，
  避免侧后方结构被外接圆选为艇首命中。艇首碰撞矩形与落地朝向读取真实艇体朝向，
  不从侧滑速度反推船首；毁伤相对速度和入射角仍读取真实运动。
- **结算 = 联合后效 + 共同降落链**：跳帮艇通过通用 `ignoresShields` 穿过全部盾面（含原版圆盾），
  不扣盾容、不付线盾脉冲电费、不在盾面落地；点防仍可攻击艇体。仅实体命中触发跳帮后效。
  落点由命中事件一次算出，艇首一排进入目标船，向内第二排保证清出
  三格宽通道。破拆只作用于建筑，不移除基架。艇身其余部分可以处于目标图的真空地形。
  后效解除弹体接管，调用普通 shuttle 的 `CaptureDomain → StripDomain → PlaceIntoMap` 与冷却、
  聚焦和源图收尾；乘员/货物仍 held，原版从艇首交互格卸员。高爆导弹撞泡泡盾时也在盾面执行
  爆炸后效，而非只销毁弹体。
- 玩家正聚焦跳帮艇口袋图时，落位后的帧边界先用 `SetFocusedWithCamera`
  交接到实际被撞容器的 Map，镜头对准撞击点并保留缩放，然后销毁源口袋图；
  玩家已切往其他图时不强制夺回聚焦。
- 侵入 shuttle 已在共同弹体工作表中，不再枚举宇宙对象拼第二个扫掠体；MPC 只出力，实体碰撞决定完成。转移源图与聚焦交接绑定在本次完成对象上，避免并发命中互相覆盖。
- 与导弹的同构性：PD 拦截（结构判据含两种 tag）、碰撞（同一核心）、后效（同一
  注册表）、目标指定（点壳）全部同链——「拦截 shuttle 和拦截导弹完全是同一个
  机制」。

### 7.6 与旧跳帮体验的对应

选中乘员 → shuttle 装货（原版登舱）→ 起飞（原版校验）→ 面板启用侵入 + 选敌壳 →
真实推进器截击 → 破拆两排并走共同降落链 → 原版从艇首卸货出击。撤离 = 普通对接召回
或占领后再次起飞。舱体堵住破口的气密性由舱体 def 保证（施工核对原版 shuttle def
的 fillage/密闭语义，不足则跳帮特化 def 补齐——def 配置差异，不是机制差异）。

## 9. NPC 与 dev 验证

- 发射与碰撞系统来源无关：任何容器/派系的武器都能发射弹体，任何弹体都能撞任何
  有碰撞面的容器（同一条链）。
- 当前 dev actions 保留 `Dump universe state`（AI 门禁、目标数、推力和任务状态）与
  弹体池状态查看。战斗验证由真实 NPC AI、`SpaceWeaponService`、shuttle 起飞/侵入和
  `SpaceProjectileService` 链路触发；旧直发弹体、手动齐射和强制 shuttle 侵入动作
  已移除，不能再用绕过武器判定的结果代替正式链路验收。
- `NpcShipAiService` 按设置间隔扫描 NPC 船，逐船记录初始推力、火力、主台与撤退状态；低于初始能力 30% 或主台继任仍触发生存底线，策略条件还可触发撤退和现有跳帮链。归档保存每船观察摘要，恢复重新读取真实图。`CompShipCombatAI` 随当前主驾驶台或 shuttle 艇体 Scribe 保存 `CombatStrategy`；备用台有独立配置。规则分别对机动和逐武器火控首条匹配，末尾内置通用规则；同一战场事实读取真实武器、船体、护盾和推进。机动由首条规则选择持续战法，再交给现有自动驾驶与 MPC；交战姿态选择与持续运动执行分开，具体契约见下。火控逐武器选敌，可同时攻击多个目标，真实发射仍走 `SpaceWeaponService` 的准备与扣费事务；只开火控时不改变驾驶。玩家策略不撤退或跳帮。NPC 仍沿现有资格门禁、返厂和侵入流程。战斗手感、命中率和性能待游戏内验收。
- 自动战斗机动：`CombatTacticSettings` 分别保存距离、本船相对视线朝向、攻击方位及其自由／敌舰／世界参考系。指定攻击方位只允许保持射位；自由方位可保持、自动换位或持续绕行。主要武器筛选限定射位基准，其余武器仍可独立开火。`CombatAttackPose` 使用八个粗朝向、最多十二门高伤害率武器的炮口射程边界与固定炮提前量细化候选，所有选中武器参与覆盖评价；射程、炮口、机械及实例射界、弹药、供能和固定直射安全路径共同约束。冷却炮保留名义覆盖，真实就绪输出分开计算。默认自动换位取代旧的 25% 窄射界分类，`CombatReposition` 只在换位事件抽取 ±30° 以内偏移和 5～10 游戏秒间隔，并受双向推力／转向能力缩小；上一段未接近目标或切向速度仍需制动时不重新抽取。协作只读取同阵营、同目标、正在自动机动且允许协作的船；稳定身份顺序确定先占方位，后来者向另一侧尝试有限换位。它不读取炮弹、开火事件或预测指令。
- 玩家曲线：六种 x/y 点集保持原保存与编辑契约，距离使用中心距；玩家曲线按原分值相加，上升末段可持续拉远，不设隐藏远距上限。基础覆盖分为名义覆盖火力比例 × 100；自动换位／绕行另加 0～8 分的真实机动能力偏好，未自定义受击曲线时风险为 `-5 × DPS/(1+DPS)`，防止默认无限后退。指定距离优先于距离曲线。只开机动仍使用距离、风险与重叠，但不计输出与固定炮对准；只开火控不提交驾驶轨迹。配置输出曲线时，每门就绪武器仅计一个允许目标，不重复累加多敌；固定炮冷却不撤销朝向约束。编辑器显示规则、选敌与逐炮原因、换位时钟和各曲线分值；示意图左拖距离／攻击方位、右拖朝向，自动值预览当前战术结果，修改仍属于待保存草稿。
- 自动战斗热路径：规则／轨迹及自动火控最多每 30 tick 更新，完整射位每 120 tick 更新，按船身份错峰；目标、规则、能力、配置、结构变化使相关缓存失效。同一轮共用 `CombatStrategyFacts`，武器风险摘要由每船 controller 持有并以 30 tick 刷新，部件索引按结构版本重建。每次最多保留最近 64 个敌舰、64 个友方占位／路线对象；每个选中目标最多精查 12 个高价值部件，部件锁 120 tick 重评，炮塔提前量 15 tick 更新但每 tick 转动。冷却中的固定炮无瞄准执行工作。射位几何复用 `SpaceCollision` 船体格数据，路线作 4 个时刻的保守占用检查；自动自由换位受阻最多缩小两次，再提交保持参考，显式参数不被改写。此检查不是连续扫掠的安全保证，真实碰撞仍由原链决定。`CombatTrajectoryIntent` 从船心参考通过统一刚体变换转换为地图原点参考，`startTick` 固定游戏时间轴；MPC／分配器／积分只有原有一条链。
- 条件与选敌：按本船／敌舰／武器集合／当前武器读取真实事实；空集合、缺敌舰不匹配，不伪装为零冷却或有弹。条件可选退出阈值，当前规则保持期间仍允许更高优先级抢占。选敌每轮重评，原目标仍合格时至少保持 120 tick，候选还需超过当前分数 20%（至少 1 分）才切换。默认忽略没有启用战斗武器的船，冷却或暂时缺弹不等于解除武装；可配置包括失去武器的目标。敌舰是否可攻击不再取决于推进能力，静止炮台和失去推进的有效舰体仍可选；无主台碎片不因此变成船。
- 火控与覆盖：`Fire/Hold` 明确决定逐炮能否射击；目标权重为零不等于停火。部件偏好包括自动／中心／武器／推进／护盾／供能／主台，候选复用真实预瞄、有效覆盖、己方安全路径及结构遮挡查询。临时交战目标独立于手动集火；最多 16 个部件排队，失效跳过、取消或队列用尽后回到策略，停火规则优先。`CombatWeaponCoverage` 在武器 Comp 上 Scribe 保存最大射程、射界和固定方向，只能缩小硬件能力；射界图、瞄准与真实发射门禁同源。显式最大射程同时限制手动射击，默认零值保留原手动射程语义。
- 文件与生命周期：独立策略 XML 格式为 **3**，必须显式带版本；完整解析／校验后复制替换，不接受旧开发格式。策略只引用组别／武器 Def 和点集，不包含目标或武器实例 ID。逐建筑 Scribe 延续 prefab、主备用、shuttle 与归档契约；运行时部件锁、队列、时钟和观测不存档，清理／丢图／controller 销毁释放。
- 离线验证入口：`scripts/NpcRetreatRegression` 覆盖规则迟滞与作用域、目标资格／重选、停火、覆盖、配置复制与 XML／逐建筑 Scribe、失效目标、坐标及既有驾驶／归档链，当前 1244 项通过。`scripts/CombatManeuverSimulation` 保留真实战机对照和多船成本数据；详见[验证记录](../scripts/CombatManeuverSimulation/README.md#策略扩展验证2026-10-29)。115 格、45 格/秒时，新换位的固定射手擦弹为 0%，移动射手对照约 1.94%；不是重炮规避验收通过。多船火控相对成本超过原定 1.25 倍门槛，完整运行时性能仍待收口。游戏内 UI、主备用／shuttle／prefab 全流程、双方实际命中率和多舰帧耗由用户实测，不能以离线通过代替。
- 敌舰人员岗位复用现有事件驱动分配：有效驾驶台和可用载人舰炮优先下达原版 `ManTurret`；剩余敌对船员加入原版 `LordJob_DefendPoint`，守卫所在船体范围并迎击登舰者。失去驾驶台后不再有炮手 controller，但原有口袋图中的船员仍可凭容器派系或已记录的 NPC 船身份获得守卫任务；已有 Lord／duty、俘虏及其他派系 Pawn 不被征用。原版通用离图任务对软对接入口的过滤保留为防循环兜底。
- Combat 日志开关打开时，`NpcShipAiService` 只在资格门禁、目标、姿态／环绕任务、撤退与无推力状态变化时输出；`Dump universe state` 从同一资格门禁和索敌谓词读取阻断原因、敌对目标数、当前图可用推力与自动驾驶状态。地图身份统一使用 `UniverseManager.MapTag`，诊断不改变目标或任务。日志与诊断结果均须游戏内验证。
- 当前重炮命中率排障使用 Development 模块的 `cannon-shot launch/result` 逐发事件，按弹体容器 ID 关联。仅有锁定船目标的 `DeltaV_Projectile_Cannon` 记录发射距离、船体包围圆半径、目标初速、预瞄提前量、炮口偏差与散布；飞行期仅在开启诊断的弹体上追踪相对目标的最近中心距离和目标偏离发射瞬间匀速预测的位移。`hull-hit` 以 `SpaceCollision` 真实命中回调的船体身份为准，盾面拦截、其他目标命中、越过目标和超时分开报告；`circleClearance` 是包围圆辅助量，不能替代建筑格命中。诊断状态由 `UniverseManager.Projectiles` 实例持有，弹体回收时清除，不入档。

### 战斗规划性能统计

2026-10-29 按用户要求将以下探针永久纳入 `Performance` 分类，沿用五秒窗口及 `detail[avgUs/maxUs/calls/totalMs]`，不依赖 `Development`。均为主线程 CPU；嵌套阶段不能直接求和。

| 字段 | 计时范围与解读 |
| --- | --- |
| `CombatPlan` / `CombatRule` | 完整战术请求（含复用、早退）／实际重新读取事实并匹配规则。 |
| `CombatPose` / `CombatPoseSetup` / `CombatPoseSearch` | 完整射位重算／武器、敌舰风险与友舰快照等准备／`Choose` 搜索。完整重算还包含所选射位的最终风险复核，不含开发日志格式化。 |
| `CombatRisk` / `CombatOutput` | 风险和预计输出回调，嵌套于搜索；风险还包含最终复核，调用次数不是唯一候选数量。 |
| `CombatReposition` / `CombatRoute` / `CombatRouteShape` | 换位更新／路线安全检查／路线检查的船体形状缓存未命中构建。 |
| `CombatTrajectory` | 按射位、实际推力和当前状态生成参考轨迹，包含内部推力预览。 |
| `DrivePreviewModel` / `DrivePreviewBraking` / `DrivePreviewAngular` / `DrivePreviewAllocation` | 控制模型（含无加力模型）／反推能力／角加速度／分配器预览。跨战斗、导航与其他调用方汇总，不能全部归因于射位搜索。 |
| `MpcAssemble` / `MpcFeasibility` / `MpcQp` | 有效请求的模型与矩阵构建／实际不可行性预检／实际 QP 求解。被预检拒绝时不计 QP 调用。 |
| `MpcBrakeRecovery` | 恢复制动分支的请求调整、预览、求解或反馈回退，内部可能包含上述 MPC 阶段。 |

`poseReplans` 是窗口内完整射位重算次数。`poseCauses[overlap]` 分别累计 `InitialOrTarget`（无有效战法，含目标变化后的清理）、`Configuration`、`Groups`、`Permission`（火控收益权限）、`Drive`、`Structure`、`Rule`、`Periodic`（射位周期到期）。一次重算可同时命中多个原因，不能相加当作重算总数；结构版本变化是触发事实，不等同于已测得的缓存重建耗时。

`poseWorst` 保留窗口内最慢一次完整射位重算的船身份、`MapTag`、毫秒、触发原因，以及主武器快照数、敌舰数、敌方武器风险快照数和友舰数。它用于将耗时峰值对应到工作量，不保留候选或船对象列表。窗口清零时释放所记 Map；这些数据不入存档。关闭分类时不读新增计时钟、不累计新增统计、不构造输出字符串；启用会增加测量成本，不能把开关日志前后的耗时差解释成优化效果。

现有 `autopilot` 均值仍为 ms/tick，`mpcSolve` 为 ms/求解，新增 detail 则为微秒/调用及窗口总毫秒。结合 `structureChanges`、`poseCauses` 和 `poseWorst` 区分频繁重算、单次搜索昂贵与真正的 QP 热点。统计不改变候选、评分、策略时钟、求解预算或推力。离线等价检查与测试环境限制见[探针验证](../scripts/CombatManeuverSimulation/README.md#战斗性能探针验证2026-10-29)。

### 9.1 远距整图归档与撤退

- 星区 POI 生成时固定 prefab 路径和姿态顺序，物化后由普通容器持有；空间站分类以 `FactoryStation` 取代敌对站，敌友取决于派系。未单独编辑策略的驾驶台和 shuttle 使用内置通用规则，NPC 的关键战损撤退判据仍作为生存底线。
- 远距普通口袋容器通过 `ArchivedMapStore` 调用原版 `Map.ExposeData`，压缩 XML 作为 `ArchivedSpaceObject.mapData` 随游戏存档保存。`Game.DeinitAndRemoveMap` 会把 Pawn 传到 World、通知丢图并清空 Things，因此归档适配层在保存快照后清理废弃运行时图中 Thing、District、Region 的地图索引和信号接收器，更新后续地图索引，移出 `Game.maps` 并释放资源；同时清除指向旧 Map 的历史目标和场景引用，保留 pocket parent 供 MapInfo 交叉引用。原版贴图缓存随后可安全回收旧 Pawn；Delta-V 的待补弹、推进器音效与排气余量等运行时索引按源图清理，随后清空废弃图的 `spawnedThings` 以断开 Thing→Map 持有链。指向该图的排队事件、进行中任务目标或全局异常石柱存在时暂缓归档，避免丢失地图外的长期状态。恢复时注册派系、意识形态、任务、世界对象、世界 Pawn 及其他地图的递归 Thing 引用，调用原版 `Map.FinalizeLoading`，成功后才清归档数据。玩家图、玩家 Pawn、原生 MapParent、弹体图与当前聚焦图不归档。
- 原版 `MoteBase.isSaveable=false`，`Map.ExposeData` 保存时已排除 Mote；它们也按 `ThingDef.HasThingIDNumber` 不取得持久编号。外部引用注册遍历的是其他已加载地图和全局对象，必须单独排除这些当前活着的 Mote，不能靠修改归档 XML 解决。该入口只按对象实例去重，两个持久对象占用同一有效编号仍进入原版冲突诊断，不按 ID 静默跳过。
- 保存前递归检查源图可保存 Things（含容器内容）的持久 ID：缺 def、应保存却无持久编号、负数编号或不同实例占用同一编号时拒绝归档，留下原图，不删除对象或擅自重编号。不保存的瞬时效果不参与该检查。原版序列化仍是唯一写入路径。
- 运行中恢复必须像原版 `Game.LoadGame` 一样，在同步作用域内使用 `ProgramState.MapInitializing`，退出（含异常）恢复进入前状态，不跨帧持有该上下文。2026-10-26 实测 #17 Enemy ship 的两名成瘾船员触发 `Need_Food.MaxLevel → StatWorker → Hediff_Addiction.Need` 空引用：原恢复器仍处于 `Playing`，需要构造尚未完成就查询了 `pawn.needs`。已补足原版加载上下文，并在地图发布前按现有 XML 的 `id + needs/needs` 核对加载 Pawn 的需求；Scribe 吞掉构造异常导致 Pawn／需求缺失时拒绝恢复、保留原归档，不再把这类半加载当作完成。此核对不宣称覆盖全部第三方 Comp 保真度。
- 离线归档与驾驶专项共 53 项通过，新增项用原版 Food／成瘾属性链复现异常，核对初始化分支、成功／异常／嵌套时全局状态恢复，以及保存 ID 与需求缺失拒绝。实际带成瘾船员的归档往返仍待游戏内复测；既有错误运行中已丢失的需求不能据此视为已恢复。
- 恢复开始、成功／失败事件常开记录对象 ID、名称、`MapTag` 与 parent；尚无真实 Map 时另外标注归档 map ID。不会逐 Thing 输出日志。性能分析另计 `ArchiveCapture`、`ArchiveRestore` 和 `SyncMapGeneration`；这些是实际操作 CPU 区间，可能嵌套在帧队列或其他生成阶段中。
- 真正开始 `Map.ExposeData` 前常开一条归档事件，写对象 ID／名称、船身份、tag、Map 身份、parent ID 与玩家距离。独立 Map 序列化产生的原版 Scribe 引用警告紧随该事件，可据此区分拆分残骸与其他普通口袋容器；这条事件不随生命周期诊断开关关闭。原版开发模式检查器只按当前独立 XML 判断引用是否同时被深存，因此 parent／Faction 等外部引用会报警；恢复器显式注册这些外部对象再解析交叉引用。该警告本身不能证明恢复失败，实际往返仍以游戏内验收为准。
- 2026-10-26 新日志中的 16 次归档均标为「残骸」，`ships=[]`；每次后续三条原版引用警告对应 pocket parent 和两个 Faction。该记录确认本次警告来自拆分残骸的独立 Map 快照，未证明恢复链成功或失败。
- 撤退、返厂目标和退场时机由 `NpcShipAiService` 决定。AI 首次记录初始推力、火力与主驾驶台（包括初始为零的能力），有图时每次决策根据当前战损重新判断；恢复地图后同样重新判断，不把保存的撤退标记当作永久命令。距离休眠、归档与恢复不读取撤退意图，也不为撤退舰豁免普通资格门禁。`UniverseManager` 在物化时通知 AI 记录初始能力并交接 marker 引用；归档前的通知只让 AI 记录派系、当前推力／火力／主台，并由有图对象捕获数值动力摘要，不触发撤退判断、选船厂或下导航命令。正常 AI 决策周期通过同一战损判据读取真实地图或观测摘要。
- 返厂目标与有效性统一由 `NpcShipAiService.ResolveRetreatHome` 管理：只选已生成的同派系 `Shipyard`，距离相同按对象 ID 排序；有效目标保持，失效后重选。物化后的船厂以当前船只派系判定，空壳或混合派系不接收返厂；AI 在归档前保存该判定的派系 `npcFaction`，供无图查询。marker 物化时将现有返厂引用交接给新容器。
- 实体受损舰到厂不删除、不治疗；到厂本身不解除撤退，是否继续撤退仍取决于 AI 对当前战损的判断。站位在船厂背离威胁的一侧，半径 = 双方以容器原点计的碰撞包围半径之和 + 20 格；碰撞范围仍由 `SpaceCollision` 同一结构缓存提供。进入该半径外 20 格内即可还击，剩余武器走共同火控，推进器失效不禁止还击。威胁消失保持站位；不追远、不跳帮，守军沿用现有 AI。防守目标和改令时机由 `NpcCombatAi` 持有：无任务、母港变化或目标相对上次下令变化达到 1 格／5° 时调用既有 `ShipAutopilot.TrackTo`。船厂自身移动由原有随动任务处理；自动驾驶接口与制导算法不增加返厂、防守规则。
- 无图路线由 AI 按决策周期更新：无船厂时续设避战临时航点，船厂失效则重选。AI 调用现有 `ShipAutopilot.FlyTo/TrackTo`，无图主体和实体主体进入同一个任务表、`Step`、MPC 制导、`ForceToCommand → Allocate → Integrate`；没有独立归档巡航算法或固定巡航速度。无图导航只接受归档前已独立飞行的单船，不能在无图状态替代分离流程。`ShipPhysics` 不读取目的地或选择航向。跨星区、到达临时航点或旧船厂坐标均不退场；无推力时只有原速度漂移。
- 动力摘要由 `MapSpaceObject.CaptureArchive` 保存逐台推进器位置、方向、有效推力及质量、惯量、质心和驾驶主体帧角；不含真实 Map／Thing 引用、油门、工作区或导航计划。`ArchivedSpaceObject` 用同一分配器执行该数值布局；不近似六个响应、不引入额外预算，也不模拟图内燃料／电力消耗。恢复后释放摘要并读取真实图。统一驾驶契约与全部调用者入口见 [在线 MPC 自动驾驶](在线MPC自动驾驶.md#驾驶契约与调用入口)。
- `UniverseManager` 逐游戏 tick 调度同一自动驾驶、手操及对象漂移接口，对象层保证每 tick 仅积分一次；随后复核普通距离恢复与 AI 到厂判断。归档／恢复在帧边界经 `ReplaceRepresentation` 保持 objectId、绝对位姿与长期事实，递增表示版本且不调用普通注销／新生。导航与对接宿主保留对象 ID，火控及弹体按 §6.2 的船／容器身份解析当前实例；延迟动作校验预期版本。表示切换清掉主体旧任务，正常 AI 周期重新决策。读档同样重建任务，不通过 prefab 重建人员。

- AI 仅在已归档撤退舰距离当前有效船厂 ≤20 格时请求退场：通过 `QueueFrameAction` 去重排队，在帧边界再次校验目标与到达条件，然后调用生命周期的通用 `TryRemoveArchivedContainer`。该入口不识别船厂或撤退策略，只负责玩家接近／已排队恢复优先、原图恢复和安全销图。先用同一 `ArchivedMapStore.TryRestore` 恢复原图，再经 `DeinitMap` 调用原版 `MapDeiniter`，将存活 Pawn 交给 World Pawns，最后清除 pocket parent 和对象。容器内存活乘员先通过原版 `ThingOwner.TryDrop` 放回地图，避免仍被舱体持有而遭后续递归 `Notify_MyMapRemoved` 清理；放出失败保留恢复图、中止退场。该后台结算不切镜头、不安排战斗 tick。人员保留原身份、关系与伤病，后续保存、伤病演变和再次选用均走原版；不模拟维修时长或生成替代舰。
- 归档失败留原图，恢复失败留归档并报错；恢复成功后立即转由恢复图承载事实，后续注册或销图异常不得再次读取旧快照复制船员。玩家追近恢复优先于到厂退场，恢复后发现玩家保护对象则取消退场。完整地图状态、人员交接与外部引用仍须按 §13 的专门场景实测。

## 10. 架构接线与单实现纪律

- **原版复用优先级纪律（2026-09-26 新增）**：**能直接调用原版函数解决的，直接
  调用；能经简单 Prefix/Postfix 解决的，用简单补丁；只有两者都不可行时才允许
  做镜像，且镜像必须收口唯一入口并注明来源与理由。** 应用实例：shuttle 起飞
  校验 = 原版发射校验函数结果直接取用；炮手就位 = 原版 `CompMannable + ManTurret`，
  Delta-V 只适配自瞄、调度和显示／建造策略；护盾容量 = 原版 comp 公共字段直写；伤害应用 =
  `GenExplosion/DamageInfo/TakeDamage` 原版原语；降落冷却 = 原版触发入口（优先
  直接调用/简单 Postfix，施工核对后固定）。
- **实例服务**：`universe.Projectiles`（弹体创建/注册、制导、超时、渲染、图池、
  ResetFlow）与 `universe.Shuttles`（起飞/侵入编排含 弹体角色接管；停靠直接用对接
  计划服务、搬运核心复用 ShipTransitions 的 `TransferDomainToNewPocket`）。均不
  序列化、读档归零。
- **tag 分派改造**：`SpaceObject` 增 tag 字段（枚举含船容器/POI marker/弹体/
  shuttle）；剪影（ShipSilhouette/PlanetGlobeRenderer/WorldShipMarkerRenderer）、
  星区记账（SectorContentService）、被动阻力与积分快路径（ShipPhysics/容器积分
  循环）、显示朝向、碰撞主动参与、**序列化过滤**（写档剔除弹体 tag）一律按 tag
  单点分派——现有各查询点逐一改造，不散写 tag 判断。
- **碰撞核心单实现**：占用集/弧几何、扫掠求交、参与判定、事件构造收口
  `SpaceCollision`（弹丸/激光/侵入/PD 四消费方共用）；相对速度/角度解算经
  `SpaceTransform`。**不得出现第二份求交或第二份己方排除规则**。
- **联合效果注册表单实现**：命中判定与后效的唯一来源；同等耐久舱壁兜底单点；
  「生成弹体」（跳弹/将来自反弹片）出口预留。
- **渲染**：弹体（弹体 building def 图形投影）、激光线段、预瞄与瞄准标记走聚焦帧
  投影 + ShellRenderer 前景层槽位（池化）；在飞 shuttle 走标准非聚焦外壳渲染。
- **Harmony 新增面**：瞄准会话内的左右键让位与瞄准键抑制（被绑定键的原版功能在
  驾驶期让位，**不含空格/暂停**——瞄准模式不占用暂停）；（如核对需要）原版冷却
  触发点。不 patch 原版 verb/射击/拦截代码。
- **按键设置**：瞄准键进 "Delta-V piloting" 分组（默认 B）；**tooltip 文案建议
  玩家不要绑定暂停等关键功能键**（Keyed）。
- **诊断日志**：发射/命中/拦截/跳弹/放行/撞停/弹体角色接管等用户事件级输出（边沿
  触发）；每 tick 碰撞求交热路径不埋点或按 `DeltaVLog.Enabled` + 状态变化。
- **tick 顺序调整随施工同步 [代码入口索引](代码入口索引.md)**（§3.3 新节奏）。

## 12. 新增不变量（定稿候选）

1. 一切模拟（弹体飞行/激光判定/PD 索敌/侵入追踪/碰撞与结算）只认游戏 tick（不变量
   #20 延伸）。
2. **「弹体」「飞船」是抽象角色不是类型**：代码只有容器 + tag + 注册效果；弹体 =
   注册进 objects 的弹体 tag 容器 + 弹体 building；一切行为分派（剪影/星区/阻力/
   显示朝向/碰撞参与/序列化过滤）按 tag 单点。
3. 碰撞是容器级特性、自研单实现核心（宽相位 + 格网步进 + 弧闭式求交，全部经
   SpaceTransform）；不引入物理引擎代理场景；**碰撞主动参与按 tag**（弹体恒为
   主动方，任何有碰撞面的容器都是合法被撞目标）——开放飞船碰撞 = 放开 ship tag
   主动参与 + 注册结构后效（舱壁×舱壁互相毁伤），不改核心。
4. 一切命中先经联合效果注册表的**命中判定**（二值：产生后效/放行），后经**命中
   后效**；跳弹（生成出射角同型弹）、放置（shuttle 进船）、自毁、破片毁伤、护盾
   消耗都是后效种类；无注册对按同等耐久舱壁规则兜底。
5. **结算对称**：碰撞事件对每个参与容器各自派发，各容器用同一 def 对解析并执行
   自己的后效；不存在攻守两套结算逻辑。
6. 命中事件附带几何事实（两侧 building、相对速度标量/矢量、入射角）一次性计算；
   参与方只消费不重算（「注册即唯一」纪律的碰撞版）。
7. 图上应用只用原版公共伤害原语（TakeDamage/GenExplosion/DamageInfo）；不 patch、
   不复刻原版 verb/射击/拦截算法。
8. **原版复用优先级**：直接调用 > 简单 Prefix/Postfix > 镜像（最后手段，须收口
   唯一入口并注明来源）；shuttle 起飞校验 = 原版结果直取是应用实例。
9. **shuttle 与飞船不得有两套逻辑**：起飞/飞行/降落/受击全部同一实现；shuttle
   特有的只有降落后处理（回落建筑 + 原版冷却）与侵入能力（真实推进器截击与共同碰撞）；对接
   计划管线的差异仅限计划脚印来源参数。
10. 护盾容量事实驻留原版 comp（建筑上）；同图战斗 = 原版机制原样；太空弧几何是
    派生缓存，不成为第二事实源。
11. **可拦截性是结构派生**：有图（依托内部建筑存在）∧ tag ∈ {projectile,
    shuttle}；不是 def 标记；有图 ⇔ 可拦截（弹体）；PD 索敌按同一判据；拦截
    shuttle 与拦截导弹同链；**侵入式对接 = 原 shuttle 的真实推进器截击，
    以附加 projectile 角色运行共同碰撞和后效机制**。
12. 可切换炮塔的地面／太空模式互斥：同图 = 原版炮塔 Verb；跨容器 = 本架构；
    两模各走其原有射击链，只共用武器实例的模式事实。
13. **火控模式是主驾驶台存档事实**，默认自动，面板或 B 键切换；手动集火的输入会话
    由玩家船 controller 持有，只有聚焦图所选船接收鼠标，跨聚焦挂起、跨对接换图保持，
    船损毁自动析构。自动战斗机动属于玩家 controller 的运行时自动任务，读档后回到自由漂移。武器组 = 主/副两套 ×
    1–6 组（gizmo 弹出菜单指派套别+组号）；点防与战斗位置独立。
14. 顶部炮塔弹排除己方容器、舰中武器弹包含（可自伤）——唯一开关在武器 comp。
15. 武器组别（套别+组号）、两套激活位、炮手预留、PD 模式和主台火控模式是存档事实；
    弹体、侵入计划、驾驶、瞄准会话、自动战斗机动及图池是运行时数据。
16. shuttle 在飞 = 自管理 MiniShip：无基架/驾驶台/归属、不进 ShipRegistry；停靠后
    回落普通建筑；起飞/停靠经统一搬运核心与对接管线，不自建第二套；装卸复用
    原版。

## 13. 验收场景（施工后游戏内验证）

1. 双船任意位姿/角速度下瞄准模式开火弹道与命中正确；瞄准标记随鼠标、预瞄标记与
   匀速目标实际截击点一致；导弹追踪转弯目标命中。
2. 火控交互：面板按钮与 B 键切换所选船的自动／手动；驾驶中空格暂停照常；手动会话
   左键射主套、右键射副套，原版点选／命令让位。退出驾驶保留手动模式；切换聚焦时
   会话挂起。同图其他手动船停火，自动船仍索敌。自动战斗机动从自动任务菜单选择；驾驶键接管时暂停，切回自动时重新选敌。
3. 武器组两套：左键只打主套激活组、右键只打副套激活组；关组即停射；进入战斗位置
   为全部可用武器上人，人手不足时优先激活组；再次进入按最新预留完整重排。
4. 弹道不依赖聚焦：切聚焦不改弹道；未聚焦敌舰被命中，毁伤正确落其图（日志核对
   universe 点与图格互逆一致）。
5. 对称结算：射弹射入船体 → 船侧破片毁伤（命中位爆炸/递减摧毁基架/人员杀伤）与
   弹体自毁同链发生；点防激光打导弹 → 导弹图内 building 被毁 + 射束临时容器自毁；dev 日志
   可见双侧后效。
6. 联合效果两段：射弹+基架概率放行（放行弹继续飞、可再撞内部结构）；激光+基架
   固定伤害；激光+舱壁入射角决定伤害；射弹+高耐久舱壁斜入射走跳弹后效（当前
   默认消灭无伤、出射弹生成出口存在但未启用）。
7. 兜底：未注册 def 对按同等耐久舱壁规则结算（伤害/跳弹随耐久与相对速度）。
8. 相对速度参与毁伤：对头命中 > 追尾命中同 def；斜入射穿深低于正入射。
9. tag 分派：弹体出现在 objects（dev dump 可见）但不进剪影/星区计数；弹体不受
   被动阻力减速（同速对照组衰减、弹体不衰减；shuttle 照常衰减）；写档后读档无
   弹体残留；弹体 ID 经单一计数器、读档对齐不撞号。
10. 顶部炮塔跨己墙不误伤；舰中固定武器朝己方射击命中己方墙自伤。
11. 护盾：弧方位随船姿旋转；命中弧消耗原版 comp 容量（与同图战斗共享同一份容量
    状态）；容量击破后弧失效、弹体放行撞格；供电充能/断电放电走原版节奏。
12. PD（结构判据）：拦截**正常飞控 shuttle（shuttle tag）**、侵入 shuttle
    （projectile tag）与有图导弹/有图直射弹；不射击无图弹与飞船（ship tag 不在
    判据内）；不响应瞄准模式射击；受武器组激活门禁；拦截敌我对称。
13. 图池：持续齐射下图池无泄漏（弹体销毁即注销归池）、无每发建图开销（profiling
    对比）；池内空闲图不被生命周期收纳。
14. 武器模式：地面模式对原版同图目标作战（无 SpaceObject 介入），太空模式只对跨容器目标开火；
    切换中停止未完成地面连射，反跳帮需选地面模式；RimExodus 同装地表零影响。
15. 炮塔、导弹架与轨道炮部件的脚印和旋转建造规则；射界外不发射。
16. 战斗位置征用全分支（预留优先/随机兜底/drafted 排除/激活组优先但不排除未激活组）；
    进入重排、退出人数与实际岗位一致；选中炮手不绘制岗位连线。
17. 炮手技能/插件级别差异体现为散布单调变化。

### 玩家驾驶任务交接（2026-10-26）

玩家每艘船的 controller 仅有手动控制或自动控制，自动控制一次持有一项任务：自由漂移、速度同步、战斗机动、定点定角驾驶或系统发起的软对接制导。火控与驾驶任务独立。手动接管停止自动出力并暂停任务；切回自动时复核主体及目标，失效则回到自由漂移。战斗机动无有效敌舰时保持任务并显示寻找目标。玩家选择其他任务时替换旧任务；速度同步的计划和稳定计时同时清理。软对接制导在手动接管后暂停，不自动重挂；其配对或目标失效时结束。玩家任务不接管 NPC 决策或侵入弹体制导。定点制导的几何和完成策略详见[在线 MPC 自动驾驶](在线MPC自动驾驶.md)。
