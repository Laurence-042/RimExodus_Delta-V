# 太空战架构

飞船 HP、暴露部件、推进器、撤退台与护盾实例从[飞船结构索引](飞船与SpaceObject解耦架构.md)取得。碰撞的局部块消费旧、新占地及地形格，盾几何与容量分别发布，炮口和轨道链只响应依赖格。导弹设施的接入和回归状态见[迁移记录](飞船结构增量索引迁移.md)。：统一容器碰撞、联合效果与 Shuttle 化跳帮

**状态：现行架构与早期设计记录（更新于 2026-10-24；截击飞控与六推进器布局待游戏内验证）。**
本文是阶段5太空战与 shuttle 化跳帮的专题文档；涉及当前控制行为时以 §6、§9 为准。
武器定位与克制关系以[武器基线的 2026-11-05 定案](舰炮与护盾基线.md#roles)为准；当前架构接线与数值不等于平衡目标已满足，尤其不能以激光热锁、通用长冷却或拉平 DPS 替代各武器分工。
护盾当前机制与待测项目以[护盾机制](舰炮与护盾基线.md#geometry)为准；本文后段仍保留部分早期圆弧盾施工记录，不作为当前机制依据。
核心模型：**「弹体」「飞船」都是抽象概念，不是类型**——代码里只有容器
（SpaceObject）；弹体 = 注册进 `universe.objects` 的、带**弹体 tag** 与弹体 building
的容器；一切命中都走**容器 collider 碰撞 → 取出两侧 building → 双 def + 相对速度
（标量与矢量）的联合效果注册表**（命中判定二值 + 命中后效），**每个参与容器各自
解析自己的后效**。侵入式对接复用真实推进器和 MPC，碰撞与后效共用弹体链；shuttle 与飞船共用同一套
起飞/飞行/降落实现，差异只允许在降落后处理。**旧跳帮舱机制整体退役**（§8）。施工
具体待验证项记在 `doc/TODO.md`；玩家可见入口见 README，单实现位置见 [代码入口索引](代码入口索引.md)。

术语：**容器** = SpaceObject 地图容器（[解耦架构](飞船与SpaceObject解耦架构.md)）；
**船** = 驾驶台认领归属 + 控制域；**弹体（抽象角色）** = 带弹体 tag + 弹体 building
的容器；**联合效果** = 注册表里的两段式碰撞效果（§3.4）；**MiniShip** = shuttle
在飞形态。

## 1. 动机与范围

- 阶段1–4 已验证参考系、连续驾驶、POI 生命周期、对接/分离与解耦重构；阶段5 补齐
  战斗。范围（2026-09-26 定案）：
  - **发射入口 = 归属 controller**：玩家主驾驶台默认自动火控，侧边栏或可配置 B 键
    切换为手动集火；手动会话按鼠标位置瞄准，左键射击主套、右键射击副套激活组。
    自动火控与 NPC 共用选敌组件，所有齐射复用同一转向和发射链；炮手位置与点防独立。
    火控键不占用空格／暂停；弹道受武器散射与炮手技能影响，预瞄只作显示；
  - **武器 = 专用 def 体系**（§5），且**同时携带原版武器 comp**：地表图上作为原版
    防御武器工作（原版机制、不经 SpaceObject）；后续可给原版武器追加本 mod comp 使
    其太空可用（仅预留思路）；
  - **弹道三类**：直射弹、激光（即时）、导弹（制导）——弹道类型与「可否被点防御
    拦截」正交（§3.2）；
  - **统一命中机制**（核心）：容器之间 collider 碰撞 → 根据 collider 获取碰撞的
    **两个 building** → 根据**两个 building 的 def + 相对速度（标量与矢量）**经
    联合效果注册表结算——**对称结算**：每个参与容器各自解析自己的后效（例：射弹
    射入船体——飞船容器的后效是对自己内部图产生破片毁伤，弹体容器的后效是摧毁
    弹体）；
  - **弹体容器注册进 `universe.objects` 并携带自己的 tag**：剪影、星区显示等一律
    按 tag 过滤；数据一致性由同一列表保证（船/shuttle tag 有显示朝向策略、弹体
    基础类型为 Projectile 的普通弹体不被被动阻力减速；将来弹体要上星球仪只是改过滤）；
  - **侵入式对接**：弹体服务接管现有 shuttle 的碰撞任务，飞控使用真实推进器、限时主推加力与截击 MPC；命中后效破拆并调用共同 Gravship 降落链（§7.5）；
  - **碰撞核心自研**（2026-09-26 讨论定案）：宽相位包围域 + 窄相位格网步进 + 弧
    闭式求交，全部经 `SpaceTransform` 现有坐标入口；tick 锁定、零分配、不引入
    Unity 物理代理场景（分析见 §3.3）；将来做物理化碎片场时再独立评估；
  - **点防御**：不受驾驶瞄准控制、自行瞄准**可拦截容器**射击；拦截 shuttle 与
    拦截导弹完全是同一个机制。**可拦截性是结构派生**（2026-09-26 修订）：可拦截
    由存活的无图导弹载荷或在飞 Shuttle 船体提供。

阶段5 原始范围外的舰体相撞现已接入共同弹体后效（见下文）；其余范围外项：
可反弹弹型的实际实现（留扩展位）、原版 pawn 武器的跨容器桥接、飞船/shuttle 燃料、
开火后效实现（只留接口）。

## 2. 概念与权威数据

| 概念 | 权威事实 | 不承担的职责 |
|---|---|---|
| 容器（唯一实体类型） | SpaceObject：tag、位姿/速度、（可选）图、弹体 building（弹体角色时） | 「弹体」「飞船」只是抽象角色，不是类型分叉 |
| tag | SpaceObject 上可叠加的角色 flags，以 `HasTag` 查询；剪影、星区记账、被动阻力、显示朝向、碰撞主动参与、序列化过滤由对象统一分派 | 不替代派系/归属语义 |
| 弹体（抽象角色） | SpaceProjectileService 管理制导与扫掠。SpaceObject 提供宇宙身份与位姿，导弹载荷持有原 Building | 纯弹体在写档时剔除 |
| 可拦截性 | 存活导弹载荷或在飞 Shuttle 角色 | 点防和扫掠使用相同目标身份与耐久 |
| 碰撞核心（SpaceCollision） | 容器级特性：碰撞面（占用格集 + 护盾弧）、扫掠求交、参与判定（tag）、命中事件（两侧 building + 相对速度） | 不结算效果（只产出事件）；不决定生命周期 |
| 联合效果注册表 | 一切命中后效的唯一来源：键 =（弹体 building def × 对面 building/基架 def），入参 = 相对速度标量 + 矢量（入射角）；每个参与容器各自取自己的后效 | 不持有运行时状态；纯函数式解析 |
| 护盾容量 | 原版 `CompProjectileInterceptor.currentHitPoints/HitPointsMax`，事实驻留护盾建筑 | 太空弧几何是派生缓存（随容器姿态旋转），不是事实源 |
| 地图容量 | 导弹与普通弹体无需地图，侵入 shuttle 使用自己的飞行图 | [无图实体迁移](无图实体迁移实施计划.md) |
| 玩家火控 | 各船身份锚通过 `ShipCombatState` 保存自动火控／手动集火，默认自动；`ShipFireControl` 供玩家与 NPC controller 共用选敌和齐射意图 | 自动候选共用 §6.1 的有效敌船资格；手动仅所选船的 `SpaceAimController` 采样鼠标；火控提供明确请求，武器层执行转向与发射事务 |
| 自动战斗机动 | `ShipAutoManeuverControl` 供玩家与 NPC controller 共用交战姿态选择和持续战法执行 | 玩家 controller 的自动任务之一；选中时替换旧任务及其同步计划，任意驾驶键可暂停，目标暂缺时显示“寻找目标” |
| 武器组 | 两套（主/副）× 每套 1–6 组；武器 comp 持久字段（套别 + 组号）+ 每船两套激活位 | 不存炮手 job 状态 |
| 点防御（PD） | 武器 comp 的瞄准模式；所在船的 `ShipFireControl` 按武器实例保存锁定、重选并请求射击 | 不受驾驶或玩家瞄准状态控制；不占玩家瞄准 |
| 武器（CompSpaceWeapon） | 持久配置：瞄准模式（齐射/PD）、组别、弹道、射界、散射、冷却、挂件/加速连接点与安全限制 | 同图/地表战斗可选走原版炮塔；共享炮手、转向和默认弹仓门禁 |
| 炮手预留 | `CompSpaceWeapon.reservedGunner` 实例持久字段（含「不指定」） | 只是分配偏好；实际操作人只读原版 `CompMannable`，操作格只读原版交互格 |
| MiniShip（shuttle 在飞） | SpaceObject 容器 + `ShipBase` 的 `ShuttleShip` 实现；角色为 Ship + Shuttle，侵入时追加 Projectile | 不使用基架归属域；停靠后仍为船成员，但不保留独立容器或驾驶宿主 |

## 3. 统一容器碰撞与联合效果（核心）

### 3.1 弹体与飞船是抽象角色，不是类型（已定）

- 宇宙碰撞消费 **SpaceObject 容器的角色**。「弹体」「飞船」「攻方/守方」由
  **tag + 注册效果 + 服务数据** 组合；共同船体接口及不同实现见
  [飞船与SpaceObject解耦架构](飞船与SpaceObject解耦架构.md) §2，碰撞不依赖具体船型。
- 弹体角色的三要素：弹体 tag（注册进 `universe.objects`，经 `AllocateOwnerId`
  正常发号——单一计数器纪律不变，弹体发号量大但 int 空间在游戏时长内无实际风险）、
  弹体 building（身份载体：def 作注册表键、脚印作 collider、HP 作受击、贴图来源）、
  服务侧弹体数据（制导律、超时、launcher/equipment 引用）。
- **tag 分派的行为**（单点分派，不散写判断）：
  - 剪影/星球仪/星区记账按 tag 过滤（弹体不进剪影与星区计数；将来弹体要显示在
    星球仪上只改过滤，机制已就绪）；
  - 显示朝向策略按 tag（船容器与 shuttle 按自身位姿角；无姿态角的点状弹体按
    速度方向）；
  - **被动阻力按 tag 豁免**（弹体不受被动阻力减速；shuttle 与船照常受阻力）；
  - **碰撞主动参与按 tag**（见下）；
  - **序列化按基础 tag 过滤**（baseTag 为 Projectile 的纯弹体是瞬态成员，写档时
    从 objects 过滤视图剔除；侵入 shuttle 只追加运行时角色，仍保存艇体与地图）。
- **碰撞参与 = 主动方角色（已定口径）**：projectile tag 容器恒为碰撞**主动方**
  （移动的攻击体）；shuttle/船 tag 不作主动方，但**任何有碰撞面的容器都是合法
  被撞目标**（飞船被弹体命中正是此路径——目标资格只看有无碰撞面）。**后续开放
  飞船碰撞 = 允许 ship tag 作主动方 + 注册飞船结构件联合后效（舱壁×舱壁互相
  毁伤），不改核心。**
- 侵入模式的 shuttle = **弹体碰撞服务接管 + 追加 Projectile 角色**，保留 Ship 与 Shuttle；
  弹体工作项负责目标解析和扫掠，MPC 负责真实推进，面板中止或目标失效时交还原艇体；命中后效解除接管并
  用共同 Gravship 链落地。baseTag 保持 Container，读档后从船体重建 Ship／Shuttle 角色并按飞船继续存在。
- **对象类别角色（2026-11-26）**：`Ship` 是承载任意 `ShipBase` 的总体标识，船体 `RolesIn`
  同时叠加子类角色——基架船 `Foundation`、一体式船 `Shuttle`、舱外人员 `Personnel`。
  容器按统一结构版本缓存。舰载武器的目标类别只在 `SpaceObject` 单点分派：点防只认
  导弹载荷与“容器内有一体式船正在独立飞行”的对象；自动选敌、自动机动锚点和导弹
  沿射线锁定只认 `Shuttle`／`Foundation`。人员永不成为舰载武器目标，只作为碰撞受击对象。

### 3.2 弹体载荷与可拦截性

存活的无图制导导弹持有原版 Building，提供脚印与耐久。独立在飞 Shuttle 仍提供真实地图上的艇体。点防依赖同一目标的角色、派系、脚印和耐久。普通实弹与激光使用 Def 与短命弹道记录。

导弹直接命中使用原版伤害接口。旧单格爆炸转为下一 tick 对同一真实实体的中心伤害。真实舰图仍用原版地图爆炸。

### 3.3 碰撞面与扫掠求交（自研，已定案）

- **实现路线定案（2026-09-26 讨论）**：自研单实现——宽相位包围域 + 窄相位格网
  步进 + 弧闭式求交。依据：负载形态为「几十个移动体 × 数千格占用集」的数组下标
  查询，无凸体/关节/堆叠需求；Unity 物理需要维护平行欧氏代理场景（第二套坐标
  表示，违反坐标纪律）与结构变化时的 collider 重建 churn；RimWorld 本体视线/
  寻路同为手搓格网算法。将来做物理化碎片场再独立评估。
- **占用格集**（碰撞面）：cell →（建筑或自然岩石引用，基架占用）。已生成建筑
  参与碰撞候选，包括不绘入外壳的炮塔和内部设备；按原版 `building.isPowerConduit`
  排除普通／隐藏电缆，它们不是保护基架的碰撞面。隐藏电缆原版免疫攻击，
  真空屏障场同样透弹；二者下方基架均可按自身概率参与命中。
  外壳仍只绘实体结构或显式规则。
  同格建筑与基架分别入缓存。重叠建筑优先墙、再按掩体效果选取。分类收口碰撞核心内部，
  与 `ShellPicking`（选择级）不得互调。**弹体的碰撞面 = 弹体 building 脚印**
  （1×1 或 2×1 的扫掠块）。
- **护盾线段**：目标发生器的守卫半径由实例拦截器 Props 读取；动能／电磁模式线段由 `CompSpaceShield.GetSegment` 按建筑朝向、相对角、距离和长度确定。碰撞与显示消费同一几何；从正面进入背面时按模式处理实弹冲量／侧向失稳或激光折射，导弹和侵入 shuttle 穿越。当前代码还能观察其他建筑拦截器并形成圆弧，但其宇宙命中只直接扣写原版容量字段，没有完整触发来源破盾／回充状态，不能视为正式自动适配；替换方案见[护盾自动太空战适配计划](护盾自动太空战适配计划.md)。
- 缓存失效：统一结构版本 + 建筑增删 + 护盾供电轮询，无时间重扫；完整重建前
  必须清空旧格数组，避免已毁结构残留。宽相位圆按占用包围盒半对角线构造，必须覆盖四角；
  休眠图冻结保留；容器注销释放（[AGENTS 缓存纪律](../AGENTS.md#架构不变量)）。
- 独立碰撞调试开关绘制全部可见对象**实际缓存**的半透明占用格与宽相位包围圆；不另建
  实时重算碰撞体，显示内容就是命中系统正在消费的事实。
- 求交（守方局部坐标，`SpaceTransform.MapPointToUniverse/UniverseToMapPoint`）：
  1. 宽相位：主动方本 tick 扫掠块 × 守方包围域（占用包围盒与弧半径取大）；
  2. **先弧后格**：扫掠块 × 弧环段求交（`GenGeo.IntersectLineCircleOutline` 同款
     语义 + 弧角限制）；命中弧 → 事件携带护盾建筑；
  3. 有半径的扫掠逐段枚举候选格，在每段内按碰撞箱的实际进入距离选首个接触。零半径沿格边逐格求交。同一格重叠且命中概率相等，或扫掠同时接触多个格时，优先结算不可通行建筑。基架首次接触读取匹配的 `substructureHitChance`。基架确认命中后，同格参与碰撞的建筑直接承伤。贯穿弹击毁建筑后，剩余预算从同一接触点续算该格基架的破坏，复用已确认的接触。
  4. 跨容器按接触点距扫掠起点的宇宙弧距排序，只结算最先通过命中判定的接触。贯穿或折射后从更新后的扫掠段重新求交。
- 事件附带几何事实（一次性计算，参与方只消费不重算）：命中 universe 点、**两侧
  building 引用**（主动方弹体 building、守方被撞 building/基架/护盾）、入射方向、
  相对速度**标量与矢量**（`v_攻 − v_守`，切空间）、入射角（入射方向与被撞面法线
  夹角；基架格以竖直法线抽象）。解算唯一入口 `SpaceTransform` 扩展，调用点禁止
  自行点乘。
- **己方规则（跨墙感知）**：顶部炮塔弹排除己方容器；舰中固定武器弹包含己方容器
  （自伤是特性）。排除从炮口格自身起算。
- 驱动节奏（**tick 顺序调整，随施工更新 [代码入口索引](代码入口索引.md)**）：`Projectiles（记录扫掠起点、普通导弹制导）→ Autopilot
  → Controls / Approach → 尚未推进的容器积分 → SpaceCollision 扫掠与结算`——先动后撞，消除一拍滞后；结算中的注销/销毁/归池经 `QueueFrameAction`
  帧边界（禁止在扫掠 foreach 内执行）。弹体与一切容器共用同一条积分链（数据
  一致性）；施工时如主循环对无推进容器有额外开销，做 tag 快速路径，不改语义。

### 3.4 联合效果注册表：命中判定（二值）+ 命中后效（已定）

基架外污渍清理由 `SubstructureDamageUtility.CleanInvalidFilth` 统一执行：毁伤地形与建筑后效完成后、Gravship 剥离源格后，按最终地形的真空限制和原版 `FilthMaker.TerrainAcceptsFilth` 清除非法污渍；毁伤复用散落服务的已有帧边界事件再检查受影响格，覆盖迟到后效。当前游戏的 Space 继承 `NaturalTerrainBase` 后仍含 `Unnatural` 污渍掩码，因此原版地形变更清理会接受建筑碎石，而生成入口另有真空限制。修复限于 Delta-V 毁伤／搬运，不改全局 Def、不周期扫图；合法基架／天然地面污渍保留，人员、物品和尸体走原搬运／散落链。

- **命中概率**：建筑按目标类型和掩体效果判定，基架读取匹配的联合效果 Def；命中后的效果也来自注册表（XML Def 可扩展）。契约两段：

### 舰体主动撞击与碰撞规避（2026-11-18）

「碰撞规避」保留游戏内名称。共同 `ShipController.CollisionAvoidanceEnabled` 默认开启，随船身份跟随换图，不随目标、任务或手动／自动切换清理；读档按控制器生命周期恢复默认开启。

每 tick 记录运动前的位姿，积分后先按点／线扫掠结算实弹、无图导弹、点防及侵入，再读取更新后的结构处理舰体对。移动目标的起止位姿仍交给共同弹体扫掠。实弹与舰体使用各自的候选调度，通过统一接触记录、效果注册表和受击视图结算。无图导弹按自己的战斗部结算并使用真实载荷实体。

舰体对采用双向外缘扫掠，包围半径先剔除远船，旋转每 2° 分段，沿共同占用格查最早边界并在线聚合同面采样。任一方关闭规避即可撞击，双方开启可互穿。同图结构不互撞。角点使用格网的稳定入射面，射线起始已重叠的格不算新的入射面，允许舰体在短时重叠后按结算运动推进。

每次确认接触提交一次 `DeltaV_Projectile_HullContact` 工作项。同一舰体对每 tick 最多结算一层实际相触的结构。舰体扫掠记录最早接触面同刻、同法线的格对，后效从这些格对汇总同层多列预算。小时间窗同时受空间容差限制。多格建筑按实体合并，实际扣血一次；同一基架格汇总后按现有阈值判损，墙体仍存活时保护其下基架。建筑伤害和基架移除均走 `TargetView.ApplyDamage`。预算沿用 `63.72 / 1800 = 0.0354` 的法向能量换算和 300 的基架阈值。

`ResolveContact → SpaceImpactEffects` 使用命中前同一份质量和惯量报告。实际支撑仍存活时卸掉法向闭合。撞开且有剩余法向能量时，成对交换当层消耗对应的冲量，保留余速。本 tick 两船的剩余位移停在接触处，下一 tick 重新以真实结构做扫掠。空舱不会触发接触后效；下一层的扣血取决于后续真实命中。

候选队列按时间与对象 ID 取下一接触，结算后更新两船和相关第三方候选。当前层撞开后第三体仍可在本 tick 改变船的速度，剩余位移限制持续到本 tick 结束。超出舰体冲量预算时，未结算候选的参与船停在最早剩余接触处，并保留已结算速度。`DriftAfterContact` 只替换当前 tick 的剩余运动段。接触格对和预算随 tick 或异常清理释放，地图注销或换表示后候选按真实身份校验。

整批毁伤或冲量提交一份命中表现。实际毁伤才登记破坏型闪光、火花和烟雾，低速冲量可播放补充碰撞声。地图声和船壳声走现有路由与节流。「超凡智能的听觉」控制补充音效，双方原版 `TakeDamage` 受击声照常结算。

自动避让仅在本船开启且处于战斗自动驾驶时生效。`HullRouteClear` 用同一舰体对几何查询候选轨迹的四秒窗口，每 0.1 秒分段。手操、普通导航、速度跟随、软对接和单独自动火控沿用自己的入口。主动跳帮由真实侵入弹体独占命中与落地。

离线验证为 `NpcRetreatRegression/run.ps1 -HullContactOnly`、`-ProjectileFullOnly` 及默认全套。覆盖开关组合、同层多列、内层保护、跨空舱后真实续撞、第三体响应、重叠后的推进、归属、表示替换、自动避让与有图／无图命中。构建 `just build` 和 `just build 1.6` 分别更新 1.7 Dev 和 1.6 Dev。游戏内战损拆图、存读档和混合交火仍需新档验收。

#### 单层结算离线验证

性能入口为 `NpcRetreatRegression/run.ps1 -HullCollisionPerformance`，覆盖 2／8／24 艘的正撞、密集破口、凹形三体及混合实弹。计时与计数可分开执行，计数额外记录逐 tick 墙体和基架毁伤、实际行程及撞开后的位移延后。参数见[开发脚本索引](../scripts/README.md)。

逐 tick 回归确认三层相连的墙和基架依次毁伤。同层三列撞到同一座多格建筑时，该建筑每 tick 只调用一次原版扣血。空舱中的漂移无接触后效，第三体仍可在开孔当 tick 传递冲量。

#### 受击结构适配（2026-11-19）

`SpaceCollision.TargetView` 是一次查询／接触内的结构视图，封装真实 Map 或无图导弹持有的 Building。地图后端复用现有占用格／护盾缓存，无图后端读取原实体脚印；不创建假地图，不复制结构、HP 或长期运动状态。普通实弹只有弹道记录，不因此成为受击实体；归档舰船、POI marker、散落人员与物品不新增战术碰撞能力。

共同 `SweepContact` 的点、线段和法线使用所属刚体局部系，球面转换全部委托 `SpaceTransform`。`ImpactEvent.HitLocal` 从后端命中点派生；既有 `hitDefenderLocal`、`resolvedHitLocal` 和公开 `VisualContact` 保留原后端坐标语义（有图为 Map 坐标，无图为实体局部坐标），在后效／表现边界统一转换，不用 Map 是否为空猜测共同记录的坐标。护盾圆心、线段、地图声与船壳附着保持同一实际位置。

真实导弹与舰体相撞由导弹原工作项对运动中的共同目标视图扫掠，使用导弹自身的脚印、护盾规则和 Def；导弹的伤害、爆炸、归因和销毁由原后效链执行，不叠加舰体双方溃缩或虚构整船质量。舰体对查询排除这些弹体角色。当前工作表中的死亡标记即时阻止后续命中，实际容器注销与实体释放仍走帧边界。建筑／基架损毁由既有结构事件在同 tick 失效共同几何缓存，下次查询直接读取新暴露结构。

直接受伤经结构视图分派到既有地图毁伤原语或实体原版 `TakeDamage`；舰体两侧毁伤同样走 `TargetView.ApplyDamage`。无图目标所受爆炸仍沿用下一 tick 的延迟伤害，出队通过 `ApplyResolvedDamage` 执行已解析的伤害，不再次入队。视图校验地图、实体存活状态与表示版本，变更接触位姿不会使旧表示重新有效。真实弹体工作项索引只在本次 `ResolveCollisions` 内有效，结束（包括异常）及流程重置时释放，不序列化。

射线查询的后端选择统一在 `TargetView.TryRay`：点防散射估算使用 `RayQuery.NextLocal` 的刚体局部接口，原地图消费者通过 `RayQuery.Next` 的坐标转换边界进入同一入口。实体矩形与地图占用格仍各自复用原几何算法；`OriginBoundsRadiusOf` 同样委托结构视图，无图实体按真实脚印给出半径。旧 `TryMissileFootprint`、`AbstractMissile.HalfFootprint` 和 `AbstractMissile.ApplyDamage` 已删除；不保留独立导弹查询／伤害入口。

回归入口仍为 `NpcRetreatRegression -HullContactOnly` 和 `-ProjectileFullOnly`，新增 `CollisionTargetChecks.cs` 覆盖地图／实体坐标与法线往返、共同射线查询、真实扣血、表示失效、静止导弹被舰体撞上、相向运动、多格旋转接触、工作表顺序、一次战斗部后效、点防击毁后的失效、来源结构损毁失效和后续普通弹体续算。补漏回归还检查生产 DLL 的旧符号删除及点防／射线／延迟伤害／舰体毁伤接线；五束散射在三种目标角度下，对照地图和实体的真实扫掠／扣血及点防预留伤害。延迟伤害覆盖重复 tick、表示替换、提前击毁／移除和多个记录在击毁后失效。爆炸检查只替代原版 Unity 场景终端并核对参数／归因；直接伤害执行真实 `TakeDamage`。游戏内新档战斗与存读档验收见 TODO。

    默认消灭无伤、可反弹扩展位），否则伤害随相对速度/入射角；

  - 普通实弹（重炮／速射）与轨道弹 + 基架：同参数同规则，按拦截概率命中后消耗贯穿预算并继续；不再使用重炮专属基架爆炸／剥离，未拦截不扣费。
  - 弹体 + 太空线盾：动能盾按实际付费法向冲量改速，并以侧向冲量／质量决定完整续飞、全质量翻滚或多体撕裂。零出力不碎裂；物理质量与剩余毁伤比例分别保留，破片不重复折损。电磁盾让激光在发射 tick 内继续分段扫掠。欠费只施加已付部分，本层短暂失效；导弹和侵入 shuttle 穿越。几何、费用与寿命规则统一见[护盾基线](舰炮与护盾基线.md#geometry)；
  - 侵入 shuttle + 船壳：判定 = 产生后效；后效（shuttle 侧）= 放置于撞击位内侧
    偏移 + 容器销毁；（船侧）= 撞击毁伤/清障（数值 §15）。
- **船体贯穿**：速射与重炮的铀弹和完整轨道弹统一用 `penetrates` 预算链；守卫按接触动能线性扣容，完整铀弹用剩余有效动能计算饱和结构预算。击穿后将实际剩余预算反算成有效动能比例，实弹与火控预测共用换算。只有实际击毁才按扣血返还余量。存活／免伤建筑截停，空舱不扣费。同格基架优先接收贯穿余量，再继续扫掠。Bullet 不继承 Bomb 建筑倍率；旧重炮固定三层宽轮廓已退出内置配置。激光和破片按自身形态在首个结构停止，护甲穿透不等于贯穿深度。
  `SpaceCollision` 把比例一次性乘入本弹 `damageScale`，从原交点继续同一盾／建筑求交链，空舱不消耗预算，遇到内层盾仍照常结算。同心盾不跳过；零盾容、已毁建筑不重复吸收。`SpaceProjectileService` 将剩余比例写回同一弹体供后续 tick 使用，不额外降低速度／穿甲系数重复扣预算。单 tick 最多处理 128 次续穿／折射，超出时停在最后交点，下 tick 继续，不凭空穿过未处理结构。
  护盾表只在盾面求交时使用；发生器实体按普通建筑承伤，防止零盾容设备无限吞弹或返还全部预算。动能盾按实际侧向冲量选择保持完整、一个全质量翻滚弹或多个碎片；形态 Def 由原弹指定，质量守恒并继承剩余毁伤比例，转换寿命不超过母弹剩余时间，按普通／轨道破片各自的低效率形态毁伤，不复制完整预算。数值与验收口径见 [武器定位与数值](舰炮与护盾基线.md#roles)。

  离线回归覆盖 EVA 太阳能板返料、首次基架命中率为零时的同格续穿、前裸基架与后墙的扫掠顺序，以及裸基架命中与破坏的独立概率。1、4、12、24 舰队场景的已启动选位均完成。游戏内验收见 TODO。
- **通用毁伤后效**适用于未匹配专用后效的结构。兜底效果按目标的最大耐久调整伤害，沿用相对速度、入射角及跳弹条件。
- 太空弹道接触参与碰撞的不可通行建筑时必中。可通行建筑默认读取原版 `ThingDef.fillPercent`，效果 Def 可覆盖命中率。点防专用激光对制导导弹
  跳过掩体概率且不加散布；基架的拦截概率由弹体×基架效果 Def 指定，命中格损毁概率 = `clamp01(本发实际伤害 / substructureBreakThreshold)`。相对速度只参与命中
  后毁伤，不参与拦截概率。加速段明确声明 `fillPercent=0.6`；
  爆炸波及由 `GenExplosion` 原生处理，不 patch 原版 verb/射击/拦截代码。碰撞面随实际结算时的建筑与基架移除事件更新。
  多层贯穿和基架连带拆除也由同一组通知登记受影响的格，跨块建筑使用移除前的完整脚印。下一次查询合并刷新涉及的 8×8 块。

### 3.5 结算：对称分发，各容器各结自己的后效（已定）

- **碰撞事件对每个参与容器对称派发**；每个容器用同一 def 对（自己的弹体/结构
  building def × 对面的 def）从注册表解析**自己的**后效并执行。「弹体被摧毁」
  「飞船受破片毁伤」不是攻守两套逻辑，是**两侧容器各自后效的输出**：
  - **射弹射入船体**：飞船容器的后效 = 对自己内部图产生破片毁伤（命中位爆炸/
    递减摧毁基架/人员杀伤，随 def 对与相对速度解析）；弹体容器的后效 = 摧毁
    弹体（销毁并注销）。
  - **点防激光命中导弹**：导弹容器（守方）的后效 = 对自己的图 TakeDamage 弹体
    building（HP 归零 → 帧边界销毁容器、图归池）；激光临时容器（攻方）的后效 =
    自毁。**与飞船通用的受击逻辑即此链**——导弹没有特殊受击代码。
  - **点防激光命中 shuttle（正常或侵入飞控）**：shuttle 容器的后效 = 对自己的图
    TakeDamage 舱体 building；激光临时容器自毁——与打导弹完全同链（可拦截性同判据）。
  - **侵入 shuttle 撞船壳**：艇体从弹体服务释放；船容器按联合效果承受撞击毁伤，
    再经共同 Gravship 链接收艇体（§7.5）。
  - **（未来）飞船撞飞船**：双方各自对自己内部图解析结构后效（舱壁×舱壁互相
    毁伤）——同一实现。
- 弹体注销与资源释放经 `UniverseManager.QueueFrameAction` 帧边界；同 tick 多
  命中按事件顺序结算，一容器销毁后跳过其后续事件。

## 4. 弹道系统

### 4.1 直射弹与导弹

- 直射弹恒速飞行，使用球面位移与共同扫掠。
- 制导导弹按目标位姿及速度，在有限加速度下追踪。侵入跳帮艇继续使用真实推进器和 MPC，指定目标 Map 局部点。身份及手动射线规则见 §6.2。
- 超时（def/全局上限）未命中 → 自毁（无后效）。
- 服务归属：`universe.Projectiles`（新实例服务，取代 `universe.BoardingPods`
  槽位）：弹体创建/注册、制导、超时、碰撞调度对接、渲染、ResetFlow。
  积分与被动阻力豁免走主容器循环按 tag 分派（§3.3）。

### 4.2 点防御（PD，已定）

- PD 是**武器的瞄准模式**（comp 字段）：不受驾驶开火控制、不参与玩家瞄准与预瞄，
  自动索敌开火。
- `ShipController` 调度本船火控；逐图武器索引用于空态早退。每船 `ShipFireControl` 在本船齐射之后遍历一次对象表，以可拦截性和相对本船的敌对关系建立本次共同候选；无敌对候选时跳过全部拦截武器（牵引器另用散落候选）。同 tick 齐射生成的弹体可立即参与筛选；候选缓冲在本次调用结束清空，不保留位置快照。
- 点防锁定和下次空锁重试 tick 只保存在 `ShipFireControl` 的逐武器状态表中。有效目标持续沿用，冷却期间仍转向；目标失效当 tick 重选，只在共同候选内检查射程和接近优先级。找不到射程内目标时等待 30 tick 再试，不逐 tick 空搜；全船无候选时清空锁表，下次出现敌对候选立即恢复搜索。武器移除、结构换属、改派系、模式切换、地图卸载和 controller 清理都释放相应状态；主台继任的绑定会剔除已不属于该船的武器锁定。牵引器无目标时保留 30 tick 重试，旧锁失效或占用冲突时立即重选空闲目标；全局独占权由散落服务持有。
- 同船点防在本次调度内按成功发射的弹体命中伤害估值临时预留目标的剩余 HP。已有锁定目标被预留火力覆盖时，后续武器转向其他射程内目标；若没有其他未覆盖目标，仍可继续集火。预留在下一次共同候选筛选时清空，不写档；冷却、失效或未能开火的武器不占火力名额。shuttle 不使用弹体 HP 的覆盖判定，仍按来袭优先级集中拦截。
- 1×1 点防御激光炮的 Def 将该模式固定为点防御：内置 16 级火控，无炮手、弹仓或插件槽；原版同图炮塔不自行索敌，武器组仍负责启停。其他武器的齐射／点防切换不变。
- 索敌读取存活导弹载荷，或独立飞行的一体式船体角色；停靠在宿主图内的艇与舱外人员都不是点防目标。点防与实际接触使用相同脚印，命中后交给共同后效。
- 射击：有飞行时间的弹体解算截击提前量；普通点防目标仍走炮手/插件散布。专用
  点防激光弹体对制导导弹跳过散布与掩体概率，并在碰撞结算 tick 对准导弹现位；
  就绪判定（武器组/炮手或插件/供电弹药/冷却）仍同齐射武器。
- 瞬时激光瞄准目标当前位置；索敌射程从武器炮口到目标碰撞包围域计算，不随所在舰体尺寸变化。当前点防激光以 50 格射程、110 tick 冷却、每发 1 W·d 蓄电与 10 点直击伤害为初始标定；25 HP 高爆导弹需要三次命中。束宽由弹体 Def 指定并复用激光渲染。
- 优先级：来袭容器按预计接近时间排序，非来袭按距离兜底；资格独立于自动敌船的推进器门禁。
- 性能分析的 `pdCandidates` 记录共同候选筛选，`pdSearch` 记录逐武器的候选内选取；两者都包含在 `pointDefense` 中。`pdInterceptTicks` 统计至少一船发现敌对拦截候选的 tick 数。离线覆盖多武器共用一次筛选、友方对象早退、有效锁延续、同 tick 失效／新候选、空锁重试，以及 25 HP 导弹在预留 20／30 点伤害时的继续集火／分散与单目标兜底；实际拦截率与 TPS 待游戏内验收。

### 4.3 激光（即时链）

- 激光弹体同样有弹体 building（注册表键与效果载体），无图型（即时，不可拦截）；
  其「飞行」= 发射 tick 内的一次即时扫掠（炮口 → 散布方向 × 最大射程），经同一
  碰撞核心与联合效果链（先弧后格；相对速度取发射瞬间双方速度）；命中 → 后效
  结算、弹体容器随即销毁；未命中 → 射线消失。
- 视觉：每件武器按实际折射段复用光束，起点跟随当前炮口，命中端和折射端以对象 ID／表示版本及局部坐标锚随对应刚体运动；未命中端保持相对发射船的位置。连续触发在相邻伤害脉冲之间保持亮度，停火后约 15 tick 渐隐；点防保留短暂显示。表现只消费已结算交点，不重做碰撞、不追加伤害或能耗。对象删除清理对应端点，换档不保存瞬态光束；暂停冻结。激光不可被拦截，可被护盾弧吸收。

### 4.4 渲染、音效、生命周期与存档

- 弹体渲染统一 = 弹体 building 的 def 图形经 `FocusedDrawPosition/
  FocusedMeshRotation` 投影到聚焦帧（ShellRenderer 前景层槽位、池化）——有图/无图
  弹体同一路径（图形取自 def，不读图）。激光另加光束线段（线段方向 = 两端点
  显示系差向量，换基回宇宙角后走唯一变换入口）。命中聚焦容器自身的后效在聚焦
  图内由原版产生。**弹体 mesh 自身不随速度向旋转**（2026-09-27 用户定案）：旋转
  = 容器姿态角的聚焦帧投影——与建筑弹体「口袋图内 Rot4 恒定、旋转由 space
  object 姿态携带」同一模型（哑弹容器角恒为发射角，导弹仅制导转向时更新）。
  轴向约定两分（2026-09-27 90° 事故后收敛）：地图几何壳/世界剪影/X 拉伸四边形
  前向 = 局部 +X（FocusedMeshRotation）；原版带朝向贴图（弹体等，图案朝 UV
  上方 = 局部 +Z）一律走 SpaceTransform.FocusedSpriteRotation 唯一入口，禁止
  调用点手写 π/2。
- 成功发射并扣费后，`SpaceWeaponShot` 把冻结的炮口、发射角和实际付费加速段交给 `SpaceProjectileService.RegisterShotVisuals`。武器 Def 的 `muzzleFlashSize` 控制闪光，`recoilDistance/recoilTicks` 控制纯绘制后坐；聚焦炮塔沿原版 `TurretTop.DrawTurret` 的 offset 接口、外壳沿 `CollectTurretTop` 读取同一 `CompSpaceWeapon.VisualRecoilOffset`，不移动建筑。未付费加速段不显示放电脉冲。
- 战斗表现仍由弹体服务唯一持有（`SpaceProjectileService.Visuals.cs` 是同一类的 partial）：弹体 Def 的 `visualStyle`、`tracerLength/tracerWidth` 和四个开火／命中 SoundDef 选择武器表现。重炮使用短白芯、外焰、烟与独立飞散碎片；轨道炮记录真实已扫过的短轨迹与贯穿喷射；激光使用程序软边光束的亮芯／红色外晕及附着热斑；点防束停留更短。导弹既有点火尾焰与烟迹继续使用原参数和材质渐隐档。
- 轨道炮从成功发射事务读取炮口与实际付费段，绘制 24 tick 的轴向蓝白炮口闪光、横向电弧及沿链错峰的段放电。完整弹芯的曳光有随战术镜头缩放的最小可见宽度（最大 0.65 格），几何仍跟随实际飞行。船体截停时显示 30 tick 的附着余辉和沿表面扇开的火星；逐层续穿沿真实入射方向喷射火星。护盾反馈由实际盾面事件决定。
- 在飞实弹曳光共用弹体贴图的中心与 `FocusedSpriteRotation`，沿贴图局部 +Z 的反方向延伸。长度取本 tick 的宇宙位移与 Def 尾迹长度的较小值。
- `SpaceCollision.VisualContact` 在每一次实际结算后复制局部交点、表面法线、盾面几何、入射预算及毁伤／续穿结果；弹体服务只收集快照，整个扫掠结束后统一生成表现，不持有池化 `ImpactEvent`。多层贯穿逐点反馈，只有实际预算续穿才喷出向前火花；普通命中不生成金属碎块，金属碎块由基架实际毁坏事件生成。守卫盾沿真实圆弧扩散，实际破盾时显示断裂弧；动能盾碎裂与电磁盾折射沿实际有限线段脉冲，光束分段复用碰撞的折射回调。
- 闪光／热斑按对象 ID、表示版本和局部点随船移动；独立碎片／烟继承产生处的刚体点速度，在 universe 中按游戏 tick 漂移，暂停冻结。寿命内表现不序列化、不参加碰撞。炮口闪光和命中中心分别最多 128 个、光束最多 256 段、独立粒子最多 768 个（普通动能粒子在 512 个时停止补入，给大口径反馈留余量），前台层批量提交；销图／对象移除清理附着效果，场景重建清空全部瞬态表，换档释放自有材质与程序光束纹理。
- 聚焦守方仅对真实 `GenExplosion` 跳过重复的主闪光与爆炸声；普通实弹沿实际贯穿接触显示冲击表现。其他开火／命中声音走 InMap，非聚焦图走 OnCamera 并按摄像机在地图平面上的距离 30/120 格衰减，镜头高度不使画面中央战斗静音。非聚焦船体命中额外乘 0.45 音高，护盾／拦截导弹维持 0.65；船体命中使用的 Hit／Heavy／Rail／Energy／Explosion Shell SoundDef 通过原版 `SoundFilterLowPass` 限制至 1600 Hz，减少金属高频。开火和启停音不受影响。原版 `SoundDefHelper.CorrectContextNow` 会屏蔽异图建筑受损／摧毁声，因此降调作用于实际可听的补充命中声，不改共享原版 SoundDef。同类声音按 tick 限频、SoundDef 限制同时声部；表现变化使用独立散列，新增声音调用隔离 `Verse.Rand` 状态。新增开火音与原有补充命中音共用「超凡智能的听觉」设置，原版爆炸音继续由原版管理。
- **近场运动与结构余响**：`SpaceProjectileService.MotionVisuals` 扩展同一实例表现管线，在对象出力／积分和碰撞后采样，只读实际油门。环境微粒及其生成、回收、绘制、专用探针已移除；近场运动参照由坐标网格提供。
- **程序化排气**：普通推进器通过 `CompProperties_ThrusterVisuals.exhaust` 配置 `ThrusterVisualProfile`；shuttle 通过自身 `CompProperties_SpaceShuttle.exhaust` 配置，可在 `virtualThrusters[].visuals` 逐喷口覆盖，侵入加力读取该 Comp 的 `afterburner`。配置包含烟雾开关、发射间隔、寿命、尺寸／扩散、颜色／不透明度，以及火焰开关、寿命、尺寸和喷速；均不进入物理求解。大／小原版推进器已追加表现 Comp。普通排气复用 `ThrusterEffects.TryGetExhaustPort`，侵入加力也读取共同推进器布局与实际油门，均继承刚体点速度后叠加喷速。粒子出生位置／速度固定在 universe，剧烈转向仅影响新粒子；暂停冻结，已脱离烟焰自然散尽。
- `MotionParticleRenderer` 运行时一次性生成噪声烟团、软边火焰及金属切面覆盖率纹理，无外部烟焰图片。顶点色承载渐隐，按烟／焰／金属／网格各合并一个动态网格，每类至多一次提交。推进烟雾预算 768、火焰预算 384，与战斗粒子预算分离，视野外烟焰不提交；预算与合批控制对象和调用数量，不能替代 GPU 重叠透明像素的游戏内性能验收。
- **性能探针与缓存失效（2026-10-25）**：早期实测日志中，交火时 Delta-V tick 平均约 8.6 ms，停火后约 1.4–2.0 ms；当时环境微粒（现已移除）绘制约 0.09 ms/帧、网格约 1.8–2.7 ms/帧，说明 TPS 下降主要在 tick 链而非亮点绘制。弹体小图每次租用已调用 `SpaceCollision.Forget(map)`，所以普通弹体注册和小图建筑变化不再推进全局结构版本；对象 ID 与 Map 查询改由 `UniverseManager` 的实例索引维护，随注册／注销／表示替换和读档更新。性能日志新增各 tick 阶段耗时、活动对象／弹体峰值及结构版本增量，修复收益与剩余热点待新档游戏内复测。
- **2026-10-25 复测与下一轮探针**：无在飞弹体、17–18 个对象的 Superfast 窗口约 138–162 TPS；`controls` 约 0.9–1.2 ms/tick，自动驾驶活动时 `autopilot` 另约 1.4–1.5 ms/tick。此轮测试尚未加载网格优化，不能用其 `grid` 值评价新实现。控制器现于无可拦截对象、无散落目标时跳过点防逐武器消费；性能日志增加点防候选 tick 数、控制器选择／决策／战斗、点防耗时，以及 MPC 求解次数与单次耗时，待新档复测确认主因。
- **统一执行后的性能统计口径**：保留 5 秒总览。`cpu[avg/max]` 的绘制／update 均值按帧，战斗／对象均值按游戏 tick，`mpcSolve` 按求解次数；max 是单次探针峰值，不是所有武器同 tick 的合计峰值。新增 `detail[avgUs/maxUs/calls/totalMs]` 全部按调用统计，窗口总量可用于归因，不能把每调用微秒直接当作每 tick 毫秒。
  - `controlCombat` 包含 `VolleyIntent`、`controlVolley` 和点防；`controlVolley` 包含逐炮 `WeaponDispatch`（组、归属与容器核对）及 `WeaponExecution`。后者包含 `WeaponAim`、`WeaponGuidance`、`WeaponPrepare`、`WeaponLaunch`；`WeaponAim` 包含 `WeaponReadiness`、`WeaponParameters`、提前量及转向，`WeaponLaunch` 包含 `WeaponCommit` 和发射表现。只对同一父级的互斥项相加，父子不能重复相加。
  - `WeaponParameters`、`WeaponAmmo`、`WeaponEnergy` 与 `WeaponLayout` 为混合调用探针：可能发生于自动瞄准、帧预瞄、状态色、火力评估或射击。后面三项有嵌套：首次选弹与能量查询都可能触发布局重建。`AimPreview` 包含本帧预瞄求解及标记提交；`AimInput` 是共享鼠标／键盘原始采样，`AimInputGate` 为 UI 门禁刷新，两者只在需要更新快照时计数。

### 4.5 测试场景重建与清理顺序

`ShipTestScene.Create → UniverseManager.BeginSceneReset` 是双船场景重建入口。重建期间保持暂停，停止宇宙 tick、驾驶输入与增量生成器的自动推进；重复请求复用正在进行的重建，不再创建第二套流程。

1. 在现有 `QueueFrameAction` 消费点排空旧动作；动作中新入队者仍在下一帧执行，后续阶段必须等待队列再次为空。已开始的增量地图生成经现有同步完成入口收尾，再取消尚未开始的生成任务，避免销毁尚未完成原版初始化的地图。
2. 停止驾驶／对接／自动驾驶等流程，调用弹体 `ResetFlow`。此时旧容器仍在注册表；活动弹体和已经死亡但待回收的弹体均完成同一收尾链，侵入 shuttle 先解除接管。在飞导弹由对象注销释放。
3. 弹体及其后续动作完成后，销毁其余旧地图、注销容器并清理宿主下的孤儿口袋图。实际销图复用原版 `PocketMapUtility.DestroyPocketMap → Game.DeinitAndRemoveMap → MapDeiniter.Deinit / Map.Dispose`；原版销图通知在旧身份仍可解析时通知弹体服务，并排队注销容器。再次等待销图产生的后续动作完成，才清理运行时缓存。重建路径不得用清空帧队列代替执行收尾；单个动作抛错时保留该批尚未执行的动作。
4. 最后排入生成新场景的原版长事件。生成异常在事件内部记录并排队清理，使事件正常返回，允许原版 `Map.FinalizeInit` 的结束回调执行。成功后的武器／controller 重建与聚焦交接，以及失败图的销毁，都在原版初始化回调完成后的帧边界进行。重建结束保持暂停，由玩家恢复运行。

这些流程状态不存档；读档仍丢弃旧运行时回调，不与同游戏实例的场景重建混用。离线回归入口为 `scripts/NpcRetreatRegression/run.ps1`，`SceneResetChecks` 覆盖生产 DLL 的弹体收尾和重建阶段顺序；Unity 地图生成、绘制资源析构与完整游戏交火重建仍按 `doc/TODO.md` 验收。

## 5. 武器体系（专用 def，双模）

### 5.1 def 与 comp 结构

武器归属使用 `CompSpaceWeapon.OwnerShip` 的独立运行时缓存：首次通过 `ShipRegistry.ShipOf(..., requireWholeFootprint: true)` 校验完整脚印，之后按统一结构版本、地图、位置／朝向及有效句柄复用；无归属结论同样缓存。未注册地图不缓存。出生、移除、地图释放和换档经 `ClearRuntimeModel` 清理，主台变更经既有 `ReconcileOwner` 推进结构版本。齐射／点防在每次分派前读取一次主副组掩码，逐炮直接判断当前套别和组号，不再为组别重复解析所属船。组别不按结构缓存，切换立即生效；归属缓存不依赖连接布局，纯指向不因此查询挂件或弹药。

- 给第三方武器追加太空能力的最小入口是 `CompSpaceWeapon`；原版 Mannable、Traverse、Magazine、
  挂件和加速件均按需添加。没有 Mannable 时按自带基础火控处理。
- 自动炮塔适配由 `AutoSpaceWeaponDefGenerator` 在 `GenerateImpliedDefs_PreResolve` 最低优先级 Postfix 中扫描最终 Def。原版生成器已在该方法返回前静默解析现有交叉引用，因此快照读取 XML 继承与 Patch 后的 turret、gun、Verb、Projectile 和 Stat。候选只按通用结构分类为原生射弹或转换光束，再由 `AutoSpaceWeaponPolicy` 读取已载入的 Mod／武器策略决定是否注入。实体射弹允许自定义 Verb、爆炸、曲射及来源资源事务；覆盖 `Projectile.Tick`／`TickInterval` 的自管飞行属于可覆盖风险，推荐模式拒绝。策略键为规范化 packageId 与 turret defName，不识别具体 Mod、Def 或类型名，设置只在下次重启的 Def 生成阶段生效。
- 合格炮塔复制 `comps`／`modExtensions` 后注入 Traverse、SpaceWeapon 和顶部桥，并生成稳定命名的 `ShellRenderRuleDef` 与只读 resolved marker；marker 同时记录 `NativeProjectile`／`ConvertedBeam` 模式并作为热重载幂等键与 Harmony 身份。原生射弹模式只使用共享的宇宙代理 Def 表达飞行阶段，不注入 `CompGunSupply`、Magazine、固定 Tuning 或额外资源结算；即时光束因没有实体射弹，仍按冻结 profile 转换为 Delta-V 激光并使用现有蓄电事务。数值公式只适用于该转换模式，见[原版与第三方自动炮塔换算](舰炮与护盾基线.md#原版与第三方自动炮塔换算)。
- `AutoSpaceAdaptationReport` 在玩家点击设置页按钮时只读候选目录和最终 Def，按活动 Mod 输出路径、支持／警告／拒绝、当前配置与本次注入状态、冻结 profile，并枚举盾容拦截器参数。报告不重跑换算、不修改 Def、不上传，也不改变“重启后注入”的设置语义。
- 自动适配的普通 `Building_Turret` 由 `AutoSpaceWeaponTurretBridge` 与 `Patch_SpaceWeaponVanillaTurret` 维持双模互斥。自动适配炮塔默认使用地面模式，模式按实例保存；地面模式完整放行来源索敌、Verb、资源和 cooldown。太空模式抑制来源自主索敌和外部强制目标，Traverse 接管顶部；`SpaceWeaponService` 只提交一次来源开火授权，桥接随后调用来源 `OrderAttack` 或真实 `TryStartCastOn`。授权窗口内允许来源 `BeginBurst`，并由来源链自行执行预热、burst、冷却和资源事务；窗口外的自主太空开火仍被拒绝。切换模式会取消旧目标、warmup 和进行中的 burst，并至少阻止同 tick 再发。已有 `Building_SpaceTurretGun` 继续走自身覆盖，不重复拦截。
- 人员武器与自动适配炮塔共用 `SpaceProjectileService.Native`。发射授权由 Verb／武器来源实例登记；所有已加载 `Projectile` 派生类的真实 `Launch` 只登记候选。首个普通 `Tick` Prefix 只抑制本地逻辑并保留记录，随后在同一次 `Thing.DoTick` 的 `TickInterval` Prefix 完成接管并阻止原方法，避免脱图后原版继续用空 Map tick。全局快速门只有待处理授权数，静息为零时每个射弹 tick 只做一次整数判断，不枚举地图、炮塔、Verb 或 Thing；无后台轮询。由自定义 Verb 隐式生成但仍调用 `Projectile.Launch` 的弹丸也在同一授权窗口捕获，不要求 Verb 类型或显式 Launch 返回值。人员与炮塔的授权都保存宇宙中心射线、本地占位中心及来源 `Verb.EffectiveRange`；每枚 Launch 只取 `destination - placeholderCenter` 的横纵偏移，并按来源射程换算成相对角度后叠加到中心射线。本图尺寸和占位距离不参与换算，因此短基线不会放大原版 0.3 格抖动。占位基线退化、使来源 spray 路径坍缩时，共同服务按 `sprayWidth`、`sprayArching`、`sprayThicknessCells`、`sprayNumExtraCells` 和 burst 数重建一次有序角偏移；该分支按几何与通用字段触发，不按 Pawn、炮塔、Mod 或 Verb 类型触发。
- 捕获后同一 `Projectile` 实例暂存于瞬态 `AbstractProjectile` 并以宇宙状态飞行。结构接触后安全帧把它放入目标图，调用最派生的虚 `Impact(Thing,bool)`；若后效销毁射弹则结束，若将其留在地图则交回原版，若仍存活但未落地则带剩余状态返回同一宇宙弹道。因此爆炸、额外 Hediff、来源归因及实现于 `Impact` 的贯穿可以保留。自定义 `Tick`／`TickInterval` 制导不会在宇宙阶段运行，推荐策略据此拒绝，强制启用只按捕获时速度作普通弹道。守卫盾仍可在交回前截停；点防资格由既有宇宙弹体规则决定。
- 重炮、速射炮和激光炮的 2×2／3×3 炮塔可逐实例切换地面／太空模式，默认太空模式。地面模式只用原版 `Building_TurretGun` 与专属 `Verb_SpaceTurretGround` 攻击同图目标；太空模式只用 `SpaceWeaponShot` 攻击其他容器。原版炮塔继续处理索敌、掩体和距离；地面 Verb 使用共同弹仓、电费与热锁，成功发射才提交消耗。`Projectile_TunedGun`／`Beam_TunedGun` 冻结质量／速度毁伤和激光功率，地面命中仍交回原版 Projectile 流程；模式门禁使切换后的未完成原版齐射停下，太空武器索引与开火均跳过地面模式。点防专用炮固定太空自动拦截，轨道炮和导弹架本轮不增加同图 Verb。
- 太空 `minRange` 和 `range` 都从实际炮口计算，`SpaceWeaponShot.Prepare` 用它们限制自动齐射与点防；手控跳过鼠标点位的距离门禁，实际射弹仍按弹体速度、寿命及碰撞规则飞行。火力估算和射界叠层读同一 Def 参数。地面最小／最大射程由原版 Verb 自身声明。小型炮塔地面 13–33 格、太空自动最小 10 格；中型地面 17–37 格、太空自动最小 15 格。固定武器自动开火的导弹架／小轨道／大轨道最小射程为 12／20／30 格；点防为 0 格。地面炮弹初速与当前装药、质量同源，激光沿用 Beam 发射和命中流程；数值见武器基线，待游戏内验证。

### 自动炮塔跟踪与开火（2026-11-12）

自动齐射保留武器目标和部件锁。每个有效炮塔每 tick 由 `ShipFireControl.TickAutoVolley` 提交一次命令，`SpaceWeaponService.ApplyControl` 从本 tick 的目标刚体点和炮口计算瞄准。冷却或等待重试时只转炮，可尝试开火时共用本次瞄点校验并发射。固定炮在冷却或等待重试时直接跳过。性能窗口的 `aimOnly` 同时统计手动只瞄准和自动只跟踪。

双舰高速同向漂移时，旧缓存的宇宙瞄点会落在目标后方，开火尝试又改用当前提前量。生产 DLL 夹具用 300／304 格每秒、约 100 格间距、60°／秒转速、1° 对准门槛复现。旧版动能炮和激光炮各有 81 次对准拒绝、0 次开火，冷却末段最大误差约 22°。修复后两类炮都在冷却结束当 tick 开火，随后各发射 8 次，0 次对准拒绝，逐 tick 最多转 1°。

单炮 360 tick 三轮中位数如下。总耗时含冷启动与真实发射事务，游戏内持续交火和 TPS 待新档复测。

### 5.1.1 装药、质量与热管理（2026-10-30）

- `SpaceWeaponSupply` 中的 `CompGunSupply : CompRefuelable` 分别保存弹头和装药，库存、目标装填量、自动补给开关均直接使用原版状态，1 物品 = 1 fuel。两个 Comp 的原版 Scribe 字段各自放入 `headSupply`／`propellantSupply` 节点，避免同名字段串仓。`CompSpaceWeaponMagazine` 统一管理同一建筑上的弹头与装药，内置仓和附加仓共用就绪与扣料。可切换的头仓在实例存档中保存当前弹头 Def，原版实例筛选只接收该弹头。退弹逐堆按实际落地量扣库存，全部退出后切换筛选。
- 单选沿用 `Gizmo_SetFuelLevel`，只把拖动状态限定在对应仓并令目标取整数；多选沿用原版目标量／自动补给命令，按仓种分组。原版 `WorkGiver_Refuel`／`WorkGiver_Refuel_Turret` 负责派工；`Patch_SpaceWeaponAmmo` 仅将带 `CompGunSupply` 的补给查询、任务创建接到选仓适配。`JobDriver_LoadGunSupply : JobDriver_Refuel` 复用预约与搬运 Toil，按实际物资定位仓，并在搬运和完成时重新读取当前弹种、目标量及开关；最终调用对应仓的原版 `Refuel(List<Thing>)`。原版只取第一个 Refuelable 的装填收尾不用于这类武器，没有额外 WorkGiver 或库存账本。
- `CompWeaponTuning` 保存 C、M、射击间隔、激光功率、双精度热量、过热锁和射击间隔剩余 tick。速射调间隔，重炮调 C/M、热量为 4C，冷却到零即就绪，无固定机械下限，激光只调功率。真实消费与积热只在发射提交时发生；调校、切换地面／太空或组别不清热，不改已经在途弹体。
- `SpaceWeaponParameters`／`SpaceProjectileLaunchSpec` 冻结本发质量、头数、装药、速度、功率与热负担。`SpaceKinetics` 提供发射速度、冲击因子、动能与盾付费改速；`SpaceTransform.VelocityAtUniversePoint/RelativeVelocityAtContact` 提供炮口继承与旋转接触点速度。火控、机动和预瞄复用同一读取；调校、补给、优先级或实际材质切换使相关估算与提前量失效。
- `WeaponHeatVisuals` 只读热状态与炮身局部喷口；两种顶部图 `_m` 的红通道标炮管，`color` 按实际热量渐红；绿通道分别标速射两侧格栅、重炮中心机匣与尾部，`colorTwo` 在过热锁期间保持最高红色，解锁时复原。聚焦 `TurretTop` 与非聚焦外壳共用原版 `CutoutComplex` 材质；冷却时速射由两侧格栅向外喷烟，重炮从顶部喷烟，旋转、后坐及船体运动使用同一局部喷口。冷却烟使用 `SpaceProjectileService.MotionVisuals` 的有界独立粒子池并在前景绘制，避免被聚焦地图遮挡；地面模式使用原版 Fleck。模拟只用游戏 tick。
- 武器定位、数值、配方与护盾规则统一见[舰炮与护盾基线](舰炮与护盾基线.md)。新建空仓；测试 prefab 装填后重导出，不迁移旧开发快照。新档存取保存库存和热状态。

### 5.2 建造规则

- 所有多格武器要求完整脚印位于同一有效基架归属。导弹架和轨道炮装弹机本身为
  不可通行、气密、承顶的结构墙体，不再要求背后另建墙；允许把加速导轨留在船外。
- 当前内置矩阵：点防御激光炮 1×1，小型炮塔 2×2、中型炮塔 3×3（各有重炮、速射炮、激光炮），
  轨道炮装弹机与加速单元统一 3×1，导弹发射架仅 1×3；原 1×2 Def 已退役。
- 无人发射架使用原版 `CompChangeableProjectile` 保存一枚待发弹和弹种筛选。`CompSpaceWeaponMagazine` 将待发位接入共同开火事务。供弹工作复用 `DeltaV_LoadGunSupply`、原版预留及搬运，优先填同船可达的空发射架，之后把实体导弹交给仓体。
- 1×2 气密导弹仓以离体武器插件接入。发射架 Def 的两个外置槽位共用武器布局的相对位置与旋转规则，要求仓体同向、同归属和同派系。建拆、旋转和归属变化通过结构订阅更新连接。共享仓可服务两座架，补弹请求按发射架 ID 逐一核扣。
- 导弹仓按弹种保存库存及各弹种上限，总容量由 Def 设置为 20。仓可退出指定弹种，销毁时尝试放出库存。发射架销毁会解除连接，独立气密仓仍留在原格。Prefab 落在仓脚印内的实体导弹可转入同一库存，溢出落在附近格。
- 导弹架的固定内构由 `graphicData` 绘制；`CompLoadedProjectileGraphic` 从 `SelectMagazine()` 获取待发弹对应的宇宙弹体 Def 并绘中层；原版 `CompDrawAdditionalGraphics` 在更高位置绘制固定终端与外壳。空仓时不绘中层。中层按宿主 Def 独立缩放与定位，飞行中的弹体仍使用弹体 Def 自身的绘制尺寸；绝不在运行时改共享的 `GraphicData.texPath`。内构与外壳沿宽度铺满格边，发射架 `graphicData.linkFlags=Wall`；原版仅把连接型 Graphic 写入 `LinkGrid`，故 `Patch_MissileLauncherWallLink` 仅为带导弹装填 Comp 的整图建筑开启此登记，使相邻原版墙贴图能接入发射架，发射架自身仍保留 1×3 三层整图。
  大型炮塔 4×4 暂不实装。点防御仍是一般武器可切换的运行时瞄准模式；1×1 专用点防激光炮由 Def 固定为点防模式。重复的 2×2 速射副炮 Def 已退役。
- 内置 2×2 顶部炮塔各有一个覆盖挂件槽，3×3 顶部炮塔各有两个槽。速射炮和重炮可装附加弹仓或自瞄，激光炮可装附加电容或自瞄。轨道装弹机与加速段各有左右两槽，允许的挂件见轨道炮分体建造一节。挂件槽随 Def 局部坐标旋转，
  美术上须在固定底座预留，不画进转动炮身。
- 地表图保留原版规则（RimExodus 兼容边界）；可切换炮塔须选地面模式才按原版 Verb 工作，Delta-V 太空弹道不在地表图运行。
- 非聚焦船壳按 `ShellRenderRuleDef.render` 指定贴图来源与表面层级。顶部炮塔用
  `TurretTop` 来源读取当前旋转炮身材质、角度、偏移和绘制尺寸，只把炮身放在
  `Exposed` 层；固定底座和覆盖插件在有顶时遮住、无顶时显示。轨道炮装弹机用 `exclude`
  在有顶时隐藏，加速段的原版内构和外壳绘入 `Exposed` 层。`MapOverlayRenderer` 收集并按
  `Deck → Hull → Exposed → Effects` 排序，再同步交给绘制后端；当前 1.6 的命令缓冲后端逐层
  清深度（保留颜色），避免依赖透明材质与海拔推测遮挡顺序。规则只控制外观，
  建筑的碰撞占用仍由 `SpaceStructureRules` 判定，与外壳是否绘制无关。

#### 武器与护盾的贴图和建造影像

- 小、中型舰炮按脚印区分。各尺寸共用固定底座，中型重炮、速射炮、激光炮分别复用相应小型旋转炮身；固定图随建筑四向，顶部随火控连续转动。小型单槽、中型双槽，接口留在固定层。1×1 专用点防有独立底座，无炮手终端或挂件槽，顶部复用激光炮身。
- 带热效的炮身用 `CutoutComplex` 蒙版。红通道标随温度变红的炮管，绿通道标冷却烟对应的散热部位；重炮在中心／尾部，速射炮在两侧。热锁保持最大热色，冷却烟另画在前景，地图与船壳共用顶部材质。
- 线盾装置分固定底座和旋转投射器。`ShieldProjector_m` 的红通道覆盖北侧发射面和中央棱镜，其余底图保留原色。动能用蓝色，电磁用蓝紫色，守卫常规／应急分别用白／红。地图与船壳共用投射材质。守卫协同轮廓和线盾模式见[护盾基线](舰炮与护盾基线.md#geometry)。
- 导弹架以 `MissileLauncher_Inner` 和 `MissileLauncher_Outer` 包住待发弹体层，飞行和装填共用同一弹体贴图。建造影像合成默认高爆弹，建造栏图标的纵向补偿按 Def 绘制比例设置。运行中的实际装填按本节建造规则读取。
- 对声明 `blueprintGraphicData` 和 `useBlueprintGraphicAsGhost` 的分层建筑，已放置蓝图和鼠标影像共用 Def 的合成图；建造栏读 `uiIconPath`，完工后回到各自动态分层。图标、蓝图的生成入口见[脚本索引](../scripts/README.md)，游戏内边界见[美术验收](TODO.md#art-acceptance)。

#### 屋顶与战损船壳

聚焦图与宇宙外壳使用同一份基架归属和连通域。基架边饰、舱壁端面和斜角随实际连通的归属域排列。同归属但已断开的残片保留各自边缘，空格与未指派基架分别处理。基架增删、改归属和建筑占地变化经结构事件刷新受影响区块。原版逆重战略起降及设施查询继续走原流程。

右下角「使用真实地图绘制非聚焦船体」提供可随存档保存的替代显示路径，默认关闭。开启时 `NativeMapShellRenderer` 向 REF `MapRuntime.Current.Rendering` 登记 `MapRenderPlan`，由各源 Map 自身的原版绘制回调在显示矩阵作用域内输出完整地图内容；不切换真实焦点，不调用额外 MapUpdate，不修改 Thing、模拟归属或宇宙位姿。显示矩阵与自定义船壳共用 `ShellRenderer.TryGetMapDisplayTransform`，不得另算平移、旋转或地图中心。此模式只替代有真实 Map 的非聚焦船壳；无图载荷、宇宙弹体、坐标网格、瞄准标记和按真实油门生成的推进器火焰仍由既有宇宙表现层绘制。关闭时完全回到下述自定义船壳管线；切换只清理可重建渲染缓存。

### 5.3 射界与跨墙感知

- 射界／射程扫描开关开启后，`WeaponArcOverlay` 只遍历原版当前选择列表中的聚焦图太空武器；多选分别绘制，空选或只选非武器时不显示。范围继续使用 `EffectiveRange`／`CoverageSector`，扫描只读游戏 tick；不影响索敌、开火或火控目标。2026-11-02 用户确认本轮改动实测通过。

- 所有武器在 `SpaceWeaponShot.Prepare` 先以 Def 的锁定弧约束目标，再按本次请求来源，以实例 `fireDeviationDeg`（自动齐射／点防）或 `manualFireDeviationDeg`（玩家手控）比较目标方向和实际发射方向；地面模式原版炮塔读取自动值。旋转炮塔持续转向且沿当前炮口发射；固定武器沿安装轴发射。手控均不按鼠标点位检查最小／最大射程；鼠标恰在炮口时沿当前炮口或固定轴发射。固定轴武器手控设为 180° 时，鼠标方向也不限制开火，弹体仍沿轴飞行；实际弹体碰撞不变。自动和手控各有独立 gizmo，分别使用原版 `Dialog_Slider` 在 0–180° 按整度调整，均支持多选；仅支持一种模式的武器只显示有效设置。重炮自动／手控均默认 1°；速射炮与激光炮自动分别为 2°／1°、手控均为 6°；轨道炮自动 1°、手控 180°；点防炮自动 0.25°；导弹架两种模式均为 180°。导弹的 360° 锁定弧允许锁定反向目标，但仍沿架体前向冷发射后制导转向。
- 顶部炮塔排除己方容器。固定武器默认沿实际炮口方向检查本归属有命中概率的建筑，
  预计先撞自己结构时拒绝发射；玩家可用 gizmo 临时关闭该安全限制。

### 5.4 散布模型

- 发射方向 = 当前炮口／固定轴方向 + 角偏移；偏移 = `clamp(Gaussian(0, 0.4), -1.2, 1.2) × baseSpreadDeg × 技能偏差系数`（角度制）。约 95% 的随机偏移在 `±0.784 × baseSpreadDeg × 系数` 内，最大偏移为 `±1.2 × baseSpreadDeg × 系数`；这不是最终命中率，炮口跟踪误差、目标机动与真实碰撞另行生效。
- 技能来源取有效自瞄插件、Def 内置火控技能与当前炮手 Shooting 的较高者；有 Mannable 而三者皆无时不能开火，
  没有 Mannable 的第三方武器使用等效技能 10。散布映射共用
  `SpaceWeaponService.SpreadFactorForSkill`。
- 2026-11-02 调整低等级曲线：令 `s = clamp(等效技能, 0, 20)`，系数为 `1.6 - 0.06s + 6.4 × max(0, 1 - s/16)²`。0／5／10／12／16／20 级分别为 8／4.325／1.9／1.28／0.64／0.4；额外惩罚在 16 级平滑归零，16～20 级保留原精度。普通自瞄与轨道炮内置火控仍等效 10 级，适用新曲线；高级自瞄与点防内置火控仍为 16 级，导弹架内置 20 级，精度不变。炮手与自瞄取高者，低于插件等级的炮手仍不影响最终精度。
- 手动、自动及普通点防通过同一发射事务应用此系数，AI 火力／威胁估计读取同一映射；炮口对准门槛、机械转速与提前量不随技能改变。专用点防激光对制导导弹的必中例外仍跳过散布。地面模式继续使用原版 ShotReport 与既有射手能力适配，不使用此曲线。
- 量级示例：中型重炮基础散布 1.5°，完全对准静止瞄点时，在 100 格处约 95% 的随机横向偏差，0／5／10／16／20 级分别约为 ±16.57／8.90／3.90／1.31／0.82 格。远距小角度下偏差近似随距离同比增长；这些数值是理论散布，不是整船或指定部件的实测命中率。
- 本轮验证：1.6／1.7 构建均为零警告、零错误，现有 `WeaponTuningRegression` 216 项通过；另核对公式量级及发射／AI 估计的共用调用点。2026-11-02 用户实测确认本轮调整无问题并授权提交；未记录受控场景下的实测命中率统计。
- 不调用原版 ShotReport 掩体／姿态命中判定；发射后的结构拦截仍由统一 SpaceCollision 处理。

    轨道装弹机无需另建岗位。选择连线只在原版当前／排队任务的两个目标有效性判断中

  - 地面炮塔保留原版 `Active`、供电、眩晕和索敌规则，只在原版 Tick 的 Mannable
    开火判定中允许有效自瞄通过；`MannedNow/ManningPawn` 始终表示真实操作人。
    太空发射仍由 `SpaceWeaponShot` 读取同一原版操作人和自瞄技能；
  - 原版 `JobGiver_ManTurrets` 的候选验证器仍带迫击炮弹药查找和炮塔强转，舰炮在该
    验证器中排除，自动派遣只走共同 controller；其他原版武器不受影响。
  - **状态变更补分配（事件驱动）**：玩家启用武装或 NPC 获得作战目标后，双方
    使用同一 `DispatchGunners`。原版 `JobDriver.Cleanup` 的统一结束通知、武器供电／生成／模式
    变化、弹仓装填／消耗、附件启停，以及 Pawn 入图、解除征召和恢复行动登记所在图；
    `ShipControlService` 在下一游戏 tick 合并事件，按同一个岗位可用性判定先释放失效
    岗位、再分配空岗。该判定同时检查武器存在、归属、已启用武装、炮手需求和必需弹药；
    每件载人武器有随档保存且默认开启的「武器无法工作时保留炮手」开关：仅已在岗炮手
    可在缺少必需弹药时继续留岗，失效武器不征用新炮手。断电不阻止派遣，炮手只决定开火资格；功耗请求不依赖到岗或供电结果。
    关闭此开关后缺弹会释放岗位，炮手可转到其他可用武器；
    解除武装、武器损毁或归属失效仍释放岗位。
    有效自瞄只排除新炮手的自动分配，已经下达的岗位仍可执行；
    复电或装填后由空闲炮手补位。双方共用同一
    分配算法，不再每 60 tick 为 NPC 重派。待到岗与排队岗位读取原版 Job/队列，
    不把原版心跳的短暂有效窗口当作分配事实；自动补位不抢其他岗位或新的手动命令；
  - 解除武装取消该船全部岗位，炮手回原工作；不进自发工作优先级。

原版岗位适配集中在 `Patch_SpaceWeaponManning`，只保留以下作用点：

| `Thing.DrawExtraSelectionOverlays` | Transpiler | 只给交互点绘制传入当前实例；下层 `GenDraw` 只有 Def／坐标，无法区分成品和同位置建造预览 |

### 5.6 自动瞄准插件（阶段5 实现）

- 独立覆盖挂件是 `BuildingOnTop` 非 Edifice，只能覆盖建造在宿主脚印内声明的旋转槽位；同一槽位已有挂件成品、蓝图或施工框架时不得再放置挂件。炮塔宿主由挂件所在格的 `GetEdifice(map)` 派生，加速段由同格 ThingGrid 中声明该槽的 `CompSpaceRailgun` 派生，不缓存、不扫描相邻格，也不使用放置 Harmony 强行允许 Edifice 重叠；
  同一基架归属且自身供电/启用时生效；选中宿主会显示兼容附件的原版建造 designator。Def
  提供等效射击技能。有效插件满足开火需求；Delta-V 顶置炮塔的炮手格默认允许覆盖建造，
  不再以插件当前是否生效决定布局是否合法。玩家实际在该格放置建筑或重装建筑时收到警告，
  prefab 重建不显示玩家消息。有效自瞄时不自动分配新炮手，仍可右键命令 Pawn 操作；炮手格被建筑阻挡或
  不可到达时无法下达操作命令。插件随后停用时不拆建筑，缺少炮手的武器停火。插件与附加弹仓均提供可多选合并的启停
  gizmo，对 PD 武器同样适用。覆盖挂件 Def 一律继承抽象基类 `DeltaV_SpaceWeaponAttachmentBase`，
  由基类声明 `clearBuildingArea=false`：蓝图与施工框架沿用原版电缆的不清场地规则，原版
  `GenConstruct.BlocksConstruction` 不把宿主判为施工阻挡，施工 WorkGiver 也就不会经
  `HandleBlockingThingJob` 派发拆除宿主的 Job。God 模式直接落成品，不经过这条施工链。
- 炮手格只由原版 Def 的 `hasInteractionCell + interactionCellOffset` 声明，位置、旋转、
  寻路和建造预览共用原版入口。有效自瞄只隐藏成品的交互点；原版
  `GenConstruct.NotBlockingAnyInteractionCells` 枚举已完成的 `Building_SpaceTurretGun` 实例时始终解除保护。
  轨道炮装填机、其他建筑、蓝图、框架以及新武器自身交互格的检查仍走原版。建造规则沿用原版通行性语义，
  不再以全图武器扫描拒绝任何覆盖。自瞄不删除实际操作格，堵格后原版右键可达性
  检查自然拒绝操作；插件停用不拆除已有建筑。
  太空模式的炮塔选择覆盖层直接调用原版 `ThingWithComps` 入口，保留交互点和插件
  槽位提示；地面模式继续调用原版炮塔入口，附带地面射程和强制目标提示。
  插件也不设原版墙面附件 `isAttachment`：它是同格覆盖建筑，选中框须居于自身格内，Gravship 搬运按普通建筑
  捕获。真正销毁宿主时先记下槽内插件，销毁后按相同 `DestroyMode` 一并处理；普通
  `DeSpawn` 搬运不清除插件。
- 预留人选是武器 comp 的存档引用；当前操作人只由原版 Mannable 持有。炮手格不区分舰内外。

### 5.7 轨道炮分体建造（阶段5 实现）

伤害与费效比的统一假设、当前数值和验证顺序见 [武器定位与数值](舰炮与护盾基线.md#roles)。

- 装弹机本身是完整固定武器，含钢铁默认弹仓、内置等效技能 10 的轴向火控、基础短导轨和炮口；保留南侧操作终端但开火不依赖炮手。没有外接件也
  能沿固定安装轴以基础性能开火。装弹机本体气密、不可通行且承顶，因此加速导轨可以布置
  在船体外。`CompSpaceWeapon` 声明可用加速件 Def 与一个或多个连接起点。
- `CompSpaceRailgun` 只表示串联加速件：装弹机是必须支付完整基础脉冲的起始加速段；外接各段只有在本发能付足该段脉冲时才增加实际出膛速度和逐发电费。没有电的段仍让弹丸穿过，后面的段继续独立尝试加速。物理链末端仍决定出膛位置，和本发有几段通电无关；没有独立炮口建筑，也不直接修改伤害倍率。联合命中链继续从实际
  相对速度得到毁伤差异。
- 装弹机和每段导轨选中时标示下一部件脚印；放置幽灵同样标示连接位置。允许各段间隔
  规划/建造，开火时只从连接点按同朝向、同归属和允许 Def 解析连续成品链；供电状态只决定各段本发是否起效。
- 统一规格链只接受声明的加速段 Def；整链随基架控制域搬运，断裂后自动按仍连续的
  前缀重算。
- 轨道炮为开场破守卫和深穿内部设备的固定轴战略武器；加速段同时提高弹速、贯穿预算与盾容冲击。参数、破盾门槛、电容容量与回充时间统一维护在 [武器定位与数值](舰炮与护盾基线.md#roles)。装弹机基础脉冲必须付足，每段依链序独立预留电容／电网脉冲，缺电段跳过但不中断后段；同网不重复预支。装弹机内置铀弹仓，双槽可装轨道电容或快速复位模块。各电容新建为空，优先代付所属部件的完整脉冲，储能不足时回退该部件所在电网取电。
- `CompSpaceWeapon.ShotInterval` 从现有连接布局读取启用挂件的间隔倍率，武器详情、战术估算与发射准备共用。成功发射提交绝对结束 tick 和本轮实际间隔，两者存档；装弹机进度条读取已提交的间隔。
- 两个部件的内构在 `Building` 层绘制。`CompRailgunShell` 把各自的遮缝外壳绘在朝前脚印边界，装弹机用 `RailgunLoader_Shell` 遮住首段接缝，加速段用 `RailgunShell`。部件均占 3×1，连接起点与逐段根格步长均为朝前 1 格。绘制从低到高依次为内构、覆盖挂件、遮缝外壳和旋转炮身。
- `RailgunLoader_Inner_m` 红通道标装弹机终端屏，加速段内构蒙版红通道标线圈。装弹机和加速段的两侧槽位均为北向 `(-1,0,0)`／`(1,0,0)`，视觉偏移分别为 `(-0.02,0)`／`(0.02,0)`，缩放均为 0.65。两者各用合成图作建造栏图标、鼠标影像与已放置蓝图，蓝图以 3×2 绘制尺寸容纳外伸接缝盖。Def 见 [DeltaV_SpaceWeapons.xml](../1.6/Defs/SpaceCombat/DeltaV_SpaceWeapons.xml)，待实测项目见[美术验收](TODO.md#art-acceptance)。

#### 炮廓近防与真空屏障场（2026-11-10）

- 真空屏障场落在基架上，使用常开气密 Portal。成品在聚焦地图和船壳上均从原版 LinkGrid 选择四邻图块，可与墙或相邻屏障连边。蓝图使用独立的单格图。弹体透过屏障，按裸露基架规则判定脚下基架；基架毁坏带走力场。装弹机和连续链末段可预览并建造屏障。
- 炮廓近防炮是横宽 3 格、纵深 2 格的气密炮座。外排嵌入舱壁，内排保留炮身和后方操作位的安装关系。固定底座、旋转炮管、固定盖顶在地图和船壳共用绘制。常规和近防均需炮手；用同一发射事务准备五枚实体弹并结算一次弹耗。参数见[舰炮与护盾基线](舰炮与护盾基线.md#roles)。
- 「配置近防目标」保存导弹、穿梭机的复选掩码并刷新武器锁定。侵入 shuttle 优先按穿梭机标签分类。炮廓炮默认穿梭机，激光点防默认全部。近防排序沿用来袭时间，实体弹以扇形弹道估算火力分配。
- 炮廓专用的舱壁安全限制检查完整发射扇形；关闭后，本船实体通过统一碰撞链承伤。该出射检查忽略炮座自身及发射侧盾面。轨道炮和导弹架保留固定轴净空检查。

### 5.8 弹药、挂件与冷发射程序

- 常规实弹消费加工后的装药／高爆弹头或穿甲弹头，原版 Refuelable 库存与双仓补给适配见 §5.1.1。默认仓优先级 0、附加仓默认 1；在能提供整发弹头和装药的仓中高者先用，同优先级按 thingID 轮换。发射成功后从已选仓扣除两项库存。
- 内置仓与附加仓可用 gizmo 切换弹种和调整优先级，附加仓还可启停。实际装填和宿主炮型一起决定弹体、质量与穿甲参数。武器可用 `allowedAttachmentDefs` 收紧允许挂件；空列表保持
  第三方开放接入。
- 弹种质量与后效见[武器基线](舰炮与护盾基线.md#ballistics)。激光附加电容建成时无储能，容量、回充及逐束电费见武器基线，不足一发时恢复从电网蓄电池取电。电容不免除持续功耗；轨道炮发射铀弹时支付装弹机基础电费及所有起效段的电费。加速段能量回收插件通过挂件能力提供本段费用减免，`SpaceWeaponEnergy` 在预留之前计算折后费用；双件加算，不影响装弹机。逐发电费优先由所属部件的电容足额代付，否则取自该部件所在 PowerNet 的蓄电池；装弹机电容与加速段电容各付各自的脉冲。激光炮和轨道炮装弹机都必须有足额电容或电网蓄电池储能，不能靠瞬时发电白射高峰值脉冲。
- 电容建筑的武器插件 `CompSpaceWeaponCapacitor` 实现 `CompSpaceWeaponAttachment` 的直供接口及 `ShotEnergyBattery` 储能身份，`CompSwitchableBattery : CompPowerBattery` 复用原版电量、充放电与存档，只扩展接网／脱网选择。`SpaceWeaponEnergy` 共用每次查询的电网余额与专属预留，接网电容两条取电路径不重复计算；提交先扣专属、再扣公共电网。无插件安全电池也能在接网时参与公共脉冲支付。隔离、插件禁用、重连与自放电的完整规则集中于[储能基线](舰炮与护盾基线.md#costs)。
- `CompSwitchableBattery` 直接继承原版开发模式的 `DEV: Fill`／`DEV: Empty`，不维护另一份能量或充放电功率。
- 电池检查行的当前储能与容量，以及详情页的 W·d 数值共用两位固定小数格式；仅格式化显示值，储能累计和开火扣费继续使用原始浮点值。
- 炮塔与加速段的 `attachmentSlots` 建造格、允许附件列表及附件自己的 `allowedHostDefs` 共用 `SpaceWeaponAttachmentSlots` 生成选中建造按钮和空／已占槽位提示；无两套家族专用绘制逻辑。武器、加速段和电容的 Def 参数经各自 CompProperties 的 `SpecialDisplayStats` 进入详情页“Delta-V太空战”分类，显示逐发耗电、射击间隔、射程、槽数及电容容量；原版电池检查行显示储能、效率和自放电，不再显示固定充电功率或空满时间。
- `SpaceRailgunConstruction` 从装弹机 `allowedAcceleratorDefs` 建立装弹机 → 加速段按钮，并反查接受当前加速段的装弹机 Def 建立加速段 → 装弹机按钮；加速段还提供同型下一段按钮。建造关联只读 Def 配置。装弹机和加速段内构均使用原版 `Graphic_Single` + `CutoutComplex`：灰度底图的对应部位由同路径 `_m` 红色蒙版标出，状态 Comp 的 `ForceColor()` 经原版 `ThingWithComps.DrawColor` 给红色通道赋色，状态边沿调用 `Notify_ColorChanged` 刷新原版建筑 MapMesh；绿色通道才对应 `DrawColorTwo`。建筑维持原版 `Building` 类型，不切换整张贴图，也不使用 `CompGlower`。装弹机的 `CompRailgunReadinessAppearance` 绑定武器的 `SpaceWeaponLayout`，每次只执行一份 `SpaceWeaponEnergy.Evaluate` 只读规划，同时分发装弹机和线圈的三态电力颜色：断电、未连接或对应脉冲预算不足为灰色；预算足够且未冷却为蓝色；预算足够且整炮冷却中为红色。缺弹、炮手和炮口安全条件不参与电力配色；加速段的颜色 Comp 只接收结果，不反查装弹机或独立轮询。外壳贴图保持独立且不变。生成接线在原版 Building.SpawnSetup 收尾、统一结构版本更新后刷新，避免 Comp.PostSpawnSetup 读取旧布局；移除、供电和成功发射触发刷新，连续储能变化最迟每 60 tick 由装弹机复核，冷却结束当 tick 刷新颜色。装弹机复用原版迫击炮的 `ProgressBar` 效果和 `CanFireIn` 秒数文本；进度、文字与颜色读取 `CompSpaceWeapon.CooldownTicksLeft`，不维护第二个计时器。冷却截止 tick 随武器保存，读档不重置；沿用游戏 tick 推进，断电不暂停冷却。效果在冷却结束或移除时释放，非聚焦外壳不绘制 Mote。跨存档复用 prefab 时清除旧世界的截止 tick。颜色不替代弹药、炮手、安全通路、武器组、瞄准目标和锁定范围判断。
- 弹体 Def 声明冷发射时长、离架速度倍率、初次强转向最长时长／转向率、点火加速时长与锁定弧；发射架仍可覆盖冷发射时长。`SpaceProjectileService.AdvanceFlight` 是冷发射 → 初次转向 → 主机追踪的唯一阶段入口，所有计时使用游戏 tick，位移和碰撞沿用现有容器积分与扫掠。
  冷发射阶段保留发射轴推出速度与宿主速度继承，不主动转向或推进；离架后初转只旋转弹体朝向，不瞬间改写平移速度，对准、目标失效或时限到达即进入主机阶段。主机在唯一的 universe 速度状态上沿弹体朝向逐 tick 施加有限加速度，转向不直接旋转速度矢量。制导期把目标速度换算至导弹位置，取「目标速度 + 指向目标的 32 格/s」作为期望速度；弹头朝目标视线转动，并按横向相对速度偏转；微小速度残差不改变朝向，单 tick 速度增量以离架速度至巡航速度差除以点火加速 tick 数为上限。这里的 32 格/s 是相对目标的期望接近速度，不限制绝对宇宙速度；两船共同高速漂移时导弹保留发射瞬间的漂移。普通弹体不接入飞船 MPC；发射瞬间的继承速度只作为初始条件，不另存运动参考系。正式高爆导弹保留 30 tick 冷发射、初转最多 12 tick／1080°/s、点火加速标定 6 tick／最大 4 格/s 每 tick 速度增量、主机转向 540°/s。固定 `timeoutTicks` 仍控制总寿命，不根据当前速度重算。目标消失后停止制导，正在进行的点火段沿当前朝向完成，之后沿当前速度飞行。发射架能力只能进一步限制、不能扩大弹体锁定包线。
  初转的实际转向符号驱动外侧 RCS 短焰；冷发射只留少量短寿命烟气，主机实际施加速度增量时才绘长尾焰和相应烟迹。普通弹体喷口取 Def 的 `exhaustOffset`（弹头前向 +X、左侧 +Y），烟迹和尾焰共用同一喷口坐标；烟迹继续使用服务已有总量上限。表现不改变弹体位姿或碰撞几何。
- 侵入 shuttle 的真实推进器、截击飞控和加力规则见 §7.3–7.5；不进入普通导弹的冷发射／简化加速度制导状态机。普通导弹尾焰只在本 tick 实际加速时显示；侵入烟焰读取真实推进器布局与油门，只有正在加力的尾部主推使用 afterburner 表现配置。

### 5.9 工程设备：惯性耦合与采矿光束

两件设备是 `CompSpaceWeapon.manualOnly` 的应用，继续使用原版炮塔绘制、
共同 Traverse、手动武器组与 `SpaceWeaponShot.Prepare → Launch → Commit`。
惯性耦合器与采矿光束由自动齐射、点防和 AI 火力估计跳过；它们不执行拖曳、停靠或地图扩容。月池牵引器复用射击事务的供电、瞄准和扣费，收集模式通过 `ISpaceWeaponLaunch` 提交回收请求，结构模式转入现有连续束发射和统一碰撞后效。自动模式从散落事件索引选择通过物品／活体筛选且未被其他设备占用的目标，跨船独占；手动模式沿炮口方向发束，按每 tick 实际交点施加牵引力（每束为大型推进器满推力的四分之一）；默认副4，多束可叠加。牵引与惯性耦合命中断片时共用外力拆分门禁，先经共同搬图链独立再施力。牵引与回收的权威设计见 [对接与舱外作业重构设计](对接与舱外作业重构设计.md)。
设备和弹体初始参数以 `1.6/Defs/SpaceCombat/DeltaV_Engineering.xml` 为唯一数值来源。
惯性耦合器的 `continuousBeam` 每游戏 tick 通过同一发射事务支付能量并更新射线，
耦合强度及冲量上限按同一步长配置；松开开火、停用武器组、失去射击资格或欠电时停止。
详情页显示每秒蓄电消耗，不显示脉冲射击间隔。
对无驾驶台残骸及天然岩石的作用来自统一射线碰撞，不要求目标具备驾驶身份。

- **惯性耦合**：`SpaceImpactEffects` 的 `CoupleMotion` 后效从仍在图上的发射器解析当前容器，
  经 `SpaceObject.CoupleMotionWith` 调用 `ShipPhysics.CoupleMotion`。双方使用现有质量和惯量，
  在命中点共同切平面分别交换容器平移动量与自旋角动量；线速度差不转成两船中心的公转。
  两种交换均等大反向且受单 tick 冲量上限限制，小残差按相同上限完成收敛，避免无阻力模式
  下分数脉冲停在浮点精度尾差。守恒的是切平面线动量和自旋角动量，不再使用含力臂的轨道角动量模型；
  不声称球面远距全局欧氏动量精确守恒。不能凭空消除共同漂移或共同旋转，本船需主动反推。
  后效只改双方已有速度，不推进位置、不再次积分、不触发推进器分离，也不保存独立任务或耦合状态。
  连续射线从发射时冻结的船体局部炮口及方向，在本 tick 刚体积分后换回宇宙坐标，跟随本船运动。
  切向量换基只由 `SpaceTransform.TransportTangent` 计算。
- **采矿**：舰载和 EVA 使用同一个 `CompSpaceWeapon` 与 `CutStructure` 后效，通过 `CompProperties_MiningBeam` 配置参数。2×2 小型舰载采矿光束射程 65 格，每 30 tick 切割 240 HP、消耗 3 Wd；3×3 中型射程 80 格，每 30 tick 切割 360 HP、消耗 5 Wd。两者均无人、`manualOnly`、固有瞄准技能 20，小型一个专用槽、中型两个专用槽，只接受采矿货箱和目标识别插件。EVA 切割器射程 6 格，每 30 tick 切割 180 HP。矿岩沿用原版 Def 的产物、掉落概率和难度修正后的产量。可损耗矿物的回收率为舰载 50%、EVA 100%，成功掉落时至少一件。不可损耗的岩块等按原版掉落概率结算。
  采矿束与 EVA 切割器对基架的命中概率均为 1；同格实体建筑先判定。切除基架时共同清理命中格与四邻格屋顶，有存活建筑的邻格及月池力场顶保留；工程切割不再叠加普通毁伤的随机八邻格掀顶。
  建筑切割消耗真实耐久，基架按单发阈值判定。确认切完时，`GenLeaving` 按原版拆除规则生成材料，切割流程在原版放置及合堆前接收这一批。基架、舱壁和设备均按舰载 50%、EVA 100% 的正常拆除量结算，倍率在原版随机取整前应用。
  建筑用 `Destroy(Deconstruct)` 保留乘员、库存及地图的原版清理，已接收的返料只出一次。本次切割移除跳过销毁起爆。基架移除复用结构清理入口，附着电缆等走切割移除。目标成功移除后，舰载和 EVA 的矿石／拆除返料全部交给 `MiningBeamOutputRouter.Deliver`；EVA 与识别拒绝项在该入口内共同调用唯一的 `QueueMiningEjection`，继承目标的刚体点速度并成为可牵引的无图 `SpaceObject`。每堆拆除返料在朝来向的 ±40° 内独立取向，额外速度为 0.4–1.8 格／秒；矿物也在同一 ±40° 锥内逐堆取向，保留 2–4 格／秒的较高额外速度。
  未安装启用的目标识别插件时，舰载返料全部允许回收；安装后按插件的 `StorageSettings` 过滤，两个识别器采用并集。识别器通过 `Command_BatchSetting` 提供可合组的「目标过滤」Gizmo；多选后只打开一个 `Dialog_MiningTargetFilter`，打开窗口不改写不同设置，实际修改才传播到仍有效的玩家插件。被全部识别器拒绝的材料不尝试落图；允许项依次尝试启用的采矿货箱，再以设备所在格为中心调用 `GenPlace.TryPlaceThing(..., Near)`，地面回退排除货箱槽位。
  每个采矿货箱是一个非 edifice 的 `Building_Storage`，沿用原版 `StorageSettings`、`SlotGroup`、搬运、合堆、拆堆、设置复制／联动、存读档与检查面板，明确允许且默认勾选岩块，默认优先级 `Low`，容量为 8 堆。多个货箱按储物优先级降序、再按炮座槽位顺序接收；主动入箱先调用原版 `Accepts`，再用 `GenPlace.TryPlaceThing(..., Direct)` 放入真实地图物品。因为原版单格容量和防变质只读取 edifice，`Patch_MiningCargoStorageCapacity`／`Protection` 仅在该格的真实 `SlotGroup` 属于采矿货箱时改读插件容量并提供小物品架保护；其他炮塔格和储物设施不受影响。物品继续由 ThingGrid 的统一入口计入结构质量，不创建内部容器、库存镜像或交易货柜接口。
  货箱过滤拒绝、容量不足或部分放入后的余量不是失败，继续落在炮塔附近；只有最终 Near 放置失败才沿用原版失败行为并丢失未放下的材料。空间不足不阻止扣耐久或完成拆除。拆除插件后，格内物品像拆除原版物品架一样留在甲板上。
  返料倍率与放置失败提示限定在本次同步切割出料的 `SalvageOutputScope` 内。`Patch_SalvageOutput_Placement`
  读取原版 `GenPlace.TryPlaceThing` 带 out 参数重载的最终返回值，失败（含部分放下后失败）
  才由 `SpaceWeaponService` 通过原版左上角消息提示玩家。矿物、建筑和基架每次出料失败均立即提示，
  不增加提示冷却、容量扫描、收益预估或存档状态；作用域在异常时也恢复。
  已确认放置失败的采矿作用域内，原版两类 GenLeaving 失败警告改由该玩家提示替代；
  其他调用及其他警告保留。
  不增加输出缓存、存档队列或重试收益。产物放置及电缆修复已通过用户游戏内验证；
  损失提示按用户反馈移除冷却，每次失败均调用原版消息入口。
  电缆沿 §3.2 共同碰撞规则处理，只有电缆的基架可正常切除并结算材料。
  多束按实际命中顺序处理，已销毁实体和已移除基架不能再兑现材料；最后一格消失后的销图仍由现有生命周期执行。
- **光束与护盾**：共同 `SpaceCollision` 处理遮挡、距离与盾面。舰载采矿光束配置建筑必中，两种切割器均配置基架必中。

### 切割炸弹背包

背包沿用原版照明弹背包的手动投掷指令、穿戴栏位及 `CompApparelReloadable`。容量 2 发，每发装填需 35 化合燃料。制造需 100 钢铁、40 塑钢、4 零部件、20 化合燃料、制作技能 8，工作量 16,000，研究见[设备科技树](设备科技树.md)。投掷只在 Delta-V 纳管地图执行。射程 12.9 格，落地后 100 游戏刻引爆，与原版破片手榴弹一致。保留原版视线、引信和同图弹体拦截盾判定。盾拦截直接销毁弹体。

背包使用封闭宽肩外壳和斜向琥珀标记。落地图也为模式按钮提供图标。穿戴图提供北向背面、东向侧面和南向正面，西向由原版镜像东向。穿戴沿用体型缩放。北向基础偏移为 `(0,-0.05)`，东向为 `(-0.31,-0.05)`，西向为 `(0.31,-0.05)`，侧向仍叠加各体型的偏移。所有装填数量共用同一套外观。投掷物使用削角灰壳和琥珀横带，飞行中与落地待爆共用贴图。见[美术对照](art/CuttingBombPack_visual_reference.png)。

瞄准和引爆共用同一条五格栅格垂线，斜投时每步沿主轴推进一格，超出地图的格子裁去。「破墙」是默认模式，以原版直接伤害结算线上可攻击的墙壁和门，保留基架。「破基架」优先调用 `TryDestroyHitFoundation`，清理该格地板、屋顶及占格建筑，更新结构归属和连通性，并提交散落处理。无基架格仍可破墙和门。引爆仅沿切割线结算，关闭相邻格随机掀顶。

## 6. 瞄准模式与预瞄

### 6.1 玩家火控与机动（统一 controller 下的独立输入会话）

- 基架船与 shuttle 的身份锚通过同一 `ShipCombatState` 保存火控模式与武器组，**普通新船默认自动火控；EVA 默认手动**。侧边栏或可配置 B 键切换当前所选船的
  自动／手动／禁用，允许模式由 `ShipBase.SupportsFireControlMode` 统一提供给面板与快捷键；EVA 仅开放手动／禁用。禁用立即释放瞄准、点防和持续牵引请求，执行入口再次拒绝发射；武器组、驾驶任务及已发射独立弹体保留。自动火控沿用有效目标；没有目标时按决策间隔评分索敌，已有目标失效时当 tick 重选。玩家与 NPC 各持有同一类
  `ShipFireControl`，经 `ShipFireControl.TickVolley` 分派统一武器命令；执行边界见 §5.1。
- `ShipFireControl.CandidateValid` 是自动索敌、逐 tick 齐射复核、预瞄和 NPC 目标数诊断的共同资格入口：候选须为战术范围内另一已加载容器的有效敌对 `ShipBase`。基架舰使用当前主台派系，shuttle 使用艇体派系。主台被毁时，同向备用台继任后使用新主台派系；无人继任则失去舰船身份，退出自动索敌。容器派系和推进能力不参与成员敌我判定。
- 自动火控只在索敌时枚举每个容器的每一艘合格船，以带种类的 `DriveSubject` 锁定。评分中的敌方火力、可用动力、船体半径及建筑耐久只读取该船；不汇总整图碎片、友方或其他成员。保留原评分权重和设置中的索敌间隔，同分按稳定船身份排序。

### 6.2 目标身份与解析

- 运行时 `CombatTarget` 区分三类：飞船（带种类的 `DriveSubject` + 可选设备 ID）、容器（objectId + 可选 Map 局部点）、自由瞄点（universe 坐标，无隐式锁定）。`TryResolve` 只回答当前位置，不判断敌对、推进能力或攻击资格。
- 飞船经 `ShipRegistry.ShipByIdentity` 找当前成员，再经 `FrameOf` 找当前承载容器；不长期持有 Map／ShipBase，也不以 ownerId 反查容器。设备被毁或离开该船时回退到同一船中心。分离、换图和同向主台继任保持船身份。
- 手动导弹先按射线选最近敌对容器，只承载人员的容器不参与；该容器中射线命中敌对船成员时记录船身份，否则记录容器身份。此策略允许失能船和残骸；没有候选时无锁定直飞。直射弹／激光仍以发射方向和碰撞结算命中。
- 在飞导弹只解析发射时指定的目标，分离后跟随原船的新容器；推进器失效不解除制导。身份消失／无法解析后清除锁定并沿当前方向继续飞行，不扫描或重新捕获其他目标。
- 玩家侵入使用明确容器局部落点；NPC 跳帮使用火控已选船身份。弹体每 tick 解析一次目标，将同次解析得到的位置用于制导、容器 ID 用于限定碰撞对象；不允许追踪新容器却仍限定命中旧容器。
- 自动机动消费同一目标身份，由战术层的 `CombatTargetSampler` 提供当前位置给 `ShipAutopilot`。轨迹、视线朝向与相对速度使用目标船位姿；避碰距离仍覆盖整个承载容器及船中心偏移。自动驾驶不解释船身份和选敌规则。
- 目标和锁定均不存档；控制器、武器状态、地图卸载与换档沿既有生命周期清理。战斗调度每 tick 通过共同身份索引取得当前船，不另留船体快照。归档由表示替换事件按原容器 ID 清除残骸锁，并在同一次遍历复核旧图目标和当 tick 解析缓存。随后旧图清理只释放弹体相关资源。普通地图卸载和容器移除仍清理相关目标；已分离到新图的船和仍可解析的无图弹体不受旧图清理影响。侵入目标失效时停止该次限定扫掠，解除接管沿共同弹体收尾路径执行，遍历中安全移除。

### 6.3 预瞄指示器与瞄准标记（已定需求）

- 手动输入会话每帧自动显示预瞄，从 `ShipFireControl.LeadPoints` 先为各激活武器准备一次精确参数，再遍历目标求解；同帧绘制复用显示结果，结构变化立即失效：对每个通过 §6.1 共同资格入口的敌船 × 激活齐射武器的真实炮口／弹种／弹速，解算并合并重合的
  瞄准点；在炮口切基中以相对速度 `w = 目标速度 − 发射继承速度` 求 `|p + w·t| = 弹速·t` 的最小正根，瞄准偏移为 `p + w·t`，再由 `OrbitSphere.Move` 转回 universe。该点补偿弹体继承的发射方速度，不等于目标的绝对未来位置；发射继承速度与真实 `Launch` 同读 `SpaceTransform.TransportVelocity(sourcePose, muzzle)`。激光档 = 目标当前位置。聚焦帧投影绘制标记。标记纯显示派生，不参与发射判定；自动齐射、PD 和预瞄复用 `SpaceWeaponBallistics.TryAim/TrySolveIntercept`。预测仍假设目标匀速，后续机动会产生误差。
- 瞄准模式激活时，**瞄准位置标记**（鼠标处）与预瞄标记同管线绘制，视觉上区分
  （形态 §15）。
- **图标与角度语义（2026-09-27 实测定案）**：图标用原版 overlay 贴图——瞄准位置
  = `UI/Overlays/TargetHighlight_Square`（原版 targeter 同款，橙红）、预瞄 =
  `Circle75Solid`（绿）。旋转与聚焦船同宇宙角（`FocusedMeshRotation(frame,
  frame.pose.angle)`）：从聚焦船看恒水平、随聚焦船旋转——不锁宇宙 0 角。

## 7. Shuttle 体系（跳帮舱改制）

### 7.1 定位与原版复用

- 月池是特殊基架地形，自带专用 `DeltaV_MoonPoolFieldRoof`：原版屋顶格负责房间、
  温度、天气和真空气密，照明判定允许完整日照透过。已有普通屋顶保留到玩家手动拆除，
  拆除后自动露出力场顶；自动／手动盖顶不作用于月池，力场顶不能拆除或坍塌。
  地形、屋顶变更和搬运落位按事件同步，读档只重建一次，不逐 tick 扫图。
  穿梭机发射、放置和 Delta-V 普通对接的原版落点检查仅在月池格豁免屋顶；
  整艘逆重飞船不豁免，落地也不拆除宿主屋顶。
  离线回归入口：`scripts/MoonPoolRoofRegression/run.ps1 -GameRoot <游戏目录> -HarmonyPath <net8.0 Harmony DLL>`；
  校验 Harmony 绑定、屋顶替换与清除、局部透光／通行和防坍塌，不替代游戏内验收。
- shuttle = 与原版 shuttle 同类的小艇建筑：停靠时是普通建筑 + 原版
  `CompTransporter`（装货/乘员登舱）+ `CompLaunchable` 系发射语义；**完全使用
  原版装货逻辑与一键卸货**，不自研装卸。跳帮舱与普通 shuttle 无非数值差异（乘员
  更少、血量更厚、机动更强；燃料差异随燃料系统后续接入）。
- **起飞校验直接取原版 shuttle 发射校验函数的结果**（2026-09-26 定案）：冷却、
  乘员等全部门禁由原版函数判定，本 mod 不做第二份检查（具体入口施工前核对
  CompLaunchable 系；按 §10 优先级纪律，能直接调就不 patch，能 Prefix/Postfix 就
  不镜像）。
- shuttle 不是武器、不占武器组、不进战斗位置征用。
- **可拦截性（2026-09-26 修订，结构派生）**：shuttle 之所以可被点防御拦截，是
  因为它是一个**有地图的、依托于内部建筑存在的 SpaceObject**，且 **tag 为
  shuttle（正常驾驶）或附加 projectile（侵入碰撞角色）**——
  结构上即拦截合法目标，**不是因为** building def 上的可拦截标记。
- **与飞船不得有两套逻辑（已定约束）**：起飞/飞行/降落/受击全部复用飞船的同一
  实现；普通降落读取 shuttle 的单建筑船体脚印与锚，同样执行
  `CaptureDomain → StripDomain → PlaceIntoMap`。shuttle 特有的只有不搬地形/不盖
  归属、落地后触发原版冷却、起飞后立即进入驾驶（玩家方），以及侵入式对接能力
  （真实推进器截击与共同碰撞）。

### 7.2 状态机：建筑 ⇄ MiniShip

```text
建筑（停靠：装货/卸货，held 货物与乘员随建筑存档；起飞门禁 = 原版校验结果）
  ↓ 起飞（原版校验通过 ∧ 非地表图；玩家方舱体自动进入驾驶）
MiniShip（在飞：普通 SpaceObject 容器 + 口袋图里的舱体建筑；tag = Ship + Shuttle；
         可驾驶/自动驾驶/受击/可被 PD 拦截）
  ↓ 停靠（与飞船同一对接计划管线 §7.4 / 侵入式截击 §7.5；都触发原版降落冷却）
建筑（停靠，冷却中 → 期满可再起飞）
```

- 起飞 = 舱体建筑（含 held 内容）经**与船脱离同一套**统一搬运核心捕获进新口袋
  容器（`TransferDomainToNewPocket`，cells = 舱体脚印；**不搬基架、不进控制域
  语义**）；新容器位姿/速度 = 宿主刚体上舱体锚点位姿（含自旋切向继承，
  `RigidPointPose`）。
- `ShuttleShip` 与 `FoundationShip` 并列继承 `ShipBase`，进入 `ShipRegistry.AllShipsOnMap` 成员枚举，
  但没有基架归属域。容器注册／积分／休眠／归档走既有 SpaceObject 通道，受击走 §3 统一碰撞链。
- 全部船型启用共同的完整战术 AI：选敌、火控、武器组、站位、战损重评与返厂不按 shuttle 船型排除，无武器只使真实火力为零。目标威胁按单艘船成员分别评估，不混入其他成员及碎片；对象敌我关系读取成员派系，陈旧环境派系不覆盖成员事实。跳帮能力的可用艇查询与执行统一由 `SpaceShuttleService` 提供，仅使用本船及其控制域内的载员侵入艇，已在飞的艇可直接侵入，不再次起飞。NPC 决策在显式对接或弹体接管期间不覆盖其任务。
- 驾驶：`ShipController` 契约复用——`PilotService` 目标泛化为「可控体」（容器 +
  推进器控制模型），玩家/NPC 双子类与按键抑制、打断语义原样适用（不复制第二套）。
  面板、星球仪与世界标记统一枚举飞船，停靠和在飞 shuttle 都有船身份。玩家方舱体**起飞完成即自动进入驾驶**
  （共同的 `TransferShipToPocket` 完成相机与 `PilotService.Enter` 交接）：只在聚焦已随起飞
  交接进新口袋图时生效，否则下一帧聚焦自动退出驾驶，进入无意义；与飞船的差异在于
  飞船本就处于驾驶状态才能出力起飞，shuttle 可经起飞按钮或驾驶按钮确认起飞进入宇宙，故需要此自动接管。
  未注视起飞（dev 敌对发射/NPC）或非玩家方舱体不自动进入，仍可经面板手动驾驶。

### 7.3 飞行动力学：矩形刚体 + 虚拟推进器（已定）

- 虚拟推进器布局是 **XML 列表**，每项显式给出 shuttle 船体帧中的作用点 `position`
  与推力矢量 `force`（方向 = 推力方向，长度 = 最大推力）；数量、位置、方向和大小均
  可自定义。原版 PassengerShuttle 的默认表为 8 台，但“8 台/四角/轴向”不是代码
  常量；跳帮档位可通过 `DefModExtension_BoardingProfile.virtualThrusters` 整表覆盖。
- 虚拟推进器由 `MapSpaceObject` 提供给共同物理核心与只读预览：质量 = def + 原版
  `CompTransporter.MassUsage` 载重，惯量 = 各建筑矩形本征惯量 + 平行轴项。3×5
  跳帮 shuttle 空载质量 280，`I=280*(3²+5²)/12≈793.3`；载重增加后加速度与转向
  响应按真实质量、惯量降低。驾驶输入、飞行辅助、被动阻力与飞船完全同构。
- 跳帮艇共六台推进器，船体帧 +X 为艇首、+Y 为左侧；以下均为推力矢量，排气方向相反。
  尾部两台位于 `(-2.2, ±0.69)`、各 `(2700, 0)`；头部两台位于 `(2.02, ±0.85)`，
  分别 `(-1900, ∓1900)`；中部两台位于 `(-0.55, ±1.1)`，分别 `(1500, ∓6900)`。
  头部与中部斜推的侧移力矩互相抵消大部分，剩余力矩由共同分配器补偿。
  常规前推总上限 8400，加力前推总上限 11100，常规反推总上限 3800。
  空载理论前向加速度为 30.0／39.6 格/秒²，500 kg 满载时为 10.8／14.2 格/秒²。
  本地 `Fighter_0` 的四台前推合计 8000，基架、推进器和 92 段船壳墙已计 884 kg，前向加速度上界约 9.1 格/秒²。
- 虚拟推进器表是有图对象持有的可重建缓存，不序列化；首次读取驾驶信息时按 XML 重建，
  读档后走同一入口，不另设全局虚拟布局注册表。舱体销毁及地图卸载事件在帧边界清理容器，
  无须每 tick 扫描在飞 shuttle。
- 受击：碰撞面 = 舱体脚印（建筑实体格）；被弹体命中 → §3 统一链（联合后效毁伤落
  shuttle 口袋图打舱体建筑）。舱体被毁 = shuttle 消失（乘员/货物按原版 transporter
  摧毁语义），帧边界注销容器。

### 7.4 普通停靠 = 与飞船同一对接计划管线（已定）

- **降落逻辑只有一套**（飞船的对接计划管线）：目标选择（排除自身容器、多候选
  按可见壳距离选）→ 选点（初始落点 = 悬停投影，玩家可调；合法性门禁照常）→
  幽灵提示 →（可选）随动自动驾驶接近（玩家可手操打断）→ 位姿窗口保持判据 →
  捕获-剥离-直接放置。**shuttle 复用全链**，唯一参数差异 = 计划脚印来源
  （船 = 控制域脚印；shuttle = 舱体 building def 脚印），选点预览按同一门禁的
  脚印校验。
- shuttle 的舱体脚印就是其完整控制域；完成时与飞船一样按选点注册的 Gravship root/
  Rotation 捕获、剥离、放置，禁止再用建筑 `DeSpawn + GenSpawn` 解释落点或朝向。
- **差异只允许在降落属性与后处理**：飞船 = 搬基架并保留结构身份；shuttle =
  `includeTerrain=false`、不盖归属，放置后成为普通建筑并触发原版降落冷却
  （入口施工核对，§10 优先级纪律）。除此之外不得有任何 shuttle 专属降落分支。
- 侵入计划/对接计划均为运行时数据：读档丢弃、按已存速度漂移、不自动续接。

### 7.5 侵入式对接：真实推进器截击与共同碰撞

- 跳帮艇的战斗区常驻「撞击侵入」。只有具备侵入能力的在飞艇可发起侵入。规避开启时，按钮灰显并提示「关闭碰撞规避后启用」。关闭规避后可直接用该命令选择敌舰外壳，进入选目标与确认发起时都检查当前规避状态。侵入进行中可用「中止侵入」恢复正常飞行。
- **运动 = 同一艇体、真实推进器、截击 MPC**：进入侵入时停止旧驾驶任务，弹体服务
  为原艇体登记唯一碰撞工作项，并调用 `ShipAutopilot.Intercept`。质量、惯量、推进器分配、
  被动阻力和积分均与正常驾驶共用；不直接改写速度方向、不设导弹巡航速度或转向率。
  玩家点选的容器局部点随其刚体运动，NPC 跳帮跟随已选船身份；同次目标解析供制导与碰撞使用。
  只与指定目标结算，沿途不会撞母舰。MPC 滚动搜索较短接触时域，接触速度自由；具体成本、
  预测与调度见[在线 MPC 自动驾驶](在线MPC自动驾驶.md#侵入截击2026-10-24)。
- **加力油箱**：侵入截击时尾部两台主推按 1.5 倍出力。独立 `CompRefuelable` 油箱新建为空，
  可装 60 单位化燃，满箱可连续加力 1920 游戏 tick（32 秒）。任一主推实际加力时每 tick 扣
  1/32 单位，两台同时加力仍只扣一次。殖民者用补油工作加入化燃，先满足原版航行油箱的补给请求。
  加力耗尽后按常规动力追击，补油达到艇体 Gizmo 设置的 1%–100% 重启阈值时恢复加力，默认 50%。
  油量和阈值随艇体存档，取消截击和落地保留油量。推力变化让截击重新规划，排气读取实际油门。
- 侵入超时为 7200 tick（120 秒）。`projectileRoleOverride` 只追加碰撞角色，不改变基础类型或阻力。
  面板主动中止、目标失效或超时均解除接管和对应 MPC 任务，保留艇体及线／角动量。
  读档不恢复侵入任务，艇体按保存速度正常漂移。
- 宽相位仍使用完整艇体外接圆，窄相位只以实际 3×5 脚印的艇首 3×1 一排触发破拆，
  避免侧后方结构被外接圆选为艇首命中。艇首碰撞矩形与落地朝向读取真实艇体朝向，
  不从侧滑速度反推船首；毁伤相对速度和入射角仍读取真实运动。
- **结算 = 联合后效 + 共同降落链**：跳帮艇通过通用 `ignoresShields` 穿过全部盾面（含原版圆盾），
  不扣盾容、不付线盾脉冲电费、不在盾面落地；点防仍可攻击艇体。仅实体命中触发跳帮后效。
  命中时固定撞击格与目标图内的四向朝向。艇首一排进入目标船，向内第二排保证清出三格宽通道。
  斜撞时还破拆与剩余艇身脚印冲突的建筑，放置冲突沿用原版 `GenSpawn.SpawningWipes` 判定。
  破拆保留基架。脚印或通道越界、碰到无法破拆的建筑时保留艇体并提示玩家。
  后效解除弹体接管，调用普通 shuttle 的 `CaptureDomain → StripDomain → PlaceIntoMap` 与冷却、
  聚焦和源图收尾；乘员/货物仍 held，原版从艇首交互格卸员。高爆导弹撞泡泡盾时也在盾面执行
  爆炸后效，而非只销毁弹体。
- 玩家正聚焦跳帮艇口袋图时，落位后的帧边界先用 `SetFocusedWithCamera`
  交接到实际被撞容器的 Map，镜头对准撞击点并保留缩放，然后销毁源口袋图；
  玩家已切往其他图时不强制夺回聚焦。
- 侵入 shuttle 已在共同弹体工作表中，不再枚举宇宙对象拼第二个扫掠体；MPC 只出力，实体碰撞决定完成。转移源图与聚焦交接绑定在本次完成对象上，避免并发命中互相覆盖。
- 与导弹的同构性：PD 拦截（结构判据含两种 tag）、碰撞（同一核心）、后效（同一
  注册表）、目标指定（点壳）全部同链——「拦截 shuttle 和拦截导弹完全是同一个
  机制」。

### 7.6 与旧跳帮体验的对应

选中乘员 → shuttle 装货（原版登舱）→ 起飞（原版校验）→ 关闭碰撞规避、点击「撞击侵入」并选敌壳 →
真实推进器截击 → 破拆两排并走共同降落链 → 原版从艇首卸货出击。撤离 = 普通对接召回
或占领后再次起飞。舱体堵住破口的气密性由舱体 def 保证（施工核对原版 shuttle def
的 fillage/密闭语义，不足则跳帮特化 def 补齐——def 配置差异，不是机制差异）。

`TransporterDropService` 是运输舱内容页、原版 `CompTransporter.CancelLoad` 整舱卸载和载具批量离舱命令的共同放出入口，不修改全局 `ThingOwner.TryDrop`。入口按运输舱真实交互格选择后端：图内调用持有容器的 `ThingOwner.TryDrop → GenDrop → GenPlace` 原生落放；有 SpaceObject 承载的太空图若落点越界，才交给 `SpaceScatterService` 的无图散落事务。任何活体 Pawn 在图外释放前显示危险确认，物品、尸体及其他货物不提示；确认前及取消后内容仍留在舱内。散落服务在下一安全帧复核运输舱的地图、根格、朝向、容器表示与原堆数量，再按指定数量交接。整舱卸载额外要求同一持有容器的完整快照仍成立；取消、表示失效或任一交接失败均不调用原版装载清理，只有整舱释放完成后才移除装载 Lord 并清空装载变量。舱口交互格用于换算宇宙位置和刚体点速度，因此 1×1 飞行图的图外交互格也可使用。重复确认及重复部分拆堆请求最多交接一次，交接失败保留原内容。成功后由共同入口按原版语义将 Pawn 移出装载队伍，并通知运输舱刷新载重。

任何已生成且非敌对的 `CompTransporter + CompShuttle` 载具，只要舱内有玩家派系 Pawn，便在载具 Gizmo 提供「让己方人员离开载具」。这包含 Delta-V 小艇、盟友跳帮艇以及原版无派系／友方任务穿梭机；敌对载具和无地图表示的运输状态不提供。命令按点击时快照一次释放全部己方 Pawn，不移动盟军乘员或货物，并与运输舱内容页共用 `TransporterDropService`。图内逐人通过持有容器原生落放；图外交互格只显示一次批量确认，随后在安全帧复核载具、容器表示和全部乘员仍有效，再逐人交给同一散落链。该路径只依赖穿梭机与货舱本身，不要求或创建服务世界运输任务的 `CompShuttle.shipParent`。成功离舱后 Pawn 按原版原因退出装载 Lord，`CompShuttle.requiredPawns` 不改写，因此任务起飞仍按真实舱内状态判定满足／不满足，不会因主动离舱误报完成。该全局入口只公开原版穿梭机已有的乘员自主离舱能力，不修改地面寻路、任务状态机或运输船运动。

### 7.7 EVA 工程载具与共用挂载（2026-11-04）

`DeltaV_EvaSuit` 是单格、单驾驶员的本地 shuttle 派生载具。`CompLocalShuttle` 保留原版装载、货舱和乘员存档，允许物品装载，不创建世界运输任务或执行其超时卸客；`CompLocalLaunchable` 不提供世界发射，仍经共同 `CanLaunch`、月池屋顶规则和 `CaptureDomain → StripDomain → PlaceIntoMap` 起降。`CompVehicleCargo` 继承原版运输舱，限制一名驾驶员，货物上限为 60 kg。`CompStructureMass` 将物品即时计入飞行质量，EVA 排除 Pawn，普通穿梭机沿用原版计重口径。EVA 不具有侵入能力。

- `ShipBase` 的 `RequiresHeadingAlignment`、`RequiresAngularVelocityMatch`、`MatchDockingPointVelocity` 供同步目标、MPC 参考、就绪与最终停靠复核共用。普通船保持原同步规则；EVA 忽略方向和角速度匹配，匹配母船当前接触点的刚体线速度（包含切向速度）。整数落位与旋转仍只生成一次。
- `AllowsAngularMotion` 由共同质量报告和归档 `DriveSnapshot` 携带，积分与外力入口消费；仅独立飞行的 EVA 贡献零角速度约束，停靠在母船上不锁母船自旋。起飞先继承原刚体点线速度，再清除 EVA 容器角速度。
- `DriveInputBasis` 保存地图平面内实际屏幕上／左方向，相机射线与地图平面求交得到两轴；输入、刹车和飞行辅助共用正逆变换，支持投影轴不正交。EVA 不消费 Q/E，也不产生辅助转向力矩。
- `ShipBase.CreateAimHandler` 创建瞄准处理器。EVA 的处理器先调用基类，再从四个合法 Rot4 的屏幕投影选最接近指示点的朝向，仅在变化时设置建筑 `Rotation` 并通知统一结构版本、网格和剪影缓存。容器位姿与建筑位置不变；同 tick 后续所有工具读取同一指向和更新后的炮口。输入会话统一挡住 UI、失焦和非当前地图输入；暂停不推进瞄准 tick。
- `ShipPocketMapFactory` 与搬运入口统一接收非负外延，默认每侧 12；EVA 为 0。尺寸、落位根均从同一边界和外延计算。`reserveRotations` 将建筑四种占格并入内容边界，EVA 得到 1×1 飞行图；本轮没有新增多格载具。

实体武器与虚拟挂载通过 `ISpaceWeaponMount` 提供宿主、宿主内稳定身份、挂载偏移与组件集合，均使用 `CompSpaceWeapon`、`SpaceWeaponService`、`SpaceWeaponShot` 和共同后效链。`CompVirtualWeapons` 为每个 Def 槽位创建独立组件集并转发生命周期与 Scribe，挂载不增加碰撞建筑。身份以宿主 ID 与槽位构成，贯穿自动目标、点防、射击上下文、持续束和牵引请求；设置按钮只合并同种槽位，不能把三个工具的组别一起改掉。工具不显示炮手操作，保留战斗面板与各自配置。

参数由 `1.6/Defs/SpaceCombat/DeltaV_Eva.xml` 定义，构建同步至 1.7。EVA 空重 20 kg，耐久 150 HP，货舱可另载 60 kg。装载、起飞和牵引收货共用这一货舱上限。推进和工具无持续资源消耗。

2026-11-04 推进布局改为四角 X 型：船体帧位置为 `(±0.3,±0.3)`，推力沿对角指向中心，各分量绝对值 150（单台模长约 212.13），排气方向向外。两台合力维持前／后／左／右各 300 的最大轴向推力；对角最大合力约 212.13，区别于旧十字布局的约 424.26。每台作用线穿过中心，不产生额外力矩。实体构建、分配、刹车预览和喷焰继续消费共同推进布局，未增加 EVA 专用求解或渲染状态。离线专项读取实际 Def 检查四种建筑朝向、八向出力、反向刹车和停火油门；游戏内喷焰与操控手感待验收。

推进布局验证：1.6／1.7 构建均零警告、零错误；`NpcRetreatRegression -EvaOnly` 149 项及 `EngineeringRegression` 8560 项通过。随后用户确认并授权接入新贴图后一并提交。游戏内显示仍见[美术验收](TODO.md#art-acceptance)。

### 持续战斗机动（2026-11-08）

`CombatReposition` 每个决策周期读取真实相对位置／速度，保留现有最短／最长间隔，不等待上一动作完成。候选包含保持和两个方向的持续切向速度；方位只是有限前瞻的评分／协作位置，不是到达后停车的航点。实际速度差和当前朝向的真实反推能力进入变速／反向成本；随机只在净分相差不超过 0.05 的动作之间选择，反向还须比最佳非反向动作高出 0.05。显式顺／逆方向过滤相反候选。弱动力允许逐轮增加可达速度，不能因一次达不到巡航速度而永远选静止。

`CombatManeuverIntent` 持有距离、持续切向速度、本船相对视线朝向及可选固定方位。`CombatAttackPose` 联合比较八个分布朝向（其中四个对齐所需加速度和主轴）、实际朝向和固定炮提前量；机动评分考虑径向误差、实际径向／切向速度、向心需求与转向时间。射界覆盖仍优先，固定炮和混装保留限制，玩家指定朝向不被主推收益覆盖。只开机动不计攻击收益；允许自动朝向时，持续巡航速度不随瞬时朝向变化反复增减；是否转向由逐炮覆盖与机动净收益比较，不按固定炮数量给整舰硬分类。候选在正式轨迹三秒处使用实际规划位置、速度和朝向复核火力／风险，时间口径与威胁快照一致；不假设加速必然躲弹，不虚构装甲强弱，也不是全局最优搜索。

`CombatFlightPlanner` 将意图转为 `CombatTrajectoryIntent`。参考从真实船心位置、速度、角度和角速度开始，径向和角速度平滑收敛；加速过渡受**当前姿态**的真实推力约束，转船期间不提前借用转过去后的主推能力。预测窗结束仍有途中速度，采样超过窗口也不夹住位置却继续声明非零速度。球面径向基随目标平移输运；角速度由同一视线曲线求导，船心／地图原点共用 `AlignLocalPoint`。路线仍检查四个时刻，自动自由动作最多降速两次；受阻提交从真实动量开始的制动参考。路线检查不是连续碰撞保证，实际碰撞保持原链。

结构、动力、武器配置变化立即刷新相关能力／评分，但不重开决策时钟或随机序列；实际规则／目标变化才替换意图。动力降低会限制新参考的巡航速度，已有 `Flight`、MPC 和真实状态继续存在。运行时意图、轨迹及诊断缓存不序列化。普通航点、保持方位、对接、截击和撤退各自保留原来的终态语义。MPC 的逐步姿态线性化、过程速度与终端代价见[自动驾驶模型](在线MPC自动驾驶.md#模型)。

复现、阶段进度、量化回归和游戏内验收集中在[持续机动重构记录](持续战斗机动重构计划.md)，不把离线无武器夹具当成完整交火验收。

### 战斗策略与执行

- 发射与碰撞系统来源无关：任何容器/派系的武器都能发射弹体，任何弹体都能撞任何
  有碰撞面的容器（同一条链）。
- 当前 dev actions 保留 `Dump universe state`（AI 门禁、目标数、推力和任务状态）与
  弹体池状态查看。战斗验证由真实 NPC AI、`SpaceWeaponService`、shuttle 起飞/侵入和
  `SpaceProjectileService` 链路触发；旧直发弹体、手动齐射和强制 shuttle 侵入动作
  已移除，不能再用绕过武器判定的结果代替正式链路验收。
- `NpcShipAiService` 按设置间隔扫描 NPC 船，逐船记录初始推力、火力、主台与撤退状态；低于初始能力 30% 或主台继任仍触发生存底线，策略条件还可触发撤退和现有跳帮链。归档保存每船观察摘要，恢复重新读取真实图。`CompShipCombatAI` 随当前主驾驶台或 shuttle 艇体 Scribe 保存 `CombatStrategy`；备用台有独立配置。规则分别对机动和逐武器火控首条匹配，末尾内置通用规则；同一战场事实读取真实武器、船体、护盾和推进。机动由首条规则选择持续战法，再交给现有自动驾驶与 MPC；交战姿态选择与持续运动执行分开，具体契约见下。火控逐武器选敌，可同时攻击多个目标，真实发射仍走 `SpaceWeaponService` 的准备与扣费事务；只开火控时不改变驾驶。玩家策略不撤退或跳帮。NPC 仍沿现有资格门禁、返厂和侵入流程。战斗手感、命中率和性能待游戏内验收。
- 自动战斗机动：`CombatTacticSettings` 独立保存距离、本船相对视线朝向、攻击方位及其自由／敌舰／世界参考。指定方位只允许保持射位；自由方位可保持、自动机动或持续绕行。主要武器限定姿态基准，其余武器可独立开火。射程、炮口、机械与实例射界、弹药、供能、固定直射安全路径共同约束，冷却炮保留名义覆盖，真实就绪输出单独评价。当前动作、联合规划与缓存纪律以上面的持续机动契约为准；协作只读同阵营、同目标、正在自动机动且允许协作的船，稳定身份顺序分配另一侧偏好。
- 玩家曲线：六种 x/y 点集保持原保存与编辑契约，距离使用中心距；玩家曲线按原分值相加，上升末段可持续拉远，不设隐藏远距上限。基础覆盖分为名义覆盖火力比例 × 100；自动换位／绕行另加 0～8 分的真实机动能力偏好，未自定义受击曲线时风险为 `-5 × DPS/(1+DPS)`，防止默认无限后退。指定距离优先于距离曲线。只开机动仍使用距离、风险与重叠，但不计输出与固定炮对准；只开火控不提交驾驶轨迹。配置输出曲线时，每门就绪武器仅计一个允许目标，不重复累加多敌；固定炮冷却不撤销朝向约束。编辑器显示规则、选敌与逐炮原因、换位时钟和各曲线分值；示意图左拖距离／攻击方位、右拖朝向，自动值预览当前战术结果，修改仍属于待保存草稿。
- 自动战斗热路径：规则／轨迹及自动火控目标分派通常每 30 tick 更新，完整射位每 120 tick 更新，按船身份错峰；目标、规则、能力、配置、结构变化使相关缓存失效，自动换位到期也立即刷新规则事实、射位与轨迹。同一轮共用 `CombatStrategyFacts`，武器风险摘要由每船 controller 持有并以 30 tick 刷新，部件索引按结构版本重建。每次最多保留最近 64 个敌舰、64 个友方占位／路线对象；每个选中目标最多精查 12 个高价值部件，部件锁 120 tick 重评，炮塔每 tick 提交一次跟踪或开火命令，见[自动炮塔跟踪与开火](#自动炮塔跟踪与开火2026-11-12)。射位几何复用 `SpaceCollision` 船体格数据，路线作 4 个时刻的保守占用检查；自动自由机动受阻最多降速两次，再提交连续制动参考，显式参数不被改写。此检查不是连续扫掠的安全保证，真实碰撞仍由原链决定。`CombatTrajectoryIntent` 从船心参考通过统一刚体变换转换为地图原点参考，`startTick` 固定游戏时间轴；MPC／分配器／积分只有原有一条链。
- 保持行为的性能优化（2026-10-29）：同次火控分派共用敌舰当前位姿；同次射位搜索共用方位、未来中心及同距坐标/速度运输，调用结束即丢弃。基础船心复用 `ShipRegistry` 的既有控制域缓存，不保存动态宇宙位姿。候选、评分、换位时钟和各级更新/失效时机均不变；与提交 `d2587ae` 的逐位行为核对及成本测量见[性能对照](../scripts/CombatManeuverSimulation/README.md#保留行为的性能优化2026-10-29)。

### 战斗规划性能统计

2026-10-29 按用户要求将以下探针永久纳入 `Performance` 分类，沿用五秒窗口及 `detail[avgUs/maxUs/calls/totalMs]`，不依赖 `Development`。均为主线程 CPU；嵌套阶段不能直接求和。

| 字段 | 计时范围与解读 |
| --- | --- |
| `CombatPlan` / `CombatRule` | 完整战术请求（含复用、早退）／实际重新读取事实并匹配规则。 |
| `CombatPose` / `CombatPoseSetup` / `CombatPoseSearch` | 完整射位重算／武器、敌舰风险与友舰快照等准备／`Choose` 搜索。完整重算还包含所选射位的最终风险复核，不含开发日志格式化。 |
| `CombatRisk` / `CombatOutput` | 风险和预计输出回调，嵌套于搜索；风险还包含最终复核，调用次数不是唯一候选数量。 |
| `CombatReposition` / `CombatRoute` / `CombatRouteShape` | 换位更新／路线安全检查／路线检查的船体形状缓存未命中构建。 |
| `CombatTrajectory` | 按射位、实际推力和当前状态生成参考轨迹，包含内部推力预览。 |
| `EngagementObservation` / `EngagementScore` / `EngagementDamage` | 每轮读取武器、外部目标和船体／候选火力与风险估算／单次弹丸只读毁伤查询。毁伤查询嵌套在候选评分。 |
| `EngagementCoverBuild` | 毁伤预测内共享掩码的实际构建。仅记录缓存未命中，命中时没有该计时调用。 |
| `DrivePreviewModel` / `DrivePreviewBraking` / `DrivePreviewAngular` / `DrivePreviewAllocation` | 控制模型（含无加力模型）／反推能力／角加速度／分配器预览。跨战斗、导航与其他调用方汇总，不能全部归因于射位搜索。 |
| `MpcAssemble` / `MpcFeasibility` / `MpcQp` | 有效请求的模型与矩阵构建／实际不可行性预检／实际 QP 求解。被预检拒绝时不计 QP 调用。 |
| `MpcBrakeRecovery` | 恢复制动分支的请求调整、预览、求解或反馈回退，内部可能包含上述 MPC 阶段。 |

`poseReplans` 是窗口内完整射位重算次数。`poseCauses[overlap]` 分别累计 `InitialOrTarget`（无有效战法，含目标变化后的清理）、`Configuration`、`Groups`、`Permission`（火控收益权限）、`Drive`、`Structure`、`Rule`、`Periodic`（射位周期到期）。一次重算可同时命中多个原因，不能相加当作重算总数；结构版本变化是触发事实，不等同于已测得的缓存重建耗时。

`poseWorst` 保留窗口内最慢一次完整射位重算的船身份、`MapTag`、毫秒、触发原因，以及主武器快照数、敌舰数、敌方武器风险快照数和友舰数。它用于将耗时峰值对应到工作量，不保留候选或船对象列表。窗口清零时释放所记 Map；这些数据不入存档。关闭分类时不读新增计时钟、不累计新增统计、不构造输出字符串；启用会增加测量成本，不能把开关日志前后的耗时差解释成优化效果。

现有 `autopilot` 均值仍为 ms/tick，`mpcSolve` 为 ms/求解，新增 detail 则为微秒/调用及窗口总毫秒。结合 `structureChanges`、`poseCauses` 和 `poseWorst` 区分频繁重算、单次搜索昂贵与真正的 QP 热点。统计不改变候选、评分、策略时钟、求解预算或推力。离线等价检查与测试环境限制见[探针验证](../scripts/CombatManeuverSimulation/README.md#战斗性能探针验证2026-10-29)。

`tickWorst` 记录窗口内耗时最长的 Delta-V 游戏 tick，包含实际 tick 编号、总耗时、完成的射位搜索数、已评估候选数及同一 tick 的各阶段毫秒数／调用数。先看 `stages` 的主阶段和剩余的 `otherMs`，再用 `nested` 查评分、毁伤、掩码构建和 MPC 等开销。主阶段的计时涵盖内部子阶段。

`NpcRound` 只计实际执行的 NPC 决策轮次。`npcWorst` 保留窗口内最慢一轮的游戏 tick、配置间隔和总耗时，并标出同轮最慢的有图 NPC 船、`MapTag`、资格状态与船级耗时。`stages` 汇总整轮的资格检查、选敌、撤退评估、战术执行、AI 推力状态日志、归档舰决策和清理。`otherMs` 包含未单独计时的对象枚举、控制器进入及状态收尾等开销。

`nested` 进一步拆出候选构造（`FireControlCandidates`）、撤退基线及其驾驶台扫描（`NpcRetreatBaseline`／`NpcRetreatConsoles`），以及战斗快照的耐久、耐久基线、推力、护盾、武器就绪读取（`CombatFacts*`）。这些耗时和调用数对应整轮。通用 `detail` 还累计玩家等其他入口调用的选敌候选和战斗快照。各阶段可能嵌套。NPC 性能统计随「性能分析」开关启用，独立于 AI 状态日志。

`updateWorst` 记录窗口内耗时最长的 Delta-V `GameComponentUpdate`，包含帧编号、该帧运行的游戏 tick 数及同一次回调内的帧动作、船壳绘制等细项。`frameMax` 仍是 Unity 帧间隔的峰值，两项峰值可能出现在不同帧。正常回调参与采样，测试场景重置期间重新开始统计窗口。

- 返厂目标与有效性统一由 `NpcShipAiService.ResolveRetreatHome` 管理：只选已生成的同派系 `Shipyard`，距离相同按对象 ID 排序；有效目标保持，失效后重选。物化后的船厂以当前船只派系判定，空壳或混合派系不接收返厂；AI 在归档前保存该判定的派系 `npcFaction`，供无图查询。返厂引用随 POI 的稳定对象 ID 解析当前表示，见[星区架构 §4](星区架构.md#4-spaceobject-与物化materialization)。
- 实体受损舰到厂不删除、不治疗；到厂本身不解除撤退，是否继续撤退仍取决于 AI 对当前战损的判断。站位在船厂背离威胁的一侧，半径 = 双方以容器原点计的碰撞包围半径之和 + 20 格；碰撞范围仍由 `SpaceCollision` 同一结构缓存提供。进入该半径外 20 格内即可还击，剩余武器走共同火控，推进器失效不禁止还击。威胁消失保持站位；不追远、不跳帮，守军沿用现有 AI。防守目标和改令时机由 `NpcCombatAi` 持有：无任务、母港变化或目标相对上次下令变化达到 1 格／5° 时调用既有 `ShipAutopilot.TrackTo`。船厂自身移动由原有随动任务处理；自动驾驶接口与制导算法不增加返厂、防守规则。
- 无图路线由 AI 按决策周期更新：无船厂时续设避战临时航点，船厂失效则重选。AI 调用现有 `ShipAutopilot.FlyTo/TrackTo`，无图主体和实体主体进入同一个任务表、`Step`、MPC 制导、`ForceToCommand → Allocate → Integrate`；没有独立归档巡航算法或固定巡航速度。无图导航只接受归档前已独立飞行的单船，不能在无图状态替代分离流程。`ShipPhysics` 不读取目的地或选择航向。跨星区、到达临时航点或旧船厂坐标均不退场；无推力时只有原速度漂移。
- 动力摘要由 `MapSpaceObject.CaptureArchive` 保存逐台推进器位置、方向、有效推力及质量、惯量、质心和驾驶主体帧角；不含真实 Map／Thing 引用、油门、工作区或导航计划。`ArchivedSpaceObject` 用同一分配器执行该数值布局；不近似六个响应、不引入额外预算，也不模拟图内燃料／电力消耗。恢复后释放摘要并读取真实图。统一驾驶契约与全部调用者入口见 [在线 MPC 自动驾驶](在线MPC自动驾驶.md#驾驶契约与调用入口)。
- `UniverseManager` 逐游戏 tick 调度同一自动驾驶、手操及对象漂移接口，对象层保证每 tick 仅积分一次；随后复核普通距离恢复与 AI 到厂判断。归档／恢复在帧边界经 `ReplaceRepresentation` 保持 objectId、绝对位姿与长期事实，递增表示版本且不调用普通注销／新生。导航与对接宿主保留对象 ID，火控及弹体按 §6.2 的船／容器身份解析当前实例；延迟动作校验预期版本。表示切换清掉主体旧任务，正常 AI 周期重新决策。读档同样重建任务，不通过 prefab 重建人员。

- AI 仅在已归档撤退舰距离当前有效船厂 ≤20 格时请求退场：通过 `QueueFrameAction` 去重排队，在帧边界再次校验目标与到达条件，然后调用生命周期的通用 `TryRemoveArchivedContainer`。该入口不识别船厂或撤退策略，只负责玩家接近／已排队恢复优先、原图恢复和安全销图。先用同一 `ArchivedMapStore.TryRestore` 恢复原图，再经 `DeinitMap` 调用原版 `MapDeiniter`，将存活 Pawn 交给 World Pawns，最后清除 pocket parent 和对象。容器内存活乘员先通过原版 `ThingOwner.TryDrop` 放回地图，避免仍被舱体持有而遭后续递归 `Notify_MyMapRemoved` 清理；放出失败保留恢复图、中止退场。该后台结算不切镜头、不安排战斗 tick。人员保留原身份、关系与伤病，后续保存、伤病演变和再次选用均走原版；不模拟维修时长或生成替代舰。
- 归档失败留原图，恢复失败留归档并报错；恢复成功后立即转由恢复图承载事实，后续注册或销图异常不得再次读取旧快照复制船员。玩家追近恢复优先于到厂退场，恢复后发现玩家保护对象则取消退场。完整地图状态、人员交接与外部引用仍须按 §13 的专门场景实测。

## 10. 架构接线与单实现纪律

- **原版复用优先级纪律（2026-09-26 新增）**：**能直接调用原版函数解决的，直接
  调用；能经简单 Prefix/Postfix 解决的，用简单补丁；只有两者都不可行时才允许
  做镜像，且镜像必须收口唯一入口并注明来源与理由。** 应用实例：shuttle 起飞
  校验 = 原版发射校验函数结果直接取用；炮手就位 = 原版 `CompMannable + ManTurret`，
  Delta-V 只适配自瞄、调度和显示／建造策略；护盾容量 = 原版 comp 公共字段直写；伤害应用 =
  `GenExplosion/DamageInfo/TakeDamage` 原版原语；降落冷却 = 原版触发入口（优先
  直接调用/简单 Postfix，施工核对后固定）。
- **实例服务**：`universe.Projectiles`（弹体创建/注册、制导、超时、渲染、图池、
  ResetFlow）与 `universe.Shuttles`（起飞/侵入编排含 弹体角色接管；停靠直接用对接
  计划服务、搬运核心复用 ShipTransitions 的 `TransferDomainToNewPocket`）。均不
  序列化、读档归零。
- **tag 分派改造**：`SpaceObject` 增 tag 字段（枚举含船容器/POI marker/弹体/
  shuttle）；剪影（ShipSilhouette/PlanetGlobeRenderer/WorldShipMarkerRenderer）、
  星区记账（SectorContentService）、被动阻力与积分快路径（ShipPhysics/容器积分
  循环）、显示朝向、碰撞主动参与、**序列化过滤**（写档剔除弹体 tag）一律按 tag
  单点分派——现有各查询点逐一改造，不散写 tag 判断。
- **碰撞核心单实现**：占用集/弧几何、扫掠求交、参与判定、事件构造收口
  `SpaceCollision`（弹丸/激光/侵入/PD 四消费方共用）；相对速度/角度解算经
  `SpaceTransform`。**不得出现第二份求交或第二份己方排除规则**。
- **联合效果注册表单实现**：命中判定与后效的唯一来源；同等耐久舱壁兜底单点；
  「生成弹体」（跳弹/将来自反弹片）出口预留。
- **渲染**：弹体（弹体 building def 图形投影）、激光线段、预瞄与瞄准标记走聚焦帧
  投影 + ShellRenderer 前景层槽位（池化）；在飞 shuttle 走标准非聚焦外壳渲染。
- **Harmony 新增面**：瞄准会话内的左右键让位与瞄准键抑制（被绑定键的原版功能在
  驾驶期让位，**不含空格/暂停**——瞄准模式不占用暂停）；（如核对需要）原版冷却
  触发点。不 patch 原版 verb/射击/拦截代码。
- **按键设置**：瞄准键进 "Delta-V piloting" 分组（默认 B）；**tooltip 文案建议
  玩家不要绑定暂停等关键功能键**（Keyed）。
- **诊断日志**：发射/命中/拦截/跳弹/放行/撞停/弹体角色接管等用户事件级输出（边沿
  触发）；每 tick 碰撞求交热路径不埋点或按 `DeltaVLog.Enabled` + 状态变化。
- **tick 顺序调整随施工同步 [代码入口索引](代码入口索引.md)**（§3.3 新节奏）。

## 12. 新增不变量（定稿候选）

1. 一切模拟（弹体飞行/激光判定/PD 索敌/侵入追踪/碰撞与结算）只认游戏 tick（不变量
   #20 延伸）。
2. **「弹体」「飞船」是抽象角色不是类型**：代码只有容器 + tag + 注册效果；弹体 =
   注册进 objects 的弹体 tag 容器 + 弹体 building；一切行为分派（剪影/星区/阻力/
   显示朝向/碰撞参与/序列化过滤）按 tag 单点。
3. 碰撞是容器级特性、自研单实现核心（宽相位 + 格网步进 + 弧闭式求交，全部经
   SpaceTransform）；不引入物理引擎代理场景；**碰撞主动参与按 tag**（弹体恒为
   主动方，任何有碰撞面的容器都是合法被撞目标）——开放飞船碰撞 = 放开 ship tag
   主动参与 + 注册结构后效（舱壁×舱壁互相毁伤），不改核心。
4. 一切命中先经联合效果注册表的**命中判定**（二值：产生后效/放行），后经**命中
   后效**；跳弹（生成出射角同型弹）、放置（shuttle 进船）、自毁、破片毁伤、护盾
   消耗都是后效种类；无注册对按同等耐久舱壁规则兜底。
5. **结算对称**：碰撞事件对每个参与容器各自派发，各容器用同一 def 对解析并执行
   自己的后效；不存在攻守两套结算逻辑。
6. 命中事件附带几何事实（两侧 building、相对速度标量/矢量、入射角）一次性计算；
   参与方只消费不重算（「注册即唯一」纪律的碰撞版）。
7. 图上应用只用原版公共伤害原语（TakeDamage/GenExplosion/DamageInfo）；不 patch、
   不复刻原版 verb/射击/拦截算法。
8. **原版复用优先级**：直接调用 > 简单 Prefix/Postfix > 镜像（最后手段，须收口
   唯一入口并注明来源）；shuttle 起飞校验 = 原版结果直取是应用实例。
9. **shuttle 与飞船不得有两套逻辑**：起飞/飞行/降落/受击全部同一实现；shuttle
   特有的只有降落后处理（回落建筑 + 原版冷却）与侵入能力（真实推进器截击与共同碰撞）；对接
   计划管线的差异仅限计划脚印来源参数。
10. 护盾容量事实驻留原版 comp（建筑上）；同图战斗 = 原版机制原样；太空弧几何是
    派生缓存，不成为第二事实源。
11. **可拦截性是结构派生**：有图（依托内部建筑存在）∧ tag ∈ {projectile,
    shuttle}；不是 def 标记；有图 ⇔ 可拦截（弹体）；PD 索敌按同一判据；拦截
    shuttle 与拦截导弹同链；**侵入式对接 = 原 shuttle 的真实推进器截击，
    以附加 projectile 角色运行共同碰撞和后效机制**。
12. 可切换炮塔的地面／太空模式互斥：同图 = 原版炮塔 Verb；跨容器 = 本架构；
    两模各走其原有射击链，只共用武器实例的模式事实。
13. **武装开关、火控模式和武器组都是船身份锚的存档事实**；新船默认解除武装并预选自动火控，启用武装后面板显式选择三种模式，B 键仍循环允许模式；手动集火的输入会话
    由玩家船 controller 持有，只有聚焦图所选船接收鼠标，跨聚焦挂起、跨对接换图保持，
    船损毁自动析构。自动战斗机动属于玩家 controller 的运行时自动任务，读档后回到自由漂移。武器组 = 主/副两套 ×
    1–6 组（gizmo 弹出菜单指派套别+组号）；点防和普通武器共用武装、供电与火控来源门禁。
14. 顶部炮塔弹排除己方容器、舰中武器弹包含（可自伤）——唯一开关在武器 comp。
15. 武器组别（套别+组号）、两套激活位、炮手预留、PD 模式和主台火控模式是存档事实；
    弹体、侵入计划、驾驶、瞄准会话、自动战斗机动及图池是运行时数据。
16. shuttle 在飞 = 自管理 MiniShip：无基架/驾驶台/归属、不进 ShipRegistry；停靠后
    回落普通建筑；起飞/停靠经统一搬运核心与对接管线，不自建第二套；装卸复用
    原版。

## 13. 验收场景（施工后游戏内验证）

1. 双船任意位姿/角速度下瞄准模式开火弹道与命中正确；瞄准标记随鼠标、预瞄标记与
   匀速目标实际截击点一致；导弹追踪转弯目标命中。
2. 武装与火控交互：解除武装时请求 Def 待机功耗、不转炮塔、不射击；启用后自动派炮手，面板三个按钮与 B 键切换所选船的自动／手动／停火；驾驶中空格暂停照常；手动会话
   左键射主套、右键射副套，原版点选／命令让位。退出驾驶保留手动模式；切换聚焦时
   会话挂起。同图其他手动船停火，自动船仍索敌。自动战斗机动从自动任务菜单选择；驾驶键接管时暂停，切回自动时重新选敌。
3. 武器组两套：左键只打主套激活组、右键只打副套激活组；关组即停射；启用武装为当前船可用武器上人，
   人手不足时优先激活组；重新分配按最新预留完整重排。无炮手且无自瞄／内置火控的武器负载为零且炮塔不转。
4. 弹道不依赖聚焦：切聚焦不改弹道；未聚焦敌舰被命中，毁伤正确落其图（日志核对
   universe 点与图格互逆一致）。
5. 对称结算：射弹射入船体 → 船侧破片毁伤（命中位爆炸/递减摧毁基架/人员杀伤）与
   弹体自毁同链发生；点防激光打导弹 → 导弹图内 building 被毁 + 射束临时容器自毁；dev 日志
   可见双侧后效。
6. 联合效果两段：射弹+基架概率放行（放行弹继续飞、可再撞内部结构）；激光+基架
   固定伤害；激光+舱壁入射角决定伤害；射弹+高耐久舱壁斜入射走跳弹后效（当前
   默认消灭无伤、出射弹生成出口存在但未启用）。

### 玩家驾驶任务交接（2026-10-26）

玩家每艘船的 controller 仅有手动控制或自动控制。手动模式高亮「正在手动驾驶」，自动模式高亮「自动任务」，「切换手动驾驶」使用普通样式。自动控制一次持有一项任务：自由漂移、速度同步、战斗机动、定点定角驾驶或系统发起的软对接制导。火控与驾驶任务独立。手动接管停止自动出力并暂停任务；切回自动时复核主体及目标，失效则回到自由漂移。战斗机动无有效敌舰时保持任务并显示寻找目标。玩家选择其他任务时替换旧任务；速度同步的计划和稳定计时同时清理。软对接制导在手动接管后暂停，不自动重挂；其配对或目标失效时结束。玩家任务不接管 NPC 决策或侵入弹体制导。定点制导的几何和完成策略详见[在线 MPC 自动驾驶](在线MPC自动驾驶.md)。
# 舱外人员交火与登舰（2026-11-25）

舱外活动资格与真空生存分开判断。每次进入太空时，只要实际穿着至少一件覆盖 `BodyPartGroupDefOf.Torso`、且被原版 `VacuumUtility.IsProtectiveApparel` 认定为防护服装的衣物，就创建一组 800 基础推力的 EVA 四角斜推；同次入场的跳跃背包等 `DefModExtension_PawnSpaceflight` 来源按各自数值额外叠加。多件基础防护服只提供一组基础推力，但任一入场时记录的基础来源仍在即可维持活动。总 `VacuumResistance` 和 `Pawn.HarmedByVacuum` 不参与升格、降格或推进器工作；防护不足的有图人员仍可移动，并由原版真空暴露随时间造成伤害。主动出舱只在点击并成功解析出口后检查这两项：缺少活动来源时提示将保持抽象漂浮，防护不足时提示持续暴露风险，玩家可确认继续。Gizmo 静息枚举不读取装备 Stat 或格网。

有图舱外人员是 `SpaceObjectTag.Personnel` 容器中的临时 `PawnSpaceflightShip`。升格后 `SpaceProjectileService` 为整个有图阶段绑定一条运行时人员弹体代理；它与人员共用同一个 `SpaceObject` 位姿和速度，不另建对象 ID、不序列化、不绘制也不独立积分。人员碰撞视图要求代理仍有效，但把命中伤害转交真实 Pawn 的 `TakeDamage`，因此代理没有第二套 HP，身体部位、护甲、倒地与死亡仍由原版健康系统结算。主武器不再转换成舰载挂载：手动主火调用装备实例的真实 `Verb`，在同调用栈只跳过一格飞行图无法表达的 warmup、射线和本地射程门禁，原 burst、冷却、弹药、燃料、充能及其他原版逐发消费保持。`CurrentTarget` 只使用 Pawn 所在的图内格作为兼容原版与第三方 Verb 后效的合法占位；每次有效手动准星采样都通过船体共同瞄准钩子更新 `PawnSpaceflightShip` 的独立射向，人物四向转身仍唯一归 `ArcadeShipAimHandler`，开火入口不得再次写 `Pawn.Rotation`。原版 `Pawn_RotationTracker.UpdateRotation` 会把无忙碌姿态的征召者强制朝南，因此只在该人员确实持有当前手动瞄准会话时跳过原版更新；失去会话、自动控制、普通地图及其他 Pawn 全部保持原逻辑。每发实际射弹在共同原生接管链登记时取得该射向快照。飞行期间不能换枪；主武器被外部强制移除后不自动换用背包武器。舱外人员永不成为舰载点防、自动选敌或导弹制导的目标；敌舰主攻只认一体式与基架飞船。类别同样只读对象角色，不从对象 ID 或地图形状推断。

原版人物持枪绘制会先从本地 `CurrentTarget` 求角度，再读取虚属性 `Verb.AimAngleOverride`。一格图合法占位与 Pawn 重合，本地向量为零；第三方喷射 Verb 还可能自行覆写该属性。人员桥接因此在启动时枚举基类及全部已加载覆写 getter，以程序集模块和 metadata token 去重后各补丁一次，并只对当前有图人员的真实主武器返回独立保存的宇宙准星方向。弹丸捕获仍读取同一方向，不能为修正外观把 `CurrentTarget` 放回图外。

NewRatkinPlus（`Solaris.RatkinRaceMod`）的 `SYS.DrawEquipment_WeaponBackPatch` 为实现武器背负、刀鞘和四向偏移而全局替换 `PawnRenderUtility.DrawEquipmentAndApparelExtras`：忙碌姿态自行从本地目标求角度，非忙碌姿态还会传入固定的 `143°/217°`，两条分支都可能绕过已经正确返回宇宙射向的 `AimAngleOverride`。合法占位与 Pawn 重合时其忙碌分支得到 `0°`，并在调用最终绘制前按该错误角度向北添加 `0.4` 格前伸量；因此仅修 getter 或最终枪口角度都会留下射击／手持切换时的位置跳动。原版 1.6／1.7 则先应用 `AimAngleOverride`，再按最终角度计算包含 `equippedDistanceOffset` 和年龄系数的前伸位置。

`Patch_PawnSpaceWeapon_DrawEquipmentAiming` 必须保留在最终公共 `PawnRenderUtility.DrawEquipmentAiming` 入口，以最低优先级只修当前有图人员真实主武器的 `aimAngle` 和重合占位的射击前伸方向。位置修正从调用者传入的旧角度减去已添加的 `0.4` 格前伸量，再按保存的宇宙准星角度加回；绘制高度、`littleDown`、其他残余位置、材质、缩放和翻面保持不变。原版路径传入角度已经等于保存射向，位置差自然为零。该修正不引用 SYS 类型，也不是 NewRatkinPlus 专用分支：任何替换上层持枪流程但仍调用公共最终绘制入口的 Mod 都遵循同一契约。已完成的人员瞄准、转向、Verb getter 和最终绘制角临时 Development 探针均已删除。

主火通过 `PawnSpaceWeaponBridge` 消费共同手动齐射意图，抓钩继续作为副组 1 临时挂载进入战斗面板。人员桥只登记来源 Verb、装备和宇宙射向授权；之后与炮塔共用 `SpaceProjectileService.Native` 的 `Launch` 登记、首 tick 接管和命中交回，不再维护人员专属待捕获列表。普通直射、`Verb_Spray` 及不经标准 Shoot Verb 但仍生成真实 `Verse.Projectile` 的来源均可进入该链。第三方 Launch 省略 equipment 参数时，以当前主 Verb 的 `EquipmentSource` 补回来源，显式传入其他装备则拒绝。来源开火抛异常或授权结束仍未产生合法射弹时清理该次状态；捕获失败的本地弹丸不得在一格飞行图继续 tick。守卫盾可截停，单兵射弹明确不满足 `InterceptionEligible`，因此不进入舰载点防。即时 `Beam` 及完全不生成 `Verse.Projectile` 的来源仍不适用于人员原生射弹模式；不支持的主武器每件装备只写一次警告。

聚焦激活是主动切图和读档恢复的共同入口。读档完成并恢复全部人员表示后，下一安全帧对当前地图调用 `ActivateFocusedVessel`；没有运行中自动任务的可驾驶船恢复手动驾驶，武装的 EVA／人员恢复手动火控。该过程不迁移持久字段，只重新应用当前聚焦规则。

手动抓钩按住副火时每 tick 刷新同一牵引连接，松开、停火、换图或表示替换即释放。人员抓钩与 EVA 货运钩索射程统一为 32 格，共用 `TractorLinkService` 的射击门禁、光束表现、目标首交点和 `ShipPhysics.ApplyTractorImpulse`：固定结构只拉动轻型发射者，可动物体两端按质量承受等大反向冲量。手动连接另暴露操作力方向和力矩；飞行辅助只稳定未被抓钩驱动的轴，自动驾驶在连接维持期间保留任务但暂停自身出力，不能以制动抵消抓钩。人员接触后效仍由同一服务处理装包或抱人。月池／舰载坐标收货及舰载手动结构牵引不改用轻型连接。

“登舰”不是独立侧栏流程。`HardDockingService` 统一提供目标器、命令状态、取消和自动驾驶生命周期，再由执行器选择完成策略：跳帮艇关闭规避并以 `SpaceProjectileService` 碰撞完成；人员与 EVA 规避始终开启，以 `NavigateToReference` 到达点击时冻结的目标格心完成。轻型执行器交出真实 32 格钩索挂载，硬对接操作用自己的 token 维持连接；实际射线、工具口、首个船体交点、射程和遮挡继续由 `TractorLinkService` 复核，多个登舰者不争用手动货物目标。远段连接和推进器同时追赶；连接服务按闭合速度及 `DriveInfo.PreviewBraking` 的实际反推能力估计停止距离，进入制动包络后松绳并以迟滞防抖，由自动驾驶反推减速。该操作连接不作为手动操作力暂停自动驾驶。`arrivalGate` 要求本次操作至少成功建立过一次真实连接，但捕获事实由硬对接操作保持；近距束线因松绳或进入开放落点而释放时不会撤销资格，避免穿越参考因错过提交而反复掉头。取消、目标／表示失效或新命令会清除该事实。

`LandingApproachController.ApplyMotionContract` 让同步参考和普通导航读取同一船体契约。普通船保持姿态、角速度和接触点速度匹配；EVA／人员忽略目标朝向及自旋，只匹配冻结落脚点的刚体线速度，因此可以钩住并追随仍在平移或旋转的有动力舰船。共享自动驾驶的普通参考导航保持零终端速度及 `0.15 cells/s` 完成容差；执行器可为到点完成任务分别提供进场目标与完成上限。人员登舰沿目标格方向跟随 `1.5 cells/s` 穿越参考，在实际相对所选刚体落脚点速度低于 `2 cells/s` 时完成，不把该行为扩散到普通飞船。MPC 的逐步／终端速度代价、交会轨迹、制动包络和回退读取同一进场目标，不再只放宽最终布尔门后仍强制刹停。完成时由既有到达提交把对象对齐到同一参考后转移，因此剩余速度不转化为撞击毁伤。人员弹体代理始终只承担受击和普通船体碰撞转接，不因登舰命令武装为主动撞击。人员和 EVA 目标只接受精确月池、开放对接口、无顶甲板或与真空相邻的可通行格；到达后复核同一格并通过共同 Gravship 搬运链放置，不搜索附近替代格、不调用破口后效、不移除墙门或清理结构。出舱 Gizmo 不解析地图结构；月池、对接口、露天及真空边缘只在玩家点击和帧边界执行一次解析／复核。
