# 原版与第三方盾容护盾自动太空战适配计划

状态：2026-11-24，完成现状审计与架构设计，尚未实施。实施前须另交逐文件计划审批。本方案不包含具体 Mod、Def 或第三方类型名特判。

## 1. 目标与明确边界

最终 Def 中使用原版 `CompProjectileInterceptor` 容量契约的建筑护盾，可按玩家的自动适配策略作为 Delta-V 守卫圆盾参与 universe 弹道碰撞。适配只增加太空圆盾碰撞，不接管来源护盾的地面行为、供能、开关、冷却、破盾等待、逐次回充、定时激活、EMP 或显示。

适配护盾不获得 Delta-V 正式守卫盾的额外能力：

- 不参与常规盾容协同，不借用其他发生器容量；
- 不获得常规／应急双容量、白银补充、快速回充或自动重新入池；
- 不获得动能／电磁线盾模式、几何设置、主动脉冲或 Delta-V 功率请求；
- 不使用联合守卫轮廓，继续由来源拦截器决定原有圆盾显示；
- 每次太空命中只扣本机来源盾容，破盾后由来源 Comp 自己决定冷却和回充。

Pawn 身上的拦截器不是飞船刚体外壳，不进入本阶段。没有继承 `CompProjectileInterceptor`、只在第三方私有字段保存容量的系统没有可验证的通用扣容契约；首阶段不反射猜字段，也不做 Mod 专项适配。

## 2. 现状审计与必须修正的问题

当前 `SpaceCollision.RebuildShields` 会把船体结构索引内所有建筑 `CompProjectileInterceptor` 直接登记为圆弧。`SpaceImpactEffects` 对没有 `CompSpaceShield` 的圆盾直接减少 `currentHitPoints`。这使原版或第三方容量盾看似已经能够挡太空弹，但不是完整支持：

1. 直接写容量没有走来源拦截器的命中状态转换；归零时可能没有建立破盾充能起点、冷却或破盾反馈。
2. `hitPointsRestoreInstantlyAfterCharge` 等来源机制可能在下一 tick 立即恢复，绕过声明的 `chargeDurationTicks`。
3. 全部拦截器被无条件纳入，没有按 Mod／单件策略关闭的 Def 注入边界。
4. 碰撞、预测和统计直接依赖 `CompProjectileInterceptor` 与 `CompSpaceShield` 两种具体实现，正式守卫的协同规则混在通用圆盾路径里。

实施时应删除“看到任意 Interceptor 就自动形成太空盾”的隐式资格。只有 Delta-V 正式盾或重启时已注入通用碰撞 Comp 的候选才登记太空盾面。

## 3. 通用碰撞组件

新增正交的 `CompSpaceGuardCollision`（最终名称以实施计划为准），作为 `SpaceCollision`、毁伤预测和战斗保护表唯一识别的圆盾碰撞能力。它不保存第二份盾容，只提供以下契约：

- 读取建筑实例的圆心、半径和当前有效状态；
- 生成与显示共用的圆盾几何快照；
- 返回当前可用容量及用于预测去重的容量银行身份；
- `Absorb(request, context)` 扣除一次实际容量并返回真实吸收量；
- 把实际命中位置、方向和伤害上下文交给容量提供者触发来源命中状态。

正式 `DeltaV_ShieldGenerator` 与 `DeltaV_ShieldGeneratorSmall` 的 Def 都显式安装该组件。自动适配只给获准的来源建筑追加同一个组件和 resolved marker，不替换或克隆其原拦截器。

### 3.1 正式守卫容量提供者

当同一建筑存在 `CompSpaceShield` 时，通用碰撞组件调用现有 `HasGuardCapacity`、`SharedRegularCapacity` 与 `ConsumeGuard`：

- 常规模式仍按本船完整脚印成员等额分摊；
- 余量仍只扣命中发生器的本地应急容量；
- 恢复等待、供电回充、手动／自动应急及联合轮廓保持不变；
- 动能／电磁模式不发布圆盾碰撞面，继续发布现有有限线段。

协同、回充和应急规则仍只属于 `CompSpaceShield`，不得下沉进通用碰撞组件。

### 3.2 来源盾容提供者

当建筑没有 `CompSpaceShield` 时，通用组件委托同建筑唯一的 `CompProjectileInterceptor`：

- 有效状态读取来源实例的 `Active`；
- 半径读取最终实例 Props；
- 最大值和余额读取 `HitPointsMax`／`currentHitPoints`；
- 实际吸收量为请求量与当前余额的较小值，超额预算按现有守卫续穿规则继续；
- 每次实际命中更新来源拦截器的原版命中／冷却状态；
- 余额归零时建立原版破盾充能起点并触发原版破盾状态，之后不再由 Delta-V 增减容量；
- 来源 `CompTick` 或其子类继续按自己的 `chargeDurationTicks`、`rechargeHitPointsIntervalTicks`、瞬间恢复、激活周期、供电和私有状态决定恢复。

不得复制来源冷却或回充计时器。为避免直接写字段造成状态缺口，实施前须根据 1.6／1.7 原版真实 IL 确认命中状态所需字段和私有调用；两版签名不同则使用版本可验证的反射桥，失败时该候选零行为并报告，不得让核心碰撞链异常。

## 4. 候选、策略与注入

在最终 Def 解析阶段扫描 `ThingDef`，候选必须满足：

1. `thingClass` 是 `Building` 或子类；
2. 唯一存在一个 `CompProperties_ProjectileInterceptor` 或其子类；
3. 最终 `radius > 0` 且 `hitPoints > 0`；
4. 没有 Delta-V 正式 `CompSpaceShield` 或已有 resolved marker；
5. Comp 类型仍继承原版容量与 `Active` 契约。

非建筑、零／负半径、无容量、多个容量来源、已有正式能力或显式禁用是硬拒绝。来源子类仍使用继承的公开容量字段和状态，不因程序集名称建立特判。若最终类型无法提供原版容量契约则硬拒绝，不反射猜测私有第三方字段。

“自动适配”页扩展为武器／护盾共同候选目录：Mod 级推荐／全部启用／全部禁用覆盖两类候选，单件覆盖键包含候选类别与 defName，避免同一 Def 同时声明武器与护盾时冲突。设置仍只在重启后的 Def 生成阶段生效；禁用候选下一次启动不注入通用 Comp，不提供虚假的热卸载。

自动适配分析报告中的护盾观察字段是本计划的输入快照，不代表当前已支持。正式实现后再增加配置状态、实际注入状态和硬拒绝／警告字段，并提升报告 schema 版本。

## 5. 碰撞、预测、显示与索引

- `ShipStructure` 分别维护正式 `CompSpaceShield` 列表和通用圆盾碰撞组件列表；前者服务协同与 UI，后者服务 universe 圆盾几何。
- `SpaceCollision.ShieldArc` 引用通用组件，不再引用原版拦截器；求交只读取组件冻结的中心、半径和状态。
- `SpaceImpactEffects.ShieldDrain` 只调用通用组件的 `Absorb`，不再直接写 `currentHitPoints`。
- `CombatProtectionTable`、`CombatDamageForecast` 与武器输出表按通用容量银行身份去重。正式常规协同池仍作为一个共享银行，适配盾各自是本地银行。
- 正式守卫继续由 `GuardShieldRenderer` 绘制联合／应急轮廓；适配盾保持来源 `PostDraw` 与船壳捕获，不加入联合裁剪。
- 盾面命中特效消费同一次碰撞快照；通用组件不得为了显示再次扣容或重算交点。
- 建筑增删、模式、半径、有效状态及容量变化继续通过结构事件或现有 shield 通知失效缓存，不增加逐 tick 扫图。

## 6. 实施阶段

1. **契约与原版状态验证**：为两版原版拦截器建立离线命中夹具，确认部分扣容、归零、冷却、瞬间／渐进恢复、EMP 和定时激活。
2. **正式盾抽取**：给两型 Delta-V 盾安装通用碰撞组件，将 `SpaceCollision` 与后效改读组件，证明正式盾的协同和现有数值完全不变。
3. **候选与设置**：生成护盾候选目录、策略键、resolved marker 和重启注入；扩展自动适配页及分析报告。
4. **预测与显示**：迁移保护表、毁伤预测、战斗快照和船壳捕获，清除具体拦截器依赖。
5. **双版本构建与开发版更新**：运行既有武器、轨道炮、守卫轮廓、预测及新增护盾适配专项，再构建 1.7／1.6 开发版。

## 7. 验收标准

- 禁用 Mod 或单盾并重启后，来源 Def 和实例完全没有 Delta-V 通用碰撞 Comp，太空弹不被其拦截。
- 启用后，来源圆盾半径、开关、破盾容量和可用状态与地面来源实例一致；新建、存读档、搬图和归档不产生第二份容量。
- 部分命中扣正确余额；超额伤害只返回真实剩余预算；归零后严格按来源等待和回充，不获得正式守卫快速回充。
- 多个适配盾不协同、不均摊；多个正式守卫继续协同，混装时二者容量银行互不污染。
- 适配盾没有线盾模式、Delta-V 几何滑条、白银补充或联合轮廓，来源 Gizmo、检查文本与地面拦截保持。
- 预测与实弹在多层正式／适配混合盾上的交点、扣容和续穿顺序一致。
- 生产代码不出现具体 Mod、Def 或第三方类型名；未安装第三方 Mod 时零行为、零错误。
- 1.7 为主要游戏内验收，1.6 复测；代理只负责构建和离线回归，不自动启动游戏。
