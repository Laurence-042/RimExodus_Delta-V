# 对接与舱外作业重构设计

日期：2026-10-21。状态：**整体实现已接线：构建和离线回归通过，待新档游戏内验收**。本轮原版核对、检查结果与待验收边界见 §13。

本文记录本次重构的目标行为、概念边界与交互规则，作为后续施工依据。用户明确提出的规则标为“已定”；为补足执行细节提出的规则标为“建议”；尚不能从需求或源码确定的事项集中列在 §12。建议不等于已获确认，技术验证失败时应反馈具体问题，不能自行换成另一套玩法。

当前实现仍以 [飞船与 SpaceObject 解耦架构](飞船与SpaceObject解耦架构.md)、[星区架构](星区架构.md) 和源码为准；本次目标行为以本文为准。本文落地前，不把旧功能说明改写成已实现的新行为，也不做旧开发存档迁移。

**实施约束：若设计或实现需要新增定期扫图、定期 tick 轮询等周期检查，必须先与用户确认。** 应先复用现有事件、结构版本失效和活动任务的更新入口；不能把“低频”“隔若干 tick”“类似点防”当作新增轮询的默认授权。确认时说明扫描对象、触发条件、频率、预计成本和为何不能用事件替代。本文描述的连续运动、进度和自动回收是行为要求，不代表已批准一种新的周期调度方案。详见 §10.4。

## 1. 要解决的问题

现有常规对接把主动船的控制域搬入目标地图。因此驱逐舰要拼接一架被击毁的战机时，战机地图必须足够大，才能容纳驱逐舰和战机。地图尺寸由潜在来访船决定，导致小船也要长期承担大图的生成、网格和运行成本。

本次改造将三种需要分开处理：

1. 人员、货物往来：通过**软对接**连接入口，两张地图始终独立。
2. 舱外扩建、焊接残骸：先**同步漂移速度**，开始作业时才按实际需要生成共同作业地图。
3. 进入已有的天然地面或维护坞：满足完整容纳条件时**停靠**，主动船进入既有目标地图。

**已定：所有独立飞船，不分玩家或 NPC，都使用紧贴实际船体的小图，并预留 12 格空位。** 舱外作业地图是按需存在的工作空间；小行星、原版 POI 等环境地图保留其自身尺寸。不能把方案改成“玩家永远使用大图，敌舰使用小图”，也不能在靠近目标时临时扩大敌舰图来容纳来船。

## 2. 概念与关系

| 概念 | 含义 | 不意味着什么 |
| --- | --- | --- |
| 飞船 | 有自身身份、结构归属和驾驶能力的 `ShipBase`；基架船与 shuttle 并列 | 不等于一张 Map，也不等于一个 SpaceObject |
| SpaceObject | 一张内部图的宇宙容器，持有唯一宇宙位姿和运动状态 | 不是飞船归属；可以承载多船、残骸或一个散落对象 |
| 小船图 | 独立飞行时容纳当前船体及安全空边的紧凑口袋图 | 不为未来对接对象预留大面积空白 |
| 软对接 | 两个对接口在空间中对齐后形成的、可断开的双向入口关系 | 不合图、不合并电网/房间/结构归属、不建立跨图连续寻路 |
| 速度同步 | 匹配目标线速度并对齐两图网格方向，不约束相对位置或整数格相位 | 到达同步条件不会自行搬图，也不要求双方有对接口 |
| 舱外作业 | 玩家明确开始的共同地图作业阶段，允许扩建、搬运和结构连接 | 不能仅凭地图变大就把两船认作一艘船 |
| 停靠 | 同步后主动船在当前位置完整落入既有目标图的硬对接结果 | 不要求把目标也搬入新图；不允许因空间不足自动换远处落点 |
| 侵入式停靠 | 弹体碰撞后，在撞击位置执行的强制进入目标图 | 不经过普通同步等待，不由自动驾驶判断撞击完成 |
| 散落对象 | 失去承载或被作业船遗留的 Pawn/物品及其无图 SpaceObject | 不是短命弹体，不允许沿用弹体超时消失或写档剔除规则 |

**已定：软对接不发生整船地图转移；速度同步与停靠属于硬对接流程。** 其中“速度同步”是准备动作，“开始舱外作业”是发生地图转移的动作，二者必须在 UI 和状态处理中分开。

地图角色与能力也要分开：目标能接受同步，不代表其内容允许搬运；目标不能搬运，不代表不能停靠。是否允许搬运、是否存在重力影响区域、是否能在某位置接收来船，应分别判定。不能通过地图大小、当前派系、是否有驾驶台或“NPC”标签间接猜测。

## 3. 地图、坐标和运动的共同约束

### 3.1 小图与扩容

**已定：常态小图；作业时按需换入较大图；恢复独立飞行时回到按当前船体计算的小图。** 不在正在运行的 Map 上原地扩缩网格。地图转换仍通过现有生成和搬运管线完成。

**已定：船体包围盒每侧留 12 格。** 一艘宽 W、高 H 的独立船，地图尺寸为 `(W + 24) × (H + 24)`；不能继续被当前 80 格最小边长或测试场景 150 格最小边长覆盖。船体边界包含实际搬运域和完整多格建筑占用，不能只量主驾驶台附近的基架而裁掉伸出的艇体。

**已定：N 是设置中的每侧额外增加格数**，设置说明直接使用“每侧扩建余量”：

- 单船作业：以进入作业前的紧凑地图为基准，`新宽 = 原宽 + 2N`、`新高 = 原高 + 2N`。
- 双方共同作业：在同一网格中，按当前相对位置、四向旋转后的实际内容求联合边界，补足每侧 12 格常态空边，再在每侧增加 N，即联合内容尺寸的长宽各加 `24 + 2N`。必须包括两船之间的间距，不能简单相加船宽或只取较大地图。
- N 为整数，每侧明确增加 N，不再按总量向两侧拆分；默认值、上限待标定。
- 已在作业图中重复点击不再次增加 N；扩建后的船离开作业图时，按新的实际结构重算小图。

**已定：维护坞将使用可建在太空上的航向引导灯等建筑占位，借实际建筑边界保留坞区。** 裁剪/搬运边界正常包含这些实际建筑，不另建“保护空白区域”、坞区掩码或其他防裁剪例外。引导灯的具体设备定义后续再做；哪些空间站可搬运仍由对象能力决定。

### 3.2 网格方向、格位与宇宙位姿

网格方向对齐允许相对角为 `0°、90°、180°、270°`。同步选取指令下达时最接近的四分之一圈方向并锁定：顺时针差 30° 选 0°，差 60° 选 90°；45° 等中点采用确定规则，不在两档间反复切换。目标转动后，选中的相对四向关系继续随目标变化。

**已定：速度同步、普通停靠与侵入停靠共用同一方向吸附函数。** 当前普通对接的 `ShipFlightTransitionService.SnapAngle` 按四分之一圈取整；侵入的 `SpaceShuttleService` 则调用 `ShipOrientation.Rot4FromAngle`，其方向分量阈值并不等价于最近 90°（例如局部 50° 仍可能取 East）。重构应在现有朝向工具中统一角度量化，再复用 `ShipOrientation.PlacementRotation` 计算原版放置旋转，清除分散算法。各调用方先将输入转换到目标地图的同一角度约定：同步输入相对网格角，侵入输入当地实际入射方向；统一算法不等于混用两种输入语义。显示、预览和最终放置也调用同一规则。

这里对齐的是 **Map 网格**；船首方向只是便于玩家理解的参照。主台在地图中的安装朝向可能不同，不能直接比较两艘船的船首角就断定网格已对齐。

搬图时还必须解决**格位相位**：即使两图方向相同，格中心仍可能错开半格。任意连续相对位置不能同时满足“原位完全不动”和“两船都精确落到同一整数格”。**已定：漂移同步不处理位置；同步后点击开始舱外作业，按当前相对偏移取最近整数根格并直接搬图。不显示鬼影、不进入位置调整驾驶、不要求再次点击；本次搬运仅取整一次。** 必须按目标分支复核该落点是否合法，修正不能变成沿地图寻找另一处遥远空地。

共同作业以发起船的网格为新图基准：将本次已确认的整数放置变换求逆，用于放置另一艘船，不重新计算或取整相对位置。停靠则保持目标图不动，沿用原放置变换。

全部转换继续使用 `OrbitSphere`、`SpaceTransform` 和 `ShipPhysics`。新图可选择不同局部原点，但结构在宇宙中的位置、方向应保持连续；切换聚焦仅改变显示参考系。合图前若存在容差内运动残差，也须有唯一收敛规则，不能无说明地丢掉目标速度。

### 3.3 一个容器只有一次运动

软对接期间两图仍各自积分；轻度吸附是朝同一对齐参考的位姿插值修正，不建立第二套运动状态。共同作业或停靠后，所有成员共享宿主的一套刚体运动；各船仍保留身份、派系、归属和设备状态。

**已定**共同作业图以发起作业船的网格方向和刚体运动场为基准；单船扩容继承自身运动；停靠继承宿主运动。原点改变时，线速度必须按新锚位置换算，包含角速度产生的切向速度，不能照抄原容器中心速度。相关残差容差需在验收中测定。

**已定：离开共同图时沿用现有撕裂/解除对接的速度继承。** `SpaceTransform.RigidPointPose` 已统一合成位置、点线速度和角速度，内部通过 `VelocityAtLocalPoint` 处理 `v + ω×r`；本次复用并归一化调用，不新建一套“作业脱离速度”公式或单独积分过程。

## 4. 软对接：两张图之间的入口

### 4.1 玩家如何建立连接

**已定交互：**右下角提供“显示对接提示器”开关。打开后，在各船对接口外侧画出两条末端带菱形的直线，玩家通过双方菱形基本重合来对齐接口。主控船对接口表现通道延长，良好对齐时进度前进，偏离时回缩，完全伸展且双方门可用后，两端成为可用出入口。

提示器要在聚焦地图和非聚焦船壳上使用同一端口几何。两条线表达通道两侧，比较相向端口的左对右、右对左菱形对；两点误差与端口朝向共同判断，避免同向端口或只重合一个点也被判作成功。具体线距、长度、菱形尺寸及通道动画素材属于后续美术契约，不以现有 8 格通道范围自动代替新设计。

**已定：右下角开关同时控制软对接启用与提示器显示。** 只有打开后才允许捕获、吸附和建立软连接；关闭后立即断开已有软连接，取消未提交转移和端口骇入操作，停用软对接计算与叠画。已经完成转移的人/物留在到达图。不能仅隐藏图形却继续后台配对、检查进度，也不能把连接冻结为永久可通行入口；重新打开后按当前状态重新对接。候选来自主控船附近的有效端口，不因“显示所有端口”而自动开启远处 NPC 的软对接任务。具体候选更新调度受 §10.4 约束。

**已定：旧同图气密通道继续在硬对接场景生效。** 软对接不会创建通道 Building 或通道地形，只复用相关贴图渲染伸展/回缩；硬对接后的实际通道仍使用旧的生成、通行和收回逻辑。关闭软对接开关不拆除硬对接的同图通道。

自由飞行的基架船可通过「自动任务 → 软对接」显式选择已加载的目标。确认时以两端口中心的球面弧距选出最近的一对空闲接口，距离相同按端口 ID 排序。已配对、正在执行其他软对接命令或已伸出硬通道的接口不参与选择。取消目标菜单或确认时已无可用接口，保留原自动任务。

一个端口同时只能绑定另一端口。自动制导保留选定接口对，手飞捕获则按菱形误差和稳定身份选取附近端口。不同端口可以建立不同连接。

### 4.2 进度、吸附与断开

| 状态 | 条件和行为 | 离开该状态 |
| --- | --- | --- |
| 未配对 | 端口可用，检测附近相向端口 | 菱形进入捕获范围，固定本次端口对 |
| 对齐但门不可用 | 保持几何配对，不开放传输；可从己方端口发起骇入 | 门可用且伸展完成后建立入口；几何失效则中断操作 |
| 对齐/伸展 | 真实推进器持续保持相对运动与位置，位姿插值辅助菱形重合；进度随误差前进或回退，尚不能跨图 | 进度满且双方门可用后绑定；完全回缩或端口失效则解除配对 |
| 已连接 | 双方门可用，双向入口开放；良好对齐时进度不下降 | 偏离后开始回缩；降至断开阈值以下解除绑定；关闭开关立即断开 |
| 回缩 | 复用同一进度与动画，不瞬间换一套视觉状态 | 重新良好对齐可恢复；低于阈值先禁用入口，再继续回缩 |

**已定：软对接是运动同步加相对位置保持。** 玩家确认目标后，发起船接入现有 MPC，以真实推进器接近指定接口并持续维持指示器左对右、右对左重合所需的位置、方向及运动；旋转目标需匹配接口处刚体点速度，不能只匹配两图中心速度。位姿插值不依赖引擎，只辅助局部菱形重合，不承担主要保持动力。任何一船移动超过保持能力都会使连接回缩、断开，不能补足远距离接近或抵消任意推进器加速。

**已定：优先修正主控船。** 主控船推进器与位姿插值共用一个端口几何参考，避免无意推走目标站；多端口时只选一对主导控制，其他端口仍按自身几何推进伸缩。插值只修正 SpacePose 的球面位置和最短方向角，不累积加速度，不直接移动 Thing/Map 格，也不计作推进器出力；真实推进器仍遵循既有出力和分离门禁。进度和吸附以游戏 tick 为时间依据，暂停冻结；不据此另建定期扫图或轮询器，调度先按 §10.4 核对。

绑定满进度和断开阈值采用滞回，防止边界抖动反复创建/销毁入口。端口被毁、所属地图删除、端口被搬往另一图等身份失效情况立即禁用入口，不等待回缩耗尽。重新连接必须重新取得有效配对。

### 4.3 人员和物品如何通过

**已定：使用巨坑、地下入口一类的跨图转移交互。** Pawn 走到本图入口后，在明确的转移步骤出现在另一图入口；货物通过入口搬运任务送入对面。通道延长是空间中的连接表现，不是一排让 Pawn 从 A 图连续走到 B 图的世界格。

对接口的“组织转移”直接打开原版 `Dialog_EnterPortal`，装载清单、数量扣减、队伍组织、任务分配和转移全部使用原版 `MapPortal → EnterPortalUtility → LordJob_LoadAndEnterPortal → EnterPortal/HaulToPortal`。接口仍是门，操作时在同格绑定一个无绘制、非实体占位的 `SoftDockPortal`，只适配目标图和门内落点；不另写窗口、批次或人员／货物 Job。右键通行与搬运也调用同一原版机制，骇入仍保留远端操作适配。断连、关闭开关或端口搬离时调用原版 `CancelLoad` 并销毁入口；入口禁止随 Gravship 搬运。保存时保留原版任务引用，读档后随软连接关闭，在帧边界取消并移除入口。窗口晚于连接关闭时，仅拦截原版提交以拒绝失效入口。用户已明确允许原版入口装载中的 60 tick 可搬运性检查及原版 WorkGiver/Lord 调度。

因此两图各自保留寻路、房间、温度、真空、电网和工作系统。软对接不会让两图工作台共享自动取料范围，也不会赋予对方船体控制权。端口损坏或对面无法保持位置时不能跳过条件强行建立入口。

**已定：不单独检测敌舰是否失能。** 只要实际保持对齐且门可用，即使敌舰仍有动力也可以软对接。建立传输通道要求对方端口能向本次操作开门；无法开门时，玩家可命令 Pawn 在**己方对接口**操作，使用原版远古防爆门的骇入机制骇入对方端口。完成后自动把该端口占领为操作者派系，无需另点占领，不转移整艘敌舰的归属。完成后仍需满足几何对齐、门可用和伸展进度，不能直接无条件传人。

被占领的端口成为敌舰上的敌对建筑，交由原版敌对建筑索敌/攻击行为处理，不另写“敌人专门破坏软对接”的 AI。敌方可攻击并摧毁该端口，摧毁后连接自然失效。若门因损坏、阻塞等原因在占领后仍无法打开，骇入不能修复这些物理条件。

原版 `JobGiver_ExitMap` 仅在 Pawn 的 AI 要求离图时运行；若当前图不能从边缘离开且是口袋图，它会将第一个可达的 `MapPortal` 作为 `EnterPortal` 目标，不检查入口通向哪张图。软对接连接两张口袋图，失去其他任务的 Humanlike 敌人会在两端重复选中对接口。敌舰船员优先经原有炮手分配接管可用舰炮；未上岗者复用原版 `LordJob_DefendPoint` 守卫当前船图，驾驶台损毁后也保留此职责。`JobGiver_ExitMap` 对软对接入口的过滤仅作防循环兜底；明确下达的入口任务仍按原有连接门禁执行。原版地下仓库的出口通向地表，且其典型威胁是古代机器与虫巢，不能以其行为推断双口袋图敌舰船员的离图行为。

**已定：shuttle 不支持软对接。** shuttle 使用普通停靠或侵入式停靠，船周围每侧 12 格空位用于给这两种落位留空间。

转移提交前必须再次检查当前连接、两端表示版本及到达位置。断开时：

- 尚在走向入口、等待或运货途中的 Pawn 留在当前地图，任务结束或失败。
- 已成功转移的对象留在到达图，不拉回。
- 没有“悬在两图之间”的第三种归属；同一 Pawn/物品在一次提交中只有一个所有者。
- 目标出口堵塞时禁止提交或按已验证的入口邻近落点规则落位；找不到位置就保留原对象，不能宣告搬运成功后丢失货物。

### 4.4 与原版入口机制的衔接边界

已核对本地 1.6 源码：`MapPortal` 提供目标地图/出口与装载列表；`JobDriver_EnterPortal` 先本图寻路、等待，再执行 `DeSpawn/Spawn`；`PortalContainerProxy` 把货物投放到目标图。这证明可复用的是**入口式操作与转移链**，不需要跨图实时寻路。

不能直接把现有对接口改为简单的原版入口子类：现有 `Building_DockingPort` 继承气密门，而 `MapPortal` 直接继承 Building；原版默认路径还会生成自己的口袋图，`PocketMapExit` 绑定的是入口/子图关系。这次必须连接两个已经存在、独立运动的宇宙地图，并保留对接口气密功能，不得重新指定双方地图的 `sourceMap` 来假装地下父子关系。

此外，原版货物代理调用投放后直接返回成功，不能未经验证就用于可能中途断开的连接。施工前先验证门与入口的组合方式，以及断连/堵出口时的无损交接，再定具体实现；本文不把未验证的继承或补丁方案写成既定接口。

原版骇入也已核对：`Building_HackableDoor` 通过 `CompHackable` 判断锁定，完成回调将门归属设为操作者派系；`JobDriver_Hack` 使用 Pawn 的骇入速度、智识学习、原版进度/效果，并要求 Pawn 接触其目标。这里必须适配“本图操作端”和“另一图的骇入目标”：Pawn 寻路、预留和站位在己方端口，骇入事实归对方端口，复用原版进度与完成链，不在两端保存双份进度，也不要求 Pawn 先跨图摸到敌门。关闭开关、失去对齐或任一端口失效时中止操作；已积累进度按原版机制保留，重开后不自动恢复任务。敌对建筑是否被原版 AI 正确选中列入游戏内验收。

## 5. 速度同步：为硬对接准备共同参考系

**已定交互：**玩家足够接近另一艘船、小行星或其他 POI 时，在侧边栏选择目标并点击“同步漂移速度”。自动驾驶匹配线速度，同时把角度调整到最近的网格对齐方向，不追踪下令位置或任何指定落点。准备就绪后才允许“开始舱外作业”。

一次同步命令只固定目标身份和所选四向关系。目标线速度经现有球面平行输运转换到本船位置，不叠加旋转目标的 `ω×offset`；同时匹配目标角速度以维持网格方向。同步不保证绕旋转目标保持相对站位。软对接因额外要求端口相对位置保持，使用宿主刚体点速度；开始作业直接进行最近格位搬运，不另建格位随动阶段。

同步任务复用现有自动驾驶和真实推进器能力，关闭 MPC 位置代价、位置接近约束及位置制动回退，不显示落点幽灵、不启用虚空动力。推进器不足时显示仍在同步/无法稳定，不把“已下达命令”当成已完成。玩家手操可接管，目标失效时结束任务。软对接的带位置控制只由玩家确认目标后启动，漂移同步继续只匹配运动；无动力船可在本来就满足运动条件时被动达到作业条件。

“同步就绪”要求本船有有效的漂移同步计划，且相对线速度、网格方向误差和相对角速度均落入容差并保持设定时长。点击作业按钮时复核同一计划。暂时失配时保留目标，重新累计稳定时长。目标注销、超距、地图卸载或换表示后需重新发起同步。取消同步、切换自动任务和读档后也需重发。手操可以暂停自动驾驶并继续维持同一个有效计划。

## 6. “开始舱外作业”的分流

在发起同步时选择目标，单候选直接开始同步，多候选弹出菜单。“开始舱外作业”只读取本船同步计划锁定的 SpaceObject，并按当前相对位置取最近格。

| 当前情况 | 结果 | 搬运方向 |
| --- | --- | --- |
| 已同步，当前姿态可完整放入所选目标图且放置合法 | 停靠，优先使用已有宿主 | 只把主动船搬入目标图 |
| 同步目标带重力区标签，当前落位不合法 | 提示“区域重力效应明显，无法展开舱外作业” | 保留原图 |
| 有满足条件、允许搬运的目标，双方当前位置可在共同网格合法共存 | 共同作业 | 双方进入按联合边界及 N 计算的新作业图 |
| 有目标但当前重叠非法、空间上限不足或表示正在变化 | 拒绝/等待，说明具体原因 | 不通过改落点或漏搬目标强行完成 |

重力限制由目标持久化的 `GravityRegion` 标签决定。原版及第三方轨道 POI 在现有登记入口赋标，含已纳管的空画布锚。星区小行星带核心和伴生小行星由内容类型配置赋标。普通飞船、残骸、空间站和作业图默认无标。物化、归档恢复和新档存读保留标签。第三方重力区只参与原有生成避让流程。

### 6.1 单船扩建与双船共同作业

“扩建作业区”是独立指令，按设置将本船地图内容搬入每侧增加 N 格的新作业图，无需同步。

**已定：单船扩建和多船共同作业是同一机制。** 都是按规则确定另一张地图，再沿旧对接流程把参与船搬进去；共同作业只是把两船放入同一张新图。此后沿用同图船的撕裂/解除对接，不增加一个必须整体开启、整体结束的船队作业状态机。

作业图朝向采用已经选定的共同网格；所有待搬域以固定四向转换和格根放入。保留当前相对姿态与船间间距，不把目标残骸自动挪到船边，更不能只复制外观。Pawn、物品、建筑内部存储、基架、屋顶和必要引用按真实内容转移。

共同作业的意义是让原版图内建造和寻路可以处理焊接：玩家铺设基架、施工、搬运，并按原有归属规则把残骸纳入本船。**合图不自动合并归属；焊接几何相连也不自动越过主驾驶台认领保护。** 未认领、异主或断连结构离开时仍要分别处理。

目标已经是一张多船图时，不能只搬一个 Ship 就销毁余下地图；必须明确本次搬运域、其他成员和遗留内容。**建议**共同作业以参与 SpaceObject 的完整待保留内容为单位规划，船身份只是域内成员；无法完整表达或不允许搬运的内容使方案不可提交。具体整图内容范围需在搬运前验证，不能用 prefab 重建代替保真转移。

## 7. 停靠与侵入式停靠

### 7.1 普通停靠

**已定：停靠是速度同步的特例。** 本船与目标地图的宇宙投影重合，并能完整放入当前位置时，“开始舱外作业”把本船整体搬入目标既有地图。

典型情况是驱逐舰停在足够大的小行星空地，或战机进入维护船/空间站的维护坞。“完整放入”检查整船实际占用与搬运内容，而非仅船体中心在图内。地图边界、障碍、屋顶/地形和原有基架占用继续走共同合法性检查；普通停靠不借侵入规则拆毁障碍。

宿主地图不扩容、不迁移，宿主宇宙运动继续存在。来船失去独立容器，但保留其 Ship 身份；同图成员共享运动，推进器出力时仍只提取主动离开的船，不能推动整个小行星。维护坞的可放置地形与既有基架是否允许艇体落位必须核对真实规则，不能由“坞”这个名称放行碰撞。

旧的任意选点并自动飞去降落流程不再作为普通硬对接入口：本次落点来自玩家实际停住的位置。若最近整数格落位非法，由玩家重新驾驶/同步；§3.2 的取整只消除不足一格的相位差。

### 7.2 侵入式停靠

**已定：侵入艇在撞击位置直接停靠，跳过普通同步条件。** 制导、命中对象、撞击点和破孔由现有弹体/碰撞/后效链决定，之后复用同一捕获—剥离—放置与收尾过程。

12 格安全空边用于容纳侵入后艇体，包括未来约 10 格长的一体式重战机。此余量不代表任意切角、任意宽度都必定合法：需验证朝向、艇体锚、四向取整和破孔后的完整脚印；不能把越界部分裁掉或移到另一个方便位置。小行星/原版 POI 不因本规则自动扩大，命中靠近其真实边缘时仍要有明确失败处理。

目标不允许整图搬运，不妨碍侵入艇搬入该目标；侵入也不会把目标地图带走。失败不能提前删除艇体或乘员；具体撞毁/停留结果沿用经核对的侵入后效规则，必要时先确认再改。

## 8. 出力脱离与回到独立小图

**已定：复用现有真实推进器出力前门禁，只有出力的船离开；其他船继续留在共同图。** 主推、侧推、姿控、主动刹车和自动驾驶实际出力都触发，不限定按键，也不依赖逆重引擎建筑。A、B、C 共图时 A 出力只摘出 A；B、C 继续作业。只剩 C 时相当于单船扩建，直到 C 也出力才离开最后一艘船。

分离统一语义是“将准备出力的船与其余内容分开”，方向以 [解耦架构 §5.2](飞船与SpaceObject解耦架构.md#52-当前结构的派生判定) 为准。工作图优先提取本船：单船扩建或残骸共同作业后，一次离开即自动回到紧凑图，无需清空剩余基架、保留大图提示或再次作业。普通飞行图战损时若没有其他独立船和天然地面，则主船保留原 Map／容器，断片逐块搬走，无承载人员／物品交给散落服务。

**已定：复用现有一次风险确认。** 干净分离照现有规则执行；涉及断片、通道或遗留人员/物品时，复用原有汇总清单和暂停确认，取消仍按原有逻辑撤销相应驾驶行为。无论风险来自战损还是作业，都不另做一套确认流程，也不新增必须先按的“结束作业”按钮。

执行顺序沿用现有搬运事务：识别离开域及残留 → 必要时一次风险确认 → 把出力船搬入紧凑小图并按旧逻辑处理断片/通道 → 若源作业图已无船，接管剩余散落对象和残骸 → 完成容器、聚焦与引用交接 → 允许新容器继续出力。源图内容交接完成前不得回收。线速度与角速度复用 §3.3 的既有换算，不能先对共同图施力再拆分。

纯惯性漂移、被动阻力和软对接吸附不触发分离。进入作业时应结束旧同步控制任务，防止它下一 tick 修正微小误差就触发脱离；取消驾驶本身不结束作业。

内容处置按实际承载关系，而非派系或距船中心的距离：

| 内容/源图状态 | 处置 |
| --- | --- |
| 离开船控制域及域内真实内容 | 随船进入紧凑小图，包括已正确并入的扩建部分 |
| 源作业图还有其他船 | 其他船和未被本次撕裂逻辑提取的内容继续留在原作业图，不整体拆散 |
| 源作业图已无船，但还有基架/建筑等残骸 | 沿结构分块与残骸搬运逻辑生成紧凑残骸 SpaceObject；承载其上的人员/物品随残骸保留 |
| 无船源作业图中的无承载 Pawn/物品 | 分别进入无图 SpaceObject；不随旧大图删除 |
| 既有小行星、空间站或原版 POI 宿主 | 只提取主动离开船，宿主及留置内容按原有生命周期保留，不套用空作业图收尾 |
| 作业图已完成全部内容交接 | 回收空的扩建地图 |

“无船作业图收尾”由船转移/结构变化触发，并在安全帧边界复核；不通过新增定期扫图来发现最后一艘船已离开。作业中基架被摧毁导致的即时失去承载，独立按 §9.1 处理，不等待最后一艘船出力。

## 9. 散落人员、物品与牵引光束

### 9.1 从失去承载到独立对象

**已定的来源有两类：**作业结束时被遗留的人员/物品，以及基架被摧毁后失去承载的人员/物品。前者发生在作业退出事务中；后者必须接到统一基架毁伤入口，不能等全图只剩最后一块基架才发现。

毁伤本身照常结算伤害，散落流程只接管其后仍存在且失去承载的实际对象，不复活死亡 Pawn 或已被摧毁的物品。建筑崩毁的掉落物、尸体也按实际结果处理；若下方仍有合法天然地面则不算落入太空。普通拆除、起飞剥离不能误触发“被摧毁”的抛散路径。

每个散落对象以原所在格/实际位置计算宇宙锚，继承原容器在该点的线速度及其切向分量；没有明确爆炸冲量时不额外随机抛射。转移过程中原图结构检查和回收必须等待接管完成；失败保留可恢复内容，不能掉回旧的“无承载图连人带物删除”。

**建议**一名 Pawn 或一堆 Item 对应一个无图对象；Pawn 身上的装备、背包、携带物仍由 Pawn 持有，不重复拆成对象。混堆和多 Pawn 同格时分别处理。建筑/基架残片继续用结构容器，继续沿用整域搬运。

### 9.2 无图散落实体与地图容量

每个散落对象通过统一载荷持有一个真实 Pawn 或一堆物品，随存档保存原实例与宇宙位姿。漂浮期间停止实体 tick，宇宙服务继续处理漂移、牵引和远距丢失。超距和离开星区在帧边界按对象身份与表示版本复核并注销。

当前太空地图提供显示参考。散落对象可用场景点选或星图跟随，己方人员也可以从侧栏定位。原版游戏结束及补充流浪者判定纳入符合原资格的漂浮人员。

真实地图继续按面积与到最近玩家飞船的距离评分回收。散落物与导弹不消耗名额。载荷和验收见[无图实体迁移](无图实体迁移实施计划.md)。

### 9.3 牵引光束与月池回收

**已定：牵引光束是只能建在月池上的工程炮塔。** 它找到并锁定散落 SpaceObject 后，把目标拉向自身所在位置；到达后把 Pawn/物品转移到自己船上的月池。一次回收一个目标，成功后再处理下一个。

“到达”采用设备附近的接收范围，不要求与设备中心重合，也不要求先消除相对速度。当前取设备中心 2 格；范围内提交到设备所在月池格，仍复核供电、表示版本、设备位置及实际落点是否可接收。月池拥堵时保留散落内容，不扩大为逐 tick 搜索整片月池。

**已定：默认副4，模式按钮显示“当前模式：收集物品／牵引结构”，使用普通批量设置命令切换，不显示启停勾叉。** 收集物品时，所属武器组启用即按过滤自动收集，禁用就停止，无需切换手动火控；牵引结构只能由手动火控按住对应开火键操作，自动火控不控制结构牵引。 两种模式共用武器组、供电、瞄准和 `Prepare → Launch → Commit`，运动分别使用下述坐标收拢与真实力学；切手动后不接受自动选取。自动模式仅查询散落对象事件索引，无目标保持 30 tick 重试；旧锁失效或被占用时立即重选，不新增周期扫描。

2026-11-01 自动牵引分配：`SpaceScatterService` 的同一请求表持有全局独占权，一台设备最多一个目标，一个散落对象最多一台设备，跨船也不可抢占。瞄准期间刷新占用，但只有本 tick 已付费的请求可以收拢；候选与旧锁均排除其他设备的有效占用，锁定失败改找空闲目标，无空闲目标则等待。断电、禁用组别、模式切换、过滤变化、移图、目标消失及未续接释放占用。有效锁不定时换目标。

## 10. 事务、持久化与已有架构的调整

### 10.1 地图转移是一个整体事务

停靠、单船扩建和共同作业都复用 `CaptureDomain → StripDomain → PlaceIntoMap`；共同作业按旧对接方式把两船放到新地图，外层只协调共同目的图和全部源图的完成收尾，不另写搬运算法。不能逐个调用“单船对接已完成并销源图”，造成第一艘成功后第二艘失败、原图已丢。

准备阶段固定参与者、结构版本、表示版本、待搬域、格根、四向旋转和目标尺寸；预览、合法性复核、完成条件、写回读取同一方案。新图生成成功并复核后才开始破坏性剥离。若生成期间对象运动或结构变化导致方案不再成立，应重新验证/取消，不在提交时暗中改另一套落点。

消费式搬运窗口禁止存档和并发归档；转移故障保留源内容或可恢复的捕获载荷，不能留下半艘船。待所有参与域完成放置、身份重建、内容交接及聚焦切换，再处理空源图。帧边界动作统一走 `QueueFrameAction`，并检查原表示版本。

在把端口所属船搬图前，先禁用受影响的跨图入口并中止未提交转移；合到同图的端口不继续通过旧入口瞬移。第三方软连接是否自动重建暂建议不自动延续，待船落定后按实际端口位置重新对接。

### 10.2 存档事实与运行流程

| 应保存的事实 | 不保存/可重建的流程与缓存 |
| --- | --- |
| SpaceObject 位姿/运动、真实地图内容、船身份与归属 | 自动驾驶同步任务、待执行硬对接方案、确认窗口 |
| 软对接两端接口身份、伸展进度和接通状态；目标端口的原版骇入进度及完成后的派系 | 自动驾驶保持任务、端口候选、提示线网格和端口骇入操作任务 |
| 正在使用的作业地图及区分临时扩建图与长期宿主的必要用途信息 | 根据实际内容可重建的边界、成员表和碰撞数据；不保存一套多人作业会话 |
| 活跃散落 Pawn/物品、其宇宙运动及内容状态 | 牵引中的临时控制请求 |

发起端 `CompSoftDocking` 是软对接唯一状态源，保存对端引用、伸展进度及接通状态；对端 comp 只保留可重建的运行时反向引用。软对接开关按原版 `PlaySettings` 字段同样的 `Scribe_Values.Look` 机制存入 `UniverseManager` 游戏组件；运行时 service 从该字段读取，读档完成后重建端口索引。开启状态读档后保持开启，但不恢复手动驾驶；原配对、地图、主控船及当前距离／角度有效时由 comp 继续推进或收回。主动关闭开关或端口搬离会清空状态，不能把旧进度转给新对端。地图用途信息须足以让新档存读后继续按原有出力分离机制执行，不能因“只剩一艘船”就误认为可带着扩建图自由飞行；不为单船/多船分别保存会话状态。

软连接有效时两端必须可访问，不能让距离归档独立卸掉一端而保留可用入口；应按连接保活或先有序断开。活动散落 Pawn 不因无基架而回收；超出回收范围按 §9.2 的丢失流程处理，不能被普通玩家地图保活／归档分支截留；所有新增运行引用在对象删除、表示替换和换档时清理。

最小验收场景：

- 驱逐舰接近小战机：战机不持有大图；软对接不生成共同图；共同作业只在点击后生成，能将残骸焊接、正确认领并带走。

### 13.2 通用池当前契约

`UniverseManager.MapPool` 按用途 tag 和精确宽高隔离空图，空池最多保留 64 张图；超额仅销毁已确认无内容的资源。申请走原有 `ShipPocketMapFactory.GenerateImmediate` / 增量生成器的同步入口；回调只负责本次业务内容，池不创建或分配 SpaceObject 身份。成功后调用方才发布容器。弹体与散落系统均调用此入口；空闲图复用原有冻结门禁，停止地图更新。

每次租用返回独立租约，旧归还/重置回调不能触碰后来复用同一 Map 的业务；填充回调失败返回失败及可恢复租约，保留已放入内容。归还必须先解除容器持有，再交接或清理业务内容，当前聚焦图不归还；Thing、Pawn（含持有中的 Pawn）、Lord 或非空地形/屋顶均阻止入池。普通归还与重置释放共用内容判据，绝不以“残留就销图”兜底。空图归还时清除预留和气体；调用方新增的地图级业务状态也须在归还前清理，池不冒充任意原版地图状态的自动回滚事务。

地图元数据只保存池用途标记，空闲队列和租约不落档。读档利用原有一次性收尾枚举恢复已标记图；仍被业务容器持有的图继续保留，只有空图进入池。弹体孤儿清理只处理明确的弹体 tag 且仅有弹体内容的地图，不按大小识别。Map 删除通过原有生命周期释放池引用，换档/场景重建按原流程清理。这里的归还时逐格空图校验是显式事件检查，没有新增周期扫描。

方向吸附统一为 `ShipOrientation.Rot4FromAngle` / `SnapAngle`，普通对接和侵入均取最近 90°。45° 平局保留旧普通对接的 `Mathf.Round` 偶数舍入约定；修正原侵入在 45°–60° 区间偏向东西向的问题。放置旋转仍调用原版 Rot4，速度同步也复用此入口。`ShipOriginFromPlacementRoot` 补齐原版整数格锚旋转到连续格心的偏移；`PoseAfterPlacement` 由同一放置结果和 `RigidPointPose` 计算新容器运动状态，避免四向搬运后半格／一格错位。

近距判据统一修正 `OrbitSphere.ArcCells` 为 `atan2(|a×b|, a·b)`，避免 float 点积舍入成 1 后把非零距离误判为零；与自动驾驶的 `Offset` 近距精度一致。星球仪的带锚剪影使用每格 2×2 像素，保留奇数地图中心的半格坐标，避免整像素四舍五入导致相邻格折叠或偏移。两项均不新增游戏状态或调度。生产 DLL 回归包含任意位置同步、MPC／回退的位置无关性、闭环制动不返航、近距精度及四向奇偶尺寸逐格核对；游戏内观感仍待验收。
