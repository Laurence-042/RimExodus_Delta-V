状态：开局、驾驶、硬对接回收、可选武器／护盾试验及赠船已落地，用户已确认 §13.4 的游戏测试通过。2026-11-06 按人工改稿调整文案、合并流程并增加月池温室，详见 §13.5；本批待新档实测。维护设计为理论课，点防、牵引、采矿及惯性耦合器等高级内容不纳入开局。§1～10 及各批记录保留历史语境。

## 1. 内容目标与边界

玩家选好的殖民者正确抵达目标星球，从冷冻休眠中醒来。前辈已经建好空间站，并解释地表的虫族、机械体、侵略性猪人、Horax 邪教与暗黑超凡智能威胁，建议后来者在太空生活。这里仍然需要劳动，殖民者必须学会基于逆重飞船基架的驾驶、维护和设计。

前辈带队进入玩家派系的测试场，演示武器与护盾；随后交付全 RCS 训练船，让玩家硬对接漂浮物、回收指定资源。完成后软对接静止造船厂，参观泊口中装有逆重引擎的飞船。前辈把它送给玩家，并坦白引擎是没人敢坐的原型机；玩家可以一直关着引擎。

首版边界：

- 教程是一个可正常存读档、可退出引导的普通游戏开局，不使用原版强制教程 storyteller，也不全局限制玩家指令。
- 原型机的危险首先是叙事设定，不据此新增随机爆炸、故障、强制点火或必须完成的原版逆重起飞任务。
- 地表威胁通过对白建立背景，不要求同时生成这些派系的地面战斗。
- 每一课验证游戏中的真实结果；点击“明白了”、经过若干秒、镜头看过目标都不能代替操作完成。
- 首版只做这一条固定课程。内容、台词与预制布局可编辑，流程分支直接用 C# 表达，不设计任意条件／动作解释器。

维护与设计按用户最终要求只讲理论，并通过教练机的真实布局在驾驶中体现；当前规则以第 12 节为准。演示武器组合及角色名单在制作内容时确定。

### 2.2 必须带进实现的细节

1. **任务接受不是场景就绪。** `QuestManager.Add` 会调用各 Part 的 `PostQuestAdded`，并可同步 `Initiate` 自动接受任务。任务生成阶段只注册描述、信号与待启动状态；待宇宙和场景角色准备完毕后才开始教学。
2. **对话关闭不代表作答。** `QuestPart_Dialog` 选项发出的新信号不继承输入信号参数；其定位选项还会关闭对话而不发送教学答案。把“等待哪一轮选择”保存在教程状态里，选项信号明确对应课程与选项。关闭、定位、读档后均可重新打开当前讲解，不重复发奖励。
3. **建造信号发生得很早。** `BuiltBuilding` 在施工完成函数前段发送，携带即将销毁的 Frame。先读取其地图、位置、建造 Def 与朝向，再通过 `QueueFrameAction` 于安全时机查询真实建筑和结构状态；不能把 Frame 直接存为完工目标，也不能只看到信号就通过。
4. **普通提示不会强制出现。** `TutorSystem.Notify_Event` 在非 TutorialMode 下并不驱动强制教程；学习提示受玩家设置与知识库影响。主指引必须始终能从任务页／当前讲解入口找到。
5. **原版任务目标参与地图保留。** REF 的 `MapArchive.CanUnloadLosslessly` 检查进行中 Quest 的 `QuestLookTargets`／`QuestSelectTargets`。桥接 Part 暴露当前仍持有必要实体引用的地图目标，复用这一保留机制；课程结束及时释放。它不等同于保证地图持续模拟，演示布置还必须满足现有生命周期的运行条件。

## 3. 玩家流程与完成判据

每阶段提供“当前要做什么、为什么、去哪里、卡住后怎样继续”。教学文本不要暴露服务名、对象 ID 或缓存状态。

| 阶段 | 玩家体验与内容 | 完成判据 | 失败／中断处理 |
| --- | --- | --- | --- |
| 0 苏醒 | 选定殖民者从站内休眠舱醒来；前辈说明抵达、地表威胁与劳动要求 | 初始站与必要设施通过校验；原版出舱完成，开始欢迎对话 | 缺舱、缺生命保障等内容错误明确报错并停止教程启动，不进入半成品课程 |
| 1 认识空间站 | 指认生活区、控制台、课程地点；介绍船体、容器与出入方式的玩家层含义 | 玩家到达指定讲解区域并确认开始课程 | 关闭对白可重开；同图前辈走位用原版 Job，不接管殖民者的日常命令 |
| 2 武器与护盾演示 | 在玩家测试场逐项演示已选武器、护盾模式与后果；先观察，再做少量操作 | 指定装置对指定靶标产生本课所需的真实发射／拦截／盾状态结果；操作题另外验证玩家操作 | 无弹药、缺电、人员或朝向不满足时说明实际原因；提供重新演示入口，不按计时直接跳过 |
| 3 维护与设计 | 驾驶前理论讲解：维护检查、力臂与推进器布局、特殊用途取舍 | 听完讲解确认后进入驾驶；实际侧移由缺少船头 RCS 的教练机体现 | 不要求修理、施工或建造技能；具体布局见第 12 节 |
| 4 接收 RCS 训练船 | 前辈交付全身 RCS 的船；进入驾驶、平移、旋转和减速／同步 | 指定训练船完成操作目标；判据读取真实控制／运动状态，阈值在内容阶段确定 | 不把“打开驾驶面板”当作会驾驶；暂停不推进计时，读档后允许重新接管 |
| 5 硬对接与回收 | 接近指定漂浮物，经已有同步与硬对接／作业入口合图，搬回指定材料 | 指定训练船与指定目标确实完成转移合图；随后指定交付范围内材料种类和数量达标 | 普通停靠与共同作业图路径都能识别；仅接近、仅开对接面板或对接其他对象均不通过 |
| 6 软对接造船厂 | 离开回收现场，飞往线速度和角速度为零的船厂，完成软对接并登站参观 | 指定端口对真正建立连接；需要登站时，再确认相关殖民者经现有入口进入指定参观区 | 距离近或进度条接近完成均不算；断连按现有机制处理，可重试 |
| 7 泊口参观与赠船 | 展示泊口中的逆重引擎船，讲明原型机背景以及可以保持关闭 | 完成参观和交付确认；玩家实际拥有可使用的船，任务正常成功结束 | 不强制点火、起飞或离站；重复对话／读档不得再次生成船或物资 |

阶段 2 的“各种武器和护盾”拆成固定的数个小课，而非一次塞进全部说明。演示矩阵从现有[舰炮与护盾基线](舰炮与护盾基线.md)选取，不在计划中复制数值。每小课写清输入条件、可见结果、成功证据和复演方式。

维护和设计课不要求在玩家刚苏醒、仍有休眠病时限时完成。空间站提供正常生活保障，课程进度不依赖殖民者持续保持征召。

回收首版验证“指定目标的对接已完成，且规定材料进入指定训练船货物范围”，不追踪每单位资源的历史来源。资源堆叠、拆分后仍按普通物资处理；不使用全家园库存作为判据。允许在“检查回收结果”时进行一次有界统计，避免为这一课新建全局库存追踪器。具体交付位置在 prefab 角色契约中固定。

### 4.2 唯一事实与存档

`UniverseManager` Scribe 一份 `TutorialRunState`；运行期服务在新档和读档时绑定这份状态。`ResetRuntimeServices` 重建服务时不能清掉已反序列化的教程事实。

持久事实仅包含课程阶段、已通过的小课、当前等待的选择／演示轮次、任务关联、仍有效的场景角色身份、一次性初始化与交付结果。原版 Quest 继续保存自己的生命周期与 Part 状态，但不再另存一份教程阶段；原版 Part 的启用状态只承担其自身消息、延迟等局部职责。

玩家船按稳定船身份重新解析，不能用出生时的 `SpaceObject` ID 永久指代它。硬对接、共同作业图与再分离会改变容器和 Map；不得用 ownerId 反查容器。实际 Thing／Pawn 引用交给 Scribe，并在地图变更后按既有归属重新解析。未来尚未生成的课程只保存内容标识，不提前持有无效实例引用。

当前课需要的目标通过原版 Quest 目标接口暴露；若仍保留未来设施的直接引用，就必须同时满足其地图保留条件。更优先按课程生成／绑定，完成后释放不再需要的目标引用，避免所有训练图永久常驻。

不存飞控任务、临时落点缓存、帧回调、对话窗口或在途弹体。读档后根据已保存课程重建说明；进行中的飞控遵循现有“保存运动事实、不续接临时计划”规则。在途演示弹体本就不保存，因此允许重新发起未完成的一轮演示，不能推定旧弹体已经命中，也不能重复发放船和补给。

信号使用 Quest 自有命名空间，处理时同时核对当前阶段、演示轮次与实际主体／目标。重复信号、迟到的旧弹体结果和连续点击均不得重复推进或交付。

### 4.3 普通 UI 与前辈

任务页提供始终可见的当前要求和目标定位。当前讲解可由受控入口重开，普通弹窗关闭不会卡死课程。初始说明统一走任务对话，避免再叠一份 `ScenPart_GameStartDialog`。

按钮高亮接入现有 `ShipStatusPanel` 等真实控件的 `UIHighlighter.HighlightOpportunity`；每帧按原版规则声明当前高亮标签，不从屏幕坐标反推建筑或操作目标。跨图聚焦走 `UniverseManager.SetFocusedWithCamera`，不另写镜头参考系。

实体前辈在同图用原版 Goto／Wait 等 Job 完成带路。前辈说话可以走原版带派系信息的对话。跨图旅行复用软对接门户及既有转移流程，不能假设 Follow 会跨图寻路；也不为讲解移动整张地图或强制瞬移玩家队伍。前辈不可用时保留任务说明和重开讲解入口，不让唯一 NPC 的寻路决定全部课程能否继续。

## 5. 场景与玩法接线

### 5.1 开局启动顺序

1. 原版 Scenario 建立 Orbit 层，选择初始轨道地图，保留玩家选人流程。
2. 初始地图按专用 GenStep 顺序生成空间站；内容生成先于 `GenStep_ScenParts` 中的到达组件。复用轨道地图注册与 `MapPrefab.Spawn`，保证依赖宇宙归属的控制台认领发生在所需容器登记之后。首轮实现核实此时 `Map.Parent.Map` 与注册入口确实可用；若不可用，调整同一生成管线的顺序，不用调试场景重置兜底。
3. 到达组件校验休眠舱数量和出生保障，将原版 Pawn 入舱；起始物资安置遵循原版枚举来源。预制舱不得内置另一批殖民者，也不用通用 Pawn marker 代替玩家选人。
4. `Scenario.PostGameStart` 通过原版 `ScenPart_CreateQuest` 创建任务，此时只登记待启动课程。
5. `UniverseManager.StartedNewGame` 完成现有注册与服务初始化后，教程通过 `QueueFrameAction` 在安全时机完成校验、开舱和欢迎流程。回调校验同一局游戏、同一轮初始化与目标有效性；不使用 `ExecuteWhenFinished` 充当通用队列。
6. 后续训练图按章节经 `ShipPocketMapFactory`／现有分帧地图生成服务创建，再注册容器、放置 prefab、绑定实例角色。大图生成、取消和失败清理沿用现有管线。

初始站和静止船厂使用现有轨道 POI／地图治理语义；活动训练船与漂浮物使用合适的宇宙容器。布置距离与位姿从同一真实宇宙锚通过 `OrbitSphere`／`SpaceTransform` 产生一次，渲染和判定读取该结果。船厂的初始线速度与角速度为零；不添加每 tick 强行清零的隐藏制动器。

开发场景代码可作为注册顺序的参考，正式开局不得调用 `ShipTestScene` 的清场或 `BeginSceneReset` 路径。

### 5.2 武器和护盾

演示发射走 `SpaceWeaponService` 的正常控制／发射链，遵守人员、供电、弹药、射界与冷却等条件。结果来自实际弹体碰撞、盾拦截和后效路径；不通过直接扣生命、直接设盾容量、生成假命中来完成教学。

观察通知应放在真正提交发射、真正解决命中／拦截的地方，并传递当前演示需要的主体、目标和结果。不为教程保存第二套弹道，也不把 UI 动画当证据。普通游戏没有活动教程时，观察入口立即返回。

**玩家派系测试场的敌我识别必须单独设计。** 当前 `ShipFireControl` 的自动选敌要求敌对目标；点防同样有目标筛选，不能假定己方炮台会自动打己方靶标。首版可由脚本发起正常的定向射击，但仍需核对各类弹体和护盾的实际过滤。点防示范若需要敌对来袭弹体，优先考虑隔离的无人发射装置并在内容阶段明确其派系；若要求所有装置都属玩家，就需另行确认实例级训练靶许可的方案。不得临时翻转整个玩家派系关系，也不得把“舰船受击过滤”与“弹体互撞过滤”混为一谈。

训练安全依靠射线隔离、靶区布局、人员位置与有限弹药。复演通过正常补给和重启流程处理，不无限刷新玩家已经拿走的资源。具体演示设施规格在 prefab 制作时验收。

### 5.3 硬对接、回收和软对接

硬对接以 [OrbitalWorkService](../Source/Interaction/OrbitalWorkService.cs) 为入口，覆盖两条现有成功路径：泊入合法宿主，以及船与漂浮物进入共同作业图。只有转移完成、归属恢复并通过正常收尾后才报告本课结果。不能只给 `DockingCompletion` 挂通知，也不能只检查某船的 `Docked` 派生状态。

结果需保留此次操作涉及的船身份和指定回收目标，再解析最终地图。旧目标 Map 被释放、船改换容器不算任务目标丢失。材料检查使用约定的训练船货物范围；若使用货柜，同时覆盖当前仓储／封存的真实存储入口，不只数地上物品。

软对接完成读取 `CompSoftDocking` 的实际 `Peer`／`Connected` 关系；登站能力由现有 SoftDockPortals 提供。匹配本课的两端口，避免靠到另一艘船也通过。通过门户后抵达参观区与连接建立是两个不同事件，按本课需求分别记录。

所有跨图转移继续使用 `CaptureDomain → StripDomain → PlaceIntoMap`。教程不新增跨图寻路、独立转移实现或位置近似判断。

### 5.4 赠船

成品船是泊口里的真实结构，有独立控制台与稳定船身份；不能把整座船厂一并认领成礼物。出厂状态包含足够的生活和维护条件，逆重引擎保持关闭，所有权与可操作状态一致。

首版建议从生成时就使用玩家所属的训练／交付船，末尾对白完成叙事交接，不增加“必须说完话才能操作”的第二套权限。若希望交付前属于前辈，则另用现有归属变更入口验证整船转移；不能把 TODO 中尚未实现的控制台骇入占领当成现成能力。

赠船只执行一次。教程结束清理信号、提示、延迟动作和不再需要的目标引用，保留玩家船、人物与正常游戏世界。是否保留 RCS 训练船作为第二艘船，在内容定稿时确定；未经约定不回收或删除它。

## 6. 内容资产与发布契约

布局制作遵循 [delta-v-prefab 技能](../.agents/skills/delta-v-prefab/SKILL.md)与 [Prefab 状态重建](Prefab状态重建.md)。本计划不预先编造建筑尺寸或替代实际布局验收。

首版资产至少包含：出生空间站、武器／护盾训练区域、维护理论讲解、六推进器训练船、资源漂浮物、静止船厂、泊口赠船。可按实际布局合并兼容区域，但不以“一场一图”硬性扩大地图数量。

每份内容契约列出：必须的角色标识、实际 Def、初始派系、供电与弹药、货物与起始物资、可达区域、生命保障、入口与端口、允许的重复实例数量。实例化后校验关键角色唯一且设施可用；`MapPrefab.Spawn` 能对局部 Thing 失败发出警告并继续，因此“Spawn 返回”本身不足以证明教程场景合格。

本地 `Prefabs/` 是被 gitignore 的导出目录，当前发布脚本也不会把它带进包。正式内容存入受版本控制的 `1.6/Prefabs/`，位于 `Defs/` 外；已有 `DeltaV.csproj` 会将非程序集内容复制到 `1.7/`，`build/Release.ps1` 会打包这两个版本目录。

扩展现有 MapPrefab 的路径入口，让正式资源从当前 ModContentPack 的有效版本内容目录加载，继续使用同一 `MapPrefabDocument` 与 Spawn 链。不要另写解析器，也不要依赖“最新导出的文件”。当前 `PrefabDirectory` 写死开发包 ID，而发布脚本会移除 `.dev`；实施时统一从实际拥有内容的 Mod 实例定位，验证开发包和发布包两种路径。

所有角色绑定针对 Spawn 后的新实例建立，不携带源存档的外部 Map、Pawn、任务或缓存引用。初始休眠舱只提供空舱；人物来自本局选人结果。台词、任务描述与提示统一 Keyed，数值与引用放入实际需要的 Def 字段，不为仅出现一次的流程配置万能动作表。
