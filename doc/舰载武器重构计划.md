# 舰载武器尺寸、炮手与备弹重构计划

**状态：讨论稿，2026-09-28。只用于确认需求与施工边界，尚未代表现行实现。**

本文针对现有舰载武器实现与实际需求的偏差，规划一次允许破坏性改写的重构。太空弹道、
容器碰撞、联合命中效果、护盾与瞄准模式继续以 [太空战架构](太空战架构.md) 为权威；
本文只负责武器建筑尺寸、炮手位、备弹、炮塔转向、导弹发射程序、轨道炮构型和第三方兼容接口。方案确认后，应把
最终架构事实并回《太空战架构》并同步 README；本文届时转为施工记录或删除，避免同一事实
长期存在两个权威位置。

本阶段只写计划，不修改代码、Defs、翻译、贴图或测试场景。

## 1. 目标与硬约束

1. 按炮艇/驱逐舰级和巡洋舰级建立小型、大型两套武器脚印。
2. 炮廓和导弹发射架本身就是船体墙体，不再是贴在墙旁的普通炮塔。
3. 非自瞄武器必须由炮手在明确的炮手位操作；自动瞄准插件可以替代炮手。
4. 装弹只要求搬运者能够抵达武器或装弹机任意邻接格，不占用炮手位。
5. 需要实体弹药的武器有本地备弹，发射成功后才消耗；无弹时不发射。
6. 轨道炮装弹机本身是一门完整武器：炮手位、默认弹仓和开火控制均在装弹机；外接
   加速单元只追加出膛速度并可推进出膛位置，没有外接单元也能以基础性能开火。
7. 各能力由正交 Comp 组合；核心射击服务不得按 defName、具体建筑类或轨道炮类型写
   特判。
8. 第三方建筑应能通过 XML Patch 添加 Delta-V Comp 获得太空武器能力，不要求继承
   Delta-V 自定义 Building 子类，也不要求复制本项目的 Def。
9. 保留既有唯一入口：跨容器开火仍由 `SpaceWeaponService.TryFire` 总装，弹体仍由
   `SpaceProjectileService` 发射，坐标仍只走 `SpaceTransform`。
10. 项目未发布，不做当前占位武器 Def 的旧存档迁移；以新档验证。
11. 内置武器默认全部需要真人炮手；自动瞄准是需要额外建筑、供电和资源投入的升级，
    不作为默认配置，以支持乘员多的玩家用人力换取较低建造成本。
12. 可转炮塔必须真实地逐 tick 转向，受到 Def 配置的最大转速和开火对准误差限制；
    “目标进入 360° 射界”不等于炮口已瞬时指向目标。
13. 同图/地表作战是每个武器 Def 可选的正交能力：可以并挂原版武器/炮塔 Comp，也可以
    完全没有；是否支持同图作战不得由 `CompSpaceWeapon` 或武器类别暗中推导。

## 2. 已确认的现状偏差

| 领域 | 当前实现 | 目标 |
|---|---|---|
| 脚印 | 全部武器与轨道部件均为 1×1 | 按小型/大型矩阵使用真实多格脚印 |
| 炮廓 | 1×1 炮塔，PlaceWorker 检查背后有墙 | 武器自身是不可通行、气密、承顶的墙体 |
| 导弹架 | 1×1 全向顶部炮塔 | 固定朝外的墙体炮廓；可并排建造；没有旋转炮塔 |
| 炮手 | `CompMannable` + 原版 `JobDriver_ManTurret` | 独立炮手位与通用操作 Job，不绑定 `Building_TurretGun` |
| 装填 | 仅轨道炮装弹机使用 `CompRefuelable` | 所有需要实体弹药的武器都有本地弹仓 |
| 轨道炮 | 装弹机→1×1 加速段→独立炮口；炮手在炮口 | 装弹机本身可开火；外接单元仅修改加速与出膛位置 |
| 轨道收益 | 每段直接增加伤害/穿深倍率 | 导轨先决定实际出膛速度，毁伤继续按联合效果链读相对速度 |
| 开火实现 | `TryFire` 直接识别 `CompSpaceRailgun` | 服务只消费通用能力接口，不认识具体武器家族 |
| 多格碰撞 | `SpaceStructureRules.ClassifyCell` 只接受 Thing 根格 | 多格建筑的每个占用格都是结构与命中事实 |
| 炮口 | 固定取 `parent.Position + 0.5` | 默认由旋转后脚印求前缘中心；特殊构型可提供炮口 |
| 炮塔转向 | 只判目标是否在射界，炮口瞬时对准 | 独立当前角、目标角和转速；对准后才允许发射 |
| 导弹制导 | 发射 tick 起立即以巡航速度追踪 | 先冷发射，再按弹体程序延时点火并进入追踪 |

原版 `JobDriver_ManTurret` 会把目标强制转换为 `Building_TurretGun`，所以不能作为炮廓、
导弹架和任意第三方 Building 的通用操作实现。原版 `JobDriver_Refuel` 使用
`PathEndMode.Touch`，其“任意邻接格装填”语义可以复用。

## 3. 尺寸与武器族

### 3.1 尺寸约定

尺寸只按需求给出的 `A×B` 脚印原样记录，不再给两个数字附加其他几何名称。落实时，
每个 Def 明确写出朝北状态的 ThingDef `size`、贴图朝向、
炮口偏移、炮手位和挂件连接点；旋转后的实际占地只使用原版
`GenAdj.OccupiedRect`/ThingDef 旋转规则，业务代码不自行交换两个数字。

### 3.2 已确定矩阵

| 武器类别 | 小型：炮艇/驱逐舰级 | 大型：巡洋舰级 | 安装性质 |
|---|---:|---:|---|
| 速射副炮 | 1×1 | 2×2 | 顶部可转炮塔；可切 PD 或按齐射模式开火 |
| 炮廓 | 2×1 | 3×2 | 固定射界、结构墙体 |
| 主炮平台 | 2×2 | 3×3 | 顶部可转炮塔；激光/速射/重炮为不同 Def 变体 |
| 轨道炮单元 | 2×1 | 4×1 | 装弹机或加速单元，按连接点组合 |
| 导弹发射架 | 1×2 | 1×3 | 固定射界、结构墙体、允许并排 |

建议小型/大型不是一个运行时枚举，而是不同 ThingDef 使用相同 Comp 组合。代码只读取
脚印和 Comp 参数，不识别“Small/Large”名称；第三方可定义任意尺寸。

点防御不是 ThingDef 类别，也没有专用 PD 炮：它只是 `CompSpaceWeapon` 的运行时瞄准
模式。速射副炮默认适合承担该任务；切回齐射模式后，同一建筑、弹仓和弹体立即作为
速射副炮使用。射速、射界、弹速等数值决定一门武器是否适合点防，代码不按 Def 身份限制。

### 3.3 墙体武器

小/大型炮廓与导弹发射架应具备：

- `Impassable`、`fillPercent=1`、承顶、阻光、气密；进入房间边界和真空判定。
- 被 `SpaceStructureRules` 识别为实心建筑，外壳显示与碰撞命中一致。
- 自身取代墙，不再要求背后另有墙；删除 `PlaceWorker_SpacesideCasemate` 的旧语义。
- 朝向决定固定武器的炮口方向；炮手位只读 Def 的局部交互格，不推导舰船内外。
- 导弹架与炮廓可左右紧邻；放置校验不得以“附近已有同类武器”为由拒绝并联。
- 放置时检查整个脚印都在同一有效基架归属上；不得只检查根格。

炮廓和导弹架不再为了复用原版炮塔 Job 而伪装成旋转炮塔。它们可以使用普通
`Building`，跨容器射击完全由 Comp 驱动。任一武器是否具备同图战斗能力由其 Def 是否
同时配置原版炮塔/Verb 能力决定；没有这些原版能力的炮廓、轨道炮或其他舰载武器在同图
上不射击。该可选能力不能反向污染固定武器结构或产生第二套跨容器弹道。

## 4. 正交 Comp 架构

### 4.1 组合原则

武器“是什么”不由类继承或 defName 决定，而由以下能力组合决定：

```text
ThingWithComps / Building
├─ CompSpaceWeapon                 必选：武器组、射界、弹体、冷却、默认炮口
├─ CompSpaceWeaponTraverse         可选：炮塔当前朝向、转速和对准门禁
├─ CompSpaceWeaponCrew             可选：存在即需要炮手；保存运行时指定的炮手
├─ CompSpaceWeaponMagazine         可选：武器自身的默认弹仓
├─ CompSpaceWeaponAttachment       挂件公共能力：宿主、启用状态、多选 Gizmo
├─ CompSpaceAutoAimPlugin          挂件：启用时满足无人火控
├─ CompSpaceAmmoAttachment         挂件：额外弹种、独立弹仓、优先级与回退
├─ CompSpaceRailSegment            加速件：只修改出膛速度和出膛位置
└─ 任意第三方 Comp                 可通过公开能力接口参与门禁/修正/开火回调
```

不存在“轨道炮版 TryFire”“导弹架版 TryFire”或按 Def 判断的分支。

### 4.2 `CompSpaceWeapon` 只保留核心射击事实

建议保留或迁入的字段：

- `projectileDef`
- 默认 `fireArcDeg`
- 固定发射轴与目标锁定范围分离；普通直射武器两者可相同，冷发射弹药可以固定轴推出后
  锁定更宽范围内的目标
- `baseSpreadDeg`
- `cooldownTicks`
- `range`
- 顶部/固定安装对己方容器排除规则
- 默认炮口局部偏移；未配置时由旋转后脚印自动求中心或前缘中心
- 既有主/副套、组号和 PD/齐射模式的持久状态
- 挂件连接位置列表；每个位置使用旋转前局部坐标、允许的 ThingDef 列表及能力类别
- 其中加速连接位置明确列出允许的加速件 Def；常规炮塔可声明多个电容位置
- 对可能被自身结构挡住的武器，默认启用发射路径安全限制；是否被玩家临时关闭是武器
  实例的持久状态，不是 Def 变体

不应继续放在核心 Comp 内的事实：弹仓容量、弹药类型、当前炮手、插件启用状态、具体
加速量。`CompSpaceWeaponCrew` 的存在本身就是“需要炮手”的唯一声明；不存在 Crew 即
武器自带基础火控，不再另设一个与 Crew 重复的 `CompSpaceWeaponAutoAim`。

### 4.3 公开能力接口与两阶段开火

`SpaceWeaponService.TryFire` 在一次调用内构建只读 `SpaceWeaponFireContext` 和可修改的
`SpaceWeaponShotSpec`，然后执行固定流水线：

1. 核心武器、组激活、冷却、供电、射界检查。
2. 按 `CompSpaceWeapon` 的连接点收集本建筑与已连接、已启用挂件提供的能力。
3. 解析火控来源和等效技能。
4. 解析目标方向；可转炮塔只写入目标角并由 tick 更新当前角，固定武器继续使用建筑朝向。
5. 解析炮口、当前实际发射方向和轨道炮等射击修正。
6. 选定本发弹仓和弹体程序参数，并冻结在 ShotSpec 中。
7. 逐个调用资源/状态门禁的 `CanFire`，包括对准、自身结构安全和备弹；此阶段不得消费。
8. 调用唯一弹体发射入口。
9. 只有发射成功才调用 `CommitFire`：扣弹、推进同优先级轮转游标、写冷却并触发后效。

建议公开的小接口按职责拆分，而不是一个万能基类：

- 火控提供者：提供等效技能，并可满足 Crew 的炮手门禁。
- 开火门禁：返回可否开火及失败原因，不产生副作用。
- 炮口提供者：返回一次计算好的 Map 连续点/Universe 点。
- 射击修正者：调整出膛速度、散布、运行时伤害参数等。
- 发射提交者：成功后消费弹药或更新局部状态。
- 开火表现：沿用 `IFireEffect`，只做表现或附加效果。

接口由 `SpaceWeaponService` 统一调用。第三方 Comp 只需实现所需接口；Delta-V 不需要知道
它的具体类型。

### 4.4 炮塔转向与同图能力边界

`CompSpaceWeaponTraverse` 只表达“上部炮塔相对建筑底座可旋转”，固定炮廓、轨道炮和
冷发射导弹架不添加它。建议字段和状态为：

- Def：初始局部朝向、左右机械射界、`turnRateDegPerSec`、允许开火的角误差。
- 实例持久状态：当前局部角；目标角与本 tick 是否受控属于可重建运行时状态。
- 每游戏 tick 以角速度上限向目标角逼近；暂停时不转，低帧率不改变游戏 tick 结果。
- 射界检查读取底座朝向，实际炮口方向读取当前炮塔角；只有角误差进入阈值才通过
  `CanFire`。PD 转换目标时同样必须花时间转炮，不能瞬时扫过多个方向。
- 当前角同时驱动旋转炮塔贴图/炮口，显示锚与逻辑发射方向读取同一值；不得只旋转贴图。

同图/地表战斗保留现有“双模可并行”原则，但改为显式逐 Def 选择：

- 有原版 `Building_TurretGun`、Verb 或相关 Comp 的 Def，原版系统继续负责同图索敌、弹体
  和伤害；`CompSpaceWeapon` 只负责跨容器模式，两条弹道不互相代发。
- 没有原版武器能力的 Def 只有太空跨容器战斗；不因为它是“炮塔”就自动获得同图射击。
- `CompSpaceWeaponCrew` 是两种模式共用的开火门禁。同图炮塔无人且无有效自瞄时，原版
  射击也被禁止；炮手到岗后才允许原版炮塔工作。
- 同图射击散布/命中率读取同一个火控解析结果，使真人炮手的 Shooting 技能确实影响
  精度；自瞄插件提供其等效技能。具体接入优先通过 Verb/命中率的窄兼容钩子完成，不复制
  原版索敌或发射实现。
- 双模 Def 的炮塔视觉角应只有一个权威来源。施工时若原版炮塔 top 已提供可复用角度，
  由 Traverse 适配器读取/驱动它；否则由 Traverse 自己持有。禁止同时显示两个不同朝向。
- 同一时刻若两种模式都请求开火，共享 Crew、弹仓和冷却能力按一次射击事务仲裁，不能
  重复扣弹或绕过载人门禁。

### 4.5 第三方最小接入路径

第三方给既有炮塔增加跨容器射击能力时，最小 XML Patch 只添加
`CompProperties_SpaceWeapon` 并配置弹体、射界和炮口。适配规则建议为：

- 既有建筑带 `CompMannable`：通过兼容适配器视作“需要炮手”，但不再调用原版
  `JobDriver_ManTurret`；Delta-V 通用操作 Job 驱动原 Comp 的 `ManForATick`。
- 带 `CompSpaceWeaponCrew`：使用明确配置的炮手位；玩家在游戏中给该 Comp 指定炮手。
- Crew 与原版 Mannable 都没有：视作自带基础火控；等效技能由 `CompSpaceWeapon` 的
  兼容默认值提供。
- 需要弹药：另加 `CompSpaceWeaponMagazine`；不加则不检查或消耗实体弹药。
- 需要自瞄、特殊弹种、额外电容或延长导轨：在武器声明的连接点覆盖建造对应挂件，
  或由第三方 Comp 实现相同公开接口。

这样“只加核心 Comp 即可工作”与“每项高级特性仍是正交 Comp”可以同时成立。

## 5. 炮手位与自动瞄准

### 5.1 炮手位

新增 `CompSpaceWeaponCrew`，其 Def 属性至少包含：

- 旋转前的固定局部炮手位偏移，语义与工作台 interaction cell 相同。
- 操作所需 WorkTag，默认 `Violent`。

“指定炮手”不是 Def 属性，而是建筑生成后由玩家在游戏中选择现有 Pawn 写入
`CompSpaceWeaponCrew` 实例的持久状态；没有 Pawn 时不存在可供预留的对象。该引用随正常
存档保存，Pawn 失效时回退到战斗位置的自动选人规则。

炮手位不根据炮口、墙面、船体中心或“舰内/舰外”动态推导。每个 Def 直接给出一个确定
的局部格，随炮塔放置 Rot4 一起旋转。例如 2×2 炮塔朝北放置时，炮手位固定取其南侧
相邻两格中的西侧一格；炮塔旋转后，该格随建筑一起旋转。预览、可达性、Job 目标和
开火门禁必须读取同一个旋转结果。

它在操作语义上等同工作台交互格，但是否必须空出取决于当前火控：

- 没有已启用的自瞄插件时，炮手位必须可站立且不得新建会阻塞 Pawn 的建筑。
- 已启用的自瞄插件满足 Crew 门禁后，炮手位不再保留，可以建造其他建筑。
- 插件随后禁用、断电、拆除或失效时，不拆除已经建在炮手位上的建筑；武器只是无法
  由炮手操作，直到插件恢复或该格重新可站立。
- 装填仍只要求接触武器或弹仓，不使用炮手位。

由于原版 `ThingDef.hasInteractionCell` 是静态事实，不能表达上述随插件状态变化的占用
规则，Crew Comp 应保存自己的局部偏移。统一的 `SpaceWeaponCrewUtility` 负责旋转后的
炮手格、站立/可达判定和“当前是否需要保留该格”；建造合法性在原版
`GenConstruct.CanPlaceBlueprintAt` 的兼容层中只追加这一项检查，Delta-V 之外零行为。

新增通用 `JobDriver_OperateSpaceWeapon`：

- 目标允许是任意带核心武器/炮手 Comp 的 `ThingWithComps`，不转型
  `Building_TurretGun`。
- Pawn 预约武器并走到精确炮手位，持续向 Crew Comp 报到。
- 战斗位置、手动右键操作和实例上指定炮手均下发同一个 Job。
- 武器 Despawn、炮手位不可达、Pawn 倒地/征召/精神状态不合格时结束。
- 对仅有原版 `CompMannable` 的第三方炮塔，通过适配器调用 `ManForATick`，保持其他
  Mod 读取 `MannedNow` 时仍得到正确结果。

### 5.2 自瞄来源

火控解析只返回“能否射击 + 等效技能”，不直接决定弹药、供电或射界：

1. 已连接、已启用且供电的 `CompSpaceAutoAimPlugin`；它满足 Crew 门禁，因此不需要炮手。
2. 当前炮手的 Shooting 技能。
3. 无 Crew/Mannable 的第三方无人炮塔使用核心 Comp 的兼容默认技能。

默认内置武器全部携带 Crew，必须使用真人炮手；多个可用来源并存取最高技能。炮手的
Shooting 技能经一个统一函数换算为散布/命中修正，跨容器与同图原版武器适配都读取这个
结果。自瞄插件不是自由邻接扫描，而是一个真实挂件：只能覆盖建造
在宿主武器声明的指定连接位置，宿主关系由位置和允许 Def 派生，不保存第二份结构事实。
插件可由自身 Gizmo 临时禁用；禁用后立即不再满足 Crew 门禁，但挂件仍保留并占用该
连接槽。开关使用可合并的同类 `Command_Toggle`，多选多个插件后一次切换，交互与多选电源
开关一致。

自瞄插件状态变化还会使炮手位的动态建造约束失效或恢复；这里只更新合法性查询和武器
可操作状态，不主动取消已有蓝图、拆除建筑或移动 Pawn。

### 5.3 通用覆盖挂件

自瞄插件、附加弹仓以及加速件都是实际 Thing，但允许按宿主声明的连接位置覆盖建造在
炮塔脚印或其指定连接格上。挂件本身不成为第二个 Edifice、不参与房间边界，也不阻塞
宿主；自定义放置检查只占用连接槽。统一规则：

- 宿主的 `CompSpaceWeapon` 声明连接位置及该位置允许的挂件 Def；PlaceWorker 只接受
  精确匹配的宿主、位置和旋转。
- 挂件不得取代宿主，不进入独立武器组；宿主移动、捕获、剥离和重放置时一同搬运。
- 宿主或挂件损毁后，连接关系从 Map 结构重新派生并立即失效，不保存可过期的 host 缓存。
- 可禁用挂件把 `enabled` 作为 Comp 实例持久状态；禁用只屏蔽其能力，不销毁库存。
- 同类挂件的 Gizmo 使用稳定的合并键，必须支持多选批量启用/禁用。

## 6. 备弹与装填

### 6.1 弹仓语义

`CompSpaceWeaponMagazine` 是实体弹药能力，不并入核心武器 Comp：

- 定义允许的现有资源 ThingDef、容量、每发消耗量、对应弹体和自动补充阈值。
- 存档保存当前备弹；显示备弹/容量与缺弹原因。
- 搬运者从地图库存取弹后，以 `PathEndMode.Touch` 到达建筑任意邻接格装填。
- 装填不要求、也不抢占炮手位；炮手可以持续在岗。
- 建筑被摧毁时按明确比例掉落剩余弹药，避免资源静默消失。
- 发射失败不扣弹；弹体成功注册后才在 `CommitFire` 扣除。
- 每个发射建筑使用自己的本地弹仓；相邻同型武器不会自动共享，因此导弹架并联不会
  形成含糊的公共库存。

第一版直接使用钢铁、铀等现有资源作为弹药，不新增“炮弹箱”“舰炮弹”“轨道炮弹丸”
之类的中间物品。优先用 `CompRefuelable` 承担武器默认弹仓的持久计数、自动补充和相邻
装填，`CompSpaceWeaponMagazine` 作为语义适配层；射击服务只看弹仓接口，不直接看
`CompRefuelable`。

附加弹仓是独立挂件 Thing，因此可以持有另一套资源过滤器和弹体配置。例如实弹主炮
自带钢铁弹仓，在指定位置覆盖建造铀弹附加弹仓后：

1. 开火时在所有已启用且有弹的默认/附加弹仓中选择最高优先级；
2. 铀弹仓提供自己的 projectileDef/ShotSpec 修正并消费铀；
3. 铀耗尽或玩家禁用挂件后，自动回退到主炮默认钢铁弹仓；
4. 本次发射一旦选定来源，CanFire、预瞄、Launch、CommitFire 必须使用同一个弹药选择，
   不得在流程中重新选仓。

### 6.2 初始容量建议

容量直接以钢铁、铀等资源数量计；每次发射消耗量也由 XML 配置。下表中的“等效发数”
仅用于确定首轮容量，不引入新的弹药 ThingDef：

| 武器 | 小型备弹 | 大型备弹 | 设计意图 |
|---|---:|---:|---|
| 速射副炮（PD/齐射） | 120 发 | 300 发 | 能承受一轮导弹饱和攻击，但持续作战仍需补给 |
| 炮廓 | 12 发 | 24 发 | 舰侧持续火力，容量高于主炮 |
| 速射主炮 | 24 发 | 48 发 | 主炮级速射武器，补给压力高于副炮 |
| 重炮主炮 | 8 发 | 16 发 | 大弹、低射速，弹仓较小 |
| 导弹发射架 | 4 枚 | 8 枚 | 脚印近似发射管/内部弹仓规模 |
| 轨道炮装弹机 | 6 枚 | 12 枚 | 单发价值高，补给压力明显 |
| 激光/纯能量武器 | 无实体弹药 | 无实体弹药 | 只受供电、冷却或将来的蓄能 Comp 约束 |

这些数值作为首轮游戏内测试基线，不是架构常量；全部放在 XML。

### 6.3 弹药种类与优先级

弹药直接引用任意 ThingDef，代码不枚举 Steel/Uranium：内置默认方案先使用钢铁，铀等
高价值资源由附加弹仓提供更高优先级弹种。第三方 Mod 可以用自己的资源 ThingDef 和
projectileDef 组成新弹仓挂件。激光保持无弹仓示例，用于验证“弹药能力确实可选”。

每个弹仓实例都有可由 Gizmo 调整并存档的整数优先级：默认弹仓初值为 `0`，附加弹仓
初值为 `1`，数值越高越先使用。Gizmo 提供增减和恢复默认值；多选兼容弹仓时可批量调整，
混合值显示为不一致状态而不偷偷覆盖。

选择规则必须确定且可复现：先过滤禁用、无效或不足一次消耗量的弹仓，再取最高优先级；
同优先级候选按宿主/挂件 `thingIDNumber` 排序并轮流发射，而不是永远耗尽最小 ID。每件
武器保存该优先级组最后一次实际消费的 ThingID（对象消失时从有序表下一项继续），只有
成功发射才推进轮转游标。默认弹仓以宿主 ThingID 参与同一规则。

第一轮 Def 采用下列直接资源消耗基线；“容量”即实际存入的资源数量，不另造弹药物品：

| 武器 | 默认资源 | 小型每发 / 容量 | 大型每发 / 容量 |
|---|---|---:|---:|
| 速射副炮（PD/齐射） | Steel | 1 / 120 | 1 / 300 |
| 炮廓 | Steel | 3 / 36（12 发） | 4 / 96（24 发） |
| 速射主炮 | Steel | 2 / 48（24 发） | 3 / 144（48 发） |
| 重炮主炮 | Steel | 8 / 64（8 发） | 12 / 192（16 发） |
| 导弹发射架 | Steel | 15 / 60（4 枚） | 25 / 200（8 枚） |
| 轨道炮装弹机 | Steel | 10 / 60（6 发） | 18 / 216（12 发） |

这些都是 XML 平衡参数，不进入代码常量；实测若单次运输、造价或持续火力不合理，只调
Def 数值，不改变弹仓接口。

## 7. 通用加速件与轨道炮重写

### 7.1 构型

删除独立 `Muzzle` 角色和 `CompSpaceRailLoader`。轨道炮装弹机本身就是一门完整武器，
即使没有任何外接单元，也能依靠内部的一小段导轨以基础速度发射：

```text
[完整装弹机武器] → [可选加速单元] → [可选加速单元] → ...
```

组成。装弹机同时携带：

- `CompSpaceWeapon`
- `CompSpaceWeaponCrew`
- `CompSpaceWeaponMagazine`
- 可选 Power Comp

加速单元只携带 `CompSpaceRailSegment`、挂件公共 Comp 和可选 Power Comp。小型单元
脚印为 2×1，大型为 4×1；代码只使用这两个脚印及其 Rot4 结果。

这套连接机制不是轨道炮私有。任何常规炮塔都可在 `CompSpaceWeapon` 中声明允许的
加速件 Def 和连接位置，例如在炮塔指定位置覆盖建造一个或多个额外电容，提高出膛速度。
轨道炮只是其中一个基础射界为 0、连接点沿炮口方向排列、加速件同时移动出膛位置
的特例。

### 7.2 链解析唯一入口

连接查询从 `CompSpaceWeapon` 声明的每个连接位置出发：

- 连接位置只接受该 Weapon Comp 白名单中的加速件 Def。
- `CompSpaceRailSegment` 只报告自己的加速修正、可选的新出膛位置和下一连接位置；不管
  炮手、弹药、武器组、冷却或命中伤害。
- 普通炮塔旁的电容可以只增加速度而不移动炮口；轨道单元同时把出膛位置推进到自身
  输出端。
- 多个合法连接分支的加速量可以汇总；动态炮口只沿明确声明“移动出膛位置”的连续
  分支推进，不能由遍历顺序决定。
- 连接断裂或没有加速件时回退到完整武器自身的基础速度和基础炮口，仍可开火。
- 查询结果一次返回：实际参与的加速件、最终 Map 炮口点、出膛速度和功耗/门禁摘要。
- 放置预览可提示连接状态，但开火前必须重走同一个主查询；不得另写近似合法性。

当前 `TryGetChain` 的“从炮口逐格反查、遇到装弹机结束”将整体删除。新入口是所有武器
共用的加速件/出膛位置解析，不向射击服务泄露 `CompRefuelable` 或轨道炮具体类型。

### 7.3 连接指示与间隔规划

装弹机和每个轨道单元都必须明确声明“输入连接口、输出连接口、下一合法部件的 root/脚印
位置”。选中建筑、蓝图或 Frame，以及手持相应建造 Designator 时，覆盖层应显示：当前
输出口、下一部件应占的完整脚印、方向箭头，以及已连接/规划中/断开/错位四种状态。
所有标记只调用链解析使用的同一个旋转连接点计算入口，不能另算一份预览坐标。

放置合法性不要求前一个部件已经完工：

- 完工建筑、Blueprint 和 Frame 都可作为规划视图中的连接节点，因此玩家可以一次画完
  整条轨道后让多个建造者并行施工。
- 轨道单元也允许在轴线上间隔放置，中间留着尚未下单或未完工的槽位；其输入/输出箭头
  仍显示，且不会因暂时没有相邻成品而拒绝蓝图。
- PlaceWorker 只检查脚印、旋转、同一 ownerId、连接口网格对齐和允许 Def，不把“已有连续
  成品链”作为建造前提；明显不共线或输出接输入错误仍以红色拒绝。
- 战斗结算只使用从武器出发的连续、完工、有效链。隔空规划的远端单元在中间段完工前
  不提供加速，也不能把炮口瞬移到远端。
- 拆除中间段后远端保留为合法孤立建筑并显示断链提示，重建缺口后自动重新接入。

### 7.4 加速与伤害

已连接并启用的加速件决定实际速度，不直接伪造伤害倍率：

```text
exitSpeed = weaponBaseSpeed + Σ(enabledConnectedAccelerator)
```

- 每个加速件的修正、单武器最大有效数量和可能的收益递减均为 Def 参数。
- `SpaceProjectileService.Launch` 需要接受本次发射的运行时初速度，而不是永远读取
  projectileDef 固定速度。
- 联合命中效果已经持有相对速度，应以实际相对速度计算轨道弹毁伤和穿深；若仍需要
  弹种固有修正，应作为 ShotSpec 参数，而不是再次按导轨数叠乘同一收益。
- 预瞄必须使用同一次链解析得到的速度，显示与真实弹道不得各算一遍。

### 7.5 炮口与装填

- 无加速单元时使用装弹机本身的基础炮口；有移动炮口的连续单元时使用最后一个有效
  单元提供的出膛位置。
- 炮口方向仍由基础武器朝向决定；轨道炮 `fireArcDeg=0`，不增加另一套瞄准规则。
- 炮手始终站在装弹机配置的炮手位。
- 搬运者可从装弹机任意可达邻接格装入钢铁或当前默认资源；加速单元不可装弹。
- 成功发射后由本次预先选定的默认/附加弹仓消费资源。

## 8. 多格建筑必须同步修正的基础设施

本次不能只改 XML size，否则外观、碰撞和所有权会互相矛盾。

### 8.1 结构分类与碰撞

`SpaceStructureRules.ClassifyCell` 当前要求 `thing.Position == cell`，会漏掉多格建筑的
非根格。应改为：ThingGrid 在该格登记的实心 Building，其整个 `OccupiedRect` 中每格
都算同一个结构建筑；命中事件仍携带同一 Building 引用。

同步验证：

- 外壳代理画出完整脚印；
- 宇宙弹体命中任一占用格都命中建筑；
- 点击拾取与遮挡排序不只命中根格；
- 建筑摧毁后全部占用格缓存失效。

### 8.2 归属与建造

武器所属船不能只读 `parent.Position`：整个脚印必须全部位于相同的正 ownerId 基架上。
提供一个唯一的“建筑脚印归属”查询；核心武器、插件邻接、轨道链接与 PlaceWorker 共用。
脚印跨多个归属或含无基架格时视为无效，不参与组激活和射击。

### 8.3 炮口、射界和局部偏移

新增统一几何入口，负责：

- 旋转脚印中心；
- 前缘/后缘中央；
- 默认炮口与 Def 显式炮口偏移；
- 轨道链覆盖的动态炮口。

任何调用方不得再自行使用 `parent.Position + 0.5` 拼炮口。

Crew 的固定交互格不属于炮口几何；它只经 `SpaceWeaponCrewUtility` 计算，避免把操作位与
发射方向重新耦合。

### 8.4 自身结构发射安全

炮廓等发射路径可能穿过己方舱壁的武器默认启用安全限制。开火前，从本次已冻结的炮口和
实际发射方向，使用 `SpaceCollision`/结构分类同源的己方占用格查询，检查弹体离开发射
容器前的扫掠段；若第一段会命中本船实心结构，则拒绝发射并给出“发射路径被己方结构
阻挡”的原因。不能用“炮口前一格是否为空”这种多格弹体和斜射下不可靠的近似检查。

武器提供可合并的“发射路径安全”Gizmo，默认开启并随实例存档；玩家可在多选后统一关闭
或开启。关闭只跳过这道预检，不给予穿墙或己方免伤：实际弹体仍走统一碰撞链，因此紧急
发射若撞上己方舱壁会正常造成伤害。顶部炮塔正常情况下不会触发该问题，但仍复用同一
能力开关，不建立炮廓特判。首轮炮廓射界定为：小型以底座朝向为中心 `60°`，大型
`45°`；这是 XML 参数，可按实测调整。

## 9. 导弹冷发射与弹药程序

### 9.1 两阶段导弹

导弹发射架自身固定 `fireArcDeg=0`，不旋转追踪目标。这里的 `0` 表示实际推出方向只能是
架体轴线，不表示只能锁定恰好位于轴线上的目标；目标锁定范围是单独的 Def 参数，内置
导弹首轮允许锁定全向目标。发射时只负责把导弹从发射口沿架体朝向推出并赋予初始冷发射
速度；导弹在可配置的延迟后点火，才开始按自身转向率和巡航速度追踪已锁定目标。冷发射
期间仍是正常 SpaceProjectile：会移动、可被拦截、会碰撞，不能穿过己方结构或暂停计时。

点火延迟以本发冻结参数 `ignitionDelayTicks` 表达。弹体 Def 给出默认值及允许范围，导弹
发射架/所选弹仓可提供编程值；发射架 Gizmo 调整的是后续发射的程序，不回写已经在飞的
导弹。默认内置值在施工时以能够明显离开发射架、又不会让近距离射击完全失效为基线，
首轮建议 30 ticks（0.5 游戏秒），之后游戏内实测。

### 9.2 通用弹药程序框架

“延时点火”不写成导弹架特判。弹体/弹药 Def 可选声明一个发射程序能力，定义可编程参数、
默认值、上下限和飞行阶段；武器与弹仓只向 ShotSpec 写本 Def 允许的参数。第一版内置阶段：

```text
ColdLaunch(initialSpeed, duration)
→ PoweredGuidance(cruiseSpeed, turnRate, lockedTarget)
```

- 没有程序能力的直射弹、激光和普通弹药完全维持现有路径。
- 程序能力跟随最终选中的 projectile/ammunition Def；换用附加弹仓后，UI 和合法参数也随
  本次弹种改变，宿主武器不按“是不是导弹”硬编码。
- `SpaceProjectileService.Launch` 把冻结的程序和阶段状态写入在飞弹体；其 tick 只执行该
  程序，不回读发射架当前设置。
- 目标锁定仍由统一武器瞄准解析完成；冷发射阶段保留锁定目标但不转向，点火时若目标已
  失效，则按弹体 Def 的失败策略继续直飞或自毁，首轮内置导弹采用继续直飞。
- `launchArc`/实际推出方向属于武器几何，`lockArc` 属于弹药程序允许的目标获取范围；
  直射弹默认令两者相同，避免为导弹特例改写通用射界检查。
- 接口应允许第三方以后增加定时引信、分段推力、延迟制导等程序，但本轮只实现冷发射→
  追踪，不预建脚本语言或任意回调执行器。

## 10. Def 重建建议

现有武器 Def 仍是占位原型，建议直接重建而不是逐个打补丁：

| 新 Def 族 | Comp 组合 |
|---|---|
| 小/大型速射副炮 | Weapon + Traverse + Crew + Magazine + Power；可切 PD 或齐射 |
| 小/大型炮廓 | Weapon + Crew + Magazine + Power；气密墙体、固定射界 |
| 小/大型激光主炮 | Weapon + Traverse + Crew + Power；顶部炮塔、无实体弹仓 |
| 小/大型速射主炮 | Weapon + Traverse + Crew + Magazine + Power；顶部炮塔 |
| 小/大型重炮主炮 | Weapon + Traverse + Crew + Magazine + Power；顶部炮塔 |

| 自瞄插件 I/II | Attachment + AimProvider + Power + 批量开关 |
| 铀弹等附加弹仓 | Attachment + AmmoProvider + 批量开关 |

旧 `DeltaV_Weapon_RailgunMuzzle` 删除；旧 Def 名是否复用不重要，因为项目不承担旧开发
存档兼容。建议保留尽量稳定、语义正确的通用 Def 名，减少 Debug/TestScene 改动噪声。

美术工作必须在尺寸、朝北方向、炮口和炮手位最终确认后进行。单向俯视贴图使用

## 12. 验收清单

### 12.1 尺寸与结构

- 所有武器旋转四向后脚印正确，尺寸二元组没有被业务代码重新解释或交换。
- 炮廓和导弹架自身构成气密房间边界，可承顶；摧毁后对应区域暴露真空。
- 两个导弹架可沿墙并排，不共享弹仓、不互相阻塞合法炮口。
- 多格武器任意占用格可被炮弹命中、选取并画入非聚焦外壳。

### 12.2 炮手与同图战斗

- 每类武器的炮手准确走到 Def 配置的固定格；四向旋转后与建筑保持同一局部关系。
- 2×2 朝北炮塔使用南侧两格中的西侧格，其他 Rot4 结果由同一偏移旋转得到。
- 无自瞄、无人操作时不能发射；炮手到位后可以。
- 自动瞄准插件生效时无人也可发射；禁用、断电、拆除或宿主关系变化后立即失效。
- 自瞄生效时可在炮手位建造；插件失效时保留已有建筑，但炮手不能操作该武器。
- 炮手与自动插件并存时取更高技能。
- 指定炮手只能在建筑实例生成后从现有 Pawn 中选择，并随存档保存。
- 起飞、对接、分离重放置后，战斗位置事件能重新分配炮手。
- 第三方普通 Building + 核心/Crew Comp 可以工作；第三方原版 Mannable 炮塔也可以。
- 内置顶部速射副炮和三类主炮落回普通地图后可使用原版同图炮塔能力；炮廓、导弹架和
  轨道炮首轮没有原版同图武器 Comp，因此不会自动攻击同图目标。
- 同图炮塔无人且无自瞄时不搜索/发射；炮手到岗后恢复，Shooting 技能变化会反映到精度。
- 太空目标换向后，炮塔按转速逐 tick 追角，未进入误差阈值前不发射；贴图、炮口与逻辑角一致。
- PD 连续切换两侧目标时不能瞬时掉头；存读档后当前炮塔角保持，暂停时角度不变化。

### 12.3 装填与备弹

- 搬运者能从任意可达邻接格装填，不必站炮手位。
- 炮手在岗时仍可由另一 Pawn 装填。
- 无弹不发射；发射服务拒绝后不扣弹；成功注册弹体后恰好扣一次。
- 并联导弹架分别显示与消耗自己的备弹。
- 铀弹附加弹仓启用且有货时优先使用铀；耗尽或禁用后回退默认钢铁弹仓。
- 自瞄插件和附加弹仓均可多选后一次启用/禁用。
- 搬运、禁用自动补给、目标库存、摧毁掉落、挂件禁用和存读档后数量均正确。
- 默认弹仓优先级为 0，附加弹仓为 1；调高、调低和多选批量修改均随存档保存。
- 两个同优先级有弹弹仓按 ThingID 有序轮流消费；失败发射不推进轮转游标。

### 12.4 轨道炮

- 装弹机使用 Def 指定的固定炮手位，装填仍可从任意合法邻接格进行。
- 0、1、2、N 个加速单元均可开火，弹速可预测且单调增加；0 个时使用武器基础性能。
- 非法、错位、跨归属或断电挂件不提供修正，但不破坏完整基础武器的开火能力。
- 弹丸从最后一个有效移动炮口单元的输出位置出现；无单元时从基础炮口出现。
- 预瞄使用同一弹速；命中毁伤读取实际相对速度。
- 拆掉中间单元后，解析在同一 tick 回退到仍连通的单元或基础炮口，不读旧缓存。
- 装弹机、轨道成品、Blueprint 和 Frame 都显示准确的下一部件脚印与方向指示。
- 玩家可以先放第一、第三、第五段再补中间蓝图；远端施工可并行，但断链部分不提供收益。
- 补齐中间段后无需重建远端单元即可自动连通；四向旋转的标记与实际连接格完全一致。

### 12.5 导弹与自身结构安全

- 导弹以发射架朝向和冷发射初速离架，配置的 tick 数到达前不追踪，到达后才点火转向。
- 修改发射架点火延迟只影响后续发射；已在飞导弹保持发射时冻结的程序。
- 冷发射期间暂停会冻结计时和运动，仍可被 PD 拦截并会与结构正常碰撞。
- 换用提供另一 projectileDef 的附加弹仓后，程序 UI、默认值和合法范围来自新弹体 Def。
- 默认安全开启时，预测会撞己方舱壁的炮廓拒绝发射并给出原因。
- 多选武器可以统一关闭安全；关闭后同一射击真实命中己方舱壁并正常结算伤害，不穿墙。

### 12.6 正交性回归

- 无 Magazine 的激光武器不被错误判定缺弹。
- 无 Crew/Mannable 的第三方自瞄炮只加核心 Comp 即可开火。
- 给普通炮塔加 Magazine 不会自动改变炮手逻辑。
- Crew 存在时必须由炮手或启用的自瞄插件满足，不存在重复的 AutoAim 内置 Comp。
- 给武器加第三方门禁/ShotModifier Comp，无需修改 `SpaceWeaponService`。
- 同一速射副炮可在 PD/齐射间切换；不存在硬编码的“PD 武器种类”。
- 导弹、直射弹、激光仍只走统一 Projectile/Collision/Impact 链。
- 给第三方武器只加 Traverse 会获得受限转向但不会自动获得同图 Verb、Crew 或 Magazine。
- 没有发射程序的弹体不产生阶段状态；有程序的第三方弹体无需修改 WeaponService 类型分支。

## 13. 已定首轮默认值与实测调参项

下列交互已经定案，首轮数值作为 XML 基线；它们不构成代码常量，游戏内实测后可调整：

1. **同图战斗**：顶部速射副炮、激光/速射/重炮主炮提供原版同图能力；炮廓、导弹架和
   轨道炮首轮只做跨容器战斗。两种模式均受同一 Crew、技能、弹仓和冷却事务约束。
2. **炮塔转速**：小型速射副炮 `180°/s`、大型速射副炮 `90°/s`、小型主炮 `60°/s`、
   大型主炮 `30°/s`；开火误差分别先用 `4°/3°/2°/1.5°`。PD 也不绕过转速。
3. **导弹架**：发射轴固定 `0°`、锁定范围首轮 `360°`，冷发射点火延迟默认 30 ticks；
   冷发射初速先用巡航速度的 25%，具体数值随弹体 Def 配置。
4. **炮廓射界**：小型 `60°`、大型 `45°`，默认开启自身结构安全检查。
5. **默认载人**：全部内置舰载武器带 Crew，覆盖安装自瞄插件后才能无人化。
6. **备弹**：使用 §6.2 等效发数与 §6.3 单发资源消耗作为首轮基线。
7. **弹仓优先级**：默认仓为 0、附加仓为 1，数值越高越优先；同优先级按 ThingID
   有序轮流消费。
