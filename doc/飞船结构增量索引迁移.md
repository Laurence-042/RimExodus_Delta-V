## 运行时契约

### 实例、归属和查询

每艘实体飞船的 `ShipBase` 直接持有一个 `ShipStructure`。基架船由主驾驶台持有飞船对象，换主台时交接同一对象，同船换图时保留结构实例与订阅并更新地图和锚。Shuttle 由自身船体组件持有独立飞船对象，使用自己的占地规则。`UniverseManager` 通过 `ShipStructureIndex` 提供身份查找和地图路由。地图连通域来自同一索引持有的 `FoundationTopologyService`，成员、推进器、护盾和各项质量贡献随归属增量更新。无主域、无主台域、同 owner 断片、天然环境及散落物由地图索引覆盖。容器物理汇总合并各船质量力矩与地图剩余贡献。

格记录覆盖基架、owner、域、支撑、地形和屋顶。成员记录覆盖 Thing ID、原点、占地、关联域、阵营、HP 及组件分类。货柜库存贡献、推进器安装、武器连接依赖、护盾成员及状态变化进入同一变化流。保留按 owner 取全部格、从主台取同 owner 连通域、忽略 owner 的物理连通、原点归属、全占地归属和跨域接触的区别。整图物理汇总中的多格建筑只计一次。

### 统一增量订阅

`Watch(filter, callback)` 在同一已提交修订上交付当前只读视图和可释放的订阅句柄。订阅可按地图、飞船、事件类别和局部格过滤。统一批次给出修订号、变更格，以及带旧值和新值的添加、移除、属性变化和归属迁移记录。调用方直接查询 Thing ID、成员、边界、计数和共享汇总。防护路径、炮口布局、碰撞位图和渲染 section 由各自模块持有，根据批次局部更新。

原版注册、生成、销毁和组件回调可能在同一调用栈发生。按实体和属性合并，先提交读模型，再发回调。回调产生的后续修改排入后续批次。同 tick 后续射击、碰撞和飞控读取上一次操作的提交。对接、拆分和工程合图沿现有 `CaptureDomain → StripDomain → PlaceIntoMap` 控制事务边界，源图和目标图一致可见。失败沿现有回滚或善后路径提交实际状态。

- 质量按贡献更新现有 `ShipPhysics` 的质量及力矩。沿用仅专用货柜计重的口径和现有 600 游戏 tick 发布节奏，届时提交已累积的货柜差值。护盾沿用现有容量、模式、线盾可用性和冷却规则。即时供电、余额、炮手在位、敌对关系及位姿继续由现有权威系统计算。

- [x] **货柜独立 600 游戏 tick。** 空闲为 -1。首个有效库存变化设为 600，随后变化只累加，计时不重置。到期发布该柜一次净差值并恢复 -1。按柜登记到期处理，游戏 tick 只取到期柜。柜型转换交接原到期时间与已发布值，搬迁、销毁、回滚和读档都验证贡献归属和释放。
- [x] **推进布局增量视图。** 结构变化统一发布受影响的实体与变化前后的范围、归属或参数。物理视图订阅回调，按推进器更新条目和其派生数值，稳定查询复用报告。基架和载荷差值更新质量、质心与惯量；实际影响推进器归属的变化才更新布局成员。滑块更新下一次驾驶读取可见，实时供电和加力仍经现有执行入口读取。
- [x] **聚焦图与宇宙外壳共用归属域边界。** 同一个建网格入口按实际基架、墙、门、屋顶及结构连通域判断基架边饰、舱壁端面、补角与斜角。按实际域身份识别同 owner 的断片及未指派基架，避免把空格当作未指派基架。相邻异域采用明确接缝，避免重复叠面。同域连续船体在逆重力场内外共用绘制规则。保持现有原版材质、四向贴片、层序和月池透明顶语义。
- [x] **局部刷新与原版边界。** 结构索引发布基架、归属及建筑占地变化。真实拆分或合并复用拓扑处理时已识别的受影响边界，含可能在远端改变归属域邻接关系的斜角。两种绘制入口按更新后的事实失效有依赖的格和跨区块邻域，合并同一区块的重复提示。普通绘制读取已提交的结构事实。原版地表、逆重战略起降截图、引擎与设施查询、力场及有效域规则沿用现有路径。

#### 验证与通过标准

#### 原版逆重引擎洪泛的触发条件

1.6 与 1.7 的原版引擎都缓存完整连通域和有效域。有效域另受力场、沿基架可达性与承载数限制。基架增删、力场设施装拆或链接变化、引擎生成及换图会使缓存置脏；Delta-V 归属变更也会显式置脏。缓存干净时读取产生 0 次洪泛。一次置脏后的首次读取执行两次洪泛。首读若经普通 getter，还会遍历地图区块并重建原版的遮罩、斜角、基架边饰三层；首读若经 NoRegen getter，执行洪泛但跳过这三层重建。原版设施判定、引擎详情、起飞检查和基架建造界面的已连接基架计数都是可能的首读者。鼠标移动只会重复查询；真正增删基架或改变其他依赖才会置脏。

起降遮罩用独立摄像机截取待移动飞船。原版给属于有效域的斜角和某些基架边饰添加使用专用遮罩材质的额外网格，避免截图漏掉这些伸出基架格的边缘。原版在起飞开始、放置降落飞船、降落收尾时设置全局遮罩引擎。收尾没有清空该引用，读到已离图的引擎则因 Spawned 检查短路。该遮罩的几何查询没有限定地图身份。

迁移前的日常外壳在区块缓存未命中或失效时再生所复用的两张原版图层，普通帧提交已有网格。再生时只有满足原版斜角或基架南侧边饰条件、并且全局遮罩引擎仍生成在图上，才会经 NoRegen getter 读取引擎缓存。此调用链没有固定周期。现有性能窗口未单独计数原版洪泛与这三层的原版全图重建，游戏内命中频次及耗时未知。

复核入口为原版 `Building_GravEngine.UpdateSubstructureIfNeeded`、`WorldComponent_GravshipController`、`SectionLayer_GravshipMask.IsValidSubstructure`、`MapDrawer.RegenerateLayerNow` 和 Delta-V `MapOverlayRenderer.PopulateSection`。本次迁移已从日常绘制移除这条调用链。原版引擎设施查询、战略起降遮罩和截图沿用原版入口。过场结束时恢复归属域图层。

#### 整占地归属

`SpaceWeaponGeometry.OwnerIdOf(Thing)` 当前每次枚举建筑脚印，并逐格读取 `SubstructureOwnership.OwnerAt`。它只在所有格都有同一个正归属时返回该 ID。例如三格发射架 `[42, 42, 42]` 返回 42，`[42, 42, 0]` 或 `[42, 42, 17]` 返回 0。该值也用于无主台的正归属结构和施工中的建筑。现有 `WholeDomain` 是整座建筑是否落在同一个连通域的布尔值，归属 ID 仍需独立维护。
