取代当前「1 tile ≈ 100 格 ≈ 一张降落图」的隐式尺度统一（`OrbitSphere.CellsPerTile = 100`）。
本文是星区模型的权威设计文档；当前实现入口见 [代码入口索引](代码入口索引.md)，玩家说明见 `README.md`。

**术语约定**：本文的「星球轨道层」即现有代码与 `AGENTS.md` 中的 universe 球面坐标
（`OrbitSphere` / `SpacePose.position` / `UniverseManager`），代码标识暂不迁移；
「恒星系」是预留层命名，不占用 universe 一词。世界地图格写作 worldtile。

**位置精度**：`SpacePose` 的唯一持久位置为双精度球面单位方向，`position` 的 `Vector3` 只是即时转换的 Unity/API 视图。`OrbitSphere` 的移动与距离计算、`ShipPhysics` 的质心三步积分和刚体点位姿使用同一方向；不保存第二套局部位置、补偿锚或位移余数。小世界单位下不能归一化已缩小的位移，也不能在每 tick 写回时舍入为 float，否则低速飞行和牵引收尾会停滞。新档直接保存三个 double 分量，不迁移开发快照；聚焦只改显示参考系。离线回归覆盖百万格/弧度的低速积分、原版 Scribe 存读档继续积分与往返显示变换，游戏内精度和切图观感仍待验收。

## 1. 动机：尺度三角无法也不应统一

worldtile 大小、生成地图大小、星球轨道坐标单位三者服务于互相冲突的需求：

- **战术需求**：玩家飞船机动需要几十格/秒量级的手感；可进入空间的自然尺度是一张
  100–1000 格的 RimWorld Map（船体几十格、POI 地形百余格）。
- **战略需求**：原版 gravship launch 是消耗大量燃料的长距离跨 tile 移动；tile 必须
  代表值得付出燃料的战略距离。
- **两者相乘即矛盾**：若一个 tile ≈ 一张地图（现状），战术速度下几秒飞穿一个 tile；
  POI 地形视觉上溢出到邻 tile，而降落选图按「最近 tile 中心」就与视觉重叠矛盾
  （2026-09-16 事故：飞船骑在粗糙狗小行星地形上，降落却落在邻 tile 新生成的空图上；
  根因见旧 `BeginDocking` 的 `TileFromDirection` 最近中心选图 + tile 归属半径
  仅约半张 POI 地图）。

**结论：不追求 worldtile / 轨道坐标单位 / map cell 的数值统一，这个统一本身就是错误
抽象。三者各自独立演化，唯一应该统一的是坐标转换 API（`OrbitSphere` / `SpaceTransform`
收口不变）。**

## 2. 核心决策：五层抽象

| 层 | 载体 | 抽象定位 | 职责 | 明确不承担 |
|---|---|---|---|---|
| Delta-V 恒星系 | Delta-V 自建三维笛卡尔坐标 | 恒星系（太阳系） | 包含多个 Delta-V 星球轨道 | 无当前功能契约，仅为后续更新预留（太阳系内不同星球间转移）；但预留 ≠ 允许无视扩展性——星球轨道层不得实现成无法扩展出恒星系层的形式（如把轨道坐标体系做成不可按星球参数化/实例化的全局 static）；扩展路径 = 届时新增恒星系坐标系与 manager，现有轨道坐标系/manager 挂为其成员 |
| Delta-V 星球轨道 | Delta-V 自建球面连续坐标（`OrbitSphere`；对象位姿 `SpacePose`） | 星球外层空间 | 飞船飞行的空间；同一星球轨道内的所有 SpaceObject 共处同一连续坐标空间 | 不被 tile 定义、不因聚焦切换改变；不同星球轨道之间不互通 |
| Delta-V 星区 | world tile | 星球轨道空间中与一个 worldtile 对应的六边形范围 | 原版兼容层的**抽象概念** + SpaceObject 的**管理/生成记账分组**：星球轨道坐标 ⇄ worldtile 的 coarse address；逆重战略飞行到某 worldtile = 降落到该 tile 上以 worldtile 地图为内部的 SpaceObject 中；内容生成按星区记账（如「每星区至少 N 个特定类型 SpaceObject」的密度保证） | ——（无实体、无图；记账维度可以属于星区，战术几何永远不属于） |
| Delta-V SpaceObject | 星球轨道坐标系中的**对象**（点；`SpacePose` 位姿）。因内部地图有面积，内部坐标 ⇄ 轨道坐标的换算经过它 | 太空中可交互的有价值空间；玩家飞船、敌对飞船、空间站、小行星都是 SpaceObject | 可进入空间和星球轨道坐标的中间层。玩家飞船接近后物化可进入空间，并将其 1:1 渲染在玩家飞船地图的显示上。当玩家飞船的轨道位姿位于某 SpaceObject 内部地图（渲染投影）的某个位置时，飞船降落就会降落到对应地图的对应位置；飞船从对应地图的某个位置起飞后，其轨道位姿仍对应渲染投影中的同一位置 | 不是坐标系；没有内部地图时依然存在（存在性与 Map 解耦） |
| 可进入空间 | Map（口袋图 / worldtile 地图） | SpaceObject 的内部布局 | 「可以走进去的内部」；只有物化后才存在 | 不承载轨道坐标、不是坐标锚、不反向驱动宇宙状态 |

## 3. 星区（worldtile）

- 星区是**抽象概念，同时是管理单元**：星球轨道坐标中与 worldtile 对应的六边形范围，
  因原版兼容（worldtile ⇄ 轨道坐标）与内容管理（SpaceObject 按星区记账/生成）而存在。
  它没有实体，也**不与任何 Map 对应**——worldtile 地图是该 tile 上 SpaceObject 的内部，
  不是「星区的图」。管理维度 ≠ 坐标维度：按星区分组不改变对象的坐标归属
  （仍是连续轨道坐标）。
- tile 是 coarse address：`TileFromDirection(universeDir)` 纯函数导出，供星球视图、
  原版世界交互（gravship 目标、WorldObject 归属）使用。
- 星球视图的玩家飞船剪影仍按连续轨道坐标映射显示（现有 `WorldShipMarkerRenderer`
  机制不变）；**一个 worldtile 对应的弧长显著增大**，硬飞跨星区需要可观时间。
  分工：世界视图剪影 = 世界视图内的显示；左侧面板星球仪（§11）= 任何时候的
  态势显示——两者同源 `SpacePose`，坐标与姿态逻辑不得各写一套。
- 移动方式分工：
  - **gravship launch = 战略转移**：跨星区、大燃料消耗、原版管线到达；
  - **连续驾驶 = 战术机动**：星区内多个 SpaceObject 之间的移动，**免费**——燃料
    耗尽等于无动力死档，救援船等兜底玩法以后再做；战略转移沿用原版 gravship
    launch 的燃料。
- **星区 = SpaceObject 的管理/生成单元**：内容生成按星区记账，支持「每星区至少
  N 个特定类型 SpaceObject」这类密度保证。星区因此不只是被动地址，但它仍然只是
  记账分组，不给对象附加坐标语义（记账与查询见 §4）。
- 碰撞、降落选点等**一切战术判定都发生在星球轨道坐标中**，与 tile 六边形几何无关。

## 4. SpaceObject 与物化（materialization）

- SpaceObject = 星球轨道坐标系中的对象：玩家飞船、敌舰、空间站、残骸、小行星/
  原版站点。持有轨道位姿（`SpacePose`）、身份与需要跨卸载保留的状态；
  **没有内部地图时依然存在**。
- **每个可进入地图都属于一个 SpaceObject**：
  - 口袋图 = Delta-V 自建对象（船/空间站/残骸）的内部；
  - worldtile 地图 = 原版站点（或空画布锚对象）的内部，经 `GetOrGenerateMap`
    原版语义物化（有图复用、没图生成）。

  两种内部在抽象上**等价**，所以需要是同一个SpaceObject类，差别只在其承载的地图（口袋图 vs 原版真实 tile 图）。
- **每个 worldtile 可包含任意数量 SpaceObject，但不是任意数量永久 Map**：未进入
  activation radius 的对象只是轻量宇宙状态；进入后物化内部。现有 `SpaceLifecycle`
  三段（活跃/休眠/删除）沿用，距离阈值保持战术口径（激活半径内同星区多对象共同
  活跃是预期行为）。
- **POI 物化是同一对象的表示切换**：marker（未物化 PoiState）=
  无图**触发器**，按设置的类型显示图标与名称；物化产物是**普通 SpaceObject 容器**
  ——没有 POI 图标身份，名称 = 图上结构拼接（纯环境用 ambientLabel 兜底），图标按
  图内容（按 §11.1 的面积、成员与残骸规则呈现）。物化经 `ReplaceRepresentation`
  保留 objectId 和完整位姿，递增表示版本。导航继续使用下令时冻结的外围锚，星图选择、
  书签与容器级任务目标仍按原 ID 解析。远距普通
  口袋容器按距离与玩家保护门禁整图归档为同 ID 的 `ArchivedSpaceObject`，接近后
  恢复真实地图；完全空白图直接注销。归档保留地图原版状态与必要对象摘要，地图
  引用保护及恢复契约见 [太空战架构](太空战架构.md) §9.1。NativeParent 例外：跟随
  原版 MapParent 镜像（保留原版图标/生命周期；其自身镜像不算图占用）。
  配套不变量：一张图只许一个承载对象；注销 POI 取消排队生成。地图生成失败时仍有效
  的 marker 进入退避期。铺设失败则注销该 POI 并在帧边界销图。物化目标图尺寸随快照
  记录的源图尺寸。
- **marker 身份在生成时一次性决定（2026-09-30 定案）**：每个自建 marker 创建时
  随机落定派系（可见、未灭亡且科技为工业时代及以上的非玩家派系——**不做类型→派系映射**，敌方贸易站
  可劫、友方战机只是路过，均为随机合法形态）并用自制 RulePack
  （`DeltaV_NamerSpacePoi`）生成完整名：`词干 + 类型名 + (派系名) + #ID`（派系为
  空省略括号段；词干↔类型名的衔接由各语言规则自带，中文「苦痛之护卫舰」式）。
  名称（envLabel）与派系（faction）随档持久；物化时直接应用——容器派系、prefab
  建筑与 pawn 派系、归属名（`NoteStructureName`）——之后不改不变；归档→再物化经
  carriedLabel/envLabel 传承同名同派系。物化顺序恒为**容器先注册、结构后铺设**
  （驾驶台 `ClaimOnSpawn` 认领要求 FrameOf 已解析）：有驾驶台的敌舰/空间站自动
  认领盖章归属成船，残骸无台保持结构态。
- **星区化生成与记账**：原版 orbit 站点本来就按 tile 生成，天然已按星区分布；
  Delta-V 自建对象的生成同样按星区记账，用于保证每星区内容密度。**内容按类型树
  配置**（2026-09-30 落地）：`SectorContentTypes` 是任意深度的分类树（分类照
  §11「星区内容类型」：飞行器五级、空间站六类等；残骸由物化地图内容派生，
  不属于生成类型），分支只
  分组，每个**叶子**独立在 Mod 设置「生成」页配置「保底数 + 分段概率额外量 +
  物化 prefab 池」（`SectorTypeRule`；全局设置，跨存档共享，只影响尚未首次生成
  的星区）；无快照 marker 首次物化的内容链 = **叶子 prefab 池**（seed 确定性选取
  与旋转）——**prefab-only**：池空在生成期拦截（报错跳过该类型），池失效在入队/
  物化期报错并取消该 POI，不回退程序生成（程序布局仅存于双船测试场景）。
  **触发时机 = 首次进入星区**：玩家参考对象的 tile 地址
  变化进入新星区时触发；逆重战略飞行在降落前对目标星区生成，然后降落到其中
  对应 worldtile 的对象；开局出生星区在世界生成时预生成。记账语义区分两样东西：
  - 「该星区已触发生成」是**持久事实**——防止重复刷对象，且不可从现存对象推导
    （对象会被销毁，销毁后数量低于下限不等于没生成过）；
  - 「该星区当前有哪些对象」是从 `universe.objects` + `TileFromDirection` 可推导的
    **可重建索引**，不序列化（符合「可重建缓存不是存档事实」纪律）。
    对象被摧毁后的补充策略按类型区分；现阶段只留接口、不做补充。
- **玩家参考点（2026-10-17）**：POI 加载／休眠／归档距离与跨星区生成共用
  `UniverseManager.PlayerReferenceObjects`：从已注册 SpaceObject 筛选含 Ship tag 且
  `HasFaction(player)` 的对象，使用其宇宙位置。盟友公共船只有在其地图被聚焦或载有玩家 Pawn（含容器内人员）时才额外提供参考点；单有操作权限不使无人设施成为自身和周边对象的加载锚。同图多船只有一个参考点，混合派系
  容器只要有玩家船成员就命中；单独飞行及侵入中的 shuttle 同样有效。两类服务不
  查询驾驶台、具体船型或普通船的自由飞行状态。成员接口与归档语义见
  [飞船与SpaceObject解耦架构](飞船与SpaceObject解耦架构.md) §2。每轮先取得对象快照，
  生成时注册 marker 不影响枚举；星区 hint 按 objectId 存于 UniverseManager 实例，
  失去资格即移除，换档清空，已生成星区记账仍按既有持久规则防重。
- **伴生物**：空间站生成时伴生同派系对象（飞船、武器平台、伴生小行星带）。
  之后的空间站蓝图会设置生成点：生成点决定伴生类别，实际对象在类别内随机。
- **坐标桥**：内部地图连续点 ⇄ 轨道坐标的唯一通道是所属 SpaceObject
  （地图点 − 地图几何中心，经对象位姿进入球面切空间）。真实轨道图由
  `PoiState(NativeParent)` 承载，其位姿取原版 tile 中心、角度 0；口袋图由船/POI
  自身承载。两类图共用 `SpaceTransform.MapPointToUniverse/UniverseToMapPoint`，
  不存在合成 tile 帧。`OrbitSphere.Offset` 是 `Move` 的局部球面反解。
- 原版站点的轨道位置仍由 tile 中心方向导出（它没有更细的地址）；Delta-V 自建对象
  拥有自由连续位置，并**远离星区边缘放置**（避免贴脸生成与跨星区激活）。同一个
  worldtile 只有一个原版站点。**投影重叠 tie-breaker**：多个 SpaceObject 的内部
  投影重叠时（CellsPerTile 设得很小、或同 tile 意外出现多个对象），屏幕渲染按
  **objectId 整壳分层**——ID 大（后纳管）者整壳在上，不逐建筑交错；所有
  非聚焦对象壳都在聚焦图自身内容之下，进场、同步漂移和软对接不改变层级。
  背景层在 BeforeForwardOpaque 按 ID 升序整组绘制、组间清深度，画完清深度
  让聚焦图覆盖；前台 AfterForwardAlpha 只绘弹体与瞄准效果，不绘对象壳。
  该分层沿用 RimExodus SeamlessTileRenderer 同款机制；负海拔高度带方案已证伪——
  正交俯视相机下 `Graphics.DrawMesh` 透明队列按 bounds 距离排序、x/z 分量压过
  海拔差，勿回退（2026-09-20）。点击拾取按 objectId 倒序遍历非聚焦壳，
  并让位给聚焦图可见内容。重叠区域的**降落目标**选择按 §7
  「可见船壳最近」判定，不用渲染层序。

## 5. 可进入空间（Map）

- 口袋图只表示「可进入的内部空间」：玩家舰、敌舰、空间站内部。
  `sourceMap` 统一锚专用宿主口袋图、`Tile` 恒 Invalid、不进 `Find.WorldObjects`
  （既有契约全部保留）。专用宿主口袋图本身**不是**任何 SpaceObject 的内部，
  只是 sourceMap 契约锚点。
- worldtile 地图保留原版真实图契约：`GetOrGenerateMap` 语义、持久语义。
  **固定↔移动转换不销毁 worldtile 图**：去留只由锚对象配置（逆重锚）与距离生命
  周期决定，转换本身不是 worldtile 图的销毁者；非 worldtile 源空白则转换后立刻
  删除（遗留基架转原位姿的**无主残骸 SpaceObject**，快照型，接近后物化），非空白
  交给距离生命周期（超距快照收纳）。不按对象身份（空画布锚/玩家 Settlement/
  站点）特判。读档清扫只自愈历史空白口袋图。**逆重发射离场不在此列**——统一走
  §6 的星区驱动标准流程（2026-09-20）。
- 共同约束：只有物化后才存在；不承载轨道坐标、不是坐标锚、不反向驱动宇宙状态；
  与轨道坐标的全部换算经所属 SpaceObject（§4 坐标桥）。

## 6. 原版 gravship launch = 战略转移

- **原版路径（兼容基线）**：目标 = tile 级。在 orbit 降落**总是**进入该 tile 上
  SpaceObject 的内部（即 worldtile 地图；tile 上没有现成对象时按需生成空画布，
  空画布同样是该 tile 上一个 SpaceObject 的内部，`DeltaV_SpaceHostParent` 语义保留）。
- **不做目标升格**：目标保持 Tile 级，原版世界目标器原样使用——落到 worldtile
  地图后再以战术机动接近星区内其他 SpaceObject（叙事上：只有 worldtile 站点
  具备逆重导航降落条件）。
- 口袋图上的原版起飞**视为从所在星区的 worldtile 起飞**（战略源地址 =
  `TileFromDirection(船 pose)`），不要求口袋图自身持有 tile。
- **自由飞行下可直接逆重战略发射**（2026-09-19 放开，`DeltaV_ShipPocket` 的
  `canLaunchGravship=true`）：燃料/航程计算（`TryGetPathFuelCost`）经 Prefix 改接

  **捕获范围 = 整船连通域**
  （`TryGetConversionCaptureScope` 对「口袋图 + ShipOnMap 命中」返回

  口径**：燃料/距离同经战略源地址改写（`StrategicSourceAddress` 按 船自有 → 停靠
  船 → 图 owner 顺序解析）。
- **逆重发射离场善后 = 星区驱动标准流程**（2026-09-20 用户决策，取代按源图身份
  分支的多重实现——旧实现从 wreck 等停靠源发射时，星区 worldtile 图无人处理、

  1. 在**任意地图**触发逆重起飞；战略源地址 = 地图归属星区 worldtile（上文地址
     链），选点/燃料/距离一律按它计算；

     守卫照常生效，删不掉的只休眠）。旅行期间 `MinPlayerDistance` 为 +Infinity
     且评估整体跳过，**不得依赖自然距离触发**——离场时刻显式执行。
  无 tile 源发射的弃置预警（`DeltaV_SectorMapAbandonConfirm`）对自有口袋图与
  停靠源**统一弹窗**（停靠源的星区图真的会被第 3 步弃置）；真实 tile 图源放行

  守卫）。固定↔移动转换不受此流程影响（§5）。

## 7. 状态机（典型操作规范）

### 基架归属模型（2026-09-18 设计；2026-09-24 解耦重构修订——飞船/容器/归属三分离，权威设计见 [飞船与SpaceObject解耦架构](飞船与SpaceObject解耦架构.md)，本节为该模型在星区语境下的落地口径）

- 每个基架格记录**归属结构 ID**（`SubstructureOwnership` MapComponent，存档事实）。
  归属 ID 与 SpaceObject 对象 ID **共用同一计数器但语义分离**（`AllocateOwnerId`
  单一分配；禁止 `ObjectById(ownerId)` 反查船或地图——容器名改为结构名拼接的派生
  缓存，不再靠数值相等关联）。裸 ID（无主台残骸归属、独立平台）合法存在。
- **ID 分配单一计数器**（2026-09-20 收拢，保留）：对象/归属/驾驶台身份一律经
  `AllocateOwnerId` 同一单调计数器；注销对象时推高计数器（被注销 ID 仍被驾驶台
  comp / 图域持有，绝不再发）；读档后抬到 max(已存值, 全部注册对象, 全部图归属格,
  全部驾驶台 comp 身份) 对齐。
- **驾驶台 = 身份与认领锚点**（2026-09-24 修订）：comp 持久 `shipId`（结构归属 ID）
  + `isMain`（主台认领事实，一归属至多一主台）。**spawn 即认领**（ClaimOnSpawn）：
  无身份新台按脚下归属——已有主台则默认备用、无主台则认领成船；未占有域领新 ID 并
  只认领脚下连通未占有片。主台摧毁由同方向备用台按稳定 Thing ID 继任（无同向成
  残骸，可手动认领恢复）；「设为主/设为备用」gizmo 显式切换（新主台朝向定义船头）；
  搬运 DeSpawn 不算损毁。改名唯一出口 `UniverseManager.RenameStructure`（归属名 =
  船名，同步本船全部引擎 RenamableLabel；引擎改名经 setter patch 反向同步）。
  驾驶台重生仍 BFS 重盖章（owner ∈ {本 ID, 未占有}）自愈；主台脚下格禁止「修改
  基架归属」（汇总提示，先设备用/拆除）。
- **写入规则**（唯一写入口 = `TerrainGrid.SetFoundation` postfix，仅 Delta-V 参考系图；
  RimExodus/原版地表零影响）：显式盖章（生成/降落/快照恢复管线）优先；玩家建造按
  邻接规则——四邻基架有效归属一致则继承并**整域吸收相连未占有区域**；无有效邻接或
  **同时邻接多个不同归属**一律**保持未占有（0）**（多归属邻接不再拒建，2026-09-24
  修订：交由玩家经归属命令划分）。未占有是真实归属域（可 bootstrap 成船）。
- **消费口径**（2026-09-24 修订）：飞船的一切结构查询走 `ShipRegistry`——控制域 =
  主台脚下**同归属四连通**；残留块 = 剩余基架**物理四连通**（两语义不得混用）。
  引擎的"自己" = 中心格归属（战略发射口径不变）；`GetConnectedSubstructure` 归属
  过滤 prefix 照旧收口 `ValidSubstructure`（战略发射力场限量域）。**战术捕获不再
  走引擎连通域**——对接完成/脱离/拆分统一按控制域经 `GravshipInterop.
  CaptureDomain/StripDomain` 无引擎搬运。降落脚印与任何归属基架重叠一律拒绝
  （自己 ID 例外已取消）；异主基架四邻接合法。剪影按 (Map, 归属 ID) 双键扫描。
- **太空图基架范围放开**（2026-09-24）：太空图（空间层 tile）上基架可在引擎覆盖
  范围外建造（在船旁建新船）；天然岩顶仍禁；地表完全保留原版限制。
- **归属命令**：Orders 分类「修改基架归属」（`Designator_ReassignSubstructure`，
  主台脚下格保护）。旧档自愈：读档时未指派基架归新分配结构 ID（不再关联对象）。

### 独占容器 → 对接合图

界面与门禁所用的 `FreeFlight/Docked` 仅从当前 Map 的同图船数和天然地面即时推导，
不写入存档；POI 物化的独立单船口袋图通常是前者。选点和对接计划是临时流程，
也不存档。**船不持有可分叉的第二套位姿**：同图船位姿 = 容器位姿 ⊕ 船体锚（`ShipRegistry.ShipPose`，经
`SpaceTransform.RigidPointPose` 派生），剪影与宿主平移、自旋同步运动。

选点确认只注册一次最终放置 root、Rot4 与宿主图连续船体中心（+ 落点盖章的结构
ID）；幽灵船、位姿窗口与最终放置均消费这份注册数据。原版 `CanDesignateCell`
接收的是鼠标输入格，不是放置 root：40×24、North 时输入 (72,54) 对应 root
(73,55)。完成前复核经 `GravshipInterop` 将 root 反编码成设计器输入格，仍调用
原版完整门禁；整数格适配不是另一套轨道坐标变换。完成转移 = **直接放置**
（CaptureDomain 按当前控制域捕获 → StripDomain 剥离 → PlaceIntoMap 放入目标图，
2026-09-24：不再重放原版 InitiateLanding）；原版战略到达的冻结捕获范围照旧。

- **可对接判定**：**飞船中心**位于某 SpaceObject 内部地图投影范围内（2026-09-21
  阶段4 修订：**任何已物化对象均可为对接目标**，含移动中的有动力飞船——随动自动
  驾驶负责速度/角速度匹配，完成判据为与预定落点位姿重合保持可配置 tick 数；旧
  「无动力才可降落、有动力走跳帮弹药流程」口径退役，跳帮舱保留为不入舱全船的
  轻型投放途径）。用中心而不用船体投影相交：空间站
  对接口不在地图边界，能降落则中心必然在图内，大船情况由空间站地图四周预留
  空白解决。投影重叠时取**可见船壳最近**者（2026-09-17 修订：原「渲染靠后
  优先」只对船壳重叠正确——目标 A 船壳小而地图大时，玩家看得见下层 B 的船壳
  却会落到 A；现在按「玩家船壳 ↔ 目标可渲染船壳」的凸包最近距离选择，与
  外壳渲染同数据源）。
- **无动力口径已退役**（2026-09-21，随可对接门禁放开）：有动力与否不再影响目标
  资格；推进器可用性只决定其自身出力（§11 动力模型）与未来的反对接机动能力（敌舰
  AI）。打瘫敌舰不再是可降落的前置条件，但仍是消除其机动的战术手段。
- **判定满足**：降落到该 SpaceObject 的内部地图（正常逆重降落管线），**落点 =
  飞船轨道位姿在该对象内部投影上的对应位置**（悬停在渲染图的哪个位置，就落到
  那张图的对应位置）——该位置只是原版降落选点的**初始落点**，玩家仍经原版
  选点、合法性预览与确认调整落点；落点逐格合法性由原版管线解决，Delta-V 的
  降落规则（2026-09-18 基架归属设计定稿，取代旧「重合或四邻接」放宽）：**可降落到
  纯太空**（宿主图内的空 Space 区域即可，不再要求接触坚固表面），但**脚印任一格
  不得与任何归属的既有基架重叠**（2026-09-24 修订：自己 ID 的遗留同样受限——基架
  不重叠，旧「自己 ID 可重叠」例外取消）；**异主基架四邻接合法**（对接允许异主相邻，
  跨归属硬连接走对接口）。小行星天然地面不是基架，不触发本门禁。地表图不受影响。
  降落的船体捕获只读冻结的 Gravship foundation（InitiateLanding Prefix 统一冻结，
  战术降落到达重放与原版战略到达同覆盖），避免目标 wreck 污染捕获形态。战术降落的
  过程 = **对接计划**（2026-09-21 阶段4 定案，取代 2026-09-17 的进场自动驾驶流程；
  完整定案见 [解耦架构 §6](飞船与SpaceObject解耦架构.md#6-战术对接地图合并流程)）：选点阶段**零消费**（游戏照常运行，2026-09-21 用户决策
  移除选点暂停）——预览用空洞 Gravship（私有无参构造器 + 只读填充脚印/包围盒/
  驾驶台/推进器），原版选点/合法性/禁触链路照常工作，船体与 zone/区域数据全程
  不动（星球仪剪影与船壳数据源不存在"从星球仪消失"的中间态）；确认落点后建立
  对接计划并**聚焦切回自己船**（不再启用 cutscene 级联锁玩家——玩家保留相机与
  常规控制，建造/规划照常、扩建随完成时捕获带走；仅封锁从计划船地图发起逆重
  发射）；存档语义（2026-09-22 修订）：计划飞行期可正常存档——计划与自动驾驶任务
  均为运行时数据不落盘，读档后计划丢弃、船按已保存速度漂移、不自动续接（读档清扫
  链负责收尾），选点与到达重放窗口仍禁存档（marker 深序列化/转移中状态）；玩家同时
  最多一个计划，超出可配置距离
  （小于休眠距离）自动取消），预定落点位姿 =
  反向映射（宿主帧 ⊕ 落点局部，角度 = 宿主帧角 ⊕ 最终放置朝向），由**幽灵船壳**
  （无图、只有船壳快照图的半透明位置提示，派生缓存不进 `universe.objects`）在
  目标图上持续指示；接近手段可选——ShipAutopilot **随动目标模式**（宿主 ⊕ 局部
  落点每 tick 重算（游戏时间语义：暂停冻结、倍速加速，[AGENTS 模拟时序约束](../AGENTS.md#架构不变量)）、六状态
  在线 MPC 联合平移/转动制导（微步 6 tick 节拍：QP 按距离自适应降频——终段每微步、
  中程 2 微步、远场 4 微步，多船按 ownerId 错峰，解间回放计划控制，详见
  `doc/在线MPC自动驾驶.md`）+ 宿主目标点速度（含 `ω×offset`）/角速度前馈 → `ForceToCommand`

  受推进器布局硬约束；软接近包络为 √(2·a_safe·d) 刹车曲线形状（满推接近/满推反推/
  v=0 恰好到点）；终段按距离渐变叠加**虚空动力**补齐「期望 − 可达」差值；
  到位后站位保持直到取消）或玩家手操——只有明确进入手动驾驶后才抑制重叠按键；
  普通飞行键不接管自动驾驶，手动／自动交接见[基础驾驶](阶段2-基础驾驶.md#玩家驾驶方式与任务2026-10-26)。**与预定
  落点位姿重合保持可配置 tick 数**即满足对接条件——先以**新鲜脚印**复核落点合法

  时刻的真实冻结**（唯一消费点：zone/地板指令/区域限制/储物组此刻收缴进清单，

  `CaptureDomain → StripDomain → PlaceIntoMap` 完成真实转移。
  战术对接不重放原版 `InitiateLanding`，因此不进入 cutscene、terrain curtain、
  `LandingEnded` 的结局掷骰或 `Scenario.PostGravshipLanded`。
  基架船的战略引擎冷却保持原样；shuttle 落地冷却由 `ShipBase.NotifyLanded`
  注入。`DockingCompletion` 在帧边界统一完成源图处置与聚焦交接。
  选点与转移待收尾窗口按统一 `PilotTarget` 身份提供存档和尺度调整门禁，
  不依赖船型或搬运后失效的旧地图快照；接口契约见解耦架构 §2。
  原版战略到达的结局、场景钩子与冷却仍全归原版。初始落点按飞船
  脚印收边并经原版合法性门禁——投影落点被禁触规则否决时自动环形外扩到最近的合法
  空位（悬停在 wreck 正上方时退到一旁的空隙），仍找不到或图比船小时留给玩家手动
  选点；选点引导 =
  原版白色条纹脚印 + 真实悬停船壳（快照不搬运，选点期间船仍在活口袋图，标准
  非聚焦外壳在聚焦图上持续显示），不再叠加额外剪影。
  降落完成后飞船与 wreck 共享同一张图的建筑拓扑，但**基架归属保持分离**（见 §7
  基架归属模型）：落点基架在放置时盖章为船 ID（InitiateLanding Prefix 的冻结集同时
  登记归属盖章），wreck 基架仍是 wreck ID；星球仪按船域分别画船剪影，剩余非太空地形独立表达；具体面积与显示门槛见 §11.1。
  **空白空画布不是可固定目标**
  （2026-09-17 用户决策：战术空画布降落退役；留有内容的画布按原版语义保留可降落；
  原版战略发射到达按需生成空画布锚的路径不受影响）。
- **对接口**（2026-10-16 气密通行单元方案）：1×1 门，真空屏障科技解锁，建在基架上。
  `Building_DockingPort` 与通道单元 `Building_DockingChannel` 同属 `Building_SealedDockingDoor : Building_Door`；
  原版门提供独立 Portal 与寻路，`ExchangeVacuum=false`。`Patch_DockingPort` 只对这些门房间的

  Space 的 `ImpassableFreeAirExchange` 会与通行区合房，因此不能仅靠地形加屋顶密封。
  通道不铺实体屋顶，甲板方向贴图由常开单元绘制，底层 `DeltaV_DockingChannel` 地形只提供通行、无基架与建造承载能力。
  通道 `fillPercent=0`；气密只由实例 `IsAirtight/ExchangeVacuum` 与上述门房间补丁提供，不声明要求 `Fillage=Full` 的 Def `building.isAirtight`。
  对接口保留玩家朝向，跳过原版单格门绘制时的邻墙自动转向；门叶动画仍走原版，建造蓝图使用保留旋转的 `Blueprint_Build`。
  战术 `DockingCompletion` 与战略 `LandingEnded` 仅通知本次到达 Map；未展开端口沿朝向探测至
  8 格内首个非 Space 地形／建筑，之前的空格逐格铺设（最多 7 格通道）；紧贴时记录零格连接，无目标则保持收起。
  已有临时通道阻断延伸，不能作为新通道的对接面；双方相向时由先伸出的端口持有整个通道，避免形成串接网络及级联留置。
  降落选点通过 `Designator_MoveGravship.SelectedUpdate` 显示双方范围：青色为待降落船、紫色为目标图端口，绿色标出预计接触面；无接触面仍显示朝向上的搜索带，已有通道及图边界截断范围。提示只表示通道几何，不替代原版落点合法性或保证接触面的可通行性。
  `GravshipInterop.BuildPreview` 将控制域内端口纳入原版 `ThingPlacements`；`DockingChannelPreview` 读取其已旋转位置／朝向和同一 designator→root 适配结果，把待落位脚印叠加为只读结构，让目标端口也能探测尚未落地的船。战略降落读取实际 Gravship 的同一放置数据。
  `TryFindChannel` 是建造／降落预览、生成与结构事件复核的唯一几何入口。保存通道格、对接面与单元的端口引用；
  prefab 旋转由端口现有局部状态换锚入口处理格与对接面，单元端口引用由整批 Scribe 重定向。
  通道不是基架，不进控制域、不参与捕获与船剪影；通道单元沿现有门类入口进入整图外壳。
  建筑移除和地形变化事件（包括原版 `RemoveGravshipTerrainUnsafe`）复核相关端口，通道破损或对接面消失时收回，不逐 tick 扫描。
  手动收回有内容物时列出清单并暂停确认；端口移除与双方脱离的收回／留置约束见解耦架构 §9。
  进场从悬停位姿、角度自动驾驶到实际选定的落点位姿。目标尚未物化时继续接近，
  进入 activation radius 加载后即可正常降落
  （软限制，无硬不兼容）。
- **空无一物**（不满足任何可降落判定）：提示「没有可固定目标」，**不再在深空
  凭空生成空画布**。
- 本规则取代现行「最近 tile + `GetOrGenerateMap`」选图；§1 的降落错图事故在此
  规则下自然消失（目标选择与对象内部投影同口径）。

### 同图船出力 → 拆分成独立容器

**触发 = 驾驶中将要产生推进器出力**（`ShipTransitions.RequestThrust` 统一分离门禁；
2026-09-24 用户定案：「脱离停靠」不再是独立命令/按钮，与其他船同图的船同样可进入驾驶，
首次出力即与所在图其余部分分离——干净脱离立即执行，有同归属断片/通道滞留时先弹
汇总确认）。分离时从当前捕获船体中心取宿主刚体点位姿，继承宿主平移速度、
`ω×offset` 切向速度与角速度。分离聚焦跟随侧边栏选中结构的主台侧，无主台时跟随较大侧；其他船离港不改变当前选择。镜头交接不自动赋予手操，完整规则与无承载图回收见 [解耦架构 §8.1](飞船与SpaceObject解耦架构.md#81-触发与结果已定)。双方物理与自动驾驶共用同一管线。

- 飞船搬入**新的地图容器**（内部 = 自己的口袋图；2026-09-24 解耦重构：脱离 =
  无引擎拆图——控制域整体经 CaptureDomain → StripDomain → PlaceIntoMap 转移，
  宿主图与宿主容器保留）；
- **捕获范围 = 主驾驶台脚下「同归属四连通」控制域**（`ShipRegistry.ControlDomain`，
  2026-09-24 修订：不要求逆重引擎——飞船识别/战术机动/脱离/对接均不要求引擎）；
  降落后被改写归属为船 ID 的 wreck 部件与后来扩建的相连结构都会随脱离带走，
  同归属断连基架与异主基架一律留下（留在宿主图的断片按无主台残骸处理，下次出力
  前经拆分入口成为独立残骸容器）；**原版逆重战略发射仍要求引擎，只带走力场内
  自己 ID 的基架**（口袋图整域绕过的旧例外已退役，2026-09-24）；
- **一致性模型**：非玩家派系没有逆重引擎——虽然能自由飞行（推进器按自身
  实际状态出力，见 §11），但无法像玩家一样使用逆重发射远距离移动；只要不逆重
  发射，飞船可以建造得很大而不必被逆重引擎范围限制。玩家丢掉引擎后仍可自由
  飞行/对接/脱离（战术链不要求引擎），不能再逆重战略发射；
- **门禁**：相连基架连通域内没有任何一台可工作推进器时，拒绝分离出力
  （对齐原版 `CannotLaunchNoThrusters` 语义）；重力图（地表 worldtile 图）拒绝
  驾驶与分离出力，只能逆重战略发射；口袋图零重力按「是否属于宇宙容器」判定
  （2026-09-24 修正：口袋图 Tile 恒 Invalid，旧实现只查 Tile.Valid 会把口袋宿主图
  全部误判为重力图）；
- 起飞后的轨道位姿 = **宿主 SpaceObject 位姿 ⊕ 起飞点的内部坐标**（从内部地图
  哪个位置起飞，轨道上就出现在渲染投影的对应位置）；真实轨道图与口袋图同构。

### 原版起降

- **原版逆重降落**：在 orbit 降落总是进入 worldtile 地图（该 tile 上 SpaceObject
  的内部；忽略同 tile 其他 SpaceObject，要进它们用战术段机动过去）。
- **原版逆重起飞**：
  - 在 worldtile 地图上起飞：完全原版；
  - 在口袋图上起飞：视为从所在星区的 worldtile 起飞（§6）。

### 位置对应关系的规范锚

- 「悬停位置 ↔ 降落落点」「起飞位置 ↔ 轨道位姿」两个方向都以**轨道位姿（状态）**
  为锚定义；1:1 渲染只是同一事实的显示投影，显示层永远不是对应关系的事实源。

## 8. 尺度重标定（落地时的参数契约）

- 实现方式仍是 `OrbitSphere` 尺度常量调整：`CellsPerTile` 从 100 提到量级更大的值，
  **默认 20000，玩家可在设置界面调整**（预期常规巡航速度 100–200 格/s；默认值下
  跨一个 worldtile 约 2 分钟，满足硬飞耗时分钟级）。约束：
  - 星区内 SpaceObject 典型间距：数百–数千格（100–200 格/s 的船 10 秒–1 分钟量级
    转移）；
  - 跨星区硬飞耗时显著（分钟级以上），与 gravship launch 的燃料价值互补；
  - 激活/删除半径（300/1200 格）保持战术口径，不得跨星区激活（对象远离星区边缘
    放置保证这一点）；
  - activation radius 与内部投影半径的关系是**玩家按自己地图尺寸调设置的软限制**：
    默认 300 格已覆盖 600×600 以内的图；骑上更大的未加载投影时继续接近，加载后
    即可正常降落，无硬不兼容；
  - 内部地图（≤1000 格）相对 tile 弧长足够小；即便视觉溢出邻 tile 也不影响任何
    战术判定（判定已与 tile 几何无关，§3）。
- **改 `CellsPerTile` 不改 tile 划分**：球面方向 → tile 是纯几何函数，与尺度常量
  无关，星区记账不因改值错位。调整**即时生效**：全部 SpaceObject 位姿相对所在
  星区中心按比例缩放，保持各星区的布局密度——只动位姿，与物化状态无关（未物化
  是常态）；**速度不缩放**（战术手感不变，战略距离随尺度拉长）。停靠、起飞流程进行中
  禁止修改该设置；存档门禁见 §7（选点/到达重放窗口禁存档，计划飞行期照常——2026-09-22
  修订）。mod 未发布，无旧档兼容负担。

## 10. 不变量

### 既有不变量（不因本架构改变）

- Map 是稳定局部坐标系；聚焦 Map 恒 identity；禁止批量修改 `Thing.Position`/`Rot4`。
- 星球轨道坐标（代码术语 universe）是球面绝对坐标，`OrbitSphere` 唯一入口；
  无锚、无 floating origin。
- 口袋图 sourceMap 锚专用宿主、不占 tile、永不聚焦；宿主不是显示画布。
- Pawn 跨 Map 与相机聚焦切换分离；可重建缓存不是事实源。
- 所有跨层坐标转换收口 `SpaceTransform`。

### 本架构新增的不变量

- 星区是 coarse address 与管理记账维度：碰撞、降落选点等战术几何判定一律在星球
  轨道坐标进行，不由 tile 几何决定。
- 内部地图坐标 ⇄ 轨道坐标的换算唯一通道是所属 SpaceObject；不存在独立于对象的
  图级坐标锚。
- 星区无实体、无图；不存在「与星区对应的 Map」。

- 范围菜单提供适配本船、适配当前星区和整球，均为一次性操作。参考船使用侧栏实际选择；没有有效船时回退当前图容器。跟随时视图沿参考点—球心连线，拖动后沿视角中心—球心连线；北轴向上，极点用上次稳定上向在当前切平面的投影回退。星区网格随视角中心绘制，仍为地址边界，按 `CellsPerTile` 淡入、同时淡出地轴，不用于战术距离或落点。
- 缩略和详细地图共用左键按下／抬起手势。单击标记或可见标签选择导航目标，命中范围重叠时优先取离鼠标最近的标记。缩略图拖动会取消点选，视角继续跟随。布局先保留所有可见标记的命中范围，再摆放标签；找不到空位时保留标记与悬停提示。「同屏」使用共同的 `GlobeView`／标记布局，按两者包围范围和标签计算一次安全视野，之后不会自动拉回玩家的手动缩放。目标离开视野时以边缘箭头、名称、距离表示；球背注明状态，精确对跖点不伪造方向。无法同屏时拉至整球并提示投影限制。
- 星图可对当前选中地点或任务目标下达「自动导航」。命令只作用于侧栏当前所选、玩家可控制的飞船；弹体、散落物、本船所在容器和失效目标不可用。确认时一次性冻结目标朝本船一侧的外围锚，净空取目标碰撞包围半径、本船船体半径与 8 格安全余量之和，船首朝向目标；不以目标中心为航点。锚保存为目标中心确认时切基中的偏移：随目标中心平移并继承其线速度，但与目标自转解耦，避免外围点绕目标旋转、到位后因切向速度继续漂离。实图直接读取 `SpaceCollision` 的碰撞面；归档保留卸载后不可重建的半径摘要；未物化目标读取其确定的 prefab／原生地图尺寸，不触发物化。星图只负责选择与生成这一个锚，执行、到位判据、失败和终态仍复用玩家定点任务与共同 MPC；长途任务没有固定时长截止，主体／参考失效或失去推力仍按共同失败链退出。
- 「查看」才通过帧边界队列和现有聚焦入口切图，落在当前目标成员／环境锚；执行前重新解析并核对对象身份和表示版本。未加载对象允许选择、收藏和定位，不通过这些显示操作触发物化，也不能查看内部图。「同屏」「查看」「定位任务」本身不下达飞控或改变 `SpacePose`；只有玩家明确点击「自动导航」才替换当前自动任务。
- 「聚焦目标」从当前有玩家可操作船的太空图发起，沿用本船图的参考系。帧边界复核目标容器的对象 ID 和表示版本，再以约 0.25 秒飞入，随后跟随船壳绘制所用的容器中心。原版相机接受方向键、中键拖动或屏幕边缘滚动时立即交还控制，缩放可继续使用。镜头跳转、切图、进入世界视图或目标船壳失效时结束，跟随会话仅存于运行时。
- 展开地图列表列出已登记对象的共同显示条目，独立于缩放、球背和面积显隐；提供名称／派系搜索与下述组合筛选，任务优先、其余按球面距离排序。点击条目选择，点击定位执行同屏。空间站来自 `Station` 类型树（不含小行星）或原版 `SpaceSettlement`；同容器最大结构作为空间站条目，访客船仍独立列于全部。未知类型仍在全部列表中，不按名称猜测分类。教程船厂与武器平台使用已有 `contentTypeId`。
- 详细地图搜索栏左侧的过滤图标打开 `Dialog_GlobeFilters`。图标在有限制时高亮，列表显示筛选后的条目数／总数；搜索与筛选共同作用于大小星图标记及列表。显示区另提供单位经纬网格开关。对话框修改独立草稿，应用时复制整份配置，取消不改变当前设置；父分类支持全选／全不选与半选显示，窗口有恢复默认和显示全部。`UniverseManager.GlobeFilters` 保存用户偏好，`GlobeNavigation.IsDisplayed` 是地图与列表的共同判断入口；缓存和运行时选择不成为筛选事实。
- 对象分类：飞船按成员分为基架／一体式；空间站树复用生成类型（卫星含子类，另有其他空间站），小行星单列为自然天体；另有残骸、弹体、散落物和其他／未知。舰级复用生成树的 Craft 叶子；当前已知容器的主结构读取生成类型，其他成员和玩家自建船保持未分类，不按尺寸或火力推断。武装按已安装舰炮／原版炮塔判断，工程工具不计，断电或缺弹不改分类；未物化且无摘要时武装为未知。成员派系不回退容器派系；己方／盟友／中立／敌对／无派系／未知独立筛选。归档摘要保留成员生成分类、武装及环境自然地形事实，恢复后改读实图。
- 同一维度内任选，维度之间同时满足；舰级维度只约束飞船。默认隐藏一体式飞船、弹体和散落物，其他维度不限。任务首版使用当前跟踪目标、其他进行中任务关联、无关联，不从历史任务推断，也不为筛选刷新委托板或生成可接任务。可附加仅书签；默认启用「始终显示当前跟踪目标」，此豁免不改任何类别配置。普通选择／书签／己方身份不绕过筛选。应用后清除被隐藏条目的临时选择，书签仍保留；定位被过滤目标时提示调整条件，不自动开启整类。
- 弹体条目由 `SpaceProjectileService.CollectGlobeEntries` 读取在飞记录，与弹体工作对象一起复用；排除已退役记录、即时激光和已经作为飞船显示的侵入艇。有图弹体的 `GlobeProjectileVisual` 随 `SpaceMapPool` 的地图资源复用，租约核验防止闲置或旧租约暴露图像，同尺寸换弹种时更新 Def 绑定；地图 Forget 释放绑定。无图实弹按弹种复用，ResetFlow／换档清理。贴图借用飞行渲染的 Def 资源，不逐弹复制纹理或销毁共享贴图；大小与姿态读取实际 drawSize／SpacePose，贴图轴向转换和飞行渲染共用 `SpaceTransform.SpriteMeshAngle`。
- 弹体始终只画等比例贴图投影，远景不放大为图标；散落物只画小点。两者均不加常驻标签、选择框、速度／画外箭头或数量聚合，保留悬停信息与列表定位。弹体不可收藏、不可查看池内地图，正常注销即移出列表。激光和侵入艇仍使用原有表现。此筛选只作用于星区大小地图，不改变原版世界地图标记、飞控、碰撞或物化。
- 普通对象面积 = 非 Space／Void 地形的去重格数，含天然地面、基架和覆盖地板；不计留白／空洞／补边。无地形的单建筑 shuttle 使用船体脚印。同图各船独立表达，环境排除船域；坐标和锚仍走 `SpaceTransform`。普通对象 `sqrt(area) × pixelsPerCell ≥ 0.5` 才出现，原版 POI、玩家船、当前参考船豁免；非残骸达到 2 像素显示名称和距离。已知空间站在横向范围不超过六倍星区尺度时保留标记。
- 当前选中、当前教程目标与书签不受面积和残骸名称门槛影响，保留至少 24 UI 像素命中范围。标注优先级为选中、课程、书签、本船和普通对象，长名称缩略、悬停完整显示。普通远景图标邻近重叠时聚合为数量标记，点击菜单列出每个成员；保护目标、本船和真实比例剪影不合并。常规空间站使用菱形、船使用朝向三角；原版 POI 保留自身图标和颜色。
- 图标／投影按共同视图尺度切换：参考船最长边（至少按 16 格计）达到 8 UI 像素时，已有地图且有投影格的对象使用真实比例剪影。近景导航框独立于船体尺寸，不放大船体。尚无投影的仍用图标；图标模式继续显示速度箭头，投影不叠加普通图标／速度箭头。原版容器图标已有可见成员投影时移除重复图标，显式导航目标保留目标表达。
- 剪影旋转复用原版 `Widgets.DrawLine` 的局部 GL 变换方式，先旋转局部顶点再应用窗口／分组偏移，不经 `GUIUtility` 重建屏幕旋转中心。1.7 的标记与网格使用后端相对 GL 路径，让 GUI 分组与 UI 缩放和标签保持一致；1.6 沿原生绝对像素矩阵绘制。所有显示的名称／距离标签均通过引线标明所属标记，不以避让或距离阈值决定是否绘制。
- 残骸定义仍为没有存活 Pawn（含容器内）、已安装武器、推进器或主／副驾驶台；按存在而非工作状态判断。无图不等于残骸，普通残骸悬停仍可查看名称与距离。`PrefabGlobeMeasurements` 在启动时测量各 prefab 非太空面积；未物化自建 marker 取类型池平均值，未知测量保留图标；绘制不读取文件、不生成地图。
- 结构、面积、剪影尺寸共用结构版本失效，人员／容器变化刷新残骸状态。剪影尺寸与实际纹理由 `ShipSilhouette.AnchoredSide` 共用计算，不能为同屏另造近似船体范围。归档补存无法从卸载图重建的显示摘要（含成员空间站分类），恢复后改读实图。销图、表示替换和换档释放条目／纹理缓存。
- 玩家主动书签是长期事实：`GlobeTarget` 仅存容器 objectId 或带艇型的独立船身份，两种 ID 分字段；成员目标跨合图／分离重新解析，不能用 ownerId 反查容器。普通环境对象注销时清除其书签；暂不可解析的成员书签显示不可用、允许取消。范围、手动选择和布局不序列化，读档恢复默认视图并从课程重建目标，不恢复历史适配动作。
- 当前课程导航角色由 `DeltaVTutorialService.NavigationRole` 派生，独立于原版 Quest 保留的全部角色引用：回收指向货架见证，邀请／软对接／试射指向武器平台入口，参观赠船指向船厂入口；跳过平台直接转船厂。合图后读取角色实际所属结构；暂缓保留提示，结束释放课程目标。侧栏「定位任务」及教程人物／设施上的同名 Gizmo 共用导航入口，不改变课程完成条件。

### 星区内容类型

- 敌对／中立／盟友差异**复用原版派系关系**，随机派系资格见 §4。
- 留**自定义结构接入接口**：后续经 debug action 导出/导入结构设计，部分导出
  结构随 mod 发布并默认加载。
- 类别：
  - **飞行器**（占位：原版逆重飞船剧本开局的逆重飞船）：战机、炮艇、护卫舰、
    驱逐舰、巡洋舰。
  - **空间站**（原版结构占位）：
    - 卫星（占位：原版小行星）：天基武器解锁卫星——骇入后获得原版轨道轰炸或
      轨道光束引导器；废弃卫星——拆解取材，或降落到其上建造连接、起飞时随
      `ValidSubstructure` 一并捕获**拼到船上**（现有船体捕获机制，无需新机制）；
    - 武器平台（占位：原版小行星）；
    - 贸易空间站（占位：原版商会定居空间站）；
    - 造船厂（占位：原版小行星）；
    - 工厂空间站（功能分类；敌友由派系决定）；
    - 小行星带：默认 prefab 是含批量标记的天然矿体核心，生成多种纯真空、部分含矿且不再嵌套标记的伴生小行星；稳定类型 ID 仍为 `Asteroid`。
  - **伴生物**：空间站生成时伴生同派系对象——飞船、武器平台、伴生小行星带
    （供玩家机动躲避的障碍，不是原版大个采矿小行星）；空间站蓝图的**生成点**
    决定伴生类别，实际对象在类别内随机。

### 动力系统改造（VEF / VGE，参考 `references/VanillaExpandedFramework`、`references/VanillaGravshipExpanded`）

- **当前默认模型**（`VanillaIntegrityPowerModel`）读推进器**自身实际状态**：
  故障（`CompBreakdownable`）、排气堵塞/不露天（`CompGravshipThruster.Blocked`）、
  断电（如有供电 comp）。**不查引擎连接与燃料管线**——原版 `CanBeActive` 要求
  连接殖民者逆重引擎与力场基架，会把无引擎的非玩家派系船全部判死（§7 一致性
  模型）。代价：VGE 燃料条件（挂在 `CanBeActive` 上）不自动生效，由将来的
  兼容层替换 `ThrusterPower.Model` 实现补上。
- 推进器（凡可作为逆重飞船推进器者皆视为可在驾驶模式提供动量的推进器）将改为
  需要 **VEF 燃料管道**连接才能工作（经上述 Model 替换实现）。
- VGE 修改了逆重飞行消耗的燃料类型：做消耗时**从实际消耗管线取燃料类型**，
  不写 `if VGE` 式硬编码。
- **电推**（后续）：推力小、不消耗燃料、只需连接电网；燃料消耗机制完成前只
  保留接口（§9 动力来源抽象——不得实现成所有推进器都必须接管道）。
