# 太空飞船与跨图战斗探索

## 简述

RimWorld 的局部地图天然适合表现殖民地、飞船内部和地面战斗，但并不提供一个让多张地图作为独立刚体在连续空间中移动、旋转和交战的系统。

SOS2、Vanilla Gravship Expanded、Gravship Conquest- RimSkyBlockDLC 本质上都是在搞抽象的接近、远离、打击角度——我不是说这个不好，它们确实兼容性极佳，但是我个人确实不太满足于 FTL: Faster Than Light 式的对轰

本 Story 计划基于 RimExodus 已有的跨地图经验，实现一套太空飞船与 POI 的连续空间系统。玩家飞船、敌对飞船和部分太空 POI 分别保存于独立的小型 RimWorld 地图中，同时通过一套脱离地图格子的统一宇宙坐标系记录其位置、速度和朝向。

玩家驾驶飞船时，当前聚焦地图本身始终保持 RimWorld 原生的固定朝向和坐标结构。飞船的移动和旋转不通过实际移动或旋转地图内容实现，而是改变其在宇宙坐标系中的姿态；其他飞船和 POI 根据其相对于当前聚焦对象的位置和角度进行渲染。

非当前聚焦地图不要求完整渲染其内部 Pawn、建筑和地形，而优先以飞船外壳或其他视觉代理显示。玩家跳帮、登陆或主动切换观察目标后，对应地图成为新的聚焦地图，并重新以其自身固定朝向正常显示。

该方式希望在尽可能保留 RimWorld 原生地图、建筑、Pawn、寻路和存档机制的前提下，实现类似 The Last Starship 的连续飞船驾驶、交战、靠近 POI 和跳帮体验。

本文档作为该功能的长期设计记录。开发过程中逐步补充源码调研、技术验证结果、实现约束和后续计划。

## 背景

RimWorld 中的每张局部地图本质上都是独立的矩形格子世界。

Pawn、建筑、房间、寻路、电网和大量 Mod 逻辑都默认：

- 地图自身不会移动；
- 地图自身不会旋转；
- 格子位置使用整数坐标；
- Thing 的朝向通常使用 `Rot4`；
- 当前相机主要围绕一张标准朝向的地图工作。

如果直接让一张已经运行中的 RimWorld 地图进行连续移动或任意角旋转，就需要同时处理：

- Thing 的位置和朝向；
- MapMesh 与动态绘制；
- Region、Room 和 PathGrid；
- 鼠标拾取和 Targeter；
- 建筑与各种 Mod Comp 缓存；
- 多地图之间的坐标转换。

这会产生大量与太空战本身无关的兼容问题。

本系统因此采用另一种受 The Last Starship 启发的模型：

> RimWorld 地图永远保持自己的局部坐标系不变，只有地图所代表的太空物体在统一宇宙坐标系中移动和旋转。

RimExodus 已经提供了若干可参考或复用的基础经验，包括：

- 多张地图的生命周期管理；
- 地图之间的位置映射；
- Pawn 跨地图转移；
- 非当前地图内容的投影绘制；
- 跨地图弹道处理；
- 聚焦地图切换；
- 存档和读档后的地图关系恢复。

新系统不要求沿用 RimExodus 的六边形世界地块语义，而是重新建立适合二维连续太空空间的坐标关系。

## 理想结果

每艘实际可进入的飞船对应一张独立的 RimWorld 地图。

默认飞船地图可以采用约 `200×200` 的尺寸，并允许在 Mod 设置中调整。地图中飞船以外区域使用透明、不可通行的虚空地形填充。

太空场景可以使用一张较大的宿主/显示地图作为宇宙背景与渲染画布，初步默认尺寸为 `800×800`，允许在设置中调整。

宿主地图只承担有限的显示和场景组织职责。真正的飞船位置不受宿主地图边界限制，而由独立的宇宙坐标记录，因此后续可以根据实际性能测试调整宿主地图大小，而不影响宇宙空间尺度。

> 因为敌人飞船之类的必须用口袋地图，而我们期望所有飞船，不论是玩家的还是敌人的，都是对等的，所以玩家的也得用口袋地图。而口袋地图需要宿主，所以才需要为玩家维护一个宿主地图

每个飞船或 POI 至少具有：

```text
SpacePose
- universePosition
- velocity
- angle
- angularVelocity
```

地图内部坐标和宇宙坐标之间通过刚体变换转换。

### 聚焦地图

任意时刻存在一张当前聚焦地图。

当前聚焦地图：

- 使用 RimWorld 原生方式正常渲染；
- 始终保持标准地图朝向；
- Pawn、建筑、寻路和交互均使用原生局部坐标；
- 不因飞船在宇宙中的实际角度而旋转地图内容。

宇宙场景的显示坐标以当前聚焦对象为参考系：

```text
DisplayTransform = inverse(FocusedObject.SpacePose)
```

因此当前聚焦飞船在视觉上始终保持固定，而其他对象根据相对运动产生平移和旋转。

如果玩家飞船旋转，表现上是星空、敌舰和 POI 朝反方向旋转，而不是实际旋转玩家地图。

如果玩家跳帮敌舰并切换聚焦：

- 敌舰地图恢复标准朝向并正常显示；
- 玩家飞船成为一个按照相对姿态旋转的外部飞船代理；
- 宇宙中所有对象仍然使用同一套绝对坐标，不发生实际坐标重写。

### 非聚焦飞船

非聚焦飞船初期不要求完整显示其内部地图。

系统根据飞船地图生成并缓存一个外部视觉代理，例如：

- 船体轮廓；
- 外墙；
- 外露推进器；
- 武器或炮塔；
- 破损区域；
- 后续需要的外部特效。

视觉代理可以自由平移和任意角旋转，而不会影响该飞船真实地图中的 Thing。

飞船内部发生结构变化时，再将对应视觉缓存标记为需要更新。

### 驾驶模式

玩家可以进入驾驶模式，通过：

- W/S：前后推进；
- A/D：侧向平移；
- Q/E：旋转；
- Space：向鼠标指向射击

控制飞船。（这些按键需要可以在设置中修改，并在驾驶模式中避免触发对应的原版按键）

飞船的线性加速度由对应方向的可用推进器和飞船质量共同决定。

初期可以使用飞船基架数量近似计算质量，之后再根据实际需求加入建筑、货物或其他质量来源。

驾驶过程中：

- 玩家地图本身不移动；
- 玩家地图本身不旋转；
- 只更新玩家飞船的 `SpacePose`；
- 其他对象按照相对于玩家的姿态重新显示。

### 固定轨道 / 建造模式

玩家可以退出驾驶状态并进入固定轨道（本质上是建造状态）。

进入该状态时，飞船的宇宙朝向吸附到：

- 上；
- 下；
- 左；
- 右；

四个正交方向之一。

固定后允许玩家正常扩建和修改飞船。

重新进入驾驶模式后，飞船继续作为一个独立太空对象进行连续运动。

进入固定模式的本质是让飞船从口袋地图上使用逆重飞船发射的机制转移到停靠地图上（但没有起降动画），并以相同的机制旋转

进入驾驶模式的本质是让飞船从地图上使用逆重飞船发射的机制转移回口袋地图（但没有起降动画），并以相同的机制旋转。飞船在驾驶模式的朝向取决于驾驶台的朝向（可以显式设置主驾驶台，第一个驾驶台总是主驾驶台，第二个驾驶台不会取代主驾驶台，除非玩家显式用gizmo设置了第二个驾驶台为主驾驶台）

### POI

宇宙中可以存在其他空间 POI，例如：

- 敌对飞船；
- 废弃飞船；
- 空间站；
- 残骸；
- 任务地点。

较远的 POI 只保留轻量级宇宙状态。

当玩家接近一定距离时：

1. 加载或生成对应地图；
2. 生成其外部视觉代理；
3. 将其加入当前场景；
4. 根据双方宇宙姿态计算相对位置和朝向；
5. 随距离继续缩短，在视觉上逐渐靠近玩家。

地图生成和加载应尽量采用事件驱动，而不要求所有宇宙对象长期保留完整 RimWorld Map。

其本质也和飞船一样，使用地图的相对渲染位置来表现移动

### 跳帮与地图切换

当两艘飞船满足跳帮或接舷条件时，可以在双方地图之间建立临时跨地图连接。

Pawn 穿过连接点时：

1. 从当前地图移除；
2. 在目标飞船地图的对应入口生成；
3. 保留必要状态；
4. 必要时将相机聚焦切换到目标地图。

切换后目标地图成为新的聚焦参考系。

双方飞船在宇宙坐标中的真实位置和角度不会因聚焦切换而改变。

### 太空战

地图内部的武器仍然可以使用 RimWorld 原有武器和 Projectile 信息作为发射来源。

太空战武器的弹丸不会真正存在于发射飞船和命中飞船的地图上。

在发射时，系统创建独立的太空弹丸状态，例如：

```text
SpaceProjectile
- position
- velocity
- source
- projectileDef
- launcher
- payload
- age
```

弹丸在统一宇宙坐标系中移动。

视觉上根据当前聚焦参考系显示其位置。

当弹丸与目标飞船发生碰撞时：

```text
宇宙命中位置
    ↓
目标飞船 SpacePose 逆变换
    ↓
目标飞船局部坐标
    ↓
对应 RimWorld Map 位置
    ↓
产生命中、爆炸或其他后效
```

这样飞船之间可以具有任意相对角度，而不需要实际旋转双方地图。

后续可以在该系统上继续扩展：

- 导弹；
- 制导；
- 点防御；
- 护盾；
- 拦截；
- 相对速度；
- 不同碰撞体。

第一阶段不要求一次完成这些能力。

## 一个典型玩家流程

一个包含主要系统的典型场景是：

- 玩家正在自己的逆重飞船内部正常建设和活动。
- 玩家进入驾驶模式。
- 玩家启动推进器，飞船开始获得速度。
- 玩家按 Q/E 转向。
- 玩家地图始终保持正常朝向，但星空和远处 POI 在画面中发生反向移动和旋转。
- 玩家逐渐接近一个敌对飞船 POI。
- 系统开始加载敌舰对应的地图并生成外壳代理。
- 玩家在自己的地图上看到敌舰从远处逐渐靠近。
- 敌舰本身可以具有与玩家完全不同的宇宙朝向，但只以旋转后的外壳显示。
- 双方进入射程后开始交火。
- 玩家飞船发射的炮弹进入宇宙空间，并沿独立弹道飞向敌舰。
- 炮弹命中敌舰外壳后，将命中坐标转换到敌舰局部地图，并在敌舰地图中产生伤害。
- 玩家继续接近敌舰并进行接舷。
- Pawn 从玩家飞船入口进入敌舰地图。
- 系统将聚焦地图切换为敌舰。
- 敌舰内部按照正常 RimWorld 地图朝向显示，Pawn 可以正常移动和战斗。
- 此时玩家自己的飞船在敌舰外部显示为一个具有正确相对位置和旋转角度的外壳代理。
- 玩家完成跳帮战斗后返回自己的飞船，聚焦参考系重新切回玩家飞船。
- 玩家脱离敌舰并继续飞行。
- 当敌舰远离活动范围后，其地图可以进入低成本状态或被卸载，只保留必要的宇宙状态。

## 预期限制

初期不要求：

- 对多张飞船地图同时进行完整内部渲染。
- 在非聚焦飞船中实时显示所有 Pawn、家具和内部活动。
- 真实旋转 RimWorld Map。
- 批量旋转飞船内部 Thing 的 `Rot4`。
- 让 Room、Region、电网或寻路跨越两艘飞船。
- 让自动工作系统跨飞船寻找目标。
- 普通搬运任务自动跨飞船执行。
- 在远距离下持续 tick 所有 POI 的完整地图。
- 一次完成所有第三方武器 Mod 的太空弹道适配。
- 一次完成导弹、点防御、护盾等高级战斗系统。
- 支持任意数量大型飞船同时完整加载。

非聚焦地图应尽可能被视为独立模拟空间，而不是另一块与当前地图真正重叠的 RimWorld 地图。

## 已完成调研

目前已经形成以下初步结论。

### 不需要旋转真实地图

玩家当前聚焦的飞船始终可以使用标准 RimWorld 朝向。

敌对飞船和其他飞船只需要在非聚焦状态显示外壳代理，因此不需要解决任意角度旋转整张 RimWorld Map 的问题。

聚焦切换后，新的聚焦地图重新按自身标准朝向显示。

因此连续宇宙旋转主要属于显示层和坐标转换问题，而不是 RimWorld Map 数据结构问题。

### `Rot4` 不应承担飞船姿态

飞船宇宙朝向应使用连续角度记录。

`Rot4` 只保留给飞船地图内部原生 RimWorld 对象使用。

固定轨道模式的四向吸附也只需要约束飞船的宇宙姿态，不要求修改整张地图中的 Thing。

### 统一宇宙坐标应独立于显示地图

飞船、POI 和太空弹丸都应拥有独立于 RimWorld Map cell 的连续宇宙坐标。

宿主地图或显示画布只是呈现窗口，不应成为宇宙空间的真实边界。

### RimExodus 可以提供实现经验

RimExodus 已经验证了多地图转移、聚焦切换、投影绘制和跨地图弹道等问题。

但新系统的空间关系是连续二维刚体，而不是六边形相邻地块，因此应复用通用经验和基础设施，不应直接套用地表邻接语义。

## 预期技术路线

### 飞船地图

每艘可进入飞船拥有一张独立局部地图。

地图内部继续使用 RimWorld 原生的：

- 格子系统；
- Thing 管理；
- Pawn；
- 寻路；
- 建筑；
- 房间；
- 电网；
- 存档机制。

飞船有效区域以外使用透明不可通行区域。

### 宇宙对象

飞船地图之外建立独立的 `SpaceObject` / `ShipState` 数据层。

该层负责：

- 宇宙位置；
- 朝向；
- 速度；
- 角速度；
- 地图引用；
- 外壳代理；
- 加载状态。

RimWorld Map 本身不保存连续运动结果。

### 坐标转换

建立统一坐标变换 API：

```text
LocalToUniverse
UniverseToLocal

UniverseToFocused
FocusedToUniverse
```

完整坐标链为：

```text
Thing / Cell 局部坐标
        ↓
飞船局部连续坐标
        ↓
Ship SpacePose
        ↓
宇宙坐标
        ↓
inverse(Focused SpacePose)
        ↓
当前参考系坐标
        ↓
显示位置
```

该 API 应成为飞船渲染、弹道、碰撞和跳帮位置转换的唯一坐标入口。

### 外壳代理

从飞船地图生成可缓存的视觉代理。

第一版只需要能够表达飞船整体轮廓，并支持：

- 连续平移；
- 任意角旋转；
- 缩放或远距离显示；
- 在结构变化后重新生成。

内部细节和高级 LOD 留待后续。

### 飞行模拟

驾驶输入直接修改宇宙状态。

第一版只需要完成：

```text
推力 → 加速度
加速度 → 速度
速度 → 位置
```

以及对应的角运动。

推进器、质量和转动惯量的具体计算方式在原型完成后再进一步设计。

### 地图生命周期

POI 根据与当前活动对象之间的距离选择：

```text
仅 Universe State
        ↓
开始加载 Map
        ↓
Map 已加载，可参与战斗/跳帮
        ↓
远离后休眠或卸载
```

具体阈值和保存方式需要结合实际性能测试确定。

### 太空弹丸

太空阶段由独立系统模拟。

RimWorld Projectile 负责提供发射参数和地图内部后效，宇宙飞行部分不依赖 Projectile 必须存在于某一张 RimWorld Map 中。

## 功能边界

该系统第一阶段的核心职责是验证：

> 多张独立 RimWorld 地图能否作为具有连续位置和旋转姿态的太空对象存在，并在玩家视角中形成稳定的飞船驾驶、交战和跳帮体验。

计划支持：

- 玩家飞船独立地图。
- 敌舰和 POI 独立地图。
- 统一宇宙连续坐标。
- 飞船平移和旋转。
- 以当前聚焦飞船为参考系的渲染。
- 非聚焦飞船外壳代理。
- 玩家飞船驾驶。
- POI 接近加载。
- 固定轨道 / 建造模式。
- 飞船之间的 Pawn 转移。
- 聚焦地图切换。
- 基础太空弹道。
- 命中位置映射回目标地图。
- 正常存档和读档。

初期不要求支持：

- 非聚焦飞船完整内部实时显示。
- 跨飞船自动工作。
- 跨飞船房间、电网或物流。
- 大规模舰队模拟。
- 完整高级太空武器体系。
- 所有第三方 Mod 的自动兼容。

## 当前阶段计划

本文档保留总体目标、技术路线和阶段路线图。

阶段内的源码调查、原型结果和具体实现细节应根据需要分别记录到独立文档中，并在实现推进后再回填本 Story。

当前暂按以下顺序推进。

### 1. 建立双飞船最小技术原型

首先只创建：

- 一张玩家飞船地图；
- 一张敌对飞船地图；
- 一个简单宇宙状态管理器。

不实现正式驾驶、战斗和 POI。

验证：

- 两张地图可以同时存在。
- 玩家地图作为正常聚焦地图运行。
- 敌舰可以使用简单外壳代理显示。
- 敌舰代理可以相对于玩家连续平移。
- 敌舰代理可以任意角旋转。
- 双方使用统一宇宙坐标，而不是直接保存显示位置。
- 将聚焦对象从玩家飞船切换到敌舰后，敌舰变为标准朝向。
- 切换后玩家飞船可以正确变成具有反向相对姿态的外壳代理。
- 多次切换聚焦不会产生明显坐标漂移。
- 存档读档后双方姿态可以恢复。

该阶段用于验证整个架构最核心的参考系模型。

### 2. 实现基础驾驶

加入：

- W/S 推进；
- A/D 平移；
- Q/E 转向；
- 速度与角速度；
- 基础推进器推力；
- 基础质量计算。

验证玩家飞船连续驾驶时，当前地图内部逻辑完全不受飞船姿态影响。

同时对宿主/显示地图尺寸进行性能测试，确认 `800×800` 是否有必要以及合理。

### 3. 实现 POI 与地图生命周期

加入最简单的太空 POI。

验证：

- 远距离只有轻量状态；
- 接近时生成或加载地图；
- 地图加载后生成外壳代理；
- 离开后可以休眠或卸载；
- 再次接近后状态能够正确恢复。

随后加入固定轨道 / 建造模式。

### 4. 实现接舷、跳帮与聚焦切换

在两艘飞船之间建立临时连接。

实现：

- 跳帮入口；
- Pawn 跨地图转移；
- 必要状态保存；
- 相机无感切换；
- 敌舰成为聚焦地图；
- 原玩家飞船转为外壳代理；
- 返回玩家飞船。

该阶段优先复用 RimExodus 已验证的跨地图 Pawn 转移经验。

### 5. 实现基础太空战

建立独立太空弹丸系统。

首先只支持简单直射武器：

```text
飞船地图发射
    ↓
创建 SpaceProjectile
    ↓
宇宙空间飞行
    ↓
飞船碰撞
    ↓
转换到目标局部坐标
    ↓
目标地图产生后效
```

验证：

- 双方具有不同位置和角度时仍可正确射击。
- 弹丸轨迹不依赖当前聚焦对象。
- 切换聚焦地图不会改变弹丸真实位置。
- 命中位置可以稳定映射到目标飞船。
- 未聚焦敌舰仍可受到正确伤害。

完成基础直射链后，再决定导弹、点防御、护盾等后续战斗能力的实现顺序。
