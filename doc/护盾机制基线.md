# 护盾机制设计基线

**状态：机制已接线，待游戏内验证与数值标定。** 本文是护盾玩法与结算契约；当前实现使用独立的 `DeltaV_ShieldGenerator` 建筑。地面圆盾复用原版 `CompProjectileInterceptor` 的容量、拦截和计时，专用子类仅将充能条件改为本机通电；`CompSpaceShield` 管理模式和太空线盾。原版 `GravshipShieldGenerator` 保持原样。初始数值只是试验值。

## 定位

护盾改变来袭攻击的路径和毁伤形态，不能替代装甲、点防或电力规划。太空侧尤其不使用“先耗尽一条总盾容才伤及船体”的规则：垂直入射可以直接命中；斜入射可能被折开；高穿深实心弹可能碎裂成仍能造成浅层、分散伤害的破片；导弹及侵入式 shuttle 穿盾而过。

一台发生器手动切换地面／舰内模式与太空模式，两种模式不同时生效。发生器的模式、几何参数、折射强度和必要长期状态属于建筑实例，须正常存读档；几何缓存与显示预览由同一组参数派生。

## 地面／舰内模式

- 提供类似原版地面护盾发生器的 **360° 单向射击护盾**，用于地面战斗与舰内跳帮防御。
- 玩家可调整投射半径。更远的投射距离提高持续耗电，但不提高盾容；护盾的吸收、击破和恢复沿地面模式自身的容量规则处理，不与太空折射规则混用。
- 原版 `CompProjectileInterceptor.Props.radius` 是 Def 共享配置，同时参与拦截与显示；实例半径不能通过修改共享 `CompProperties` 实现。施工前需沿原版 1.6 源码核对所有读取半径的路径，使实际拦截边界和显示边界一致。

## 太空模式：几何与单向性

- 发生器向**自身朝向**投射一条**有限线段**。玩家通过 gizmo 逐实例调整投射距离、线段偏转角（相对**护盾建筑朝向** −90° 至 +90°）、长度和**折射强度**。偏转角为 0° 时，盾线与建筑朝向垂直、正面法向与建筑朝向相同；偏转角改变时盾线和法向一起转动。距离与长度增加持续耗电；建筑朝向与实例参数确定船体局部线段，随后随 `SpacePose` 变换，不跟随舰首或屏幕朝向。
- 护盾建筑朝向是线段**正面法向的基准**，反侧为背面。只有弹道从正面穿越线段进入背面时才发生作用；从背面向正面射击和沿线段平行掠过均不受影响。正反面由护盾自身朝向与偏转角确定，**不从舰体内外、舰首、弹体阵营或发射者位置推导**。判定使用交点处运动方向与同一法向。
- 每一层护盾独立求交、结算和扣电。经过上一层折射后的弹丸、激光及破片继续沿所得方向运动，遇到下一层时仍适用完全相同的“正面向背面穿越”规则。没有专门为“已折射”对象开设第二套处理链。
- 显示预览必须直接呈现结算所用的线段、正反面及实际船体位置；投射线段不因美术外壳或屏幕投影改变物理位置。

## 折射与弹种

折射采用**液体到气体界面**式的方向变化：以线段从正面指向背面的法线量入射角，出射仍保持原切向分量的符号，并比入射方向更偏离该法线。发生器的折射强度控制这一偏转幅度；具体强度档位与等效折射率的映射留待数值标定。达到相应临界角时发生**全反射**。因而**垂直入射角为 0° 时，速射弹和激光方向不变，这一层没有防御效果**；若盾线恰与来袭方向垂直，直射弹便能穿过。

| 来袭对象 | 太空护盾的目标行为 |
| --- | --- |
| 速射弹与其他轻型实弹 | 折射后保留实体弹体与正常后效；后续护盾按新轨迹再次判定。 |
| 激光 | 发射 tick 内沿折射后的方向继续即时扫掠，视觉光束显示实际分段路径；不把它变成实体破片。后续护盾仍按同一规则判定。 |
| 重炮弹与轨道炮弹 | 相对于护盾法向的入射角不超过**该弹体类型可配置的碎裂临界角**时不碎裂，**仍按本层强度折射**；该角通常设在 8° 以内，垂直入射必定保持完整、方向不变。超过临界角且本层效果成功支付时，原弹体依自身类型规则生成新的破片 projectile。碎裂把集中穿深变为分散毁伤，不直接抹除伤害。每层按进入该层时的新方向重新计算入射角。 |
| 导弹与侵入式 shuttle | 不受太空折射盾影响，保持现有制导／侵入、点防与命中链；敌对 shuttle 仍是点防的主动拦截目标。 |

**碎裂是由原 projectile 类型定义的弹体变换，不是所有弹丸共用的通用属性复制。** 每个可碎裂的 projectile 子类自行指定碎裂角阈值、生成的新 projectile 类型及初始化逻辑，可按该弹体的设计继承或重新设定速度、基础伤害等属性，并设定散射角与生成数量。新破片作为完整的 projectile 进入现有飞行、折射与命中链；后续能否再次碎裂也由**新类型自身**定义。各类型的生成链必须限制总数和深度，避免多层护盾令弹体指数倍增。连续求交须避免同一弹体在同一盾面反复碰撞，同时保留真正进入下一层盾的机会。具体数值在实弹标定时确定。

## 电力与平衡

- 太空模式持续耗电随线段**投射距离和长度**增大；每次实际折射或碎裂另需支付该层的电力成本。**折射强度越高，该次脉冲耗电越高**。各发生器独立判定、独立支付，不存在一条全舰共享盾容。
- 本层蓄电不足以支付预定效果时，**先耗尽可用电量，再让该发生器短暂失效**；触发失效的这一发**不发生本层折射或碎裂，沿原轨迹通过**，但随后仍可与其他有效护盾相交。失效时长与恢复条件留待标定。多层盾可作为高耗电防御选项，但会与激光、轨道炮和点防争夺同一蓄电资源。
- 护盾不能保证单层免伤。调参以“正面入射仍要求装甲，导弹仍要求点防，多层斜置盾可以提高防护但明显增加电力负担”为基线，而不是以总吸收量对齐旧盾容。

## 单实现与施工验证

太空侧扩展 `SpaceCollision` 的既有扫掠求交；`SpaceProjectileService` 负责沿结果继续推进实体弹体、按原 projectile 类型创建新 projectile、在同 tick 追踪激光折线路径及显示，不建立平行的护盾命中系统。所有几何变换继续走 `SpaceTransform`／`OrbitSphere`。旧圆弧残余代码只保留给未配置 Delta-V 线盾的其他拦截器，正式盾建筑不走它。

验证至少覆盖：护盾建筑四向朝向与实例角度、垂直／碎裂临界角内／临界角外入射、同向平行多层盾与舰船机动寻找直射角、全反射、从盾背面向正面射击、线段端点、不同船姿与运动、连续两层以上折射、不同原 projectile 类型碎裂为各自指定的新 projectile、破片再折射、导弹与侵入式 shuttle 穿越且敌对 shuttle 仍被点防索敌、缺电及短暂失效、地面半径调整、存读档与非聚焦船壳预览。每组同时核对实际命中位置、视觉路径和逐层电量变化。

## 当前试验数值与实现入口

- 地面半径 8–40 格，默认 24.9 格；持续功耗为 `200 + 4 × (半径² − 8²)` W。原版拦截器通过每实例 Props 副本读取相同半径，盾容仍按原版 Comp 保存。
- 太空投射距离 2–32 格，默认 12；长度 4–32 格，默认 18；相对角度 −90° 至 +90°；折射强度 1–5 档，默认 2。持续功耗为 `200 + 12 × (距离 − 2) + 24 × (长度 − 4)` W，默认 656 W，最大距离和长度同时启用时 1232 W。单台覆盖上限使大船仍需分区布置多台。折射率比为 `1 + 0.2 × 强度`，达到临界角全反射。
- 逐层脉冲费用由 projectile Def 提供基础 W·d，再乘强度与本次偏折角比例；碎裂按全额。装弹机、舰炮与激光共用电池的蓄电链。缺额时耗尽该电网可用蓄电，本层停用 180 tick，当前弹直行；模式切换没有额外延迟。
- 重炮碎裂阈值 7°，散射 3 枚浅穿深弹；轨道炮 5°，散射 4 枚。破片为新 projectile Def，后续继续折射，但不再碎裂，限制数量和深度。
- 原版同图圆盾及容量状态只在地面模式使用；太空线盾由 `SpaceCollision` 同一碰撞扫掠链结算。`SpaceProjectileService` 按结果续飞、生成破片与分段激光。盾层实时图从 `CompSpaceShield.GetSegment` 取得，与碰撞几何同源。
- 切换到太空模式后，只要通电且同电网有蓄电，线盾立即显示并参与碰撞；断电、无蓄电或脉冲欠费后的短暂失效期间，线盾不显示也不拦截。切换模式没有额外计时门禁；地面圆盾直接沿用原版拦截器自身的充能、容量与开关状态。固定底座由建筑本体绘制，独立投射器由护盾 Comp 按建筑朝向与实例线盾角度旋转。半径、距离、长度、角度、强度在设置窗口拖动时立即预览，确认保留，取消／关闭窗口恢复进入窗口时的值。折射参考按载入的弹体 Def 和碰撞共用公式，以 30° 正面入射计算转向、碎裂／反射及单发脉冲电费；实际费用随入射角变化。持续功耗由原版电力说明显示。
