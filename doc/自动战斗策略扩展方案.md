# 参照 Cosmoteer 扩展每船自动战斗策略

状态：2026-10-29 已接入功能并完成当前离线回归；**性能及高速重炮规避效果未通过整体验收**。本文件保留已批准的目标与门槛，实际实现以[太空战架构 §9](太空战架构.md#9-npc-与-dev-验证)为准，测量与未通过项见[验证记录](../scripts/CombatManeuverSimulation/README.md#策略扩展验证2026-10-29)。依据[能力对照报告](自动战斗策略与Cosmoteer对照.md)及本机 Cosmoteer 0.30.5a 的规则、UI 文本与实际调用。

目标是让任意拼装舰船在真实武器和推进能力内，能自行选择有效射位、换位、协同夹击、分配火力并适应战损；玩家可以把这些能力组合成随船保存的条件策略。“与 Cosmoteer 一样聪明”以这些具体行为验收，不用运动外观、非零速度或未经测量的胜率代替。

## 1. 总体结构与保留能力

保留 `CompShipCombatAI` 的每驾驶台/shuttle 独立配置、主备用切换、复制和文件导入导出；保留玩家机动/火控独立权限、逐炮选敌、共同自动驾驶/MPC/物理及真实发射链。策略不保存地图、目标或武器实例 ID。

在当前模型上形成下列执行顺序，不另建平行 AI：

1. 读取本船能力、敌舰候选、友方交战意图，形成一次决策共用的事实。
2. 目标规则决定本船围绕谁交战。
3. 机动规则决定交战距离、本船朝向、攻击方位和运动方式。
4. 射位求解器把自动参数解析为具体目标，保留玩家明确约束；多船模块协调可自由选择的攻击方位。
5. 战术运行状态维护换位目标、节奏与阶段，向既有自动驾驶提交连续目标轨迹。
6. 逐炮规则决定各炮攻击对象与部件；实际推进、转向、发射、冷却、点防及命中继续由共同服务执行。

Cosmoteer 的武器几何选射位、方位换位、包抄、保存攻击设置、逐炮/部件控制作为功能基准。每船条件编排、评分曲线和独立策略文件是本项目继续保留的扩展。历史资料、玩家命令、NPC 模块和 Mod 参数分别标注，不再混成一个“Cosmoteer 算法”。

## 2. 每条机动规则表达的意图

| 配置 | 选项与含义 | 默认 |
| --- | --- | --- |
| 距离 | 自动；指定中心距；距离曲线。指定值优先，曲线不会暗改指定值 | 自动 |
| 主要武器 | 全部启用齐射武器；指定主/副武器组。用于射位覆盖评价，不自动关闭其他武器 | 全部启用齐射武器 |
| 本船朝向 | 自动；船首正对目标；相对目标视线的指定角度 | 自动 |
| 攻击方位 | 自由选择；目标船首参考的指定方位；世界参考的指定方位 | 自由选择 |
| 运动方式 | 自动换位；保持射位；持续绕行 | 自动换位 |
| 换位幅度/间隔 | 方位目标的随机偏移幅度、最短/最长间隔；显式填写，非隐藏噪声 | ±30°，5～10 游戏秒 |
| 协同包抄 | 允许同阵营、同目标的自动交战船协调攻击方位 | 开启 |
| 绕行方向 | 自动保持、顺时针、逆时针，仅绕行使用 | 自动保持 |
| 机动强度 | 允许使用的速度/加速度预算比例；不表示躲避概率 | 沿用 80% |

约定：目标船首方位 0°=敌舰前方、90°=敌舰左侧、180°=后方、−90°=右侧；本船相对朝向 0°=船首指向目标。世界参考采用统一 `SpaceTransform` 角度与运输规则，UI 明示参考系，不建立第二套战斗坐标。

显式攻击方位表示需要守住的方位，不被随机换位或包抄覆盖，只能与“保持射位”组合。编辑器将方位与运动方式作为同一组有效配置编辑，展示联动结果后由保存操作生效；XML 中出现“指定方位+自动换位/持续绕行”则拒绝导入，不静默改写。自由方位可选择三种运动方式。显式朝向不随战损自动撤销，无法保持时显示原因，玩家可用另一条战损条件规则改变它。

执行优先级为：玩家权限与临时命令→规则明确约束→自动参数求解→随机换位/协同建议；任何一级都不能绕过真实硬件、开火与碰撞门禁。临时命令仅覆盖其指定字段，其余策略继续生效。

| 玩家开关 | 默认执行范围 |
| --- | --- |
| 两者都关 | 不选自动机动轨迹、不分派自动齐射；保留既有手动及独立点防行为 |
| 只开机动 | 按距离、敌方武器风险、重叠和可达性选择射位/换位；不计输出及固定炮对准收益、不自动齐射 |
| 只开火控 | 逐炮选敌/部件并执行停火规则；不向驾驶提交轨迹或朝向 |
| 两者都开 | 完整射位、换位、协同和逐炮火控；手动集火仍不改机动目标 |

只开机动时，自动距离可继续读取主要武器的静态射程作为位置参考；这不赋予火控权限。显式朝向始终是驾驶约束，无论火控是否开启都执行。

## 3. 内置通用策略的行为

### 射位

默认以启用武器的有效覆盖建立交战距离和本船朝向。逐门检查炮口位置、最小/最大射程、安装与机械射界、预瞄、己方安全路径、弹药及实际供能。名义持续火力用于保留有用射位，临时冷却不使主炮从设计中消失；真实就绪输出单独计算，不能把预计开火当成已经发射。

初始搜索沿用八个粗朝向与重要炮口边界/固定炮提前量细化，所有符合筛选的武器参与评价；已有等价射位优先保留。常规更新复核当前射位并做有限候选改进，结构、能力、规则或目标变化再完整搜索，不在每 tick 枚举所有位置。

不同射程武器混装时，用户可指定主要武器组或直接设距离。其余武器可以择敌开火，但不强迫主炮舰为了副炮冲近。无可用主要武器时，保留锁定目标时的距离参考；无机动能力时仅运行可执行的火控/姿态部分，不循环请求不可能的平移。

本项目继续用中心距明确显示配置，不复制 Cosmoteer 边到边距离的数值。近距安全边界依据统一船体几何验证；自动候选先用包围范围粗筛，精查复用现有碰撞几何，避免把细长舰船一律视为实心包围圆。实际碰撞仍由原链决定。自动默认在可交战范围内选射位，玩家上升距离曲线仍可明确要求持续拉远，不另加隐藏远距封顶。

### 换位

默认将当前持续绕圈改为“到一个射位、保持一段时间、再换到邻近攻击方位”。单舰参照 Cosmoteer 的当前方位加 ±30°偏移；多舰优先选择其他攻击者方位的反侧，再加同样的有限偏移。偏移在换位事件上生成，保持到下一次换位或目标失效；规则检查、MPC 微步和帧刷新都不重新抽样。

5～10 秒是决策节奏，不能覆盖真实能力。计时按模拟 tick 推进，暂停冻结；发出换位目标时抽取下次间隔，到期且上一段必要制动完成后才允许普通换位，不要求每次完全停稳后另等 5～10 秒。换位路线先检查可用推力、反推、角加速度、转向期间主炮覆盖及碰撞安全；不可行时缩小偏移或保持当前可行射位，并显示原因。慢船不会因为定时器到期就持续左右反转：未完成上一段必要制动时保留当前目标；目标失效、明确规则切换与碰撞危险可以中断。

船首角与移动方位独立：侧推不足的炮塔舰可选侧舷迎敌，用主/反推完成换位；固定炮舰继续维持炮口提前量，只有能保持/重新取得射击窗口的换位才作为默认候选。取消“窄射界火力达到 25% 就一律站定”的分类法，也不要求所有炮塔舰持续绕圈。

持续绕行保留为玩家明确选择的战法。已测非对称往返先作为离线对照，不因为某一组闪避结果好就自动推广为所有船的默认战法。

### 防御与曲线

默认先保证可交战射位与真实可执行运动，再在同等或相近射位间比较敌方武器射界暴露、碰撞风险和友方占位；不让无界的“受击越低越好”重新驱动无限后退。明确玩家偏好可以改变这个默认取舍。

六条曲线保留为射位偏好：距离、真实就绪武器的可用输出、敌方武器风险率、敌武器预计最早威胁时间、重叠率、固定炮对准误差。输出评价对每门武器只取允许目标中的最佳值，不对多个敌人重复相加；其他敌人的威胁都可计入风险。

风险只读取敌舰武器、供能/弹药、冷却、朝向、转速及船体能力，不读取飞行中的炮弹。曲线预览和说明明确它是风险估计，不承诺某次加速一定躲弹；不恢复“0.5at²超过半径就几乎免伤”的评分近似。默认运动的擦弹效果用生产物理/碰撞离线模拟验证。

覆盖、机动、每条曲线和稳定代价分别显示。保留现有覆盖 0～100 分的明确尺度，将默认机动/风险的有界取舍写进说明；用户自定义曲线按其数值实际叠加，不做未告知的归一化。指定距离/朝向等约束先缩小候选范围；没有可行候选时报告约束冲突，不悄悄改玩家参数。

## 4. 规则事实与运行状态

条件增加明确作用域：本船、候选/当前敌舰、武器集合。机动与选敌规则可选择全部启用齐射武器或主/副某组，并用“任意满足/全部满足”判断逐武器冷却、弹药、供能、射界；火控还可使用“当前这门武器”。就绪比例继续是集合指标。

空武器集合不视为“全部就绪”；无敌舰时敌方条件不匹配，并显示缺少目标；不再用冷却 0、有弹 1、敌距 100000 等看似正常的值代替缺少事实。编辑器只开放该规则可用的作用域，XML 校验同口径。选择器只保存组别/类型等定义，不保存实例身份。

规则仍有序、首条匹配。可选的进入/退出阈值提供条件迟滞：未填写则使用同一阈值；使用迟滞时，当前规则只有在退出条件成立才释放，但更高优先级规则匹配可以抢占。UI 显示当前保持原因。换位计时独立于规则匹配，不能把规则扫描当作动作重启。

例子必须能够用 UI 表达并通过离线测试：

- 主组 1 的任意轨道炮进入真实冷却后，切到换位；该组全部就绪后回到主炮射位。
- 护盾低于 25% 时拉远，高于 50% 后恢复近战；不自动进入玩家返厂或跳帮流程。
- 主要武器组缺弹时，选择另一组作为射位基准。

运行时目标、部件锁、换位阶段、随机序列和曲线缓存由现有 controller/实例服务持有；策略文件只保存配置。正常读档仍按现有约定恢复为玩家自由漂移，NPC 在正常决策入口重新建立意图；不额外保存可重建缓存。

## 5. 选敌与舰队协作

增加独立的目标规则页，分别表达目标资格过滤和目标排序。默认优先正在构成威胁且本船有能力交战的敌舰，综合可用火力、距离、目标状态；重选有稳定门槛，不再“只要旧目标有效就永不重选”。玩家可偏好最近、威胁高、易收尾，或让机动围绕主要武器组最有价值的目标展开。

每轮决策顺序固定为候选事实→目标规则→机动规则→逐炮分派；用同一轮快照计算，不在几个模块间递归重选。机动目标与逐炮目标允许不同，但 UI 明示原因。逐炮选择默认允许其他敌人；可限定只攻击当前机动目标，适用于集火船。

拆开“可被攻击”与“有动力可驾驶”。有有效船体身份、敌对且有战术价值的静止平台/推进器全毁炮舰仍可被自动攻击；没有主台的碎片不借此恢复成船，残骸手动攻击沿用既有语义。默认目标规则可放过完全失去战斗能力的目标，玩家可显式改变此过滤。

协同包抄只读取同阵营、同目标、开启协作且正在自动战斗的船；不接管手动船，不改玩家明确攻击方位。第一艘保留可行射位，后续船选择空缺/相对一侧，分配结果有稳定保持期，避免双方同时交换位置。根据船体占用与路线可行性拒绝相互挤占，不建立全局可变静态阵位表；利用现有 controller 意图或 `UniverseManager` 实例服务，注销/换图/换目标及时释放。

这项能力是战斗包抄，不等于新增独立的全舰队巡航编队系统；战斗外编队另立需求，不作为本轮完整性前提。

## 6. 逐炮控制与部件目标

火控规则增加明确的“允许射击/保持停火”动作；输出/威胁/收尾权重只负责选敌，全部为零不再被误解成停火。逐炮命令和武器组设置继续独立，手动输入权限优先。

增加部件目标偏好：自动、船体中心、武器、推进、护盾、供能、驾驶台。自动默认在有可行命中路线的候选中选择高价值且暴露较少遮挡的部件；每门炮独立选择，并允许退回船体目标。部件被毁、移图或失去归属时失效重选，不用旧 ID 指向新物体。

沿用 `CombatTarget.SystemId` 的运行时部件定位与刚体点速度。候选部件索引按结构版本维护；目标路线查询扩展已有 `SpaceCollision`/武器安全查询入口，不另建碰撞器或从渲染网格推导。评分只估计可达性/遮挡及武器效果，不预演并替代真实伤害链，也不宣称能精确知道穿透后的伤害。

参照 Cosmoteer 补逐武器的自定义最大射程、限制射界和固定瞄准方向，默认沿用 Def 能力；玩家只能缩小允许范围，不能扩展硬件射程、转速或机械射界。实际瞄准、候选评价、预瞄显示和开火门禁共用同一有效覆盖查询。明确区分射界、固定指向与“允许开火偏差角”。逐建筑设置随 prefab/Scribe 保存；独立策略文件只引用武器组，不把一艘船的部件 ID 或安装位置导入另一艘船。

提供临时“指定交战舰/部件”命令和取消命令；临时覆盖只存在 controller，不能暗改保存策略。自动机动目标指定与现有鼠标手动集火明确分开，后者继续不改变防御机动。可排有限部件目标队列，目标失效跳过，队列用尽回到策略；保持停火时不得因队列而自动开火。

## 7. 编辑器与数据

驾驶台/shuttle 编辑器分为选敌、机动、火控、NPC 任务四类规则。普通玩家可直接使用通用策略；提供“主炮射位”“侧舷换位”“协同夹击”“远程保持”四个可复制模板，模板生成普通规则，不隐藏另一套行为。

机动编辑区提供三个独立的距离/朝向/方位示意，数值与预览使用同一状态；指定目标时可拖动射位预览并回填数值。默认展示简洁配置，高级展开条件作用域、曲线和迟滞。当前状态显示：命中规则、交战目标、下一射位、换位剩余游戏秒、逐炮选择，以及无法执行/被覆盖的原因。

策略格式升级为 **3**，Mod 版本不变。独立 XML 完整解析、校验后复制替换；旧格式明确拒绝，不做旧开发快照迁移。新增配置走现有逐建筑 Scribe；曲线仍显式存 x/y 点。输入限制包括有限数值、严格递增曲线、最短间隔不大于最长间隔、合法组别、作用域/指标匹配、互斥的方位与运动模式。无效导入和取消编辑不改变原配置。

当前主台读取配置、备用台继任、shuttle 起降与多船 prefab 保持原契约。玩家和 NPC 使用同一套战术解释；仅权限和 NPC 生存底线不同。不得为追求 NPC 相似行为暗加玩家策略覆盖，例如健康低于 50% 自动废弃用户朝向。

| `CompSpaceWeapon` / `SpaceWeaponService` / `SpaceWeaponShot` | 自定义覆盖约束的持久化及共同执行门禁 |
| `CompShipCombatAI` / 现有编辑窗口和侧栏 | 策略文件格式 3、编辑/预览、临时命令、选择原因 |

规则与轻量轨迹刷新沿用常规 30 tick，完整射位重评沿用 120 tick/事件失效，换位另用 5～10 秒节奏。缓存按现有结构/能力/配置版本失效；同一决策共享敌舰、部件和武器观测，不为每条规则重扫地图。炮口、候选和友方意图均限制枚举量，武器出力查询不随角度×距离×部件无界增长。

本项目不照搬 Cosmoteer 的后台线程机制；RimWorld 对象访问保持既有主线程契约。结构变化、新档、归档/恢复、主体删除都必须有释放或重建入口。调试沿用 Development 状态边沿日志，不增加逐 tick 常驻日志。

## 9. 实施顺序与验收门槛

每一阶段完成编译和对应离线检查再进入下一阶段；阶段划分是交付顺序，不是把其余项目排除出完整方案。

| 阶段 | 实现内容 | 必须通过的检查 |
| --- | --- | --- |
| A 配置与目标基础 | 条件作用域、真实武器组事实、静止目标资格、目标重评、模型复制/校验 | 轨道炮真实发射后才触发冷却条件；空组和无目标不伪装就绪；静止炮台可选；更优目标可切换且不高频摇摆 |
| B 完整射位与换位 | 距离/朝向/方位分离；保持/换位/绕行；目标参考系；主炮组射位 | 左右舷固定炮与混装武器能建立可射击姿态；方位保持随敌旋转/保持世界方向两种语义正确；时钟不会被重规划重置；低推力船无虚构加速 |
| C 多舰与火控 | 协同包抄、逐炮部件偏好、停火动作、临时目标队列和覆盖约束 | 两船占不同可行侧面；不会持续互换阵位；同船不同射界分别开火；停火规则零发射；失效部件/队列正确回退；限制射程/射界同时影响选择与执行 |
| D 编辑与持久化 | 完整 UI、预览与分项原因、模板、XML3、Scribe | 多船 prefab 配置独立；重复实例化/存读档/归档恢复/主备用损毁继任/shuttle 起降保持配置；无效导入不覆盖；取消无写入 |
| E 效果与性能 | 真实战机运动对照、场景矩阵、多舰成本；文档收口 | 不把“运动了”作为规避通过；输出原始数据、差异和失败场景，不能只留成功案例 |

战斗效果对照固定船体、推进、炮弹及初态，比较当前 Circle、保持射位、Cosmoteer 式换位、可达性约束后的换位、已测非对称往返；覆盖 30/35/45 弹速、100/115/140 距离及多个固定随机种子。记录船体包络擦弹比例、实际开火窗口、维持距离比例、朝向误差、换位完成率和反向次数。固定射手实验之后追加双方移动，区分几何擦弹与护盾/拦截/实际伤害。**换位没有降低重炮命中时，应如实报告，不把它包装成闪避成功。**

必须覆盖固定主炮、全炮塔、主推强侧推弱、左右舷炮、混装射程、主炮冷却、两舰夹击、多敌分火、静止炮台、无武器船、战损低推力和四种玩家开关组合。默认双方有交战能力时不因风险分持续脱离；用户明确拉远策略仍生效。手动集火不改变防御机动，玩家不自动返厂/跳帮。

性能用同机、同输入、相同 1/4/12/24 舰配置测量战术/火控和 MPC 分项均值、P95及峰值，并与修改前基线比较。先报告结构缓存热态，再报告结构变化的重建成本；离线耗时不冒充游戏 FPS/TPS。默认策略热态的战术+火控每模拟秒总耗时均值及 P95 以不超过同场景旧基线 1.25 倍作为初始验收门槛，超出则优化或明确列为未通过，不能只写“勉强可接受”；新增高级部件搜索另列增量。新增候选处理必须有计数上限和错峰，不能靠降低物理或武器 tick 率通过性能检查。

交付运行 `dotnet build Source/DeltaV.csproj -c Release`、扩展现有离线回归与模拟；更新太空战架构、代码入口索引、README 和对照报告状态。游戏启动、手感、实战命中率和运行时性能由用户验收。保留当前未提交改动，不自动提交、不修改 Mod 版本号。

## 10. 本方案不承诺的结果

物理条件不给规避余量时，Cosmoteer 式机制也不能保证小船躲炮。此次扩展不自动改弹速、伤害、推力、质量或船体；这些只作为离线对照变量。完成后应先达到参考机制的射位、换位、包抄和玩家表达能力，再依据实测决定武器平衡。

不在本轮新增完整战略任务语言、战斗外舰队编队、任意脚本执行或全场多步最优博弈求解器。玩家仍通过有限、明确、可验证的规则和战术参数设计行为。
