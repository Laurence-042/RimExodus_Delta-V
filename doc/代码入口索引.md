# 代码入口索引

按任务查阅相关小节，用于定位当前唯一实现及局部接线约束；跨任务规则见 [AGENTS.md](../AGENTS.md)。复杂机制以链接的专题为准，数值、玩法说明和验收进度只在各自权威文档维护。修改入口时更新对应条目，不把完整清单搬回 AGENTS。

## 宇宙、坐标与船体

- `UniverseManager`：objects、ID 分配、Map→SpaceObject、聚焦、tick/update 总装和帧动作队列。`ObjectById` 与 `SpaceObjectOnMap` 使用可重建的实例索引，注册、注销、表示替换和读档时同步；POI 直接换图后的首次查询从 objects 补入 Map 索引。弹体容器注册不推进真实结构版本。`PlayerReferenceObjects` 是 POI 距离与跨星区生成的唯一玩家参考集合，只筛选含 Ship tag 且 `HasFaction(player)` 的对象；按 objectId 跟踪星区，运行时 hint 由本实例持有。
- `OrbitSphere`：球面移动、弧距、切空间基和 sphere↔tile。
- `SpaceTransform`：全部坐标、速度、刚体点和停放锚转换。Map 连续点互转使用 `MapPointToUniverse/UniverseToMapPoint`，停放 root 换算使用 `ShipOriginFromPlacementRoot`；调用方不得自行拼接旋转、平移、中心或 designator 偏移。
- `ShipRegistry` / `ShipBase` / `FoundationShip` / `ShuttleShip`：`StructuresOnMap/StructureCells/HasStructure` 为侧边栏含无主台结构的查询入口，按共同结构版本缓存并随 Map/换档释放；船体身份、状态、脚印、锚、朝向、派系与火控的共同契约；`BuildThrusters/Weapons/CollisionCells/CanDriveIn/PrepareThrust/RolesIn/Transfer/NotifyLanded/CanBoard` 提供船体能力与搬运差异，对象层只汇总能力，详见解耦架构 §2。`AllShipsOnMap` 唯一枚举成员，`ShipByIdentity`、`ShipOf` 与 `DefaultVesselOnMap` 统一解析身份、归属及默认选择。`Ship` 仅为基架控制域查询快照，`FoundationShipsOnMap` 仅供结构操作。`PilotTarget` 委托共同事实给基类；停靠 shuttle 仍是船成员，但不能驾驶宿主。
- `SubstructureOwnership`：基架事实、归属、连通认领和结构版本；`FoundationAt/HasFoundation/CellsOnMap/CollectConnected` 是结构查询的共同入口，只读原版 foundation 层，不以覆盖地板的 `TerrainAt` 判断基架。质量算法仍只在 `ShipPhysics`；归属、质量报告、控制域、剪影与碰撞共用基架事实，船体能力与角色缓存也共用结构版本失效判定，无时间重扫；`HasSupport` 与整图真实底层查询 `HasNaturalGround` 均按结构版本缓存，避免生命周期及驾驶热路径重复遍历全图；`Patch_ShipStructure` 汇总纳管地图的建筑生成／移除与地形变化失效事件。基架与归属同步移除（`RemoveFoundation`/`RemoveGravshipTerrainUnsafe` postfix → `NotifyFoundationRemoved`），「归属仅在有基架的格上有意义」恒成立。
- `CompDeltaVPilotConsole` / `Designator_ReassignSubstructure` / `Alert_MissingPrimaryConsole`：主副台认领、玩家改划及缺主台提示。主台查询共用 `ShipRegistry.MainConsoleForOwner`，玩家整域保护共用 `SubstructureOwnership.CanReassign/Reassign`，内部转移仍走既有写入链；副台在归属通知及 Spawn 后同步脚下身份，不反向盖章。主台替换复核现有主台管理权限；原版占领、同向副台继任保持原规则。警告通过 `ShipRegistry.MissingPrimaryConsoleTargets` 从玩家建筑所在基架域派生，不保存警告状态；面板无主台提示读取当前选中的结构归属。规则详见解耦架构 §3.2。
- `SpaceObject` / `MapSpaceObject` / `ArchivedSpaceObject` / `DriveSubject` / `DriveInfo`：统一驾驶身份、只读信息与预览、执行、清理、漂移与收敛；主体按船归属或 shuttle 身份区分。推进器布局由船体子类提供，随共同物理报告重建；对象角色按共同结构版本缓存，点防保留 Projectile／Shuttle tag 快速筛选，基架船不贡献 Shuttle 角色；对象层保证每 tick 单次积分，分离后通过主体重新解析当前容器。
- `ShipPhysics`：质量/惯量、推进器、分配器、阻力和积分的唯一算法。`ReadDriveInfo`／`ExecuteDrive` 是实时动力状态读取边界，`DriveInfo` 预览与求解消费已读取的数值模型；`DriveControl.FromInput` 与期望力共用对象执行入口及按模型／动力版本／指令复用的分配结果，机制见基础驾驶专题。
- `UniverseManager.SetFocusedWithCamera`：聚焦与相机连续性交接；拆分的跟随规则见解耦架构 §8.1。
- `Patch_Game_CurrentMapFocus` / `UniverseManager.ApplyCameraZoomScope`：同一 `CurrentMap` setter 补丁以目标图处理宿主图门禁、休眠唤醒和切图前缩放，完成后按实际图同步缩放并通知散落服务；不读取可能已被删除的旧当前图。地表与太空图分别使用图外与 Delta-V 上限，原版逆重过场沿用当前图上限；SCS 设置写入由可选补丁即时同步。`Patch_CameraCenterClamp` 仅在 Delta-V 图跳过原版 `CameraDriver.Update` 的地图边缘镜头中心 clamp；`Patch_ExteriorLightingScope` 随镜头重建原版地图外光照遮罩网格。`ShipStatusPanel` 从当前结构派生重新聚焦位置与运动数据，无主台位姿由 `ShipRegistry.StructurePose` 给出。
- `HostColonistBarVisibility` / `Patch_ColonistBar_CheckRecacheEntries` / `ColonyGroupsBarVisibility`：太空图无人分组用同一 `ShouldHide` 判断，分别过滤原版与可选 Colony Groups 的栏缓存；专用宿主、弹体及闲置池图始终隐藏。对象注册、注销、池租还与设置切换使两种栏缓存失效；Colony Groups 反射签名不符时仅跳过可选补丁。

## 驾驶与跨图转移

机制见 [飞船与 SpaceObject 解耦架构](飞船与SpaceObject解耦架构.md) 和 [在线 MPC 自动驾驶](在线MPC自动驾驶.md)。

- `DeltaVMod.DrawGeneralTab` / `PilotService.RebuildPilotKeySet`：Mod 设置通用页提示原版改键路径；`KeyPrefs` 保存按键，驾驶输入抑制在 `KeyPrefsData` 换代后刷新。默认绑定与分类由 `DeltaV_KeyBindings.xml` 定义，不建第二套按键存储或编辑窗口。
- `PilotTarget` / `PilotService` / `ShipControlService` / `ShipController`：普通船与 shuttle 的统一驾驶层；每个带种类的 `DriveSubject` 身份由实例注册表持有一个玩家或 NPC controller；身份索引、容器成员和船体设备缓存按共同结构版本失效，换图／换表示／注销与换档统一清理，基类调度每船火控与炮手事件；`BindShip` 同步刷新战斗缓存与已开启的驾驶目标，使当前会话跟随换图和主台继任。侧边栏操作由对应 controller 注册，经 `ShipBase.Collect*PanelActions` 委托，公共驾驶／对接操作放控制器基类，跳帮艇侵入操作放玩家子类；面板只负责显示和布局，无主台时不得通过面板自动认领。两类身份锚通过同一 `ShipCombatState` 保存火控模式（默认自动）与武器组，`SpaceAimController` 只在手动集火且为聚焦图所选船时提供输入和预瞄。
- `CompShipCombatAI` / `CombatStrategy` / `CombatRuleOptions` / `CombatTacticSettings`：每主台或 shuttle 持有 XML3/Scribe 配置；目标、机动、逐炮规则使用真实作用域与进入／退出阈值。`Dialog_CombatStrategy.Options` 提供模板、选择器和高级条件，`Dialog_CombatPose` 拖动距离／朝向／攻击方位；`Dialog_CombatOrders` 发送运行时交战目标／部件队列。`CombatAttackPose` 选择主要武器覆盖射位，`CombatReposition` 保存逐船换位时钟和方位，`ShipAutoCombat.Tactics` 组合风险／协同／路线检查并提交 `CombatTrajectoryIntent`；船心轨迹用 `AlignLocalPoint` 转成共同自动驾驶的地图原点契约。`ShipFireControl.Strategy` 管理目标重评、逐炮停火、部件与观测缓存，`CombatWeaponThreat` 从真实炮口生成武器风险，`CombatTarget` 的部件失效不会悄悄落到船心。`CombatWeaponCoverage` / `Dialog_WeaponCoverage` 保存和编辑单炮覆盖约束，瞄准、预览与 `SpaceWeaponShot` 共用。细节与验证界限见 [太空战架构 §9](太空战架构.md#9-npc-与-dev-验证)。
- `ShipControlService.Tick` / `ShipController.TickCombat`：调度每船齐射及点防；火控在齐射后经 `CollectInterceptionCandidates` 一次筛选本船敌对可拦截对象，各炮共用，无候选早退。有效锁持续沿用，空锁等待重试；牵引器继续消费散落服务索引。候选缓冲只活到本次调用结束；锁清理保留结构版本及显式归属事件。详细点防节拍和 `pdCandidates`／`pdSearch` 探针口径见太空战架构 §4.2；自动齐射复用 `TryGetIntent` 已解析的目标。
- `ShipAutopilot`：固定/随动/战斗轨迹共用任务表；不读取 Map、归档字段或具体对象类型，统一读取驾驶信息并提交期望力／力矩；实体与无图主体共用任务表和 Step，只替换主体及能力数据来源，不识别返厂策略；制导经同一 `IAutopilotGuidance`，战斗轨迹不建立独立出力链。`CombatTrajectoryIntent.startTick` 保持战斗轨迹的固定时间原点，每次自动驾驶微步沿同一轨迹采样，只有真正重规划时更新。持续绕行朝向以目标视线为基准；固定炮的相对角由真实炮口与提前量确定，不能借用目标船自身角速度。
- `ShipFlightTransitionService`：共同搬运、真实出力分离及源图善后；`TransferShipToPocket` 统一两类船起飞／分离／方向罗盘的相机交接；`FinishEmptyWorksite` 在搬运及结构事件中处理最后一船离开后的残骸。`ShipRegistry.RequiresOwnPocket` 统一预检与执行时的分离方向；普通飞行图断片逐块搬出，`SpaceScatterService.LooseCargo/ScatterLoose` 处理无承载内容，失败保持出力门禁。已证实无残留块的结论按图和 ownerId 复用；基架增减或归属变化只清除该图结论，下次出力前重算。散落货物首次按图建索引，此后由 ThingGrid 与承载地形事件逐格维护；注销图和换档释放索引。排队分离复核源容器表示版本及当前所属 Map。
- `DockingCompletion`：普通停靠与侵入共用落地／聚焦／源图收尾；不再弃置源图人员，交回共同残留处理。转移待收尾集合负责存档、尺度和生命周期门禁。
- `LandingApproachController`：`DriftSyncPlan` 只保存目标身份与最近四向，`SpaceTransform.MatchingDriftPose` 统一线速度／方向参考，`MatchesMotion` 与任务就绪共用判据；无位置锚、落点幽灵或虚空动力。`OrbitalWorkService` 在开始作业事件中才生成 `DockingPlan`，按当前相对偏移求最近整数根格并立即搬图；`DockingPlan` 只是本次命令的整数落位数据，没有后续驾驶或鬼影阶段。共同作业以发起船为基准，复用该整数变换的逆变换放置目标船；停靠仍使用目标图基准。软对接的 `SoftDockService.AlignmentReference → SpaceTransform.AlignLocalPoint` 同时供真实推进器 MPC 与位姿插值读取，按端口双菱形交叉重合保持站位；`UniverseManager.GameComponentTick` 在物理积分后调用 `SoftDockService.ApplyAlignmentAssist`，仅无实际引擎出力且菱形误差在捕获范围内时按距离平方倒数插值。沿用既有任务 tick，无新增候选轮询。原版停靠／重力复核、单船／多源工作图也由玩家事件编排；旧战术选点接管已删除。
- `ShipOrientation`：普通对接、侵入落位及速度同步的最近四向吸附入口；`SnapAngle` 委托 `Rot4FromAngle`，放置旋转继续经原版 `Rot4.Rotated`。
- `Building_DockingPort` / `Building_DockingChannel` / `DockingChannelPreview` / `Patch_DockingPort`：单格对接口、非基架气密通道及限定门房间的真空语义；`TryFindChannel` 共用生成／建造及双方降落预览／事件复核，`RetractChannelsFor` 共用双方脱离清理。建造朝向不受原版门绘制自动转向覆盖；到达通知只作用于本次目标图。完整机制见星区架构 §7。
- `GravshipInterop`：原版 Gravship 私有逻辑镜像、designator 适配、预览和 `CaptureDomain/StripDomain/PlaceIntoMap`。
- `BrakingRecoveryState`：`ShipAutopilot.Flight` 的运行时制动恢复状态与重试调度；复用同一个 MPC 的位置／速度模式，详见 [在线 MPC 自动驾驶](在线MPC自动驾驶.md#战损后的制动恢复)。
- `SpaceShuttleService`：shuttle 起飞、侵入指挥与命中落点；空图处置和外部销图使用共同转移／生命周期入口；侵入由 `SpaceProjectileService` 解析目标并登记共同碰撞工作项，`ShipAutopilot.Intercept` 经真实推进器出力，跳帮后效的落地与普通对接共用 Gravship 转移和 `DockingCompletion`。
- 搬运约束：designator 输入格不等于最终 root；捕获与剥离共用同一份绝对 cells，不从旋转后的 `Gravship.Foundations` 反推源格。捕获会消费区域、指令和携带物，合法性和生成预检必须先完成。跨图后旧 `Ship` 快照失效，按身份重新查询；`SpaceTransform.PoseAfterPlacement` 从最终放置根格统一派生容器位姿与刚体点速度。

- `CompSoftDocking`：每个对接口的配对、几何、伸展进度、接通判定与吸附事实源；发起端保存对端引用、进度和接通标志，对端只持有可重建的运行时反向引用。`UniverseManager.SoftDockEnabled` 通过游戏组件 `ExposeData` 保存开关；`SoftDockService` 读取该开关，持有端口索引和自动驾驶／入口接线，读档后重建索引，按已配对每 tick、未配对每 15 tick 调用 comp；物理积分后的吸附遍历有效配对，不以推进器制导任务是否仍在运行作为门禁；主动关闭清理状态。`SoftDockPortals` 将门绑定为原版 MapPortal，直接使用 Dialog_EnterPortal、Lord、原版入口／搬运 Job；关闭、断连、搬离时 CancelLoad 并销毁入口。原版 60 tick 装载检查与工作分配已获准；`Patch_SoftDockPortalDialog` 仅拦截失效入口的窗口提交。`JobDriver_SoftDock` 仅含远端 CompHackable 操作。
- `Patch_SoftDockExitMap`：只过滤原版 `JobGiver_ExitMap` 为非玩家 Pawn 生成的软对接入口撤离结果，作为守舰职责缺失时的防循环兜底；显式入口 Job 与原版其他入口不受此过滤。
- SpaceScatterService：毁伤、搬运收尾、内容移除与聚焦切换事件生成／回收散落图；同 SpaceProjectileService 使用 SpaceMapPool，无定时扫图。牵引通过 CompSpaceTractor 的 ISpaceWeaponLaunch → Scatter.TryLaunch/Pull 接入，Scatter.Tick 在容器漂移后按接收船局部坐标插值，收货复用深钻井 GenPlace.Near；同一运动与回收链供自动／手动使用；进度见 [对接设计 §13](对接与舱外作业重构设计.md)。

## 武器、弹体与护盾

机制见 [太空战架构](太空战架构.md) 和 [护盾机制基线](护盾机制基线.md)。

- 工程设备复用 `CompSpaceWeapon.manualOnly`、手动组、`SpaceWeaponShot` 与统一光束碰撞；惯性耦合束逐 tick 支付及结算、跳过全部盾面，后效经 `SpaceObject.CoupleMotionWith → ShipPhysics.CoupleMotion` 交换冲量，采矿后效由 `SpaceImpactEffects` 的 Engineering partial 执行切割及原版拆除产出，惯性耦合和采矿不负责拖曳／对接／地图扩容。牵引器 `SpaceTractor` 使用同一发射事务的 ISpaceWeaponLaunch 能力和月池放置门禁，不进入弹体／碰撞后效链，`ShipFireControl` 保持有效锁定、失效后复用 30 tick 重选，候选来自散落服务的事件索引。机制以太空战架构 §5.9 和对接设计为准。
- `SpaceWeaponService` / `SpaceWeaponShot`：武器索引、共同 `ApplyControl(WeaponControlCommand)` 执行及唯一 Prepare→Launch→Commit 事务；只消费明确指向与触发意图，手动导弹锁定仅在发射准备中调用共同射线查询；逐发弹药、装弹机基础脉冲、沿物理链逐段预留的加速脉冲、电容放电与末端炮口在此一次性冻结，成功发射后统一扣费；缺电加速段跳过且不增加弹速，后段仍继续检查。电容武器插件仅通过抽象挂件基类的直供接口参与开火，独立的 `CompSwitchableBattery : CompPowerTrader` 管理限速充电、储能、存档和可开关的电网回送。锁定弧与发射轴分离，请求携带手控来源，武器实例分别保存手控与自动偏离角，事务按来源检查目标与实际炮口/固定轴夹角；地面模式原版炮塔读取自动角度。Traverse 无独立逐 tick 扫描，只按火控或原版图内目标命令转向；载人岗位统一使用原版 `CompMannable + ManTurret`，操作人只读原版 Mannable、位置只读原版交互格；预留人选存武器 comp，补位由统一原版 Job 清理通知及武器/Pawn 事件触发。`SpaceWeaponManning` 仅提供无状态的自瞄开火、成品交互点、实例建造保护和岗位连线适配，不另存操作人或镜像 Mannable getter。Mannable/Traverse/Magazine/Attachment/加速件以正交 Comp/能力接口参与，第三方不得建立家族特判。
- `SpaceWeaponControl.cs`：不可变指向／触发命令与武器执行边界；纯手动转向早退，冷却／操作／电力和弹药检查由武器负责，执行重入门保护当次能量账本。
- `SpaceWeaponModel.cs`：`SpaceWeaponLayout` 是挂件、弹仓与加速连接的唯一缓存；`SpaceWeaponEnergy` 是实时可复用预留工作区；`SpaceWeaponBallistics` 是自动、点防和手动预瞄的共同精确参数／提前量入口。生命周期及统计口径见太空战架构 §5.1、§4.4。
- 武器归属热路径：`CompSpaceWeapon.OwnerShip` 缓存完整脚印归属，`ClearRuntimeModel` 负责释放；`ShipFireControl` 齐射／点防共用本次组掩码，避免重复解析所属船。失效与实时切组契约见太空战架构 §5.1。
- `PlayerInputStamp.cs`：`UniverseManager.PlayerInput` 持有 `PlayerFrameInput`，驾驶与瞄准首次消费时按帧采样，UI 门禁单独失效；OnGUI 只负责按下授权，tick 执行前核对当前会话。释放及边界见太空战架构 §6.1。

- `Building_SpaceTurretGun` / `DefModExtension_SpaceTurretArt`：替换指定炮塔的旋转顶部材质，位置、角度和绘制继续走原版 `Building_TurretGun`/`TurretTop`；Def 固定为仅点防的 1×1 激光炮不触发原版同图索敌，以免发射原版机炮弹。

- `CompMissileAutoloader` / `CompMissileMagazineFacility` / `SpaceMissileMagazineGeometry` / `CompLoadedProjectileGraphic`：唯一 1×3 无人导弹架使用原版 `CompChangeableProjectile` 的一发待发状态和弹种筛选；前一格嵌墙、后两格在船内。1×2 气密导弹仓是普通 `Building`，由设施 Comp 保存按弹种计数的内部库存、上限与退出命令，`WorkGiver_LoadMissileMagazine` 负责把实体导弹装入。左右槽位由发射架 Def 声明；原版设施 Comp 登记链接，建造与运行时复用同一几何判定，同归属同派系才自动补弹。开火、库存、筛选、供电和归属事件合并到下一游戏 tick 按发射架 ID 顺序补弹，双架共享仓逐架消费。发射架保留三层整图，以 `Patch_MissileLauncherWallLink` 使原版墙在 `LinkGrid` 中与其相连。导弹物品通过 `DefModExtension_SpaceMissileAmmo` 指向宇宙弹体，三层绘制中层读取同一 `SelectMagazine()` 结果；不改共享 `GraphicData`。
- `Command_BatchSetting<T>` / `Command_BatchToggle<T>`：武器、挂件、护盾、导弹仓的可批量设置命令走原版 gizmo 合组时收集目标，点击或弹窗确认后写入整组；护盾的实时预览窗还保存每台原值供取消恢复。针对船或对接口的一次性动作保持各自入口。
- `SpaceProjectileService` / `SpaceCollision` / `SpaceImpactEffects`：含冷发射程序的宇宙弹体、统一碰撞与联合命中效果链；普通弹体每发新建 SpaceObject，侵入 shuttle 接管现有容器与地图，复用同一弹体碰撞工作表而不归入普通弹体图池；`Projectiles.Tick` 在自动驾驶前记录扫掠起点，侵入运动只由对象驾驶接口积分。炮口闪光、点火尾焰/烟迹和命中视觉只由弹体服务（含 Visuals partial）登记并在前台层绘制；逐次接触读取 `SpaceCollision.VisualContact` 快照，不另建弹道。炮塔绘制后坐共用 `CompSpaceWeapon.VisualRecoilOffset`。完整弹芯以效果 `penetrates` 启用预算续穿，`ApplyToDefender` 返回实际吸收后的剩余比例；`SpaceCollision` 同 tick 从原交点继续唯一求交链，`SpaceProjectileService` 持有跨 tick 剩余倍率，不再重复衰减速度和穿甲。盾面效果与发生器实体效果分开解析；轨道破片不继承母弹贯穿能力。基架毁伤统一由 `SubstructureDamageUtility` 提供：命中／破片／采矿后效调用 `TryDestroy`，`CanDamage` 复用建筑保护判定；原版毁伤经 `Patch_SubstructureDamage` 在专用毁伤入口共用清理。`RemoveFoundation` 补丁只同步归属，承伤契约见太空战架构 §3.4。重炮逐发诊断由 `SpaceWeaponShot` 在真实发射时附加，并由 `SpaceProjectileService` 结合 `SpaceCollision.VisualContact` 报告实际船体命中与越靶距离。
- `CompSpaceShield` / `CompDeltaVShieldInterceptor` / `SpaceShieldRefraction` / `SpaceShieldProjectileBehavior`：独立 `DeltaV_ShieldGenerator` 的守卫、动能、电磁三模式逐实例状态、几何、逐发电费和分层投射器绘制；原版发生器保持原样。专用拦截器保留原版容量／拦截，守卫盾容 3000、新建满盾、每累计通电一游戏小时免费充满，恢复倒计时保存剩余 tick，断电／关机／搬运／归档暂停，期间由原版 `CompRefuelable` 实体白银 1:1 补充；守卫由原版 `CompPowerTrader` 自动接电、持续消耗 10 W，断电仍可用已有盾容拦截；新建时满盾且可立即切换，从其他模式切回守卫后才锁定至累计通电一小时，半径由实例化的原版拦截器 Props 提供。动能线盾只碎裂非制导实弹，弹体 Def 确定破片，盾实例确定速度变化；破片 Def 与实际速度决定毁伤。电磁线盾只折射激光，`SpaceShieldRefraction` 的同一公式供碰撞与说明使用。盾交点只在 `SpaceCollision` 求解，逐发脉冲从本机电网电池按实际支付量扣费；欠费本发仍碎裂／按已付电量偏转，随后线盾短时失效。线盾显示、选中预览、碰撞与扣费只读取 `CompSpaceShield.State`，盾段几何共用 `GetSegment`。设置窗口拖动时写入实例参数，关闭未确认时恢复旧值；不修改 Def 共享 `GraphicData` 或原版盾 Props。具体契约以 `doc/护盾机制基线.md` 为准。
- 采矿出料结果由 `SalvageOutputScope` 限定同步调用范围，`Patch_SalvageOutput` 观察原版放置返回值并替代作用域内重复失败警告；提示限频归 `SpaceWeaponService`，不增加落点或容量检查。

## 渲染与视图

- `ShellRenderer` / `MapOverlayRenderer` / `ShellHullVisuals` / `ShellDrawBackend` / `ShellRenderRuleDef` / `ShipSilhouette`：整壳分层、地图内容收集、非聚焦基架／舱壁外观、绘制后端、Thing 外壳绘制配置和剪影。`MapOverlayRenderer` 只收集、排序并同步交付命令，`ShellLayer` 管理前后层及槽位，`ShellDrawBackend` 是当前 1.6 的命令缓冲提交与清深度入口。一般入壳 Thing 的静态层走原版 `Thing.Print`，外壳命令剔除 `CompPower.PostPrintOnto` 所加的电器接线材质与原版太阳阴影材质；实时捕获也剔除太阳阴影。基架及其地板沿用当前地形材质，原版 `SectionLayer_SubstructureProps` 负责基架侧边。`GravshipHull` 沿用原版图集及材质，四向变种、按对应两侧及对角基架填充的原版 CornerFiller 补角及相邻地板格内接缝由 `ShellHullVisuals` 对同一基架／舱壁邻接计算驱动（有基架侧始终连接），按 section 缓存网格、结构变化使邻格及跨 section 失效；太阳光向直接投影到对象切平面，经 `SpaceTransform.RotateInverse` 转入船体局部系，只更新斜面和接缝的逐边连续明暗强度，不重建几何；切向光近零时使用平滑船体局部补光。Odyssey 舱壁斜角直接取原版 `SectionLayer_GravshipHull` 网格及材质，实时层经限定作用域捕获原版 `Graphics.DrawMesh`；替代图为有序整组替换。门在外壳上仅同步全开／全关终态。炮塔旋转炮身由 `IShellTurretTopSource` 提供当前材质和角度，规则决定仅绘炮身并置于船壳上层；轨道装弹机用规则排除，加速段内构与外壳入壳，不修改碰撞分类。
- `ShellHullVisuals.BuildEdges`：恰好邻接两面垂直舱壁的地板格用独立的四分之一圆弧网格替代两条直缝；圆角的两张角向渐变复用直缝衰减曲线和各自受光符号，半径为 1 格。`MapOverlayRenderer.AddHullCornerCommands` 逐边传入当前光向，不因旋转重建 section 网格。
- `GlobeDisplayInfo` / `GlobeDisplayRules` / `PrefabGlobeMeasurements`：星象仪非太空地形面积、成员标记、残骸与缩放门槛的共同入口；有图读 Map，未物化读启动时 prefab 测量，归档保存无法从卸载图读取的显示摘要，恢复改读实图。具体显示和缓存契约见星区架构 §11.1。`SpaceAimController` 与 `Patch_AimModeClicks` 共用 UI 门禁，只有原版 UI 处理后剩余的地图按下事件能授予手动开火资格，细则见太空战架构 §6.1。
- `ThrusterEffects` / `ThrusterAudio`：只读真实分配油门的喷口火焰与循环音；`TryGetExhaustPort` 由同一火焰几何提供排气起点。`SpaceProjectileService.MotionVisuals` 在既有实例表现管线管理宇宙排气、成组启停声和本船重击余响，`CompThrusterVisuals` 与 shuttle Comp 配置排气，`MotionParticleRenderer` 生成覆盖率纹理并合批。`SpaceCoordinateGrid` 经 `OrbitSphere` 提供绝对网格，背景缓冲先网格、再粒子、再船壳；基架碎片从 `SubstructureDamageUtility.CompleteDestruction` 触发。机制、预算和验收见太空战架构 §4.4。
- `DeltaVPerformanceProbe`：`UniverseManager` 持有的运行时探针；日志页开关控制 5 秒窗口，按帧记录 FPS/帧耗时，按实际游戏 tick 记录 TPS、对象与弹体峰值、结构版本增量、实际出力／漂移／归档对象峰值，并拆分 NPC、弹体、火控齐射／逐武器瞄准、点防清理／共同候选筛选／索敌、对象手动驾驶／分离门禁／分配器／漂移／归档检查、碰撞、运动表现及生命周期等 CPU 耗时。背景/前景绘制另行分段；所有计时仅为主线程 CPU，不测 GPU。射位准备／搜索／风险、路线形状构建、推力预览及 MPC 构建／预检／求解／恢复另有常驻探针，并记录重算原因与最慢射位实例；字段及嵌套关系见[战斗规划性能统计](太空战架构.md#战斗规划性能统计)。
- `ThrusterDebugOverlay` / `WeaponArcOverlay` / `CollisionDebugOverlay`：聚焦图上的三个独立视图开关；状态在 `UniverseManager.ExposeData` 随当前存档保存，渲染类只持有可清理的绘图缓存。`Patch_DeltaVPlaySettings` 还提供默认开启的撕裂确认开关，`ShipFlightTransitionService.RequestFoundationSeparation` 只在普通飞行图拆分方向读取它；关闭时经原帧队列自动拆分并发原版消息，脱离停靠方向保持确认。武器射界直接读取武器 Def 的真实射程与安装射界；只绘边界和按游戏 tick 扫动的线，实例颜色由 Thing ID 稳定分配，不影响火控。射界开关关闭时不调用绘制入口，材质和网格只在开启后首次需要时创建，并在关闭时释放。
- `MoonPoolUtility` / `Patch_MoonPool` / `Patch_MoonPoolRoof` / `MoonPoolGraphics` / `SectionLayer_MoonPool`：月池地形与专用力场屋顶同步、透光及穿梭机通行、连接视觉；地形和屋顶事件逐格维护，读档一次校正，不按 tick 重扫。
- 外壳排序：所有非聚焦对象壳按 objectId 整壳分层，统一位于聚焦图下；进场／同步漂移不改变层级。前台命令缓冲只承载弹体与瞄准效果。不退回逐建筑海拔或透明队列排序。推进器火焰每条命令使用独立的 `MaterialPropertyBlock`。

## 生命周期、NPC 与星区生成

- `CompWeaponTuning` / `SpaceWeaponSupply` / `GunSupplyJob`：炮塔调校、tick 热锁、双仓 `CompRefuelable` 及原版装填上限控件；补给仍由原版 WorkGiver 派工，Job 适配只选择正确的仓；`SpaceKinetics` 为发射、毁伤、护盾共用无状态计算。地面 `Verb_SpaceTurretGround` 成功后扣同一库存与热量，`Projectile_TunedGun`／`Beam_TunedGun` 冻结毁伤。`WeaponHeatVisuals` 共用炮管／炮身着色，烟进入既有 MotionVisuals 粒子池；见[太空战架构 §5.1.1](太空战架构.md#511-装药质量与热管理2026-10-30)。
机制见 [星区架构](星区架构.md) 和 [太空战架构 §9.1](太空战架构.md#91-远距整图归档与撤退)。

- `SpaceLifecycleService`：生成、休眠、物化、归档和销图。普通口袋图无承载时经 `HasMapSupport/QueueStructureCheck/RecycleUnsupportedMap` 在帧边界复核回收，剩余 Pawn/物品不阻止；不受当前聚焦或玩家保护豁免，细则见解耦架构 §8.1。无快照 marker 首次物化的内容链 = 类型 prefab 池（seed 确定性选取，入队测尺寸与盖章同一解析），**容器先注册、结构后铺设**（驾驶台 `ClaimOnSpawn` 认领要求 FrameOf 已解析；归属名 = marker 生成时决定的完整名，经 envLabel/归档 carriedLabel 传承）。池空在生成期拦截；池失效在入队/物化期报错并取消该 POI（prefab-only，不回退程序生成）。
- `NpcShipAiService` / `NpcShipController`：所有船型使用完整战术 AI，无武器不按船型禁用站位或撤退；NPC 战术资格、当前战损重评、返厂目标、无图导航意图、退场决定及跳帮均在 NPC 层；选敌和站位调用上述共用类。生命周期沿用普通距离规则，只执行通用归档、恢复与销图，不解释撤退意图；归档通知只记录 AI 观测值，数值动力摘要由有图对象捕获，不触发战术决策；恢复后清理摘要与运行时导航任务。已选目标的射击、点防与自动驾驶仍逐 tick，开火走共同 controller 和 `SpaceWeaponShot`。炮手补位由岗位结束、武器状态和 Pawn 可用性事件触发，NPC 不再每 60 tick 重派；`ShipControlService.ProcessGunnerEvents` 在炮手分配后给未上岗的敌舰船员分配原版 `LordJob_DefendPoint`，驾驶台损毁后仍处理该图的守卫任务。AI 资格门禁与 dev 诊断共用同一判定，Combat 日志只输出状态变化。`ArchivedMapStore` 是远距普通口袋容器的原版 `Map.ExposeData` 整图序列化与运行时卸载/恢复入口，归档内容随 `ArchivedSpaceObject` 落档；远距归档与恢复按设置周期全量检查；有图／无图导航共用 ShipAutopilot 任务表、Step、MPC 与 ShipPhysics 分配／积分，无图阶段以逐台数值推进器布局进入同一分配器；推进后复核普通距离恢复，与生命周期扫描周期无关。该路径尚待游戏内存读档和引用完整性验收。
- `SectorContentService` / `SectorContentTypes`：星区首次生成的幂等记账与按类型生成循环；marker 身份在生成时一次性决定——随机派系（可见非玩家派系，不做类型→派系映射）+ 完整名（`DeltaV_NamerSpacePoi` RulePack 词干 + 类型名 + (派系名) + #ID）烘焙进 envLabel/faction，物化时直接应用。`SectorContentTypes` 是任意深度的分类树（星区架构 §11 分类），分支只分组、生成与设置只遍历叶子；规则读 `DeltaVSettings.sectorRules`（`SectorTypeRule`：保底数/分段额外量/prefab 池；缺条目用注册表默认，读路径不静默改写设置）。
- `QueueFrameAction`：离开当前 tick/加载调用栈的唯一帧边界延迟机制。双船场景重建经 `UniverseManager.BeginSceneReset` 在该消费点逐阶段排空旧动作后销图、清缓存、生成新图；不得先注销弹体容器或直接丢弃待执行清理。弹体退出共用 `QueueProjectileCleanup`，原版销图仍经 `SpaceLifecycleService`；完整顺序见太空战架构 §4.5。

- 容器与宿主：对象存在性不以 `Find.Maps.Contains` 判断，归档／恢复经 `UniverseManager.ReplaceRepresentation`，不触发普通注销／新生。`UniverseHostParent_DeltaV` 只承担 pocket-map `sourceMap` 契约，无 tile、不可聚焦、不进 WorldObjects，不承载游戏事实。

通用地图工具包（上述坐标/渲染/搬运/生命周期/生成条目同属一个将来通用的地图工具包；后续地图能力一律扩展这些入口，不建平行实现）：

- `MapContentSpawner`：Thing 记录回放（def/stuff/quality/hp/stack/faction → `GenSpawn`）、Scribe 恢复实例落位、基架盖章包裹器与设施重链（`RelinkGravshipComponents`）的唯一入口；`PoiSnapshot`/`ShipProceduralLayout`/`MapPrefab` 的落物一律经此。
- `MapPrefab` / `MapPrefabDocument` / `MapPrefabThingState`：通用地图 prefab 的唯一门面、文档与逐实例状态入口。地形及旋转锚继续复用原版 `PrefabUtility`，建筑/物品通过原版 `Thing.ExposeData` 导出并整批 Scribe 读取；基架/屋顶另存侧车，锚点掩码只纳入 Building+Item。重建顺序为 foundation（含指定归属）→ terrain → 整批解析内部引用、重分配 Thing ID、指定派系与旋转落位 → roofs → 重链 → marker 展开；外部旧地图引用不随 prefab 复制。驾驶台源身份在落位前清理，对接口通道格按新锚换算。文件落 mod 根 `Prefabs/`，新文件格式要求重新导出旧 prefab；地形 Def 读入走原版 XML 交叉引用管线。prefab 池仍由 `LoadRelative`、`ListPrefabFiles`、`ResolvePoolPath` 维护。具体契约见 `doc/Prefab状态重建.md`。
- `CompPrefabMarker` / `CompPrefabPawnSpawner`：prefab 重建标记框架——只有 `MapPrefab.Spawn` 在整片放置完成后调用 `Expand(PrefabSpawnContext)`（context 含 Map/Faction/OwnerId/Root/Rotation/Universe，为后续 SpaceObject 展开器预留）；普通读档与 `PoiSnapshot.ApplyTo` 恢复不调用展开。新展开器 = 新子类 + CompProperties，`TryGetComp` 基类匹配零修改纳入。当前仅实现 Pawn 标记：每个标记生成一名 Pawn，Def 指定 PawnKind 优先，其次目标派系基础成员、原版 `Faction.RandomPawnKind`，最后由 Def 指定后备种类；原格优先、附近可站立格兜底，成功后销毁标记。人形船员的真空服与头盔统一由 `SpacePawnEquipment` 在入图前穿戴，程序测试船员同用此入口。SpaceObject 标记延期。
- `ShipProceduralLayout` / `ShipPocketMapFactory` / `ShipTestScene`：口袋图生成与程序生成布局。双船场景的 prefab 与初始位姿由 `DeltaVSettings` 的通用设置页配置；创建时冻结距离、相对方位和两船初始角度，经 `SpaceTransform.Rotate` 与 `OrbitSphere.Move` 放置。程序生成仅存于 `ShipTestScene`（MapPrefab 导入失败时的唯一回退特例）；星区 POI 物化不走程序生成。
- `SpaceMapPool` / `SpaceMapLease` / `DeltaVPocketMapMetadata`：`UniverseManager` 持有的通用图池，按 tag/精确尺寸租用，通过内容回调装载；归还校验租约及内容，读档使用原有一次性收尾恢复。弹体和散落系统共用此入口；空闲图复用既有冻结门禁。`Patch_SingleCellMapGeneration` 限定正在生成的 Delta-V 单格图补齐原版 GasGrid RNG 计数。契约和验证边界见 [对接设计 §13](对接与舱外作业重构设计.md#13-本轮实施记录)。

- 玩家驾驶任务：`PlayerFlightOrders` 保存手动/自动任务意图、暂停恢复和定点参考；`PlayerNavigationInput` 从地图拖曳采样冻结位置与绝对船首角度，并从当前画面外壳选择移动参考；`PilotService` 接管驾驶键和飞行键；`ShipControlService.SelectPlayerAutoTask` 是任务替换入口。定点出力/到位通过 `ShipAutopilot.NavigateToReference` 共用 MPC，速度同步由 `LandingApproachController` 持有计划，软对接交接由 `SoftDockService` 持有。
