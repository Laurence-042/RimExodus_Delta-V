# 代码入口索引

按任务查阅相关小节，用于定位当前唯一实现及局部接线约束；跨任务规则见 [AGENTS.md](../AGENTS.md)。复杂机制以链接的专题为准，数值、玩法说明和验收进度只在各自权威文档维护。修改入口时更新对应条目，不把完整清单搬回 AGENTS。

## 宇宙、坐标与船体

- 设备研究：`1.6/Defs/ResearchProjectDefs/DeltaV_Research.xml` 定义独立 Delta-V 标签页与六项研究；建造前置在设备 Def，弹药制造前置在 RecipeDef／recipeMaker，教程初始科技在 `DeltaV_Tutorial.xml`。归属、点数与验收见[设备科技树](设备科技树.md)。
- 舰载持续电源：`1.6/Defs/ThingDefs_Buildings/DeltaV_ShipReactor.xml` 组合原版发电、补料、开关与故障组件，无独立运行时代码；参数、母舰预算和验证见[舰载供电](舰载供电.md)。
- 玩家权限：`PlayerAccess` 从实时派系关系与公共标记派生 Hostile／Neutral／Public／Player，`ShipBase.PlayerMayOperate`、`PublicFacility.PlayerMayUse` 与软对接入口共同委托；分类不存档、不缓存，具体功能通过操作／交互／骇入能力选择等级。公共设施、对接口及验证边界见[解耦架构 §3.4](飞船与SpaceObject解耦架构.md#34-公共设施与统一访问权限2026-11-09)。

- 通用太空任务：`UniverseManager.missionState` 持久化业务事实，`Missions` 为可重建实例服务，教程 `tutorialRun` 是该状态内课程数据的访问入口。`Source/Quests/SpaceMissionService` 管报价、资格、接单、逐人结果与一次结算，`QuestNode_SpaceMission` 组合原版 QuestParts；`MissionWealth` 复用原版估值和 holder 筛选，`MissionCargo` 保存物资清单与拆封事实。`Building_SpaceTradeTerminal.Missions`／`Dialog_SpaceMissions` 接实际到达终端交互；`Patch_MissionPassengers` 限定本系统乘客的原版违规与直接外交接线。`SpaceObject`／`OrbitalWorkService` 发布实际驾驶与两条硬对接完成事件，教程订阅后保留自身核验；`ShipControlService` 结构变化触发战斗主台复核，`NpcShipAiService` 退场前查询目标保护。`GlobeNavigation` 汇总所有委托目标与教程当前角色。规则、Def 及验证见[太空任务系统](太空任务系统.md)。

- 可选武器／护盾课程：`TutorialCombatRange` 经既有 prefab／口袋图入口生成独立平台与靶舰，复用重力矩形检查；`TutorialFlightCourse` 在 `Salvage` 后进入 `Range`，同一对白讲解软对接并邀请自行试验；`GoToShipyard` 转入 `Visit`，不要求连接、试射或操作终端，`DeferRange` 只关闭对白供自由参观。`rangePort` 保留为任务导航目标。`Visit` 不限定空间站对接方式；`Defer{stage}` 一律保留当前进度。`CompUsable_TutorialShieldTerminal`／`CompTutorialShieldTerminal` 复用原版 `UseItem` 与 `CompUseEffect`，通过持久 objectId／ThingID 找靶舰主盾及同船护盾，切换现有模式、Def 指定的强度和开关；三档线盾同时启用同船发生器，保留 prefab 的独立投射几何，不增加伤害或补充逻辑。`CompTutorialRangeBriefing` 通过原版 `UseItem` 展示入口说明，确认后以原版 `CompHackable.HackNow` 解锁绑定的盟友防爆门。制作入口与验收见[试验场](教程开局实施计划.md#13-可选武器与护盾试验场2026-11-04)。

- 教程开局：`GenStep_DeltaVTutorialStation` 经原轨道 POI 登记和 `MapPrefab.Spawn` 生成受损移民船；`ScenPart_ConfigPage_TutorialColonists` 在原版候选生成前选用 `Colonist` 类型生成日常衣物；`ScenPart_DeltaVTutorialArrival` 只替代初始到达方式，保留原版选人及物品来源。`UniverseManager.tutorialRun` 保存唯一的课程事实，`DeltaVTutorialService` 处理启动、阶段选择和清理，薄 `QuestPart_DeltaVTutorial` 复用任务目标、Gizmo 和信号。`MapPrefab.LoadRelative` 按当前 Mod 的版本文件夹优先级读取正式资源，不依赖开发包 ID；布局源与回归在 `scripts/TutorialContent`／`TutorialRegression`。移民船由 `arrival_layout.py` 基于用户原船副本 `arrival_intact.prefab` 删改生成；`BindArrivalCaskets` 根据唯一氧气泵所在房间绑定货仓队长舱，其余船员留在原位舱内，剧本不额外补给；环境与生成期间的房间系统开关完全由 REF prefab 管线处理，教程只检查密封／可达性。`Patch_TutorialCandidateCrew` 保留未选人物供原版休眠舱接收，`Welcome` 的确认只关闭对白，`Patch_TutorialComms` 从真实通讯任务直接进入 `Inquiry`；`TutorialFlightCourse` 负责初始教练机泊口、远离殖民地重力矩形的课程生成、驾驶前维护／设计理论（`Design → StartPractice → Flight`）、RCS、硬对接回收、软对接和参观交接；驾驶证据从真实积分收尾采集，两条硬对接路径先绑定目标实体再在搬运完成后核验。公共船规则见 `PlayerAccess`／`PublicFacility`／`Patch_PublicFacility` 和[解耦架构 §3.4](飞船与SpaceObject解耦架构.md#34-公共设施与统一访问权限2026-11-09)。课程状态与验收见[当前开局](教程开局实施计划.md#11-受损移民船与星界边境2026-11-04)。
- 星区内容 prefab：类型树及每个叶子的内置默认路径在 `SectorContentTypes`；`DeltaVSettings.EnsureSectorRulesSeeded` 为缺失规则或空池播种默认文件，已有非空自定义条目保持原值，类型停用改数量而不是清空物化池。正式资源分在 `Common/Prefabs/Sector/{Craft,Stations,Asteroids}/`，小行星带子体与核心同目录；舰船布局在 `scripts/TutorialContent/sector_craft.py`，小型站点和小行星布局在 `sector_layout.py`，三座民用聚居站模块在 `sector_settlements.py`，同源示意图及 XML 由共用 `build.py` 写出。`Asteroid` 是稳定 ID，只有 `SectorAsteroid.xml` 含 cluster 标记，五份子体均无标记。生成页由 `SectorSettingsUI` 只画选择按钮，`Dialog_PrefabSelector.OpenMultiple` 负责目录树多选。覆盖、format-2、cluster 子对象安全、真空／矿产层和贸易仓引用由 `TutorialRegression.SectorContentDefaults` 检查。

- 船心查询性能：`ShipRegistry.HullCenter` 复用既有 `CachedDomain` 的中心，失效/释放与控制域共用；`SpaceTransform.BoundsCenterOfCells` 直接交给原版枚举算法。只缓存局部几何，不缓存运动位姿。战斗性能夹具及逐位轨迹对照见 [验证记录](../scripts/CombatManeuverSimulation/README.md#保留行为的性能优化2026-10-29)。

- `UniverseManager`：objects、ID 分配、Map→SpaceObject、聚焦、tick/update 总装和帧动作队列。`ObjectById` 与 `SpaceObjectOnMap` 使用可重建的实例索引，注册、注销、表示替换和读档时同步；POI 直接换图后的首次查询从 objects 补入 Map 索引。弹体容器注册不推进真实结构版本。`PlayerReferenceObjects` 是 POI 距离与跨星区生成的唯一玩家参考集合，只筛选含 Ship tag 且 `HasFaction(player)` 的对象；按 objectId 跟踪星区，运行时 hint 由本实例持有。
- `OrbitSphere`：球面移动、弧距、切空间基和 sphere↔tile。
- `SpaceTransform`：全部坐标、速度、刚体点和停放锚转换。Map 连续点互转使用 `MapPointToUniverse/UniverseToMapPoint`，停放 root 换算使用 `ShipOriginFromPlacementRoot`；调用方不得自行拼接旋转、平移、中心或 designator 偏移。`VelocityAtMovingLocalPoint → OrbitSphere.MoveVelocity` 求实际位置导数，`OriginVelocityForPoint/AlignLocalPoint` 反解锚点；地图原点与质心速度契约见[基础驾驶](阶段2-基础驾驶.md#锚点速度与偏心质心2026-11-08)。
- `ShipRegistry` / `ShipBase` / `FoundationShip` / `ShuttleShip`：`StructuresOnMap/StructureCells/HasStructure` 为侧边栏含无主台结构的查询入口，按共同结构版本缓存并随 Map/换档释放；船体身份、状态、脚印、锚、朝向、派系与火控的共同契约；`BuildThrusters/Weapons/CollisionCells/CanDriveIn/RolesIn/Transfer/NotifyLanded/CanBoard` 提供船体能力与搬运差异，对象层只汇总能力，详见解耦架构 §2。`AllShipsOnMap` 唯一枚举成员，`ShipByIdentity`、`ShipOf` 与 `DefaultVesselOnMap` 统一解析身份、归属及默认选择。`Ship` 仅为基架控制域查询快照，`FoundationShipsOnMap` 仅供结构操作。`PilotTarget` 委托共同事实给基类；停靠 shuttle 仍是船成员，但不能驾驶宿主。
- `SubstructureOwnership` / `UniverseManager.Structures`：基架事实、归属、连通认领与实例级版本服务；单图派生缓存使用 `StructureVersion(map)`，全局事件号仅供全局枚举；结构通知只置脏，读取时合并发布，删除／表示替换释放。`FoundationAt/HasFoundation/CellsOnMap` 读取原版 foundation 层。`FoundationTopologyService` 统一控制域、断片、命中查域及按完整脚印查询建筑归属。带建造认领、原版力场或布局裁剪约束的查询保留各自的候选格限制。质量算法仍只在 `ShipPhysics`；归属、质量报告、控制域、剪影与碰撞共用基架事实，船体能力与角色缓存也共用结构版本失效判定，无时间重扫；`HasSupport` 与整图真实底层查询 `HasNaturalGround` 均按结构版本缓存，避免生命周期及驾驶热路径重复遍历全图；`Patch_ShipStructure` 汇总纳管地图的建筑生成／移除与地形变化失效事件。基架与归属同步移除（`RemoveFoundation`/`RemoveGravshipTerrainUnsafe` postfix → `NotifyFoundationRemoved`），「归属仅在有基架的格上有意义」恒成立。
- `CompDeltaVPilotConsole` / `Designator_ReassignSubstructure` / `Alert_MissingPrimaryConsole`：主副台认领、玩家改划及缺主台提示。主台查询共用 `ShipRegistry.MainConsoleForOwner`，玩家整域保护共用 `SubstructureOwnership.CanReassign/Reassign`，内部转移仍走既有写入链；副台在归属通知及 Spawn 后同步脚下身份，不反向盖章。主台替换复核现有主台管理权限；原版占领、同向副台继任保持原规则。警告通过 `ShipRegistry.MissingPrimaryConsoleTargets` 从玩家建筑所在基架域派生，不保存警告状态；面板无主台提示读取当前选中的结构归属。规则详见解耦架构 §3.2。
- `SpaceObject` / `MapSpaceObject` / `ArchivedSpaceObject` / `DriveSubject` / `DriveInfo`：统一驾驶身份、只读信息与预览、执行、清理、漂移与收敛；主体按船归属或 shuttle 身份区分。推进器布局由船体子类提供，随共同物理报告重建；对象角色按共同结构版本缓存，点防保留 Projectile／Shuttle tag 快速筛选，基架船不贡献 Shuttle 角色；对象层保证每 tick 单次积分，分离后通过主体重新解析当前容器。
- `ShipPhysics`：质量/惯量、推进器、分配器、阻力和积分的唯一算法。`ReadDriveInfo`／`ExecuteDrive` 是实时动力状态读取边界，`DriveInfo` 预览与求解消费已读取的数值模型；`DriveControl.FromInput` 与期望力共用对象执行入口及按模型／动力版本／指令复用的分配结果，机制见基础驾驶专题。
- 货柜：`Building_SpaceCargoContainer` 复用 ASF 仓储；`Building_SealedSpaceCargoContainer : Building_Crate` 复用原版内部库存及 Open 任务，骇入仅解锁；倾泻沿用原版落点，主动弹射及两态毁伤释放接入 `SpaceScatterService`。`CompSpaceCargo.SetStorageMode` 在两种形态间搬移原物品，保存 ASF 设置、更新终端绑定，失败回滚；插件通过 Comp 识别两种宿主。`ISpaceCargoContainer` 提供终端所需的实际库存接口。没有 forbidden 封存控制或轨道信标过滤补丁。终端通过 `Building_SpaceTradeTerminal.Configuration`／`Dialog_SpaceTradeTerminal` 配置商人类型、周期、多个锁定供货仓与唯一解锁取货仓；`PlaceWorker_TradeTerminal` 接原版设计器可见性与放置校验，仅 God Mode 可建造；配置和配置窗口内的无差别供货复选框亦只在 God Mode 提供。Rare tick 与手动补货共用当前设施／所在船派系检查，默认禁止玩家设施刷新，显式开启无差别供货才放行。商人库存入柜前经原版 SplitOff 按 stackLimit 拆堆，按真实堆数分柜；货柜 TryStore 拒绝超上限输入，避免 SpawnSetup 截断。货柜本体为普通 edifice，覆盖销毁沿用原版 GenSpawn。交易货源由 `Building_SpaceTradeTerminal.Ships`／`Dialog_StationTradeSource` 按符合对接条件的玩家主台船 Map 合并；`UniverseManager.StationTrade` 管理临时选择，商品和白银直接调用原版 `TradeUtility.AllLaunchableThingsForTrade`，成交重读同一路径。`Patch_SpaceStationTradeDeal` 只做成交前数量和容量复核，`Patch_SpaceCargoOutdoorTemperature` 处理室外温度基线，`ShipPhysics.InvalidateMass` 随储物事件更新载重。手动结构牵引的双端冲量在 `ShipPhysics.Coupling`，命中与施力入口在 `SpaceImpactEffects.Engineering`；`SharedMapBackend.Spawn` 在当前 Def 集合中剔除 prefab 储物筛选的缺失引用。玩法及 prefab 接线见 [空间站交易与货柜](空间站交易与货柜.md)。
- `UniverseManager.SetFocusedWithCamera`：聚焦与相机连续性交接；拆分的跟随规则见解耦架构 §8.1。
- `Patch_Game_CurrentMapFocus` / `UniverseManager.ApplyCameraZoomScope`：同一 `CurrentMap` setter 补丁以目标图处理宿主图门禁、休眠唤醒和切图前缩放，完成后按实际图同步缩放并通知散落服务；不读取可能已被删除的旧当前图。地表与太空图分别使用图外与 Delta-V 上限，原版逆重过场沿用当前图上限；SCS 设置写入由可选补丁即时同步。`Patch_CameraCenterClamp` 仅在 Delta-V 图跳过原版 `CameraDriver.Update` 的地图边缘镜头中心 clamp；`Patch_ExteriorLightingScope` 随镜头重建原版地图外光照遮罩网格。`ShipStatusPanel` 从当前结构派生重新聚焦位置与运动数据，无主台位姿由 `ShipRegistry.StructurePose` 给出。
- `HostColonistBarVisibility` / `Patch_ColonistBar_CheckRecacheEntries` / `ColonyGroupsBarVisibility`：太空图无人分组用同一 `ShouldHide` 判断，分别过滤原版与可选 Colony Groups 的栏缓存；专用宿主、弹体及闲置池图始终隐藏。对象注册、注销、池租还与设置切换使两种栏缓存失效；Colony Groups 反射签名不符时仅跳过可选补丁。

## 驾驶与跨图转移

机制见 [飞船与 SpaceObject 解耦架构](飞船与SpaceObject解耦架构.md) 和 [在线 MPC 自动驾驶](在线MPC自动驾驶.md)。

- `DeltaVMod.DrawGeneralTab` / `PilotService.RebuildPilotKeySet`：Mod 设置通用页提示原版改键路径；`KeyPrefs` 保存按键，驾驶输入抑制在 `KeyPrefsData` 换代后刷新。默认绑定与分类由 `DeltaV_KeyBindings.xml` 定义，不建第二套按键存储或编辑窗口。
- `PilotTarget` / `PilotService` / `ShipControlService` / `ShipController`：普通船与 shuttle 的统一驾驶层；每个带种类的 `DriveSubject` 身份由实例注册表持有一个玩家或 NPC controller；身份索引、容器成员和船体设备缓存按共同结构版本失效，换图／换表示／注销与换档统一清理，基类调度每船火控与炮手事件；`BindShip` 同步刷新战斗缓存与已开启的驾驶目标，使当前会话跟随换图和主台继任。侧边栏操作由对应 controller 注册，经 `ShipBase.Collect*PanelActions` 委托，公共驾驶／对接操作放控制器基类，跳帮艇侵入操作放玩家子类；面板只负责显示和布局，无主台时不得通过面板自动认领。两类身份锚通过同一 `ShipCombatState` 保存火控模式（默认自动）与武器组，`SpaceAimController` 只在手动集火且为聚焦图所选船时提供输入和预瞄。
- `CompShipCombatAI` / `CombatStrategy` / `CombatRuleOptions` / `CombatTacticSettings`：每主台或 shuttle 持有 XML3/Scribe 配置；目标、机动、逐炮规则使用真实作用域与进入／退出阈值。`Dialog_CombatStrategy.Options` 提供模板、选择器和高级条件，`Dialog_CombatPose` 拖动距离／朝向／攻击方位；`Dialog_CombatOrders` 发送运行时交战目标／部件队列。`CombatEngagementSettings` / `Dialog_CombatStrategy.Engagement` 提供共用交战指标、筛选与权重曲线；`ShipAutoCombat.Engagement` 经 `CombatEngagementEvaluation` 比较候选的单发火力及风险，`CombatDamageForecast` / `CombatResourceLedger` 复用一次开火内的局部毁伤与盾面扣减。`CombatAttackPose` 保留姿态结果和共用射界能力，不再另跑旧姿态选择器；`CombatReposition` 保存逐船决策时钟和持续速度，到期按真实状态／反向制动成本评分，随机只打破近似等价净分。`ShipAutoCombat.Tactics` 复核协同与路线，形成 `CombatManeuverIntent`；`CombatFlightPlanner` 生成从实际完整状态开始的 `CombatTrajectoryIntent`；船心轨迹用 `AlignLocalPoint` 转成共同自动驾驶的地图原点契约。`ShipFireControl.Strategy` 管理目标重评、逐炮停火、部件与观测缓存，`CombatWeaponThreat` 从真实炮口生成武器风险，`CombatTarget` 的部件失效不会悄悄落到船心。`CombatWeaponCoverage` / `Dialog_WeaponCoverage` 保存和编辑单炮覆盖约束，瞄准、预览与 `SpaceWeaponShot` 共用。细节与验证界限见 [太空战架构 §9](太空战架构.md#9-npc-与-dev-验证)。
- `ShipControlService.Tick` / `ShipController.TickCombat`：调度每船齐射及点防；火控在齐射后经 `CollectInterceptionCandidates` 一次筛选本船敌对可拦截对象，各炮共用，无候选早退。有效锁持续沿用，空锁等待重试；牵引器继续消费散落服务索引。候选缓冲只活到本次调用结束；锁清理保留结构版本及显式归属事件。详细点防节拍和 `pdCandidates`／`pdSearch` 探针口径见太空战架构 §4.2；自动齐射复用 `TryGetIntent` 已解析的目标。
- `ShipAutopilot`：固定/随动/战斗轨迹共用任务表；不读取 Map、归档字段或具体对象类型，统一读取驾驶信息并提交期望力／力矩；实体与无图主体共用任务表和 Step，只替换主体及能力数据来源，不识别返厂策略；制导经同一 `IAutopilotGuidance`，战斗轨迹不建立独立出力链。`CombatTrajectoryIntent.startTick` 保持战斗轨迹的固定时间原点，每次自动驾驶微步沿同一轨迹采样，只有真正重规划时更新。持续绕行朝向以目标视线为基准；固定炮的相对角由真实炮口与提前量确定，不能借用目标船自身角速度。
- `ShipFlightTransitionService`：共同搬运、真实出力分离及源图善后；`RequestPilotDeparture/CanDepart` 为停靠船驾驶按钮确认起飞入口，船体 `CheckDeparture/MoveColocatedItems` 提供起飞限制及同格物品携带差异；`TransferShipToPocket` 统一两类船起飞／分离／方向罗盘的相机交接；`FinishEmptyWorksite` 在搬运及结构事件中处理最后一船离开后的残骸。`ShipRegistry.RequiresOwnPocket` 统一预检与执行时的分离方向；普通飞行图通过 `HasResidualBlocks` 增量预检，有残留才调用原 `ControlDomain/ResidualBlocks` 分组搬出。`SpaceScatterService.LooseCargo/ScatterLoose` 处理无承载内容，失败保持出力门禁；散落货物首次按图建索引，此后由 ThingGrid 与承载地形事件逐格维护，注销图和换档释放。排队分离复核源容器表示版本及当前所属 Map。
- `FoundationTopologyService` / `FoundationConnectivity` / `Topology/GridTopology`：`UniverseManager` 实例持有的按图断裂查询索引；拓扑算法来自 TopologyLab，署名见 [CONTRIBUTOR](../CONTRIBUTOR.md)。基架增删及 `Assign/ClearOwner` 同一结构写路径标记变更格，查询时合并并读取最终基架／归属事实；不存第二份归属事实、不改变控制域规则。初次按图重建，此后局部增量维护；读档、地图释放、表示替换与换档丢弃索引。判据、流程边界及回归见[解耦架构 §8.1](飞船与SpaceObject解耦架构.md#81-触发与结果已定)。
- `DockingCompletion`：普通停靠与侵入共用落地／聚焦／源图收尾；不再弃置源图人员，交回共同残留处理。转移待收尾集合负责存档、尺度和生命周期门禁。
- `LandingApproachController`：`DriftSyncPlan` 只保存目标身份与最近四向，`SpaceTransform.MatchingDriftPose` 统一线速度／方向参考，`MatchesMotion` 与任务就绪共用判据；无位置锚、落点幽灵或虚空动力。`OrbitalWorkService` 在开始作业事件中才生成 `DockingPlan`，按当前相对偏移求最近整数根格并立即搬图；`DockingPlan` 只是本次命令的整数落位数据，没有后续驾驶或鬼影阶段。共同作业以发起船为基准，复用该整数变换的逆变换放置目标船；停靠仍使用目标图基准。软对接的 `CompSoftDocking.AlignmentReference → SpaceTransform.AlignLocalPoint` 同时供真实推进器 MPC 与位姿插值读取，按端口双菱形交叉重合保持站位；`UniverseManager.GameComponentTick` 在物理积分后调用 `SoftDockService.ApplyAlignmentAssist`，仅无实际引擎出力且菱形误差在捕获范围内时按距离平方倒数插值。沿用既有任务 tick，无新增候选轮询。原版停靠／重力复核、单船／多源工作图也由玩家事件编排；旧战术选点接管已删除。
- `ShipOrientation`：普通对接、侵入落位及速度同步的最近四向吸附入口；`SnapAngle` 委托 `Rot4FromAngle`，放置旋转继续经原版 `Rot4.Rotated`。
- `Building_DockingPort` / `Building_DockingChannel` / `DockingChannelPreview` / `Patch_DockingPort`：单格对接口、非基架气密通道及限定门房间的真空语义；`TryFindChannel` 共用生成／建造及双方降落预览／事件复核，`RetractChannelsFor` 共用双方脱离清理。建造朝向不受原版门绘制自动转向覆盖；到达通知只作用于本次目标图。完整机制见星区架构 §7。
- `GravshipInterop`：原版 Gravship 私有逻辑镜像、designator 适配、预览和 `CaptureDomain/StripDomain/PlaceIntoMap`。
- `BrakingRecoveryState`：`ShipAutopilot.Flight` 的运行时制动恢复状态与重试调度；复用同一个 MPC 的位置／速度模式，详见 [在线 MPC 自动驾驶](在线MPC自动驾驶.md#战损后的制动恢复)。
- `SpaceShuttleService`：shuttle 起飞、侵入指挥与命中落点；空图处置和外部销图使用共同转移／生命周期入口；侵入由 `SpaceProjectileService` 解析目标并登记共同碰撞工作项，`ShipAutopilot.Intercept` 经真实推进器出力，跳帮后效的落地与普通对接共用 Gravship 转移和 `DockingCompletion`。
- 搬运约束：designator 输入格不等于最终 root；捕获与剥离共用同一份绝对 cells，不从旋转后的 `Gravship.Foundations` 反推源格。捕获会消费区域、指令和携带物，合法性和生成预检必须先完成。跨图后旧 `Ship` 快照失效，按身份重新查询；`SpaceTransform.PoseAfterPlacement` 从最终放置根格统一派生容器位姿与刚体点速度。

- `CompSoftDocking`：每个对接口的配对、几何、伸展进度、接通判定与吸附事实源；发起端保存对端引用、进度和接通标志，对端只持有可重建的运行时反向引用。`UniverseManager.SoftDockEnabled` 通过游戏组件 `ExposeData` 保存开关；`SoftDockService` 读取该开关，持有端口索引、显式软对接命令的端口预留和入口接线，读档后重建索引，按已配对每 tick、未配对每 15 tick 调用 comp；物理积分后的吸附遍历有效配对，不以推进器制导任务是否仍在运行作为门禁；主动关闭清理状态。`SoftDockPortals` 将门绑定为原版 MapPortal，直接使用 Dialog_EnterPortal、Lord、原版入口／搬运 Job；关闭、断连、搬离时 CancelLoad 并销毁入口。原版 60 tick 装载检查与工作分配已获准；`Patch_SoftDockPortalDialog` 仅拦截失效入口的窗口提交。`JobDriver_SoftDock` 仅含远端 CompHackable 操作。
- `Patch_SoftDockExitMap`：只过滤原版 `JobGiver_ExitMap` 为非玩家 Pawn 生成的软对接入口撤离结果，作为守舰职责缺失时的防循环兜底；显式入口 Job 与原版其他入口不受此过滤。
- SpaceScatterService：毁伤、搬运收尾、内容移除与聚焦切换事件生成／回收散落图；同 SpaceProjectileService 使用 SpaceMapPool，无定时扫图。牵引通过 CompSpaceTractor 的 ISpaceWeaponLaunch → Scatter.Pull 接入，Scatter.Tick 在容器漂移后按接收船局部坐标插值，收货复用深钻井 GenPlace.Near；自动独占权同表持有、跨船不可抢占；结构模式经共同连续束碰撞与 TractorPull 后效逐设备叠加真实冲量；进度见 [对接设计 §13](对接与舱外作业重构设计.md)。
- `SpaceScatterService.ClearPawnTransferJob` 供散落与牵引回收共用；`SpaceLifecycleService.FreezeScattered` 经 REF 设置散落图 tick 速率。`SpaceMapPool.TryMakeRoom` 供口袋图、分帧物化和归档恢复共用，在帧边界先释放空图，再由 `SpaceLifecycleService.ReleaseForCapacity` 按分数回收。机制见[单格地图与对象池](对接与舱外作业重构设计.md#92-单格地图与对象池)。

## 武器、弹体与护盾

- `GuardShieldRenderer` / `GuardShieldOutline`：守卫常规盾按已有 `OwnedShields` 与实际 `Active` 裁剪原版柔边贴图网格，融合联合外缘，应急独立、选中整圆、失效选中灰圈；`Patch_SpaceShieldMode.PostDraw` 供聚焦图与船壳共用。网格仅为显示缓存，建筑离图、`MapOverlayRenderer.Release/ClearRuntimeCaches` 释放；宇宙受击仍由 `SpaceProjectileService.Visuals` 消费真实交点。

机制见 [太空战架构](太空战架构.md) 和 [护盾机制](舰炮与护盾基线.md#geometry)。

- `SpaceTurretTopRenderer`：炮塔的 `TurretTop.DrawTurret` 前缀与护盾组件 `PostDraw` 共用 `Draw`，船壳共用 `SourceFor/MatrixFor`。`IShellTurretTopSource` 可由建筑或组件提供；护盾保持普通 `Building`，不依赖子类。顶部尺寸读取 `turretTopDrawSize`；船壳另采集拦截器圆盾效果，不绘固定底座。`CompSpaceWeaponTraverse.AdvanceToward` 统一阻止所有瞄准来源的断电与关机转向。

- 工程设备复用 `CompSpaceWeapon.manualOnly`、手动组、`SpaceWeaponShot` 与统一光束碰撞；惯性耦合束逐 tick 支付及结算、跳过全部盾面，后效经 `SpaceObject.CoupleMotionWith → ShipPhysics.CoupleMotion` 交换冲量，采矿后效由 `SpaceImpactEffects` 的 Engineering partial 执行切割及原版拆除产出，惯性耦合和采矿不负责拖曳／对接／地图扩容。牵引器 `SpaceTractor` 使用同一发射事务的 ISpaceWeaponLaunch 能力和月池放置门禁，收集模式直接提交散落请求，结构模式使用共同弹体／碰撞后效链，`ShipFireControl` 保持有效锁定，自动候选由散落服务统一检查独占与过滤，空锁 30 tick 重试、失效立即重选。`SpaceTractor.Settings` 保存原版物品过滤与活体矩阵，`ITab_TractorCargo` 通过临时 `TractorCargoSelection` 同步多选物品筛选，`Patch_TractorInspectTabs` 补原版非仓储建筑的多选 tab 门禁；`ShipFlightTransitionService.Tractor.PrepareExternalForceTarget` 供牵引与惯性耦合共用，按 `FoundationTopologyService.PhysicalBlocks` 的结构版本缓存提取受力连通块，仍走共同搬图核心。机制以太空战架构 §5.9 和对接设计为准。
- `SpaceWeaponService` / `SpaceWeaponShot`：武器索引、共同 `ApplyControl(WeaponControlCommand)` 执行及唯一 Prepare→Launch→Commit 事务；只消费明确指向与触发意图，手动导弹锁定仅在发射准备中调用共同射线查询；逐发弹药、装弹机基础脉冲、沿物理链逐段预留的加速脉冲、电容放电与末端炮口在此一次性冻结，成功发射后统一扣费；缺电加速段跳过且不增加弹速，后段仍继续检查。电容武器插件仅通过抽象挂件基类的直供接口参与开火，`CompSwitchableBattery : CompPowerBattery` 复用原版储能与结算，并通过原版连接入口切换接网／隔离；插件提供储能身份，专属预留同步占用公共电网余额，提交先专属后公共以防重复扣费。锁定弧与发射轴分离，请求携带手控来源，武器实例分别保存手控与自动偏离角，事务按来源检查目标与实际炮口/固定轴夹角；地面模式原版炮塔读取自动角度。Traverse 无独立逐 tick 扫描，只按火控或原版图内目标命令转向；载人岗位统一使用原版 `CompMannable + ManTurret`，操作人只读原版 Mannable、位置只读原版交互格；预留人选存武器 comp，补位由统一原版 Job 清理通知及武器/Pawn 事件触发。`SpaceWeaponManning` 仅提供无状态的自瞄开火、成品交互点、Delta-V 顶置炮塔交互格放行／建造警告和岗位连线适配，不另存操作人或镜像 Mannable getter。Mannable/Traverse/Magazine/Attachment/加速件以正交 Comp/能力接口参与，第三方不得建立家族特判。
- `SpaceWeaponControl.cs`：不可变指向／触发命令与武器执行边界；纯手动转向早退，冷却／操作／电力和弹药检查由武器负责，执行重入门保护当次能量账本。
- `CompRailgunEnergyRecovery` 提供挂件的本段减耗能力，`CompSpaceRailgun.ShotEnergy` 汇总启用插件，供同一预留账本使用；不修改电容储能组件。`CompCargoTemperature` 复用原版目标温度控件与 ASF 温度函数，货柜覆盖插件沿用 `SpaceWeaponAttachmentSlots`、放置校验和宿主销毁入口。
- `SpaceWeaponModel.cs`：`SpaceWeaponLayout` 是挂件、弹仓与加速连接的唯一缓存；`SpaceWeaponEnergy` 是实时可复用预留工作区；`SpaceWeaponBallistics` 是自动、点防和手动预瞄的共同精确参数／提前量入口。生命周期及统计口径见太空战架构 §5.1、§4.4。
- 武器归属热路径：`CompSpaceWeapon.OwnerShip` 缓存完整脚印归属，`ClearRuntimeModel` 负责释放；`ShipFireControl` 齐射／点防共用本次组掩码，避免重复解析所属船。失效与实时切组契约见太空战架构 §5.1。
- `PlayerInputStamp.cs`：`UniverseManager.PlayerInput` 持有 `PlayerFrameInput`，驾驶与瞄准首次消费时按帧采样，UI 门禁单独失效；OnGUI 只负责按下授权，tick 执行前核对当前会话。释放及边界见太空战架构 §6.1。
- `SpaceWeaponAttachmentSlots` / `SpaceRailgunConstruction`：武器 Def 声明的插件槽位、允许挂件与串联加速件的选中建造按钮及槽位提示唯一入口；加速段到装弹机的反向关联从 Def 注册反查。轨道炮状态 Comp 绑定武器唯一连接布局并统一查询能量、分发颜色；加速段颜色 Comp 不独立轮询。两者经原版 `ThingWithComps.DrawColor → ThingComp.ForceColor` 给 `CutoutComplex`／`_m` 红色蒙版提供主色；绿色通道才对应 `DrawColorTwo`。状态变化经 `Notify_ColorChanged` 刷新 MapMesh，不要求建筑专用 `thingClass`；不切换整张贴图，也不使用 `CompGlower`。状态与预瞄都复用 `SpaceWeaponEnergy` 的只读能量规划，不创建射击事务，安全路径复用同一判定。
- `Building_SpaceTurretGun` / `DefModExtension_SpaceTurretArt`：提供旋转顶部材质与原版当前角度；`Building_TurretGun`/`TurretTop` 仍负责调用绘制，Delta-V 前缀转交共同顶部绘制器。Def 固定为仅点防的 1×1 激光炮不触发原版同图索敌，以免发射原版机炮弹。
- 重炮、速射炮、激光炮的 2×2／3×3 炮塔逐实例地面／太空模式互斥：地面原版 `Building_TurretGun` + `Verb_SpaceTurretGround`，太空 `SpaceWeaponShot`；`CompSpaceWeapon` 是模式和太空最小射程的事实源。专用点防不切换。

## 生命周期、NPC 与星区生成

机制见 [星区架构](星区架构.md) 和 [太空战架构 §9.1](太空战架构.md#91-远距整图归档与撤退)。

- `SpaceLifecycleService`：生成、休眠、物化、归档和销图。普通口袋图无承载时经 `HasMapSupport/QueueStructureCheck/RecycleUnsupportedMap` 在帧边界复核回收，剩余 Pawn/物品不阻止；不受当前聚焦或玩家保护豁免，细则见解耦架构 §8.1。无快照 marker 首次物化的内容链 = 类型 prefab 池（seed 确定性选取，入队测尺寸与盖章同一解析），**容器先注册、结构后铺设**（驾驶台 `ClaimOnSpawn` 认领要求 FrameOf 已解析；归属名 = marker 生成时决定的完整名，经 envLabel/归档 carriedLabel 传承）。池空在生成期拦截；池失效在入队/物化期报错并取消该 POI（prefab-only，不回退程序生成）。
- `NpcShipAiService` / `NpcShipController`：所有船型使用完整战术 AI，无武器不按船型禁用站位或撤退；NPC 战术资格、当前战损重评、返厂目标、无图导航意图、退场决定及跳帮均在 NPC 层；选敌和站位调用上述共用类。生命周期沿用普通距离规则，只执行通用归档、恢复与销图，不解释撤退意图；归档通知只记录 AI 观测值，数值动力摘要由有图对象捕获，不触发战术决策；恢复后清理摘要与运行时导航任务。已选目标的射击、点防与自动驾驶仍逐 tick，开火走共同 controller 和 `SpaceWeaponShot`。炮手补位由岗位结束、武器状态和 Pawn 可用性事件触发，NPC 不再每 60 tick 重派；`ShipControlService.ProcessGunnerEvents` 在炮手分配后给未上岗的敌舰船员分配 `LordJob_NpcShipDefenders`，直接使用原版主动索敌。接受炮位命令后离开索敌队伍。驾驶台损毁后，该图仍会分配索敌任务。AI 资格门禁与 dev 诊断共用同一判定，Combat 日志只输出状态变化。`ArchivedMapStore` 是远距普通口袋容器的原版 `Map.ExposeData` 整图序列化与运行时卸载/恢复入口，归档内容随 `ArchivedSpaceObject` 落档；远距归档与恢复按设置周期全量检查；有图／无图导航共用 ShipAutopilot 任务表、Step、MPC 与 ShipPhysics 分配／积分，无图阶段以逐台数值推进器布局进入同一分配器；推进后复核普通距离恢复，与生命周期扫描周期无关。该路径尚待游戏内存读档和引用完整性验收。
- `SectorContentService` / `SectorContentTypes`：星区首次生成的幂等记账与按类型生成循环；marker 身份在生成时一次性决定——经 `SpaceFactionCandidates` 随机选派系（清剿委托及双船测试复用，资格见星区架构 §4）+ 完整名（`DeltaV_NamerSpacePoi` RulePack 词干 + 类型名 + (派系名) + #ID）烘焙进 envLabel/faction，物化时直接应用。`SectorContentTypes` 是任意深度的分类树（星区架构 §11 分类），分支只分组、生成与设置只遍历叶子；规则读 `DeltaVSettings.sectorRules`（`SectorTypeRule`：保底数/分段额外量/prefab 池；缺条目用注册表默认，读路径不静默改写设置）。
- `QueueFrameAction`：离开当前 tick/加载调用栈的唯一帧边界延迟机制。双船场景重建经 `UniverseManager.BeginSceneReset` 在该消费点逐阶段排空旧动作后销图、清缓存、生成新图；不得先注销弹体容器或直接丢弃待执行清理。弹体退出共用 `QueueProjectileCleanup`，原版销图仍经 `SpaceLifecycleService`；完整顺序见太空战架构 §4.5。

- 容器与宿主：对象存在性不以 `Find.Maps.Contains` 判断，物化及归档／恢复共用 `UniverseManager.ReplaceRepresentation`。物化顺序与失败清理见[星区架构 §4](星区架构.md#4-spaceobject-与物化materialization)。`UniverseHostParent_DeltaV` 只承担 pocket-map `sourceMap` 契约，无 tile、不可聚焦、不进 WorldObjects，不承载游戏事实。

## 通用地图与 prefab

运行时契约见 [Prefab 状态重建](Prefab状态重建.md)。

公共实现已迁至同级 [RimExodus Framework](../../RimExodusFramework/README.md)。Delta-V 唯一使用 REF；`SharedMapBackend` 只负责船体归属、武器/驾驶台身份与标记展开等业务回调。公共渲染、坐标映射、区域 prefab、整图归档、休眠和无 tile 宿主均不再保留本地旧实现。Surveillance Shift 的地图外裁剪兼容由 REF 统一处理。

REF 与 Delta-V 的地图接线（通用能力扩展 REF，飞船策略扩展现有适配器，不建平行实现）：

- `MapContentSpawner`：Thing 记录回放（def/stuff/quality/hp/stack/faction → `GenSpawn`）、Scribe 恢复实例落位、基架盖章包裹器与设施重链（`RelinkGravshipComponents`）的唯一入口；`PoiSnapshot`/`ShipProceduralLayout`/`MapPrefab` 的落物一律经此。
- Delta-V `MapPrefab` / REF `MapPrefabDocument`、`MapPrefabThingState`：通用地图 prefab 的唯一门面、文档与逐实例状态入口。地形及旋转锚继续复用原版 `PrefabUtility`，建筑/物品通过原版 `Thing.ExposeData` 导出并整批 Scribe 读取；基架/屋顶另存侧车，锚点掩码只纳入 Building+Item。重建顺序为 foundation（含指定归属）→ terrain → 整批解析内部引用、重分配 Thing ID、指定派系与旋转落位 → roofs → 重链 → marker 展开；外部旧地图引用不随 prefab 复制。驾驶台源身份在落位前清理，对接口通道格按新锚换算。内置文件位于 `Common/Prefabs/`，游戏内导出写入 RimWorld 用户数据 `DeltaV/Prefabs/`；新文件格式要求重新导出旧 prefab，地形 Def 读入走原版 XML 交叉引用管线。prefab 池仍由 `LoadRelative`、`ListPrefabFiles`、`ResolvePoolPath` 维护。具体契约见 `doc/Prefab状态重建.md`。
- `CompPrefabMarker` / `CompPrefabPawnSpawner` / `CompPrefabObjectSpawner` / `CompPrefabClusterSpawner`：prefab 重建标记框架——只有 `MapPrefab.Spawn` 在整片放置完成后调用 `Expand(PrefabSpawnContext)`（context 含 Map/Faction/OwnerId/Root/Rotation/Universe）；普通读档与 `PoiSnapshot.ApplyTo` 恢复不调用展开。Pawn 标记按既有后备链生成船员并由 `SpacePawnEquipment` 穿戴真空装备。精确 SpaceObject 标记把 prefab 路径、相对距离／方位／朝向与派系规则冻结为子 `PoiState`；cluster 标记按带权池、面积密度、环带、最小间距、上限与种子确定性生成一组子 `PoiState`，预检全部 prefab 后原子登记。批量子对象写入并向精确后代传递持久 `clusterChild`；该来源链里的批量标记只销毁自身，不再展开。子对象位姿与刚体点速度只经 `SpaceTransform.RigidPointPose`，后续物化、归档及恢复复用 `SpaceLifecycle`；配置与选中预览由 `PrefabObjectMarkerUI` 使用可丢弃半透明剪影，不参与事实判定。具体契约见 `doc/Prefab状态重建.md`。
- `ShipProceduralLayout` / `ShipPocketMapFactory` / `ShipTestScene`：口袋图生成与程序生成布局。双船场景的 prefab 与初始位姿在 `DeltaVMod` 的「开发调试」页配置；创建时冻结距离、相对方位和两船初始角度，经 `SpaceTransform.Rotate` 与 `OrbitSphere.Move` 放置。程序生成仅存于 `ShipTestScene`（MapPrefab 导入失败时的唯一回退特例）；星区 POI 物化不走程序生成。
- `SpaceMapPool` / `SpaceMapLease` / `DeltaVPocketMapMetadata`：`UniverseManager` 持有的通用图池，按 tag/精确尺寸租用，通过内容回调装载；归还校验租约及内容，读档使用原有一次性收尾恢复。弹体和散落系统共用此入口；空闲图复用既有冻结门禁。`Patch_SingleCellMapGeneration` 限定正在生成的 Delta-V 单格图补齐原版 GasGrid RNG 计数。契约和验证边界见 [对接设计 §13](对接与舱外作业重构设计.md#13-本轮实施记录)。

- 玩家驾驶任务：`PlayerFlightOrders` 保存手动/自动任务意图、暂停恢复和定点参考；`PlayerNavigationInput` 从地图拖曳采样冻结位置与绝对船首角度，并从当前画面外壳选择移动参考；`PilotService` 仅在显式手动驾驶会话中接管飞行键，不再由飞行键自动切换模式；`ShipControlService.SelectPlayerAutoTask` 是任务替换入口。定点出力/到位通过 `ShipAutopilot.NavigateToReference` 共用 MPC，速度同步由 `LandingApproachController` 持有计划；`SoftDockService.SelectTarget` 仅在玩家确认目标后提交软对接任务，捕获和断连独立更新连接。

### EVA 与共用武器挂载

- 行为契约和参数归属：[太空战架构 §7.7](太空战架构.md#77-eva-工程载具与共用挂载2026-11-04)。`Buildings/CompEvaSuit.cs`：本地装载／发射适配、驾驶员与货物容量、船体能力；不建立第二套飞行状态。
- `Buildings/SpaceWeaponMount.cs`：实体／虚拟武器共同挂载接口，稳定槽位身份、生命周期、Scribe 与组件解析。`CompSpaceWeapon.On/Component` 是枚举与能力入口；火控缓存、持续束、命中上下文及设置合组不得退回建筑 ID 或首个组件。
- `Interaction/ShipAimHandler.cs`、`Core/SpaceDrive.cs`：先共用瞄准、后建筑 Rot4 更新；摄像机投影输入基与辅助正逆变换。`ShipBase` 提供对齐、角运动、火控模式及处理器创建能力。
- `Interaction/SpaceTractor.cs`、`CompCargoTractor.cs`：接收条件／结果两个扩展函数；`SpaceScatterService` 保留共同占用、运动、取消与同判据延迟交接。`Core/SpaceImpactEffects.Engineering.cs` 处理切割拆除与焊接。
- `Generation/ShipPocketMapFactory.cs`：显式外延及四向占格并集，尺寸与搬运根使用同一参数。验证入口为 `NpcRetreatRegression -EvaOnly`、`-TractorOnly` 与 `EngineeringRegression`。
