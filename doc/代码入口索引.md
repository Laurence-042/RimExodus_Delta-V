# 代码入口索引

按任务查阅相关小节，用于定位当前唯一实现及局部接线约束；跨任务规则见 [AGENTS.md](../AGENTS.md)。复杂机制以链接的专题为准，数值、玩法说明和验收进度只在各自权威文档维护。修改入口时更新对应条目，不把完整清单搬回 AGENTS。

## 宇宙、坐标与船体

- `UniverseManager`：objects、ID 分配、Map→SpaceObject、聚焦、tick/update 总装和帧动作队列。`PlayerReferenceObjects` 是 POI 距离与跨星区生成的唯一玩家参考集合，只筛选含 Ship tag 且 `HasFaction(player)` 的对象；按 objectId 跟踪星区，运行时 hint 由本实例持有。
- `OrbitSphere`：球面移动、弧距、切空间基和 sphere↔tile。
- `SpaceTransform`：全部坐标、速度、刚体点和停放锚转换。Map 连续点互转使用 `MapPointToUniverse/UniverseToMapPoint`，停放 root 换算使用 `ShipOriginFromPlacementRoot`；调用方不得自行拼接旋转、平移、中心或 designator 偏移。
- `ShipRegistry` / `ShipBase` / `FoundationShip` / `ShuttleShip`：`StructuresOnMap/StructureCells/HasStructure` 为侧边栏含无主台结构的查询入口，按共同结构版本缓存并随 Map/换档释放；船体身份、状态、脚印、锚、朝向、派系与火控的共同契约；`BuildThrusters/Weapons/CollisionCells/CanDriveIn/PrepareThrust/RolesIn/Transfer/NotifyLanded/CanBoard` 提供船体能力与搬运差异，对象层只汇总能力，详见解耦架构 §2。`AllShipsOnMap` 唯一枚举成员，`ShipByIdentity`、`ShipOf` 与 `DefaultVesselOnMap` 统一解析身份、归属及默认选择。`Ship` 仅为基架控制域查询快照，`FoundationShipsOnMap` 仅供结构操作。`PilotTarget` 委托共同事实给基类；停靠 shuttle 仍是船成员，但不能驾驶宿主。
- `SubstructureOwnership`：基架事实、归属、连通认领和结构版本；`FoundationAt/HasFoundation/CellsOnMap/CollectConnected` 是结构查询的共同入口，只读原版 foundation 层，不以覆盖地板的 `TerrainAt` 判断基架。质量算法仍只在 `ShipPhysics`；归属、质量报告、控制域、剪影与碰撞共用基架事实，船体能力与角色缓存也共用结构版本失效判定，无时间重扫；`HasSupport` 按结构版本缓存一次，避免生命周期扫描重复遍历全图；`Patch_ShipStructure` 汇总纳管地图的建筑生成／移除与地形变化失效事件。基架与归属同步移除（`RemoveFoundation`/`RemoveGravshipTerrainUnsafe` postfix → `NotifyFoundationRemoved`），「归属仅在有基架的格上有意义」恒成立。
- `CompDeltaVPilotConsole` / `Designator_ReassignSubstructure` / `Alert_MissingPrimaryConsole`：主副台认领、玩家改划及缺主台提示。主台查询共用 `ShipRegistry.MainConsoleForOwner`，玩家整域保护共用 `SubstructureOwnership.CanReassign/Reassign`，内部转移仍走既有写入链；副台在归属通知及 Spawn 后同步脚下身份，不反向盖章。主台替换复核现有主台管理权限；原版占领、同向副台继任保持原规则。警告通过 `ShipRegistry.MissingPrimaryConsoleTargets` 从玩家建筑所在基架域派生，不保存警告状态；面板无主台提示读取当前选中的结构归属。规则详见解耦架构 §3.2。
- `SpaceObject` / `MapSpaceObject` / `ArchivedSpaceObject` / `DriveSubject` / `DriveInfo`：统一驾驶身份、只读信息与预览、执行、清理、漂移与收敛；主体按船归属或 shuttle 身份区分。推进器布局由船体子类提供，随共同物理报告重建；对象角色按共同结构版本缓存，点防保留 Projectile／Shuttle tag 快速筛选，基架船不贡献 Shuttle 角色；对象层保证每 tick 单次积分，分离后通过主体重新解析当前容器。
- `ShipPhysics`：质量/惯量、推进器、分配器、阻力和积分的唯一算法；查询与执行入口仅供对象层使用，`DriveInfo` 提供无副作用能力预览。
- `UniverseManager.SetFocusedWithCamera`：聚焦与相机连续性交接；拆分的跟随规则见解耦架构 §8.1。

## 驾驶与跨图转移

机制见 [飞船与 SpaceObject 解耦架构](飞船与SpaceObject解耦架构.md) 和 [在线 MPC 自动驾驶](在线MPC自动驾驶.md)。

- `PilotTarget` / `PilotService` / `ShipControlService` / `ShipController`：普通船与 shuttle 的统一驾驶层；每个带种类的 `DriveSubject` 身份由实例注册表持有一个玩家或 NPC controller；身份索引、容器成员和船体设备缓存按共同结构版本失效，换图／换表示／注销与换档统一清理，基类调度每船火控与炮手事件；`BindShip` 同步刷新战斗缓存与已开启的驾驶目标，使当前会话跟随换图和主台继任。侧边栏操作由对应 controller 注册，经 `ShipBase.Collect*PanelActions` 委托，公共驾驶／对接操作放控制器基类，跳帮艇侵入操作放玩家子类；面板只负责显示和布局，无主台时不得通过面板自动认领。两类身份锚通过同一 `ShipCombatState` 保存火控模式（默认自动）与武器组，`SpaceAimController` 只在手动集火且为聚焦图所选船时提供输入和预瞄。
- `ShipFireControl` / `CombatTarget` / `ShipAutoManeuverControl`：每船 controller 持有唯一火控，统一自动敌船选择、设备压制、逐武器点防状态、手动射线锁定与预瞄解算；自动候选按单艘成员评分，统一门禁为 `ShipFireControl.CandidateValid`。`CombatTarget` 只保存船身份／设备 ID、容器 ID／局部点或自由瞄点，统一解析当前位置，不承载攻击策略；武器只接收 `WeaponFireRequest`，不得补选。机动消费同一船目标并向自动驾驶提供位姿采样器，战术距离低频更新，按制导微步用 `DriveInfo` 规划 2–6 秒可达轨迹；玩家机动不触发撤退或跳帮。完整目标及失效契约见太空战架构 §6。
- `ShipAutopilot`：固定/随动/战斗轨迹共用任务表；不读取 Map、归档字段或具体对象类型，统一读取驾驶信息并提交期望力／力矩；实体与无图主体共用任务表和 Step，只替换主体及能力数据来源，不识别返厂策略；制导经同一 `IAutopilotGuidance`，战斗轨迹不建立独立出力链。姿态参考从本船当前位置到目标中心的视线计算，不能由提前点或目标船自身角速度代替。
- `ShipFlightTransitionService`：分离、跨图转移、对接发起和源图善后；`SplitSelection` 只在搬运事务中映射侧边栏已有选择，按主台优先／较大侧交接，不保存第二套观察身份；`TransferShipToPocket` 统一两类船起飞／分离／方向罗盘后的相机与驾驶交接。排队分离同时复核源容器表示版本和当前船的所属 Map，已换图的旧请求丢弃。选点期只持有 `PendingTarget`，发布和复核共用 `DockingPlan` 与 `GravshipInterop.BuildPreview(PilotTarget)`。
- `DockingCompletion`：唯一对接完成收尾，落地差异通过 `ShipBase.NotifyLanded` 注入，标签读取基类；运行时键由容器注销统一清理。选点保存统一 `PilotTarget`；转移后按源图登记待收尾集合，普通对接与并发侵入共用存档、尺度与 prefab 替换门禁，逐图释放且收尾前不归档。
- `LandingApproachController`：唯一对接计划、落点注册、复核和完成触发。
- `Building_DockingPort` / `Building_DockingChannel` / `DockingChannelPreview` / `Patch_DockingPort`：单格对接口、非基架气密通道及限定门房间的真空语义；`TryFindChannel` 共用生成／建造及双方降落预览／事件复核，`RetractChannelsFor` 共用双方脱离清理。建造朝向不受原版门绘制自动转向覆盖；到达通知只作用于本次目标图。完整机制见星区架构 §7。
- `GravshipInterop`：原版 Gravship 私有逻辑镜像、designator 适配、预览和 `CaptureDomain/StripDomain/PlaceIntoMap`。
- `SpaceShuttleService`：shuttle 起飞、侵入指挥与命中落点；空图处置和外部销图使用共同转移／生命周期入口；侵入导弹的制导/碰撞由 `SpaceProjectileService` 唯一负责，跳帮后效的落地与普通对接共用 Gravship 转移和 `DockingCompletion`。
- 搬运约束：designator 输入格不等于最终 root；捕获与剥离共用同一份绝对 cells，不从旋转后的 `Gravship.Foundations` 反推源格。跨图后旧 `Ship` 快照失效，按 ownerId 重新查询。原版 `MoveDesignator()` 缓存旧 Map，战术对接每次创建 `Designator_MoveGravship(targetMap, marker)`。

## 武器、弹体与护盾

机制见 [太空战架构](太空战架构.md) 和 [护盾机制基线](护盾机制基线.md)。

- 工程设备复用 `CompSpaceWeapon.manualOnly`、手动组、`SpaceWeaponShot` 与统一光束碰撞；惯性耦合束逐 tick 支付及结算、跳过全部盾面，后效经 `SpaceObject.CoupleMotionWith → ShipPhysics.CoupleMotion` 交换冲量，采矿后效由 `SpaceImpactEffects` 的 Engineering partial 执行切割及原版拆除产出，不建立拖曳／对接／地图扩容入口。机制以太空战架构 §5.9 为准。
- `SpaceWeaponService` / `SpaceWeaponShot`：武器索引、只读瞄准能力、实际转向与唯一 Prepare→Launch→Commit 事务；仅执行明确的 `WeaponFireRequest`，不扫描宇宙对象选敌；逐发弹药、装弹机基础脉冲、沿物理链逐段预留的加速脉冲、电容放电与末端炮口在此一次性冻结，成功发射后统一扣费；缺电加速段跳过且不增加弹速，后段仍继续检查。附件电容独立储能、限速充电，仅充电需求变化时更新 `CompPowerTrader.PowerOutput`。锁定弧与发射轴分离，全部武器统一以实例 `fireDeviationDeg` 检查目标与实际炮口/固定轴夹角。Traverse 无独立逐 tick 扫描，只按火控或原版图内目标命令转向；载人岗位统一使用原版 `CompMannable + ManTurret`，操作人只读原版 Mannable、位置只读原版交互格；预留人选存武器 comp，补位由统一原版 Job 清理通知及武器/Pawn 事件触发。`SpaceWeaponManning` 仅提供无状态的自瞄开火、成品交互点、实例建造保护和岗位连线适配，不另存操作人或镜像 Mannable getter。Mannable/Traverse/Magazine/Attachment/加速件以正交 Comp/能力接口参与，第三方不得建立家族特判。
- `SpaceWeaponAttachmentSlots` / `SpaceRailgunConstruction`：武器 Def 声明的插件槽位、允许挂件与串联加速件的选中建造按钮及槽位提示唯一入口；加速段到装弹机的反向关联从 Def 注册反查。轨道炮由装弹机的状态 Comp 管理已解析加速段并统一规划能量、分发颜色；加速段颜色 Comp 不独立轮询。两者经原版 `ThingWithComps.DrawColor → ThingComp.ForceColor` 给 `CutoutComplex`／`_m` 红色蒙版提供主色；绿色通道才对应 `DrawColorTwo`。状态变化经 `Notify_ColorChanged` 刷新 MapMesh，不要求建筑专用 `thingClass`；不切换整张贴图，也不使用 `CompGlower`。状态与预瞄都复用 `SpaceWeaponShot` 的能量规划，安全路径复用同一判定。
- `Building_SpaceTurretGun` / `DefModExtension_SpaceTurretArt`：替换指定炮塔的旋转顶部材质，位置、角度和绘制继续走原版 `Building_TurretGun`/`TurretTop`；Def 固定为仅点防的 1×1 激光炮不触发原版同图索敌，以免发射原版机炮弹。
- 重炮、速射炮、激光炮的 2×2／3×3 炮塔逐实例地面／太空模式互斥：地面原版 `Building_TurretGun` + `Verb_SpaceTurretGround`，太空 `SpaceWeaponShot`；`CompSpaceWeapon` 是模式和太空最小射程的事实源。专用点防不切换。
- `CompMissileAutoloader` / `SpaceMissileMagazineGeometry` / `CompLoadedProjectileGraphic`：唯一 1×3 无人导弹架使用原版 `CompChangeableProjectile` 的一发待发状态和弹种筛选；前一格嵌墙、后两格在船内。1×2 气密导弹仓只可与船内两格同向并排，左右槽位由发射架 Def 声明；原版设施 Comp 登记链接，建造与运行时复用同一几何判定，同归属同派系才自动送入实体导弹。开火、库存、筛选、供电和归属事件合并到下一游戏 tick 按发射架 ID 顺序补弹，双架共享仓不重复取弹；仅库存被原版预留而受阻时保留条件性 60 tick 重试。发射架保留三层整图，以 `Patch_MissileLauncherWallLink` 使原版墙在 `LinkGrid` 中与其相连。导弹物品通过 `DefModExtension_SpaceMissileAmmo` 指向宇宙弹体，三层绘制中层读取同一 `SelectMagazine()` 结果；不改共享 `GraphicData`。
- `SpaceProjectileService` / `SpaceCollision` / `SpaceImpactEffects`：含冷发射程序的宇宙弹体、统一碰撞与联合命中效果链；普通弹体每发新建 SpaceObject，侵入 shuttle 接管现有容器与地图，复用同一导弹工作表而不归入普通弹体图池。炮口闪光、点火尾焰/烟迹和命中视觉只由弹体服务（含 Visuals partial）登记并在前台层绘制；逐次接触读取 `SpaceCollision.VisualContact` 快照，不另建弹道。炮塔绘制后坐共用 `CompSpaceWeapon.VisualRecoilOffset`。完整弹芯以效果 `penetrates` 启用预算续穿，`ApplyToDefender` 返回实际吸收后的剩余比例；`SpaceCollision` 同 tick 从原交点继续唯一求交链，`SpaceProjectileService` 持有跨 tick 剩余倍率，不再重复衰减速度和穿甲。盾面效果与发生器实体效果分开解析；轨道破片不继承母弹贯穿能力。基架毁伤门禁统一为 `SpaceImpactEffects.CanDamageSubstructure`，原版毁伤经 `Patch_SubstructureDamage` 共用；地板联动清理沿用 `RemoveFoundation` 补丁，承伤契约见太空战架构 §3.4。
- `CompSpaceShield` / `CompDeltaVShieldInterceptor` / `SpaceShieldRefraction` / `SpaceShieldProjectileBehavior`：独立 `DeltaV_ShieldGenerator` 的守卫、动能、电磁三模式逐实例状态、几何、逐发电费和分层投射器绘制；原版发生器保持原样。专用拦截器保留原版容量／拦截，守卫盾容 3000、新建满盾、每累计通电一游戏小时免费充满，恢复倒计时保存剩余 tick，断电／关机／搬运／归档暂停，期间由原版 `CompRefuelable` 实体白银 1:1 补充；守卫由原版 `CompPowerTrader` 自动接电、持续消耗 10 W，断电仍可用已有盾容拦截；新建时满盾且可立即切换，从其他模式切回守卫后才锁定至累计通电一小时，半径由实例化的原版拦截器 Props 提供。动能线盾只碎裂非制导实弹，弹体 Def 确定破片，盾实例确定速度变化；破片 Def 与实际速度决定毁伤。电磁线盾只折射激光，`SpaceShieldRefraction` 的同一公式供碰撞与说明使用。盾交点只在 `SpaceCollision` 求解，逐发脉冲从本机电网电池按实际支付量扣费；欠费本发仍碎裂／按已付电量偏转，随后线盾短时失效。线盾显示、选中预览、碰撞与扣费只读取 `CompSpaceShield.State`，盾段几何共用 `GetSegment`。设置窗口拖动时写入实例参数，关闭未确认时恢复旧值；不修改 Def 共享 `GraphicData` 或原版盾 Props。具体契约以 `doc/护盾机制基线.md` 为准。
## 渲染与视图

- `ShellRenderer` / `MapOverlayRenderer` / `ShellDrawBackend` / `ShellRenderRuleDef` / `DockingGhostRenderer` / `ShipSilhouette`：整壳分层、地图内容收集、绘制后端、Thing 外壳绘制配置、幽灵和剪影。`MapOverlayRenderer` 只收集、排序并同步交付命令，`ShellLayer` 管理前后层及槽位，`ShellDrawBackend` 是当前 1.6 的命令缓冲提交与清深度入口。入壳 Thing 的静态层走原版 `Thing.Print`，实时层经限定作用域捕获原版 `Graphics.DrawMesh`；替代图为有序整组替换。门在外壳上仅同步全开／全关终态。炮塔旋转炮身由 `IShellTurretTopSource` 提供当前材质和角度，规则决定仅绘炮身并置于船壳上层；轨道装弹机用规则排除，加速段内构与外壳入壳，不修改碰撞分类。
- `GlobeDisplayInfo` / `GlobeDisplayRules` / `PrefabGlobeMeasurements`：星象仪非太空地形面积、成员标记、残骸与缩放门槛的共同入口；有图读 Map，未物化读启动时 prefab 测量，归档保存无法从卸载图读取的显示摘要，恢复改读实图。具体显示和缓存契约见星区架构 §11.1。`SpaceAimController` 与 `Patch_AimModeClicks` 共用 UI 门禁，只有原版 UI 处理后剩余的地图按下事件能授予手动开火资格，细则见太空战架构 §6.1。
- `ThrusterEffects` / `ThrusterAudio`：只读真实分配油门的表现。
- `ThrusterDebugOverlay` / `WeaponArcOverlay` / `CollisionDebugOverlay`：聚焦图上的三个独立会话视图开关。武器射界直接读取武器 Def 的真实射程与安装射界；只绘边界和按游戏 tick 扫动的线，实例颜色由 Thing ID 稳定分配，不影响火控。射界开关关闭时不调用绘制入口，材质和网格只在开启后首次需要时创建，并在关闭时释放。
- `MoonPoolUtility` / `Patch_MoonPool` / `MoonPoolGraphics` / `SectionLayer_MoonPool`：月池判定、无顶密封和连接视觉；每图月池格缓存首次查询建立，此后随地形变化逐格维护，不按 tick 重扫。
- 外壳排序：按 objectId 整壳分层，背景壳在聚焦图下，进场／选点壳在聚焦图上；不退回逐建筑海拔或透明队列排序。推进器火焰每条命令使用独立的 `MaterialPropertyBlock`。

## 生命周期、NPC 与星区生成

机制见 [星区架构](星区架构.md) 和 [太空战架构 §9.1](太空战架构.md#91-远距整图归档与撤退)。

- `SpaceLifecycleService`：生成、休眠、物化、归档和销图。普通口袋图无承载时经 `HasMapSupport/QueueStructureCheck/RecycleUnsupportedMap` 在帧边界复核回收，剩余 Pawn/物品不阻止；不受当前聚焦或玩家保护豁免，细则见解耦架构 §8.1。无快照 marker 首次物化的内容链 = 类型 prefab 池（seed 确定性选取，入队测尺寸与盖章同一解析），**容器先注册、结构后铺设**（驾驶台 `ClaimOnSpawn` 认领要求 FrameOf 已解析；归属名 = marker 生成时决定的完整名，经 envLabel/归档 carriedLabel 传承）。池空在生成期拦截；池失效在入队/物化期报错并取消该 POI（prefab-only，不回退程序生成）。
- `NpcShipAiService` / `NpcShipController`：所有船型使用完整战术 AI，无武器不按船型禁用站位或撤退；NPC 战术资格、当前战损重评、返厂目标、无图导航意图、退场决定及跳帮均在 NPC 层；选敌和站位调用上述共用类。生命周期沿用普通距离规则，只执行通用归档、恢复与销图，不解释撤退意图；归档通知只记录 AI 观测值，数值动力摘要由有图对象捕获，不触发战术决策；恢复后清理摘要与运行时导航任务。已选目标的射击、点防与自动驾驶仍逐 tick，开火走共同 controller 和 `SpaceWeaponShot`。炮手补位由岗位结束、武器状态和 Pawn 可用性事件触发，NPC 不再每 60 tick 重派。AI 资格门禁与 dev 诊断共用同一判定，Combat 日志只输出状态变化。`ArchivedMapStore` 是远距普通口袋容器的原版 `Map.ExposeData` 整图序列化与运行时卸载/恢复入口，归档内容随 `ArchivedSpaceObject` 落档；远距归档与恢复按设置周期全量检查；有图／无图导航共用 ShipAutopilot 任务表、Step、MPC 与 ShipPhysics 分配／积分，无图阶段以逐台数值推进器布局进入同一分配器；推进后复核普通距离恢复，与生命周期扫描周期无关。该路径尚待游戏内存读档和引用完整性验收。
- `SectorContentService` / `SectorContentTypes`：星区首次生成的幂等记账与按类型生成循环；marker 身份在生成时一次性决定——随机派系（可见非玩家派系，不做类型→派系映射）+ 完整名（`DeltaV_NamerSpacePoi` RulePack 词干 + 类型名 + (派系名) + #ID）烘焙进 envLabel/faction，物化时直接应用。`SectorContentTypes` 是任意深度的分类树（星区架构 §11 分类），分支只分组、生成与设置只遍历叶子；规则读 `DeltaVSettings.sectorRules`（`SectorTypeRule`：保底数/分段额外量/prefab 池；缺条目用注册表默认，读路径不静默改写设置）。
- `QueueFrameAction`：离开当前 tick/加载调用栈的唯一帧边界延迟机制。双船场景重建经 `UniverseManager.BeginSceneReset` 在该消费点逐阶段排空旧动作后销图、清缓存、生成新图；不得先注销弹体容器或直接丢弃待执行清理。弹体退出共用 `QueueProjectileCleanup`，原版销图仍经 `SpaceLifecycleService`；完整顺序见太空战架构 §4.5。

- 容器与宿主：对象存在性不以 `Find.Maps.Contains` 判断，归档／恢复经 `UniverseManager.ReplaceRepresentation`，不触发普通注销／新生。`UniverseHostParent_DeltaV` 只承担 pocket-map `sourceMap` 契约，无 tile、不可聚焦、不进 WorldObjects，不承载游戏事实。

## 通用地图与 prefab

运行时契约见 [Prefab 状态重建](Prefab状态重建.md)。

通用地图工具包（上述坐标/渲染/搬运/生命周期/生成条目同属一个将来通用的地图工具包；后续地图能力一律扩展这些入口，不建平行实现）：

- `MapContentSpawner`：Thing 记录回放（def/stuff/quality/hp/stack/faction → `GenSpawn`）、Scribe 恢复实例落位、基架盖章包裹器与设施重链（`RelinkGravshipComponents`）的唯一入口；`PoiSnapshot`/`ShipProceduralLayout`/`MapPrefab` 的落物一律经此。
- `MapPrefab` / `MapPrefabDocument` / `MapPrefabThingState`：通用地图 prefab 的唯一门面、文档与逐实例状态入口。地形及旋转锚继续复用原版 `PrefabUtility`，建筑/物品通过原版 `Thing.ExposeData` 导出并整批 Scribe 读取；基架/屋顶另存侧车，锚点掩码只纳入 Building+Item。重建顺序为 foundation（含指定归属）→ terrain → 整批解析内部引用、重分配 Thing ID、指定派系与旋转落位 → roofs → 重链 → marker 展开；外部旧地图引用不随 prefab 复制。驾驶台源身份在落位前清理，对接口通道格按新锚换算。文件落 mod 根 `Prefabs/`，新文件格式要求重新导出旧 prefab；地形 Def 读入走原版 XML 交叉引用管线。prefab 池仍由 `LoadRelative`、`ListPrefabFiles`、`ResolvePoolPath` 维护。具体契约见 `doc/Prefab状态重建.md`。
- `CompPrefabMarker` / `CompPrefabPawnSpawner`：prefab 重建标记框架——只有 `MapPrefab.Spawn` 在整片放置完成后调用 `Expand(PrefabSpawnContext)`（context 含 Map/Faction/OwnerId/Root/Rotation/Universe，为后续 SpaceObject 展开器预留）；普通读档与 `PoiSnapshot.ApplyTo` 恢复不调用展开。新展开器 = 新子类 + CompProperties，`TryGetComp` 基类匹配零修改纳入。当前仅实现 Pawn 标记：每个标记生成一名 Pawn，Def 指定 PawnKind 优先，其次目标派系基础成员、原版 `Faction.RandomPawnKind`，最后由 Def 指定后备种类；原格优先、附近可站立格兜底，成功后销毁标记。人形船员的真空服与头盔统一由 `SpacePawnEquipment` 在入图前穿戴，程序测试船员同用此入口。SpaceObject 标记延期。
- `ShipProceduralLayout` / `ShipPocketMapFactory` / `ShipTestScene`：口袋图生成与程序生成布局。程序生成仅存于 `ShipTestScene`（MapPrefab 导入失败时的唯一回退特例）；星区 POI 物化不走程序生成。
