# 项目级单实现审计（2026-09-22）

> **历史审计，已退役，不可作为当前实现依据。** 下方 `ShipState`、`ShipModeService`、`ShipStructureResolver`、`dockedMap` 等名称和结论记录当时的收口过程，不能指导现行施工。当前入口见 [代码入口索引](代码入口索引.md) 和 [飞船与 SpaceObject 解耦架构](飞船与SpaceObject解耦架构.md)：一图一个容器，同图可多船，对接合图、实际出力拆图。

范围：`Source/**/*.cs` 的可执行逻辑。目标是识别同一事实、同一计算或同一生命周期动作的
重复实现；不改变玩法规则、设置、Def、翻译键或存档字段。工作树原有未提交改动作为基线保留。

状态定义：**删除** = 无调用价值或重复入口已移除；**收口** = 调用方已迁入唯一入口；
**明确保留的双路径** = 行为目标相同但引擎边界不同，必须共享权威数据/算法而不能强行合并。

## 审计清单

| 域 | 结论 | 唯一入口 / 处理 |
|---|---|---|
| 坐标与停放锚 | 收口 | `OrbitSphere` 负责球面几何；`SpaceTransform` 负责全部坐标与停放锚镜像。检查脚本禁止其他文件出现 `PrefabUtility.GetRoot`/`engineToCenter`（2026-09-30 起豁免 `MapPrefab`：其调用 prefab 放置角点重载 `GetRoot(PrefabDef, pos, rot)`，属原版 prefab 放置语义，非停放锚换算）。停靠船原点由 `ShipStructureResolver.DockedOrigin` 唯一恢复。 |
| 对象、地图与 ID | 收口 | `SpaceObject.InteriorMap` 是当前内部图语义；`UniverseManager.ObjectById/ShipById` 是 ID 查询；对象列表只经 `RegisterObject/UnregisterObject` 改变。ID 高水位按全部已占用 ID 的最大值加一校正，注册时拒绝碰撞并推进计数器。 |
| 船体、引擎与成员关系 | 收口 | `ShipStructureResolver` 统一当前图、主引擎、连通域、Thing 成员与停靠原点。渲染、拾取、UI、星球仪、对接及跳帮调用同一入口。 |
| 基架归属 | 收口 | `SubstructureOwnership` 独占归属算法；驾驶台不再自带 BFS。待盖章状态属于各 MapComponent 的非序列化实例，生成/放置只清理自己的地图。 |
| 对接与发射状态 | 收口 | `ShipModeService` 持有 universe 级非序列化模式状态并独占模式编排；`LandingApproachController.DockingPlan` 仍是注册后落点/位姿的唯一事实。 |
| 原版 Gravship 私有行为 | 收口 | `GravshipInterop` 是空洞预览、私有字段和实际放置收尾的唯一镜像；模式编排只决定何时调用。真实消费仍只发生在完成捕获窗口。 |
| 生成、休眠与销毁 | 收口 | `UniverseManager.Generation` 与 `UniverseManager.Lifecycle` 持有实例状态。休眠集合、生成队列/活动任务/阻塞计时不再是静态跨档状态；地图删除统一先由生命周期入口忘记休眠状态并释放 overlay。 |
| 读档与 dev 重置 | 删除重复序列 | `UniverseManager.ResetRuntimeServices` 是缓存、输入门、生成和生命周期状态的共同清理入口；两条路径只保留各自特有的对象替换/迁移工作。 |
| 物理与时钟 | 明确保留的双路径 | 手操与自动驾驶是两种输入路径，但都经过 `ShipPhysics` 的分配器；总装在 `GameComponentTick`，自动驾驶船从普通积分循环排除，避免双积分。表现层允许帧时钟，Core/Interaction/Lifecycle 禁止帧时钟模拟。 |
| 渲染与拾取 | 明确保留的双路径 | 背景/前台命令缓冲是层序要求下的两条渲染通道，共享 `ShellRenderer` 数据。拾取只读同一船壳/内部图查询。对接幽灵仅缓存纹理材质，位置、角度、对齐均每帧读取 `ActivePlan`。 |
| Harmony | 收口 | Patch 只做原版边界参数适配、门禁和通知；船体、生命周期、模式状态、坐标及 Gravship 镜像均回交对应服务，不在 Patch 中复制算法。 |
| Debug | 收口 | dev `ResetObjects` 使用与读档相同的运行时清理入口；测试场景通过对象注册入口和生命周期销毁入口处理状态。Debug 帧耗时统计是表现诊断，列入静态状态白名单。 |

## 本批删除或替换的重复入口

- 删除散落的 `docked ? dockedMap : map` 当前图选择，统一为 `InteriorMap`。
- 删除旧模式控制器内的引擎、船体成员与停靠原点查询副本，统一为
  `ShipStructureResolver`。
- 删除 `SubstructureOwnership.PendingStamps` 全局字典和全局清空语义。
- 删除驾驶台自己的归属域 BFS，统一调用 `ClaimConnectedDomain`。
- 删除生成、休眠的静态队列/集合与读档 logger/provider 配置。
- 删除对接幽灵复制的 host/offset/angle 状态。
- 删除测试场景直接 `objects.Clear()`；所有对象变更均经过注册入口。
- 删除读档和 dev 重置两份缓存/服务清理序列。
- 已不存在 `FlyToAsync`，未保留兼容入口。

## 明确保留而不合并的路径

- POI 同步生成与分帧生成：前者是外部 `MapGenerator` 抢占边界，后者是预算化任务；二者
  共用同一实例生成服务的队列、活动任务和清理入口。
- 战术降落与战略发射：原版入口和玩家语义不同，但共享 `GravshipInterop`、模式状态、
  船体解析、停放锚和生命周期处置，不再各自维护事实。
- 聚焦图内容与非聚焦船壳：一个是原版 Map renderer，一个是派生代理；共享对象当前内部图、
  船体域与位姿，不允许代理反向成为事实源。

## 自动门禁

运行 `tools/architecture-check.ps1`。它阻止：

- `UniverseManager` 外直接修改 `objects`；
- 调用点重写当前内部图 ternary；
- `SpaceTransform` 外出现停放锚私有语义；
- Core、Interaction、Lifecycle 使用帧时钟推进模拟；
- 生命周期服务外直接依赖底层休眠集合；
- 未进入显式白名单的可变静态状态。

白名单仅覆盖 Def/设置 UI、输入快速门、渲染/反射缓存、调试计数及 Harmony 重入卫兵；
新增项必须在代码评审中说明类别，不能仅为通过脚本而扩充。

## 非本批问题

本轮未发现需要扩大范围修复的独立玩法缺陷。游戏启动、Harmony 实际绑定和完整交互矩阵仍需
在 RimWorld 内实测；静态构建不能替代该验证。
