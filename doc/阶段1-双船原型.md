对应 [story.md](story.md)「当前阶段计划 §1」。目标：验证整个架构最核心的参考系模型——两张口袋地图作为独立太空对象，统一宇宙坐标，非聚焦船外壳代理（连续平移 + 任意角旋转），聚焦切换不改绝对状态，存读档恢复。

**状态：已实现并完成游戏内验证（2026-09-11 实现，2026-09-12 验证通过）。** 验证通过后移除全部阶段1 调试设施（分模块日志开关、点击诊断日志、姿态 dump、调试 HUD、网格诊断 action、轨道测试动画，见「调试设施」节）；保留场景创建、聚焦切换、外壳点选与敌舰手动平移/旋转。2026-09-12 修订：① `WorldCameraDriver` 每帧红字 → 飞船图持有真实轨道 tile；② 宿主图提前进阶段1 + 修复显示偏移；③ void 花屏 → 船图恢复 `renderWorld=true`；④ 甲板换逆重基架 Substructure、修复 Void.png 颜色错误；⑤ 架构定稿：宿主图仅为机制锚点、固定模式走逆重降落（未来阶段）；⑥ 外壳代理定稿为每帧网格重放（原版 DrawMesh 通道），离屏纹理捕获方案经三轮实测失败后废弃（教训见下）。

## 坐标与角度约定（改动必须同步本节）

- 宇宙是 2D 平面，与地图 XZ 平面平行。`SpacePose.position` 用 Vector2 表示 (x, z)。
- `angle` 弧度，0 = +X。2D 旋转公式（把 (x,z) 当平面直角坐标逆时针为正）：
  - `u.x = p.x·cosθ − p.z·sinθ`，`u.z = p.x·sinθ + p.z·cosθ`
  - 对应 Unity：`Quaternion.Euler(0, −θ·Rad2Deg, 0)`（已验证符号一致）。
- 显示层矩阵只能从 `SpaceTransform.FocusedMeshRotation` 取得，禁止在渲染代码手写 Euler。
- 阶段1 pivot 约定：**ship local 原点 = 地图几何中心**（`Map.Size / 2`）。`SpacePose.position` 即地图中心在宇宙中的位置。阶段2 若改为按船体结构包围盒取原点，只动 `SpaceTransform.ShipLocalOrigin`，但会改变已有存档中姿态的语义，需迁移。
- 坐标链各段唯一入口：`MapToShipLocal` / `ShipLocalToUniverse` / `UniverseToShipLocal` / `UniverseToFocused` / `FocusedToUniverse`（+ 角度版与绘制便利版）。

## 地图管线

三层结构：**宿主图（轨道层真实 tile）→ 飞船口袋图 ×2 → 船体结构**。

### 宿主/显示地图（2026-09-12 按用户决策提前进阶段1）

- 宿主 = Universe Layer 映射到星球外层空间（轨道层）**真实 PlanetTile** 上的普通地图：`TileFinder.RandomSettlementTileFor(轨道层)` 选空 tile → `GetOrGenerateMapUtility.GetOrGenerateMap`（普通管线，非 pocket），WorldObjectDef `DeltaV_SpaceHostParent`（普通 `MapParent` + `mapGenerator=DeltaV_SpaceHost`）。
- 生成器 `DeltaV_SpaceHost`：镜像原版 Space 字段，`renderWorld=true`（真实 tile → `MapParent.Tile` 有效，聚焦宿主图时星球背景合法工作）、`disableMapClippers`，genSteps 复用原版 `Space` genstep（全图铺 Space 地形）。
- 作用（story「口袋地图需要宿主」的引擎语义）：两张船图的 `PocketMapParent.sourceMap` 指向宿主图——`StorytellerUtility.DefaultThreatPointsNow` 直接读 sourceMap 无空检查（NRE 风险），财富统计、运输船任务、移除级联都以它为锚；真实 tile 还让事件/世界 UI 原生兼容。
- 轨道层由 Odyssey 开局剧本注册；无轨道层的游戏（非 Odyssey 开局）宿主创建会明确报错中止。
- **聚焦宿主图 = 空间画面**：以 `UniverseManager.HostFrame`（合成显示帧：宇宙原点/0 角，锚在宿主图中心，纯显示层、不是宇宙状态）把**所有**飞船画成代理。宿主图自身尺寸（150×150）是显示/性能参数，不是宇宙坐标协议；story 规划的 800×800 尺寸性能测试仍属阶段2。

### 飞船口袋图

- 生成器 `DeltaV_ShipPocket`（MapGeneratorDef，参考原版 SpacePocket 字段）：
  - `renderWorld=true`：**必须有**星球背景模式。渲染链为 `WorldSkyboxCamera`（清色缓冲+深空底色）→ `WorldCamera`（星球，每帧由 `WorldCameraDriver.ApplyMapPositionToGameObject` 定位到地图所在 tile 上空）→ 地图相机（**不清色**）。透明 void（`dontRender`）透出的正是前两层。`renderWorld=false` 时世界相机关闭、无人清色缓冲，void 区残留上一帧——2026-09-12 实测花屏根因（RimExodus VoidTerrain.xml 注释记录过同款问题）。
  - 无 tile 口袋图与 renderWorld=true 的组合在原版不存在，直接组合会每帧红字（`PocketMapParent.Tile`=-1 送进 `GetTileCenter`）。解法（2026-09-12 定稿）：**飞船图生成时直接持有真实轨道层空 tile**——`MapInfo.Tile` 由 `parent.Tile` 派生，`Map.Tile` 因此有效，`WorldCameraPosition` 与 `currentMap.Tile.Layer.BackgroundWorldCamera*` 视差参数全部走原版正路，无需任何 override。tile 由 `FindFreeOrbitTileNear` 在宿主 tile 附近挑空闲格（排除已有世界对象与已有地图，`Game.FindMap` 按 `map.Tile` 匹配所以不可撞车）→ 各船星球背景与宿主图几乎一致。代价：宇宙抽象坐标与星球 tile 暂时是两套账（背景只是视觉锚点），Universe Layer 的正式映射属阶段2。
  - `disableMapClippers=true`：不生成边缘裁切平面，代理画到地图矩形外不被 z-erase；
  - `destroyOnParentMapAbandoned=false`：宿主图被移除时不级联销毁飞船（场景重建时先销毁船再销毁宿主）；
  - `canLaunchGravship=false`、biome Orbit、恒温 21°C；
  - 无 ScenParts / FogSpace：无散落物件、全图直接可见。
- 铺设流程：`GenerateShipPocketMap`（`PocketMapUtility.GeneratePocketMap` 的本地复制，WorldObject 换 `DeltaV_ShipMapParent`）→ `ShipStructureStamp`（genSteps 完成后补铺，正常 gameplay 时点，mesh/region 走原版 dirty 机制）。
- 阶段1 船体不盖屋顶、不供电（Orbit biome + 恒温下光照与温度都无问题）。

## 外壳代理（2026-09-12 第四版定稿：每帧网格重放）

**架构定稿（用户决策，2026-09-12 当日修正表述）**：宿主图是"宇宙位置标记 + 口袋图宿主"的机制件，不承载**完整内构**渲染（当时的争议点是试图在宿主图绘制含内构的完整船体）；固定模式（未来阶段）用逆重飞船降落机制把口袋图的船真正落到宿主图上（记录降落前宇宙位置）——届时玩家在宿主图上看到的是自己船的**真实建筑**，敌舰接近时在宿主图上以外壳对轰。但**船体框架外壳在任何视角都照常显示**（含宿主图——玩家误入宿主图不能看到空白，聚焦宿主图 = 空间总览）。驾驶模式下玩家看自己船图（identity），其他船以重放外壳显示。

技术路线（`ShellRenderer` 每帧重放，RimExodus 邻居图重放思路 + 旋转矩阵）：

- 内容源：飞船 Map 的 `MapDrawer.sections[,]`（反射读取）中每 section 的 `SectionLayer_Terrain` + `SectionLayer_ThingsGeneral` 子网格。Void 地形 `dontRender` 不产生网格，重放出来的天然只有甲板与建筑；渲染经原版材质 → **其他 mod 的墙体贴图天然兼容**。
- **提交通道 = 原版 `MapDrawLayer.DrawLayer` 同款**：`Graphics.DrawMesh(mesh, matrix, material, subMesh.renderLayer)`——camera=null + Layer 路由。这是本管线唯一验证过的即时网格通道。
- **地形纹理必须使用 ship-local UV**：代理为每个地形子网格派生普通透明材质网格，把源顶点 `(x,z) × 0.0625` 显式写入 UV，再走同一代理矩阵。`0.0625 = 1/16` 来自 RimWorld 1.6 本机 `Custom/Terrain hard` DXBC 顶点程序的实际指令，不能省略，否则纹理比例会放大 16 倍。缓存以 SectionLayer 为事实源，在 section dirty、换焦、读档及场景重置时释放重建，不持久化。
- **显示参考系由当前地图决定**（`UniverseManager.ShipOnMap(Find.CurrentMap)`），不依赖持久化的 focusedShipId——玩家可能经殖民者栏/地图按钮等任何原版途径切图，显示层必须无差别跟随；focusedShipId 由 GameComponentUpdate 每帧向当前船图同步（只动参考系字段，不碰 pose，符合不变量 #5）。
- 变换：`TRS(drawPos − R·shipCenter, R)`，即"绕飞船中心旋转 + 平移到聚焦帧绘制位置"，任意角成立。
- 剔除：视野矩形逆变换回飞船局部取包围盒（保守），与 `section.Bounds` 相交测试；dirty 自驱动分两档（2026-09-12 实测"结构变更后旧网格残留叠加"后修正）：① `dirtyFlags != 0` → `TryUpdate`；② **`TryUpdate` 会清零 `dirtyFlags` 但对视野外保留 `anyLayerDirty=true`，原版由 `Section.DrawSection` 每帧检查并调 `RegenerateDirtyLayers` 补建**——重放必须镜像这条补建路径（反射 `anyLayerDirty`/`RegenerateDirtyLayers`），只查 `dirtyFlags` 会永久错过视野外变脏的 section。网格提交也必须镜像原版 `MapDrawLayer.DrawLayer`，只画 `finalized && !disabled` 的子网格：结构删除某材质后，该子网格仍留在列表且底层 Mesh 可能暂存旧顶点，但 `finalized=false` 是原版用于禁止旧几何继续显示的权威门槛。
- 除地形层的局部 UV 派生网格外无独立缓存；该网格可从 SectionLayer 完整重建，不持久化，并有 dirty、换焦、读档与场景重置清理入口（不变量 #13）。

### 已废弃方案与教训（勿回退）

1. **分类色块 quad**：观感如遮罩（用户实测否决）。
2. **离屏纹理捕获**（自建相机 + RT 读回）：三轮实测全空。定位到的硬约束：① `Graphics.DrawMesh` 提交只存活一帧，运行中创建的相机次帧才渲染；② **"指定相机"的 DrawMesh 重载在本渲染管线不被消费**（反编译确认原版只用 camera=null + Layer 四参数重载）；③ GravshipMask 层路由方案亦未出图（原因未明）。若未来重启纹理捕获（性能优化或 LOD），方向应是复刻原版 GravshipCapturer 的常驻副相机 + 色键管线，而不是自建相机。
3. **宿主图上重放完整内构**（含 LightingOverlay 等的完整内部渲染）：兼容面问题，已被定稿否决；但宿主图上照常重放**船体框架外壳**（聚焦宿主图 = 空间总览，全部飞船以 HostFrame 显示）——注意这是两回事，勿混淆回退。

## 与 RimExodus 的复用边界（本次实际取舍）

- **复用**：口袋地图生命周期经验、Void 地形保证项（整套 XML 注释照搬含第三方 minimap NRE 教训）、"CurrentMap setter 是聚焦切换唯一漏斗"、"非序列化缓存必须读档自愈"等纪律、SectionLayer 网格收集与 dirty 自驱动结论（用于纹理捕获）。
- **未复用**：其 CommandBuffer 邻居重放管线（逐帧排序、WaterDepth 副相机、SkyTint 补丁、裁切面开洞）以轴对齐邻接为前提；且逐帧重放整体内部结构已被纹理捕获方案取代。

## 交互：外壳点选聚焦（2026-09-12 增）

点击显示中的飞船外壳 → 聚焦切换到对应地图，相机落在点击位置对应的船内格（所见即所落），并**同步缩放**（RimExodus SeamlessCameraFocus 同款结论：`CurrentMap` setter 的 `Notify_SwitchedMap` 会用目标图 rememberedCameraPos 同时恢复位置+缩放，切图后必须记录 `RootSize` 并在跳转后 `SetRootSize` 显式重设——三处聚焦切换都已应用：外壳点击、dev 切换、聚焦宿主图）。

**选取点击与瞄准点击的兼容契约（勿回退）**：

- `ShellPicking.ShipAtFramePoint`（`Source/Interaction/ShellPicking.cs`）是外壳命中的**唯一入口**：聚焦帧地图点 → 宇宙 → 各船局部 → 船脚印（非 Void 格）命中。选择与未来的武器瞄准（阶段5）共用。
- 选择路由（`UniverseManager.HandleShellClick`）在**瞄准会话**（`Find.Targeter.IsTargeting`）或建造设计器选中时**完全不参与**——那类点击属于瞄准/建造流程；瞄准层届时在自己的 Targeter 流程内调 `ShellPicking` 解析目标，不经选择路由。分界 = 是否处于瞄准会话，从第一版即成立。
- 选择路由另有让位条件：鼠标悬停窗口（`WindowStack.GetWindowAt`）、当前地图原版可选物（`ThingSelectionUtility.SelectableByMapClick`）、按下-抬起间拖拽（框选）。不消费 GUI 事件，原版点击流程不受影响。
- 命中精度为**选择级**（脚印格）；武器碰撞属**碰撞级**几何（AGENTS §14 三体不等价），阶段5 另行实现，不复用本判定。
- **中心系/地图系混用 bug 家族（2026-09-12 三次事故，已 API 级根治）**：`UniverseToShipLocal` 返回以地图中心为原点的船局部坐标，三次被直接当地图坐标用（FocusedDrawPosition 漏加中心、ShellPicking 查格子、点击后相机跳转→左下角）。根治：`SpaceTransform.UniverseToMapPoint`（universe → 含中心偏移的地图坐标）为消费方唯一正确入口，落格子/落相机一律用它；直接拿 `UniverseToShipLocal` 输出当地图坐标 = 反模式。

## 已知风险 / 待实测核对项

- **重放内容完整性**：不重放 LightingOverlay/雾/水层，不画动态物件（Pawn 等走 dynamicDrawManager 无静态网格）——夜间飞船全亮、看不到敌舰船内 Pawn；后续按需补（RimExodus NeighborGlowOnlyMaterial 思路）。
- **星球背景一致性**：飞船图各自持有宿主附近的真实轨道 tile（`FindFreeOrbitTileNear`），背景与宿主图几乎一致；若仍出现 void 残影/花屏，检查是否所有船图都经 `GenerateShipPocketMap` 生成（parent.Tile 必须有效，无 tile + renderWorld=true 会红字且无背景）。
- **显示偏移修复（2026-09-12）**：首版 `FocusedDrawPosition` 漏加"聚焦地图中心"偏移（聚焦船宇宙原点渲染在其地图中心，而非地图角落），代理整体偏了半张地图——引入宿主帧时已修复，公式：`地图世界坐标 = 聚焦帧坐标 + ShipLocalOrigin(承载地图)`。
- **相机 clamp**：CameraDriver 把镜头限制在当前聚焦地图矩形内；聚焦船图时敌舰偏移/轨道半径已按 150 地图内设计。聚焦宿主图可同时看到两船代理（空间画面）；更远的宇宙视野属阶段2（宿主图尺寸与重投影策略）。
- **敌舰图进入方式**：阶段1 只能通过 dev 菜单聚焦切换进入敌舰图；无跳帮。
- **RimExodus 联装**：其通配 genstep 注入会在 Delta-V 口袋图上打出 `GenStep_SeamlessTile: map has no valid worldTile, skipping` 警告（每张图一次）——其守卫按预期跳过口袋图，无害。
- 编译用 NuGet ref 1.6.4633 对游戏 1.6.4871：所用 API 均已在反编译源码中核对，版本偏差风险低。
