# 有利射位与交战收益规划

## 单发射位估算（2026-11-12）

玩家和 NPC 共用当前观察。每轮捕获可用武器和开火参数，逐炮停火、供电和弹药门禁用真实状态。每个候选以真实炮口、射界、武器选择和接触方向估算一次开火。单发几何可求匀速提前量和预计接触速度，毁伤使用 `SpaceCollision.RayQuery` 与共用后效计算。弹丸、贯穿和破片在本次开火内共享局部扣减。其他武器与候选从初始观察开始，真实电力、弹药、护盾、建筑及随机流不受查询影响。

结构损伤用 HP／秒，守卫扣容用容量／秒，关键设备损伤按设备价值加权折为比例／秒。外层装甲项以首件实际受伤的全掩体非关键建筑的当前耐久为分母，衡量每秒能打掉多少比例，同样可以改权重或移除。这个指标允许单发伤害相同的激光射线偏好薄甲。默认原线性收益和风险曲线的横轴按旧默认 30 秒折算。护盾消耗、部件暴露和方向风险依赖本次观察。下一轮读取实际战损和资源。

保留方位／距离／朝向候选、保持与延续、物理到位和变速成本、路线检查及换位阈值。现有发射周期用作持续火力折算。策略和诊断已删除交战窗、爆发窗及预测失能。虚拟发射、到达队列和逐刻推进已删除。对局里逐发抢电、先破盾后打船等结果随实际开火产生，由后续观察反映。

### 同步射位评分：复用采样掩码（2026-11-14）

### 外部火控目标

自动火控和射位预测只从目标船的外部武器和推进器中找瞄点。默认先试外部武器，火控规则也可设为优先推进器。同类设备按稳定身份顺序检查，首选类别都不可达时检查另一类，两类都不可达时尝试船体中心。炮口安全和弹道检查按当前或候选位姿执行。敌舰装甲与护盾仍由共用弹体碰撞处理。

露天设备可作为目标，顶部炮塔和炮廓可从船壳识别。内部设备、驾驶台、供电和护盾发生器不参与部件目标选择。船体承伤仍处理实际碰到的建筑，关键毁伤奖励按允许瞄准的武器和推进器计算。玩家队列指令入队与执行时都校验归属、敌对关系和外部目标资格。

删除了射位预测和自动火控中的旧部件价值排名、按部件扫描遮挡深度的射线及全量部件清单。候选搜索同步完成，沿用现有火控与选位时钟。玩家部件指令窗口也使用同一清单，只列出目标船的外部武器和推进器。

## 目标与边界

默认预设通过玩家可编辑的同一套策略规则回答：**在当前双方能力下，去哪里、以什么相对运动状态交战，预期交换收益最好？** 对舰首武器／防护强、舰尾弱且确实能利用该弱点的目标，应绕到有利侧，减小相对方位漂移并保持有利射程；当弱侧改变、无法跟随或其他位置收益更高时，再转移。Automatic 是共用求解入口，具体偏好由生效规则的配置决定。

“尾部”不是固定奖励标签。真实弱侧可能是侧面、装甲缺口或护盾外露方向；全向炮塔仍能向后射击。持续环绕、占位、拉开和退出都是候选动作，取舍来自输出、承伤与到达成本。不得调整武器数值、护盾规则或船体布局来制造 AI 优势。

保持射位指保持**敌舰局部方位与距离带**，不是停在世界固定点，也不是把自身速度清零。敌舰平移／转动时，需要相应的非零终端速度和角速度；我舰朝向还须兼顾武器射界、真实轴向推力和自身防护。

继续保持既有分层：战术层选择交战意图，`CombatFlightPlanner` 生成完整状态参考，共同自动驾驶／MPC 与真实推进器执行。每个决策周期从真实状态独立重评，不等上段完成；执行连续、随机流连续。显式方向／方位／距离／朝向、逐炮规则、停火与撤退约束继续有效，显式环绕命令仍能持续环绕。

本阶段不重做全球坐标图、武器结算、战略 AI 或旧开发档迁移。极轴备用切基接缝仍是独立边界。涉及公共计算的抽取必须保持生产结算结果，不新增第二套碰撞／伤害规则。

## 策略编辑器与预设共用契约

2026-11-08 用户补充的硬约束：**这套策略必须能由玩家在现有策略编辑器中自行构建；内置版本只提供一套预设的规则优先级、条件和权重，不得成为独立的智能策略系统。** 本节约束后续所有阶段，编辑能力不是运行逻辑完成后的附加面板。

1. **一份数据、一条决策链。** 扩展现有 `CombatStrategy`、`CombatStrategyRule`、`CombatTacticSettings` 和评分曲线契约；玩家策略、内置预设与 NPC 的战斗机动消费相同配置、事实查询、候选搜索和评分执行入口。不得按预设名称／ID、是否内置、是否从编辑器创建来启用额外绕后、保持或收益奖励。既有 NPC 生命周期门禁不属于机动偏好，不能借其注入另一套选位逻辑。
2. **优先级与权重分清。** 规则列表仍按现有顺序匹配，先命中的规则决定本轮策略；条件与进入／退出迟滞沿用原契约。生效规则内再按配置的权重／曲线比较候选，低优先级规则不能暗中叠加偏好。每个新增字段明确作用域、单位、默认值及与现有六种曲线的关系。
3. **所有战术偏好可表达。** 有效输出、承伤、关键设备价值、射程／方位偏好、途中与切换代价、收益切换阈值及允许的机动选择，凡影响预设行为的取舍都须有可编辑的规则参数或曲线。新增观测量接入共用条件／评分能力；不能只增加一个不可展开的“智能绕后”开关，也不能要求玩家写代码或手改 XML 才能复现预设。具体字段在 P0 按用途映射，避免重复控件表达同一权重。
4. **通用计算负责事实与执行。** 弹道、毁伤估计、物理可达性、参考连续性与 MPC 是所有策略共享的能力；数值精度、查询预算等实现参数不必成为玩家权重。硬件／碰撞可行性不会因偏好权重为零而消失，关闭某个软评分项则必须真正去掉其贡献，不能回退到隐藏的默认奖励。
5. **预设可完整展开与重建。** 默认配置、内置规则说明、复制为自定义和恢复默认读取同一来源；依赖舰体能力的自动值须显示其计算含义及本次有效值，复制后保留同一语义。玩家能从空白规则构建等价配置，也能改成偏进攻、偏保全、少换位或持续绕行等不同偏好。预设本身没有额外执行权限。
6. **编辑、持久化与诊断同时交付。** 新字段同步接入草稿确认／取消、规则复制／排序、多选应用、策略文件导入导出、Scribe 与 prefab／归档保存；校验与 Keyed 说明同时补齐。诊断展示实际命中规则、指标原值、权重／曲线后的贡献和切换原因，与执行读取同一份配置。

现有入口已支持规则排序、条件迟滞、机动选项、六种曲线及内置规则复制；尚不足以直接表达本计划新增的全部收益与切换取舍。实施时先补齐这套公共表达能力，再用它配置默认策略，不另外建设策略语言或第二套编辑器。

| `CombatReposition` | 当前速度、制动成本、到期重评、近似等价随机 | 去掉运动进度本身的默认收益；同尺度比较到位保持与继续运动 |

| `CombatWeaponThreat` | 炮口、射界、转船／炮塔可达时间、散布命中包络 | 防护方向、有效毁伤、资源约束，以及敌方转向后的威胁变化 |
| `ShipFireControl.Strategy` / `SpaceCollision.TargetObstruction` | 已有部件选择及只读遮挡深度 | 遮挡深度并非穿透毁伤；与战术收益复用同一目标事实和估计口径 |
| `SpaceCollision` / `SpaceImpactEffects` / 护盾服务 | 真实占用、入射角、效果注册、贯穿／分层穿深、跳弹、护盾和原版后效 | 抽取可复用的纯查询／数值计算，提供有明确适用范围的只读期望估计 |
| `CombatManeuverIntent` / `CombatFlightPlanner` | 连续速度意图、指定敌舰局部方位及其角速度、完整状态参考 | 接收自动选出的有利方位和距离带，检验减速到位与动态跟随 |

现有 `ExpectedDamage` 默认按墙体效果估算名义伤害；真实伤害还受命中物、入射、弹种及后效影响。`TargetObstruction` 明确不预测穿透，也不消耗护盾。不能直接将这两个量重命名为“有效输出”。

## 计算契约

### 1. 事实与只读交战估计

- 结构事实复用真实建筑／基架占用、归属、武器炮口与射界、护盾几何、现有部件分类。静态几何按统一结构版本缓存；HP、冷却、弹药、能源、热状态、盾容量和设备工作状态按本次观察读取，不能等到建筑摧毁才更新。
- 所有坐标使用 `SpaceTransform` / `OrbitSphere`。同图多船按船体归属取样，不把容器内所有建筑算成一艘船；拆分、合图、归档／恢复、换档与删除必须正确失效和释放。
- 从真实命中链抽取共享纯计算：命中顺序、入射角、伤害参数、穿透停止条件、护盾作用。对 RimWorld／REF 后效先读对应版本源码，核对建筑伤害倍率、实际扣血和特殊 DamageWorker，不能凭装甲名或名义 AP 猜测效果。
- 估计不调用实舰 `TakeDamage`、爆炸、护盾消耗或武器发射，不推进全局随机流，不改装备／弹药／能量状态。随机遮挡、散布等用有界确定性采样或期望值；与真实结算对照只在隔离测试世界进行。
- 输出至少拆开命中概率、盾吸收、结构有效损伤、关键设备失能风险及不确定范围。关键价值从现有设备作用和能力贡献推导，避免既把扣血计分又完整重复奖励同一次失能；不预测任意连锁爆炸或完整未来毁舰过程。
- 支持范围逐项列明：直击／预算贯穿、分层穿深、爆炸、护盾和制导等按真实机制核验。尚不能精确预测的效果保留保守估计与诊断标记，不按零威胁处理，也不把缺少模型当作弱侧。若核心场景依赖的效果无法验证，阶段不算通过。

### 1.1 武器与防护的组合效果

2026-11-08 用户补充：**弱侧是相对于己方可用武器而言的，必须至少区分动能盾、电磁盾、实体装甲与守卫盾；不同武器组成应导出不同的选位收益。** 不能先把四者合成一个“防御强度”，再用全舰总 DPS 评分。

估计的基本粒度是“本次可用武器／弹种 × 候选射位和姿态 × 实际入射路径上的防护”。各武器先经过对应防护链计算有效结果，再按生效策略的权重／曲线汇总。武器家族可作编辑与诊断分组，物理估计仍读取具体弹种、质量、速度、功率、穿深、命中和资源状态，不能用固定的类别克制倍率代替真实机制。机制权威见[舰炮与护盾基线](舰炮与护盾基线.md)，本计划不重新定义平衡参数。

| 防护类别 | 估计必须保留的差异 |
| --- | --- |
| 动能盾 | 作用于实弹的真实法向／侧向冲量、改速、翻滚／撕裂、入射角与支付能力；激光不因动能盾存在而折损。多层强盾不是一条通用 HP 池，重弹与轻弹也不能用同一抵消率 |
| 电磁盾 | 激光按实际入射方向折射／反射后继续求交，可能击中其他位置或返回射手；不能把覆盖区一律算免伤。物理弹不套用激光损失，供电与强度按实际状态读取 |
| 实体装甲 | 真实材料／耐久、厚度、入射路径、跳弹与贯穿停止条件；激光首个结构停止与完整实弹逐层预算的差别必须保留，不将原版 AP 当作舰体穿深 |
| 守卫盾 | 真实盾面与弹种扣容、同船共享常规容量、本地应急容量、恢复与支付状态；先算护盾受损，再算可达的结构损伤，不能把扣盾量直接当成同量结构毁伤 |

混合防护按路径顺序处理。不同武器对同一结构的削弱、共享盾容消耗与后续可达性使用同一有限时间估计，不能给每门炮各算一遍完整破盾收益；不能把反射后可能伤及自己的输出记为纯收益。敌方对我方也使用相同粒度，包含我舰朝向带来的防护差异。

用户示例作为核心夹具：目标尾部动能防护强、实体装甲薄，侧面实体装甲厚但无盾。在供能、射程与射界允许时，增加可持续激光输出应提高尾部相对输出收益；增加具有相应穿深的可用实弹输出应提高侧面相对输出收益。这里的方向偏好由真实武器效果产生，不额外加入“激光绕后／动能绕侧”的硬编码权重。不能要求缺电激光、无法穿过侧甲的轻弹或无法瞄准的武器也产生同样变化。

### 2. 从即时火力改为有限时间收益

候选描述包括敌舰局部方位、距离带、我舰朝向和预期相对运动状态。对双方使用一致的观测和时间口径，估计整个评估窗口内的有效输出／承伤。

- 冷却中的武器在下一发可用时恢复贡献；能量／弹药不足不能假设持续满射速。只使用可验证的补能／循环事实，不假设未来有人补弹或修复。多个武器共用弹药、能量和同一护盾容量时不能重复花费资源。
- 目标转船、炮塔回转、弹丸飞行时间、距离与最小射程均影响实际交火窗口。我舰姿态变化也会改变自身防护与输出，不能只优化敌舰哪一面薄。
- 用“预计有效输出价值 − 预计承伤价值 − 机动及切换代价”形成共同效用，各项价值和取舍由生效规则的权重／曲线计算，默认预设只填入其中一组配置。距离／朝向等玩家策略约束继续保留；现有自定义曲线的单位与含义不得暗改。P0 明确旧曲线如何参与新效用，避免名义火力、覆盖率和有效毁伤重复加分。
- 以相同评估窗口比较候选，包含途中暴露、停止射击、制动／转船时间和到位后剩余交火时间。机动损失与制动成本只计一次，不能再给“移动了多少”额外奖励。
- 战术评估窗口与 MPC 控制窗分离。通过有界到达时间估计与到位收益评价看见远侧机会；不对到不了的位置立即记满分，也不只看三秒内能否变好。窗口、远期折扣、到达上限及敌方响应假设在 P0 固定并做敏感性检查。
- 对敌方保持当前运动和向我转向等少量可行响应取样，按其真实推力／转向能力限制。不能假定敌方永不转身，也不能预知敌方下次随机选择。不能保持的弱侧允许放弃，转而寻找次优位置或拉开。

### 2.1 可编辑的风险取舍

“打得进去”只增加输出收益，不保证该位置获选。对上述尾部薄甲场景，再加入尾向大量敌方火力：即使我方激光较强，默认预设也应能因预计承伤与短时间失能风险放弃绕后。不能先选定最大输出方向，再将规避伤害只作为路线微调。

- 共用编辑器须允许按武器类别／现有武器筛选范围配置有效输出价值，分别表达护盾消耗、结构损伤和设备失能的取舍，并提供总承伤、关键设备风险及短时间集中承伤的评分曲线。不同防护类型的估计分项可供策略条件／曲线选择；分类筛选仍扩展现有配置，不另建武器或策略身份。
- 区分长期平均承伤和当前耐久下的短时危险。平均 DPS 相同的连续小伤与同步重击可能导致不同失能风险；使用有明确定义的时间窗、当前结构耐久／能力余量和可验证的威胁场景。未经校验的估计不得伪装成精确“死亡概率”。
- 风险曲线允许非线性：小幅承伤扣分较缓，接近关键能力丧失或无法完成机动的危险区间时急剧增加惩罚。默认预设给出保全倾向的配置；玩家可提高进攻收益、降低风险惩罚，或通过高优先级风险条件选择拉开／其他允许动作。规则和曲线变化必须真正影响决策，不能被隐藏的“绝不冒险”策略覆盖；真实物理不可行性与既有安全约束仍有效。
- 每项指标标明统计对象、时间窗、单位／归一化基准，以及先分武器计分还是汇总后过曲线。类目曲线与总量曲线不得默认重复奖励／惩罚同一效果；能力失能额外价值与直接扣血价值分清。预设系数是玩家偏好，武器对防护的物理响应是公共事实，两者不得混用。
- 诊断须能解释“尾侧激光有效输出较高，但尾向预计承伤与失能惩罚更大，因此选择侧面／其他位置”，列出真实分项、应用曲线及加权贡献。只打印一个总威胁值或“弱侧”标签不足以验收。

### 3. 搜索与连续执行

先按敌舰局部方向和双方有效射程做粗评，再对少量优选位置联合优化我舰朝向、转移方向和到位速度。候选必须包括当前位置附近保持、沿当前运动继续、向两个方向转移及适用的拉开动作。远侧候选直接参与目标搜索，不再限于本周期可完成的小段弧长。

只对有限优选候选调用现有完整飞行规划／路线检查；以真实质量、惯量、推进器和角速度估计到达及保持能力。候选数量、采样次数、精评数量和查询预算有明确上限，在 P0 测量后冻结，禁止无界“方向 × 距离 × 朝向 × 武器 × 建筑”穷举。

每轮重新计分；上一轮目标只用于估计当前切换代价及连续性，不作为必须完成的任务锁。反向需有足够净收益，随机只用于近似等价的可行候选。结构／目标／能力变化标记相关观察过期，由对应反应时钟安排重评，不再要求事件当 tick 抢占决策；即时物理有效性检查与 AI 反应分离，详见下方优化方案。缓存刷新不重置随机种子。

到位前生成平滑减速参考，到位后跟随敌舰局部方位／距离带。距离带内不为微小误差来回换目标；超出可跟随能力时重新规划。意图切换不清空执行器状态，不直接写速度或角速度，不把制动推进器点火次数当成战术反向次数。

## 分阶段实施与退出条件

各阶段先完成本阶段门槛再继续。失败记录实际证据和原因，不通过改夹具布局、放宽容差或换一组随机种子消除失败。

### P0：复现、基线和指标冻结

1. 以 `c81b2eb` 为连续机动基线，保存可复跑 DLL／源码摘要、命令与环境；区分共享工作树中的其他改动。
2. 在现有 `NpcRetreatRegression` 建立真实结构和真实武器的场景：舰首重武装／重防护、尾部薄弱；先独立证明该夹具在当前弹种、射程和双方能力下确有可利用弱侧，再闭环复现“绕过弱侧而不占位”。不把口头布局描述或人工收益回调当成毁伤证据。
3. 先完成“预设行为 → 共用规则／指标／参数 → 编辑器控件 → 序列化字段”的映射表，明确规则优先级和规则内加权语义；没有编辑路径的预设偏好不得进入实现。冻结观察窗口、效用分量／曲线语义、候选预算及验收容差。记录基线的目标局部方位、射程、相对角速度、有效输出／承伤、关键设备状态、换向、参考连续性和分阶段 CPU 成本。
4. 将历史运动回归拆清：显式持续环绕仍须满足原连续性门槛；对称无威胁的 Automatic 可保持位置，不再把“必须转够圈数”当正确目标。无收益换向、周期性无端刹车、物理一致性和日志开关行为一致仍保留。
5. 加入尾部动能盾／薄甲与侧面厚甲／无盾的混合防护夹具，独立标定激光和可穿甲实弹的收益排序；再加入尾向集中火力，冻结默认风险曲线应否决该方向的条件。记录每种武器与防护的有效结果，不以总 DPS 或统一盾强度代替。

退出：核心闭环失败可稳定复现，失败归因到战术收益而非无法命中／无供能／不可达；公共配置与编辑映射完整，基线、测量方法和后续门槛落到结果文件。

### P1：共享只读毁伤与持续火力估计

完成事实分层、共享纯计算和有限时间资源约束。针对已知简单结构，对比只读估计与隔离世界真实生产结算：正／斜入射、厚薄结构、不同 HP、预算贯穿、分层穿深、多格建筑、盾覆盖／容量及核心场景弹种。至少交叉验证激光／普通实弹／轨道弹与动能盾／电磁盾／实体装甲／守卫盾，追加混合防护、多层次序、供能失效及反射危险；沿用现有导弹特殊机制检查，不能误套实弹响应。确定性分支逐项一致，随机分支用固定种子批次验证期望误差。

退出：方向差异来自真实结构／火力，估计不修改世界或全局随机流；资源共享与缓存失效回归通过；不支持或近似的效果有明确边界。公共计算抽取前后真实伤害行为一致。

### P2：有利方位／距离的收益搜索

接入双方有效输出、承伤、自身姿态防护与目标响应；对应的共用配置、编辑控件、复制／校验／持久化同阶段实现。先做不驱动飞船的候选排序回归，再引入真实到达成本；把粗评与精评的分项结果输出到同一诊断记录。默认预设完全由这些公开配置组成。

退出：弱侧／强侧及距离的排序符合实际结算证据；旋转／镜像布局后选择随事实变化；全向对称布局没有舰尾固定偏好；远侧能被发现，但不可达目标不能靠虚构到位收益获胜。混合防护下改变可用武器组成能改变方向收益，危险射界可由风险曲线压过输出优势，修改曲线能形成不同风险偏好。内置预设与从空白规则重建的等价配置候选分项及排序相同；修改权重、关闭软评分项和调整规则顺序能产生预期变化。

### P3：自动转移、占位与动态重评

Automatic 按生效规则使用新收益选择动作，移除内置换位进度奖励，保留真实速度／反向制动代价及其可配置取舍。预设和自定义策略经同一调用链复用现有意图与飞行参考，完成减速到位、敌舰平移／转向跟随、收益变化后的转移或退出。

退出：静态弱侧场景实际到位并长期停留输出；移动／转向目标下使用正确的非零目标速度；每轮独立重评、无无收益反复换向、无任务窗口末端隐含停车。显式玩家约束、强轴炮塔舰、固定炮／混装及弱转向舰回归通过。

### P4：完整交战和扰动回归

用生产火控、碰撞及后效验证选位收益；禁止仅用人工打分器证明成功。覆盖多敌威胁、友舰占位、路线受阻、途中能力损失、目标结构破损、盾耗尽／恢复、弹药／供能变化及目标失效。对不可达弱侧、对方转向更快和无法形成有效火力优势的情况，允许保持次优射位／拉开；不得强制追尾。

退出：下方回归矩阵通过；至少多个固定种子与镜像布局重跑，报告分布及失败个例。输出／承伤同时记录有效交战时长与损毁过程，不因某一方早早死亡而制造“低承伤”结论。

### P5：性能、诊断、文档与交付

## 重复预测、局部失效与反应节奏优化方案（2026-11-08）

状态：2026-11-08 用户授权开工，O0 参照留存与 O1 的 Map 级迁移已接入，全部优化阶段尚未完成。用户要求针对同步预测、多舰重复工作和全局结构失效造成的长尾制定方案；保持决策质量与原性能门槛，允许舰船对战损有正常反应延迟。本节修订此前“结构变化即刻重评”的要求，不改变真实物理和伤害规则。

### A. 不变项与验收口径

- 保持既定交战窗口、候选覆盖、精评数量、采样精度、曲线和风险项；不通过少看敌人、少算武器、降低射线精度、拉长正常决策周期或缩短窗口过关。结构事件引发的额外抢占重算可以合并取消，但正常到期决策不能因此缺失。只删除已证明等价的重复工作，或用已证明不影响结果的界限排除无效工作。
- 同一观察快照、策略、决策时钟和随机状态下，优化开／关须得到相同原始分项、候选排序、最终选择和随机流；浮点比较沿用既有容差，不为本轮另放宽。不同推进批次大小、日志状态、机器快慢不得改变结果。
- “允许反应延迟”是新的明确行为契约，不伪装成计算误差。将按此时钟运行的完整预测作为质量参照；旧即时反应实现仍保留交战结果对照，不要求新延迟行为逐 tick 复制旧行为。原弱侧占位、混装防护、风险取舍、无收益反向、有效交战收益等门槛不变。
- 原 1／4／12／24 舰、1800 tick、300 tick 预热、1500 tick 结构变化和三轮串行中位数保持；平均和 P99 均不得超过冻结 P0 的 1.25 倍。另分别记录正常到期决策完成数、事件额外重算数、每次完整决策 CPU、队列等待和清空积压所需时间，防止把计算推到测量窗口之外“变快”。固定输入任务集还须全部求值完成后比较总 CPU；P99 改善不能掩盖总 CPU 增长或决策长期拖欠。

### B. 先分离即时事实与有延迟的反应

| 层次 | 战损发生时 | 反应到期时 |
| --- | --- | --- |
| 真实世界、物理及资源支付 | 真实拓扑、归属、质量／惯量、碰撞、供能和损毁即时生效；已消失设备不能继续出力、开火或供能 | 无需等待 AI 才成为真实事实 |
| 自动驾驶的战损适应 | 保留仍属于原驾驶主体且仍有效的推进器旧油门；失效／脱离／断供的通道立即失去作用，不把其推力即时补到其他推进器 | 读取当前能力，重建自动驾驶模型并重新求分配；实际完整状态作为新参考起点 |
| 自动火控 | 保持有效的当前目标／部件意图；无效句柄停止发射或只保留最后合法预瞄，不自动寻找替代部件、改追碎片或转火 | 重新观察、选择敌舰和部件，按共用策略更新火控意图 |
| 战术选位 | 相关数据标记过期，继续当前有效机动意图，不因一次掉甲立即重新搜索全部方位 | 按既有机动决策周期读取最新观察，完整重评；不等上一段机动完成 |

推进器反应延迟不能通过“旧目标力输入新分配器”实现，那仍会在战损当 tick 自动补偿。需要在现有驾驶链中保存按设备稳定身份对应的已执行油门，由共同 `ShipPhysics` 根据幸存设备的当前能力、当前力臂和当前质量积分。缓存数组下标不能作为跨重建身份。拆出的新主体不继承对原主体的控制权限；没有合法驾驶主体的碎片按现有无控制规则处理。不开第二套积分器，也不冻结质量／碰撞来制造迟钝。

正常无战损时保留现有连续 MPC／控制节奏，短时保持只针对能力突变后的自动适应。显式手动输入、取消、停火立即生效；失效句柄的即时禁用只是有效性门禁，不借此执行新的最优站位／转火。对接、停放与侵入制导先保持既有契约；战斗反应设置不得隐式改变这些调用方。

反应参数进入共用策略配置和编辑器，玩家自动战斗与 NPC 同样读取，默认预设没有隐藏快速通道。初始建议：战损后动力适应 15–30 tick，目标／部件重新选择 30–60 tick，战术沿用现有约 5–10 秒独立周期。前两者的最小／最大时段在行为回归建立时冻结，之后不因性能不够而加长；各舰用稳定身份确定范围内错峰，不消费战术平局随机流。这里列的是待实现参数，不是现有行为。

第一次相关事件建立待处理标记和截止时间，后续事件只合并最新版本，不反复重置截止时间；持续交火不能让 AI 永远反应不过来。主体、目标仍有效时，到期用当时最新状态开始一轮观察；“独立重评”保留，事件抢占取消。

### C. 缩小失效范围：同一事件源，按真实依赖更新

1. 扩展已有 `ShipStructureChanges`／`SubstructureOwnership` 事件入口，携带 Map、变化格／设备及变化前后的归属。移除、拆分、合并、转图均捕获旧归属后再写事实；跨边界变化覆盖两侧。不另建一套 AI 专用结构事实或依靠定时全图扫描。
2. 由 `UniverseManager` 实例服务维护局部版本及事件合并。先落地 Map／表示代次，再落地可明确归属的船体版本；统一事件同时推进必要版本。原全局版本只保留确实依赖全局枚举的读者和显式全局恢复路径，不再作为每舰战术、部件表和质量报告的普遍失效条件。元数据全是可重建运行态，不序列化。
3. 物理报告与整图碰撞面依赖对应 Map，船体部件／驱动／武器布局依赖对应身份与归属版本；战术任务记录自身、目标和本轮相关威胁／路线几何的实际依赖。A 舰掉甲不能使另一张无关 Map 上 B 舰的布局或质量重建。共享 Map 的碰撞面可先保守按 Map 重建，不能把尚未分块的整图数组伪称为船级缓存。
4. 位姿、速度、HP、能源、热量、冷却和盾容不是结构缓存。到规定观察点重新采样；不通过结构版本未变来复用旧的动态收益。新威胁进入、旧威胁离开和移动障碍，在观察时查询现有空间／身份服务，不能只订阅上一轮看到的敌人而漏掉新对象。
5. 缺少细节的事件先局部退化为“该 Map 过期”，并补齐调用者；不静默恢复为全世界失效。仅有无参数的全局测试失效另作为全局恢复压力项保留。冻结的全局失效负载不因新增局部场景而取消；同时新增真实单船毁伤／拆分场景，验证通常路径不扩散。
6. 归档／恢复、拆分合图、删除 Map／Object、换档和配置变更都释放或重绑依赖；身份相同但表示代次不同也不能复用旧句柄。先列全调用点，再逐个迁移与对拍，不能仅改战术入口而留下底层质量／碰撞仍全局重建。

### D. 减少重复预测：共享事实与纯计算，隔离因果状态

| 内容 | 复用方式 | 禁止复用的边界 |
| --- | --- | --- |
| 船体几何、归属、炮口安装关系、护盾几何、部件候选 | 按局部结构／配置版本持有不可变查询数据；同一观察批次的多舰引用一次捕获结果 | 不持有会被重建原地改写的碰撞数组，不把 Map 内其他船变化视为本船事实不变的充分证明 |
| 弹种参数、伤害系数、完整状态下的能力预览 | 复用公共纯函数的相同输入结果；缓存键含实际弹种、材料／Def、配置与必要状态 | 动态供能、改变弹药、转台角度、推进器可用性不藏在“静态参数”中 |
| 相同源／目标几何下的射线、部件遮挡、到达解 | 一轮内按完整输入复用，精确键匹配；优先消除重算点速度、相同部件与同一射线的重复查询 | 不将相近角度／距离量化成相同输入；虚拟毁伤、盾状态、目标姿态不同则不能套旧结果 |
| 发射与资源演化 | 共享确实不受候选影响的初始数据和演化前缀，候选差异出现时才分出私有状态 | 不能把“满额资源下的发射清单”用于途中武器被毁或枪盾抢电的精评；同一电网、盾池与弹仓仍联合结算 |
| 重复子过程 | 按实际依赖判等后复用：例如完全相同的射击几何、资源与毁伤历史前缀 | 不因舰型相同或武器相同就合并不同来袭方向；不把多舰威胁简化成总 DPS |

原 `Observation`、护盾副本和武器预测仍含真实 Thing／Comp 引用及实时 getter，不能直接跨 tick 保存后声称是冻结快照。跨 tick 之前须把求值所需几何、HP／系数、资源网络、武器和护盾动态量冻结为数值／稳定身份数据；查询继续从共同碰撞与伤害规则生成。真实对象句柄只用于捕获和最终有效性检查，求值过程中不重新偷读变化后的世界。外部未知行为继续带不确定性，不静默视为零。

调度从逐 tick 反复询问就绪，改成推进到下一次有意义的事件：冷却结束、既定瞄准刷新／重试、弹体到达、资源阈值或盾恢复边界。同 tick 顺序、共同能源支付顺序、发射后同 tick 命中顺序保持不变。能证明等价的静态区间批量推进；热量、电池分配或恢复含阈值／舍入而尚不能证明等价时，仍调用原逐 tick 数值推进，只跳过无必要的昂贵几何查询。先用快慢两种执行方式对同一快照逐事件对拍，不靠减少事件采样率加速。

共享前缀和跨候选 memo 采用有界、按需建立的缓存，不预先生成“所有舰对 × 所有方位 × 所有武器”的大表。缓存命中必须验证完整键；可淘汰的是重复计算结果，不是候选或未算完的必要工作。记录命中率与每次决策节省的真实查询次数，低命中缓存不为形式保留。

### E. 将完整决策拆成可续算工作，避免单 tick 独占

- 在现有每舰控制服务上组织 `等待反应点 → 捕获快照 → 粗评 → 精评 → 完整结果待发布` 的临时工作状态，由 `UniverseManager` 所属调度服务分配工作；不通过 `QueueFrameAction` 或后台线程读取活地图计算，不依赖墙钟或渲染帧推进。
- 全部候选仍要按同一算法完成。每个工作单元细到有限事件／接触批次；不能把整个候选的 30 秒模拟算作一个“可中断单元”。用现有 128 接触／递归上限及实测单元耗时校验最坏一步是否可控，必要时细化暂停点，不降低上限和精度。
- 每 tick 使用确定性的总工作额度与公平轮转顺序。CPU 毫秒只用于测量，不用于决定某台机器少算哪些候选。额度在固定负载下按原性能门槛和允许延迟确定；如果全量工作无法按时完成，视为性能失败，继续优化，不缩减搜索、延长反应期或发布粗评赢家。
- 一艘船同一时刻至多一个任务及一个合并的待更新标记。任务中的结构更新不会令整项预测从头重启；快照代表这次观察，后续变化进入下一轮。身份消失／表示替换可终止无效任务并释放资源；仅延续稳定有效的旧意图，不将无效引用硬保留。
- 记录观察年龄、开始／完成／发布 tick、等待原因和截止时间。调度需满足固定最大任务年龄和完成期限；持续过载或错过下一决策点必须被回归捕获，不能无声跳过正常决策，也不能积压多个过期意图待依次执行。
- 发布时校验主体、目标、配置与表示代次；新意图从发布时的真实完整运动状态交给共同飞行规划器，不能把快照的旧起始位姿写回。检查当前几何是否仍允许执行；不允许则停止无效动作并保留待重评状态，不临时跑另一套轻量决策替代完整结果。持续几何变化下，过期／废弃次数及恢复时限也须过关。
- 平局随机仅在完整决策选择时消耗一次；排队、分片、缓存失效和任务取消不重置／推进该随机流。反应错峰使用独立的确定性身份映射。任务、快照和缓存不存档，读档后按现有生命周期重新建立；不得引入可变静态游戏状态。

### F. 实施顺序与退出检查

1. **O0 固定参照与计数。** 保存当前完整求值器及典型输入快照，增加决策 ID、完成工作量、依赖重建次数、事件数、队列年龄、分配量与 GC 暂停的独立测量。时序改变前冻结反应参数和快慢执行对拍口径；不把 GC 次数当作暂停耗时。
2. **O1 局部版本与事件合并。** 迁移共同结构入口及依赖缓存，先覆盖跨 Map 隔离、同图多船、移除前归属、拆分合并和删除释放。做到事件只置脏，不强迫全舰战术与火控立即重算；此阶段不伪造旧物理状态。记录全局测试失效和实际单船事件两种路径。
3. **O2 快照与等价计算复用。** 消除对活世界 getter 的中途读取，建立有界共享几何／纯查询与私有因果账本；逐项加入事件推进和可证明的公共前缀。每项先过同输入分项／事件／选择对拍，再测查询数和每次完整决策成本。
4. **O3 有界续算与反应执行。** 接入公平调度、既定反应时钟、幸存推进器油门保持和延迟转火。完成共用编辑器、复制、Scribe、日志及关闭日志的确定性对拍。测试连续战损不延后截止时间、不反复取消重启、不饿死后排舰船。
