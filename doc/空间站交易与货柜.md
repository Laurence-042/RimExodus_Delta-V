# 空间站交易、货柜与结构牵引实施计划

状态：2026-11-02 用户确认现有功能无明显问题并授权提交；随后调整自建货柜解锁、骇入出货与插件安装面；2026-11-03 补齐终端配置、独立仓库绑定和周期补货，修复货柜覆盖替换；新改动待游戏内复测。

## 玩法契约

- 单一货柜 Def 使用 Adaptive Storage Framework 的 `ThingClass` 与原版储物格，持有可交易、可劫掠的同一份真实货物。六个地图格中的物品由 ASF 遮蔽绘制，交易、骇入、毁伤、搬图和存读档都消费同一实例。装备保留品质、材质、耐久和组件状态。
- `CompHackable.IsHacked` 是唯一解锁状态：玩家新建货柜首次出现即解锁；NPC 新建货柜保持锁定，prefab、读档和搬图保留实际锁定状态。玩家只能通过 God Mode 的“锁定货柜”命令重新锁定并清零骇入进度。锁定时黄灯，不能存取货物或切换仓储模式；骇入后蓝灯，解锁内容页、开箱与仓储模式，并立即通过 ASF 原出货入口弹出全部库存、允许搬运。主动开箱仍可完整吐出后续库存；被摧毁时损失大半并吐出剩余货物。剩余物品必须交给现有落物、承载丧失和散落对象流程，不能因源图回收消失。
- 一个交易终端显式绑定多个锁定供货仓和唯一的解锁取货仓。货柜必须位于同一连通基架；不能同时属于两个终端。更换取货仓只替换引用，不移动原有货物；绑定不会自动锁定或解锁货柜。断连、毁坏、换图或被骇入的供货仓立即停止提供库存。取货仓可主动开箱吐出货物供气闸搬运。
- 玩家自建终端始终提供配置按钮，也可由殖民者右键打开配置；NPC 终端只在 God Mode 允许配置。可选择原版商人类型及 1／3／7／15／30／60 天的补货周期，默认 15 天。非玩家终端在配置有效时按游戏 tick 定期调用原版 `TraderStock` 重新生成实体库存，清除仍有效供货仓中的旧货；取货仓与未绑定货柜完全不参与刷新。首次启用时若供货仓已有预制库存则保留，到期才刷新。玩家搭建阶段只由 God Mode 手动补货，不自动生成免费货物。交易窗口打开期间不刷新。商人类型、周期、货柜引用、补货时间与价格种子随原版 Scribe 存取。
- 配置和手动补货不要求软对接；实际交易仍要求有效软对接、供货与取货仓、谈判者可达和原版交易资格。条件不满足时保留禁用交易选项并显示原因。
- 玩家软对接后，出售范围是对接玩家侧**整张地图**上的地面物品及货柜内容；不按结构归属或船只派系筛选，同图其他船的物品也能被出售。交易由站内交易员／终端发起，使用原版 `Dialog_Trade`、`TradeDeal`、`TraderKindDef` 和价格、白银规则；不使用影子或真实远行队。
- 货柜内容的质量位于货柜所在格，进入现有 `ShipPhysics` 的质量、质心及惯量；库存增减即时失效。搬走满载货仓应比空仓困难。
- 每个货柜占地 2×3，最多每格 8 堆，共 48 堆；每堆遵循原版物品堆叠上限。解锁后 ASF 的“内容”页可用，检查面板始终显示当前占用。玩家可用 Gizmo 切换仓储模式，默认关闭；启用后原版搬运按筛选和优先级自动存入，工作台可从格内取材。锁定或关闭模式时储物优先级为“未储存”，货物被禁止拿取。关闭模式仍由 ASF 和原版维护地格物品，不再使用隐藏 `IHaulSource`。
- 货柜外挂船壳，本体不耗电，货物始终使用室外气温。单个覆盖槽可安装温控插件，复用现有插件的建造、开关、绘制与宿主销毁链。插件使用原版目标温度控件（默认 -10°C），按 ASF 原函数相对室外最多调节 100°C；低于目标时制热 175 W，高于目标时制冷 200 W，到达目标或停用为 0 W。停用、断电、拆除后回到室外气温。控件目标和插件开关由各自组件存档，不修改共享 Def 的温度参数。
- 牵引的自动独占／物品与活体筛选、手动多束叠力及断片提取统一以[对接设计 §9.3](对接与舱外作业重构设计.md#93-牵引光束与月池回收)为准。结构不自动收进月池。

## 已核对的原版与现有入口

- RimWorld 1.7 `ITrader.Goods` 与 `ColonyThingsWillingToBuy` 要求 `Thing`，`Tradeable.ResolveTrade` 逐项调用 `GiveSoldThingToTrader/Player`；`Dialog_Trade` 接受地图上的谈判者。ASF 仅提供储物/UI/温度基础设施，不改原版搬运 AI；实际货物在地图上，内容页有容量滑杆，大量货物的 tick 和存档成本仍须实测。
- `SoftDockPortal` 已提供原版 `MapPortal` 的人员／货物入口；交易取玩家侧真实 Map，不新建跨图寻路或影子商队。
- 结构分离使用现有 `CaptureDomain → StripDomain → PlaceIntoMap`；货柜作为建筑随所处结构搬运。散落物进入 `SpaceScatterService`，建筑残片保持结构对象。
- `ShipPhysics.GetReport` 用结构版本和运输舱载重失效；新货柜内容变化须接入该入口。`SpaceScatterService` 目前只允许散落对象被牵引，手动结构牵引需要扩展目标与力分配，不可复用坐标插值。

## 施工顺序

1. 新增单一货柜与终端 Def、组件、Keyed 文本和黄／蓝状态贴图。货柜继承 ASF `ThingClass`；骇入解锁并自动出货，主动打开也将格内货物移到柜外，毁坏时保留约四分之一并落地。
2. 终端配置与绑定由 `Building_SpaceTradeTerminal.Configuration` 和 `Dialog_SpaceTradeTerminal` 提供；出现后的帧边界及 Rare tick 检查补货期限。关联保存真实建筑引用并在补货／交易边界复核，断开的货柜仍保留内容。
3. 终端实现 `ITrader` 适配，玩家侧地图枚举可出售物品；原版 `TradeDeal` 逐项移入锁定库存柜或已解锁交货柜。白银与商品共用库存，不做第二份账本。成交前按所需堆数检查两类状态货柜的容量；随机库存为每个锁定柜预留 16 个出售位，生成溢出不入柜。
4. 把货柜质量接入 `ShipPhysics`，内容变化触发既有报告失效；归档、恢复、prefab 与 Gravship 搬图均验证库存和引用。
5. 扩展牵引光束手动模式的结构选取和双端受力，自动模式继续现有散落回收；为锁定、供电、射程、结构断裂、地图替换建立清理与重选入口。
6. 编译 1.7 和 1.6；做必要离线回归与静态核对。新档游戏内验收由用户完成，不自动启动游戏。

## 调试入口

- God Mode 选中货柜：加入钢铁、白银及有品质／受损的装备样本；查看库存、质量和骇入状态；锁定并重置骇入进度；立即骇入／打开；清空；按正常毁伤路径炸毁并检查战利品损失。
- 选中自建终端 →“配置交易终端”：选择商人类型、补货周期，在货柜列表中分别绑定多个供货仓和一个取货仓。供货仓先通过货柜自身 God Mode 命令锁定；取货仓保持解锁。God Mode 配置窗口另提供“重新生成供货库存（替换旧货）”，可在无软对接时验货；也允许配置 NPC 终端。

## 当前接入边界

- 2026-11-03 修复终端检查文本：仅在原版基础检查文本非空时加分隔换行，并去掉其末尾换行；基础文本为空时直接以商人类型开头。未修改原版检查面板或屏蔽错误日志。

- 货柜本体是普通 `isEdifice=true` 建筑；覆盖建造由原版 `GenSpawn.SpawningWipes → WipeExistingThings` 先销毁旧建筑，再注册新储物格。只有覆盖安装的温控插件保留 `isEdifice=false`；不为货柜添加 Spawn 或 HaulDestinationManager 特判。
- 离线专项共 95 项通过，含 4 项原版覆盖判定及 17 项终端绑定／补货检查。终端测试执行真实绑定、库存筛选和到期替换逻辑，只替代基架几何、商人随机生成与 ASF 实际落物；完整地图、UI、跨图贸易和存档／prefab 引用重建仍待游戏内验证。

- 自建初始化只由 `PostMake` 设置的一次性运行时标志触发，ASF `OnSpawn` 完成后按派系调用原版 `HackNow`；该标志不存档，读档／prefab 不重新推导锁定状态。原版 1.6／1.7 没有重新锁定 API，God Mode 命令直接重置原 Comp 的骇入和锁出字段，不新增状态副本。`OnHacked` 共用已有 `OpenContents → ASF.Eject`；其原物品实例与允许搬运参数由离线夹具核对，实际地图落点仍待游戏实测。回归替代 ASF 初始化、地图储物刷新和原版骇入通知，保留真实首次生成判断、原版骇入状态转换、解锁回调和逐堆出货循环。
- 2026-11-02 修复货柜配置错误及循环打印异常：货柜必须注册 `AdaptiveStorage.GraphicsDef`，包含有真实 `graphicData` 的 `StorageGraphic`。先前空 `<li />` 虽能建立 Worker，却会被安装版 ASF 的 `ConfigErrors()` 报错并移除，之后仍可能解引用空的 `CurrentGraphic`。现由 `StorageGraphicData_CargoState` 直接读取原版 `CompHackable.IsHacked`，在同一 ASF 图层选择黄／蓝贴图；不新增锁定状态。原版骇入组件不再配置贴图，ASF 基础图与内容绘制关闭，避免重复绘制；`OnHacked` 标记图层和地图网格失效，存档恢复由 ASF 正常重建图层。
- 对应离线回归先用原版 XML 加载器读取真实图层定义，完整枚举安装版 ASF 的 `ConfigErrors()`，再调用真实 `UpdateBuildingGraphics` 和 Worker 绘制入口，覆盖锁定、解锁和重复重建；同时复现旧空图层被报错并删除。夹具替换 Unity PrintData 创建与最终绘图为计数器，未覆盖完整 Mod 初始化、地图网格与游戏内显示，仍须用户实测。

- 本项目的星区内容是 prefab 池驱动；仓库当前没有贸易空间站成品 prefab。贸易站 prefab 作者需要在同一连通基架上放入至少两个货柜、交易终端与对接口，然后加入 `TradeStation` 物化池。导出前应在终端配置好商人类型、多个锁定供货仓和一个解锁取货仓；可以手动补货验货。玩家建造的终端不会自动生成库存。
- 手动牵引仅对有实体地图的独立零重力结构对象生效。仍需游戏内确认射线命中点、反作用分离提示、结构断裂后的重选、炮台火控与轨道球面切线运输。
- ASF 安装版目前仅声明支持 RimWorld 1.4–1.6。1.7 会回退加载其 1.6 文件夹并标记版本不兼容；两个 Delta-V 目标均可编译，但 1.7 ASF 运行时须实测。此货柜未使用 ASF 的配方取色 GraphicsDef，可避开已知的 `StorageRenderer.GetColorFromRecipe()` 路径。
- ASF 使用真实地图物品；大量不同装备的 tick、存档、生成与开箱成本仍需实机测量。封存状态禁止自动存取，但地图物品仍存在。

## 多船软对接的当前边界

- `TradingMap()` 按站内 `Map.listerThings.AllThings` 中对接口的枚举顺序，返回与终端同一连通结构上首个有效软对接的玩家地图；顺序不是按距离、谈判者来源或先到先服务。多艘玩家船分属不同地图时，只读取其中一张地图的物品／白银，其他地图不合并；若多船同在选中的地图，则仍按整图出售。
- 供货仍取当前终端绑定的货仓，所有购入物统一放入该终端的唯一取货仓，不按来船分箱。即使同站安装多个终端，各自仓库独立，同一连通结构上的终端仍使用同一套首个对接口规则，不会自动各分配一艘船。
- 原版交易窗口暂停游戏，交易逐笔执行；当前实现没有多船选择器或固定本次会话来源地图。重新查询时若原对接断开，可以改取另一有效地图；成交前检查原物品是否仍在当前选中的地图，不符合则拒绝。多船选择或合并是待确定的玩法，不在本轮显示修复中改变。

## 游戏内验收重点

- God Mode 原位覆盖货柜时旧柜被销毁，无储物格重叠红字；温控插件可正常覆盖安装。终端无软对接也可配置，多供货／单取货绑定和商人类型随存档、prefab 导出导入保留。NPC 到期重新生成供货库存，取货仓已购货物保留；供货仓遭骇入后不被自动重新填货。

- 软对接后同图多船的所有可出售物品都进入交易窗口；买入、卖出、白银结算后货柜库存只变化一次，蓝灯接收柜打开后实体可搬运。
- 玩家正常及 God Mode 建造均默认解锁；只有 God Mode 能重新锁定，存读档和搬图保留锁定。骇入货柜时灯光由黄变蓝并自动弹出全部库存；此前无法开箱、改仓储模式或从内容页取货。货柜装备在交易、骇入、毁伤、拖走、归档恢复后保持品质、材质、耐久与组件状态；满仓／空仓质量和牵引加速度不同。
- 终端关联仓库模块被炸断后立即失去该库存；模块独立漂移、被拖走后仍可骇入。任意状态的货柜毁坏只损失既定部分，幸存物品被现有散落流程接管。
- 自动牵引仍回收散落物；手动牵引结构时目标和发射船的速度／角速度符合受力点、质量和反作用力，停火后按各自惯性漂移；暂停、切图、存读档不继续施力。
- 玩家货柜启用仓储模式后，物品按筛选与优先级自动入柜；工作台直接从柜内取所需材料，向更高优先级储物设施搬运时只取目标堆；关闭后封存并禁止拿取。检查“内容”页、48 堆容量、满仓交易拒绝、温控插件的安装／拆除、制热／制冷、停用／断电恢复室外温度、存读档和满载质量。
