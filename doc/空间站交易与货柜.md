# 空间站交易、货柜与结构牵引实施计划

状态：2026-11-02 用户确认现有功能无明显问题并授权提交；随后调整自建货柜解锁、骇入出货与插件安装面；2026-11-03 补齐终端配置、独立仓库绑定和周期补货，修复货柜覆盖替换；新改动待游戏内复测。

## 玩法契约

- 同一货柜有两种实际建筑形态：仓储态 `DeltaV_CargoStorage`／`Building_SpaceCargoContainer` 继承 ASF `ThingClass`，货物在真实储物格内；封存态 `DeltaV_CargoContainer`／`Building_SealedSpaceCargoContainer` 继承原版 `Building_Crate`，货物由原版 `ThingOwner` 持有、不在地图物品格上。建造栏只提供默认封存形态。模式切换移动同一批物品，不复制、不重新生成、不合并堆；品质、材质、耐久、数量和组件状态保持原样。
- 封存态以 `CompHackable.IsHacked` 为唯一锁定状态。玩家新建默认解锁，NPC 新建保持锁定；读档、prefab 和搬图保留状态。God Mode 可以重置原版骇入进度。骇入成功后变更归属并保留库存。锁定货柜须先解锁才能出货或切换模式。
- 一个交易终端显式绑定多个锁定供货仓和唯一的解锁取货仓。货柜必须位于同一连通基架；不能同时属于两个终端。更换取货仓只替换引用，不移动原有货物；绑定不会自动锁定或解锁货柜。断连、毁坏、换图或被骇入的供货仓立即停止提供库存。取货仓可主动开箱吐出货物供气闸搬运。
- 交易终端占地 2×2，交易任务通过原版 Touch 寻路接近建筑。终端不开放普通建造；God Mode 可通过原版建造栏放置。所有派系的终端仅在 God Mode 提供 DEV 配置 Gizmo，殖民者右键只提供交易。可选择原版商人类型及 1／3／7／15／30／60 天的补货周期，默认 15 天，所有配置回调再次检查 God Mode。
- 有效终端按游戏 tick 调用原版 `TraderStock` 重新生成实体库存。默认禁止向玩家设施补货：终端或任一有效供货仓自身属于玩家，或处于玩家主台的当前控制域内，均暂停整次刷新；不以混合地图的总派系判断。因此 NPC 站与玩家船同图仍可补货，切到玩家船上的 NPC 终端／供货仓则停止刷货。仅在配置交易终端对话框内显式勾选“DEV：无差别供货”可解除此限制，God Mode 本身不会绕过；自动和手动生成共用检查。开关默认关闭，随 Scribe 保存，退出 God Mode 后保留所选设置。
- 刷新只清除仍有效供货仓的旧货；取货仓与未绑定货柜完全不参与。首次启用时若供货仓已有预制库存则保留，到期才刷新；交易窗口打开期间不刷新。商人类型、周期、货柜引用、补货时间与价格种子随原版 Scribe 存取。
- 配置和手动补货不要求软对接；实际交易要求存在符合玩家驾驶台归属和软／硬对接条件的船、有效供货与取货仓、谈判者可达和原版交易资格。条件不满足时保留禁用交易选项并显示原因。
- 玩家软／硬对接后，到达终端打开“选择货物来源”对话框。选项显示玩家主台飞船名称，实际选择该船所在 Map，同图飞船合并显示。商品与白银直接读取该图 `TradeUtility.AllLaunchableThingsForTrade`，由已通电玩家交易信标决定范围，不再按单船控制域过滤；排除终端自身商人库存，防止双侧重复。使用原版 `Dialog_Trade`、`TradeDeal`、`TraderKindDef`、可售位置、价格和白银规则；只将收发货改为真实供货／取货柜，不使用远行队或空投。货柜仍只容纳物品，不增加活体仓储。
- 货柜内容的质量位于货柜所在格，进入现有 `ShipPhysics` 的质量、质心及惯量；库存增减将货柜标记为待更新，按[基础驾驶](阶段2-基础驾驶.md)的 600 tick 窗口合并发布。搬走满载货仓应比空仓困难。
- 每个货柜占地 2×3，ASF 每格 8 堆、共 48 堆，每堆遵循原版堆叠上限。默认封存，解锁后点击“当前模式：仓储／封存”切换，灰色闭合箱图标表示当前封存、青灰色开放箱表示当前仓储，不绘制勾叉。仓储模式继续使用 ASF 的筛选、优先级、内容页、容量滑杆，以及原版搬运、取材和信标交易。封存柜没有储物格或搬运来源接口；货物不在地图上，解除物品禁用无法拿取，原版信标也不会枚举。想要取货时，解除封存从中取出部分，或者选择一种出货方式。封存柜脚下另外放置的地面物品不是箱内库存。
- 货柜外挂船壳，本体不耗电，货物始终使用室外气温。单个覆盖槽可安装温控插件，复用现有插件的建造、开关、绘制与宿主销毁链。插件使用原版目标温度控件（默认 -10°C），按 ASF 原函数相对室外最多调节 100°C；低于目标时制热 175 W，高于目标时制冷 200 W，到达目标或停用为 0 W。停用、断电、拆除后回到室外气温。控件目标和插件开关由各自组件存档，不修改共享 Def 的温度参数。
- 牵引的自动独占／物品与活体筛选、手动多束叠力及断片提取统一以[对接设计 §9.3](对接与舱外作业重构设计.md#93-牵引光束与月池回收)为准。结构不自动收进月池。
- **冷退役与任务地址**：空间站近期现场走限时整图保真，到期后可退回同 ID 的 A 并从 prefab 重建。同一空间站的任务板和货运／客运地址只认 `SpaceObjectId`，任意终端均可接取和交付；当前交互仍使用该终端本地绑定的货柜。终端没有 UUID，运行时 `ThingID`、prefab 顺序和坐标都不是长期地址。完整契约见[地图归档保留与退役](地图归档保留与退役.md)。

## 已核对的原版与现有入口

- RimWorld 1.7 `ITrader.Goods` 与 `ColonyThingsWillingToBuy` 要求 `Thing`，`Tradeable.ResolveTrade` 逐项调用 `GiveSoldThingToTrader/Player`；`Dialog_Trade` 接受地图上的谈判者。ASF 仅提供储物/UI/温度基础设施，不改原版搬运 AI；实际货物在地图上，内容页有容量滑杆，大量货物的 tick 和存档成本仍须实测。
- `SoftDockPortal` 已提供原版 `MapPortal` 的人员／货物入口；交易取玩家侧真实 Map，不新建跨图寻路或影子商队。
- 结构分离使用现有 `CaptureDomain → StripDomain → PlaceIntoMap`；货柜作为建筑随所处结构搬运。散落物进入 `SpaceScatterService`，建筑残片保持结构对象。
- ASF 储物事件与封存货柜信号共用库存标记入口。已发布重量由 `CompSpaceCargo` 持有，`SpaceCargoMassUpdates` 在首次到期读取时合并采样待更新货柜，向物理报告提供旧、新重量。`SpaceScatterService` 目前只允许散落对象被牵引，手动结构牵引需要扩展目标与力分配，不可复用坐标插值。

## 施工顺序

1. 两种货柜形态分别复用 ASF 仓储和原版战利品箱；`CompSpaceCargo` 只负责模式转换、插件、温控入口、质量失效和调试操作。`ISpaceCargoContainer` 仅向终端暴露真实库存与转移接口，不另实现搬运或开箱。
2. 终端配置与绑定由 `Building_SpaceTradeTerminal.Configuration` 和 `Dialog_SpaceTradeTerminal` 提供；出现后的帧边界及 Rare tick 检查补货期限。关联保存真实建筑引用并在补货／交易边界复核，断开的货柜仍保留内容。
3. 终端实现 `ITrader` 适配，所选地图通过原版通电玩家信标枚举可出售物品；原版 `TradeDeal` 逐项移入锁定库存柜或已解锁交货柜。白银与商品共用库存，不做第二份账本。成交前按所需堆数检查两类状态货柜的容量；原版商人生成器允许超上限总量，入柜前用原版 `Thing.SplitOff` 按各物品 `stackLimit` 拆成实体堆；按真实堆数分配多个供货柜，每柜预留 16 个出售位，所有柜的可用位耗尽后才丢弃未入柜的生成余量。`TryStore` 拒绝超上限输入，避免原版 `SpawnSetup` 截断数量。
4. 货柜库存质量按快照加入 `ShipPhysics`。跨图搬运与两种货柜形态转换沿用已发布质量和待更新状态，读档由真实库存建立初值。
5. 扩展牵引光束手动模式的结构选取和双端受力，自动模式继续现有散落回收；为锁定、供电、射程、结构断裂、地图替换建立清理与重选入口。
6. 编译 1.7 和 1.6；做必要离线回归与静态核对。新档游戏内验收由用户完成，不自动启动游戏。

## 货柜出货与回收

- 解锁且有库存的封存货柜可选择「倾泻到地上」或「弹射到太空」。倾泻沿用原版开箱的落点规则，放不下的货物留在箱内，可再次倾泻或弹射。弹射直接把箱内货物转成可牵引回收的漂浮物。
- 太空货柜被击毁时，仓储态读取 ASF 的 `StoredThings`，封存态读取内部库存。两态都按每堆数量的 25% 随机取整，幸存堆在帧边界各自成为独立漂浮物，叠加 0–4 格／秒的相对速度。仓储态在建筑销毁前移走幸存堆，漂浮物从原储物格中心出发，同格货物可以重叠。封存态从释放点沿随机方向偏移 1.5 格。建筑建材仍由原版销毁流程结算。
- 散落图暂时无法租用时，主动弹射的堆保留在箱内，击毁的幸存堆留在或放回原图。ASF 仓储页主动弹出先尝试附近非储物格，放不下的余货进入散落流程。

## 模式转换

- `CompSpaceCargo.SetStorageMode` 创建目标形态，将原物品先从源库存取下，源建筑正常离图后才生成目标建筑，不叠加两套储物格。成功后重定向终端的货柜引用，再销毁已离图且空仓的旧建筑；插件留在原格，按新宿主重新解析。
- 保存 ASF 实际生效的筛选、优先级、容量限制和名称；解除封存先放回原物品，再恢复容量限制，允许保留 ASF 原本“已占用大于调低后限额”的状态。转换保留位置、朝向、派系、耐久和原版喷漆；失败时撤销目标形态并恢复源库存与绑定。
- 两种形态分别走自身原版／ASF 存档与搬图路径；封存时保存待恢复的 ASF 设置。没有影子仓库、双份库存或第二套开箱任务。

## 调试入口

- God Mode 选中货柜可加入样例货物、查看库存、锁定或瞬间解锁、清空，以及按正常毁伤路径击毁货柜。
- God Mode 选中终端 →“DEV：配置交易终端”：选择商人类型、补货周期，在货柜列表中分别绑定多个供货仓和一个取货仓。供货仓先通过货柜自身 God Mode 命令锁定；取货仓保持解锁。God Mode 配置窗口另提供“重新生成供货库存（替换旧货）”，可在无软对接时验货；玩家设施须先在同一配置窗口内勾选“DEV：无差别供货”（位于商人类型与周期下方，不再提供独立 Gizmo）。导出正式 NPC 站 prefab 前关闭该调试开关。

- ASF 安装版目前仅声明支持 RimWorld 1.4–1.6。1.7 会回退加载其 1.6 文件夹并标记版本不兼容；两个 Delta-V 目标均可编译，但 1.7 ASF 运行时须实测。此货柜未使用 ASF 的配方取色 GraphicsDef，可避开已知的 `StorageRenderer.GetColorFromRecipe()` 路径。
- 仓储态由 ASF 管理真实地图物品，封存态按原版战利品箱持有并保存内部物品；大量不同装备的性能、完整存读档和开箱落点仍需实测。

## 货仓与终端绘制

- 2×3 货仓在聚焦地图画 `CargoPort`。北向左上为骇入终端，右上格 `(1,0,1)` 为温控安装位，挂件缩放 0.6 且中心在格心。骇入站在左中根格朝向左上终端。其余可站立区域显示舱盖、装卸线和六段占用条，按真实堆数与当前容量填充。
- 非聚焦船壳改用 `CargoExterior`，由 `ShellRenderRuleDef.alternateGraphics` 绘在 `Exposed` 层，独立投影读同一太阳方向。装运口与外箱分别按 Def 的留白补偿尺寸绘到约 2×3 格。贴图契约见[货仓 Def](../1.6/Defs/ThingDefs_Buildings/DeltaV_StationTrade.xml)和[船壳规则](../1.6/Defs/Misc/DeltaV_ShellRenderRules.xml)。
- 交易终端是 2×2 的灰色削角俯视交互台，水平深青屏、输入区和通讯区绘在同一张 `TradeTerminal` 图上，由 `Graphic_Single` 随建筑和船体转向。视觉复核集中在[美术验收](TODO.md#art-acceptance)。

### 货仓与安全电池共用状态色

颜色表达取用状态。货仓锁定优先于已解锁时的仓储／封存模式。安全电池只用青灰和中性灰，实际容量由电量条独立表示。

| 状态 | 货仓含义 | 电池含义 | 材质参考 | CutoutComplex RGB乘色参数（0～255） |
| --- | --- | --- | --- | --- |
| 青灰 Active | 仓储，可正常搬运、取材 | 已实际接入电网，可充放电 | 现有速射炮主装甲 | `193,245,255`（`#C1F5FF`） |
| 中性灰 Reserved | 已解锁但封存 | 主动隔离，或尚无实际电网连接 | 现有重炮中性灰装甲 | `224,224,224`（`#E0E0E0`） |

## 交易货源

- 到达终端后打开独立的“选择货物来源”窗口，而非交易目标浮动菜单。仅有一个来源时也明确选择。候选入口仍要求有效玩家主驾驶台和软／硬对接关系，终端所在玩家船也可用；同 Map 的候选合并为一行，显示全部候选船名。
- 硬对接复用同图关系。软对接要求终端连通结构上的接口接通，且对端属于候选船控制域；控制域只用于判断对接资格，不用于读取商品。
- 确认后仅保存货源 Map 和本次终端／谈判者／站点 Map。`UniverseManager.StationTrade` 持有运行时选择，不存档或导出；关闭窗口、删除地图、对象注销／表示替换、运行时服务重置均清理。货源图必须持续有符合条件的玩家船；其中一艘易主而其他候选仍在同图时，货源继续有效。失去最后一条有效对接关系后拒绝成交，不自动回退其他地图。
- 商品清单直接调用原版 `TradeUtility.AllLaunchableThingsForTrade(sourceMap, terminal)`：原版负责玩家信标、通电、范围、重叠去重、嵌套容器和 `PlayerSellableNow`，白银遵守同一范围。已撤销 `TradeDeal.InSellablePosition` Prefix，原版迷雾与附近禁售规则继续生效；封存货物在原版箱内，不在信标枚举的地图物品中，无需额外过滤补丁。本终端供货仓物品仍从玩家侧排除，避免同地图双侧重复。
- 成交前再次读取相同货源路径，检查待售数量、商人库存与双方货仓容量。售出物品经过原版 `SplitOff`／`PreTraded` 后进入供货柜；买入物品从真实供货柜移到取货柜，无空投。原版交易窗口、定价与白银结算保持不变。
- 离线回归使用真实 `AllPowered`、`AllLaunchableThingsForTrade` 和 ThingGrid，替代信标房间几何、价格可售性条件、船体几何及名称翻译，验证通电和玩家派系筛选、范围去重、同图多船、断电／失去覆盖、断接及成交复核。完整 GUI、原版价格／白银结算及实图传货由用户验收。

## 游戏内验收重点

- 普通模式没有终端建造按钮和配置入口；God Mode 可放置、配置和切换无差别供货。终端所在玩家船可选；把 NPC 终端或供货仓连基架转移到玩家船后，关闭无差别供货时定期和手动补货均不刷新。只有其他玩家船硬对接在 NPC 站上时，NPC 站仍正常补货。开启调试开关后玩家设施可定期／手动补货，存读档保留开关。

- God Mode 原位覆盖货柜时旧柜被销毁，无储物格重叠红字；温控插件可正常覆盖安装。God Mode 下终端无软对接也可配置，多供货／单取货绑定和商人类型随存档、prefab 导出导入保留。NPC 到期重新生成供货库存，取货仓已购货物保留；供货仓遭骇入后不被自动重新填货。

- 软／硬对接后只允许选择具有玩家主台飞船的货源地图，货源对话框按地图合并显示船名；只有所选地图内通电玩家信标提供的物品与白银进入交易窗口；买入、卖出、白银结算后货柜库存只变化一次，蓝灯接收柜打开后实体可搬运。
- 玩家建造默认解锁，存读档和搬图保留锁定状态。新档验收时在 6 格平台上检查骇入前后库存相同，倾泻放不下的堆仍在箱内，弹射后能牵引回收。
- 终端关联仓库模块被炸断后立即失去该库存；模块独立漂移、被拖走后仍可骇入。分别击毁锁定柜、解锁封存柜和仓储柜，核对幸存货物的数量、品质、材质、耐久和组件状态，确认其相对残骸飞散并可牵引回收。
- 自动牵引仍回收散落物；手动牵引结构时目标和发射船的速度／角速度符合受力点、质量和反作用力，停火后按各自惯性漂移；暂停、切图、存读档不继续施力。
- 玩家货柜启用仓储模式后，物品按筛选与优先级自动入柜；工作台直接从柜内取所需材料，向更高优先级储物设施搬运时只取目标堆；关闭后封存并禁止拿取。检查“内容”页、48 堆容量、满仓交易拒绝、温控插件的安装／拆除、制热／制冷、停用／断电恢复室外温度、存读档和满载质量。
