# 在线 MPC 自动驾驶

## 目标与边界

`ShipAutopilot` 只编排固定航点/随动目标任务、回调、到达判定和 60 Hz 游戏 tick
控制请求；对象负责执行和积分。制导算法经 `IAutopilotGuidance` 隔离。制导按**微步**（6 tick = 0.1 s，
与 MPC 计划步长一致）节拍：QP 求解周期按运行时阶段选择——巡航每 4 微步
（2.5 Hz）、制动每 2 微步（5 Hz）、精确对位每微步（10 Hz）。精确对位沿用 9 格
终段距离；制动依据闭合速度、当前反推能力、阻力与计划回放时间提前开始。多船任务
按 `(微步序号 + ownerId) mod K` 确定性错峰；解之间逐微步**回放计划控制**
（`TryGetPlannedStep` 读上次解的后续输入），而不是只持有首控制量；计划耗尽或数值
回退时立即重解。2026-09-25 定案：10 Hz 全速求解实测拖垮 6x 倍速（360 tps 下单
tick 预算 2.78 ms，Balanced 档单次求解 avg ~3 ms）。对接完成仍只由
`LandingApproachController` 的位姿窗口与保持 tick 判定，MPC 不感知对接。

对象执行层在微步内缓存同一能力版本和期望力／力矩的分配结果；版本、指令或微步变化即重算。真实推进器可用性变化同步更新能力版本。预览不写真实油门或表现时间；终段虚空动力仍由任务给出渐变比例，对象执行层补齐期望与可达出力之差。

## 驾驶契约与调用入口

`DriveSubject` 区分容器 ID、船归属 ID 与 shuttle 身份。`SpaceObject.TryGetDrive` 返回只读 `DriveInfo`（位姿、船体帧角、质量、质心、惯量、推进布局和能力版本）；`PreviewModel / Preview / PreviewBraking / PreviewAngular` 共用物理求解核心。`ApplyDrive` 返回执行、等待分离、主体失效或本 tick 已推进；`ClearDrive / AdvanceDrift / SettleDrive` 统一取消、漂移与固定航点终态。

`MapSpaceObject` 从真实图与既有主体适配读取能力，执行 `RequestThrust` 门禁及真实分配。`ArchivedSpaceObject` 使用卸图时记录的推进器位置、方向、有效推力及质量惯量，通过同一求解器积分；不执行图内燃料／电力消耗。归档动力摘要的生命周期见 [太空战架构 §9.1](太空战架构.md#91-远距整图归档与撤退)。

| 调用方 | 当前入口 | 已删除的旧路径 |
|---|---|---|
| 自动驾驶 | 主体解析 → TryGetDrive → MPC → ApplyDrive | Map／归档／shuttle 分支、专用重载、摘要捕获、直接分配积分与写位姿 |
| 手操与 Universe | 输入换算 → ApplyDrive；统一 AdvanceDrift | Universe 内质量查询、分离判据、分配与积分；归档专用推进函数 |
| AI、战斗轨迹 | DriveInfo 信息与只读预览 | 直接读取地图物理报告、预测写油门 |
| 取消、分离、对接 | ClearDrive；收敛后 SettleDrive | 分散清油门与自动驾驶终态位姿写回 |
| 状态、火焰、音效、调试 | MotionInfo 只读视图 | 各表现调用者直接取得可变物理报告 |
| shuttle 动力布局 | MapSpaceObject 按 XML 重建并持有 | shuttle 服务注入入口、全局虚拟布局注册表 |
| 弹体 | 既有制导／碰撞策略 → 对象 AdvanceDrift | Universe 绕过对象的点质量积分分支 |

基类和子类均不选择目的地。AI 决定返厂、避战和守位；生命周期只决定地图表示。归档与恢复清掉主体旧任务，目标引用按 objectId 解析，正常 AI 周期重新下令。物理算法仍只有 `ShipPhysics` 一份；旧六响应样本、凸组合预算与专用离线巡航不再存在。

## 模型

状态为 `[px, py, vx, vy, angleError, relativeAngularVelocity]`，其中位置/速度在目标点
球面切基表达。控制量为 `[fx, fz, torque]`，各轴以正反向平均能力为共同力单位，正反向能力之比决定
上下界；预测和 `DesiredWrench` 使用同一单位，不能在执行时再按符号缩放一次。
每次求解按当前质量、惯量、船体角度、
可用推进器和终段虚空动力比例重新线性化为双积分模型；预测期内目标按恒定线速度和
角速度运动，两次求解之间按计划开环推进。`ShipPhysics.HeldInputFactors` 组合 60 Hz
半隐式积分及逐 tick 阻力，供非均匀预测网格使用；阻力作用于本船绝对速度，转换为相对
状态时保留目标速度前馈。姿态及分配器在一次求解内仍是当前状态的局部线性近似。

战斗机动由 `ShipAutoManeuverControl` 每个制导微步规划 2–6 秒后的可达轨迹：战术距离
决定径向修正，推进器实际侧推与转向能力决定切向推进，前视角最多 60°。环绕方向进入
任务时按实际侧推能力选定，船首偏角为 0°。轨迹给共同 `ShipAutopilot` 的是未来位置、
速度、终点角与角速度，以及当前位置到敌舰中心的途中船首角和视线角速度；自动驾驶在
每个预测步由同一条球面曲线采样位置、速度和船首朝向，不把弧段按终点速度直线回推。
MPC 在各预测步惩罚偏离轨迹和途中船首参考，并在终点成本中追求未来姿态；船首跟不上时规划层缩短切向推进，而不让理想环绕相位按固定
时钟继续前进。该模式仍只用真实推进器，不启用终段虚空动力。稳定环绕优先使用 5 Hz
制导，偏离轨道或姿态时恢复 10 Hz；既有求解和计划回放路径不分叉。

### 分阶段制动（2026-10-01）

`ShipAutopilot` 在制导微步使用 `ShipPhysics.PreviewBrakingAcceleration` 只读调用真实
分配核心，按当前接近方向采样反推，不写油门。预览能力乘 MPC 与回退共用的 0.8
安全系数；停止距离按当前阻力半衰期计算（无阻力时为 `v²/(2a)`），并计入最长四个
微步的继续闭合距离。反推不足立即进入制动。长期随动目标重新远离，连续 1 秒满足
双倍安全余量后才恢复低频巡航，防止阶段边界反复抖动。

阶段切换或计划回放的停止余量不足时立即重解。制动要求放入 QP 的整条预测轨迹，
不再以首步停止距离检查把有限的 MPC 解切换到回退控制。侵入 shuttle 由导弹服务接管，
不走自动驾驶 MPC。

随动目标点速度统一由 `SpaceTransform.VelocityAtLocalPoint` 计算：宿主锚点速度加
`ω×offset` 后平行输运到目标点。不得退回只匹配宿主中心速度的实现。

QP 使用状态、终端、输入及相邻输入变化的二次成本。默认尺度为 10 格、5 格/秒、
10°、10°/秒；状态权重 `[4,4,2,2,4,2]`，终端权重 20 倍，输入权重 0.15，输入变化
权重 0.75。运行状态成本、输入成本和输入变化成本均乘当前段时长，避免 0.1 秒近场段
相对远场粗段被额外惩罚出力。该变化成本是分段控制增量的正则项，不是连续导数成本。

普通航点/随动的接近约束使用停止距离 `v_close²/(2*a_safe) <= d` 的保守分段线性形式：

- 冻结本次求解的接近视线，`d` 为到目标接近平面的有符号距离；`a_safe` 为真实反推
  预览的 0.8 倍。二次停止曲线忽略阻力助刹，状态预测本身仍包含阻力。
- 以 `Vmax=max(1, sqrt(|v_relative|²+2*a_safe*distance))` 划分四个速度区间。
  区间端点为 `vi,vj`，每条弦约束为
  `(vi+vj)/(2*a_safe)*v_close - d <= vi*vj/(2*a_safe)`。
  凸平方函数的弦在区间内位于曲线上方，四条弦的上包络给出保守停止距离。
- 每个预测节点再约束 `v_close <= Vmax` 及 `d >= -0.05`。初始距离不超过 0.05 格时
  退出接近约束，由完整二维位置、速度、角度、角速度代价完成保持；无反推能力时不构造
  除以零的停止约束。战斗轨迹继续跟踪其逐点参考，不套用固定目标接近约束。
- 这组硬约束取代原先在零输入轨迹上对平方根取切线的软包络；后者是宽松外近似，且
  近零距离的斜率与大松弛权重导致数值病态。角向直接由完整状态与终端成本优化。

这不是任意船型的全局可达性证明：真实分配器有平移/旋转耦合，姿态在飞行中变化，
目标也可能机动。闭环微步重规划及实际出力日志仍用于检查模型误差。

## 求解器与预设

`DenseAdmmQpSolver` 是无游戏依赖的纯 C# 稠密 ADMM QP 求解器。每 8 次迭代检查
原始可行性与真实 KKT 平稳性残差 `Px+q+A'y`，两者分别满足
`1e-4 + 1e-4 * 对应尺度` 才接受。每 32 次按归一化残差平衡调整 rho；第 32、128 次
及迭代上限尝试活跃约束 KKT 精修，精修仍须满足原问题的边界、乘子符号与残差。
失败的精修不覆盖 ADMM 解或其诊断。工作区复用，不以墙钟时间决定输出。

非均匀网格的热启动按实际经过的秒数重采样旧计划；模型和网格变化后清空旧对偶乘子。
预测时域由当前反推能力估算停止和接近所需时间，不能使用更强的侧推能力缩短制动预测。

- Fast：16 段、最多 128 次迭代、最长 30 秒。
- Balanced：24 段、最多 512 次迭代、最长 45 秒，默认。
- Precise：32 段、最多 768 次迭代、最长 60 秒。

当前运行时使用 `Balanced`，属于 `ShipAutopilot` 实例且不存档。前 8 段保持 0.1 秒
微步，其余按预测时域均分。分解失败、非有限结果或迭代上限仍未收敛才进入既有数值
回退，并明确记录失败；本轮修复的回归要求全程不触发回退。求解器的残差、rho 平衡与
精修方法参考 [OSQP 官方算法说明](https://osqp.org/docs/solver/)，未引入外部运行依赖。

## 失败与验证

数值求解失败时使用 `BrakingGuidanceFallback`，按
`v_limit=sqrt(2*a_safe*distance)` 提前制动，
旋转使用同构角停止距离；不会恢复旧饱和 PD。数值失败警告只在状态边沿输出。固定航点
最长 120 秒或连续 10 秒无进展后失败回调，不再强制改写位姿。

开发者入口：

- `MPC: diagnostics summary`
- `MPC: deterministic self-test`
- `Combat autopilot: trajectory snapshot`：按需输出预测时长、环绕前视角、船首目标／
  误差、实际／目标角速度及请求／真实力矩；热路径不逐 tick 输出日志。

纯数值自测覆盖初速 20 格/秒与 0.5、1.0、2.2 格/秒²三档制动能力，且各档分
`K=1`（每微步求解）与 `K=4`（求解 + 计划回放）两种闭环语义验证；执行侧经过
`DriveInfo` 无副作用分配预览，另覆盖非对称反推/移动目标及不同阻力下的停止距离次序。
游戏内仍需验证
移动/旋转目标、偏置落点、非对称或故障推进器、暂停/倍速、终段虚空动力与火焰一致性、
6x 倍速下多船求解的 TPS 表现。

离线回归：先执行项目标准 Release 构建，再运行
`& scripts/MpcRegression/run.ps1 -Strict`（需 .NET 8 SDK 和本机游戏程序集）。脚本直接编译
生产制导/求解器源码，调用生产 DLL 的真实分配核心，不使用虚空动力或辅助控制。
涵盖静止进场、55°/180° 转向、横向初速、K=4 回放、弱反推、20 格/秒初速、阻力及
带阻力的移动目标；任何回退、越过初始目标平面超过位置容差、进入后丢失对接窗口或
超时都判失败。此外核对已知 QP 最优解与 60 Hz 积分组合系数。它是局部平面闭环数值
回归，不代替球面坐标、船体锚、游戏内对接流程和多船倍速性能实测。
