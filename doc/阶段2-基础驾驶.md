## 按键与 Harmony 设计

- 冲突事实（1.6 实测核对）：原版默认 **W/A/S/D = 相机平移**（`CameraDriver.Update` 轮询 `IsDown`）、**Q/E = 设计器旋转/绘图样式**；`KeyBindingDef` 是轮询式，无事件消费机制，抑制只能在读取入口收口。
- 自定义 `KeyBindingDef`（分类 `DeltaV`，`selfConflicting=false`、不设 `checkForConflicts`）→ 原版「选项 → 控制 → 按键设置」显示 Delta-V 驾驶分类并提供改键；Mod 设置的「通用」页只提示这一路径。保存、取消和跨存档持久化由原版 `KeyPrefs` 管理。原版窗口确认后，驾驶键抑制集合在下一帧按新绑定刷新；与原版键位互不自动抹除（`KeyPrefsData` 冲突检测按 category 隔离）。
- Prefix ×3（`KeyBindingDef.IsDown` / `JustPressed` / `KeyDownEvent` getter）：驾驶激活时，本 mod 分类的绑定放行；其余 def 若**当前实际绑定键与驾驶键集合（6 驾驶键 + 切换键，A/B 槽）重叠**则返回 false。非驾驶模式只有静态 bool 早退。
- 键集合在进入驾驶及原版改键确认后按当前绑定重建 → 双方任意改键后抑制关系仍然正确。
- 切换键默认 `Keypad0`（原版全部字母默认键均被占用）；另有屏幕按钮与 dev action 入口。
- csproj 加 `Lib.Harmony.Ref 2.3.3`（编译期引用；运行时用游戏自带 0Harmony），About.xml 声明 `brrainz.harmony` 依赖。

## 物理模型

```text
输入（PlayerFrameInput 每帧首次消费时统一采样 IsDown／鼠标）→ 帧快照
        ↓ 每 tick 与当前速度的飞行辅助合成 Command (fx, fz, torque)（无输入轴反向指令）
推进器油门联合分配（盒约束最小二乘，同时求 Fx/Fz/力矩）
        ↓ ΣF / m → a；Στ / I → α
半隐式欧拉（dt = 1/60，每 tick，暂停冻结）
        ↓ v += a·dt；ω += α·dt；angle += ω·dt
质心不变量：OrbitSphere.Move(position, Rotate(comLocal, angle)) = 质心宇宙位置
```

### 锚点速度与偏心质心（2026-11-08）

`SpacePose.velocity` 是该位姿锚点的位置导数，`angularVelocity` 是切基角 `angle` 的导数。地图原点、船心和质心各自的速度不能混用；质心状态由 `SpaceTransform.RigidPointPose` 派生，不保存第二套运动事实。

`OrbitSphere.MoveVelocity` 对实际 `Move` 公式求导，包含球面东／北基随锚点移动的变化及局部点运动。`SpaceTransform.VelocityAtMovingLocalPoint` 是业务入口；`OriginVelocityForPoint` 反解同一雅可比，`AlignLocalPoint` 用它修正实际对齐点的位置并反求原点速度。`TransportTangent` 仍是切平面投影，不能单用平面 `v + ω×r` 再投影代替位置导数。朝向仍遵守现有切基角相加契约。

共同积分器先取得质心的实际速度，按真实力、力矩和原有半隐式 tick／阻力规则推进质心，再反求地图原点的完整状态。牵引与惯性耦合更新质心动量和自旋后也反求原点速度；玩家平移辅助读取质心速度。自动驾驶的任务落点仍指地图原点，但 MPC 的动力学状态和每个战斗预测步的参考统一转为质心，推力列及制动方向换到同一参考切基。停放／拆分仍通过既有刚体点入口继承真实锚点速度。

适用边界：上述导数要求球面坐标基在局部连续。既有 `OrbitSphere.Basis` 在极轴附近改用备用北向（投影平方长度小于 `1e-6`），切换线本身不连续；跨线反求可能没有满足固定切基角的解，本轮未重定义全球朝向或消除该接缝。极区平滑区域与精确极点备用基区域分别验证，不把跨接缝导数当作已保证的能力。回归数据与游戏内验收见[持续机动实施记录](持续战斗机动重构计划.md)。

- **质量**（story：先用基架近似）：Substructure 甲板格 × `MassPerDeckCell`(1) + 建筑质量（def 带 Mass stat 用 stat 实值——如 LargeThruster=30，否则 `MassPerBuilding`=4）；质心按点质量求和；转动惯量 I = Σm·|r−CoM|²。Delta-V 专用货柜额外计入已采样的库存质量。地面物品、Pawn、原版运输舱和 EVA 舱内载荷保留各自的库存及发射容量规则，船体报告仅采样专用货柜。结构变化即时重测，复用已有货柜快照。货柜服务每图间隔至少 600 游戏 tick 合并采样待更新的货柜。物理报告消费旧、新重量的差量，以地图原点的一阶矩和惯量增量更新总质量、质心与质心惯量，复用推进器布局。物理量无变化时沿用报告版本与分配结果。
- **推进器**：实体建筑按 `CompProperties_GravshipThruster` 及其子类识别。作用点取占用矩形中心，默认推力方向由 `ShipPhysics.ThrustDir` 按建筑 Rot4 定义；有符号 Def 推力在 `BuildInstalledThruster` 中归一化为实际方向与非负大小，负值反向，零值停用。非对称布局继续由共同分配器按真实几何补偿力矩。Shuttle／EVA 沿用各自虚拟推进器配置。
实体推进器的基础推力通过建筑 `modExtensions` 中的 `DeltaV.DefModExtension_ThrusterPower.thrust` 配置。例如 `<li Class="DeltaV.DefModExtension_ThrusterPower"><thrust>-800</thrust></li>` 代表相对建筑默认推力方向反向出力 800。字段允许有限的正数、零和负数；省略字段才使用缺省换算，不以负数作未配置标志。非有限值会产生配置错误，并在读取时按零处理。普通推进器没有此扩展也可接入。

缺省换算读取推进器自身 `statOffsets/GravshipRange`；没有该项视为零。标定点由原版小型／大型推进器最终 Def 的航程加成和显式推力提供，当前为 `(0,0)`、`(10,800)`、`(16,2000)`。航程 `R ≤ 10` 时 `F = 80R`，`R > 10` 时 `F = 800 + 200(R − 10)`，超过大型标定点继续线性外推；不截断负值。修改标定 Def 后，两段系数随之变化。两座标定 Def 必须提供有限的显式推力及递增的正航程，否则缺省换算不给出动力。

推进器详情页在与「建筑」同级的「Delta-V」分区显示「基础推力」。`Patch_ThrusterStats` 在原版 `ThingDef.SpecialDisplayStats` 的结果后追加 `StatDrawEntry`，以现有 `ThrusterPower.IsThrusterDef` 识别组件及其子类，数值直接读取 `BaseThrust`，不额外要求 Delta-V 出力上限组件。原有航程等条目保留。该值不乘实例出力上限或实时油门，保留零和负号；建筑 Def 与实例详情使用相同口径，条目说明交代负值方向及实际出力的限制。

详情条目使用浮点通用格式，避免将极小的正／负推力舍入为零。2026-11-18 两版原生离线详情入口、双语和护盾设置回归通过，次数与验收边界见[护盾能源说明](舰炮与护盾基线.md#维持功率与逐发能源)。

实际出力大小为 `abs(F) × 玩家出力上限 × 分配器油门`；出力上限仍为 0–100%，负推力不会绕过故障、排气阻塞或断电检查。驾驶门禁、推力汇总、自动驾驶、调试箭头和归档读取归一化后的同一动力布局。离线布局工具读取同一 XML 标定，将候选推力按整数单位量化进入近似约束，最终机动验收仍调用生产分配器；本轮不重新生成内置 prefab。

2026-11-18 验证：1.7／1.6 的 `TutorialRegression` 默认组各通过 39236 项，包含原生 XML 可空字段读取、分段连续性、动态标定、显式正／零／负推力、四向归一化、真实分配和力矩；1.6 共同运行组通过 2092 项。Python 离线值与两版生产代码的 20 个换算点一致，混合大小／负推力的方向容量、限推与联合安装模型通过。两版星区专项均在旧巡洋舰额外 20% 均布载重的侧向加速度断言停止：约 0.35，原要求 0.68；本轮不调整布局或放宽阈值。离线数值通过不替代游戏驾驶、火焰、对接及归档往返验收。

- **分配器**：每台推进器提供一列 `[Fx,Fz,(r−CoM)×F]`，以坐标下降求解 `0≤throttle≤1` 的归一化加权最小二乘。未输入平移轴与力矩的零值保持权重更高：AD/WS 纯平移会差动同向推进器，必要时调用正交方向的相反推进器组成力偶，以抵消不过质心的平移推力。布局物理上无解时降低主轴出力，合力/合力矩仍按真实几何重算。每次求解先计算列系数和分母，迭代不重复计算固定几何；工作数组随布局复用。
- **输入快照**：驾驶键、临时刹车和手动瞄准共用 `UniverseManager.PlayerInput`；同帧多 tick 不重读按键，暂停绘制可先采样。地图、焦点、会话变化会失效资格，原版 UI 的地图 MouseDown 授权仍只在 OnGUI 执行；详细输入边界见 [太空战架构 §6.1](太空战架构.md#61-玩家火控与机动统一-controller-下的独立输入会话)。
- **驾驶执行**：手动输入（含飞行辅助）直接提交归一化指令，自动驾驶提交期望力／力矩，统一在 `SpaceObject.ExecuteDrive` 汇入上述分配器和积分。对象读取驾驶视图及执行出力时分别刷新一次动态动力状态；数值预览、指令换算和求解不再各自重读。相同物理报告、动力版本和指令直接沿用上次油门／合力，不按 6 tick 定期重算；结构／载重重建、动力失效／恢复、加力变化、指令变化及取消驾驶均使结果失效。分离授权与积分仍逐 tick，复用结果时也刷新推进表现新鲜度。离线覆盖持续输入 120 tick 只求解一次、逐次实时动力检查、同 tick 预览后动力改变、手动／自动等价指令、重建、取消及零输入；火焰持续性和实际 TPS 待游戏内验收。

## 玩家驾驶方式与任务（2026-10-26）

每艘玩家船的 controller 在运行时持有手动或自动控制及唯一自动任务；读档重建为“自动 · 自由漂移”。自动任务包括自由漂移、速度同步、战斗机动、定点定角驾驶，以及系统发起的软对接制导。侧边栏控制按钮与驾驶切换快捷键共用交接入口；普通推进／旋转键不进入驾驶，自动驾驶时不屏蔽原版相机与建造旋转。从自动进入手动会停止自动出力并暂停当前任务；回到自动时复核主体和目标后恢复，失效则显示原因并回到自由漂移。明确选择其他任务会替换旧任务；选点或菜单取消不会替换。速度同步在手动接管时保留几何稳定计时，改选其他任务时清除计划与计时。战斗机动暂无敌舰时保持“寻找目标”。软对接制导手动接管后不得自行重新挂回。火控和驾驶任务独立，NPC 决策及侵入弹体制导保持原入口。

定点任务在地图拖曳选择位置与船首宇宙绝对角度；松开时按参考系修改键可选当前画面中的非聚焦对象外壳。移动参考只带动目标位置及刚体点速度，绝对船首角度和零目标角速度不变。到位后写回完整目标位姿与速度并结束，进入自由漂移。几何、MPC 和容差详见[在线 MPC 自动驾驶](在线MPC自动驾驶.md#玩家定点定角任务2026-10-26)。
- **推进动画**：分配器在可重建的质量报告中留下每台推进器本 tick 的连续油门；表现层只读取该派生状态。火焰复用 `CompProperties_GravshipThruster` 的 Shader、贴图与方向偏移，油门同时控制火焰长度/亮度/透明度、排气发射率/粒子尺寸/速度；火焰根部随长度变化保持在喷口处。油门新鲜度统一由 `DriveInfo.HasFreshThrottles` 按最近执行出力的游戏 tick 判定（15 tick，即 0.25 游戏秒），复用分配结果也刷新；未写入与清零使用 -1。聚焦地图、非聚焦船壳、shuttle、排气与音效共用该判据。火焰亮度噪声也使用游戏 tick；暂停保留火焰与亮度，不继续产生排气，恢复后真实停推立即熄焰。2026-11-01 修正了 Unity `Time.time` 在游戏暂停期间仍推进、导致火焰超时消失的问题；两版编译零警告／错误，`NpcRetreatRegression/run.ps1 -ThrusterPauseOnly` 的 20 项专项通过（含暂停超过旧超时、恢复、断电、取消、零输入与分配复用）；拆船测试已补齐组合运行时遗漏的 `GravEngine` 定义初始化，34 项专项通过；较大的 `-DrivePerformanceOnly` 继续运行后在战斗目标测试的 `MapDormancyService.IsDormant` 遇到空引用，整套未通过。2026-11-01 用户确认本轮暂停火焰修复游戏内实测无问题。动画不参与物理、不持久化，也不对 Delta-V 飞船图以外的地表推进器生效。
- **推进工作音**（2026-09-20，`ThrusterAudio`，与火焰同源同判据——同一份 report + `HasFreshThrottles`，暂停时停止工作音）：聚焦图内逐推进器空间化循环（`SoundInfo.InMap(建筑)`，声源每帧跟随建筑、镜头衰减交给原版 `distRange`，音量 = √油门）；非聚焦船壳整船 OnCamera 循环（跨图 InMap 声源被引擎 context 强制静音，只能挂相机；音量 = clamp01(Σ√油门/3) × 距摄像机 30~120 格线性衰减，位置复用 `FocusedDrawPosition` 与所见一致）。两个 SoundDef 引用原版剪辑 `Gravship/Gravship_Engine_Loop`（`ContentFinder<AudioClip>` 跨包解析，素材经设置内临时试听页于 2026-09-20 选定）且**不可混用**生成方式（world 子音必须 InMap、onCamera 子音必须 OnCamera，Sustainer 构造对错配红字/静默转换）；淡入淡出走原版 `sustainAttack`/`sustainFadeoutTime`，PerFrame 维护断供自动 End 兜底。纯表现缓存，不写物理、不进存档，读档/重置经 `ThrusterAudio.Reset` 自愈；世界视图与非 Delta-V 图经 DrawingMap/frame 门控整体静音（兼容 RimExodus 地面图）。
- **飞行辅助**（Mod 设置，默认开；**按住 Ctrl（可改键）临时启用，辅助关闭时也可刹停**）：无输入轴在船体系发反向指令走同一分配器，主要减速受该方向推进器真实出力限制；**残差直接衰减**（用户决策 2026-09-13）：低于 0.6 c/s / 0.1 rad/s 的剩余漂移按固定减速度（2.4 c/s² / 0.4 rad/s²）收尾到零，不要求推进器布局完美消除微小漂移；辅助轴另有"反推不越过零"过冲保护。
- **积分中心 = 质心**；`SpacePose.position` 锚仍是地图几何中心，每步通过上述共享变换派生质心并恢复锚点状态；新档存读档保存原点的真实速度，不为旧开发快照迁移。
- 数值（40×24 玩家船，约 1830 质量）：前进加速度 ≈ 2.2 cells/s²（2 台 × 2000 推力）；敌舰（约 870 质量、单台线性推进器）≈ 2.3 cells/s²。

## Universe Layer 正式映射（消除阶段1"两套账"）

- **语义**：宇宙系锚定宿主图 tile——宇宙原点 = 宿主图中心，+X 东 / +Z 北（宿主 tile 切平面局部系）。阶段1 的 HostFrame 参数由此升格为正式记账锚点（机制不变，仍是纯显示帧）。
- **方向唯一**：universe → tile（不变量 #9，tile 绝不反驱 pose）。
- 船口袋图 `parent.Tile` = 该船 universe 位置的球面投影（从当前 tile 贪心邻接走向，尺度 `CellsPerTile = 100` 格/tile）；`MapInfo.Tile => parent.Tile` 无缓存、`Game.FindMap` 实时匹配，`WorldObject.Tile` setter 自带渲染器/FastTileFinder/PositionChanged 收尾——运行时重锚安全。
- 重锚：`UniverseManager.GameComponentTick` 每 60 tick 检查全部船；投影 tile 变化且未被占用（世界对象/地图）才写入；场景创建同样经投影 + 最近空闲 tile（替换阶段1 的 FindFreeOrbitTileNear）。
- 效果：驾驶飞远后星球背景真实平移/换 tile；两船初始偏移在同一 tile 内（100 格/tile），行为与阶段1 观感一致。
