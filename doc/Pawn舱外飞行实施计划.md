# Pawn 舱外飞行实施计划

状态：2026-11-25，路线 B、第 3 节原范围及第 5 节修订范围已获批准并完成代码实现。已合并抛出与散落的抽象接管入口。人员的飞船能力只在有图飞行表示中按入场状态临时创建；星图始终把人员作为同一个宇宙对象条目。活动资格现与真空生存分离：覆盖躯干的防真空服装提供一次基础活动能力，总真空抗性只决定原版暴露风险。1.6／1.7 构建、人员专项、EVA、玩家飞控和弹体回归结果见第 6 节；游戏内新档验收及两项既有专项故障保留在 TODO 与审计记录中。

## 1. 玩家流程与首版规则

1. 玩家选中太空图中征召的 Pawn，点击「出舱」。按钮保持稳定，不在静息枚举时扫描格网；点击后才解析并冻结月池、开放对接口、无顶甲板或与真空相邻的甲板出口，Pawn 随后进入共同抽象漂浮流程。
2. 具备太空移动能力且可分配地图时，同一 Pawn 转为独立 1×1 真空口袋图并可接管。其位置和速度沿用抽象对象，包括出舱点继承的自旋切向速度。WASD 按摄像机方向推力，保留刹车和飞行辅助。角色面向随准星更新，地图在聚焦时仍是 identity，物理状态由该 `SpaceObject` 持有并按游戏 tick 积分。
3. 当前主武器在飞行时由现有手动主火直接执行真实 `Verb`。只跳过一格图无法表达的预热、视线和本地射程门禁，原 burst、冷却、弹药／燃料／充能消费保持；实际生成的弹丸进入宇宙弹道，并在命中目标图时执行同一实例的原虚 `Impact`。太空战可以击中这名 Pawn，原版健康、护甲、真空暴露、温度与需求继续按图内规则更新。
4. 从共同战斗侧栏选择友方或敌方舰壳上的合法格，启用人员硬对接；它与跳帮艇共用命令、目标器、取消及自动驾驶生命周期。跳帮艇仍以碰撞完成，人员则保持碰撞规避，以相对落脚点 `1.5 cells/s` 的穿越参考飞向点击时冻结的精确格，并在低于 `2 cells/s` 时完成落脚，不破墙也不清理结构。友舰与敌舰登舰使用同一流程。
5. EVA 将人和货物抛出时，两者都先从舱口成为抽象 `SpaceObject`。之后由共同人员服务检查 Pawn 的能力。已在飞行图上的 Pawn 失去行动或太空移动能力时，同一对象退回抽象漂浮，可继续定位和回收。
6. 舱外 Pawn 可用战斗面板副组 1 的抓钩收拢目标。抓钩既拉目标，也把自己拉向目标。身体与目标接触后，能装的货物自动入背包，可搬运的人员由 Pawn 抱起。钩住结构可借力接近舰体，登舰仍由共同硬对接的人员落脚流程完成。

### 已实施的首版规则

| 项目 | 建议规则 |
| --- | --- |
| 资格与推力 | 至少一件实际穿着、覆盖躯干且被原版认定为防真空的服装授予一组 800 基础推力，不要求总真空抗性达到完全防护。多件基础服装不重复叠加；Royalty 跳跃背包等带扩展的装备按 Def 追加各自虚拟推进器。进入可控太空表示时按当刻真实穿戴创建一次飞行快照。当前飞行期间禁止换装，背包中新增装备不增加能力；能力来源被摧毁或强制移除时只允许减少或失效。降格、落脚或回舰后销毁快照，下次出舱重新创建。地面跳跃继续使用原版充能。 |
| 抛出与升格 | 释放人或物都先建立无图载荷。共同人员服务只根据合格躯干服装、可用个人推进器及行动能力决定抽象 Pawn 是否转成飞行图；总真空抗性不参与升格。物品留在抽象载荷。地图名额不足或没有活动服装时，已成功抛出的 Pawn 留在太空抽象漂浮，可定位和回收。玩家接管另按驾驶权限判断。 |
| 失能与降格 | 有图 Pawn 倒地、失去行动能力或失去全部入场基础活动来源时立即结束驾驶、火控、抓钩和登舰，随后转回同 ID 的抽象 `SpaceObject`，并销毁本次飞行能力。真空抗性不足不会直接降格；有图期间由原版真空暴露造成伤害，伤害最终使其失去行动能力时才触发降格。抽象漂浮沿用现有暂停实体 tick 的语义，单靠时间流逝不会让倒地者恢复。死亡处理原版实际尸体和散落物。 |
| 太空武器 | 自动识别单一常规远程弹体或光束 Verb，映射为个人尺度的实弹或光束。可经 Def 显式配置兼容性复杂的武器。无限供应弹药，保留游戏 tick 冷却、射程和毁伤上限。首版参数用常规步枪、连发武器和光束武器校验输出关系，个人武器定位为近距交火、威胁暴露设备和支援登舰。 |
| 抓钩操作 | 首版建议把抓钩作为可操作舱外 Pawn 的副组挂载，按住手动开火键收绳，松开解除。抓钩一次锁一个目标，保持真实动量。抱人占原版手部搬运槽，可带人一起回舰。 |
| 反制 | 普通太空射击可命中飞行 Pawn。舱外人员永不成为舰载武器的目标：体积太小、通常无法对飞船造成有效伤害，敌我识别也分不清被抛出的己方人员与准备登舰的敌人，所以点防、自动选敌和导弹制导都不锁定人员（见 §6.2 第 30 条）。人员通过盾面参照现有跳帮艇，无盾容消耗。个人武器射出的弹体和光束照常受盾。舰队自动机动、NPC 批量出舱和小队控制留待后续。 |
| 登舰 | 与跳帮艇共用硬对接命令、目标器、取消及制导事务，但执行器选择不同完成方式：跳帮艇碰撞完成，人员以 `1.5 cells/s` 穿越参考进场并在实际相对落脚点速度低于 `2 cells/s` 时到达完成。人员点击时只接受精确的月池、开放对接口、无顶甲板或与真空相邻甲板格，始终保持碰撞规避；封闭端口、阻挡设施、落点已占用或支撑消失时取消落位。不破墙、不清理着陆区，目标舰结构毁伤恒为零。 |

## 2. 实施契约

### 2.1 抛出、抽象化、升格与降格

| 阶段 | 输入与职责 | 完成时的结果 |
| --- | --- | --- |
| **1. 抛出人和物** | 各来源只确定本次要释放的真实实体、持有者、释放数量、位置和初速度。保留原有确认、所有权及释放预检。舱口等来源通过 `SpaceTransform` 得到同一个刚体释放状态。 | 把统一释放请求交给抽象化入口。此阶段没有太空移动判定、建图预检或驾驶逻辑。 |
| **2. 成为抽象 `SpaceObject`** | 共用 `UniverseManager.CapturePayload`，在安全帧把同一 Pawn 或物品转交 `AbstractPawn`／`AbstractItem` 并登记无图对象。发布成功后才对来源确认放出，失败时保留或还原未交接的源内容。 | 人和物已经在太空，取得对象 ID 和 `SpacePose`。货物到此为止。活体 Pawn 发布成功后，请求独立的人员能力复核。 |
| **3. 抽象 Pawn 按能力升格** | `PawnSpaceflightService` 从已登记 `AbstractPawn` 读取原 Pawn，统一计算太空移动能力。判断通过才申请地图，并在安全帧复核原表示、实际资格、唯一持有关系及回收占用。 | 以现有 `ReplaceRepresentation` 将同一对象变成可驾驶的 1×1 图，玩家是否能接管由权限决定。未满足条件、容量不足、生成失败或已被抓取时，保留正确的当前状态。 |
| **4. 有图 Pawn 按能力降格** | 同一服务用同一个能力判据复核在飞 Pawn。触发边沿时先清驾驶出力、火控、抓钩和落脚请求，再在安全帧交接。 | 同一 Pawn 和 `SpaceObject` ID 转回 `AbstractPawn`，位置、速度连续。抽象对象登记成功后回收旧图，供后续救援或再次升格。若交接失败，保留真实 Pawn 的原图并禁用操控，交接仍可复核重试。 |

- EVA 舱口、甲板出舱、毁艇幸存者及已有的人员与货物散落入口都只负责阶段 1 和 2。毁艇继续使用原版卸载和伤亡判定。升格由共同对象发布后调度，抛出调用方无须查装备、健康、图容量或物化结果。活体危险确认可以保留，装载状态以抽象对象是否成功接管为准。
- 阶段 3 在升格前按实际穿戴的合格躯干防真空服装、附加推进来源、主武器和行动状态创建本次飞行快照；总真空抗性只供点击出舱时提示风险，并由有图状态下的原版真空暴露消费，不参与升格资格。阶段 4 只用快照仍然依赖的真实来源和当前健康状态判断能力是否减少或失效，不把飞行期间新增的装备热接入能力。松开推进键、暂停和切换聚焦均不会改变资格。由抽象 Pawn 发布、健康变化、能力来源丢失及读档重建触发复核。容量不足只登记待重试的对象 ID，实际腾出地图名额时重新检查，避免反复扫描。抽象实体沿用原版漂浮载荷停 tick 的约定，失能的人可被抱起或被月池收回治疗。
- 升降格在 `UniverseManager.QueueFrameAction` 完成，各阶段以对象 ID、表示版本和真实持有关系复核。`ReplaceRepresentation` 保留原 Pawn、对象 ID、完整 `SpacePose` 和本 tick 的积分记账，只更新表示版本与相关索引。当前飞行表示保存可供飞行中存读档恢复的临时能力、挂载和火控状态；降格、落脚、被抱起或回舰时整体销毁，不复制进抽象人员或地面 Pawn。抽象和有图状态都可独立存档，事务中间状态由既有存档门禁保护。成功后交接聚焦，运行时星图选择按同对象重新解析，旧图在无实物后回收。

### 2.2 人员落脚与跨图交接

- 有图时原 Pawn 是地图上生成的飞行主体，以 Pawn Thing ID 和人员种类建立仅供 controller 使用的临时 `DriveSubject`，承载图保存真实 Pawn 引用和本次飞行快照。该身份不是 `SpaceObjectId`，也不承担对象分类；宇宙对象类型只由 `SpaceObjectTag.Personnel` 等角色表达。地面或舰内 Pawn 不生成 `PawnSpaceflightShip`，宇宙位姿仍只由容器持有。
- 跨图落脚共享 `CaptureDomain → StripDomain → PlaceIntoMap`，增加人员专用搬运范围。现有按格捕获会读取同格实体、区域和地图状态，原版整船放置还会应用故事状态和自动屠宰配置。人员范围只搬选定 Pawn 与该 Pawn 已持有的内容，共享原版 Pawn 放置、`PreSwapMap`／`PostSwapMap` 语义。初次主动出舱要求手部空闲，穿戴、武器和库存随人转移。抱人返回或登舰时，救援对象仍处于原版抱起状态，落脚后可用原版操作放下。人员转移跳过整船捕获中会让抱起对象掉在源格的处理。源图其他人、区域、任务队伍及目的地故事状态各归原图。
- 落脚或抱起仍有图的人员使用共同搬运链，抽象 Pawn 升格从已有载荷接管并复用同一人员放置步骤。交接失败保留或还原原 Pawn、征召状态、位姿和持有关系。两个 Pawn 抢同一落脚格、或抓钩与升降格交错时，依据同一事务及版本校验保证每个实体只交接一次。

### 2.3 动力、武器与受击

- 复用 EVA 的相机输入和 `ShipPhysics` 推进分配。入场时记录全部合格的基础服装来源，但只选一件仍存在的来源生成一组基础四角斜推；带 `DefModExtension_PawnSpaceflight` 的其他装备逐件叠加。推进器布局从入场快照读取，不因背包中新增装备而扩大；能力来源损坏只能使对应出力减少，全部基础来源消失才失去活动资格。实时出力及开火检查仍读取当前可行动状态。身体、实穿衣物、装备、库存和抱持对象纳入质量，抓钩收货可由质量真实降低机动能力；附加推进器以轴向推力和制动收益验收。复用统一质心和积分。
- 每个受支持的入场主武器使用真实装备实例 ID 派生本次飞行的挂载身份。虚拟舰载冷却、火控和武装状态只保存在当前飞行表示，飞行中存读档可恢复；降格或落脚即销毁，地面武器不安装持久舰载状态。太空中禁止换枪、主动丢枪和从背包装备武器；来源武器被强制移除时只关闭当前挂载，不自动改用另一件武器。飞行火控借用现有准备／提交、弹道、盾面和命中链，武器射程在手动开火判定时也生效。原版同图射击的 Verb 仅在正常图内使用。
- 有图人员阻止穿戴、脱下、装备、换枪和主动丢弃装备的命令与工作。抓钩收取只进入 `Pawn_InventoryTracker`，抱人只进入 `Pawn_CarryTracker`，两者都不能触发自动装备。外部 Mod 强制改变装备时由通知入口使旧来源失效或降格，不从新装备热创建能力。
- 飞行 Pawn 作为显式受击对象加入同一 `SpaceCollision` 查询。人员接触几何来自实际 Pawn 和飞行表示。共同后效把个人命中交给原版 `Pawn.TakeDamage`，按 Pawn 的身体和护甲结算。舰体相撞的结构预算、点防按建筑 HP 预留致死弹量的算法各保留其适用主体。默认外壳只额外绘制舱外 Pawn，真实地图绘制模式使用 REF 的原版动态绘制，两种模式均只画一遍。

### 2.4 无墙登舰与返回

- 指令确认时锁定目标船或结构域、目标局部边缘和整数落脚格。预览、助推参考、接触判定及写回读取同一锚点。用 `SpaceTransform` 得到该点当前的位置和刚体速度，辅助接近使用现有 MPC 的随动与制动能力。
- 人员弹体代理在整个有图阶段只负责受击与普通船体碰撞转接，不因登舰命令切换为主动撞击弹体。`HardDockingService` 为人员提交 `ShipAutopilot.NavigateToReference`，位置参考始终从目标容器当前位姿与冻结局部格心计算；人员执行器另提供 `1.5 cells/s` 进场目标和 `2 cells/s` 完成上限。MPC 构造在预计交会时刻穿过格心的随动参考，停止约束只处理超过进场速度的部分；人员不能关闭碰撞规避。跳帮艇仍由同一服务选择碰撞完成并交给弹体扫掠。
- 到达后排入 `UniverseManager.QueueFrameAction`，同一精确格判据复核支撑、开放状态、占用及目标身份；不做半径搜索或自动改落相邻格。失败时保留飞行主体并提示。成功后原版 Pawn 图内战斗与敌舰守卫接手。

### 2.5 个人抓钩与舰载牵引的共同能力

- 现有舰载系统保留两种运动方式：月池自动收集继续坐标收拢，舰载手动结构牵引继续用既有弹体后效在真实接触点施力。人员抓钩与 EVA 货舱钩索则共同进入 `TractorLinkService` 的轻型物理连接：共享发射门禁、首交点、端点、有效时段、目标占用、取消与接收事务，并通过 `ShipPhysics.ApplyTractorImpulse` 施加冲量。
- 抓钩依实际发射方向选最先触及的有效目标。散落人员及货物来自既有索引，结构和有图飞行 Pawn 走共同碰撞查询。固定命中实体或结构局部点，显示、冲量和收取读取同一端点。可移动的两端按质量施加等大反向冲量，散落货物的质量取实际件数，有图或无图人员使用实际人体与随身负载。固定结构锚承担反作用，角色靠真实推力和抓钩运动。可移动结构使用既有命中域及分离复核，牵引只作用于解析出的结构域。
- 用游戏 tick 中双方接触几何的扫掠判断是否真正重合。申请后效与安全帧交接读取同一接触记录，复核目标和发射者表示、占用及接收资格。断线、松键、失效、超距或目标被遮挡时释放连接，两端保有当时实际速度。抓钩状态在读档时重建为未连接，存档保存实际位置、速度、背包及手部持有物。

| 接触目标 | 后效 |
| --- | --- |
| 普通散落货物 | 收取前重算原版背包剩余质量、可接收数量和负载后的有效机动能力，能带动的数量自动放入 `Pawn_InventoryTracker.innerContainer`。可以只装部分。装不下或带不动的余量仍由原散落对象持有，全部交接成功后才注销。 |
| 活体 Pawn | 手部空闲且满足原版抱起条件时，交给 `Pawn_CarryTracker.TryStartCarry`。无图漂浮人员走 `AbstractThing.Handoff`。有图飞行人员经共同人员转移中的抱起目的端交接，成功后清理原飞行图。拒绝抱起时目标留在原表示。抱起后将所抱人员和随身负载计入载人者质量，落脚后可在舰内放下。 |
| 舰体、岩体或残骸 | 人员与 EVA 都保持钩在真实表面锚点，只把轻型发射者拉向该点。抵达表面后停止继续施力，松键可脱钩。接触结构本身只产生借力与接触反馈，登舰仍需满足 §2.4 的精确开放落脚条件。 |

## 3. 逐文件实施范围

### A. 统一抽象化、表示切换与驾驶

| 文件 | 操作 | 具体改动 |

游戏内验收由用户在新档完成，优先 1.7，1.6 对照关键入口。最小场景为一名征召殖民者、一艘能平移和旋转的友舰及一艘有外露甲板、关门和点防的敌舰。

1. 从旋转友舰出舱，分别体验真空服和背包叠加。暂停、飞行辅助、控制切换和反复聚焦正确，实际只出现一名殖民者。
2. 用步枪近距互射，验证连续射击、护甲与真实弹药／燃料／充能消耗，并确认单兵射弹不进入舰载点防目标。倒地后同 ID 自动退回抽象漂浮，可定位救回。另用直接致死的命中验证只产生一具可回收尸体。核对两种绘制模式均只显示一个人。
3. 对旋转敌舰从开放边缘登舰，核对位置、装备、征召及图内战斗。接触前关门、炸掉甲板、让另一人先占落脚格均应拒绝落位。回友舰重复同一流程。
4. 在自由飞行、武器冷却和接近中分别存读档。核对身份、入场快照、装备、健康、冷却和宇宙位姿。读档后可手动接管，旧接近指令已结束。飞行中不能换装或换枪；回舰后换装并再次出舱时生成新能力。重复出舱和回舰后，实际地图数回到场景基线。
5. 从飞行 EVA 抛下两种能力状态的殖民者及一堆货。核对共同发布的抽象对象及舱口速度。地图已满时，有飞行资格的 Pawn 仍成功离舱并可回收，腾出名额后可升格。试验抽象与有图两种状态的独立存读档。
6. 用抓钩分别收取货堆、抱起无图漂浮人员和有图飞行人员，再钩住一处旋转结构。观察轻重目标两端的运动、满载余量和接触失败。抱人返舰后放下，核对身份、衣物、健康和回收前后的地图数。

## 5. 已批准的追加范围与身份修订

`SpaceObjectId` 使用全局无类型身份空间，不按人员、基架船或 shuttle 分段。对象角色由 `SpaceObjectTag` 区分。抽象人员和有图飞行人员都只生成一个对象级星图条目；临时 `PawnSpaceflightShip` 不进入持久船体成员条目、书签或对象分类。`ReplaceRepresentation` 保持同一对象 ID，运行时选择在条目刷新后按对象重新解析；书签随存档保留，临时选择沿用现有读档重置规则。战略世界视图的船体剪影仍排除 `Personnel` 对象，由已在范围内的 `UniverseManager.cs` 约束枚举。

虚拟推进器缓存当前只为 `ShuttleShip` 建立和刷新。共同结构缓存扩展为读取当前有图表示的临时能力提供者。人员的布局来自升格时保存的飞行快照，不因太空中新增装备热重建；库存和抱持重量仍通过共同质量入口即时影响运动。驾驶会话释放复用现有 `ShipControlService.ForgetMap`。

## 6. 实施与代码审计报告（2026-11-25）

### 6.1 已落地的主链

- 释放来源只提交实体、持有者与刚体释放状态，`CapturePayload` 统一完成抽象持有和对象发布；人员对象取得 `SpaceObjectTag.Personnel`。发布、升格、降格、落脚和抱起都以对象 ID、表示版本及真实持有关系复核。对象注册现在返回显式成功值；即时或帧边界发布失败会恢复原地图／原 `ThingOwner`，无来源的瞬态实体会销毁，不能留下“实体被抽象持有但对象未注册”的孤儿。
- `PawnSpaceflightService` 只从已发布的 `AbstractPawn` 决定升格。至少一件覆盖躯干且被原版认定为防真空的实穿服装、仍可行动且有地图名额时创建 1×1 图、同 ID `MapSpaceObject`、入场快照和临时 `PawnSpaceflightShip`，并为整个有图阶段绑定一条共用同一对象位姿的运行时弹体代理；能力不合格或名额不足时保持抽象漂浮。总真空抗性不参与升降格；有图人员失能或失去全部入场基础来源后走同一服务降格并释放代理，读档按当前有图表示重建。地面 Pawn 没有飞船能力；换装锁以有图表示为准，失能至安全帧降格的间隙也不能换装。
- 临时驾驶身份使用 `DriveSubjectKind.Personnel`，对象身份仍是普通 `SpaceObject.objectId`，分类只读 tag。审计修正了 `DriveSubject.Of(PilotTarget)` 曾把人员重新压成 foundation/shuttle 二元身份的问题。星图对人员直接生成对象级单条目，不枚举临时船成员；世界船体标记排除人员对象。
- 入场快照记录全部合格躯干防真空服装，但只生成一组 800 基础 EVA 四角斜推；跳跃背包等扩展来源各自额外叠加，不再复制或换算主武器。推进器缓存只读快照来源；新增装备不热接入，附加来源消失会减推力，全部基础来源消失才降格。飞行中主火只认当前仍装备的同一主武器实例，外部强制移除后失效。身体、装备、库存与抱持对象进入人员质量，抓钩新增货物会即时降低机动能力。
- 有图人员在 `SpaceProjectileService` 中始终绑定一条不序列化、不绘制、不另建 `SpaceObject` 的人员受击代理。射线与扫掠先确认该代理存在，再把命中转交真实 Pawn 的原版 `TakeDamage`；代理没有独立 HP、位姿或积分。人员不进入舰载点防、自动选敌或导弹制导的目标，身份比较读取完整 `DriveSubjectKind`。主火由 `PawnSpaceWeaponBridge` 直接运行真实 Verb；完整逐发调用结束后，仍存在的标准 `Verse.Projectile` 由 `AbstractProjectile` 持有并注册为瞬态宇宙对象。结构命中不套用 Delta-V 舰炮伤害，而在目标图重放同一弹丸最派生的虚 `Impact`；burst、冷却与原资源消费保留。单兵射弹不进入点防，首种模式暂不兼容即时光束和完全自管发射的特殊 Verb。`DeltaV_PawnSpaceflight.xml` 提供透明的人员受击代理、真实弹丸碰撞契约，以及副组 1 抓钩的虚拟挂载／连续束 Def。
- 返回／登舰与跳帮艇共用 `HardDockingService` 的目标器、命令状态、取消和自动驾驶生命周期，执行器选择完成策略。跳帮艇仍要求关闭规避，以弹体扫掠碰撞后破口、清理着陆区并落艇；人员与 EVA 不能关闭规避，使用 `NavigateToReference` 飞到点击时冻结的精确合法格，再分别经单 Pawn 搬运或既有 EVA Dock 提交完成落位。轻型执行器同时交出真实 32 格钩索；硬对接操作以独立 token 维持连接，远段与推进器共同追赶，进入实际反推能力对应的制动包络后松绳。首次真实挂钩前到达门不会提交；成功捕获后资格保持到本次操作结束，近距实时束线释放只停止牵引力。人员代理不因登舰武装为撞击弹体，途中普通碰撞只走既有受击／船体转接。
- `CompPawnGrapple` 作为副组 1 的 `ISpaceWeaponFireGate + ISpaceWeaponLaunch` 接入共同战斗面板；按住副火刷新、松开即释放。`TractorLinkService` 持有人员抓钩与 EVA 货运钩索的运行时连接、真实局部命中点、遮挡复核和安全帧接收。二者射程均为 32 格。可移动目标与发射者承受按质量响应的双向冲量，固定结构只拉动轻型发射者；光束显示、距离和冲量读取同一端点。手动连接的方向和力矩作为操作力暴露给驾驶：飞行辅助不制动被连接驱动的轴，已有自动任务保留但在连接期间不出力。硬对接拥有的连接不争用手动目标，也不暂停登舰自动驾驶，允许多名人员／多台 EVA 同时钩住同一结构。人员货物按背包质量部分接收，抽象人员经载荷交付，有图人员先捕获为临时载荷再交给 `Pawn_CarryTracker`。月池／舰载坐标收货和舰载手动结构牵引保留原实现。
- 人员主动出舱的聚焦交接复用 shuttle 起飞后的镜头换基：只有抽象对象成功升格和发布有图表示后才聚焦、选中临时人员船并进入手动驾驶；征召在进入手操时完成。聚焦其他玩家可控船且不存在自动任务、接近或硬对接时也会自动手操；EVA／人员武装时同时切手动火控。人员准星先更新身体朝向，再在同一帧提交武器瞄准。装备页允许把背包物品交给共同抽象散落入口，穿脱／丢弃装备则在点击入口立即拒绝。
- `PawnSpaceflightService` 为抽象人员记录资格、快照、建图、载荷交接、表示发布和弹体代理阶段状态；“Dump SpaceObject at position”会附带该诊断。资格拒绝不再作为瞬态失败盲重试，建图或交接失败保留可重试状态。
- 主动出舱 Gizmo 只按人员派系、征召和太空图语境稳定显示，不读取屋顶、地形、端口、相邻格、装备 Stat 或活动资格。点击后 `PersonnelAccess` 才解析月池、开放对接口、无顶甲板或真空边缘；出口有效后分别读取活动服装与真空风险，必要时用一次确认框说明不可控漂浮、回收方式或持续暴露伤害。确认后帧边界复核冻结结果；月池／无顶甲板垂直释放，不强加水平初速度。

### 6.2 审计中发现并已纠正的歪点

1. `DriveSubject.Of(PilotTarget)` 丢失 `Personnel` 种类，可能把人员和同数值 foundation 身份合并；已改为完整复制 `kind`。
2. 人员目标初版会让普通地图的 `InterceptionBody` 也走实体后端，绕过结构伤害；现仅无图载荷和 `Personnel` 目标使用实体后端。
3. 抓钩初版以对象中心施力、人员有图质量未套实际负载；现固定真实首个命中点并统一质量报告。
4. 有图人员抱起初版直接跨图调用 `TryStartCarry`；现先经抽象持有事务交接，失败恢复原 Pawn。
5. 失能至降格的短窗口初版会解除换装锁；现锁随有图表示生命周期。
6. 对象注册冲突初版只写日志，`CapturePayload` 仍会返回未发布对象；现注册结果显式化并覆盖失败回滚回归。
7. 登舰初版只复核开放格并在接触点附近搜索；现点击时冻结精确合法格，每 tick 复核目标表示与该格资格，到达同一随动参考后才落脚，不再以普通船体碰撞或附近搜索完成。
8. 既有 EVA 离线场景没有初始化 Pawn capacity Def，新人员发布通知会触发容量缓存异常；现未初始化 Def 明确保持抽象态，完整 EVA 专项恢复通过。
9. 返回／登舰初版在 `PawnSpaceflightService` 内另建目标器、参考点和完成状态，与跳帮艇撞击侵入形成两套硬对接；现抽为共同执行器，人员与跳帮艇共享命令生命周期，但分别使用到点和碰撞完成。
10. 抓钩初版提供独立 Pawn Gizmo 和目标器，绕过战斗面板、武器组、停火和持续手动射击；现改为副组 1 虚拟挂载，连接只由共同射击事务触发／续期。
11. 人员推进器初版在中心生成基数四向推力，不符合 EVA 四角斜喷几何；现每个装备来源生成四角斜推，轴向合力保持来源标称推力，多个来源继续叠加。
12. 出舱 Gizmo 初版每次枚举都会扫描相邻地形和建筑；现只在点击和帧边界复核，静息 UI 不产生格网检查。
13. 出舱与落脚初版只识别真空边缘；现统一支持月池、开放对接口、无顶甲板及相邻真空甲板，外壳目标器通过同一精确落点解析接受没有建筑的月池地形，人员落脚要求所选格仍合法且不破坏或清理结构。
14. 人员碰撞记录初版只在发起硬对接后临时创建，普通飞行受击仍绕过该代理；现代理覆盖整个有图表示生命周期，登舰不改变其角色，降格、返舰、抱起、注销或换档才释放／重建。技术 Def 改用透明 `Void`，不再错误请求不存在的 EVA 单图贴图。
15. EVA 手动货运钩索初版仍调用坐标收拢，无法产生发射者反作用；现与人员抓钩共用轻型连接和真实冲量。月池／舰载坐标回收及舰载手动结构牵引未改。
16. 装备页初版只在底层装备 tracker 拒绝，UI 点击可能先排任务而不立即提示；现补丁在 `ITab_Pawn_Gear.InterfaceDrop` 分流背包抛出与装备拒绝。
17. 人员主武器初版被换算成无限弹药 `CompSpaceWeapon`，绕过原 burst、弹药和第三方逐发状态；现删除换算层，直接执行真实 Verb，并把实际生成弹丸暂存后在目标图重放原虚 `Impact`。单兵射弹不进入点防。
18. 抓钩冲量初版会被飞行辅助或正在运行的自动任务当成漂移制动；现把活动连接标记为操作力，辅助只稳定未驱动轴，自动任务保留但暂时停推。
19. 真实 Verb 初版把手动集火点投射到一格图外作为 `CurrentTarget`；IsoRim 的枪口火光后效把该越界坐标当作楼层行索引，在弹丸已生成后抛出 `IndexOutOfRangeException`。旧异常收尾又只清待接管列表，导致 Verb 持续连射异常且本地弹丸最终命中射手。现用 Pawn 所在合法格作为纯本地占位，宇宙射向按每发独立快照；异常会销毁未接管弹丸并重置 Verb，普通捕获失败也不再遗留本地弹丸。
20. 合法本地占位与 Pawn 重合，原版人物武器渲染会把零向量解释成北向。现只对当前舱外人员的真实主武器覆写 `Verb.AimAngleOverride`，从 `PawnSpaceflightShip` 保存的宇宙准星返回角度；弹丸和兼容后效读同一方向，不把本地目标重新移出一格图。
21. 初版把完整真空抗性和 `requiredForFlight` 自定义扩展同时当成活动门槛，第三方躯干防真空服即使使总抗性达到 100% 也会诊断为 `NoRequiredFlightSource`，而防护不足者完全不能活动。现改为原版躯干防护服装判据提供一次基础推力，总真空抗性只作为点击警告和原版暴露伤害输入；诊断分别报告 `mobilityEligibility` 与 `vacuumRisk`。
22. 独立武器射向初版只在实际开火入口更新，并且同时直接写 `Pawn.Rotation`；结果是未开火时准星不会驱动人物转身，开火瞬间又会覆盖相机投影的四向选择。现由共同 `ShipAimHandler` 在每次有效手动准星采样时通知船体保存射向，`ArcadeShipAimHandler` 唯一负责人物四向转身，开火入口只消费同一状态。
23. 初版 Harmony 只补丁基类 `Verb.AimAngleOverride` getter，并把主武器硬限制为 `Verb_LaunchProjectile`；覆写 getter 的 `Verb_Spray`／第三方喷射 Verb 因而仍朝北，且即使正常调用原版 `Projectile.Launch` 也会在无日志的类型门处被拒绝。现枚举所有已加载 Verb 类型并去重补丁各自 getter，同时按 `defaultProjectile` 与实际原版弹丸捕获能力接入喷射／扫射 Verb；完全自管弹体仍不伪装为兼容。
24. 读档恢复人员表示后初版没有为当前聚焦图复用 `ActivateFocusedVessel`，旧档武装人员可能保留 `Disabled` 火控而没有瞄准会话。现于 `Personnel.Resume` 后排队执行共同聚焦激活规则，正常恢复手动驾驶、征召与手动火控，不另建人员专用状态分支。
25. 人员被自动征召后，原版 `Pawn_RotationTracker.UpdateRotation` 会在没有忙碌姿态时每次把人物重置为南向；Delta-V 虽已按准星写入正确四向，下一视觉更新仍会覆盖，因此表面上只有开火进入 `Stance_Busy` 后才转身。现只在该人员实际持有当前手动瞄准会话时跳过原版旋转更新，由 `ArcadeShipAimHandler` 保持唯一四向权威；失去会话后立刻恢复原版行为。
26. 启动诊断显示按每个派生类型取属性 getter 后，反射包装对象的普通 `Distinct` 没有真正合并继承自同一声明方法的条目，导致同一 `AimAngleOverride` getter 被重复提交给 Harmony。现以模块和 metadata token 唯一化真实方法。后续最终绘制角诊断又确认 NewRatkinPlus（`Solaris.RatkinRaceMod`）的 `SYS.DrawEquipment_WeaponBackPatch` 全局替换原持枪流程，并在忙碌姿态用与 Pawn 重合的合法占位算出 `0°`、在非忙碌姿态传入固定 `143°/217°`，完全绕过正确的 getter。其忙碌分支还在最终调用前按错误的 `0°` 向北添加 `0.4` 格前伸量，所以只修角度后枪械虽然朝向正确，射击／手持切换仍会跳位。现于公共 `PawnRenderUtility.DrawEquipmentAiming` 最终入口以最低优先级、仅对当前有图人员真实主武器恢复保存射向，并把重合占位的既有前伸量从旧角度旋转到准星方向；不依赖 SYS 类型，也不改第三方的高度、残余位置、材质与翻面。原版先应用 getter 再计算位置，旧新角相同而修正量为零。本轮临时瞄准、转向、getter、弹丸捕获和绘制角日志已删除。
27. 人员登舰初版复用 `ShipAutopilot` 的全局 `0.15 cells/s` 终端相对速度门槛，实际要求近乎停稳，不利于单兵跳帮。第一次修订只把最终完成门放宽到 `2 cells/s`，但 MPC 的逐步／终端速度代价、停止距离包络和回退仍以零速为目标，游戏内仍会先刹到约 `0.1 cells/s`。现由执行器同时提供 `1.5 cells/s` 进场目标和 `2 cells/s` 完成上限；MPC 以预计交会时刻为锚构造穿越落脚点的参考，阶段切换、速度代价、制动包络和回退共同读取该目标。普通参考导航仍保持零终端速度及 `0.15 cells/s` 门槛，跳帮艇仍只认真实碰撞。完成提交沿用既有参考对齐与转移，不把剩余速度结算为撞击伤害；侧栏按钮统一为“登舰”。
28. 人员到点登舰初版只靠推进器追随目标参考，EVA 仍停留在 shuttle 的旧返回表现，因而对有动力且持续运动的舰船缺少与跳帮艇同等级的截获手段。现把人员与 EVA 都接入共同硬对接执行器并使用各自真实 32 格钩索：操作连接保存真实船体接触点和冻结落脚点，远段收绳、近段按实际反推停止距离松绳，自动驾驶继续负责制动。共同运动契约使两者只匹配落脚点线速度，不追随舰体朝向和自旋；连接建立是到达提交的必要条件。操作连接与手动抓货连接分开，不占目标独占、不暂停自动驾驶，也不让轻型单位取得撞击破口能力。
29. 钩索登舰初版把“本次操作曾真实捕获目标”错误实现为“到达提交的同一 tick 仍保持运行时连接”。人员进入月池、对接口或露天落点时，首个船体交点射线可能在自动驾驶检查前自然释放；`arrivalGate` 因而拒绝本可完成的第一次穿越，穿越参考在目标另一侧反向后形成往返乒乓。现由 `HardDockingService.Operation` 粘滞记录本次真实捕获：首次建立前继续禁止提交，建立后近距松绳或表面射线释放不撤销资格；取消、目标／表示失效或新操作不继承该状态。位置、相对速度和精确落脚格仍按原路径逐次复核。
30. 点防初版为舱外人员单列类别并默认纳入，敌舰自动火控也把升格后的 `PawnSpaceflightShip` 当成普通 Ship 成员参与选敌；人员容器没有建筑记录，`HullHealth` 恒为 0，`finishing` 项恒为 1，附近人员反而拿到最高分。现 `Ship` 改为总体标识，三种船体各自叠加 `Personnel`／`Shuttle`／`Foundation` 子类角色；点防类别与「配置近防目标」中的人员复选框删除，`CandidateValid` 与手动导弹沿射线锁定只认一体式与基架飞船。一体式船的 Shuttle 角色同时改为类标识，点防的“独立飞行才可拦截”改由容器缓存判定，停靠在宿主图内的艇行为不变。
