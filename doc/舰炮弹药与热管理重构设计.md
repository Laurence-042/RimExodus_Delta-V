# 舰炮弹药与热管理重构设计

**状态：已实施，离线验证通过，待用户新档游戏内验收。日期：2026-10-30。**

本轮将常规实弹改为批量生产的装药与弹头，建立炮塔热管理、可调射击参数，以及质量和速度共同参与的弹体结算。目标是让常规备弹支持持续交火，并让爆发、射击间隔、命中机会和补给成本形成可配置的取舍。轨道炮继续承担少量决定性攻坚射击，激光承担耗电但无需实体弹药的持续火力。

本文保存本轮获批目标和实施计划（下文“草案／待标定”保留设计阶段语义）。当前已实现行为见[太空战架构](太空战架构.md)、[护盾机制基线](护盾机制基线.md)和[武器伤害与费效比基线](武器伤害与费效比基线.md)；机制和首轮数值已归回这些专题，本文不作为当前数值来源。

2026-11-05 文档校正：武器职责以[武器定位与克制关系](武器伤害与费效比基线.md#武器定位与克制关系2026-11-05-定案)为准。下文已移除过期的重炮机械冷却下限和动能盾自动购买完整制动能量草案，不得从旧施工记录恢复这些规则。

## 1 已确定的设计

1. 单份材料批量生产多份弹药组件。装药与弹头独立供应、独立整数扣费，不在多次开火之间累计小数材料欠账。
2. 速射轻弹就是装药量 1、弹头质量档 1 的重炮弹。同材质、同质量、同速度、同弹体形态具有完全相同的命中、毁伤、贯穿、碎裂和护盾交互规则；发射炮塔的家族和尺寸不提供隐形伤害倍率。
3. 速射炮优化连续装填和持续散热，固定发射 1／1 弹，玩家调射速。每发积热，炮管逐渐发红；过热后炮身发红、冒烟并停火，必须彻底冷却后才能恢复。更高射速不保证更高的长期平均 DPS。
4. 重炮可分别调整装药和弹重。固定弹重时增加装药提高初速；固定装药时增加弹重降低初速。高质量提供更高穿深，碎裂后继承更高破片质量。
5. 重炮每发按装药发热，冷却至零后再射；固定机械周期下限已在 2026-11-01 取消。重炮须保持低 DPS、强穿甲的定位，但不得据此擅自恢复机械下限或统一增加长冷却。
6. 动能处理走公共 util。弹丸、破片的质量与实际相对速度共同参与毁伤和盾耗，不在武器、盾、AI 和预览中复制公式。
7. 激光可调功率，以更高逐发耗电提高毁伤；没有单发深穿。电磁盾相同设置与入射几何下的偏折角不随功率降低，入射能量越大，主动偏折耗电越多。低偏折角仍可能击中大船；现有几何续飞语义保留。

## 2 弹药生产与供应

### 2.1 物品与扣费

常规炮使用通用装药、钢弹头、铀弹头三类物品。钢和铀分别批量制成对应弹头；装药也使用钢铁制作，配方描述为“钢铁可燃，这是常识”，避免矿产充足而燃料不足的太空补给瓶颈；产量、加工时间、工作台与研究前置见武器基线，不将铀作为推进药消费。单材料多产出的经济方向保持不变。

| 发射配置 | 装药扣费 | 弹头扣费 | 说明 |
| --- | ---: | ---: | --- |
| 速射炮 | 1 | 1 | 弹头材质由当前有效弹仓选择 |
| 重炮 | 装药档 C | 质量档 M | 将 M 个标准弹头单位合成为一枚本发弹体 |
| 轨道炮 | 不消费化学装药 | 按自身固定弹芯规格 | 弹芯供应接入新弹头物品，电磁加速仍支付原有基础及逐段脉冲 |

装药、质量档取正整数。拆分供应后，不再使用整合弹药的 `max(C, M)` 扣费规则；物品库存质量、弹体实际质量和 UI 的质量档必须明确区分，不能把“档位 1”直接当作所有材质都重 1 kg。

同一发只能选择一种弹头材质。现有弹仓优先级继续决定供弹来源；缺少当前配置需要的任一种组件即不能发射，不静默减装药、减弹重或拼接混合材质。若沿用优先级向下一弹仓回退，必须重新完整计算该弹种的质量、速度、提前量和费用。

### 2.2 库存与搬运

炮内提供独立的装药和弹头库存，铀挂件继续作为可选弹头来源。弹仓容量以可持续射击时间和完整齐射次数标定；物品堆叠、制造批次、搬运频率一起核对，避免材料经济改善后仍依靠每几秒补仓维持射击。

库存必须使用原版 `CompRefuelable`，由原版 gizmo 分别设置装药／弹头的目标装填量和自动补给开关。已核对 1.6／1.7：原版补给只取首个 Comp，双仓因此需要明确选仓，存档节点与滑条拖动状态也须隔离。现有实现及唯一接线说明见[太空战架构 §5.1.1](太空战架构.md#511-装药质量与热管理2026-10-30)，不另做输弹网络或数量账本。

库存物品正常生产、搬运和保存；新建武器不凭空获得满仓的新制弹药。测试 prefab 则显式配置所需备弹。实际发射先校验并预留本发所有库存，成功后统一提交消耗，任何失败都不能只扣其中一种材料。

## 3 共同弹体模型

### 3.1 发射时冻结的事实

在既有 `SpaceWeaponShot` 准备阶段形成一次不可变的发射参数：弹头材质、质量、装药量、离架速度、完整弹芯／破片形态、毁伤与贯穿参数，以及激光的本发能量。沿 `SpaceProjectileLaunchSpec` 传入现有弹体实例，飞行后不再回读炮塔滑条。

发射初速继续叠加真实炮口运动；撞击与盾面作用使用接触位置的相对速度，包含防守刚体的旋转点速度。世界参考系、聚焦切换及双方共同漂移不得改变相同相对碰撞的结算。

速射和重炮共用普通实弹的联合效果配置。不同炮塔只限制可选档位、装填、散热、射速、射程、散布及表现，不再通过 `impactScale` 或独立弹体 Def 为同参数炮弹制造不同后效。尺寸更大的炮塔可提供更高装药／弹重上限或更好的装填散热能力，但 1／1 弹不自动变强。

### 3.2 公共计算入口

在现有 `SpaceImpactEffects` 及其纯计算部分收口质量、速度、毁伤与贯穿计算；可拆同类 partial／无状态 util 文件，但不得再建一套武器命中服务。`SpaceShieldProjectileBehavior` 负责盾作用及破片编排，调用同一计算入口。联合效果注册表继续决定碰撞组合的后效，`SpaceCollision` 仍是唯一求交和续穿入口。

公共入口需要分别提供：

- 装药、质量与材质决定的离架速度。
- 给定实际相对速度的动能，以及能量转回速度的计算。
- 单次毁伤、护甲穿透、贯穿余量和弹孔范围；这些量语义独立，不把护甲穿透当作可穿层数。
- 母弹碎裂后的质量分配、方向、速度及对应能量结算。
- 盾处理所需能量、实际支付后可实现的效果。

以下为**计算草案，系数与具体曲线待离线标定**：装药提供发射能量 `E发射 = k装药 × C`，离架速度可取 `v = sqrt(2 × E发射 / m)`；质量 `m` 由材质和 M 决定。贯穿量必须独立体现质量优势，例如以 `m × v` 为起始标定量，而不是直接等同于动能。固定装药增大质量时，应在有效工作范围内呈现“速度下降、穿深上升”。毁伤函数同时读取质量和速度，静止破片不能仅因质量大仍造成满额撞击伤害。

这个草案不承诺真实弹道学模拟。验收以明确的游戏关系为准：同参数同效果；高质量提供贯穿优势；速度降低牺牲命中机会；共同运动不制造额外能量；没有从炮塔类型补发的隐藏加成。

### 3.3 贯穿与碎裂

普通实弹统一使用参数驱动的贯穿结算。替换当前“重炮固定三层局部轮廓、速射只单格直击”的家族分工；轻弹是否能穿过目标取决于真实参数和结构，不能因来自速射炮而强制取消贯穿。优先扩展已有完整弹芯的连续求交与剩余预算链，不复制第二套穿层算法。伤害仍交回原版 `TakeDamage`，只有实际破坏和实际吸收才消耗对应余量，空舱不重复扣费。

碎裂由弹体形态及碰撞组合决定，速射与重炮同参数使用同一规则。破片质量之和不得超过本次参与碎裂的母弹质量；未生成的细小碎屑可以作为明确的质量损失，但不得每片都复制母弹完整质量。固定碎裂方案下，母弹越重，生成破片也越重。

破片数和方向采用有界的共同规则，不能靠质量无限增加弹体数量。散布、反推与碎裂损耗共用同一能量分配结果；不得向每片分别发放整发反推动能。破片继续用自身材质、形态、质量和速度走共同毁伤链。破片与完整弹芯可以有不同的贯穿效率，不能另给“重炮破片”叠加来源倍率。

轨道弹也使用共同质量、速度和盾交互；其完整弹芯形态、串联加速和集中贯穿定位保留，通过重新标定真实参数接入。接入时清理重复的旧伤害倍率，维持高储能成本、低频决定性射击的目标，不保留新旧两套贯穿预算。

## 4 炮塔调校与热状态

### 4.1 速射炮

gizmo 调整目标射速，范围由炮塔能力限定；实际间隔由游戏 tick 可实现的射速确定，UI 显示实际档位。每发成功发射才增加热量，正常散热只随游戏 tick 推进。基础规则为 `热量增量 = 本发发热 − 期间散热`，热量不小于零。

未过热时允许按所选射速开火；到达过热阈值后进入锁定状态，必须降到冷态零值才解除。阈值以下暂停射击可以提前散热，但已经触发的锁定不能靠降射速、切火控、切组或开关电源取消。低档能否持续射击由发热与散热平衡自然产生，不另给无限射击特权。

炮管红热程度随实际热量渐变；过热时炮身出现红热和烟。视觉只读取热状态，暂停时不推进热量或烟的模拟时间。高射速的收益是缩短输出窗口，不保证提高完整升温—冷却周期的平均 DPS。

### 4.2 重炮

gizmo 分别调整 C、M，显示实际质量、初速、消耗及冷却时间。每发热量由装药决定，完全排热后就绪；现行公式和范围见[武器基线](武器伤害与费效比基线.md)。已取消固定机械周期，不能同时保留旧的 `max(机械周期, 排热时间)` 草案。

修改 C、M 只影响下一发，不改变已产生热量；不得以调档清除热锁。低装药重弹的理论 DPS 过高是待校准项，不代表认可重炮替代速射的高 DPS 职责。

### 4.3 激光炮

gizmo 调整功率档，沿现有脉冲节奏提高单束能量、逐发电费和毁伤。电容与电网先预留、成功后扣费，不能只提高显示功率或伤害而仍支付旧电费。功率档上限、功耗／毁伤曲线和默认值待标定。

单束仍只作用于首先命中的结构，不新增一次贯穿多层的能力。后续脉冲可沿破口继续攻击内层；电磁盾按实际路径改向，光束不被静默删除。激光无需实体弹药，但高功率仍受储能、回充与功率范围约束。本轮不自动给激光添加尚未提出的过热系统，也不把点防和工程束一并开放为可调主炮。

## 5 护盾结算

### 5.1 动能盾

动能盾当前使用固定法向能量预算，先碎裂，再按实际支付预算制动／反推，保留切向运动；不随来弹能量自动购买完整制动费用。唯一规则与公式见[护盾基线](护盾机制基线.md#动能模式碎裂与能量脉冲)，此处不保留已被取代的“先全额抵消，再额外反推”收费草案。

按武器定位验收碎裂克制与盾反：高出力盾可能使速射轻弹反伤加重；低出力盾也应使重炮穿甲明显失效；轨道长杆应偏转断裂为低穿甲破片。较重、较快的弹不易被反推，不等于能有效穿过动能盾。各弹体仍走统一求交和后效链。

### 5.2 电磁盾与守卫盾

电磁盾沿用 `SpaceShieldRefraction` 的几何规则：入射角、盾设置决定出射方向；足额付费时，增加激光能量只增加电费，不减小既定偏折角。主动偏折费用按实际追加角度与本束能量结算；被动折射仍沿用现有免费脉冲规则，不因功率滑条另加收费分支。欠费继续按实际付费取得有限效果并触发既有失效机制。

低角偏折可能命中大船其他部位，高强度可把光束导离舰体或返回来向。路径、碰撞、预览与实际电费共用同一次计算。不能为了表现“完全防御”而删除折射后的光束。

守卫盾保留独立的盾容与恢复机制，但实弹削盾、余量续穿要读取新的共同弹体事实，不再叠加已经被质量模型取代的旧倍率。导弹、侵入 shuttle 的穿盾分工不在本轮重设计。

## 6 接线与状态归属

| 当前入口 | 本轮改造职责 |
| --- | --- |
| `SpaceWeaponComponents.cs` 的弹仓能力 | 独立装药／弹头来源、整数需求、材质选择与完整预留；复用优先级和挂件连接 |
| `CompSpaceWeapon` 及正交能力 Comp | 保存调校参数、热量、过热锁和射击间隔；沿现有能力接口门禁和提交 |
| `SpaceWeaponModel`、`SpaceWeaponBallistics` | 唯一实时参数读取；预瞄、火控、状态显示共用当前材质、质量和速度 |
| `SpaceWeaponShot` | Prepare 冻结本发参数、两类库存、电费及热负担；Launch 成功后 Commit 一次 |
| `SpaceProjectileLaunchSpec`、`SpaceProjectileService` | 携带本发质量／能量／形态，生成及回收破片时完整赋值，复用对象不得残留上一发参数 |
| `SpaceImpactEffects`、联合效果 Def | 公共毁伤与贯穿计算；替换速射／重炮家族后效，使用唯一续穿链 |
| `SpaceShieldProjectileBehavior`、`CompSpaceShield` | 质量与速度参与能量预算、付费、碎裂和反推；电磁费用读取本束能量 |
| `CombatWeaponThreat`、`CombatStrategyFacts`、火控调用者 | 读取真实调校、备弹、冷却／热锁状态；不继续使用旧 Def 常数估算当前武器 |
| `Building_SpaceTurretGun`、`Verb_SpaceTurretGround`、`Patch_SpaceWeaponAmmo` | 核对双模式共享库存、热量和射击间隔的接入；避免原版逐发扣费和太空提交重复扣费 |
| `Command_BatchSetting<T>`、Keyed、武器统计 | 每武器 gizmo、多选批量设置、实际参数与缺料／过热原因显示 |
| 炮塔顶部绘制与 `IShellTurretTopSource` | 聚焦／非聚焦读取同一热状态；炮管、炮身分区红热与烟，保留转向和后坐 |

调校与热状态属于武器实例的长期事实，随正常存档、prefab 和地图归档保留；预留、射击事务、预览与渲染缓存不序列化。切地面／太空模式不重置库存、热锁或射击间隔。地面仍经原版 Verb 和命中流程，不能把宇宙穿透链另复制进普通地图。

热量只按游戏 tick 演进，每件武器每 tick 至多更新一次。静态仅放纯计算和可释放的表现缓存；热武器的登记、移除与换档清理由现有实例服务管理，不加逐 tick 全图扫描。首轮生命周期方案采用卸载／归档期间暂停热状态、恢复继续剩余周期，避免离开加载范围获得免费冷却；实施前与现有休眠和冷却计时路径统一，不同时保留绝对到期 tick 与另一份独立倒计时。

修改调校或弹头来源应立即使本武器的弹道和火力摘要失效，但不伪造结构变化。热量平滑变化不要求每 tick 重建船体、布局或完整射位。冷却期间保留机动的名义火力覆盖，实际开火就绪另判，防止重炮每发后自动丢失朝向。

公共计算必须进入预瞄、实际发射、盾作用、命中与必要的 AI 估算调用点；不允许“实际射击读新质量、预瞄仍读固定弹速”。同一发的显示和实际扣费取同一准备结果。

## 7 实施顺序

### 第一步 冻结参数口径与原版接入证据

## 8 验收矩阵

### 离线检查

| 场景 | 必须成立的结果 |
| --- | --- |
| 速射与重炮均发射同材质 1／1 弹 | 在相同碰撞条件下，质量、速度、伤害、穿深、碎裂与盾耗一致；射击间隔允许不同 |
| 不同尺寸炮塔发射相同参数 | 不因尺寸或 Def 身份额外获得伤害倍率 |
| 固定 C 增加 M；固定 M 增加 C | 前者初速下降且在标定工作区穿深上升；后者初速上升；UI 与实弹一致 |
| 改档、切弹仓、铀来源耗尽回退 | 下一发完整重算；已发射弹体及本次冷却不变；缺任一材料不发射 |
| 发射准备后被门禁拒绝／Launch 失败 | 两类库存、蓄电和热量均不消费；成功只提交一次 |
| 相同母弹的破片集合 | 质量与能量分配有界，无复制母弹全质量／整发反推能量；重弹生成更重破片 |
| 同速不同质量、同质量不同速度撞动能盾 | 费用读取实际能量；欠费保留相应向内余速或部分反推，无免费全额反射 |
| 多层盾与同网多炮同 tick | 顺序扣实际可用电；不重复预支，不重复扣贯穿余量 |
| 激光功率变化 | 足额同角偏折，费用随能量增加；低角折射后仍可命中舰体其他部分 |
| 速射完整升温／冷却周期 | 发射次数、热量、锁定时长一致；最高射速不被要求具有最高持续 DPS |
| 重炮 1／1 与高档配置 | 无固定机械下限；每发冷却至零；高负荷排热不被热条截断；改档不改变已产生热量 |
| 暂停、切模式、切图、拆装、归档及存读档 | 无清热、补弹、解除锁定或重复计时；正常保存恢复事实一致 |
| 双方共同平移、旋转接触点及聚焦切换 | 依相同接触相对速度结算；预瞄与真实发射共用当前弹速 |
| 轨道弹击盾及穿空舱 | 仍是少量高成本攻坚射击，无质量和旧倍率重复放大；空舱不消耗预算 |
| 点防、导弹、工程设备与侵入 shuttle | 原有职责、门禁、后效与转移链不被常规炮改造误接管 |

### 用户游戏内验收

1. 两舰分别从射程外和近距开局，记录完整战斗及至少一个持续交火窗口：发射量、两类弹药消耗、补给次数、实际命中、过热停火占比和战损。分开判断“弹药耗尽”“补给断流”“热锁”“已失能”。
2. 相同速射炮的低／中／高射速对照，检查爆发窗口、完全冷却、炮管到炮身的红热顺序、烟和实际可开火时间一致。
3. 重炮高速轻弹、低速重弹、满负荷重弹对照同材质多层舱壁和移动目标；记录命中率、最深损伤层及盾后破片，验证取舍而非只看单发总伤害。
4. 多船同屏检查聚焦与外壳视觉、暂停、读档及战损后的炮塔；红热不能覆盖插件、底座或改变实际炮口和碰撞。
5. 激光不同功率对电磁盾正入射、斜入射和大船边缘照射，检查电量、折线路径及盾欠费后的窗口。
6. 混装轨道炮、重炮、速射、激光验证供电／备弹竞争和持续交战节奏。记录正常与加速游戏下 TPS／帧耗时，避免用增加破片数或每 tick 全图扫描换取表现。

游戏启动、运行时 Harmony 验证和上述实测由用户执行。计划完成不代表代码已改、构建通过或玩法已验收。
