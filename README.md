太空铀弹的穿深随动能提高而逐渐趋缓。满装中型重炮、5 格和 10 格轨道炮正面命中连续钢铁逆重飞船舱壁时，单发分别可击毁 3、4、6 道。加长轨道炮仍按付费段数提高守卫扣容，破盾后按余下动能计算穿深。详见[单发基线](doc/舰炮与护盾基线.md#ballistics)。

舰体相撞使用外缘扫掠。同一舰体对每 tick 最多毁伤一层，实际相触的多列一起结算。撞开后保留余速，后续真实接触再毁伤内层。详见[舰体接触](doc/太空战架构.md#舰体主动撞击与碰撞规避2026-11-18)。

选中速射炮、重炮或附加弹仓，可用「弹头类型」切换高爆钢弹和穿甲铀弹。换种时退出旧弹头，保留装药。每发按优先级从一座备齐弹头和装药的仓取料。中型速射炮满载可备 150 发，加装一个满载附加仓可备 300 发。轨道炮从内置仓装填铀弹。详见[舰炮与护盾基线](doc/舰炮与护盾基线.md#ballistics)。

轨道炮弹芯现有完整飞行、翻滚和单枚碎片三种外观。舰炮装药、高爆弹头和穿甲弹头各使用专属贴图，落地时按单件、未满堆和满堆切换。见[弹药与补给](doc/舰炮与护盾基线.md#ammunition)和[轨道炮](doc/舰炮与护盾基线.md#railgun)。

教程武器试验场的六门炮塔在矩形平台北侧分成主、副两排，和东端轨道炮一起朝东。主、副两排的速射与重炮都装有附加弹仓。两仓均满载，主组使用高爆钢弹，副组使用穿甲铀弹。中型激光可设为功率 1–6，试验场主、副组分别预设为 3 和 6。舱内从西到东是无盾、动能、电磁、守卫四列终端。保持同一门炮朝正东，动能可选 0°／35%、45°／7%、45°／35%、45°／100%。用两种 35% 档比较入射角，再用 45°／35% 对照重炮钢弹翻滚与铀弹穿深。动能和电磁各有四台对齐的终端。电磁可选 0°／20%、45°／20%、45°／50%、45°／100%。守卫可对照单台与三台协同。联合档用轨道炮只打一台圆盾，可观察三台分摊常规盾容，以及受击盾独自消耗应急盾容。靶舰西侧彩墙便于辨认落点。开发调试页可生成玩家所属的同款试验场和一名玩家殖民者。玩家殖民者可操作己方和获准使用的公共试验场终端。教程回收残骸的 75 钢铁直接放在基架上。见[武器试验场](doc/教程开局实施计划.md#1310-矩形平台与独立武器测试)。

太空撞击和炮击会把原版实际生成的击毁掉落抛成可牵引物品。原版基架与逆重舱壁击毁时没有建材掉落。详见[战损结算](doc/太空战架构.md#combat-leavings)。

非战斗自动武装巡航减少了无敌舰时的战斗快照、推进表现读取时的硬件检查，以及距离检查中重复构造的玩家参考列表。现有选敌、飞控、加载与恢复频率保持；两版开发构建和离线回归通过，用户已确认本轮优化可提交。测试条件、收益与专项验收边界见[轮询审计](doc/轮询审计.md#非战斗巡航前三项优化2026-11-18)。

推进器详情页新增「Delta-V → 基础推力」，保留零值和负值。护盾设置提供各自的用途说明，长度与投射距离显示维持用电，反推／激光偏转强度显示随设置变化的单次拦截耗电示例；实际费用取决于来弹条件。见[基础驾驶](doc/阶段2-基础驾驶.md)与[护盾能源说明](doc/舰炮与护盾基线.md#维持功率与逐发能源)。

小型推进器基础推力现为 800，大型为 2000。第三方推进器可在 Def 中显式配置推力，负值表示反向出力；未配置时按航程加成分段换算。玩家出力上限和实际油门继续生效，配置契约见[基础驾驶](doc/阶段2-基础驾驶.md)。已有船只使用小推进器的方向会相应减弱，布局不自动调整。

带 Odyssey 原版驾驶组件或其子类的建筑自动接入 Delta-V，可认领船体、切换主备并从侧栏驾驶。Vanilla Gravship Expanded 的驾驶舱和舰桥符合条件，副驾驶台继续用于协助驾驶。自定义驾驶台也可显式接入。两版游戏内联测待验收，详见[驾驶台与认领](doc/飞船与SpaceObject解耦架构.md#3-驾驶台船体与主备用认领)。

战斗性能实验分支用武器距离输出表和方向防护表初筛射位，并用共用弹道规则复核入围射位的毁伤。自动朝向优先保留有射击收益的姿态，换位和规避通过平移与路线调整。获选固定直射炮和火控共用同一次弹道提前量，舰体跟踪该提前点。双表初筛采用固定时间窗的近似值，发射和命中仍由武器系统结算。实验条件见[双表射位评分实验](doc/有利射位与交战收益规划.md#双表射位评分实验)。

载人武器使用原版炮手操作链。没有有效自瞄时显示交互点并保留原版建造保护；有效自瞄时隐藏成品交互点、解除保护且不自动征用新炮手，仍可右键操作，堵格后不可下达操作命令。已有岗位可继续执行。2026-10-14 已删除独立炮手状态和操作 Job；显示、四向建造、补位、三种取消方式及存读档待游戏内回归。

采矿每次出料实际放置失败时，都会通过原版左上角消息提示损失，覆盖矿物和拆除材料，无提示冷却或额外容量扫描。电缆不再作为保护基架的碰撞建筑，修复隐藏电缆使基架无法切除的问题；同格墙体等实体建筑仍保护基架。产物放置和电缆修复已通过用户游戏内验证；损失提示按用户反馈改为每次失败立即提示。

月池自带透光的密封力场顶，按室内屋顶维持气压、温度和天气防护，仍接受日照。殖民者不会在月池上自动盖顶，也不能建造或拆除力场顶；已经盖出的普通屋顶保留且遮光，可手动拆除。原版和 Delta-V 穿梭机可穿过月池起降，整艘逆重飞船不能借月池落地。已修正月池名称和说明的简中翻译，并补上「月池力场顶」名称。该机制和简中显示待游戏内验收。

## 构建

```powershell
just build       # 默认 1.7
just build 1.6   # 1.6
just release     # 同时构建并打包 1.6 与 1.7 正式版
just alpha-release # 同时构建并打包 1.6 与 1.7 Alpha 版
```

Windows 构建和发布入口使用系统自带的 `powershell.exe`，无需安装 PowerShell 7；构建与发布脚本仅在各自进程中使用 `-ExecutionPolicy Bypass`，不修改系统设置。

开发目录以 `RimExodus: Delta-V (Dev)` 和 `RimExodus.DeltaV.dev` 加载，依赖 `RimExodus.Framework.dev`。`just release` 分别尝试构建 1.6 和 1.7；缺少某版构建环境时复用不早于源码及 REF DLL 的已有产物，过时则警告并中止。成功后两版一起打包到同级 `RimExodus_Delta-V.release`，去掉名称的 `(Dev)` 并把自身 ID、REF 依赖和加载顺序转换为正式版；正式包通过 `LoadFolders.xml` 为两个游戏版本分别加载对应目录，需要启用 REF 正式包。重复运行会替换发布目录，包内不含源码、文档或编译引用。默认游戏目录为 `RimWorld_1.6`（1.6）和 `RimWorld`（1.7），可通过 `RimWorld16Dir`、`RimWorld17Dir` 或 `RimWorldDir` 覆盖。

`just alpha-release` 使用同一构建流程，生成同级 `RimExodus_Delta-V.alpha.release`，名称为 `RimExodus: Delta-V [ALPHA]`，包 ID 为 `RimExodus.DeltaV.alpha`。Alpha 依赖正式版 `RimExodus.Framework`，发布前须更新工坊上的 REF，使其包含本次构建所使用的接口。首次在游戏内上传后，重新打包会保留 Alpha 目录的 `About/PublishedFileId.txt`。

Delta-V 现在依赖同级独立 Mod [RimExodus Framework 1.0.0](../RimExodusFramework/README.md)，不再提供实验开关或旧地图后端。请启用与开发版／正式版对应的 REF，加载顺序为 Harmony → REF → Delta-V。

`just build` 先执行 REF 的 `just build`，成功后拉取 `RimExodus.Maps.dll` 到 `References/REF/<版本>/`，最后生成 `<版本>/Assemblies/DeltaV.dll`。引用 DLL 不复制到 Delta-V 的运行时 Assemblies，避免与 REF 重复加载。直接执行 `dotnet build Source/DeltaV.csproj` 前须先通过 just 准备对应版本的 REF 引用。

1.7 需要 SDK 10；可设置 `DOTNET_EXE` 指定 SDK，也可使用本项目已有 `.local-tools/dotnet/dotnet.exe`。1.6 使用 net48 编译期 NuGet 引用。游戏和 Harmony 路径见 `build/RimWorldReferences.props`。公共接口、已迁入范围和未完成项见 [REF 地图模块](../RimExodusFramework/doc/地图模块.md)。

1.7 生成图门禁兼容修正和实时上层矩阵修正已经通过离线回归；用户已确认非聚焦船壳上的护盾与导弹架上层正常。2026-10-31 用户确认 REF 修复 Surveillance Shift 强制开启地图边缘裁剪造成的图外黑屏与船壳遮挡后，当前迁移版本可提交；兼容补丁由 REF 提供，Delta-V 不重复安装。其他存读档与生命周期验收仍按各专题清单执行。

## 测试

1. 启用开发者模式（选项 → 开发者模式）。
2. 进入 **Odyssey 开局**的游戏（需要轨道层）并处于地图视图中。
3. 打开调试面板（Dev quick commands → Debug actions，或 `~` 菜单），找到 **Delta-V** 分类。
4. **Create two-ship test scene**：生成玩家飞船图与敌舰图（按实际内容边界、每侧预留 12 格），自动聚焦玩家船；口袋图均不占轨道 tile（sourceMap 统一挂专用宿主口袋图）。在 **Mod 设置 → 开发调试 → 双船测试场景**通过目录树分别选择两船 prefab，并设置敌舰相对玩家船中心的距离、方位及两船初始角度；方位以玩家所在球面切空间东向为 0°、北向为 90°，不随玩家船首朝向变化。默认距离 65 格、方位约 22.62°（原偏移 60 格东／25 格北），两船初始角度为 0°／35°。列表包含用户与内置 prefab 的子目录，每次打开重新扫描；配置跨存档保存、下次创建生效。两船默认均为「自动选择」。玩家船使用 RimWorld 用户数据 `DeltaV/Prefabs/` 下最新导出，加载失败回退程序船；敌舰使用标配舰炮和船员的 `Sector/Craft/SectorFrigate.xml`。新实例化的 NPC 舰船使用自动火控并启用主、副各六组武器，敌对目标进入战术范围后由 NPC 控制器自动机动。复测时选择锤头鲨为玩家船，敌舰可选巡洋舰或使用自动选择的护卫舰。创建后解除暂停，观察敌舰锁定、机动和开火。敌舰的默认 prefab 或手动指定的文件若失效，在清理旧场景前报错并中止。
5. 其余菜单项：**Prefab: export home area as timestamped file**（把当前聚焦图居住区导出为通用地图 prefab）、按键抑制/MPC/坐标自测、**Dump universe state**、弹体池状态、聚焦图诊断与网格重建；生命周期回归保留强制归档最近容器、主船传送 1500 格及在玩家星区调用正常生成入口。调试菜单不再提供手动改敌舰位姿/派系、强制完成对接或绕过武器服务发射弹体的动作。

6. **Dump SpaceObject at position**：在 Delta-V 分类启用后，左键点聚焦图内容、飞船外壳或漂浮物，在原版开发日志中查看 `[DeltaV:Diag]` 条目。右键退出工具。

双船测试场景重复创建时会先加载本次 prefab，再暂停，完成旧弹体与排队清理、销毁旧地图，生成新场景并交接镜头；完成后仍保持暂停。连续点击不会叠加重建。交火／侵入中及增量生成期间重建的游戏内验收见 [TODO](doc/TODO.md)，清理契约见 [太空战架构 §4.5](doc/太空战架构.md)。

在「Mod 设置 → 开发调试 → 双船测试场景」开启「保留 Prefab 标记」，下次生成时两船的人员、精确对象和批量对象标记会留在地图上，跳过标记展开。可在 God 模式编辑，再通过居住区导出命令保存。开关默认关闭，跨存档共享。见 [Prefab 状态重建](doc/Prefab状态重建.md)。

- **原地替换调试图**：Dev → Delta-V → **Prefab: replace focused map...**，从统一 prefab 列表（含子目录）选择文件，再选择派系。派系列表首项默认沿用当前地图派系（优先容器／地图派系，纯飞船图从面板所选船取得；没有则保持无派系），也可指定游戏内其他派系或无派系；取消选择不改地图。确定后游戏暂停，在当前聚焦宇宙地图的位置生成新口袋图，沿用原容器的位置、角度、线速度与角速度。新图按实际 prefab 内容边界、每侧 12 格生成并居中放置，完成后交接镜头并删除旧图及其内容（原生轨道图还会移除旧世界对象）。加载或放置失败保留旧图；地表图、弹体图以及正在生成／起飞／对接的状态不可使用。地图替换与派系选择的基本流程已于 2026-10-16 经用户游戏内验证通过。
- **导出**：开发者菜单的居住区导出命令按当前地图的 Home Area 保存模板。导出飞船前，取消选中船外空白真空格，并选中露天甲板和外置设备的完整占地。导出成功时可从原版调试日志复制完整文件路径，无需开启 Delta-V 日志选项。模板可重复实例化，派系由导入时指定。地形沿用原版 `PrefabUtility`，建筑与物品逐实例保存原版存档数据，包含电池、燃料、装填、插件及容器状态。基架与屋顶另存侧车。地图上的实体只收录锚点在选区内的建筑和物品。见[导出与环境采样](doc/Prefab状态重建.md)。
- **重建**：`MapPrefab.Spawn` 以指定派系整片放回任意地图——顺序为基架（含结构归属认领）→ 原版地形 → 整批读取建筑与物品状态、重分配身份并落位 → 屋顶 → 设施重链 → **标记建筑展开**。「Prefab 标记」标签中的 `Delta-V 预制图角色标记` 有独立的蓝色人形菱形图标，便于与其他模组的标记区分：每个标记优先在原格生成一名目标派系成员，原格不可站立时找附近格；派系没有基础成员时从原版派系生成池选人，再无可用种类时回退到殖民者。人形船员在入图前穿真空服和头盔；成功生成后标记消失。可在 Def 的 `CompProperties_PrefabPawnSpawner.pawnKind` 指定其他 PawnKind。精确／批量 SpaceObject 标记同样经 `CompPrefabMarker` 接入，配置与防递归规则见专题文档。标记仅在 prefab 首次重建时展开；普通存读档和远距离归档后的快照恢复不会重复生成。文件读入走原版 XML 管线（含 Def 交叉引用运行时解析），**导出后无需重启**即可用。
- **星区生成池（2026-09-30；2026-11-09 补齐内容）**：导出的 prefab 可注册为**星区内容类型的物化生成池**——在 Mod 设置「生成」页按飞行器或空间站的叶子类型勾选统一 prefab 列表（含子目录）里的文件即可。五档舰船及七类空间内容各有一份随 Mod 提供的默认 prefab；新建或缺失的规则自动带入对应文件，已有自定义规则不覆盖。该类型的 POI 首次物化时按各自 seed 从池中确定性选取一份整片放置（旋转亦由 seed 派生）。**物化内容链是 prefab-only**：池为空的类型在星区生成期即报错跳过（不生成该类型对象）；配置了路径但文件失效时该 POI 在物化期报错取消（不回退程序生成——程序布局仅存于双船测试场景）。残骸由地图内容动态判定，不占专门生成类型。工作流：调试动作导出 → 在用户数据 `DeltaV/Prefabs/` 下手动移动／重命名或建立子目录 → 设置页重新扫描并勾选。
- 该系统是通用的（飞船/空间站/地面基地/小行星皆可），不限于居住区；`<prefab>` 地形节点保持原版 `PrefabDef` XML 形状，逐实例建筑状态位于 `<thingStates>`。保真度边界见「已知限制」。
- 双船测试的默认选择与失败处理见上节。基架写入或建筑落位失败会记录完整错误并销毁本次测试图。
- 储物建筑的筛选与优先级按导出时实际生效的设置复制；旧地图的储存组关系不复制。导弹仓按内部库存重建；旧 prefab 中位于仓体脚印内的实体导弹在导入时装入该库存。
- 重复生成同一 prefab 时，炮塔内部枪械及其射击动作也获得独立身份，修复保存后重载出现重复 ID 的问题。已有错误测试图需重建；该修复已于 2026-10-18 经用户游戏内存读档验证通过。

### EVA 工程套装

新增 1×1 单人 EVA：装入一名健康驾驶员和最多 60 kg 货物，可从太空露天甲板或月池起飞。WASD 跟随实际摄像机方向，保留飞行辅助与刹车；Q/E 不转向，手动火控下套装随指示点四向转身，工具仍精确指向目标。不能世界地图发射或侵入撞击。

太空图中通过原版运输舱页面卸出物品或乘员时，落点在地图外就抛入太空，成为可牵引回收的漂浮对象。抛出人类或其他类人乘员前会显示确认框。物品可选择整堆或指定数量，图内落点照常卸出。

EVA 使用专属黄灰工程外骨骼贴图，单人驾驶舱配合不对称夹爪和工程工具，随瞄准四向转身。推进器采用四角 X 型布局，向外斜喷；前后左右由两台合力，保持原有轴向推力，对角方向受单台斜推能力限制。新贴图的游戏内显示待复核。

- 主组 1 切割器射程 6 格，可切割己方结构。结构按正常拆除量全额返料。拆除材料与采出的矿物从命中点飞入太空，可用牵引束回收。
- 副组 1 焊枪：3 格、每 10 tick 修复 10 HP；命中基架时清理污渍，遵循正常遮挡和随机命中。
- 副组 2 牵引束：8 格，手动回收散落物到货舱；容量不足时仅接收能装下的部分。

火控统一为自动／手动／停火；EVA 默认预选手动，仅支持手动／停火。停火停止全部武器与持续工具，但保持武装、供电意图与武器组；解除武装才是总关闭。EVA 保留战斗面板与工具分组，没有炮手岗位操作。当前仍使用初始数值；机制、双版本编译与离线回归已接入，完整游戏内新档验收待完成。详细契约见[太空战架构 §7.7](doc/太空战架构.md#77-eva-工程载具与共用挂载2026-11-04)。

- 聚焦 Delta-V 图（飞船口袋图/真实轨道图）时可**缩放到设置上限并自由移动镜头中心**：远处敌舰/POI 的外壳代理画在世界空间，zoom out 或移镜头可以看见（方位即真实相对方位）。地图外的背景色调遮罩随镜头视野扩展；远离当前选中结构时侧边栏出现“重新聚焦”，可返回该结构。无驾驶台结构和残骸也显示速度、航向与角速度，默认以地图北侧为朝向。普通地图保留原版镜头移动边界；切回普通地图恢复原先缩放上限。兼容 Simple Camera Setting 的最大缩放设置，在宇宙图修改 SCS 上限后，离图使用新设置值。
- 原版逆重飞船的起飞／降落镜头沿用当前地图的缩放上限：地表图使用地表或 Simple Camera Setting 的上限，Delta-V 太空图允许大视野。过场另行设置的专用缩放范围仍由原版处理。
- 所有 SpaceObject 的非聚焦代理共用同一套**结构外观**标准：有实体屋顶的基架格沿用当前基架／地板贴图、舱壁和太阳方向明暗组成船壳；无顶格显示实际甲板和其上的建筑，包括家具、驾驶台、引擎、炮塔底座、插件及轨道装弹机。多格建筑跨越破口时，保留的屋顶逐格遮住其下部分。月池透光力场顶按开放甲板显示，另盖普通屋顶后仍遮住内部。舱壁连接和补角以有顶基架及实际舱壁为准，不再把无顶甲板填成封闭外壳；无墙支撑的屋顶边缘显示程序生成的伸出钢梁、断面和弯折线缆，造型在重建与存读档间稳定。炮塔旋转炮身、护盾投射器与显式外置部件仍露在船壳之上；物品、Pawn、雾、电器接线和原版太阳阴影不显示。推进器火焰继续读取真实油门。多个船壳仍按对象 ID 整壳分层，全部位于聚焦地图内容之下。2026-11-01 用户确认屋顶分层与战损机制正常；月池普通屋顶误取未生成材质的问题已修复、待复测，密集战损性能仍待专项验收；实现与参数见[太空战架构](doc/太空战架构.md#屋顶与战损船壳)。
- 非聚焦船壳的舱壁内外圆角朝同一方向鼓起，随太阳方向呈现明暗。圆角填充沿用相邻墙材质，双层舱壁的四墙交点也会补齐。规则见[屋顶与战损船壳](doc/太空战架构.md#屋顶与战损船壳)。
- 非聚焦船壳的逆重舱壁斜边会随太阳方向呈现高光和阴影，光带沿斜边接到相邻墙面。见[屋顶与战损船壳](doc/太空战架构.md#屋顶与战损船壳)。
- 非聚焦船壳的墙边高光、阴影和甲板接缝覆盖普通墙、关闭的门及通风口和冷气机等嵌墙建筑。打开门时，墙面光带在门洞处断开。见[屋顶与战损船壳](doc/太空战架构.md#屋顶与战损船壳)。
- 聚焦地图和非聚焦船壳都显示建筑本体的原版伤痕。屋顶上可见的炮塔头和护盾投射头用自身贴图的透明通道裁切伤痕，划痕可以分布在整个可见部件上。推进器和月池力场顶下的设备也会显示伤痕。修复会更新伤痕，实体屋顶会遮住下方设备及其伤痕。见[屋顶与战损船壳](doc/太空战架构.md#屋顶与战损船壳)。
- 星球/星空背景随飞船 universe 位置**连续**移动，并随当前参考系**反向旋转**；聚焦飞船图与停靠图背景同源同步，切换聚焦无跳变。
- 星球视图切到轨道层时，所有玩家飞船（含 shuttle）按连续 universe 位置显示**船体剪影标记**，点击可聚焦切图。世界标记和左侧星球仪共用船体脚印与位姿：基架船读取控制域，shuttle 读取艇体脚印；同图多船各有标记，身份、换图与结构变化按共同缓存规则处理。
- 宇宙坐标为**球面绝对坐标**（轨道层球面）：位置即球面方向，sphere↔tile 互推为纯函数（按 `PlanetLayer` 参数化，tile 划分与尺度常量无关），长途航行绕星球一周回到原点，无坐标漂移，也不需要任何平移记账。一个星区（worldtile）的弧长由**星区尺度设置**定义（默认 20000 格），连续驾驶跨一个星区需分钟级；tile 只是 coarse address 与生成记账维度，碰撞、降落选点等战术判定一律在连续轨道坐标中完成。
- 地图点到轨道位置及其逆向统一使用该图所属 `SpaceObject` 位姿；原生轨道图与口袋图同一规则。对接选点保留原版整数格语义：计划固定最终放置 root，完成前复核将它转换成原版设计器输入格，因此偶数尺寸船体不会误检相邻脚印。

### POI（阶段3 + 星区模型）

- 所有轨道层、可持有地图的 `MapParent`（含 Mod 子类）会自动注册为 POI，**包括原版空白 Space 画布站与容纳对接船的宿主图**——「每个可进入地图都属于一个 SpaceObject」。Delta-V 飞船/宿主、玩家船容器和宇宙宿主口袋图除外。自建 POI marker 由 `SectorContentService` 根据生成设置创建，prefab 池只用于其首次物化。
- **星区内容生成记账**：首次进入星区（移动跨界 / 逆重战略到达 / 开局出生星区）按**类型树**（§11：飞行器五级、空间站六类等）生成 Delta-V 自建对象——每个叶子独立「保底数 + 分段概率额外量」，在 Mod 设置「生成」页配置（各叶子默认 0），POI 首次物化用该叶子的 **prefab 生成池**（prefab-only：池空的类型报错且不生成，见「通用地图 prefab」节）。**POI 的名称与派系在生成时一次性随机决定**（名称走自制 RulePack：`词干 + 类型名 + (派系名) + #ID`，如「苦痛之护卫舰(堕落帝国) #123」；派系从可见、未灭亡且达到工业时代及以上的非玩家派系中随机——敌方贸易站可劫、友方战机只是路过），物化时直接应用于容器、prefab 建筑与 pawn、结构归属名；整图归档→恢复时名称与派系完整传承。物化后带驾驶台的敌舰/空间站自动认领归属成船（可交战、可被索敌），无驾驶台且有基架的地图按内容呈现为残骸。「已触发生成」持久化防重复刷对象，当前对象清单由坐标查询重建、不序列化。原版 orbit 站点本就按 tile 生成，不受影响。
- 接近（≤ 加载/唤醒距离）按距离排队并在帧预算内生成地图；同一时间只有一个生成任务占用 `MapGenerator` 静态状态。未知 GenStep 暂按原子步骤运行，超预算会报告具体步骤。
- 离开加载距离后，地图保留但同时停止 Map 更新和全局 Thing tick；返回时只恢复一次。超过删除距离后，原生 POI 延迟采用其 `ShouldRemoveMapNow`、`alsoRemoveWorldObject` 与强制删除标记；任务主动销毁仍立即生效。
- **POI 容器与物化容器分离（2026-09-25）**：未物化 POI 是无图触发器（marker，按类型显示图标/名称）；接近后物化为**普通容器**——没有 POI 图标身份，名称 = 图上结构拼接（纯环境用环境名兜底），星象仪按船成员、环境地形及实际面积显示图标或投影（见上文星象仪规则）。物化容器生命周期按图内容判定：有承载结构且受玩家保护的地图保持活跃；小行星和零碎残骸超删除距离后直接消失。其他普通口袋容器可整图归档，追近时原样恢复。若有原版排队事件、进行中的任务目标或全局异常石柱仍指向该图，归档暂缓至引用消失。见[星区生命周期](doc/星区架构.md#4-spaceobject-与物化materialization)。

### 驾驶台、认领与模式转换（解耦架构，2026-09-24）

基架上铺设地板或被临时地形覆盖后，仍按实际基架参与归属、连通、质量、剪影与碰撞。POI 接近加载和跨星区生成统一跟随玩家船所在的宇宙对象，单独飞行或侵入中的 shuttle 也能探索；同图多船只计一个参考点，混合派系时只要仍有玩家船成员便有效。这两项修正已接入，游戏内验收见 [TODO](doc/TODO.md)。

敌舰 AI 对基架船与 shuttle 使用同一套战斗机制，但策略由各船当前主驾驶台或 shuttle 艇体独立保存（细项待游戏内验收）：机动和逐武器火控分别按有序条件规则选择偏好；新 Comp 默认使用内置通用策略，备用台接班后使用自己的配置。机动复用真实推进器自动驾驶，武器复用现有开火事务，跳帮 shuttle 复用起飞和侵入链。战损后撤向已生成的同派系最近船厂；没有可用船厂时继续避战，跨星区或到达临时航点均不会删除舰船。玩家追到船厂时，受损舰保持原状，在船厂外侧守位还击，不追远或跳帮。远距普通口袋容器仍按统一距离规则休眠、归档和恢复，整张 Map 压缩进存档并从运行图表卸载；撤退航程由共用自动驾驶按游戏 tick 推进，无图时使用卸载前逐台记录的数值推进器布局，经同一分配器限制出力；不模拟图内燃料和电力消耗。中途追上会恢复原地图、战损与船员，舰船 AI 根据当前损毁重新决定是否继续返厂。只有归档舰船抵达船厂、且玩家未追入加载范围时，才抽象为维修／拆解后重新部署并退场，存活船员交给原版 World Pawns，满足原版条件时可能出现在以后的舰船中；不强制治疗、永久保留或立即刷新替代舰。归档与恢复异常会记错误并保留可恢复数据；返厂防守、人员交接与存读档仍待游戏内验收，机制见 [太空战架构 §9.1](doc/太空战架构.md#91-远距整图归档与撤退)。

- **普通基架船 = 主驾驶台 + 同归属四连通基架**（控制域）。SpaceObject 只是「一张内部地图 + 轨道运动」的容器——同图可承载多艘船与无主台残骸归属；容器名 = 图上全部结构名拼接（UTF-8 顺序）。**主/备用认领**：无主归属上新建驾驶台自动认领成主台（形成飞船，新主台朝向定义船头）；已有主台的归属上新建默认备用；仅玩家派系驾驶台显示主备切换 gizmo；「设为主驾驶台」显式换主（原主台降备）、「设为备用驾驶台」主动放弃认领（不自动选回）；主台被摧毁由同方向备用台按稳定 ID 继任，无同向则成残骸（可手动认领恢复）。主驾驶台提供**改名**（归属名 = 船名，同步本船全部引擎名；原版引擎改名也同步回船名）。「修改基架归属」保护有主台的整个来源归属（包括断连基架），引擎损坏或断电不解锁；必须主动降副台，或摧毁主台且没有副台继任。敌方驾驶台沿用原版占领条件，玩家自建副台不能替换非玩家主台；无主台残骸可划入已有飞船。
- **无主台状态**：允许主动取消最后一座主台；该归属不再形成有效基架船，驾驶和自动驾驶结束，地图与结构保留。已加载地图中载有玩家建筑的无主台基架归属会显示持续的「基架结构缺少主驾驶台」警告（shuttle 本体除外）。侧边栏允许继续选择无主台结构，显示宇宙视图和设置主台提示，不提供自动认领的驾驶按钮；其他有效船不受影响。副台随基架改划同步身份，显式设为主台后按当前脚下归属恢复船舶操作，警告自动消失；存读档保留副台状态。
- **基架建造**：太空图上**允许在引擎覆盖范围外铺设基架**（在船旁建新船：铺基架 → 改新归属 → 建驾驶台成船；天然岩顶仍禁止）；地表保留原版范围限制。邻接单一归属则继承并吸收相连未占有域；孤立/多归属邻接一律保持**未占有**（多归属不再拒建，交由玩家划分）。降落脚印与**任何归属**的既有基架**重叠**一律禁止（自己 ID 的遗留也不例外）；异主基架**四邻接合法**。
- **地图关系的派生判定**：`ShipRegistry.StateOf` 只读取当前地图结构，不保存船级停靠状态。普通飞行图只有一艘独立有效船且整图无天然地面时派生为 `FreeFlight`；同图有其他独立船、整图包含天然地面或处于共同作业图（包括单船扩建）时派生为 `Docked`。地表图还受重力门禁限制。无主台残骸不算第二艘船。对接将控制域放入目标图，实际推进器出力经统一门禁拆分或提取到新容器；无人出力时共享原容器继续漂移。
- **速度同步与硬对接**：侧栏使用同一个“开始舱外作业”按钮。没有同步任务时，单船作业图每侧增加设置中的格数。有同步任务时，等同步稳定后点击，按当前位置取最近格，整船能合法落位则停入同步目标图。带“重力区”标签的目标在发起同步时就会提示须整船停靠，落位失败则保留原图。其他可搬迁目标在无法停靠时可与本船共同进入新作业图。见[对接与舱外作业设计](doc/对接与舱外作业重构设计.md#6-开始舱外作业的分流)。
- **脱离（对接 → 拆图）= 出力即分离**（2026-09-24 统一定案：「脱离停靠」不再是独立命令）：与其他船同图或停在天然地面上的船进入驾驶后首次推进器出力即分离（**不要求逆重引擎**，至少一台可用推进器）。干净脱离（无断片、无通道滞留）立即执行；有断连残片（留在宿主）或对接通道上滞留人员/物品时弹**汇总确认**（游戏暂停）；取消 = 撤销自动驾驶任务 + 退出驾驶并提示，重新进入驾驶再推进即可重试。通道收回只影响本次分离相关通道，通道内容物原格留在宿主图。执行 = 控制域整体搬入新口袋容器（新容器位姿/速度 = 宿主刚体上船体锚点的位姿，含自旋切向继承）；分离后聚焦跟随侧边栏当前选中结构：有主台跟随主台侧，无主台跟随较大侧，同大优先留在原图；相机视点按宇宙参考系连续换算，其他船离港不会带走镜头。源图按承载结构规则回收，worldtile 图保持既有生命周期。
- **断连拆分（出力前公共检查，与脱离同一门禁）**：仅「将要产生推进器出力」的行为触发（手操、主动刹车辅助、自动驾驶）。有断连块（同归属断片或异主结构）或散落内容时，默认暂停并弹出汇总确认窗。确认后各断片独立成新残骸容器（「残骸 #N」，速度/位置连续继承，断片上的备用台不自动升级），取消则退出驾驶（重新进入+推进可重试）。搬运方向按上述地图关系判定；普通飞行图中的无承载人员／物品先交给散落服务，即使没有断片也须交接成功后才能出力。污渍不触发整船提取，毁伤与搬运收尾清除非法残留。被动阻力与纯漂移不拆船；切入驾驶/零出力不触发。NPC 走同一分离算法、不弹玩家确认（玩家/NPC controller 为同基类双子类）。
- **出力分离提示**默认开启，统一控制断连拆分和脱离停靠的确认框。点「确定并关闭之后的提示」确认本次分离并关闭后续弹窗。可在右下角重新开启，状态随存档保存。关闭期间自动分离，基架船断连拆分仍会在左上角显示消息。见[分离确认](doc/飞船与SpaceObject解耦架构.md#82-确认窗已定与方案建议)。
- **无承载地图回收**：毁伤失去基架的人员／物品，以及最后一艘船离开工作图后遗留的无承载内容，经事件触发转为各自的 1×1 散落图。残余基架块复用拆分链成为残骸；空图清理或归池不删除尚未交接的人员／物品。
- **控制状态**：手动模式高亮「正在手动驾驶」，再次点击可切回自动。自动模式高亮「自动任务」，点击「切换手动驾驶」可接管。自动任务及暂停状态由玩家 controller 在运行时持有，读档恢复为“自动任务：无”。火控独立；NPC 仍由其 controller 决策。
- **跳帮侵入制导**：尽早撞击敌舰，接触速度自由。直线对准时持续推进；偏离航线时修正横向误差。近距高速截击已通过离线回归，游戏内撞击待复测。见 [在线 MPC 自动驾驶](doc/在线MPC自动驾驶.md#侵入截击2026-10-24)。
- **自动驾驶制动**：MPC 预测与执行统一正反推力单位，按非均匀时间步计算出力成本，通过停止约束和逐 tick 阻力预测规划提前制动。静止目标对接修复已获用户验收；算法与离线回归见 [在线 MPC 自动驾驶](doc/在线MPC自动驾驶.md)。
- **被动阻力**（默认开）：线速度半衰期 8s、角速度半衰期 3s（设置可调），与飞行辅助并存；不是推进器指令（不耗油、无火焰、不拆船），自动驾驶 MPC 预测同口径（刹停/航点/跟随/站位保持一致）。
- **逆重战略发射**（仍要求引擎，捕获 = 引擎覆盖范围内的本归属结构——口袋图整域绕过的旧例外已退役）：口袋图发射以所在星区 tile 为战略源地址；发射后走**星区离场标准流程**（飞船自有口袋容器销毁、星区 worldtile 图按逆重锚决定去留、其余 POI 图休眠收纳）。战术对接/脱离全程不启动引擎冷却。
- **软对接与对接口**：打开右下角软对接开关，所有对接口显示双线菱形指示器。在侧栏选「自动任务 → 软对接」，再选择已加载的目标。系统按接口间距离选定最近的一对空闲接口，并使用推进器接近和保持对齐。手飞也可对齐菱形并建立连接。接近或远离指示器只影响配对与通道，当前自动任务由玩家选择。完成后，可在接口选择“组织转移”，批量指定人员和货物数量；也可选中人员右键本船接口通行、指定搬运物品／倒地人员，或在对方门不可通行时骇入。骇入使用 Odyssey 防爆门同等的 1800 工作量和原版骇入速度；完成后自动占领对方接口，敌人可按原版敌对建筑行为攻击它。偏离会收回通道并断连；关闭开关立即断连并停算。软对接开关随游戏存档保留：开启状态读档后仍开启，原配对再次满足捕获条件时从端口保存的伸展进度和接通状态继续；驾驶任务重建为自动自由漂移，恢复的旧配对仅恢复连接。主动关闭开关会清零。软对接不生成通道建筑；同图硬对接继续使用原有气密通道。shuttle 不支持软对接。敌舰船员优先接管可用舰炮。未上岗的船员会主动索敌并迎击登舰者，有空缺时可从索敌队伍调回炮位。见[敌舰船员防卫](doc/太空战架构.md#9-npc-与-dev-验证)。原版通用离图任务不再自动选择软对接入口，避免两图往返；此修正待游戏内验证。
- **Shuttle / 跳帮**：原版 shuttle 装货与发射门禁 → 起飞成为可驾驶 MiniShip（XML 可自定义逐台虚拟推进器；玩家方起飞后**自动进入驾驶状态**，无需再点驾驶按钮）→ 普通停靠把舱体视为单建筑控制域，复用漂移同步、主动开始作业和 `CaptureDomain → StripDomain → PlaceIntoMap`；跳帮艇在开启碰撞规避时，「撞击侵入」灰显并提示「关闭碰撞规避后启用」。起飞并关闭规避后，直接点「撞击侵入」选择目标，按真实推进器与截击 MPC 加速追踪、撞穿并以舱体堵孔；跳帮艇下调了空载与加力时的机动强度。加力由独立化燃油箱供给，耗尽后按常规动力追击，补油达到「加力重启阈值」后可再次加力。选中艇体可查看油量并调整阈值。斜撞时落位会一并破拆与艇身脚印冲突的建筑。跳帮艇可穿过全部护盾；参数见 [太空战架构 §7.5](doc/太空战架构.md#75-侵入式对接真实推进器截击与共同碰撞)。飞行期可正常存档；侵入/对接任务读档丢弃，shuttle 按已存速度漂移。停靠时可通过艇体 Gizmo 起飞；驾驶、对接与指定侵入目标在左侧面板操作。
- **牵引光束**：只能建在月池上，需要供电和蓄电，默认编入**副4**。用模式按钮切换“当前模式：收集物品／牵引结构”，只显示模式名称，不显示启停勾叉。收集物品时，启用所属武器组便按“牵引物品”页和活体筛选自动回收散落内容至月池附近，关闭组别即停止；无需手动火控，默认不收敌方活体，每个目标只由一台设备收集。牵引结构时，启用所属组并切到手动火控，按住对应开火键（默认右键）持续沿炮口发束，牵拉射程内命中的结构，鼠标无需点中目标；自动火控不会操作结构牵引。单束牵引力为大型推进器满推力的四分之一，多束叠加并各自承受反作用。建议让作用线穿过目标重心，并配合惯性耦合器减少旋转。两种设备命中尚与其他结构同图的断开连通块时，先通过共同搬图链分离，再对独立结构施力。物品、活体筛选和模式仍支持多选批量设置。机制与验证边界见[对接设计 §9.3](doc/对接与舱外作业重构设计.md#93-牵引光束与月池回收)；2026-11-01 用户确认本轮牵引、耦合与模式按钮修改无问题并授权提交。

基架船和普通穿梭机均可在左侧驾驶栏切换「碰撞规避」。关闭时允许舰体撞击，双方按同额结构预算承受毁伤：先伤墙体，击毁后的余量再判定其下基架；弱侧墙和基架被毁时，强侧可能只损失部分墙体 HP。碰撞交换动量，当前接触层可同时毁伤多列。撞开后保留余速，后续 tick 按真实接触逐层结算；允许短时重叠。剐蹭修复保留当前毁伤效率，沿侧面滑行保留切向运动，无伤贴靠不再持续冒出破坏特效，并补齐碰撞音效；关闭「超凡智能的听觉」只停用补充音效，本船实际受伤的原版受击声保留。双方开启时可以互相穿过。本船开启且处于战斗自动驾驶时，会主动避让关闭规避后冲来的飞船；手操、普通导航、速度跟随和单独自动火控不自动避让。换目标、换任务或切手动保留设置，读档恢复默认开启。跳帮艇须关闭后才能发起撞击侵入。机制和验证边界见[舰体接触](doc/太空战架构.md#舰体主动撞击与碰撞规避2026-11-18)，剐蹭观感与听感仍待新档游戏内验收。

定点定角驾驶：在侧边栏“自动任务”选择定点命令，在地图上按下设目标位置、拖出船首宇宙绝对角度；拖曳太短不会提交。松开时不按修改键，目标固定于宇宙且目标速度、角速度为零。按住可改绑的参考系修改键（默认左右 Alt）松开，可从当前画面中的非聚焦对象外壳选择移动参考；位置随该对象平移和旋转，目标速度含刚体点的旋转速度，船首角度仍保持宇宙绝对值。两种任务均在位置、速度、角度、角速度进入容差后结束，随后自由漂移；选点或参考菜单取消不改变原任务。
