# RimExodus: Delta-V (Dev)

每个可进入的宇宙对象由一张 RimWorld Map 和一个 SpaceObject 承载；同一 Map 可包含多艘基架船或单建筑 shuttle，船体身份与地图容器独立。宇宙姿态保存在 Map 之外的统一连续宇宙坐标系中；当前聚焦地图保持原版朝向与坐标（identity transform），非聚焦飞船以可平移、可任意角旋转的外壳代理显示。总体目标与阶段路线图见 [doc/story.md](doc/story.md)。

对接与舱外作业已按新设计接线，机制与验收边界见 [技术设计](doc/对接与舱外作业重构设计.md)。独立飞船采用每侧 12 格紧凑图；软对接保持两张地图，速度同步后可主动开始共同作业或停靠。工作图中的船真实出力时逐船分离，遗留人员和物品进入单格散落图，由月池牵引光束回收。弹体与散落物共用按 tag／尺寸分桶的地图池。旧战术选点入口与开发快照迁移已删除；须使用新档进行游戏内验收。

软对接捕获保留手动驾驶；未由引擎出力的游戏刻，菱形进入捕获范围后按距离平方的倒数渐进修正船体位置与角度，超出范围不吸附。跨图入口已修正目标地图寻路参数和敌方接口检查面板空行。球面位置改为双精度存储与积分，修正低速不动及牵引收尾停滞；物品／人员收至月池、空图归池已通过离线检查，仍待新档游戏内验收。

已连接的对接口提供“组织转移”：直接使用原版巨坑转移窗口、装载清单、队伍和搬运任务，可修改或取消装载，断连会取消。共同舱外作业保留发起船的网格朝向；普通出力脱离继续保留当前方向，不再强制朝东。停靠仍以不搬动的目标地图为准。牵引进入设备 2 格范围后，按深钻井同款原版规则在附近放置、合堆，不再要求中心格空闲。

**当前状态：飞船与 SpaceObject 解耦重构（2026-09-24）已实现、待游戏内验证**——SpaceObject 退为「地图容器 + 轨道运动」层，普通基架船 = 主驾驶台认领的归属 + 同归属四连通基架（[解耦架构](doc/飞船与SpaceObject解耦架构.md)）：一图多船、在船旁建新船、主/备用驾驶台认领与继任、归属名即船名（引擎改名互通）、无引擎战术对接/分离（任意 cells 捕获-剥离-放置搬运链）、**出力即分离统一门禁**（拆分/脱离同入口，与其他船同图的船可入驾驶、首次真实推进器出力即从该图分离；玩家 forcePause 确认窗，取消退出驾驶可重试）、被动阻力（默认开、平移半衰期 8s/角速度 3s，[在线 MPC 制导](doc/在线MPC自动驾驶.md)预测同口径）、玩家/NPC 同基类双子类 controller（NPC 敌舰战术 AI 核心流程已由用户验证，细项待验收）。对接计划/跳帮舱/驾驶/星区模型等此前能力按新模型重接线（对接完成改为直接放置，不再重放原版降落动画；跳帮目标 = 地图容器整图）。星区内容类型占位、伴生物与 VEF/电推动力实现仍为设计状态。**太空战（阶段5，2026-09-26 施工完成；核心流程已由用户游戏内验证，未见严重阻塞，细项仍待验收）**：统一容器碰撞 + 联合效果注册表（详见 [doc/太空战架构.md](doc/太空战架构.md)）——弹体 = 注册进 objects 的 projectile tag 容器（写档剔除）、玩家自动火控／手动集火（默认 B 切换；手动时左键主套／右键副套）、主/副武器组×6 + 进入战斗位置、导弹/激光/直射弹、点防御（可拦截性结构派生）、可切换地面圆盾／太空折射线盾（待实测）、月池（无顶密封的起降基架）、shuttle 体系（起飞/驾驶/侵入=导弹机制；旧跳帮舱退役）。2026-09-29 舰载武器重构已落地、待实测：点防御激光炮（1×1）、小型（2×2）与中型（3×3）炮塔脚印及其他多格武器脚印，导弹架本体为气密墙，固定旋转炮手位、可转炮塔转速，钢铁/铀本地弹仓与优先级挂件，装弹机即完整武器的串联轨道加速链，导弹冷发射后点火制导，以及默认开启、可紧急关闭的己方舱壁安全限制；能力拆为正交 Comp，第三方可直接追加 Comp 接入。**旧存档不迁移**，测试请用新档（dev "Create two-ship test scene" 重建）。

基架船和 shuttle 共用驾驶、火控、武器组、战术 AI、世界标记与星球仪能力；各船身份锚保存火控模式和武器组，新船默认自动攻击附近敌对飞船；侧边栏或 B 键可切换为只让当前选中船接收鼠标的手动集火。侧边栏另有独立的自动战斗机动开关，默认关闭且读档复位；开启会替换当前自动驾驶任务，驾驶键可立即接管，对接计划保留；侵入弹体接管期间不可开启机动。自动火控与机动共用 NPC 的选敌和站位组件，但玩家不会自动撤退或跳帮。炮手战斗位置与点防继续独立运行；新控制模式待游戏内验证。

手动集火只接受地图上未被 UI 消费的按下事件。菜单、侧边栏（含星象仪、滑条和空白区域）及原版控件不会触发开火；按住射击移入 UI、切图或切走游戏会停止射击，需要松开后重新在地图按下。

已修正 UI 缩放下手动开火把地图鼠标误判为日志窗口或底栏的问题：持续开火检查使用实时鼠标位置，日志窗口开启但鼠标位于地图上时仍可发射。离线回归及用户游戏内实测通过。

手动集火时，空选中右键也可发射已激活的副武器组；多选武器后可用一次分组菜单统一指定主／副和组号。自动火控与预瞄按相对运动补偿弹体继承的本船速度，避免移动射击时提前量重复计入本船运动；目标后续加速或转弯仍会带来预测误差。本轮修复待游戏内回归。

「杂项」新增两件 2×2 无人工程设备，研究前置沿用真空屏障。**惯性耦合器**默认属于副组5，按住开火持续照射，分别交换双方平移动量和自旋角动量，使两船线速度和角速度趋同；小残差也会消除，共同漂移不会凭空停止。本船会受到反作用，需用推进器制动。**采矿光束**默认属于副组6，切割建筑、矿岩和裸露基架，完成后在设备附近按原版规则合堆、寻找落点，不再要求八格内留空格；完全无处放置时仍继续切割，放不下的材料会损失。矿物回收基础产量的50%，不搬运完整设备、人员或货物。两者需通电及蓄电，启用对应副组、切到手动集火后按右键操作；不自动索敌、不点防，也不提供拖曳或对接。惯性耦合束穿过所有护盾，持续照射时连续消耗蓄电；采矿束仍受守卫盾阻挡和电磁线盾折射。机制见 [太空战架构 §5.9](doc/太空战架构.md#59-工程设备惯性耦合与采矿光束)，功能与外观待游戏内验证。

星象仪中原版 POI 和玩家船常驻，其他对象按实际非太空地形面积随放大逐步出现；未加载原版 POI 保留原版图标，未物化／归档飞船保留箭头，缩放进入投影档后，已有地形投影的对象统一显示真实比例剪影；尚未物化或没有可用投影的继续使用图标。小艇和碎片不再单独保留固定大小标记。残骸（无存活人员、已安装武器、推进器、主副驾驶台）隐藏常规名称标注，悬停仍可查看名称。未物化自建 POI 的面积来自启动时测量的 prefab 池平均值，中途替换文件不更新测量。详细规则见 [星区架构](doc/星区架构.md#左侧信息面板与星球仪)；近景投影切换已通过用户实测，其他边界回归见 TODO。

两类船的推进器、武器和碰撞几何现通过同一船体接口提供；shuttle 默认没有武器，扩展添加的艇载武器仍复用共同火控。点防继续先按对象 tag 筛选：独立飞行的 shuttle 可被拦截，基架船不作为点防目标。停靠艇不会用自身推进器推动宿主。成员、武器和身份查询复用缓存，结构变化时刷新；两类船共用转移收尾期间的存档、尺度调整保护，多个侵入落地也分别完成清理后解除保护。飞行中的 shuttle 不再重复提供起飞；同 tick 起飞后毁艇也会先按原版方式放出乘员和货物，再判断空图清理。基架船换图或同向备用台继任后，现有驾驶会话随船身份更新；已经换图的船不再执行旧容器排队的分离请求。本轮调整仍待游戏内回归。

自动火控（玩家与 NPC）及手动集火预瞄只选择仍有有效船体身份、且本船至少有一台可用推进器的敌对船。基架船失去主台且无人继任，或全部推进器失效后，不再成为自动攻击候选；无主台碎片不显示预瞄标记。同图敌船分别评分；射击、预瞄和自动机动跟随所选船的中心。导弹发射后保持原船身份，分离后追踪新容器，推进器失效仍继续追踪，身份消失后沿当前方向飞行；同图残片或其他船的推进器不能维持失能船的目标资格。手动导弹仍可沿射线锁定失能船和残骸，无候选则不制导；点防保持来袭优先、最近目标兜底及独立启停。每船火控重构已通过离线回归，战损与分离场景待游戏内回归。

载人武器使用原版炮手操作链。没有有效自瞄时显示交互点并保留原版建造保护；有效自瞄时隐藏成品交互点、解除保护且不自动征用新炮手，仍可右键操作，堵格后不可下达操作命令。已有岗位可继续执行。2026-10-14 已删除独立炮手状态和操作 Job；显示、四向建造、补位、三种取消方式及存读档待游戏内回归。

采矿每次出料实际放置失败时，都会通过原版左上角消息提示损失，覆盖矿物和拆除材料，无提示冷却或额外容量扫描。电缆不再作为保护基架的碰撞建筑，修复隐藏电缆使基架无法切除的问题；同格墙体等实体建筑仍保护基架。产物放置和电缆修复已通过用户游戏内验证；损失提示按用户反馈改为每次失败立即提示。

## 环境要求

- RimWorld 1.6（Odyssey）
- [Launch into empty space](https://steamcommunity.com/sharedfiles/filedetails/?id=3532333408)（允许原版逆重飞船选择没有 POI/WorldObject 的 Orbit tile）
- .NET SDK（编译用；游戏运行不需要）
- Harmony（游戏自带 0Harmony；About.xml 已声明 brrainz.harmony 依赖）

## 构建

```
dotnet build Source/DeltaV.csproj -c Release
```

输出到 `1.6/Assemblies/DeltaV.dll`。RimWorld API 经 NuGet 包 `Krafs.Rimworld.Ref` 引用，Harmony 经 `Lib.Harmony.Ref`（编译期引用，运行时用游戏自带 0Harmony），首次还原需要联网。

## 测试

1. 启用开发者模式（选项 → 开发者模式）。
2. 进入 **Odyssey 开局**的游戏（需要轨道层）并处于地图视图中。
3. 打开调试面板（Dev quick commands → Debug actions，或 `~` 菜单），找到 **Delta-V** 分类。
4. **Create two-ship test scene**：生成玩家飞船图与敌舰图（按实际内容边界、每侧预留 12 格），敌舰初始位于切空间偏移 (60, 25)、35°，自动聚焦玩家船；口袋图均不占轨道 tile（sourceMap 统一挂专用宿主口袋图）。在 **Mod 设置 → 通用 → 双船测试场景**分别选择玩家船和敌舰的 prefab，列表包含 `Prefabs/` 子目录，每次打开重新扫描，配置跨存档保存、下次创建生效。默认两船均为“自动”，使用根 `Prefabs/` 下最新导出；自动加载失败才回退程序生成布局（玩家船 = 40×24“日”字船体 + 6 台全向推进器 + 逆重引擎/4 台力场扩展器 + 主驾驶台 + 2 名殖民者；敌舰约 24×14 船体 + 推进器组）。明确指定的文件若失效，在清理旧场景前报错并中止。
5. 其余菜单项：**Prefab: export home area as timestamped file**（把当前聚焦图居住区导出为通用地图 prefab）、按键抑制/MPC/坐标自测、**Dump universe state**、弹体池状态、聚焦图诊断与网格重建；生命周期回归保留强制归档最近容器、主船传送 1500 格及在玩家星区调用正常生成入口。调试菜单不再提供手动改敌舰位姿/派系、强制完成对接或绕过武器服务发射弹体的动作。

双船测试场景重复创建时会先加载本次 prefab，再暂停，完成旧弹体与排队清理、销毁旧地图，生成新场景并交接镜头；完成后仍保持暂停。连续点击不会叠加重建。交火／侵入中及增量生成期间重建的游戏内验收见 [TODO](doc/TODO.md)，清理契约见 [太空战架构 §4.5](doc/太空战架构.md)。

### 通用地图 prefab（2026-09-30）

- **原地替换调试图**：Dev → Delta-V → **Prefab: replace focused map...**，从 `Prefabs/`（含子目录）选择文件，再选择派系。派系列表首项默认沿用当前地图派系（优先容器／地图派系，纯飞船图从面板所选船取得；没有则保持无派系），也可指定游戏内其他派系或无派系；取消选择不改地图。确定后游戏暂停，在当前聚焦宇宙地图的位置生成新口袋图，沿用原容器的位置、角度、线速度与角速度。新图按实际 prefab 内容边界、每侧 12 格生成并居中放置，完成后交接镜头并删除旧图及其内容（原生轨道图还会移除旧世界对象）。加载或放置失败保留旧图；地表图、弹体图以及正在生成／起飞／对接的状态不可使用。地图替换与派系选择的基本流程已于 2026-10-16 经用户游戏内验证通过。
- **导出**：以任意 cell 掩码（当前唯一入口 = 居住区 Home Area）把当前聚焦图的一片内容导出为可重复实例化、派系无关的模板，文件落 mod 根 `Prefabs/`（gitignore，本地生成）。地形沿用原版 `PrefabUtility`；建筑与物品逐实例保存原版存档数据，包含电池、燃料、装填、插件及容器状态；基架与屋顶另存侧车。pawn/filth/蓝图等非 Building+Item 内容不导出；多格建筑按其锚点格是否在掩码内取舍。
- **重建**：`MapPrefab.Spawn` 以指定派系整片放回任意地图——顺序为基架（含结构归属认领）→ 原版地形 → 整批读取建筑与物品状态、重分配身份并落位 → 屋顶 → 设施重链 → **标记建筑展开**。「地板」建造栏中的 `Delta-V 预制图角色标记` 有独立的蓝色人形菱形图标，便于与其他模组的标记区分：每个标记优先在原格生成一名目标派系成员，原格不可站立时找附近格；派系没有基础成员时从原版派系生成池选人，再无可用种类时回退到殖民者。人形船员在入图前穿真空服和头盔；成功生成后标记消失。可在 Def 的 `CompProperties_PrefabPawnSpawner.pawnKind` 指定其他 PawnKind。标记仅在 prefab 首次重建时展开；普通存读档和远距离归档后的快照恢复不会重新生成 Pawn。新展开器仍通过 `CompPrefabMarker` 子类接入；SpaceObject 标记尚未实现。文件读入走原版 XML 管线（含 Def 交叉引用运行时解析），**导出后无需重启**即可用。
- **星区生成池（2026-09-30）**：导出的 prefab 可注册为**星区内容类型的物化生成池**——在 Mod 设置「生成」页按飞行器或空间站的叶子类型勾选 `Prefabs/` 目录（含子目录）里的文件即可。该类型的 POI 首次物化时按各自 seed 从池中确定性选取一份整片放置（旋转亦由 seed 派生）。**物化内容链是 prefab-only**：池为空的类型在星区生成期即报错跳过（不生成该类型对象）；配置了路径但文件失效时该 POI 在物化期报错取消（不回退程序生成——程序布局仅存于双船测试场景）。残骸由地图内容动态判定，不占专门生成类型。工作流：调试动作导出 → 手动移动/重命名进 `Prefabs/` 下的子目录 → 设置页重新扫描并勾选。
- 该系统是通用的（飞船/空间站/地面基地/小行星皆可），不限于居住区；`<prefab>` 地形节点保持原版 `PrefabDef` XML 形状，逐实例建筑状态位于 `<thingStates>`。保真度边界见「已知限制」。
- 双船测试的默认选择与失败处理见上节；基架写入或建筑落位失败会记录完整错误并销毁本次测试图、中止生成，避免把程序船叠在半成品上。
- 储物建筑的筛选与优先级按导出时实际生效的设置复制；旧地图的储存组关系不复制。不可通行的导弹仓等建筑，其原版储物格内物品也随 prefab 重建。
- 重复生成同一 prefab 时，炮塔内部枪械及其射击动作也获得独立身份，修复保存后重载出现重复 ID 的问题。已有错误测试图需重建；该修复已于 2026-10-18 经用户游戏内存读档验证通过。

### 驾驶（阶段2）

- 自动驾驶按当前飞船的实际反推能力与阻力提前制动：远场低频巡航，接近时逐步提高修正频率，终段精确对位；不按船型设固定巡航速度。普通飞船与 shuttle 对接共用此控制。侵入式跳帮艇则由导弹服务接管，以导弹速度追踪所点敌壳位置，只在所选目标触发撞击后效；可随时中止并恢复飞行。该改动待游戏内验证。
- 自动战斗机动按选定交战距离连续调整接近、撤离和环绕；它每次依据敌舰运动及本船可用推进器预测未来 2–6 秒的可达位置与姿态，环绕前视最多 60°。本轮船首始终尝试指向敌舰，侧推不足时放慢环绕，真实出力仍由共同自动驾驶与推进器分配器决定。新轨迹与姿态控制待游戏内验收。
- 导弹采用冷发射离架、RCS 快速折转、主机点火提速的动作节奏，后续巡航速度与追踪转向能力保持原值。跳帮艇侵入时从贴图的两个尾喷口绘制导弹式加力尾焰；普通驾驶的主推也拆成双台，合计推力不变，侧推与姿控位置按船体轮廓调整。沿用轻量弹体制导，不增加 MPC 求解；四向喷口静态核对与离线回归通过，实际观感、近距离命中和密集齐射性能待游戏内验证。

- 进入：聚焦一艘船的地图后按 **Keypad0**（可在 选项 → 控制 → "Delta-V piloting" 改键）或点屏幕左侧"Pilot this ship"按钮。聚焦离开该船自动退出。与其他船同图的船同样可进入驾驶——首次推进器出力即触发与所在图其余部分的分离（见「脱离」）。驾驶操作统一走面板按钮/快捷键，作用于面板当前选中（或默认）船；驾驶台 gizmo 只保留侧边栏没有的功能（改名、设为主/备用驾驶台）。
- 操纵：**W/S** 前后推进、**A/D** 侧向平移、**Q/E** 旋转。驾驶中这些键不再触发原版行为（相机平移/设计器旋转）；非驾驶时原版按键不受任何影响。
- 物理：推力/质量/质心/转动惯量按船体实际结构计算（甲板基架 + 建筑 + 推进器位置），旋转绕质心；联合分配器同时求解两个平移轴和力矩，纯平移优先保持零净力矩；实际出力的推进器会按各自连续油门改变复用自 Odyssey Gravship 的火焰尺寸、亮度、排气频率与排气速度（火焰只读分配器真实油门——聚焦船画在地图内、非聚焦船画在船壳上，0.25s 新鲜期防幽灵火焰；降落进场自动驾驶时即可在船壳上看到），并同步播放推进器循环工作音（复用 Odyssey 引擎循环音：聚焦图内逐推进器按各自油门出声、随镜头距离衰减；非聚焦船壳按总油门与摄像机距离衰减）；推进器按**实际状态**出力——故障、排气被堵塞或断电的推进器不参与分配（当 tick 生效），进入自由飞行要求船上至少一台可用推进器；飞行辅助默认开启（无输入的轴按推进器真实出力反向减速），可在 Mod 设置关闭获得纯牛顿漂移；按住 Ctrl（可改键）随时临时刹停，微小残差由辅助直接衰减归零。
- **宇宙 HUD → 统一左侧面板**：聚焦 Delta-V 语境的图（飞船口袋图/停靠宿主图/轨道图/POI 内部）时显示单一左侧面板，内容超出屏幕时操作区滚动，星球仪与缩放滑条固定在顶部。面板从上到下：**可缩放星球仪**（线框星球，南北轴 + 经纬网格、背侧不显示，星区网格淡入时南北轴同步渐隐；相机沿飞船—球心连线、北轴向上；拉近后物化对象的标记被真实比例剪影替代（图例变成剪影），名称与距离标注统一水平居中于图例（剪影或投影点三角/图标）下方，不再使用右侧布局；图标模式下聚焦船带朝向与速度矢量箭头，投影模式不叠加图标；极点附近保持上次稳定 roll）；**缩放滑条**（也支持在星球仪上滚轮）——拉远为整球态势，拉近显示星区六边形网格；对象显隐与名称采用逐对象面积门槛，图标／投影按视图尺度统一切换，原版 POI 与玩家船常驻（规则见上文及星区架构）；图标/飞船**可悬停**（名称、距离、未物化注记）与**点击聚焦**切图（未物化对象提示先接近）；标题与状态行（聚焦船的控制状态、速度、航向、转速、质量和辅助设置；地图关系行显示由 `ShipRegistry.StateOf` 即时推导的独占容器／同图合体结果（`FreeFlight/Docked` 不落档））；**驾驶此船/停止驾驶/切换为自动驾驶**单一控制按钮（独占容器与同图多船通用）、**同步漂移速度**及**开始舱外作业**按钮（自由飞行船可用；同图船出力分离后可用）；同图多结构时面板显示**结构列表**（名称 + 状态），允许选择有主台的船、无主台残骸和未占有基架；有效选择在切图和主台损毁后保留，无主台结构不提供驾驶操作。没有有效选择时优先玩家船，否则选默认船或最大结构。**点击基架上的建筑/物品/pawn，面板选择其结构归属**（只改面板选中，不动原版选择）。独占口袋容器时面板提供**驾驶台朝向罗盘**（十字排布的东西南北四向，一次点击指定主台屏上朝向）——飞船整图移入与当前位置重合的新口袋图并旋转建筑，容器角反向补偿，使飞船在轨道坐标中的朝向、位置与速度保持不变；对接计划进行中不可用。
- 左侧面板的战斗选项可折叠；展开后超过高度上限时可在区块内纵向滚动。跳帮艇在其聚焦图的侧边栏提供侵入武装与撞击目标操作。防卫建造栏按武器家族排列（原版从屏幕最下排开始，排满再换到上一排）；Delta-V 护盾是独立建筑，原版逆重护盾发生器不受影响。护盾可逐实例切换三模式：动能线盾碎裂来袭实弹并按强度降速或反射破片；电磁线盾被动折射激光、加大强度可令其原路返回；守卫圆盾持续耗电 10 W，以 3000 点盾容挡住投射物；断电仍可消耗已有盾容拦截，但恢复倒计时暂停。新建时默认守卫、满盾且可立即切换；从其他模式切回守卫后锁定至累计通电一小时，到期免费充满并解锁，此后留在该模式每累计通电一小时免费充满一次；断电、关机与搬运暂停计时，恢复后接续剩余时间；等待期间可用白银 1:1 补盾。两种线盾需供电，逐发从蓄电支付脉冲；欠费后短时失效。护盾参数拖动时实时预览，取消恢复；详细规则见 [护盾机制基线](doc/护盾机制基线.md)。舰炮射界有独立视图开关，按武器 Def 的真实射程画边界和逐 tick 扫描线；0° 为固定射线，360° 为整圈扫描，颜色按武器实例稳定分配。
- Mod 设置（分六个 tab）：**通用**（飞行辅助开关；宇宙视野缩放上限 60–5000 默认 400）；**对接**（同步稳定时长默认 60 tick、角度容差默认 1.15 度、取消距离默认 250 格；舱外作业每侧额外增加 N 格，默认 24）；**物理**（被动阻力——设置项名「让牛顿在棺材里代替飞船旋转」，默认开；线速度/角速度半衰期默认 480/180 tick；「超凡智能的听觉」太空战开火及补充命中音效，默认开——真空能不能传声是个物理问题）；**世界**（星区尺度每 worldtile 宇宙格数 100–100000 默认 20000，修改即时生效——全部对象位姿相对所在星区中心按比例缩放、速度不变，停靠/起飞进行中禁止修改，主菜单修改后于读档时统一重标定；分帧地图生成预算 1–16ms 默认 8ms；POI 加载/唤醒与删除距离默认 300/1200 格）；**生成**（星区内容按**类型树**配置：飞行器（战机/炮艇/护卫舰/驱逐舰/巡洋舰）、空间站（卫星→天基武器解锁/废弃、武器平台、贸易空间站、造船厂、工厂空间站、小行星）——树按 [doc/星区架构.md](doc/星区架构.md) §11 分类，任意深度、分支只分组、每个**叶子**独立配「保底数 + 多段概率额外量（每段独立掷骰，命中追加 1..上限）+ 物化 prefab 池（扫描 `Prefabs/` 目录勾选，见「通用地图 prefab」节）」；现阶段各叶子默认保底 0，残骸由物化地图内容判定，不单列类型。**全局设置、跨存档共享，只影响尚未生成过的星区**）；**日志**（分模块诊断开关 Core/Input/Physics/Harmony/Lifecycle/Render/Combat/Development，默认关；「开发调试」是通用临时排障入口，日志前缀为 `[DeltaV:Development]`，输出内容随当前调试问题变化；驾驶进出与按键抑制激活等关键日志始终输出；Render = 船壳分层摘要，每秒最多 1 条）。

### 宇宙视野与背景（阶段3）

- **Mod 设置 → 通用 → 隐藏没有玩家 Pawn 的太空地图分组**默认开启，即时过滤殖民者栏中没有存活玩家派系 Pawn 的 SpaceObject 地图，避免敌舰碎片占位。玩家动物、机械体及 shuttle／休眠舱等容器内的玩家 Pawn 也计入；地表地图和商队不受影响。关闭后恢复这些分组；专用宿主和弹体地图仍沿用原有隐藏规则。
- 聚焦 Delta-V 图（飞船口袋图/真实轨道图）时可**缩放到设置上限**：远处敌舰/POI 的外壳代理画在世界空间，zoom out 直接看见（方位即真实相对方位）。
- 所有 SpaceObject 的非聚焦代理共用同一套**结构外观**标准（2026-09-18 起统一，不再区分船/POI 两套配置）：地形按 `TerrainAt` 实际显示语义绘制（原版回落链让基架顶替太空表面、地板盖住基架，Space/Void 因 `dontRender` 天然不画）；墙、门、**气密结构与自然岩石**自动入壳（大小推进器本体、船壳、岩石都显示，无规则即用原始贴图）；入壳建筑的静态层复用原版 Print（含连接角盖），实时层捕获原版 DrawMesh；门在船壳上只同步开／关终态。`ShellRenderRuleDef` 可纳入其他 Thing、排除船内建筑，或指定绘制来源、有序整组替代图与船壳表面层级：点防／小型／中型炮塔仅把实时旋转炮身绘于船壳之上，固定底座与插件不入壳；轨道炮装弹机不露出船壳，加速段的内构和外壳进入船壳。物品与非气密建筑（家具、驾驶台、逆重引擎等内部设备）默认不显示。推进器**点火火焰按分配器真实油门**画在船壳上（自动驾驶或未来 AI 出力的非聚焦船同样显示；排气粒子不进船壳层）。多个船壳在屏幕上重叠时按**对象 ID 整壳分层**（ID 大者整壳在上，不逐建筑交错；点击拾取优先命中视觉最上层），且全部船壳位于**聚焦图内容之下**；进场、同步漂移和软对接均不改变这个层级。
- 星球/星空背景随飞船 universe 位置**连续**移动，并随当前参考系**反向旋转**；聚焦飞船图与停靠图背景同源同步，切换聚焦无跳变。
- 星球视图切到轨道层时，所有玩家飞船（含 shuttle）按连续 universe 位置显示**船体剪影标记**，点击可聚焦切图。世界标记和左侧星球仪共用船体脚印与位姿：基架船读取控制域，shuttle 读取艇体脚印；同图多船各有标记，身份、换图与结构变化按共同缓存规则处理。
- 宇宙坐标为**球面绝对坐标**（轨道层球面）：位置即球面方向，sphere↔tile 互推为纯函数（按 `PlanetLayer` 参数化，tile 划分与尺度常量无关），长途航行绕星球一周回到原点，无坐标漂移，也不需要任何平移记账。一个星区（worldtile）的弧长由**星区尺度设置**定义（默认 20000 格），连续驾驶跨一个星区需分钟级；tile 只是 coarse address 与生成记账维度，碰撞、降落选点等战术判定一律在连续轨道坐标中完成。
- 地图点到轨道位置及其逆向统一使用该图所属 `SpaceObject` 位姿；原生轨道图与口袋图同一规则。对接选点保留原版整数格语义：计划固定最终放置 root，完成前复核将它转换成原版设计器输入格，因此偶数尺寸船体不会误检相邻脚印。

### POI（阶段3 + 星区模型）

- 所有轨道层、可持有地图的 `MapParent`（含 Mod 子类）会自动注册为 POI，**包括原版空白 Space 画布站与容纳对接船的宿主图**——「每个可进入地图都属于一个 SpaceObject」。Delta-V 飞船/宿主、玩家船容器和宇宙宿主口袋图除外。自建 POI marker 由 `SectorContentService` 根据生成设置创建，prefab 池只用于其首次物化。
- **星区内容生成记账**：首次进入星区（移动跨界 / 逆重战略到达 / 开局出生星区）按**类型树**（§11：飞行器五级、空间站六类等）生成 Delta-V 自建对象——每个叶子独立「保底数 + 分段概率额外量」，在 Mod 设置「生成」页配置（各叶子默认 0），POI 首次物化用该叶子的 **prefab 生成池**（prefab-only：池空的类型报错且不生成，见「通用地图 prefab」节）。**POI 的名称与派系在生成时一次性随机决定**（名称走自制 RulePack：`词干 + 类型名 + (派系名) + #ID`，如「苦痛之护卫舰(堕落帝国) #123」；派系从可见非玩家派系中随机——敌方贸易站可劫、友方战机只是路过），物化时直接应用于容器、prefab 建筑与 pawn、结构归属名；整图归档→恢复时名称与派系完整传承。物化后带驾驶台的敌舰/空间站自动认领归属成船（可交战、可被索敌），无驾驶台且有基架的地图按内容呈现为残骸。「已触发生成」持久化防重复刷对象，当前对象清单由坐标查询重建、不序列化。原版 orbit 站点本就按 tile 生成，不受影响。
- 接近（≤ 加载/唤醒距离）按距离排队并在帧预算内生成地图；同一时间只有一个生成任务占用 `MapGenerator` 静态状态。未知 GenStep 暂按原子步骤运行，超预算会报告具体步骤。
- 离开加载距离后，地图保留但同时停止 Map 更新和全局 Thing tick；返回时只恢复一次。超过删除距离后，原生 POI 延迟采用其 `ShouldRemoveMapNow`、`alsoRemoveWorldObject` 与强制删除标记；任务主动销毁仍立即生效。
- **POI 容器与物化容器分离（2026-09-25）**：未物化 POI 是无图触发器（marker，按类型显示图标/名称）；接近后物化为**普通容器**——没有 POI 图标身份，名称 = 图上结构拼接（纯环境用环境名兜底），星象仪按船成员、环境地形及实际面积显示图标或投影（见上文星象仪规则）。物化容器生命周期按图内容判定：有承载结构且受玩家保护的地图保持活跃；其他普通口袋容器超删除距离后以原版 Map 序列化整图归档，原 Map 从内存卸载，追近时原样恢复。若有原版排队事件、进行中的任务目标或全局异常石柱仍指向该图，归档暂缓至引用消失。拆分产生的残骸容器同口径（修地图永久加载泄漏）。

### 驾驶台、认领与模式转换（解耦架构，2026-09-24）

基架上铺设地板或被临时地形覆盖后，仍按实际基架参与归属、连通、质量、剪影与碰撞。POI 接近加载和跨星区生成统一跟随玩家船所在的宇宙对象，单独飞行或侵入中的 shuttle 也能探索；同图多船只计一个参考点，混合派系时只要仍有玩家船成员便有效。这两项修正已接入，游戏内验收见 [TODO](doc/TODO.md)。

敌舰 AI 对基架船与 shuttle 使用同一套完整策略（基架船核心流程已由用户游戏内验证，未见严重阻塞；细项仍待逐项验收）：近距敌对舰船按已加载目标的威胁与战损选择目标；在「生成」页可对每个 prefab 排列 Brawler、Standoff、Missile boat、Boarder、Disabled / retreat 姿态。生成时固定所选 prefab 与姿态列表；未配置默认为 Standoff → Brawler → retreat。机动复用真实推进器自动驾驶，武器复用现有开火事务，跳帮 shuttle 复用起飞和侵入链。战损后撤向已生成的同派系最近船厂；没有可用船厂时继续避战，跨星区或到达临时航点均不会删除舰船。玩家追到船厂时，受损舰保持原状，在船厂外侧守位还击，不追远或跳帮。远距普通口袋容器仍按统一距离规则休眠、归档和恢复，整张 Map 压缩进存档并从运行图表卸载；撤退航程由共用自动驾驶按游戏 tick 推进，无图时使用卸载前逐台记录的数值推进器布局，经同一分配器限制出力；不模拟图内燃料和电力消耗。中途追上会恢复原地图、战损与船员，舰船 AI 根据当前损毁重新决定是否继续返厂。只有归档舰船抵达船厂、且玩家未追入加载范围时，才抽象为维修／拆解后重新部署并退场，存活船员交给原版 World Pawns，满足原版条件时可能出现在以后的舰船中；不强制治疗、永久保留或立即刷新替代舰。归档与恢复异常会记错误并保留可恢复数据；返厂防守、人员交接与存读档仍待游戏内验收，机制见 [太空战架构 §9.1](doc/太空战架构.md#91-远距整图归档与撤退)。

- **普通基架船 = 主驾驶台 + 同归属四连通基架**（控制域）。SpaceObject 只是「一张内部地图 + 轨道运动」的容器——同图可承载多艘船与无主台残骸归属；容器名 = 图上全部结构名拼接（UTF-8 顺序）。**主/备用认领**：无主归属上新建驾驶台自动认领成主台（形成飞船，新主台朝向定义船头）；已有主台的归属上新建默认备用；仅玩家派系驾驶台显示主备切换 gizmo；「设为主驾驶台」显式换主（原主台降备）、「设为备用驾驶台」主动放弃认领（不自动选回）；主台被摧毁由同方向备用台按稳定 ID 继任，无同向则成残骸（可手动认领恢复）。主驾驶台提供**改名**（归属名 = 船名，同步本船全部引擎名；原版引擎改名也同步回船名）。「修改基架归属」保护有主台的整个来源归属（包括断连基架），引擎损坏或断电不解锁；必须主动降副台，或摧毁主台且没有副台继任。敌方驾驶台沿用原版占领条件，玩家自建副台不能替换非玩家主台；无主台残骸可划入已有飞船。
- **无主台状态**：允许主动取消最后一座主台；该归属不再形成有效基架船，驾驶和自动驾驶结束，地图与结构保留。已加载地图中载有玩家建筑的无主台基架归属会显示持续的「基架结构缺少主驾驶台」警告（shuttle 本体除外）。侧边栏允许继续选择无主台结构，显示宇宙视图和设置主台提示，不提供自动认领的驾驶按钮；其他有效船不受影响。副台随基架改划同步身份，显式设为主台后按当前脚下归属恢复船舶操作，警告自动消失；存读档保留副台状态。
- **基架建造**：太空图上**允许在引擎覆盖范围外铺设基架**（在船旁建新船：铺基架 → 改新归属 → 建驾驶台成船；天然岩顶仍禁止）；地表保留原版范围限制。邻接单一归属则继承并吸收相连未占有域；孤立/多归属邻接一律保持**未占有**（多归属不再拒建，交由玩家划分）。降落脚印与**任何归属**的既有基架**重叠**一律禁止（自己 ID 的遗留也不例外）；异主基架**四邻接合法**。
- **地图关系的派生判定**：`ShipRegistry.StateOf` 只读取当前地图结构，不保存船级停靠状态。独立口袋图只有一艘有效船且未停在天然地面时派生为 `FreeFlight`；同图多船、停在天然地面或处于共同作业图（包括单船扩建）时派生为 `Docked`。地表图还受重力门禁限制。无主台残骸不算第二艘船。对接将控制域放入目标图，实际推进器出力经统一门禁拆分或提取到新容器；无人出力时共享原容器继续漂移。
- **速度同步与硬对接**：侧边栏选择“同步漂移速度”，自动驾驶匹配目标线速度及最近四向网格方向，随目标角速度保持方向关系；没有指定位置，也不要求整数格相位重合。同步过程不显示落点幽灵、不启用虚空动力。同步就绪后点击“开始舱外作业”，立即按当前相对偏移的最近整数格放置并搬图，无鬼影等待或再次确认对齐步骤。整船可合法停入所选对象时，搬入对方地图；否则可搬运对象与本船共同移入新工作图。没有合格目标时进入单船扩建图。设置 N 表示每侧增加 N。所有重力区域都参与判断，小行星／原版 POI 不搬图，只有整船能停入时才允许停靠。单候选直接应用，多候选供玩家选择；具体尺寸与门禁见技术设计。上述行为已通过编译及离线回归，仍待游戏内验收。
- **脱离（对接 → 拆图）= 出力即分离**（2026-09-24 统一定案：「脱离停靠」不再是独立命令）：与其他船同图或停在天然地面上的船进入驾驶后首次推进器出力即分离（**不要求逆重引擎**，至少一台可用推进器）。干净脱离（无断片、无通道滞留）立即执行；有断连残片（留在宿主）或对接通道上滞留人员/物品时弹**汇总确认**（游戏暂停）；取消 = 撤销自动驾驶任务 + 退出驾驶并提示，重新进入驾驶再推进即可重试。通道收回只影响本次分离相关通道，通道内容物原格留在宿主图。执行 = 控制域整体搬入新口袋容器（新容器位姿/速度 = 宿主刚体上船体锚点的位姿，含自旋切向继承）；分离后聚焦跟随侧边栏当前选中结构：有主台跟随主台侧，无主台跟随较大侧，同大优先留在原图；相机视点按宇宙参考系连续换算，其他船离港不会带走镜头。源图按承载结构规则回收，worldtile 图保持既有生命周期。
- **断连拆分（出力前公共检查，与脱离同一门禁）**：仅「将要产生推进器出力」的行为触发（手操、主动刹车辅助、自动驾驶）——有断连块（同归属断片或异主结构）时先弹汇总确认窗（游戏暂停），确认后各断片独立成新残骸容器（「残骸 #N」，速度/位置连续继承，断片上的备用台不自动升级），取消则退出驾驶（重新进入+推进可重试）。若域外还有无基架的污渍、物品或屋顶等内容，则提取本船到新图，残骸及其零散内容先留在宿主图，随后检查承载结构，避免残骸内容随本船飞走。被动阻力与纯漂移不拆船；切入驾驶/零出力不触发。NPC 走同一分离算法、不弹玩家确认（玩家/NPC controller 为同基类双子类）。
- **无承载地图回收**：毁伤失去基架的人员／物品，以及最后一艘船离开工作图后遗留的无承载内容，经事件触发转为各自的 1×1 散落图。残余基架块复用拆分链成为残骸；空图清理或归池不删除尚未交接的人员／物品。
- **控制状态**：未控制 / 手动 / 自动驾驶（玩家子类手操与自动驾驶同源，NPC 子类运行敌舰战术 AI）；驾驶状态不跨存档（读档后船按已保存速度漂移、无人驾驶）。
- **自动驾驶制动**：MPC 预测与执行统一正反推力单位，按非均匀时间步计算出力成本，通过停止约束和逐 tick 阻力预测规划提前制动。静止目标对接修复已获用户验收；算法与离线回归见 [在线 MPC 自动驾驶](doc/在线MPC自动驾驶.md)。
- **被动阻力**（默认开）：线速度半衰期 8s、角速度半衰期 3s（设置可调），与飞行辅助并存；不是推进器指令（不耗油、无火焰、不拆船），自动驾驶 MPC 预测同口径（刹停/航点/跟随/站位保持一致）。
- **逆重战略发射**（仍要求引擎，捕获 = 引擎覆盖范围内的本归属结构——口袋图整域绕过的旧例外已退役）：口袋图发射以所在星区 tile 为战略源地址；发射后走**星区离场标准流程**（飞船自有口袋容器销毁、星区 worldtile 图按逆重锚决定去留、其余 POI 图休眠收纳）。战术对接/脱离全程不启动引擎冷却。
- **软对接与对接口**：打开右下角软对接开关，所有对接口显示双线菱形指示器。主控船接口与另一图接口接近对齐后，自动驾驶持续微调真实推进器保持相对位置、方向与运动；位姿插值辅助双方菱形左对右、右对左重合，并伸出视觉通道；完成后，可在接口选择“组织转移”，批量指定人员和货物数量；也可选中人员右键本船接口通行、指定搬运物品／倒地人员，或在对方门不可通行时骇入。骇入使用 Odyssey 防爆门同等的 1800 工作量和原版骇入速度；完成后自动占领对方接口，敌人可按原版敌对建筑行为攻击它。偏离会收回通道并断连；关闭开关立即断连并停算。软对接开关随游戏存档保留：开启状态读档后仍开启，原配对再次满足捕获条件时从端口保存的伸展进度和接通状态继续；主动关闭开关会清零。软对接不生成通道建筑；同图硬对接继续使用原有气密通道。shuttle 不支持软对接。
- **Shuttle / 跳帮**：原版 shuttle 装货与发射门禁 → 起飞成为可驾驶 MiniShip（质量含实际载重，XML 可自定义逐台虚拟推进器；玩家方起飞后**自动进入驾驶状态**，无需再点驾驶按钮）→ 普通停靠把舱体视为单建筑控制域，复用漂移同步、主动开始作业和 `CaptureDomain → StripDomain → PlaceIntoMap`；跳帮型可在面板切换侵入驱动并用「撞击敌壳」按钮点选敌壳，按导弹机制满推追踪、撞穿并以舱体堵孔。飞行期可正常存档；侵入/对接任务读档丢弃，shuttle 按已存速度漂移。shuttle 舱体 gizmo 只保留落在目标图、作为普通建筑时的**起飞**；起飞后的驾驶、对接、侵入指定统一在左侧面板。
- **牵引光束**：只能建在月池上，默认自动回收射程内的散落人员和物品；关闭自动模式后通过常规武器组手动瞄准、开火。需要供电和蓄电，锁定后按游戏 tick 收拢目标相对坐标，随本船平移和旋转，横向漂移速度不再导致拉脱；进入设备 2 格范围即可将内容放上月池，不要求完全重合或先降到低速。接收使用深钻井同款附近放置与合堆逻辑；原版找不到落点时保留尚未放下的内容并提示。牵引直接查找散落对象，不依赖光束命中或碰撞箱；超出设置中的删除距离或离开星区后，内容视为丢失并销毁，对象注销、小图归池，不进入远距归档。现有独立黄黑回收投射器、建造图标和向内流动的牵引束。新版坐标牵引及简化宽口回收器外观已于 2026-10-22 经用户验收。
游戏内交互：**点击显示中的飞船外壳可直接聚焦切图**（相机落在点击处；瞄准/建造/框选/原版选中优先，不冲突）。玩家船与敌舰／残骸的双向点击、同步漂移及软对接后的反向切图仍待游戏内回归。
